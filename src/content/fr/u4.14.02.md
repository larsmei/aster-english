# u4.14.02 Opérateur COPIER

## 1 But

Dupliquer un concept utilisateur sous un autre nom.

Cette commande est rarement utile et elle présente l'inconvénient de doubler l'espace «disque» du concept dans la base globale de l'utilisateur. Le concept produit peut être détruit (commande DETRUIRE) pour récupérer l'espace disque.

Seuls certains types de concepts sont acceptés.

## 2 Syntaxe

```text
/ cabl_precont
/ evol_elas
/ evol_noli
/ evol_ther
/ fonction
/ listis
/ listr8
/ maillage
/ modele
/ nappe
/ table = COPIER(
    ◇ reuse = <objet de CONCEPT>,
    ◆ CONCEPT = cabl_precont / evol_elas / evol_noli / evol_ther / fonction / listis / listr8 / maillage / modele / nappe / table,
    ◇ INFO = / 1 (par défaut),
             / 2,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Opérandes

### 3.1 Mot clé CONCEPT

```text
♦        CONCEPT = co1
```

Nom du concept que l'on veut dupliquer.

Le résultat de la commande est du même type que le concept dupliqué.

### 3.2 Types de CONCEPT autorisés

```text
On ne peut dupliquer tous les types de concepts.

Seuls sont traités actuellement :
```

### 3.3 Remarques

Le besoin de dupliquer un concept est rare car il est a priori inutile de disposer d'un même objet sous deux noms différents.

Le concept produit (co2) correspond à une copie «profonde» du concept initial (co1), c'est à dire que l'on a dupliqué TOUS les objets JEVEUX de co1.

Le «volume» de co2 dans la base globale est identique à celui de co1.

L'utilisation de la commande conduit donc toujours à une perte dans l'espace disque.

### 3.4 Opérande INFO

```text
◊    INFO = info
```

Ce mot clé n'a aucune influence.

## 4 Exemple

```text
Lr1    =    DEFI_LIST_REEL (    …    )

Lr2     =    COPIER (CONCEPT = Lr1)
```
