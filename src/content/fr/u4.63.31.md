# u4.63.31 Opérateur REST_GENE_PHYS

## 1 But

Restituer dans la base physique des résultats en coordonnées généralisées.

Cet opérateur permet de restituer dans l’espace physique des résultats obtenus sur un système en coordonnées généralisées par des méthodes de recombinaison modale.

Le concept produit est un concept de type:

- dyna_trans si les résultats généralisés proviennent d’un calcul par recombinaison modale ou suite à l’extrapolation de résultats de mesures expérimentales sur un modèle numérique (le concept d’entrée est de type tran_gene),
- mode_meca pour la restitution suite à un calcul modal avec projection sur une base modale (le concept d’entré est de type mode_gene),
- dyna_harmo pour la restitution suite à un calcul harmonique avec projection sur une base modale, sans sous-structuration (le concept d’entré est de type harm_gene).

## 2 Syntaxe

```text
/ dyna_harmo
/ dyna_trans
/ mode_meca = REST_GENE_PHYS(
    ◆ RESU_GENE = harm_gene / mode_gene / mode_meca / tran_gene,
    ◇ MODE_MECA = mode_meca,
    ◇ NUME_DDL = nume_ddl,
    ◇ / TOUT_INST = "OUI" (ou non renseigné),
      / INST = list[float],
      / LIST_INST = listr8,
      / TOUT_ORDRE = "OUI" (ou non renseigné),
      / NUME_ORDRE = list[int],
      / NUME_MODE = list[int],
    ◇ / FREQ = list[float],
      / LIST_FREQ = listr8,
    ◇ CRITERE = / "ABSOLU",
                / "RELATIF" (par défaut),
    # Si: (equal_to("CRITERE", 'RELATIF'))
        ◇ PRECISION = float (défaut: 1e-06),
    # Si: (equal_to("CRITERE", 'ABSOLU'))
        ◆ PRECISION = float,
    # Si: exists("RESU_GENE")
        ◇ ENVELOPPE = / "NORME_MOMENT",
                      / "VALE_ABS",
    ◇ INTERPOL = / "LIN",
                 / "NON" (par défaut),
    ◇ / MULT_APPUI = "OUI" (ou non renseigné),
      / CORR_STAT = "OUI" (ou non renseigné),
    ◇ / ACCE_MONO_APPUI = list[fonction / formule / nappe],
    ◇ / GROUP_NO = list[grno],
    ◇ / GROUP_MA = list[grma],
    ◇ TOUT_CHAM = "OUI" (ou non renseigné),
    # Si: not exists("TOUT_CHAM")
        ◇ NOM_CHAM = / "ACCE" (par défaut),
                     / "ACCE_ABSOLU",
                     / "DEPL",
                     / "EFGE_ELNO",
                     / "FORC_NODA",
                     / "SIGM_ELNO",
                     / "SIPO_ELNO",
                     / "VITE",
    ◇ & DIRECTION = list[float],
    ◇ TITRE = text,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

### 3.2 Opérande MODE_MECA

```text
◊    MODE_MECA = mode
```

Concept du type mode_meca contenant une base de modes propres obtenue par sous‑structuration dynamique.

Cet opérande est utilisé dans le cas d'une restitution dans le système physique d'un résultat de calcul transitoire effectué sur base modale calculée par sous-structuration dynamique. La base modale contenue dans le concept mode_meca a été obtenue par la commande REST_SOUS_STRUC [U4.63.32](doc:u4.63.32). Il s'agit donc d'une double restitution, après avoir fait une double projection (cf.exemple au [§4]).

### 3.3 Opérande NUME_DDL

```text
◊    NUME_DDL = numeddl
```

Concept du type nume_ddl contenant une numérotation correspondante à un modèle réduit dans le cas d’un calcul avec condensation dynamique lorsque l’utilisateur souhaite une restitution sur les ddls appartenant à ce modèle réduit.

Cet opérande permet ainsi d’obtenir suite à la restitution un concept mode_meca qui pourrait être utilisé par la suite pour un calcul sur le modèle réduit (voir le cas-test SDNV107A pour exemple).

### 3.4 Opérandes TOUT_ORDRE/NUME_ORDRE/NUME_MODE/TOUT_INST/ LIST_INST/INST

```text
◊    /    TOUT_ORDRE = 'OUI'
```

Pour restituer sur tous les modes du concept mode_gene.

```text
/    NUME_ORDRE = num
```

Liste d’entiers contenant les numéros d’ordre des modes sur lesquels s’opère la restitution.

```text
/ NUME_MODE = num
```

Liste d’entiers contenant les numéros des modes dans le spectre global sur lesquels s’opère la restitution.

```text
/ TOUT_INST = 'OUI'
```

Si l'on souhaite restituer sur tous les instants contenus dans le résultat généralisé (tran_gene).

/ LIST_INST = list

Liste de réels croissants de type listr8 contenant les instants pour lesquels on souhaite effectuer la restitution.

/ INST = inst

Liste de réels contenant les instants sur lesquels s’opère la restitution.

Pour un calcul transitoire, on vérifie que les instants demandés par l'option LIST_INST sont bien dans le domaine de définition du tran_gene.

Les résultats à un instant quelconque peuvent être obtenus par interpolation linéaire entre les résultats de deux instants de calcul effectivement contenus par le tran_gene.

### 3.5 Opérandes FREQ / LIST_FREQ

Ces opérandes sont utilisées dans le cas d'une restitution sur base physique de calculs harmoniques généralisés (harm_gene).

```text
/    FREQ = freq
```

Fréquence à laquelle on souhaite restituer le calcul harmonique

```text
/    LIST_FREQ = list
```

Liste de réels contenant les fréquences pour lesquelles on souhaite effectuer la restitution.

Pour chaque fréquence indiquée, on restitue les champs obtenus à la fréquence de calcul la plus proche. Il n'y a pas d'interpolation.

### 3.6 Opérandes TOUT_CHAM / NOM_CHAM

```text
◊    /    TOUT_CHAM = 'OUI'
```

Permet de restituer les champs de nom symbolique DEPL, VITE et ACCE contenus dans le résultat généralisé (tran_gene, harm_gene).

```text
/    NOM_CHAM = nomcha
```

Liste des noms symboliques de champ que l'on souhaite restituer : 'DEPL', 'VITE', 'ACCE' et éventuellement s'ils ont été calculés, 'ACCE_ABSOLU', 'EFGE_ELNO', 'SIPO_ELNO', 'SIGM_ELNO' ou 'FORC_NODA'.

La restitution des champs 'EFGE_ELNO', 'SIPO_ELNO', 'SIGM_ELNO' et 'FORC_NODA' est possible en multi‑appuis.

### 3.9 Opérande MULT_APPUI

Après le calcul transitoire de la réponse sismique généralisée d'une structure, l'utilisateur doit indiquer 'OUI' sous le mot clé MULT_APPUI pour restituer les déplacements (et/ou vitesses et/ou accélérations) absolus. S'il ne précise rien, l'opérateur restitue les grandeurs relatives.

**Remarque:**

Si le calcul transitoire de la réponse sismique généralisée d’une structure est fait dans l’option TRAN_GENE de CALC_MISS *,* le résultat est directement en absolu sans préciser MULT_APPUI=’OUI’, car le chargement provient directement des forces sismiques de sol calculées par MISS.

### 3.10 Opérandes ACCE_MONO_APPUI et DIRECTION

```text
◊    | ACCE_MONO_APPUI = (gamma1, gamma2, gamma3),              [fonction]
     | DIRECTION        = (dx1, dy1, dz1, dx2, dy2, dz2, dx3, dy3, dz3),  [l_R]
```

Après le calcul de la réponse sismique généralisée d'une structure mono excitée, l'utilisateur indique le nom des accélérogrammes imposés (mot clé ACCE_MONO_APPUI) et  les directions du séisme (mot clé DIRECTION) pour restituer les accélérations absolues (accélérations uniquement, qui

seront stockées dans le champ ACCE_ABSOLU). S'il ne précise rien, l'opérateur restitue les grandeurs relatives. Le champ ACCE_ABSOLU sera alors absent.

**Remarque:**

Il est possible d’imposer jusqu’à 3 *accélérogramme* s *sous* le mot clé ACCE_MONO_APPUI *.* Ils *doi* ven *t être le* s *même* s *que ce* ux *imposé* s *sous le mot clé* FONC_MULT *d* u mot clé facteur EXCIT d *e la commande* DYNA_VIBRA *.*

Si le calcul transitoire de la réponse sismique généralisée d’une structure est fait dans l’option TRAN_GENE de CALC_MISS *,* le résultat est directement en absolu sans préciser ACCE_MONO_APPUI et DIRECTION, car le chargement provient directement des forces sismiques de sol calculées par MISS.

### 3.11 Opérande CORR_STAT

Après le calcul transitoire de la réponse sismique généralisée d'une structure, à condition que l'utilisateur ait demandé 'CORR_STAT' ='OUI' dans DYNA_VIBRA, il peut alors restituer les déplacements (et/ou vitesses et/ou accélérations) avec correction par les modes statiques de la troncature de la base modale. L'utilisateur doit indiquer 'OUI' sous le mot clé CORR_STAT. S'il ne précise rien, l'opérateur restitue les grandeurs sans correction statique.

### 3.12 Opérande GROUP_NO

```text
◊    /    GROUP_NO = lgrno
    /    GROUP_MA = lgrma
```

Après un calcul de dynamique transitoire sur base modale, l'utilisateur peut restituer des champs cinématiques sur une partie seulement des nœuds ou mailles du maillage.

Liste des groupes de nœuds/mailles correspondant aux lieux où l'utilisateur veut restituer des champs cinématiques.

### 3.13 Opérande ENVELOPPE

```text
◊    ENVELOPPE = "VALE_ABS" / "MOMENT_NORM"
```

Cette opérande permet de calculer les enveloppes des différents champs au cours du temps :
`ACCE`, `VITE`, `DEPL`, `EFGE_ELNO` et `REAC_NODA`, en utilisant l’une des options suivantes :

| Option | Description |
| --- | --- |
| VALE_ABS | Calcule le maximum des composantes à partir de leurs valeurs absolues : pour chaque composante scalaire $x_i(t)$, on retient $\max_t \|x_i(t)\|$. |
|  |  |
| NORME_MOMENT | Similaire à **VALE_ABS**, sauf pour le calcul de l’enveloppe des composantes du moment. Dans ce cas, l’enveloppe est déterminée à partir de la norme résultante du moment. Formellement, si $\mathbf{M}(t) = (M_x(t), M_y(t), M_z(t))$, on définit la norme du moment comme $\\|\mathbf{M}(t)\\| = \sqrt{M_x(t)^2 + M_y(t)^2 + M_z(t)^2}$.L’instant correspondant à la norme maximale est $t^* = \arg\max_t \\|\mathbf{M}(t)\\|$.Les valeurs d’enveloppe sont alors données par $\mathbf{M}^* = \mathbf{M}(t^*)$.En d’autres termes, l’enveloppe correspond aux composantes du moment à l’instant où le moment résultant est le plus intense. |

## 4 Exemple : Restitution d'un résultat de calcul transitoire effectué sur base modale calculée par sous-structuration dynamique : double restitution

Calcul modal sur un modèle généralisé : $(\stackrel{ˉ}{\text{K}}-\stackrel{ˉ}{\text{M}}{\omega}^{2})\eta =0$

avec $\stackrel{ˉ}{\text{K}}=(\begin{array}{ccc}{\stackrel{ˉ}{\text{K}}}_{1}& & \\ & {\stackrel{ˉ}{\text{K}}}_{2}& \\ & & \ddots \end{array})$ et $\stackrel{ˉ}{\text{M}}=(\begin{array}{ccc}{\stackrel{ˉ}{\text{M}}}_{1}& & \\ & {\stackrel{ˉ}{\text{M}}}_{2}& \\ & & \ddots \end{array})$ et équations de liaison $\text{L}\eta =0$

```text
modgene = CALC_MODES ( MATR_RIGI = :math:`\stackrel{ˉ}{\text{K}}`,
MATR_MASS = :math:`\stackrel{ˉ}{\text{M}}`
)
```

On obtient une base modale généralisée : les modes propres de la structure globale sont des combinaisons linéaires des modes propres des sous-structures : c'est sur cette base modale généralisée $\Phi$ que l'on projette les matrices assemblées généralisées (double projection).

$\begin{array}{cccc}\overline{\overline{\text{K}}}& =& {\Phi}^{T}\overline{\text{K}}\Phi & \text{opérateur}\text{PROJ\_MATR\_BASE}\\ \overline{\overline{\text{M}}}& =& {\Phi}^{T}\overline{\text{M}}\Phi & \\ \overline{\overline{\text{C}}}& =& {\Phi}^{T}\overline{\text{C}}\Phi & \\ {\overline{\overline{\text{F}}}}_{\mathrm{ext}}& =& {\Phi}^{T}{\overline{\text{F}}}_{\mathrm{ext}}& \text{opérateur}\text{PROJ\_VECT\_BASE}\end{array}$

Calcul transitoire sur la base modale $\Phi$ obtenue par sous-structuration dynamique.

```text
trangen = DYNA_VIBRA (BASE_CALCUL="GENE",
                      MATR_MASS = :math:`\overline{\overline{\text{M}}}`,
                      MATR_RIGI = :math:`\overline{\overline{\text{K}}}`,
                      MATR_AMOR_GENE = :math:`\overline{\overline{\text{C}}}`,
                      EXCIT = _F(VECT_ASSE_GENE = :math:`{\overline{\overline{\text{F}}}}_{\mathrm{ext}}`)    )
```

Restitution de la base modale $\Phi$ dans le système physique initial:

```text
modmeca = REST_SOUS_STRUC    (    RESU_GENE = modgene,
SQUELETTE = squel    )
```

Restitution du calcul transitoire dans le système physique initial:

```text
tran = REST_GENE_PHYS( RESU_GENE = trangen,
                       MODE_MECA = modmeca    )
```
