# u4.51.03 Operator STAT_NON_LINE

**Summary:**

Compute the coupled mechanical or thermo-hydro-mechanical evolution, in quasi-statics or in
dynamics, of a structure in the non-linear regime.

The non-linearity is related either to the constitutive behaviour of the material (for example plastic), or to the
geometry (for example in large displacements), or to frictional contact.

For details on the solution method used, one should refer to the reference
documentation [Quasi-static non-linear algorithm](doc:r5.03.01)

The evolution can be studied in several successive jobs (re-entrant concept), either as a
continuation (the last computed time instant is the initial time instant of the following analysis), or as a recovery
starting from an earlier time instant.

Produces a data structure of type evol_noli.

## 2 Contents of the EVOL_NOLI data structure

The EVOL_NOLI data structure contains the list of the fields archived in the course of the analysis (according to
the various options of the keyword ARCHIVAGE). By default, it contains, for each time instant,
the following list of fields:

- DEPL: field (at the nodes) of the displacements;
- SIEF_ELGA: field (at the Gauss points) of the stresses;
- VARI_ELGA: field (at the Gauss points) of the internal variables;
- COMPORTEMENT: map of the constitutive behaviour. This map contains information on the non-linear
constitutive behaviour used; it is not readable when one prints it in MED format.

Depending on certain analysis options, other fields will be present:

- CONT_NOEU: field (at the nodes) of the information on frictional contact (see
[U4.44.11](doc:u4.44.11) for more details on the contents of this field);
- CONT_ELEM: field (on the elements) of the information on frictional contact for the
LAC method (see [U4.44.11](doc:u4.44.11) for more details on the contents of this field);
- STRX_ELGA: field (at the Gauss points) relating to the structural elements;
- HHO_CELL and HHO_FACE: fields specific to the HHO method (see [r3.06.14](doc:r3.06.14)).

In addition to these fields, the data structure also contains parameters. At each
time instant, one stores at least:

## 3 General parameters

```text
◆ MODELE = modele,
◆ CHAM_MATER = cham_mater,
◇ CARA_ELEM = cara_elem,
◇ INFO = / 1,
            / 2,
# Si: equal_to("INFO", 2)
    ◇ INFO_DBG = / "APPARIEMENT",
                    / "CONTACT",
                    / "FACTOR",
                    / "MECANONLINE",
                    / "PILOTAGE",
                    / "SOLVEUR",
◇ TITRE = text,
```

The general parameters describe the model, the field of the materials and the elementary
characteristics (in particular for the structural elements).

MODELE is the name of the model whose elements are the subject of the mechanical analysis. The data
structure comes from the command [U4.41.01](doc:u4.41.01). It is always mandatory.

CHAM_MATER is the name of the material field assigned on the model. The data
structure comes from the command [U4.43.01](doc:u4.43.01). All the main mesh cells of the
model must be associated with a material.

CARA_ELEM is the name of the characteristics of the shell, beam, pipe, bar and cable elements, and
of the discrete elements assigned on the model. The data structure comes from the command
[U4.42.01](doc:u4.42.01). Obviously, this keyword is optional: if the model does not
contain such elements, it is not useful; on the other hand, if the model contains such
elements, it is mandatory.

### 3.1 Title

The keyword TITRE makes it possible to give a title to the analysis. It will be printed at the head of the results.
See [ref:U4.03.01 <U4.03.01>].

### 3.2 Management of the verbosity

The keyword INFO makes it possible to carry out various intermediate printouts in the message file.

Other printouts are made systematically during the non-linear analysis, independently
of the value assigned to the keyword INFO: these are the printouts of the residuals and of the relative
displacement increments in the course of the Newton iterations.

Warning: the output files can become very large with INFO greater than 2.

The keyword INFO_DBG makes it possible to limit the output to certain functionalities in order to control
the size of the output file.

## 4 Parameterisation of the analysis

```text
◆ INCREMENT = _F(
        # Si: exists("INST_INIT") or exists("INST_FIN")
            ◇ CRITERE = "RELATIF",
            # Si: (equal_to("CRITERE", 'RELATIF'))
                ◇ PRECISION = float (défaut: 1e-06),
        ◆ LIST_INST = list_inst / listr8,
        ◇ / NUME_INST_INIT = int,
        / INST_INIT = float,
        ◇ / NUME_INST_FIN = int,
        / INST_FIN = float,
    ),
```

The non-linear analysis is solved by an incremental method, so it is necessary to
**parameterise** the analysis. One uses for this the time variable (denoted INST), even if it has no
physical meaning in statics.
The (pseudo)-temporal discretisation is managed by the factor keyword INCREMENT, which defines
the time intervals taken in the incremental method.

**Note**

The time instants thus defined have a physical meaning only for constitutive relations in which
time enters explicitly (viscoelastic or viscoplastic, for example).
In the other cases, they only make it possible to index the load increments and to
parameterise the evolution of a possible temperature field.

### 4.1 General definition of the list of time instants

To supply the list of time instants, there are two ways of proceeding. The first is direct:
one gives the list of time instants by the keyword LIST_INST. This list is given by the operator [U4.34.01](doc:u4.34.01).
This way of proceeding does not give access to the advanced functionalities for the automatic management of the
list of time instants. It is therefore not recommended.

One can define the analysis time instants by the operator [DEFI_LIST_INST](doc:u4.34.03) and manage
at the same time the automatic subdivision of the time step and other advanced functionalities. This is
the recommended way of proceeding.

It should also be recalled that, by convention, the initial time instant of the analysis
of a virgin analysis (without recovery) is designated by the order number 0. Furthermore,
the order numbers are necessarily increasing and without "gaps".

### 4.2 Management of the recoveries

If one specifies nothing, the analysis will be carried out over all the time instants defined by LIST_INST. It is
possible to manage this list more finely.
The initial time instant of the analysis (which is therefore not (re)computed) is designated either by its value
(INST_INIT), or by its order number in the list of time instants litps (NUME_INST_INIT).

In the absence of the keywords INST_INIT or NUME_INST_INIT, the default is NUME_INST_INIT=0.

The final time instant (last computed step) is designated in the same way as the initial time instant
(either NUME_INST_FIN, or INST_FIN), except that it is not possible to refer to the time instant
of the initial state.

- If the automatic subdivision of the time step is activated, NUME_INST_FIN does not take it into
account and always works on the initial list of time instants. NUME_INST_INIT and NUME_INST_FIN
are active only at initialisation.
- The list of time instants being strictly increasing, it can happen that certain time steps
are not archived although they were requested. For example, in the case of a recovery of an analysis.
If the analysis in recovery of a previous analysis has no time instant greater than the first *
phase of the analysis, no time step will be archived.
- If INST_INIT does not exist in the list of time instants, one takes the immediately greater time step

**Notes**

**A - Simple example (default behaviour)**

```python
listInst = DEFI_LIST_REEL(DEBUT=0.,
                          INTERVALLE=_F(JUSQU_A= 10.,NOMBRE=10)),
evolNoli = MECA_NON_LINE(INCREMENT=_F(LIST_INST=listInst,
                         INST_FIN=4.)),
evolNoli = MECA_NON_LINE(reuse=evolNoli,
                         INCREMENT=_F(LIST_INST=listInst),
                         ETAT_INIT=_F(EVOL_NOLI=evolNoli))
```

The first MECA_NON_LINE carries out the analysis for the time instants 1, 2, 3 and 4.

The second MECA_NON_LINE: carries out the analysis for the time instants 5, 6, 7, 8, 9 and 10, the initial state
corresponding to time 4.

**B - Example to show the interest of INST_INIT**

```python
listInst = DEFI_LIST_REEL(DEBUT=0.,
                          INTERVALLE=_F(JUSQU_A= 10.,NOMBRE=10)),
evolNoli = MECA_NON_LINE(INCREMENT=_F(LIST_INST=listInst,
                         INST_FIN=4.)),
evolNoli = MECA_NON_LINE(reuse=evolNoli,
                         INCREMENT=_F(LIST_INST=listInst,
                         INST_INIT=8.),
                         ETAT_INIT=_F(EVOL_NOLI=evolNoli))
```

First MECA_NON_LINE: carries out the analysis of the time instants 1 to 4.

Second MECA_NON_LINE: carries out the analysis for the time instants 9 and 10 (one does nothing
for $t=5,6,7$ and 8), the initial state corresponding to time 4.

### 4.3 Selection of the time instants

The time instants in MECA_NON_LINE are located by an order number (an integer). If the user
wants to use a time instant (a real) and not an order number for the selection, the keywords
PRECISION and CRITERE make it possible to identify this order number (see [U4.71.00](doc:u4.71.00)
for the detailed syntax)

These parameters are used to locate the correct order number (NUME_INST_FIN/NUME_INST_INIT) when
the user supplies the time instant (INST_FIN/INST_INIT).

Consider the following list of time instants:

| NUME | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| INST | 0.0010 | 0.0020 | 0.0030 | 0.0040 | 0.0050 | 0.0060 | 0.0070 |

If the user wants to select the time instant corresponding to NUME=4, it is enough to say
INST=0.0040.

Let us take another example

| NUME | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| INST | 0.10000001 | 0.10000002 | 0.10000003 | 0.10000004 | 0.10000005 | 0.10000006 | 0.10000007 |

If the user wants to select the time instant corresponding to NUME=4, it is not enough to say
INST=0.10000004, because the relative gap between the time instants is
$\frac{0,10000005-0,10000004}{0,10000004}=1,0\times 10^{-7}$ which is smaller than the
default precision value ($1,0\times 10^{-6}$ ).
One will therefore not be able to distinguish NUME=3, 4 and 5 (the code then stops in fatal error).
It is then enough to change the parameter PRECISION in order to be able to select the time instant
(in our example, PRECISION=1E-8 will do).

## 5 Settings of the non-linear solvers

### 5.1 Choice of the method

```text
◇ METHODE = / "IMPLEX",
            / "MODELE_REDUIT",
            / "NEWTON" (par défaut),
            / "NEWTON_KRYLOV",
```

There exist several categories of accessible non-linear solvers: the Newton method (and
its variants), the Newton-Krylov method, the IMPLEX method, access to the non-linear
solver SNES of the PETSc library, and the use of model-reduction
methods (ROM).
The solver is selected by the keyword METHODE.

### 5.2 Newton method

```text
⟐ NEWTON = _F(
      ◇ REAC_INCR = int (défaut: 1),
      ◇ PREDICTION = / "DEPL_CALCULE",
                     / "ELASTIQUE",
                     / "EXTRAPOLE",
                     / "TANGENTE",
      ◇ MATRICE = / "ELASTIQUE",
                  / "TANGENTE" (par défaut),
      ◇ PAS_MINI_ELAS = float,
      ◇ REAC_ITER = int (défaut: 1),
      ◇ REAC_ITER_ELAS = int (défaut: 0),
      ◇ EVOL_NOLI = evol_noli,
      ◇ MATR_RIGI_SYME = / "NON" (par défaut),
                        / "OUI",
  ),
```

When METHODE="NEWTON", one uses the Newton-Raphson algorithm to solve the problem
(see [R5.03.01](doc:r5.03.01)).

It is the factor keyword NEWTON (a single occurrence) which makes it possible to set the various
parameters.
The keyword MATR_RIGI_SYME is used to force the symmetry of the stiffness matrix. It is useful
when one simultaneously uses a functionality which uses a non-symmetric matrix
(Simo-Miehe formalism, loadings of follower-pressure type, etc.) and the contact
formulation of type DISCRETE or LIAISON_UNIL (cf. [U4.44.11](doc:u4.44.11)).
Indeed, the latter can work only with a symmetric stiffness matrix.
Making the stiffness matrix symmetric has consequences on the rate of
convergence, which can go as far as its failure, but will never produce incorrect results.
If making the stiffness matrix symmetric makes the convergence of
Newton's algorithm impossible, the user is invited to use a contact formulation of type
CONTINUE, which works with a non-symmetric stiffness matrix.

#### 5.2.1 Prediction phase

The prediction phase (Cf. [R5.03.01](doc:r5.03.01)) aims to compute an estimate
of the displacement field so as to allow Newton's method to converge more quickly.
When the keyword is absent, it is the rate tangent matrix (option RIGI_MECA_TANG) which
is used if one has chosen for Newton's method a PREDICTION='TANGENTE', and it is the
elastic matrix (option RIGI_MECA) which is used if one has chosen PREDICTION='ELASTIQUE'.

It is also possible to make a prediction by using preliminary results coming
from another analysis.

For PREDICTION='EXTRAPOLE', one computes the estimate of the displacement increment from
the total increment obtained as the solution at the previous time step (weighted by the
ratio of the time steps). One projects this estimate onto the set of
kinematically admissible fields (i.e. satisfying the Dirichlet boundary conditions) according to
the norm given by the elastic matrix, which must therefore be computed. This functionality
is of interest in the case of the use of explicit local integration schemes of
Runge-Kutta type, which do not supply a tangent matrix: in this case Newton's
method uses an elastic matrix, but the number of iterations required can be
high. The use of the extrapolation can improve the performance.

For PREDICTION='DEPL_CALCULE' it proposes, as the displacement for the prediction at each time
step, the displacement given by a mechanical history specified under the keyword EVOL_NOLI
(by the keyword EVOL_NOLI). The displacement is projected onto
the set of kinematically admissible fields, as for the EXTRAPOLE method.

- The methods 'EXTRAPOLE' and 'DEPL_CALCULE' carry out a projection of the solution
onto the set of kinematically admissible fields. One uses for this the Dirichlet
boundary conditions given in the keyword EXCIT. In this case, it is not possible
to use Dirichlet loadings of "kinematic" type (operand AFFE_CHAR_CINE) but
only Dirichlet loadings by dualisation (operand AFFE_CHAR_MECA).
The analysis works, but the risk in this case being that the displacement field is not
kinematically admissible, the user must be attentive to it.
- The methods 'EXTRAPOLE' and 'DEPL_CALCULE' do not take into account the contact terms at
the prediction phase. Consequently, it is advisable to choose the methods
'ELASTIQUE' or 'TANGENTE' in prediction for contact analyses.
- It is necessary that the displacements used in 'EXTRAPOLE' and 'DEPL_CALCULE' come
from an analysis using the same mesh, because the boundary conditions must be consistent.
- Because of this projection onto the boundary conditions, these two options are incompatible
with the functionalities of PILOTAGE.

**Notes:**

These two methods have other uses. For example, if one has obtained a first solution on the
same mesh with other material parameters or another constitutive behaviour, the displacement
fields can be reused in the analysis.

Likewise, this makes it possible to reduce the memory space and to keep these results with a view to a
later continuation. For a large analysis, one can store only the displacements at
all the time instants in IMPR_RESU. If one wants to recompute the stresses and the internal
variables, one does a LIRE_RESU in the appropriate format and then one uses DEPL_CALCULE with ITER_GLOB_MAXI=0
(one carries out a single iteration) and ARRET='NON' (there is no convergence, one does not check
equilibrium). It is however necessary, for reasons of syntax, to give a loading
(avoid the Dirichlet loadings, which impose a linear solution) as well as a convergence
criterion, even if this information is not taken into account.

Because of the impossibility of correctly "projecting" the boundary conditions from one
mesh onto the other, it is now strongly inadvisable to use EXTRAPOLE and
DEPL_CALCULE from a mesh different from that of the current analysis.

#### 5.2.2 Correction phase

The matrix used for the global iterations of the method is the (consistent) tangent matrix
[R5.03.01](doc:r5.03.01) if MATRICE='TANGENTE', or the elastic matrix if MATRICE='ELASTIQUE'.

The keyword REAC_INCR makes it possible to control the update frequency of the matrix
with respect to the time steps.

- If the matrix used in prediction corresponds to the elastic analysis, it is evaluated only once
at the initial time instant, at the beginning of the algorithm, unless the elastic characteristics depend on
time or on a command variable such as the temperature, which depends on time
- This "elastic" matrix is computed by using Young's modulus given under the keyword ELAS
of the operator [DEFI_MATERIAU](doc:u4.43.01), and not the slope at the origin
of the traction curve given under the keyword TRACTION (and which is used, for its part, in the expression
of the constitutive relations VMIS_ISOT_TRAC, VMIS_ECMI_TRAC and VISC_ISOT_TRAC)

**Notes:**

The keyword REAC_ITER makes it possible to control the update frequency of the matrix
with respect to the Newton iterations.
Thus, at the first Newton iteration, one reassembles the tangent matrix only if it is equal to 1:
otherwise one keeps the matrix used in the prediction phase. By convention, if it is equal to 0
the matrix is not re-evaluated during the whole time step.

#### 5.2.3 Switch of the matrix in correction

The options PAS_MINI_ELAS and REAC_ITER_ELAS make it possible to pass from the tangent matrix to the
unloading matrix (i.e. considering that the non-linearities do not evolve) when the time
step is smaller than PAS_MINI_ELAS. This unloading matrix is the elastic matrix for
constitutive models of plastic type; for damage models it is identified
with the secant matrix.

As convergence with the elastic matrix is slower than that with the tangent matrix,
the keyword ITER_GLOB_ELAS under the factor keyword CONVERGENCE makes it possible to define a maximum
number of iterations specific to the use of the elastic matrix and different from that
associated with the use of the tangent matrix.

One can define an update frequency of the unloading matrix with the keyword
REAC_ITER_ELAS (analogue of REAC_ITER). If the unloading matrix does not depend on the state of
strain (which is the case for plastic materials but not for damage
models), take REAC_ITER_ELAS = 0 (since it will be the same in the course of the iterations).

These options can be useful when the automatic subdivision of the time step is not enough to
make an analysis converge. For example, in the case of softening laws, the tangent matrix
can become singular and it is therefore better to use the elastic matrix in order to converge.

### 5.3 Newton-Krylov method

If one chooses METHODE='NEWTON_KRYLOV', one uses an inexact version of the
Newton-Raphson algorithm; the accuracy of the solutions of the linear systems by an iterative method
is adapted in the course of each loading step (see [R5.03.01](doc:r5.03.01)).
All the options described for Newton's method (management of the matrices, of the
updating, etc.) can be used by the Newton-Krylov method.

### 5.4 IMPLEX method

When METHODE='IMPLEX', one uses the IMPLEX algorithm to solve the problem (see
[ref:R5.03.81 <R5.03.81>]). This method can be used only with a limited number of:
constitutive behaviours.

When METHODE='MODELE_REDUIT', one uses a model-reduction method to carry out the non-linear

- contact and friction (all methods)
- piloting,
- the line search,
- dualised boundary conditions (AFFE_CHAR_MECA): one must use AFFE_CHAR_CINE,
- mixed models: model reduction is compatible only with
displacement finite elements (nor with structural models either)

**Model reduction is not compatible with the following functionalities:**

One can specify the characteristics of the method of solution of the non-linear
incremental problem by a model-reduction method.
The prediction strategy can be set as in the case of Newton with the keyword
PREDICTION.
One can set the updating of the matrices with the keywords REAC_INCR and REAC_ITER.

The reduced basis is given by the keyword BASE_PRIMAL. This basis must have been built on
the same model and the same mesh as the analysis (but the loadings, the materials and the
constitutive behaviour can be different).

It is possible to activate hyper-reduction, which uses a method of dEIM
type (discrete Empirical Interpolation Method) by DOMAINE_REDUIT='OUI'. In this case, the analysis is
reduced to a restricted zone of the mesh (called RID) and built with the help of
the operator [DEFI_DOMAINE_REDUIT](doc:u4.67.02).

One must give the node group on which the interface between the RID and the rest of the
domain is defined, with the help of the keyword GROUP_NO_INTERF.

To improve the quality of the results in hyper-reduction, it is possible to make a
correction of the hyper-reduced analysis by a detailed finite-element analysis with CORR_COMPLET='OUI'.
For this, it is necessary to define a node group used to make the connection between the
RID and the rest of the model with the keyword GROUP_NO_ENCASTRE (defined for example in the
command [DEFI_DOMAINE_REDUIT](doc:u4.67.02)). This node group makes it possible to impose the
Dirichlet boundary conditions necessary for the corrected problem to be well defined. These
boundary conditions being defined by penalisation, the penalisation coefficient can be changed
by the keyword COEF_PENA.

This correction always being carried out on the reduced domain, it will not be as accurate
as a true detailed analysis (complete domain). Nevertheless, it is very useful when one changes
the boundary conditions significantly between the definition of the reduced basis (off-line
phase in [DEFI_BASE_REDUITE](doc:u4.67.01)) and the analysis using this reduced basis
(on-line phase in STAT_NON_LINE).

The line search can make it possible to improve the convergence of Newton's method

This factor keyword RECH_LINEAIRE makes it possible to activate the line search (see [R5.03.01](doc:r5.03.01)).

The keyword METHODE makes it possible to choose the line-search method, that is to say
the algorithm for searching for the zero of the functional. The CORDE method (by default) is the

One gives the maximum number of iterations to be carried out by ITER_LINE_MAXI and the precision
to be reached by RESI_LINE_RELA in order to achieve convergence of the line search.

For the CORDE method, it is not necessary to specify a very high precision or a very high number
of iterations, practice showing that two or three line-search
iterations are sufficient. One can therefore be content with requesting three iterations with
the default precision. The user cannot put more than 999 line-search
iterations for the CORDE method.

On the other hand, for the MIXTE method, on problems with damage, several tens
of iterations are often effective.

## 6 Loadings

```text
◇ EXCIT = _F(
      ◆ CHARGE = char_cine_meca / char_meca,
      ◇ FONC_MULT = fonction / formule / nappe,
      ◇ TYPE_CHARGE = / "DIDI",
                      / "FIXE_CSTE" (par défaut),
                      / "FIXE_PILO",
                      / "SUIV",
                      / "SUIV_PILO",
  ),
```

### 6.1 General principles

The factor keyword EXCIT makes it possible to describe at each occurrence a load (loads and
boundary conditions), and possibly a multiplying coefficient and/or a type of load.

The non-linear analysis is solved by an incremental method, so it is necessary to
**parameterise** the analysis.
One therefore also applies the loadings in an incremental manner, for example by applying
the force progressively (a ramp).
The basic principle is to separate the *spatial* part of the loading and the
*(pseudo)-temporal* part.

The spatial part of the loading
$\underline{L}_{ext} \left ( \underline{u} \right )$ is given by the keyword
CHARGE (possibly including the evolution of a temperature field).

- In a thermo-mechanical analysis, if the initial temperature is different from the reference
temperature (given in [AFFE_MATERIAU](doc:u4.43.01)), the associated strain field at
the initial time instant can be incompatible and therefore lead to an associated state of stresses and of
internal variables which is non-zero. If one uses an incremental constitutive relation
and if one does not explicitly define an initial state of stresses and of internal variables
(associated with an initial temperature field different from the reference temperature),
the field of stresses and of internal variables computed at the first increment will take into account
only the variation of temperature between the initial time instant and the first time instant, and not
the possible compatibility stresses associated with the initial temperature. To take
this initial state into account, one must give it explicitly, for example by means of
the keywords in ETAT_INIT. To avoid such situations, which can lead to
analysis errors, it is better to start an analysis by considering that one must start from a
virgin state.
- If one carries out an analysis in axisymmetry and one imposes nodal forces, these forces
must be divided by $2\pi$ (one works on a sector of one radian) with respect
to the real loadings. Likewise, if one wishes to compute the resultant of the forces, the
result is to be multiplied by $2\pi$ in order to have the total resultant on the complete
structure. Likewise, in plane stresses or in plane strains, one works on a
unit thickness: the forces (over the thickness) applied must be divided by the thickness,
and the real forces are obtained by multiplying the forces of the analysis by the thickness.

**Notes:**

The temporal part of the loading $g \left ( t \right )$
is given by the keyword FONC_MULT.
If one does not specify the multiplying function, one applies a step function.

It is possible to define directly
$\underline{L}_{ext} \left ( {\underline{u}, t} \right )$ in the keyword CHARGE
if one uses the command [AFFE_CHAR_MECA_F](doc:u4.44.01) (function of time). In this case, one must be careful:
indeed, if one uses FONC_MULT at the same time, one multiplies the loading again by
a function of time.

By default, TYPE_CHARGE is equal to 'FIXE_CSTE': this corresponds to a loading applied on the
initial geometry and not piloted. It can however be a function, and, in particular,
depend on time.
A fixed loading is re-evaluated only at each new time instant, and only if it depends on
time (defined in [AFFE_CHAR_MECA_F](doc:u4.44.01) and parameterised by the time instant, or else affected
by FONC_MULT).

### 6.2 Follower loadings

If TYPE_CHARGE='SUIV', the loading is said to be a "follower", that is to say that it depends on the value
of the unknowns: for example, the pressure, being a loading applied in the
normal direction to a structure, depends on the updated geometry of the latter, and therefore on the displacements.
A follower loading is re-evaluated at each iteration of the solution algorithm.

At present the loadings which can be qualified as followers are the gravity
loading for the CABLE_POULIE element, the pressure for the modellings
3D, 3D_SI, D_PLAN, D_PLAN_SI, AXIS, AXIS_SI, C_PLAN, C_PLAN_SI, COQUE_3D and for all the
THM modellings, and the centrifugal force in large displacements
(keyword ROTATION in [AFFE_CHAR_MECA](doc:u4.44.01)). There is also the surface force
FORCE_FACE for the 3D elements.
One can also impose that a Dirichlet loading be a follower in the case of the
rigidification of a part of the structure by the use of LIAISON_SOLIDE (see [AFFE_CHAR_MECA](doc:u4.44.01)) in large transformations.

- The pressure can be defined by a function depending on the geometry.
In the follower case, one can choose whether this dependence is with respect to the initial
geometry with the parameters X, Y and Z of [DEFI_FONCTION](doc:u4.31.02) or with respect to the
updated geometry with the parameters XF, YF and ZF.
- The follower loading of type LIAISON_SOLIDE is strictly incompatible with piloting
and the line search. It can be used only with 2D and
3D isoparametric finite elements (not with structural elements such as beams, plates and shells).
- In the case of COQUE_3D, the pressure loading can be created by the keywords
PRES_REP/PRES or FORCE_COQUE/PRES of [AFFE_CHAR_MECA](doc:u4.44.01). The other operands
of FORCE_COQUE (FX, FY…, F1, F2, ...) are not compatible with follower loadings.

**Notes:**

### 6.3 Piloted loadings

If TYPE_CHARGE is equal to 'FIXE_PILO', the loading is still fixed (independent of the geometry) but
it will be piloted by means of the factor keyword PILOTAGE. The pilotable loads must come from
the operator [AFFE_CHAR_MECA](doc:u4.44.01) or [AFFE_CHAR_MECA_F](doc:u4.44.01) (if it is not
a function depending on time) and must not be affected by the keyword FONC_MULT.

One cannot pilot the gravity loadings, the centrifugal force, the Laplace forces,
the thermal loadings or those of initial or anelastic strains, and the connection conditions.

To have piloted loads depending on the geometry (so-called "follower" loads), one uses
TYPE_CHARGE='SUIV_PILO'.

### 6.4 Incremental loadings

If TYPE_CHARGE='DIDI' then the Dirichlet conditions (imposed displacements,
linear conditions) will apply to the displacement increment from the time instant given
under ETAT_INIT/NUME_DIDI (by default the recovery time instant of the analysis) and not to the total
displacement.

For example, for an imposed displacement (keyword DDL_IMPO of [AFFE_CHAR_MECA](doc:u4.44.01)) the
condition will be of the form $u-{u}_{0}=d$ where ${u}_{0}$ is the displacement defined
by NUME_DIDI and not $u=d$ .

The differential Dirichlet option is available both for mechanical loadings (CHAR_MECA)
and for kinematic loadings (CHAR_CINE).

### 7.1 General principles

When the intensity $\eta$ of a part of the loading is not known a
priori (so-called reference loading defined in [AFFE_CHAR_MECA](doc:u4.44.01)
with a load of type FIXE_PILO), the keyword PILOTAGE makes it possible to pilot this loading
by means of a node (or node group) on which one can impose
various piloting modes (keyword TYPE).

- With FIXE_PILO, one cannot use the keyword FONC_MULT for the reference loading.
- When the reference loading is defined by [AFFE_CHAR_MECA_F](doc:u4.44.01), this
loading can be a function of the space variables but not of time. Likewise, the
changes coming from command variables (such as the temperature) which depend on time
cannot be used with piloting.
- Piloting is forbidden with contact.
- It is not possible to do piloting with PREDICTION='DEPL_CALCULE' or
PREDICTION='EXTRAPOLE'

**Notes:**

### 7.2 The types of piloting

The type of piloting carried out is given by the keyword TYPE. Seven piloting modes are
available (Confer [R5.03.80](doc:r5.03.80) for more details).

#### 7.2.1 Piloting for the displacements

Piloting for the displacements will control the intensity of the loading in order to control a
displacement or equivalent.

TYPE='DDL_IMPO' makes it possible to impose a given value of displacement increment (a single
component $i$ possible) at a single node (or of a node group comprising only
one node) given by the keywords NOEUD or GROUP_NO. At each time increment, one seeks
the amplitude $\eta$ of the reference loading which will make it possible to satisfy the following
incremental relation

$$
C \,  \Delta {u}_{i} (\text{noeud}) = \Delta t
$$

TYPE='LONG_ARC' makes it possible to pilot the intensity $\eta$ of the reference loading by the
length (curvilinear abscissa) of the displacement response of a node group (to be used for
example when one wants to control the buckling of a specimen). One checks the following relation:

$$
C \, \parallel \Delta u\parallel =\Delta t
$$

with $\parallel (\Delta u)\parallel =(\sqrt{\sum_{n}\sum_{c}({\Delta u}_{n,c}^{2})})$

where $n$ are the piloting nodes and $c$ the components of the displacement of the nodes
considered. Even if the piloting node group is reduced to a single node, one must still
use GROUP_NO.

For both types, $C$ is given by the keyword COEF_MULT and NOM_CMP gives the name of
the component (corresponding to the degree of freedom $i$ ) used for the piloting
('DX' for example).

#### 7.2.2 Piloting for the limit analysis

The piloting TYPE='ANA_LIM' is specific to the limit-load analysis (law NORTON_HOFF) by the kinematic
approach (cf. [ref:R7.07.01 <R7.07.01>] for more details). If $F$ denotes the
piloted assembled loading (indicated by TYPE_CHARGE='FIXE_PILO'), then the piloting function
is written simply:

$$
P(u)=F \cdot u = 1
$$

Except for the limit-load analysis, this functionality is of no interest *a priori*.
For this piloting mode, no other keyword is to be specified.

#### 7.2.3 Piloting for the softening constitutive behaviours

The use of softening constitutive laws can lead to sudden snap-backs which
make the course of the analysis delicate. The following two piloting modes remedy this:
(Cf. [R5.03.80](doc:r5.03.80) for more details).

The piloting TYPE='DEFORMATION' guarantees that at least one Gauss point of the structure sees its
strain evolve in a monotonic way. One checks the relation:

$$
C \,\underset{\mathrm{Pg}}{\max} \left( \frac{\dot{\varepsilon}}{\parallel \dot{\varepsilon}\parallel } \cdot \Delta \varepsilon \right) =\Delta t
$$

This piloting mode is valid for all the constitutive laws, including in large
strains SIMO_MIEHE.

When one wants to use this piloting mode, it is indispensable to carry out a first
analysis without the keyword PILOTAGE in order to prime the problem and obtain an initial state
${\varepsilon}^{-}$ different from zero (otherwise division by zero).
One then carries out a recovery from this non-zero initial state
and one uses the piloting.

The piloting TYPE='PRED_ELAS' ensures that at least one Gauss point of the structure leaves the linearised
elasticity threshold ${f}_{\text{pred-elas}}$ by a quantity $\frac{\Delta t}{C}$ .

One checks the relation:

$$
C \, \underset{\mathrm{Pg}}{\max} \left( {f}_{\mathrm{PRED\_ELAS}} \right) =\Delta t
$$

This piloting mode is valid only for the laws ENDO_SCALAIRE (with the non-local version),
VMIS_ISOT_NL (with the local version only),
ENDO_FISS_EXP (non-local only), ENDO_ISOT_BETON and ENDO_ORTH_BETON (with the local version
and the non-local version), BARENBLATT, BETON_DOUBLE_DP, CZM_EXP (with the elements with internal
discontinuity *_ELDI), CZM_OUV_MIX, CZM_TAC_MIX and CZM_LAB_MIX (interface elements *_INTERFACE), CZM_EXP_REG
(joint elements *_JOINT or X-FEM modelling) and CZM_LIN_REG (joint elements).

$C$ is given by the keyword COEF_MULT but fixing this parameter is difficult to
define at the first attempt because the notion of departure from the criterion $\frac{\Delta t}{C}$ is
not intuitive and varies according to the constitutive laws. For the laws ENDO_SCALAIRE,
ENDO_FISS_EXP and ENDO_ISOT_BETON, a different version of the definition of
$\frac{\Delta t}{C}$ is used, in which this parameter is linked to the damage
increment (see [R7.01.04](doc:r7.01.04)).

The solution of the two previous equations makes it possible to obtain the unknown intensity of the loading.
In certain cases, the solution of these equations can lead to several solutions for
the intensity. One then always chooses the solution which is the closest to
${\varepsilon}^{-}$ . This is why, when one wants to impose an
alternating loading, one is obliged, at each change of sign of the loading, to carry out a first
analysis without the keyword PILOTAGE in order to obtain an initial state ${\varepsilon}^{-}$
of tension or of compression. One then carries out a second analysis in continuation from the
previous initial state with the keyword PILOTAGE.

These two types of piloting are not available for the structural elements.

One gives the mesh cells or mesh-cell groups used to pilot the analysis by the keywords
GROUP_MA, MAILLE or TOUT. This is of interest in order to lighten the solution of the equations of these piloting
modes.

### 7.3 Control of the bounds

These keywords ETA_PILO_R_MAX and ETA_PILO_R_MIN make it possible to define the search interval
of the piloting values. At each Newton iteration all the piloting values outside
$[\eta^{R}_{min}, \eta^{R}_{max}]$ are ignored. This can lead to a "piloting failure"
if this interval is too restrictive.

If one does not specify any values, one has $\eta^{R}_{min}=-\infty$ and $\eta^{R}_{max}=+\infty$.

A possible use of this interval is the following. One wishes, for example, to pilot a
pressure imposed on the structure and one expects to keep this pressure positive. By setting
$\eta^{R}_{min}=-0$, this makes it possible to impose positive piloting values.

The keywords ETA_PILO_MAX and ETA_PILO_MIN make it possible to specify the interval of piloting
values desired. One uses it to stop the analysis cleanly when ETA_PILOTAGE reaches
the bounds of this interval.

This interval must be more restrictive than the search interval defined previously, because the
latter is applied in every case. The principle of operation is the following: at
convergence of the Newton iterations, if one of the bounds has been reached, the analysis stops.

A possible use of this interval is the following. In the case of the presence of snap-back,
by setting $\eta_{min}$ to a small value, this makes it possible to stop the analysis before a
complete tearing/damage of the specimen and thus to avoid the divergence at the last time step.

The other possible use is that of $\eta_{max}$ as a maximum limit load.

With the law ENDO_ISOT_BETON, these two keywords are mandatory, because they are used to
fix the piloting bounds at element level.

In the event of overshoot of the interval $[\eta_{min}, \eta_{max}]$, the user can indicate
whether one wants to project the piloting value onto $[\eta_{min}, \eta_{max}]$ with
PROJ_BORNES='OUI'.

With PROJ_BORNE='OUI', the projection will be carried out (if $\eta>\eta_{max}$ then $\eta=\eta_{max}$;
if $\etaw\eta_{min}$ then $\eta=\eta_{min}$), which makes it possible, in the event of convergence,
to stop the analysis precisely on $\eta_{min}$ or $\eta_{max}$.

With PROJ_BORNE='NON', one does not modify the values of eta, even if during the Newton
iterations the latter has a value greater than $\eta_{max}$ or smaller than
$\eta_{min}$. On the other hand the analysis is stopped if, at convergence, $\eta$ exceeds the
bounds.

A possible use of the interval $[\eta_{min}, \eta_{max}]$ with the option
PROJ_BORNE='OUI' is the following.
One wishes, for example, to compare several analyses for a softening model, which are
piloted in displacement. These piloting parameters make it possible to stop the analyses at the
same loading when the structure is sufficiently softened. This strategy makes the comparison
easier, thanks to the control of the last piloting point.

It is strongly recommended to call on the option PROJ_BORNE='OUI' when setting up
test cases involving piloting of the loading. This indeed makes it possible to stop the analysis at
precise points where one comes to test the values, which improves the robustness of the test and facilitates
its maintenance. An example of this data setup is proposed in the tests ssnp133a and ssnp133d.

With PROJ_BORNE='NON' one can in certain cases unblock the analyses, which otherwise do not
converge with the too restrictive conditions imposed via
the interval $[\eta^{R}_{min}, \eta^{R}_{max}]$. Suppose one pilots a pressure
imposed on the structure and one expects to keep this pressure positive. By setting
$\eta^{R}_{min}=0$, the analysis stops in piloting failure.
On the other hand, by imposing $\eta^{R}_{min}$ slightly negative, one authorises de facto
the passage through a "non-physical" state during the Newton iterations, which facilitates
convergence.
The converged state in this case can just as well be physical (positive pressure) or non-physical.
It is the value of $\eta^{R}_{min}=0$, which will govern the behaviour in the event of convergence
outside the bounds. This strategy makes it possible to keep only the positive piloting values, if one
finds at least one positive piloting value.

### 7.4 Control of the multiple solutions

The keyword SELECTION makes it possible to select the method making it possible to choose the piloting value
in the case where several solutions are supplied by the piloting solution.

SELECTION='NORM_INCR_DEPL' makes it possible to select the piloting value by the smallest norm
of the displacement increment over the time step considered.

SELECTION='ANGL_INCR_DEPL' makes it possible to select the piloting value by the smallest angle
between the displacement obtained for the current time step and the displacement obtained for the previous
time step. This choice is available only with TYPE=LONG_ARC.

SELECTION='RESIDU' makes it possible to select the piloting value leading to the smallest residual.

SELECTION='MIXTE' makes it possible to select the piloting value by relying on several
strategies. One starts with the NORM_INCR_DEPL strategy above. If the results
of the objective function (the norm of the displacement increment) are too close, one switches
for this iteration to the RESIDU strategy. There again, if the residuals are too close, one
returns to the NORM_INCR_DEPL strategy and one examines whether the list of the residuals RESI_GLOB_MAXI of the current
time step presents cycles. If this is the case, it is the worst solution of
NORM_INCR_DEPL which is chosen for this iteration. Otherwise, one simply chooses the better
of the two, even if they are not sufficiently contrasted.

- If one does a recovery of an analysis (reuse) with the keyword SELECTION='ANGL_INCR_DEPL', it is
important to bear in mind that this criterion requires the two previous time steps.
One will therefore have to take care to archive correctly the results of the previous analysis,
at the risk of obtaining incorrect results. An alarm warns the user in this situation.

**Note:**

The keyword EVOL_PARA makes it possible to impose the growth or the decrease of the piloting parameter.

### 8.3 Management of the iterations

The keyword ITER_GLOB_MAXI gives the maximum number of iterations carried out to solve the
global problem at each time instant. An excessive increase of this parameter
is generally the sign of a problem in the modelling or of an inadequate temporal
discretisation.

This test is always carried out except in the case of the subdivision of the time step by the method
'EXTRAPOLE'.
In the case of the solution of a contact/friction problem by the CONTINUE formulation
in generalised Newton, it is often necessary to increase the number of Newton iterations beyond
its default value.

The keyword ITER_GLOB_ELAS fixes the maximum number of iterations carried out with the elastic matrix
when one uses the keyword PAS_MINI_ELAS of the factor keyword NEWTON to solve the
global problem at each time instant.
One recalls that PAS_MINI_ELAS makes it possible to pass from the tangent matrix to the elastic matrix
when the time step is, or becomes (by the subdivision), smaller than a certain value
specified under PAS_MINI_ELAS.

Unlike ITER_GLOB_MAXI, this parameter can easily take large values
(several hundreds) because convergence on a non-linear problem with the elastic matrix
(very stiff) is slow although guaranteed from the theoretical point of view for all the laws describing
generalised standard materials.

### 8.4 Management of the stop

If one of the chosen global convergence criteria is not satisfied after the maximum number
of iterations, then the analysis stops (the previous results are saved).

It is nevertheless possible to continue the analysis by using ARRET='NON'.

This possibility is to be reserved for very particular cases because it gives incorrect results.

number 0.

By default (if one specifies nothing) all the fields are identically zero. The initial state can
be defined either by specifying each field of the initial state, or by
extraction from a pre-existing concept of type evol_noli.

If one gives a data structure of type EVOL_NOLI coming from another analysis by the keyword
EVOL_NOLI, one automatically extracts the fields of this data structure for the initial state.

The extraction of the initial mechanical state in the evol_noli data structure is done from the
archiving order number NUME_ORDRE or from the archiving time instant INST.

These extracted fields will be archived at the first time instant of the list of time instants defined
under the keyword INCREMENT.
In the case where one supplies INST, the keywords PRECISION and CRITERE (see
[U4.71.00](doc:u4.71.00) for the detailed syntax) are used to locate the correct order number.
Indeed, the time instants are located by an order number (an integer). If the user wants
to use a time instant (a real) and not an order number for INST, the operand PRECISION
makes it possible to select this order number.

The first MECA_NON_LINE carries out the analysis for the time instants 1, 2, 3 and 4.

The second MECA_NON_LINE: carries out the analysis for the time instants from 5 to 10, the initial state
corresponding to time 4.

**B - Example to show the interest of two different lists of time instants**

```python
listInst1 = DEFI_LIST_REEL(DEBUT=0.,
                           INTERVALLE=_F(JUSQU_A= 10., NOMBRE=10)),

evolNoli = MECA_NON_LINE (INCREMENT=_F(LIST_INST=listInst1))

                           INTERVALLE=_F(JUSQU_A= 30., NOMBRE=10))

```

The first MECA_NON_LINE carries out the analysis for the time instants from 1 to 10. The initial
state, of order number 0, is virgin (all the fields are zero).

The second MECA_NON_LINE carries out the analysis of the time instants 21 to 30. The initial state
corresponds to time instant 10 of the first MECA_NON_LINE (last time instant computed in the
first MECA_NON_LINE). This initial state corresponds, for this second MECA_NON_LINE, to
time instant 20 (INST_INIT=20.).

The use of a non-zero initial state will change the computation of the thermal strain.
If there is a non-zero initial state, then the computation of the thermal strain is purely incremental.

If one uses an initial state whose model is different from the analysis model supplied in
the operator, one automatically proceeds to the passage between the two models:

- If the analysis model is included in the model given in the initial state, the data
of the initial state are simply copied mesh cell by mesh cell for all the fields
- If the model given in the initial state is included in the analysis model, one begins
by copying the values of the initial state for the common mesh cells and then completes with the
zero value. One must be careful of the meaning that a zero initial
internal variable can have in the analysis

The keywords DEPL, SIGM and VARI make it possible (respectively) to give an initial field of displacement, of
stresses and of internal variables.

Other fields are available only in certain modellings:

- The keyword STRX gives the field of forces and of displacements corresponding to the structural
elements

If a result given by the keyword EVOL_NOLI is also given, the fields above come and
overload it.

If one of these fields is not specified, it is taken as zero by default. They can for example
come from the command CREA_CHAMP [U4.72.04](doc:u4.72.04), or else have been read in a
file by the command LIRE_RESU [U7.02.01](doc:u7.02.01).

The field of stresses and of internal variables at the Gauss points, and the field of the displacements,
is a field at the nodes. If the fields are not defined on the correct
supports the conversions can be made automatically.
There is no condition imposed on the fields given by the user. They may very well
represent a non-equilibrated mechanical state and/or one which does not respect the constitutive law.
If the analysis has difficulty in converging in this case, the simplest thing is to create artificially
a zero initial stress state in order to force the selection of the incremental mode,
or to use a purely elastic matrix, which allows a certain convergence at the price
of a large number of iterations.

In large strains, the user wishing to use the GDEF_LOG formalism with an
initial stress field (ETAT_INIT) should refer to the test case SSNP159b. Indeed, in order to
impose an initial stress field, the user must give as input the stress
tensor defined in the logarithmic space $T$ (and not that of Cauchy
$\sigma$ ). The components of the latter being stored as internal
variables, one must use the keyword VARI.

If the material characteristics depend strongly on the command variables, one should
be careful about the selection of the initial state, at the risk of not converging. Indeed,
the elastic constitutive behaviours exist in two versions (see
[U4.51.11](doc:u4.51.11)). The "pure" elastic version is chosen automatically
by the code when there is no initial state; otherwise, one selects the incremental version.
Now, only the latter is effective if one has strong variations of the material characteristics
(elastic in this case) with respect to the command variables.

If one uses simultaneously a state coming from a complete result (keyword EVOL_NOLI) and the
*individual* definition of a field (for example the stresses), the overloading rule applies
and the fields given individually replace those present in the data structure
given as the initial state.

In the case of loadings of differential Dirichlet type DIDI, one gives under NUME_DIDI the
archiving order number of the mechanical state (displacements) which serves as a reference for the application
of these boundary conditions. By default one takes the mechanical state defined under
NUME_ORDRE or INST.

The factor keyword OBSERVATION makes it possible to post-process certain fields at the nodes or on the elements
on parts of the model at time instants of a list (called the observation list) generally finer

#### 12.3.1 Selection in the transient

For other fields, one must make a request for an evolution.

The selection for NOM_VARI works only for fields of type VARI_ELGA.

The keywords TOUT, GROUP_NO and GROUP_MA make it possible to define the geometrical support of

#### 12.3.4 Observation of an ELGA field

For an ELGA field, one begins by choosing the components, or the formula between the components, with
the keyword EVAL_CMP:

- If EVAL_CMP='VALE', one simply extracts the list of the components given by NOM_CMP or NOM_VARI.
- If EVAL_CMP='FORMULE', one evaluates the formula given by the simple keyword FORMULE.

If one applies a formula to the components, one will therefore have one value and therefore one observation;
otherwise, one will have as many observations as there are components in the list NOM_CMP or NOM_VARI.

Once the components, or the formula on the components, have been evaluated, by the keyword EVAL_ELGA, one
can:

- Extract these values on the integration points and sub-points with EVAL_ELGA='VALE'.
In this case, one must explicitly specify the integration point and sub-point by POINT
and SOUS_POINT. The integration sub-points appear for the structural elements
(beams, plates, shells, pipes, etc.).
- Request the extraction of the maximum EVAL_ELGA='MAX' or of the minimum EVAL_ELGA='MIN' over all the
points and sub-points of a mesh cell.

If one explicitly requests a point and a sub-point, one will have as many realisations as there are
points requested, multiplied by the number of components requested. On the other hand, if one requests
the maximum or the minimum, there will be a single observation per component requested.

Once the components (or the formula on the components) have been evaluated, as well as the extraction
point/sub-point, one can, by the keyword EVAL_CHAM:

- Extract these values on all the mesh cells with EVAL_CHAM='VALE'.
- Request the extraction of the maximum EVAL_CHAM='MAX', of the minimum EVAL_CHAM='MIN' or of the mean
EVAL_CHAM='MOY'
- Request the extraction of the minimum value in absolute value EVAL_CHAM='MINI_ABS' such that
MINI_ABS(-1,3,4,-12,-0.1) = 0.1
- Request the extraction of the maximum value in absolute value EVAL_CHAM='MAXI_ABS' such that
MAXI_ABS(-1,3,4,-12,-0.1) = 12

Here is an example to extract the maximum of the trace of the stress tensor on
GROUP_MA='TOTO':

```python
trace  = FORMULE(VALE='0.333*(SIXX+SIYY+SIZZ)', NOM_PARA=('SIXX','SIYY','SIZZ',));

OBSERVATION =_F( NOM_CHAM = 'SIEF_ELGA',
                 GROUP_MA = 'TOTO',
                 EVAL_CHAM = 'MAX',
                 NOM_CMP = ('SIXX','SIYY','SIZZ',),
                 EVAL_CMP = 'FORMULE',
                 FORMULE = trace,
                 EVAL_ELGA = 'MAX')
```

of name 'ANALYSE_MODALE' attached to the evol_noli data structure. The buckling modes

### 14.4 Selection in the transient

The time instants for which one wants to carry out a stability analysis are given by a list
of time instants supplied by LIST_INST or by a frequency PAS_CALC.

The selection is controlled by the keywords PRECISION and CRITERE, see
[U4.71.00](doc:u4.71.00).

In the absence of these keywords the criterion is computed at all the time steps.

### 14.5 Settings of the modal solver

The keyword OPTION makes it possible to choose the type of search:

- OPTION='PLUS_PETITE': the NMAX_CRIT eigenvectors and eigenvalues corresponding to the
smallest eigenvalues;
- OPTION='BANDE': the eigenvectors and eigenvalues for the critical loadings lying
in the band CHAR_CRIT;
- OPTION='CALIBRATION' gives only the number of eigenvalues for the critical loadings
lying in the band CHAR_CRIT;.

The keyword COEF_DIM_ESPACE (5 is its default value) makes it possible for the user to control the
size of the subspace in the Sorensen method (the size of the subspace is equal to the
multiplication of this coefficient by the value nbfreq supplied previously).
The interest being to be able to reduce this space in the case where one uses in addition
the operand DDL_STAB.

### 14.6 Selection of the matrices

The keyword RIGI_GEOM ('OUI' by default) gives the user the choice between carrying out a
search for generalised eigenvalues with the geometric matrix on the right-hand side or not
(case of large strains).

Choosing 'NON' means that the geometric stiffness matrix is replaced by the identity.

The keyword MODI_RIGI ('NON' by default) makes it possible to specify whether the global stiffness matrix
(and the geometric stiffness matrix if it is used) must be modified at the level of the
degrees of freedom which one lists with DDL_EXCLUS. This makes it possible, for example, for mixed
models, to conduct the stability analysis by excluding certain types of degree of freedom and by
correcting the global stiffness matrices so that the terms linked to these degrees of freedom do not:
come and disturb the search for instability. Other details are given in the paragraph
devoted to DDL_EXCLUS. If the list of excluded degrees of freedom is empty, then MODI_RIGI is
therefore of no use.

### 14.7 Selection of the degrees of freedom

The keyword DDL_EXCLUS (empty list by default) designates the set of degrees of freedom which one
wishes to set to 0 in the right-hand side of the search for generalised eigenvalues. It can
be used only under the condition RIGI_GEOM = 'NON' or if MODI_RIGI = 'OUI'.

In the case RIGI_GEOM = 'NON' and MODI_RIGI = 'NON', this makes it possible to impose additional
compatibility conditions on the eigenmodes and thus to carry out a
selective search. This is particularly suited to mixed formulations. In this case,
the elimination of the Lagrange multipliers on the right-hand side makes it possible to exclude the
parasitic modes with a dominant Lagrangian character and with negative eigenvalues.

In the case MODI_RIGI= 'OUI', this makes it possible to modify the stiffness matrix (and, if need be,
the geometric stiffness matrix) so as to conduct the stability analysis without taking
account of the excluded degrees of freedom. For example, one must use this option for the coupled
fluid-structure models (formulation $(u,p,\phi )$ , *confer* documentation
[R4.02.02](doc:r4.02.02), which can be used with DYNA_NON_LINE but not STAT_NON_LINE) in order to
exclude the fluid degrees of freedom because the global assembled stiffness matrix is singular
for these degrees of freedom.

For more details, the user may usefully refer to the documentations
[U2.06.11](doc:u2.06.11) and [U2.08.04](doc:u2.08.04).

The keyword DDL_STAB designates the set of irreversible degrees of freedom in the stability
study which one wishes to carry out with CRIT_STAB . It can be used only under the
conditions: TYPE='STABILITE' and RIGI_GEOM='NON' .
This makes it possible to carry out a study of the sign of the second derivative of the energy, at the loading
considered, by looking only at the perturbations liable to increase the degrees of freedom
declared in DDL_STAB . This in order to respect the mechanical conditions of irreversibility.

### 14.8 Selection of the criteria

The keyword SIGNE makes it possible to specify which type of instability criterion will be used. This criterion
will make it possible to trigger a clean stop (database saved) of the non-linear analysis in the event
of instability, if the user specifies it, under [DEFI_LIST_INST](doc:u4.34.03).

Without this declaration under DEFI_LIST_INST, even in the event of a detected instability the non-linear
analysis will try to continue: this is the default mode.
For the stability analyses without geometric stiffness matrix, the instability criterion
is that a critical load tends towards 0, or changes sign. In this case, the keyword SIGNE
is of no use.

On the other hand, for the cases where the geometric stiffness matrix is used, this keyword SIGNE
is useful. With the default value SIGNE = ' POSITIF_NEGATIF' , the solution will be declared
unstable in the cases where a critical load comes to lie between -1 and 1. If the user
chooses the option 'NEGATIF' then the instability domain will be bounded by the values -1 and 0.
Conversely, the option 'POSITIF' will define the values 0 and 1 as limits of the

instability domain. The default choice is the most conservative, but in certain cases where one can
clear a priori part of the instability domain, it is then relevant to modify the
criterion with the keyword SIGNE. One recalls that the critical load computed by CRIT_STAB, in the
case where the geometric stiffness matrix is taken into account, is equal to the multiplying
coefficient of the imposed loading which makes the problem unstable. Therefore if the value computed
by CRIT_STAB is equal to 1 this means that one is unstable for the imposed load.
If one obtains the value -1, then the instability will occur for an imposed load of the same value
but of opposite sign. Therefore, for known imposed loadings evolving in a monotonic way, it
is easy to restrict the instability domain because one knows that the loading cannot change
sign. On the other hand, for cyclic or arbitrary loadings, it is safer not to
restrict the instability domain.

The keyword PREC_INSTAB makes it possible to define the relative tolerance with which one wishes
to check the instability criterion, which is parameterised by the previous keyword SIGNE .

## 16 Use of substructuring

```text
◇ SOUS_STRUC = _F(
        ◆ CAS_CHARGE = text,
        ◆ / TOUT = "OUI" (ou non renseigné),
          / SUPER_MAILLE = ma,
        ◇ FONC_MULT = fonction / formule / nappe,
    ),
```

The factor keyword SOUS_STRUC makes it possible to specify which are the loadings to be used
for the static substructures, which then necessarily form part of the model.
In its absence, the loadings on the substructures are zero.

These loadings are added to the "finite element" loadings which can be applied
on the rest of the model. For more precision concerning the use of y
substructures (linear elastic) in a non-linear structure, one should refer
to the documentation [U2.07.02](doc:u2.07.02) and to the test case ssnv193a.

CAS_CHARGE gives the name of the load case to be used. See the operator [ref:MACR_ELEM_STAT <U4.62.01>].

The keyword TOUT = 'OUI' makes it possible to assign the loading to all the
substructures of the model.

The factor keyword SUPER_MAILLE makes it possible to assign the loading only to certain
substructures.

FONC_MULT=:math:{f}_{i} is the function of time multiplying the loading
specified at the i-th occurrence of SOUS_STRUCT.

The behaviour of this keyword is the same as for its occurrence in EXCIT.

## 17 Monitoring of the analysis

This section groups the various tools making it possible to monitor an analysis: measurement of the times,

### 17.1 Real-time monitoring of values

### 17.2 Measurement of the times

```text
⟐ MESURE = _F(
     ◇ TABLE = / "NON" (par défaut),
               / "OUI",
     ◇ UNITE = unit,
  ),
```

#### 17.2.1 General principles

The command MESURE makes it possible to output measurement information on the analysis:

- either in a table of name 'STAT' recoverable by [RECU_TABLE](doc:u4.71.02)
(see keyword OBSERVATION)
- or in a file in CSV format whose logical unit is given by the keyword UNITE

It should be noted that these measurements are also output in the usual .mess file.

#### 17.2.2 Contents of the table or of the generated file

The table is indexed by the time step: presence of a column 'INST' of real type. Each
type of measurement can exist in two forms (simultaneously or not):

- a CPU time (elapse): in this case, the column will contain a real and will have as its name the type
prefixed by Time_;
- a number of occurrences (for example the number of Newton iterations): in this case, the column
will contain an integer and will have as its name the type prefixed by Count_;
- a memory footprint (vmpeak, in MB): in this case the column will contain an integer and will have
as its name the type prefixed by Count_;

| Type of measurement | Time | Occurrences | Description |
| --- | --- | --- | --- |
| Compute | Yes | No | Total computation time |
| Lost_Time | Yes | No | Time "lost" because of the cuttings of the time step |
| Time_Step | Yes | Yes | Time and total number of time steps |
| Newt_Iter | Yes | Yes | Mean time of a Newton iteration per time step and number of iterations per time step |
| Store | Yes | Yes | Time for archiving and number of archivings in total |
| Post | Yes | Yes | Time taken for the post-processing (buckling, … ) and number of post-processings in total |
| Integrate | Yes | Yes | Time for the integration of the constitutive behaviour and number of integrations of the constitutive behaviour per time step |
| Factor | Yes | Yes | Time for the factorisation of the matrix and number of factorisations per time step |
| 2nd_Member | Yes | Yes | Time for the construction of the right-hand side and number of constructions per time step |
| Solve | Yes | Yes | Time for the solution of the linear systems and number of solutions per time step |
| Cont_Geom | Yes | Yes | Number of geometrical updates and time spent in the pairing for the contact |
| Cont_Algo | Yes | Yes | Number of contact iterations and time spent in the solution (discrete methods) |
| Cont_Prep | Yes | Yes | Number of preparations of the contact and time spent in these preparations (for the continuous method: creation of the elements, creation and filling of the input field, etc.) |
| Cont_Elem | Yes | Yes | Number and time spent in the elementary computations for the contact (continuous method) |
| Matr_Asse | Yes | No | Time spent in the creation of the matrices |
| Cont_NCont | No | Yes | Number of nodes/points/patches in contact |
| Cont_NFric | No | Yes | Number of nodes/points/patches in friction |
| LineSearch | No | Yes | Number of line-search iterations |
| Cont_Cycl1 | No | Yes | Number of cyclings of contact type (see R5.03.52) |
| Cont_Cycl2 | No | Yes | Number of cyclings of sliding/sticking type (see R5.03.52) |
| Cont_Cycl3 | No | Yes | Number of cyclings of forward/backward sliding type (see R5.03.52) |
| Cont_Cycl4 | No | Yes | Number of cyclings of flip/flop type (continuous method, see R5.03.52) |

Examples:

- Parameter Count_Cont_NCont: number of nodes in contact;
- Parameter Time_Factor : time spent in the factorisation.

### 17.3 Displays

```text
⟐ AFFICHAGE = _F(
     ◇ INFO_RESIDU = / "NON" (par défaut),
                     / "OUI",
     ◇ INFO_TEMPS = / "NON" (par défaut),
                    / "OUI",
     ◇ UNITE = unit,
     ◇ PAS = int,
  ),
```

The factor keyword AFFICHAGE makes it possible to customise the display of the convergence table in y
STAT_NON_LINE and DYNA_NON_LINE.

If this keyword is not supplied, the table is built according to the various analysis
options (line search, piloting, contact, etc.) and with INFO_RESIDU='NON'.

If UNITE is supplied, the convergence table will be duplicated in the file of unit *unit*,
in .csv format (the separator being the comma).

PAS indicates the update frequency of the display in the message file. This operand
makes it possible to reduce the volume of the printouts, particularly in explicit dynamics.
It has no influence on the updating of the file in .csv format (keyword UNITE).

The keyword INFO_RESIDU makes it possible to add a column for each residual evaluated
(RESI_GLOB_RELA, RESI_GLOB_MAXI, RESI_COMP_RELA and RESI_REFE_RELA). This column will indicate
the node where the residual is maximum, which can help the user when there are difficulties
of convergence. For example, to see whether the material has been badly defined with an incorrect value
on an element.

The keyword INFO_TEMPS makes it possible to add a column which gives the time spent in
the Newton iteration.
