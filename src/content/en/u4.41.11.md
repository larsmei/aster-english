# u4.41.11 Operator MODI_MODELE_XFEM

## 1 Purpose

Create a new model by introducing specific finite elements which can be crossed by a crack of X-FEM type, starting from an existing model.

This operator makes it possible to modify certain classical finite elements into enriched finite elements; the elements to be modified have been determined beforehand by the operator DEFI_FISS_XFEM [U4.82.08](doc:u4.82.08).

The new model thus defined may be used in the rest of the analyses as input data:

- to the operators MECA_STATIQUE [U4.51.01](doc:u4.51.01) or STAT_NON_LINE [U4.51.03](doc:u4.51.03) if the initial model is a mechanical model;
- to the operator THER_LINEAIRE [U4.54.01](doc:u4.54.01) if the initial model is a thermal model.

The operator produces a concept of type modele.

## 2 Syntax

```text
modele = MODI_MODELE_XFEM(
    ◆ MODELE_IN = modele,
    ◆ / FISSURE = fiss_xfem,
      / MODELE_THER = modele,
    ◇ INFO = / 1 (par défaut),
             / 2,
    ◇ CONTACT = / "SANS" (par défaut),
                / "STANDARD",
                / "MORTAR",
    ◇ PRETRAITEMENTS = / "AUTO" (par défaut),
                       / "SANS",
                       / "FORCE",
    ◇ DECOUPE_FACETTE = / "DEFAUT" (par défaut),
                        / "SOUS_ELEMENTS",
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```
## 3 Operands

### 3.1 Operand MODELE_IN

```text
♦    MODELE_IN        =    mo
```
mo: name of the initial model (also called the “sound model”) built on the mesh which served to define the crack beforehand by the operator DEFI_FISS_XFEM [U4.82.08](doc:u4.82.08).

This initial model, built with the operator AFFE_MODELE [U4.41.01](doc:u4.41.01), serves as the basis for the creation of the new model. It is necessary to choose a different name for the new model; modification of an existing model is not allowed, and the check is carried out during the syntax analysis of the command file.

### 3.2 Operand FISSURE

```text
♦     / FISSURE        =    (fiss1, ...)
```
(fiss1,...): list of the names of the cracks defined beforehand by the operator DEFI_FISS_XFEM [U4.82.08](doc:u4.82.08). The number of cracks in a model is not limited.

### 3.3 Operand MODELE_THER

```text
/ MODELE_THER    =     modxth
```
The use of this keyword is of interest only in the particular case of chained thermo-mechanical analyses with X-FEM. In this case the following checks will be carried out by the operator:

- modxth must be the thermal X-FEM model (already produced by the operator MODI_MODELE_XFEM, with the keyword FISSURE) with which the linear thermal problem is solved by the operator THER_LINEAIRE [U4.54.01](doc:u4.54.01);
- the sound model mo must be a mechanical model, and must have been defined on the same mesh as the enriched thermal model modxth

The model produced by the operator is a mechanical model.

### 3.4 Operand CRITERE

```text
♦    CRITERE        =    crit
```
crit: real value of the criterion making it possible to cancel the enriched degrees of freedom when the crack passes close to a node. When the crack cuts a 3D finite element into two volumes, the ratio between the smallest volume and the largest volume must not exceed this criterion; otherwise, this can cause conditioning problems in the stiffness matrix, and lead to zero pivots. Thus, if the criterion is exceeded, the degrees of freedom liable to lead to zero pivots are eliminated automatically. The default value of the criterion is based on simple tests [R7.02.12](doc:r7.02.12).

### 3.5 Operand CONTACT

```text
♦    CONTACT        =    /    ‘SANS’

/    ‘STANDARD’

/    ‘MORTAR’
```
This operand makes it possible to indicate whether interface forces exist between the lips of the crack: these may be contact, or cohesive forces.

If this is the case, a contact load or cohesive forces must then be introduced by the command DEFI_CONTACT. For all the formulations, it is the value STANDARD which must be specified, except for the cohesive law CZM_LIN_MIX, which is a mixed cohesive law suited to linear finite elements (see R5.03.55]), for which one specifies the value MORTAR. Indeed, the latter requires the addition of several multiplier fields, which must therefore be specified when modifying the model in order to create the appropriate finite elements.

### 3.6 Operand PRETRAITEMENT

```text
♦    PRETRAITEMENT    S    =    /    ‘AUTO’

/    ‘SANS’

/    ‘FORCE’
```
This operand makes it possible to indicate whether the algebraic preconditioning algorithms must be activated (modification of the stiffness matrix). By default, the choice is automatic ('AUTO'). One can either deactivate them ('SANS'), or force them ('FORCE').

**Note**: if there are quadratic finite elements in the model, the preconditioning algorithms will be activated.

### 3.7 Operand DECOUPE_FACETTE

```text
♦    DECOUPE_FACETTE    =    /    ‘DEFAUT’

/    ‘SOUS_ELEMENTS’
```
This operand makes it possible to activate an alternative procedure ('SOUS_ELEMENTS') for constructing the contact facets, other than the default one ('DEFAUT').

The alternative procedure makes it possible in particular to treat the case of quadratic facets.

### 3.8 Operand INFO

| / 1: | printout on the 'MESSAGE' file of 1. The stages of the analysis 2. The number of finite elements of the model |
| --- | --- |
| / 2: | the same printout + printout, for each mesh cell, of the type of enriched mesh cell and of its finite-element type number. |
