# u4.55.01 Operator FACTORISER

## 1 Purpose

**Factorise** an assembled matrix or **build a preconditioning matrix**.

The matrix produced by this operator is supplied to the operator RESOUDRE[U4.55.02] in order to solve the linear systems.

This operator makes it possible:

1. Either to factorise the assembled matrix (into a product of two triangular matrices) for the direct methods,
2. Or to build a preconditioning matrix for the iterative methods, with the aim of accelerating convergence during the solution.

This command is a mandatory preliminary step before calling the solution command RESOUDRE.

Produces (or enriches) a data structure of type matr_asse.

## 3 Operands

The choice of the solution method is made beforehand in the command NUME_DDL (keyword METHODE).

Five methods are possible: 'MULT_FRONT', 'MUMPS', 'GCPC', 'PETSC' and 'LDLT'.

### 3.1 Keyword reuse = matas

For the sake of simplifying the programming and also in order to save disk space, the “in-place” factorisation of the matrix (use of reuse) is in general mandatory.

The exception is the pair ('GCPC', 'LDLT_INC'). In this case, it is forbidden to use reuse.

### 3.2 Operand MATR_ASSE

```text
♦    MATR_ASSE= mat
```

Name of the assembled matrix to be factorised or to be preconditioned, depending on the method.

For the methods 'LDLT', 'MULT_FRONT' and 'MUMPS', this matrix may be real or complex, symmetric or not. On the other hand, for the methods 'GCPC' and 'PETSC', this matrix must be real. For 'GCPC', the matrix must also be symmetric.

### 3.3 Operands STOP_SINGULIER, NPREC, TYPE_RESOL , PCENT_PIVOT, PRETRAITEMENTS, GESTION_MEMOIRE, ACCELERATION, LOW_RANK_SEUIL, PRE_COND, NIVE_REMPLISSAGE, REMPLISSAGE, RENUM, REAC_PRECOND and ELIM_LAGR

These keywords are described in [U4.50.01](doc:u4.50.01).

### 3.4 Operand TITRE

```text
◊    TITRE= titre
```

Title which one wants to give to the result [U4.02.01](doc:u4.02.01).

### 3.5 Operand INFO

```text
◊    INFO=
```

1: no printout

### 3.6 Partial factorisation (LDLT method)

For the method 'LDLT', the operator makes it possible to factorise the matrix only partially. This possibility makes it possible to factorise the matrix in several goes (several jobs), or even to modify on the fly the last rows of this factorised matrix. Today, this feature is of little interest except for certain methods (known as discrete) of frictional contact, where one has, deliberately, placed in the last rows of the matrix the terms concerning the nodes liable to be in contact. Thus, as the pairing iterations proceed, the relations between these nodes changing, one deletes and then recomputes only these last contributions of the factorised matrix. It is a typical example where the clever use of a rather crude algorithm can bring major gains (in time).

```text
◊    /    BLOC_DEBUT= bd
```

bd: partial factorisation from the bd-th block inclusive.

```text
/    DDL_DEBUT= dd
```

dd: partial factorisation from the dd-th equation inclusive (in the internal numbering established by the operator NUME_DDL [U4.61.11](doc:u4.61.11)).

```text
◊    /    BLOC_FIN= bf
```

bf: partial factorisation up to the bf-th block inclusive.

```text
/    DDL_FIN= df
```

df: partial factorisation up to the df-th equation inclusive (in the internal numbering established by the operator NUME_DDL [U4.61.11](doc:u4.61.11)).

BLOC_DEBUT and DDL_DEBUT

- in the absence of the keywords BLOC_DEBUT and DDL_DEBUT, the matrix will be factorised starting from its first row.
- if the argument bd of the keyword BLOC_DEBUT is negative or zero, the matrix will be factorised starting from the first block. Otherwise, one performs a partial factorisation starting from the bd-th block inclusive.
- if the argument dd of the keyword DDL_DEBUT is negative or zero, the matrix will be factorised starting from the first equation. Otherwise, one performs a partial factorisation starting from the dd-th equation inclusive.
