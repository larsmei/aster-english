# u4.66.03 Operator CALC_FORC_AJOU

## 1 Purpose

This command makes it possible to compute the effect of the hydrodynamic overpressure due to the entrainment motion of the structure in seismic analysis, in which one decomposes the total motion into an entrainment motion and a relative motion. The analysis of this force is carried out in the same way as that of the added mass by thermal analogy, but instead of taking into account only the relative motion, one obtains an added force on the right-hand side, also projected onto the modes of the structure without the fluid, in order to take the entrainment motion into account.

The analysis of the added masses [R4.07.03](doc:r4.07.03) by CALC_MATR_AJOU [U4.66.01](doc:u4.66.01) and that of the added forces by CALC_FORC_AJOU can be launched simultaneously with the aid of the macro-command MACRO_MATR_AJOU [U4.66.11](doc:u4.66.11).

Produces a concept of type vect_asse_gene_R

## 3 Operands

### 3.1 Operand MODELE_FLUIDE

```text
♦    MODELE_FLUIDE = fluide
```
**Thermal** model which one assigns to the part of the mesh which corresponds to the fluid. The boundary elements at the fluid/structure interface must be present in the fluid model. It is on this model that one solves the Laplace equation with a boundary condition of "fluid flux" type, in order to have the pressure field throughout the fluid and *a fortiori* the pressure field at the fluid/structure interface.

The nodes of the elements of the fluid mesh must all be numbered in such a way that the Jacobian of the element is of positive sign over the whole fluid mesh.

### 3.2 Operand MODELE_INTERFACE

```text
♦    MODELE_INTERFACE = interf
```
**Thermal** interface model gathering all the boundary elements defining the fluid/structure interface. It is on this model that one computes the terms of the added matrices.

The analysis depends on the **orientation** of the normal of these interface elements. One must ensure that this normal is oriented, on **all** these elements, from the structure towards the fluid (adopted convention).

If the fluids bathing the structure are of different densities, one must define the interface model by as many mesh-cell groups, geometrically non-coincident, as there are fluids in contact with the structure. For example, a pipe may have its inner surface in contact with a fluid of density 1, and its outer surface in contact with a fluid of density 2. The interface model is therefore built on two mesh-cell groups which are geometrically non-coincident, one in contact with the fluid of density 1 (interfa1) and the other in contact with the fluid of density 2 (interfa2).

### 3.3 Operands CHAM_MATER / CHARGE

```text
♦    CHAM_MATER = matflui
```
Material field defining the fluid immersing the structure. This material is defined by equivalent **thermal** characteristics in the operator DEFI_MATERIAU [U4.43.01](doc:u4.43.01). The thermal conductivity (keyword LAMBDA) is **always taken equal to 1.** The specific heat (keyword RHO_CP) plays the role of **density of the fluid.**

```text
♦    CHARGE = charge
```
Thermal load of type [char_ther] necessary for the solution of the linear system arising from the Laplace equation in the fluid. One must impose an **arbitrary** temperature (which in fact plays the role of a pressure) on an **arbitrary** node of the fluid mesh, in order to make the system non-singular. This operation is carried out with the operator AFFE_CHAR_THER [U4.44.02].

### 3.4 Operands MODE_MECA / MODELE_GENE

```text
♦    /    MODE_MECA = modes
```
Dynamic modes computed on the structural model. If one has several disconnected structures immersed in the same fluid, for which one wants to determine the added matrices including the coupling terms through the fluid, the structural model which one defines gathers all of the immersed structures. The modes used by the operator are the modes computed for the global structure.

```text
/    MODELE_GENE = modgen
```
Generalised model built by the operator DEFI_MODELE_GENE [U4.65.02](doc:u4.65.02). This keyword is to be used when one carries out an analysis by dynamic substructuring, and when one wants to compute the added mass matrix coupling all of the substructures. In this case, the substructures may be in different mesh files, these files themselves possibly being distinct from the fluid mesh file. The substructures which exhibit a repetitiveness within the fluid need be meshed only once, but one will take care, at the level of the fluid mesh, to mesh all the fluid/structure interfaces. Moreover, one must ensure that the fluid interface nodes coincide as well as possible with the structure interface nodes, in order to be able to copy, on the basis of a geometric proximity criterion, the values of the structural displacement field onto the fluid interface nodes (see operand DIST_REFE).

### 3.5 Operand DIST_REFE

Reference distance to be supplied when one carries out an analysis of **added force** on a generalised model. This distance is an absolute geometric criterion intended for copying values of structural displacements into a thermal fluid model, in order to solve there the Laplace equation of the unsteady pressure field. By default, it is equal to 10–2 m.

### 3.6 Operand NOEUD_DOUBLE

```text
◊    NOEUD_DOUBLE = 'OUI'
```
This operand is to be used when one carries out an analysis of **added force** from a generalised model which includes a substructure meshed by a wire or surface mesh (*i.e.* without thickness, such as a beam or a shell) and surrounded by two fluids. In this case one must, at the mesh level, duplicate the nodes of the fluid interfaces with respect to those of the structure, in order to be able to compute the jump in hydrodynamic pressure on either side of the structure (*cf.* figure below).

### 3.7 Operand POTENTIEL

```text
◊    POTENTIEL = phi
```
Steady (thermal) potential necessary for the analysis of the added damping and of the added stiffness of the structure subjected to a potential flow. This potential is produced by the operator THER_LINEAIRE [U4.54.01](doc:u4.54.01).

### 3.8 Operand DIRECTION

```text
♦    DIRECTION = (d1 , d2 , d3 , r1 , r2 , r3)
```
Components of a vector giving the direction of the entrainment earthquake in the global frame. It is a list of three reals if the imposed accelerograms are only translations. If one also imposes rotational accelerations, a list of six reals is expected (valid for modellings with discrete elements).

### 3.9 Description of the entrainment motion

#### 3.9.1 Operand MONO_APPUI

```text
♦    /    MONO_APPUI = 'OUI'
```
The structure is excited uniformly at all the supports (rigid-body entrainment motion).

#### 3.9.2 Multi-support excitation

In this case, the accelerations undergone by all the anchor points of the structure studied are not necessarily identical and in phase.

##### 3.9.2.1 Operand MODE_STAT

```text
/    ♦    MODE_STAT = mode
```
Static modes of the structure: concept of type mode_meca produced by the operator MODE_STATIQUE [U4.52.14](doc:u4.52.14) with the option DDL_IMPO. They correspond to the 3 or 6 * nb_supports static modes, where nb_supports is the number of different accelerograms undergone by the structure.

**Note:**

*If the structure is subjected only to translations, there are then 3 nb_supports static modes.*

##### 3.9.2.2 Operands NOEUD / GROUP_NO

```text
♦    /    NOEUD = no
/    GROUP_NO = grno
```
List of nodes (no) or node groups (grno) of the structure subjected to the seismic excitation: these nodes carry the degrees of freedom of the supports of the structure to which the imposed motions are applied.

### 3.10 Operand NUME_DDL_GENE

> ◊    NUME_DDL_GENE = numgen

Generalised numbering based on the mechanical modes of the global structure. The presence of this operand makes it possible to compute an added mass matrix of type matr_asse_gene_R. It must necessarily be present if one subsequently wants to carry out a modal, harmonic or transient analysis.

### 3.11 Factor keyword SOLVEUR

See [U4.50.01](doc:u4.50.01).

### 3.12 Operand AVEC_MODE_STAT

Makes it possible to switch off the analysis of the added-mass terms on the static modes contained in the modal basis of the substructures in the case of an analysis with a generalised model (*cf.* [§3.4]).

### 3.13 Operand NUME_MODE_MECA

Makes it possible to specify a list of numbers of modes retained for the analysis.

### 3.14 Operand INFO

```text
◊    INFO =
```
Indicates the printout level of the results of the operator on the MESSAGE file.

1: no printout

2: printout of the added-force terms.
