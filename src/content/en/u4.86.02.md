# u4.86.02 Macro-command POST_CZM_FISS

## 1 Purpose

This macro-command makes it possible to carry out the following two types of post-processing:

- supply, at each loading increment, information on the length of a straight 2D cohesive crack (positions of the crack tip and of the cohesive tip). More precisely, the macro supplies the distance between an origin point POINT_ORIG and each of the two tips in the direction and the sense of the direction vector VECT_TANG, as well as the distance between the two tips (size of the cohesive zone);
- compute and store in a map the stress triaxiality in the solid elements directly neighbouring the cohesive elements.

## 2 Syntax

```text
/ carte
/ table = POST_CZM_FISS(
    ◆ OPTION = / "LONGUEUR",
               / "TRIAXIALITE",
    ◆ RESULTAT = evol_noli,
    # Si: equal_to("OPTION", 'LONGUEUR')
        ◆ GROUP_MA = grma,
        ◆ POINT_ORIG = float,
        ◆ VECT_TANG = float,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Operand RESULTAT

```text
♦ RESULTAT        = resu
```

Name of the result concept of a non-linear analysis with cohesive elements.

### 3.2 Operand OPTION

```text
♦ OPTION        = /'LONGUEUR'
/'TRIAXIALITE'
```

Choice of the type of post-processing carried out by the macro-command

### 3.3 Operand GROUP_MA

```text
♦ GROUP_MA         = group_ma
```

Name of the group of cohesive mesh cells with the modellings PLAN_JOINT, PLAN_INTERFACE, AXIS_JOINT or AXIS_INTERFACE. And having one of the cohesive constitutive behaviours: CZM_OUV_MIX, CZM_TAC_MIX, CZM_LIN_REG, CZM_EXP_REG.

This operand is possible only when OPTION = 'LONGUEUR'.

### 3.4 Operand POINT_ORIG

```text
♦ POINT_ORIG         = point

Point initial de la fissure cohésive: deux composantes réelles dans le plan (X,Y) (voir figures ci-dessous)
```

This operand is possible only when OPTION = 'LONGUEUR'.

### 3.5 Operand VECT_TANG

```text
♦ VECT_TANG         = vecteur

Vecteur directeur: deux composantes réelles dans le plan (X,Y) (voir figures ci-dessous).
```

This operand is possible only when OPTION = 'LONGUEUR'.

## 4 Concept produced

### 4.1 Case OPTION = 'LONGUEUR'

As output one creates a table of type table_sdaster containing four columns:

INST: the time instant of the analysis

LONG_FIS: distance between the crack tip and the reference point (LF see figure2).

LONG_TOT: total length (LF + LZC see figure2)

LONG_COH: size of the cohesive zone (LZC see figure2)

### 4.2 Case OPTION = 'TRIAXIALITE'

The macro-command produces in this case a map (of NEUT_R with one component X1) sized to the number of mesh cells carrying cohesive elements. For each mesh cell, the value stored is that of the stress triaxiality, read and averaged in the elements of the solid directly neighbouring (by edge in 2D or by face in 3D) this mesh cell. The stress field used for this post-processing is the one which corresponds to the last archived time step in the evol_noli supplied under the keyword RESULTAT.

## 5 Scope of use

### 5.1 Case OPTION = 'LONGUEUR'

The evol_noli supplied under the keyword RESULTAT must be the result of a 2D non-linear analysis with cohesive elements. The crack must furthermore be straight.

The command issues an error or alarm message if the user goes outside the scope of use:

- The user is required to define properly the half-line from the point POINT_ORIG (aligned with the GPs) and the direction vector VECT_TANG (collinear with the line of the GPs). One checks these conditions but also that there do indeed exist GPs on the half-line in question (sense of the vector properly chosen).
- In the case where one of these three conditions is not satisfied, one displays an error message indicating the problem encountered as well as the extrema of the coordinates of the GPs in order to help the user define the half-line properly.
- As defined, the lengths are valid only if the cohesive zone is connected. If this is not the case, an alarm message is displayed.
- If one observes that the cohesive zone is composed of only three GPs or fewer, one displays an alarm message stating that the mesh does not seem fine enough to capture this zone correctly (see doc U2.05.07, advice on the use of cohesive models).

### 5.2 Case OPTION = 'TRIAXIALITE'

This post-processing is available in 2D and in 3D. The modellings supported in the solid and on the cohesive interface are summarised in the table below.

| Modellings supported in the solid | Modellings supported on the cohesive interface |
| --- | --- |
| 'D_PLAN', 'C_PLAN', 'AXIS', '3D' | 'PLAN_JOINT', 'AXIS_JOINT', '3D_JOINT' |
| 'PLAN_INTERFACE', 'AXIS_INTERFACE', '3D_INTERFACE' |  |
| 'PLAN_INTERFACE_S', 'AXIS_INTERFACE_S', '3D_INTERFACE_S' |  |

## 6 Details of the command

### 6.1 Case OPTION = 'LONGUEUR'

The cohesive crack is represented in figure 1; it is assumed straight, and it is decomposed into three distinct zones: sound, cohesive (or damaged) and free surface (or cracked). One represents respectively in red, green and blue the Gauss points (GPs) of these zones.

From these zones one defines a cohesive tip (white point) and a crack tip (black point). The macro gives the distance between the origin point POINT_ORIG (red point) and each of the two tips in the direction and the sense of the direction vector VECT_TANG (red vector) as well as the distance between the two tips.

![Figure](/figures/u4.86.02/10000201000003EB000001C73380AB1D040B53AC.png)

**Figure1**: Diagram of the cohesive crack and of its Gauss points.

In order to define the position of the tips (see figure2) one relies on the geometrical coordinates of the GPs and on the field of the internal variable VARI_ELGA, component V3 of the CZM laws, which takes the value 0 if the GP is sound, 1 if the GP is damaged and 2 if the GP is cracked. For each of these three states one defines Dmin and Dmax corresponding to the minimum and maximum distances with respect to the origin point. The crack tip is positioned between the broken GPs and the damaged GPs, the cohesive tip is positioned between the damaged GPs and the sound GPs.

![Figure](/figures/u4.86.02/1000020100000460000000FC6D2CB90697BCF4C3.png)

**Figure2**: Diagram of the GP field of a straight 2D cohesive crack with the position of the tips (as an example one draws Dmin and Dmax for the damaged GPs).

### 6.2 Case OPTION = 'TRIAXIALITE'

For this option, the operation of the macro-command is as follows.

1. Detection of the presence of cohesive elements (see the modellings supported in the paragraph “scope of use”) in the model which was used to produce the evol_noli supplied under the keyword RESULTAT. If no cohesive element is detected, a fatal error message is issued.
2. Recovery of the stress field corresponding to the last archived time step.
3. Carrying out of a loop over the mesh cells assigned cohesive elements. During this loop, for each cohesive mesh cell, one identifies the mesh cells of the solid which are directly neighbouring it (by face in 3D, and by edge in 2D) by means of the data structure sd_voisinage. One makes sure that this cohesive mesh cell has only one or two neighbouring mesh cells of this type (the zone of the mesh assigned the cohesive elements must therefore: either cross the structure completely, or lie on a part of the boundary, as is for example the case when one models a symmetry condition). Once these neighbouring mesh cells have been identified, one computes the stress-triaxiality ratio at all the Gauss points of these neighbouring elements. One then carries out the arithmetic mean of the triaxiality at the Gauss points: by element and then over the number of neighbours if the current cohesive mesh cell has 2 neighbours in the solid. Finally, in the map produced by the macro-command, one stores for the current cohesive mesh cell the value of this averaged triaxiality.

The map produced by the macro-command may then be used as a command variable in the operator AFFE_MATERIAU (AFFE_VARC / CHAM_GD) [U4.43.03](doc:u4.43.03) in order to make the parameters of the cohesive law vary with the triaxiality.
