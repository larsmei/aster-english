# u3.03.01 Interface of the IDEAS mesh file with Aster

**Summary:**

The purpose of this document is to describe the principle of the IDEAS (SDRC) interface with *Aster*.

This interface is activated in *Aster* by the procedure PRE_IDEAS [U7.01.01](doc:u7.01.01).

The datasets of the I-DEASTM universal file read by the IDEAS–*Aster* interface are dataset 151 (title), datasets 15, 781 or 2411 (coordinates of the nodes), datasets 71, 780 or 2412 (description of the mesh cells), datasets 752, 2417, 2429, 2430, 2431, 2432, 2435 or 2467 (node groups or mesh-cell groups) and dataset 735 (nodes or mesh cells attached to the curves, mesh areas and mesh volumes).

As a result, the I-DEASTM versions currently supported are versions 4, 5 and 6 as well as versions 1., 2., 3., 4., 5., 6., 7., 8., 9. and 10. of Master Series.

## 1 IDEAS vocabulary

'geometry'

set of geometric entities on which the mesh is supported. They may be curves ('curve'), surfaces ('mesh area') or volumes ('meshvolume').

'curve'

line geometric entity which may be composed of sub-entities, segments, circular arcs, options. The mesh cells which are supported on these sub-entities are segments with 2 or 3 nodes.

'mesh area'

surface geometric entity bounded by 'curves', on which the surface mesh cells are supported: triangles with 3 or 6 nodes or quadrangles with 4 or 8 nodes.

'mesh volume'

volume geometric entity bounded by 'meshareas'. The volume mesh cells which are supported on these sub-entities are hexahedra with 8 or 20 nodes, pentahedra with 6 or 15 nodes or tetrahedra with 4 or 10 nodes.

'group'

an arbitrary grouping (chosen by the user) of geometric entities, of nodes or of mesh cells; the user gives it a name.

'universal file'

the formatted file produced by IDEAS constitutes the data file of the interface. It contains the whole mesh (nodes and mesh cells), the geometric entities, the groups and the geometric-entity–mesh associations.

'geometric entity – mesh association'

list of nodes or of mesh cells supported on a given geometric entity.

- for each 'curve', the nodes which compose it,
- for each 'mesharea':
- the nodes which compose it,
- in 2D the mesh cells which compose it.
- for each 'meshvolume':
- the nodes and the mesh cells which compose it.
- the nodes which compose it,
- in 3D the mesh cells which compose it.

## 2 Purpose of the mesh interface

The information contained in the IDEAS universal file (for versions 4, 5 and 6 and versions 1., 2., 3., 4., 5., 6., 7., 8., 9. and 10. of Master Series) is transcribed into the mesh file. This concerns in particular the coordinates of the nodes, the mesh cells, and the node groups and mesh-cell groups. These are most often simple transfers of sub-files, except for the mesh cells, where a permutation of the nodes is necessary.

The names created by the interface are:

- for the nodes: NO followed by the IDEAS node number,
- for the mesh cells: MA followed by the IDEAS element number.

The mesh cells are grouped into sub-files of homogeneous type: TRIA., QUAD., TETRA., PENTA., HEXA.

- for the node groups or mesh-cell groups created by the user and named in IDEAS, the name is simply transcribed **in upper case**:
- 8 alphanumeric characters at most (otherwise truncation of the name),
- the underscore is permitted.

**Note**

The name of the group cannot begin with "COUL_xxx", otherwise it is ignored by the interface (an alarm message warns the user).

- In IDEAS, one can assign a colour to each mesh cell generated (by default, the mesh cells are green). The colours are identified by a number (for example 7 for green).

In order to keep this information in *Aster*, the interface PRE_IDEAS can generate mesh-cell groups of name "COUL_xxx" IDEAS colour number containing all the mesh cells of colour "IDEAS colour number". In order to generate these mesh-cell groups, the user must request it explicitly by CREA_GROUP_COUL = 'oui' in the command PRE_IDEAS.

Without an explicit request from the user, these mesh-cell groups are not created, so as to limit the number of mesh-cell groups and so as not to increase the size of the mesh file unnecessarily.

From the geometric-entity–mesh associations, the interface builds:

- the GROUP_MA associated with the 'mesh volume' in 3D or else with the 'mesharea' in 2D. They bear the name M_VOLUi or M_AREAi for the original geometric entity, of number i.
- the GROUP_NO associated with the 'mesh volume', 'mesh area' or 'curve', which bear the names M_VOLUi, M_AREAi, CURVEi according to the case.

**Note:**

*The* *mesharea and the* *meshvolume no longer exist in versions 1., 2., 3., 4., 5., 6., 7., 8., 9. and 10. of Master Series. The user must therefore take care to define the node groups and the mesh-cell groups which he needs for his study.*

*The mesh interface (PRE_IDEAS) does not transcribe the boundary conditions and loadings which may be present in the universal file.*

## 5 Coordinate systems

The IDEAS–*Aster* interface transcribes only the meshes whose nodes are defined by coordinates in a Cartesian frame.
