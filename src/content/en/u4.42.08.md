# u4.42.08 Macro-command CALC_ENDO

**Summary:**

This macro-command makes it possible to facilitate the data setup of a viscous-damage analysis. As for any non-linear mechanical analysis, the loading is discretised into physical time instants supplied by the user. For each of these physical time instants, `CALC_ENDO` calls `STAT_NON_LINE` in order to compute a fictitious loading sequence, composed of a loading ramp and a stabilisation phase. This stabilisation phase ends when a stabilisation criterion is satisfied.

`CALC_ENDO` produces a result concept in which these stabilised time instants are saved.

The use of this macro-command is limited to the constitutive laws `ENDO_LOCA_TC` and `ENDO_FISS_TC`.

## 2 Principle

This macro-command aims to simplify the data setup of viscous-damage analyses. In such an analysis, the viscosity refers to:

- the viscous damage. It makes it possible to pass through instabilities linked to the sudden propagation of the damage, and is available only for certain constitutive laws (`ENDO_LOCA_TC` and `ENDO_FISS_TC`).
- the viscous regularisation (see [REGU_VISC](doc:r5.03.34)). It makes it possible to stabilise the fully damaged elements.

Note that, in order to be able to use `CALC_ENDO`, the characteristic viscosity times of these two phenomena must necessarily be set to 0 (no viscosity) or to 1.

The introduction of these numerical viscosities into the model leads to a delay in the propagation of the damage. In the case of a loading which is a function of time, it is necessary to let the damage stabilise before applying the next loading increment. Thus, the loading transient is divided into several fictitious loading sequences.

A fictitious loading sequence corresponds to a ramp phase in which one applies the loading increment. There then follows a stabilisation phase, in which the loading is frozen until the stabilisation criterion is reached. This principle is illustrated in Figure 1. The stabilisation criterion is checked by means of `OBSERVATION` carried out in the course of the fictitious non-linear analysis.

![Figure](/figures/u4.42.08/PrincipeChargement.png)

*Figure 1: Discretisation of the loading. On the left, as a function of physical time. On the right, for a fictitious loading sequence.*

Once the analysis has stabilised, one saves the last time instant in the output result concept of the macro-command, and one moves on to the next fictitious loading sequence.

The macro-command `CALC_ENDO` makes it possible to greatly facilitate the implementation of such an analysis, by carrying out all the operations described previously and by calling `STAT_NON_LINE` as many times as necessary, automatically. The syntax of `CALC_ENDO` is therefore very similar to that of `STAT_NON_LINE`.

**Note**

Piloting of the loading is incompatible with the use of a numerical viscosity and is therefore not available in `CALC_ENDO`.

**Note**

For the moment, it is not possible to use a loading which is a function of time by means of the commands `AFFE_CHAR_MECA_F` or `AFFE_CHAR_CINE_F`. One must necessarily use `FONC_MULT` in the definition of the loading (see [STAT_NON_LINE](doc:u4.51.03))

**Note**

Any command variables which are a function of time are treated as a loading which is a function of time. In a fictitious loading sequence, these command variables evolve during the ramp phase, and are frozen during the stabilisation phase.

- a list of physical time instants. For each physical time instant, `CALC_ENDO` will compute a fictitious loading sequence. This list of time instants is defined by means of the factor keyword `INCREMENT` (see [STAT_NON_LINE](doc:u4.51.03)). Any parameterisation of this list of time instants by means of `DEFI_LIST_INST` is not taken into account.
- a list of fictitious time instants, which describes the fictitious loading sequence. This list of time instants is defined by the keyword `LIST_INST` under the factor keyword `ENDO_VISC`. Any parameterisation of this list of time instants by means of `DEFI_LIST_INST` is taken into account.

## 3 Operands

For the most part, the syntax of `CALC_ENDO` is identical to that of `STAT_NON_LINE` (see [STAT_NON_LINE](doc:u4.51.03)). Only the specific features of `CALC_ENDO` are described below.

### 3.1 Keyword INCREMENT

This keyword makes it possible to describe the time discretisation of the **physical** time instants, for which a fictitious loading sequence will be computed. Its syntax is identical to that of `STAT_NON_LINE` (see [STAT_NON_LINE](doc:u4.51.03)).

Note that any parameterisation of the list of time instants by means of the command `DEFI_LIST_INST` is not taken into account.

### 3.2 Keyword ARCHIVAGE

This keyword makes it possible to describe the archiving of the **physical** time instants. Its syntax is identical to that of `STAT_NON_LINE`. (see [STAT_NON_LINE](doc:u4.51.03)).

### 3.3 Keyword OBSERVATION

This keyword makes it possible to describe the observations carried out for each **fictitious** analysis time instant. The syntax is identical to that of `STAT_NON_LINE`. (see [STAT_NON_LINE](doc:u4.51.03)).

Some of these observations may be used to evaluate a stabilisation criterion after each stabilisation phase. In this case, the titles of these observations must be declared in the keyword OBSERVATION under the factor keyword ENDO_VISC. Note that it must be a scalar (the maximum, the minimum or the mean of a field, for example).

### 3.4 Keyword ENDO_VISC

```text
◆ ENDO_VISC = _F(
        ◆ LIST_INST = list_inst / listr8,
        ◇ & OBSERVATION = list[text],
        & PREC_STAB = list[float],
        ◇ ARRET = / "NON",
                / "OUI" (par défaut),
        ◇ TABLE = co,
        ◇ RESULTAT = co,
    ),
```

#### 3.4.1 Keyword LIST_INST

This mandatory keyword makes it possible to define the time discretisation of a **fictitious** loading sequence. This list must necessarily contain three reals:

- the duration of a fictitious loading ramp.
- the duration of a fictitious ramp added to that of a unit stabilisation phase. The stabilisation criterion will be evaluated after each unit stabilisation phase. If the analysis is not stabilised, another stabilisation phase will be computed.
- the maximum total duration that a fictitious loading sequence may last.

This list is therefore necessarily increasing.

This list of time instants may come from the commands (either one):

- `DEFI_LIST_INST`. In this case, `CALC_ENDO` will use, in the calls to `STAT_NON_LINE`, the parameterisation of the list of time instants supplied by the user.
- `DEFI_LIST_REEL`. In this case, `CALC_ENDO` will use a default parameterisation of the subdivision of the time step, suited to the constitutive laws `ENDO_LOCA_TC` and `ENDO_FISS_TC`, in order to guarantee a continuous evolution of the damage.

#### 3.4.2 Keyword OBSERVATION

This optional keyword makes it possible to define the list of observation titles used for the evaluation of the stabilisation criterion.

In the absence of this keyword, the stabilisation criterion is evaluated from the viscous stresses, on the basis of two observations:

- the maximum of the difference between the internal variable `SIGMVISC` (laws `ENDO_LOCA_TC` and `ENDO_FISS_TC`) and the stress which would have been computed in the absence of viscosity. This observation is named `VISCENDO`.
- the maximum of the viscous stress of `REGU_VISC`. This observation is named `VISCELAS`.

By default, these two observations are compared with 1% of the parameter $f_t$.

If the user supplies additional observations whose title is `VISCELAS` or `VISCENDO`, then these default observations are overwritten. If the titles differ from `VISCELAS` or `VISCENDO`, then these additional observations are added to the default observations.

#### 3.4.3 Keyword PREC_STAB

This optional keyword makes it possible to supply the list of real values with which the observations will be compared for the stabilisation criterion.

This list must necessarily be supplied if `OBSERVATION` is present. It must be of the same length as that supplied in `OBSERVATION`.

#### 3.4.4 Keyword RESULTAT

This optional keyword makes it possible to create a dictionary-of-results concept (`evol_noli` concepts) containing the **fictitious** time instants of each loading sequence. The dictionary is indexed by the number of the loading sequence.
This keyword is mandatory if one wishes to archive these fictitious time instants (see `ARCHIVAGE_VISC`).

#### 3.4.5 Keyword ARRET

This optional keyword makes it possible to continue or to stop the analysis if the stabilisation criteria are not satisfied at the end of the fictitious loading sequence.

By default, this parameter is equal to `OUI` and the analysis stops in error.

If this parameter is equal to `NON`, one moves on to the next loading sequence even if the criterion is not satisfied.

#### 3.4.6 Keyword TABLE

This optional keyword makes it possible to recover, in the form of a table, all the observations (the default ones and those defined by the user).

This table is indexed, among other things, by two parameters `INST` and `INST_VISC`. The first corresponds to the **physical** time instants, the second to the **fictitious** time instants.

### 3.5 Keyword ARCHIVAGE_VISC

This optional keyword makes it possible to describe the archiving of the **fictitious** time instants for each loading sequence. Its syntax is identical to that of `ARCHIVAGE` in `STAT_NON_LINE`. (see [STAT_NON_LINE](doc:u4.51.03)).

By default, these fictitious time instants are not archived. If one wishes to archive them, then the keyword `RESULTAT` under `ENDO_VISC` is mandatory.

The syntax is identical to that of `STAT_NON_LINE`, with the exception of the keyword `ENDO_VISC`.
The physical time discretisation is described under the keyword `INCREMENT`, by the list `inst_me`. All the physical time instants are archived by default.
The discretisation of a loading sequence is described under the keyword `ENDO_VISC`, by the list `inst_visc`.

The default parameters are those used for the evaluation of the stabilisation criteria and the parameterisation of the time step.

The variable `tab_obs` will contain a concept of type `TABLE` containing all the observations of the analysis.
