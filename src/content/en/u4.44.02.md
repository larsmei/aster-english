# u4.44.02 Operators AFFE_CHAR_THER and AFFE_CHAR_THER_F

## 1 Purpose

Assign thermal loadings and boundary conditions on a model.

For the operator AFFE_CHAR_THER, the assigned values do not depend on any parameter and are defined by real values.

For the operator AFFE_CHAR_THER_F, the values are functions of one or more parameters to be chosen from the set (INST, X, Y, Z). For the loadings used in non-linear thermal analysis, the functions depend solely on the temperature (TEMP) and must be tabulated. Moreover, for certain loadings (for example SOURCE), the values may depend on the command variables.

These functions must previously be defined by calling one of the operators:

- DEFI_CONSTANTE[U4.31.01];
- DEFI_FONCTION [U4.31.02](doc:u4.31.02);
- DEFI_NAPPE[U4.31.03];
- FORMULE[U4.31.05];
- CALC_FONC_INTERP [U4.32.01](doc:u4.32.01).

The concept produced is of type char_ther.

**Possible error messages related to the command** **AFFE_CHAR_THER**

## 4 Operands

### 4.1 General remarks on the operands

#### 4.1.1 The two forms of operands under a factor keyword

The operands under a factor keyword are of two forms:

- the operands specifying the topological entities on which the loadings are assigned (keywords GROUP_NO and GROUP_MA, etc.). The arguments of these operands are identical for the two operators.
- the operand or operands specifying the assigned values (`TEMP`, `COEF_H`, etc.). The meaning of these operands is the same for the two operators, but the arguments of these operands are all of type real for the operator AFFE_CHAR_THER and of type fonction (created by one of the operators DEFI_FONCTION, DEFI_NAPPE, DEFI_CONSTANTE, FORMULE or CALC_FONC_INTERP) for the operator AFFE_CHAR_THER_F.

We shall therefore not distinguish, in this document, except where expressly stated otherwise, between the two operators AFFE_CHAR_THER and AFFE_CHAR_THER_F.

#### 4.1.2 Topological entities for the assignment of the loadings

In general, the topological entities on which values are to be assigned are defined:

- by nodes, using the operand GROUP_NO, which makes it possible to introduce a list of node groups,
- by mesh cell, using the operand GROUP_MA, which makes it possible to introduce a list of mesh-cell groups,

**Rule:**

*In order to define the assignment domain as simply as possible, the overloading rule is used: it is the last assignment which takes precedence.*

### 4.2 Operand MODELE

```text
♦    MODELE =    mo,
```

Concept produced by the operator AFFE_MODELE [U4.41.01](doc:u4.41.01), in which the types of finite elements assigned on the mesh are defined.

### 4.3 Operand DOUBLE_LAGRANGE

```text
◊    DOUBLE_LAGRANGE = ’OUI’/’NON’
```

This keyword makes it possible to state whether or not the user wishes to duplicate the Lagrange multipliers used to define and dualise the boundary conditions in the assembled matrix.

Concretely, duplicating the Lagrange multipliers makes it possible to use linear solvers which do not allow pivoting. Not duplicating the Lagrange multipliers makes it possible to reduce the number of degrees of freedom of the problem (and therefore the size of the problem to be solved), but its use is limited to the solvers MUMPS and Petsc.

Note that the two Lagrange multipliers associated with the relation will be such that the first will be located before all the terms involved in the relation and the second after them, in the assembled matrix. This choice has the advantage of producing an assembled matrix whose storage requirement is smaller, but has the disadvantage of being able to give rise to a singularity in the matrix. Since the numbering is in any case liable to be modified by the renumberer of the chosen external solver, this detail therefore remains purely technical.

### 4.4 Keyword TEMP_IMPO

#### 4.4.1 Purpose

Factor keyword usable to impose, on nodes or node groups, a temperature.

Depending on the name of the operator called, the values are supplied directly (AFFE_CHAR_THER) or by means of a concept of type fonction (AFFE_CHAR_THER_F).

```text
                          |    TEMP_INF =    tinf,                    [R]
```

```text
TEMP_IMPO = _F(    ♦    |    TOUT =        'OUI',
```

### 4.5 Keyword FLUX_REP

#### 4.5.1 Purpose

Factor keyword usable to apply **normal fluxes**, to a **face** of a volume element or of a thermal shell defined by one or more mesh cells of type **triangle** or **quadrangle**. This keyword also makes it possible to apply a normal flux to an edge (in 2DPLAN or AXIS or AXIS_FOURIER) on mesh cells of type segment.

Depending on the name of the operator called, the values are supplied directly (AFFE_CHAR_THER) or by means of a concept of type fonction (AFFE_CHAR_THER_F).

#### 4.5.2 Syntax

- for AFFE_CHAR_THER

```text
FLUX_REP = _F(    ♦    /    TOUT =        'OUI',
                       /    GROUP_MA =        lgma,                [l_gr_maille]
                  ♦    /     FLUN =            fl,                    [R]
                       / |     FLUN_INF =        flin,                [R]
                         |     FLUN_SUP =        flsup,                [R]
            )
```

- for AFFE_CHAR_THER_F

```text
FLUX_REP = _F(    ♦    /    TOUT =        'OUI',
                       /    GROUP_MA =        lgma,                [l_gr_maille]
                  ♦    /    FLUN =                    flf,                [fonction]
                       / |  FLUN_INF =        flinf,                [fonction]
                         |    FLUN_SUP =        flsupf,            [fonction]
                       / |    FLUX_X =        flx,                [fonction]
                         |    FLUX_Y =        fly,                [fonction]
                         |    FLUX_Z =        flz,                [fonction]
                )
```

#### 4.5.3 Operands

```text
/    FLUN : fl flux imposé normal à la maille.
```

This loading applies to the following mesh-cell types and modellings:

| **Mesh cell** | **Modelling** |
| --- | --- |
| TRIA3, TRIA6, QUAD4, QUAD8, QUAD9 | 3D, 3D_DIAG |
| SEG2, SEG3 | PLAN, AXIS, AXIS_FOURIER, PLAN_DIAG, AXIS_DIAG |

More precisely, the boundary condition applied is: $\lambda (\mathrm{grad}T\cdot n)$ = fl

where $\lambda$ is the thermal conductivity and $n$ is the normal oriented in the direction of the numbering of the nodes of the mesh cell. The orientation convention is that used in AFFE_CHAR_MECA [U4.44.01](doc:u4.44.01).

```text
/    |    FLUN_INF = flin
     |    FLUN_SUP = flsup
```

Normal flux imposed on the lower and upper walls of a thermal shell.

These loadings apply to the following mesh-cell types and modellings:

| **Mesh cell** | **Modelling** |
| --- | --- |
| TRIA3, TRIA6 | COQUE |

$n$ being the normal orienting the surface [U4.44.01](doc:u4.44.01), the boundary condition applied is:

$\lambda (\mathrm{grad}T\cdot n)$ = flin where flin is the normal flux imposed on the lower wall of the shell,

$\lambda (\mathrm{grad}T\cdot n)$ = flsup where flsup is the normal flux imposed on the upper wall of the shell.

![Figure](/figures/u4.44.02/1000000000000266000001788D76A7B399E3E6E9.png)

```text
/    |    FLUX_X = flx
|    FLUX_Y = fly
|    FLUX_Z = flz
```

Vector flux $\mathit{fl}$ in the global frame (only for AFFE_CHAR_THER_F), which is projected onto the normal to the element (for the definition of the normal [U4.44.01](doc:u4.44.01)).

$\lambda (\mathit{grad}T\cdot n)=\mathit{fl}\cdot n=\mathit{flx.nx}+\mathit{fly.ny}+\mathit{flz.nz}$

This loading applies to the mesh-cell types and modellings:

| **Mesh cell** | **Modelling** |
| --- | --- |
| TRIA3, TRIA6, QUAD4, QUAD8, QUAD9 | 3D, 3D_DIAG |
| SEG2, SEG3 | PLAN PLAN_DIAG |

Note: the persistence rule (see U1.03.00) applies between the different quantities that one can assign: FLUN, FLUN_INF, ... FLUX_Z.

#### 4.5.4 Note

The simple keyword CARA_TORSION of this factor keyword FLUX_REP is not documented here and must not be used by the user. It is used only by the macro-command MACR_CARA_POUTRE. The latter is used to identify the geometric characteristics of beam cross-sections. For the torsion characteristics, the command solves a Laplacian problem by using the linear thermal operators indirectly.

### 4.6 Keyword FLUX_NL

#### 4.6.1 Purpose

Factor keyword usable to apply **normal fluxes** that are functions of the temperature, to a **face** of a volume element defined by one or more mesh cells of type **triangle** or **quadrangle**. This keyword also makes it possible to apply a normal flux to an edge (in 2DPLAN or AXIS) on mesh cells of type segment. One can thus model a radiation condition of Stefan-law type.

This type of flux is available only in the command AFFE_CHAR_THER_F and is used only by the commands THER_NON_LINE [U4.54.02](doc:u4.54.02) and THER_NON_LINE_MO [U4.54.03](doc:u4.54.03).

The values are supplied by a concept of type fonction. The function depends on the temperature, to the exclusion of any other parameter. Moreover, it must necessarily be a tabulated function and not a formula.

#### 4.6.2 Syntax

- For AFFE_CHAR_THER_F

```text
FLUX_NL = _F(♦    /    TOUT =        'OUI',
                  /    GROUP_MA =        lgma,                [l_gr_maille]
             ♦        FLUN =            fl,                    [fonction]
          )
```

#### 4.6.3 Operands

```text
FLUN : flux imposé normal à la maille.
```

This loading applies to the following mesh-cell types and modellings:

| **Mesh cell** | **Modelling** |
| --- | --- |
| TRIA3, TRIA6, QUAD4, QUAD8, QUAD9 | 3D, 3D_DIAG |
| SEG2, SEG3 | PLAN, AXIS PLAN_DIAG, AXIS_DIAG |

More precisely, the boundary condition applied is:

$\lambda (\mathrm{grad}T\cdot n)$ = fl

where $n$ is the normal oriented in the direction of the numbering of the nodes of the mesh cell. Orientation used in AFFE_CHAR_MECA, document [U4.44.01](doc:u4.44.01).

### 4.7 Keyword RAYONNEMENT

#### 4.7.1 Purpose

Keyword making it possible to define the flux radiated to infinity according to the formula:

${\Phi}_{\mathit{ray}}=\sigma \epsilon ({[T+273,15]}^{4}-{[{T}_{\infty}+273,15]}^{4})$

by supplying the emissivity $\varepsilon$, the Boltzmann constant $\sigma$ and the temperature at infinity ${T}_{\infty}$ expressed in Celsius. The temperature $T$ will itself also be expressed in Celsius; one must therefore take care, for consistency, to use only degrees Celsius for the whole study.

#### 4.7.2 Syntax

- for AFFE_CHAR_THER

```text
RAYONNEMENT = _F(   ♦    /    TOUT =        'OUI',

                    ♦         SIGMA =            sigma,                [:ref:`R8 <R8>`]
                    ♦         EPSILON =            epsilon,            [:ref:`R8 <R8>`]
                    ♦         TEMP_EXT=            tex,                [:ref:`R8 <R8>`]
                )
```

- for AFFE_CHAR_THER_F

```text
RAYONNEMENT = _F(   ♦    /   TOUT =        'OUI',
```

Depending on the name of the operator called, the values are supplied directly (AFFE_CHAR_THER) or by means of a concept of type fonction (AFFE_CHAR_THER_F).

#### 4.8.2 Syntax

- for AFFE_CHAR_THER

```text
         /    |    ♦    COEF_H_INF    =    hin,            [R]

```

- for AFFE_CHAR_THER_F

```text
ECHANGE = _F    (
    ♦    /    TOUT =        'OUI',
         /    GROUP_MA =        lgma,                [l_gr_maille]

              ♦    TEMP_EXT =            texf,            [fonction]

                    ♦    TEMP_EXT_INF =    texinf,        [fonction]

```

#### 4.8.3 Operands

```text
/    ♦    COEF_H = h,
     ♦    TEMP_EXT = tex,
```

This loading applies to the following mesh-cell types and modellings:

| **Mesh cell** | **Modelling** |
| --- | --- |
| TRIA3, TRIA6, QUAD4, QUAD8, QUAD9 | 3D, 3D_DIAG |
| SEG2, SEG3 | PLAN, PLAN_DIAG AXIS, AXIS_FOURIER, AXIS_DIAG |

More precisely, the boundary condition applied is:

$\lambda (\mathit{grad}T\cdot n)=h(\mathit{tex}-T)(h>0)$

where $n$ is the normal oriented in the direction of the numbering of the vertex nodes (orientation used in AFFE_CHAR_MECA [U4.44.01](doc:u4.44.01)).

```text
/    |    ♦     COEF_H_INF        = hin,
          ♦     TEMP_EXT_INF        = texin,
     |    ♦     COEF_H_SUP        = hsup,
          ♦     TEMP_EXT_SUP        = texsup,
```

This loading applies to the following mesh-cell types and modellings:

| **Mesh cell** | **Modelling** |
| --- | --- |
| TRIA3, TRIA6 | COQUE |

$n$ being the normal orienting the surface [U2.03.03](doc:u2.03.03), the boundary condition applied is:

$\lambda (\mathrm{grad}T\cdot n)=\mathrm{hin}(\mathrm{texin}-T)$

| where hin | exchange coefficient on the lower wall of the shell, |
| --- | --- |
| and texin | external temperature, on the lower-wall side. |

$\lambda (\mathrm{grad}T\cdot n)=\mathrm{hsup}(\mathrm{texsup}-T)$

| where hsup | exchange coefficient on the upper wall of the shell, |
| --- | --- |
| and texsup | external temperature, on the outer-wall side. |

Notes:

- the persistence rule (see U1.03.00) applies between the different quantities that one can assign: COEF_H, COEF_H_INF, ... TEMP_EXT_SUP.
- In the case of function loadings (AFFE_CHAR_THER_F), since there are two distinct components (the exchange coefficient and the temperature), which are *a priori* independent, one cannot use this loading simultaneously with a multiplier function in the solution operator (THER_LINEAIRE or THER_NON_LINE). An error message will warn you.

### 4.10 Keyword PRE_GRAD_TEMP

#### 4.10.1 Purpose

Factor keyword usable to apply to a 3D or 2D element (PLAN, AXIS) a temperature gradient assumed uniform in the element. This “initial” temperature gradient can be used, for example, to solve the elementary problems determining the correctors of stationary linear thermal analysis in the basic cell (2D, 3D), in periodic homogenisation.

The homogenised conductivity coefficients are obtained by computing, with the operator POST_ELEM [U4.81.22](doc:u4.81.22), keyword ENER_POT, the thermally dissipated energy at equilibrium in linear thermal analysis from the correctors.

Because of the thermal analogy, this approach can be used to obtain the correctors in anti-plane elasticity in the 2D basic cell, as well as in electrical conduction.

The analysis uses the conductivity of the material. The latter is assumed to be isotropic and independent of the temperature.

The assignment can be made on one or more mesh cells or on all the elements of the model.

#### 4.11.1 Purpose

Factor keyword usable to define a linear relation between degrees of freedom of two or more nodes.

Depending on the name of the operator called, the values are supplied directly (AFFE_CHAR_THER) or by means of a fonction concept (AFFE_CHAR_THER_F).

```text
LIAISON_DDL = _F    (

    |                'TEMP_MIL',
    |                'TEMP_INF',
    |                'TEMP_SUP',
    |                'H1',

    ♦    COEF_IMPO =                b    ,            [R]
    )
```

- for AFFE_CHAR_THER_F

```text
LIAISON_DDL = _F    (
    ♦    GROUP_NO =        lgno,            [l_gr_noeud]

    ◊    DDL =        |                'TEMP',        [DEFAUT]

    |                'TEMP_INF',
```

#### 4.11.3 Operands

The list of nodes ${N}_{i}$ ($i=1,r$) defined by GROUP_NO is ordered in the natural way, that is, in the order of the list of node groups, and, for each node group, in the order of definition of the group by GROUP_NO.

The argument of DDL must be a list of degrees of freedom ${T}_{i}$ ($i=1,r$) of $r$ texts taken from among:

`TEMP`,    `TEMP_MIL`,    `TEMP_SUP`,    `TEMP_INF`,    `H1`

If the keyword DDL is omitted, by default the linear relation will bear on the degrees of freedom 'TEMP'.

The argument of COEF_MULT must be a list ${a}_{i}$ ($i=1,r$) of coefficients (of type real for AFFE_CHAR_THER and AFFE_CHAR_THER_F).

The argument of COEF_IMPO is a coefficient $\beta$ for AFFE_CHAR_THER, a function of space for AFFE_CHAR_THER_F.

The following kinematic condition is applied: $\sum_{i=1}^{r}{\alpha}_{i}{T}_{i}=\beta$

**Notes:**

*The components 'TEMP_MIL', 'TEMP_SUP' and 'TEMP_INF' can appear only in combinations assigned* **solely** *to nodes which belong to* **shell** *elements (modelling 'COQUE').*

*The component 'H1' can appear only in combinations assigned* **solely** *to nodes which belong to* **X-FEM** *elements. In this case, only the degrees of freedom 'TEMP' and 'H1' may appear in the linear relation.*

*In the case of a linear relation between the degrees of freedom of one and the same node, one will repeat, after the keyword* **GROUPE_NO***, the name of the group defining the node as many times as there are degrees of freedom in the relation.* **Example:** *to impose* ${T}_{\sup}={T}_{\inf}$ *on the node of group* $\mathit{GN}1$*, one will write:*

```text

    DDL            =    ('TEMP_SUP',    'TEMP_INF'),
    COEF_MULT    =    (1.,-1.),
    COEF_IMPO    =    0.,
    )
```

*It is important to note that to one occurrence of the factor keyword* **LIAISON_DDL** *there corresponds one and only one linear relation.*

*If one wishes to impose the same relation between 2 node groups* **GRN01** *and* **GRN02** *(the same temperature, node to node, for example),* **one cannot write:**

```text
LIAISON_DDL = _F    (    GROUP_NO    =    (GRN01, GRN02),
    DDL            =    ('TEMP',    'TEMP'),
    COEF_MULT    =    (1.,-1.),
    COEF_IMPO    =    0.,
    )
```

*This form of writing makes sense only if* **GRN01** *and* **GRN02** *each contain only one node. In the case above, each linear relation will have to be written out explicitly, node by node.*

**The keyword LIAISON_GROUP, on the other hand, makes it possible to condense the writing of the linear relations between 2 node groups facing each other.**

#### 4.12.4 Use of LIAISON_GROUP

- LIAISON_GROUP generates linear relations only between 2 nodes (one on ${\Gamma}_{1}$, one on ${\Gamma}_{2}$)

To generate linear relations on more than 2 nodes, use the keyword LIAISON_DDL.

- determination of the pairs of nodes facing each other:

first, the two lists of nodes to be placed face to face (i.e. to be paired) are established, for each occurrence of the factor keyword LIAISON_GROUP:

- for the keywords GROUP_NO_1 and GROUP_NO_2, these are the nodes constituting the node groups,
- for the keywords GROUP_MA_1 and GROUP_MA_2, these are the nodes of the mesh cells constituting the mesh-cell groups.

Redundancies having been eliminated, the two lists of nodes obtained must have the same length.

The determination of the pairs of nodes facing each other is carried out in several stages:

- for each node $\mathit{N1}$ of the first list, one looks for the image node $\mathit{N2}=f(\mathit{N1})$ of the second list. If f is not injective (a node $\mathit{N2}$ is the image of two distinct nodes $\mathit{N1}$ and $\mathit{N1}'$), the following error message is issued:

```text
<F> <AFFE_CHAR_THER> <PACOAP> CONFLIT DANS LES VIS-A-VIS
DES NOEUDS
LE NOEUD N2 EST LE VIS-A-VIS DES NOEUDS N1 ET N1'
```

- for each node $\mathit{N2}$ of the second list, one looks for the image node $\mathit{N1}=g(\mathit{N2})$ of the first list. If g is not injective (a node $\mathit{N1}$ is the image of two distinct nodes $\mathit{N2}$ and $\mathit{N2}'$), the following error message is issued:

```text
<F> <AFFE_CHAR_MECA> <PACOAP> CONFLIT DANS LES VIS-A-VIS
DES NOEUDS
LE NOEUD N1 EST LE VIS-A-VIS DES NOEUDS N2 ET N2'
```

- one checks that $g={f}^{-1}$, that is, that the pairs obtained by stages a) and b) are the same (one wishes to have a bijection $f$ between the two lists of nodes). If f is not surjective, the following error message is issued:

```text
<F> <AFFE_CHAR_MECA> <PACOAP> CONFLIT DANS LES VIS-A-VIS GENERES
SUCCESSIVEMENT A PARTIR DES LISTES LIST1 ET LIST2
LE NOEUD DE LA PREMIERE LISTE N1 N'EST L'IMAGE D'AUCUN NOEUD PAR
LA CORRESPONDANCE INVERSE
```

For a given node $N$, one calls image node $f(N)$ the node of the other list of nodes which achieves the minimum of the distance to $N$. To facilitate the pairing, in particular in the case of particular geometries (where the boundaries ${\Gamma}_{1}$ and ${\Gamma}_{2}$ could “almost” be deduced from one another by the composition of a translation and a rotation), the possibility is offered of performing a virtual geometric transformation of the first group of nodes (translation and rotation (cf. [Figure 4.11.3-a]) before computing the distances (keywords TRAN, CENTRE and ANGL_NAUT).

For each occurrence of the factor keyword LIAISON_GROUP, the list of the new pairs facing each other is thus constructed. When all the occurrences have been scanned, the duplicate pairs are removed from the list.

**Note:**

*In the pairs of nodes facing each other, the order of the nodes is important. If, for the first occurrence of* *LIAISON_GROUP, a node* $N$ *belonged to the first group of nodes and a node* $M$ *to the second group of nodes, and if, for the second occurrence of* *LIAISON_GROUP, it is the reverse, one will obtain at the end of the pairing the pairs* $(N,M)$ *and* $(M,N)$*. They will not be eliminated during the detection of redundancies; on the other hand, the matrix obtained will be singular. Thus, one is advised to keep the same logic when describing the edges facing each other.*

### 4.13 Keyword LIAISON_MAIL

#### 4.13.1 Purpose

Factor keyword making it possible to “tie thermally” two edges of a structure. These edges may be meshed differently (incompatible meshes) but must be deducible from one another by rotation and/or translation.

#### 4.13.2 Syntax

- in AFFE_CHAR_THER only

```text
LIAISON_MAIL = _F    (
    ♦    GROUP_MA_MAIT =            lgma_mait,

    ♦    |    GROUP_MA_ESCL =            lgma_escl,
    |    GROUP_NO_ESCL =            lgno_escl,

    ◊        DISTANCE_MAX =        d_max,            [R]

    ◊    |    ♦    TRAN =        (tx, ty, [tz]),            [l_R]
    |    ♦    CENTRE =        (xc, yc, [zc]),            [l_R]
    ♦    ANGL_NAUT =    (alpha, [beta, gamma]),    [l_R]
    )
```

Face 1 is called the “master” face; face 2 is called the “slave” face.

#### 4.13.3 Operands

##### 4.13.3.1 GROUP_MA_ESCL / GROUP_NO_ESCL

These keywords make it possible to define the set of nodes of the slave face. One takes all the nodes specified by the keyword GROUP_NO_ESCL plus, possibly, the nodes carried by the mesh cells specified by the keyword GROUP_MA_ESCL.

##### 4.13.3.2 GROUP_MA_MAIT

This keyword makes it possible to define the set of mesh cells in which one will look for the counterparts of the nodes of the slave face.

One must not give the surface mesh cells (in 3D) making up the master face, but the volume mesh cells adjacent to the master face. The mesh cells specified are candidates for the search for counterparts. One may give too many of them.

##### 4.13.3.3 DISTANCE_MAX

To project the mesh $\mathit{MA1}$ onto the mesh $\mathit{MA2}$, the method looks for the element of the mesh $\mathit{MA1}$ in which each node of $\mathit{MA2}$ lies, then interpolates the value by means of the shape functions of the element. When a node of $\mathit{MA2}$ lies in no element of the mesh $\mathit{MA1}$, the method relates the node to the (boundary) point of the nearest element. It interpolates the value by means of the shape functions of the element, even if the node is “far” from this element.

If one wishes a node which lies in none of the elements of the mesh $\mathit{MA1}$ not to be concerned by the projection, one uses the operand DISTANCE_MAX. This operand makes it possible to give the maximum distance that one authorises between the node and the nearest element.

If the node does not satisfy the proximity criterion, the field will not be projected onto this node (i.e. the node will carry no component).

There is no default value for DISTANCE_MAX. This means that, by default, the field will be extended outside the material as far as necessary.

##### 4.13.3.4 DISTANCE_ALARME = d_ala

The code issues an alarm when a node of $\mathit{MA2}$ is judged “distant” from the mesh cells of $\mathit{MA1}$.

Let d be the distance separating a node of $\mathit{MA2}$ from the nearest mesh cell of $\mathit{MA1}$.

By default, the criterion for judging whether a node is distant is relative:

d > 1/10th of the size of the nearest mesh cell.

But if the user uses DISTANCE_ALARME = d_ala, the alarm message is issued if d > d_ala (absolute criterion).

##### 4.13.3.5 CENTRE / ANGL_NAUT / TRAN

These operands make it possible to define the geometric transformation (rotation and/or translation) making it possible to pass from the slave face to the master face. The command first performs the rotation, then the translation.

Caution: the transformation is in the slave-to-master direction.

This boundary condition applies to plane modellings ('PLAN' or 'AXIS') or volume modellings ('3D').

#### 4.14.4 Use of ECHANGE_PAROI

> *In the case of a meshed wall:*

The user gives two lists of mesh cells from which the pairs of paired nodes will be taken. These lists are first sorted by mesh-cell type: the paired nodes will come from mesh cells of identical type. For each mesh cell of the first list, one determines the nearest mesh cell in the second list by computing all the distances of the nodes taken two by two (one runs through all the possible permutations). The minimum distance obtained defines both the mesh cell facing it and the pairs of paired nodes for the two mesh cells concerned. As in LIAISON_GROUP [§4.11], it is possible to perform a virtual geometric transformation (rotation and/or translation) before computing the distances.

> *In the case of one or more X-FEM cracks:*

One defines as many pairs of walls facing each other as there are cracks in the list supplied for the keyword FISSURE.

- If the keyword COEF_H is present, all the cracks contained in this list will be assigned the same exchange coefficient (real or function). To assign a value of the exchange coefficient specific to each crack, one must use the repeatable character of the factor keyword ECHANGE_PAROI.
- If the keyword TEMP_CONTINUE is present, one imposes the continuity of the temperature field across all the cracks contained in this list.

### 4.15 Keyword LIAISON_UNIF

#### 4.15.1 Purpose

Factor keyword making it possible to impose one and the same (unknown) value on the temperatures of a set of nodes.

These nodes are defined by the mesh-cell groups or the node groups to which they belong.

#### 4.15.2 Syntax

- for AFFE_CHAR_THER and AFFE_CHAR_THER_F

```text
LIAISON_UNIF = _F    (
    ♦    /    GROUP_MA    =    lgma,                [l_gr_maille]
    /    GROUP_NO    =    lgno,                [l_gr_noeud]

    ♦      DDL =    |    'TEMP'    ,                    [DEFAUT]
    |    'TEMP_MIL',
    |    'TEMP_INF',
    |    'TEMP_SUP',
    )
```

#### 4.15.3 Operands

```text
♦    /    GROUP_MA
     /    GROUP_NO
```

These operands make it possible to define a list of $n$ nodes ${N}_{i}$ from which redundancies have been eliminated (for GROUP_MA, these are the connectivities of the mesh cells).

```text
♦    DDL
```

This operand makes it possible to define a list of degrees of freedom ${T}_{i}(i=1,r)$ of $r$ texts taken from among: 'TEMP', 'TEMP_MIL', 'TEMP_INF', 'TEMP_SUP'.

The $r\times (n-1)$ resulting ‘kinematic’ conditions are:

${T}_{i}({N}_{1})={T}_{i}({N}_{k})$ for $k\in (2,\mathrm{...},n)$, $i\in (1,\mathrm{...},r)$

**Note:**

*The components 'TEMP_MIL', 'TEMP_SUP', 'TEMP_INF' can appear only for nodes of shell elements.*

### 4.16 Keyword LIAISON_CHAMNO

#### 4.16.1 Purpose

Factor keyword usable to define a linear relation between all the temperatures present in a CHAM_NO concept.

#### 4.16.2 Syntax

```text
LIAISON_CHAMNO = _F    (
    ♦    CHAM_NO =    chamno,                [cham_no]
    ♦    COEF_IMPO=     b,                    [R]
    )
```

#### 4.16.3 Operands

```text
CHAM_NO=
```

Name of the chamno which is used to define the linear relation. The temperatures that are related are all those present in the chamno. The coefficients to be applied to the temperatures are the values of these temperatures in the chamno.

**Example:**

Suppose that one has a chamno bearing on 3 nodes of names $\mathit{N01}$, $\mathit{N02}$ and $\mathit{N03}$.

Suppose that the values of the temperatures at these 3 nodes in the chamno are respectively 2., 5.4 and 9.1. The linear relation that one will impose is:

$2.T(\mathit{NO1})+5.4T(\mathit{NO2})+9.1T(\mathit{NO3})=\beta$

```text
COEF_IMPO=
```

This is the value of the real coefficient $\beta$ on the right-hand side of the linear relation.

### 4.17 Keyword CONVECTION

#### 4.17.1 Purpose

Keyword usable to take into account the term of heat transport by convection, whose expression is $\rho {C}_{p}.V\mathit{grad}T$, appearing in the expression of the material derivative $\rho {C}_{p}\frac{\mathit{dT}}{\mathit{dt}}:\rho {C}_{p}\frac{\mathit{dT}}{\mathit{dt}}=\rho {C}_{p}\frac{\partial T}{\partial t}+\rho {C}_{p}V\mathit{grad}T$.

In the case of a liquid medium, $V$ denotes the imposed velocity of the fluid particle at the current point.

In the case of a moving solid medium, $V$ denotes the velocity of the solid. In all cases, one assumes that the velocity field is known a priori. The case of a moving solid is fairly frequent in practice. It concerns in particular welding or surface-treatment applications, which involve a heat source moving in a given direction and at a given velocity.

The thermal problem is then studied in a reference frame attached to the source (cf. THER_NON_LINE_MO [U4.54.03](doc:u4.54.03)).

#### 4.17.2 Syntax

```text
CONVECTION = _F    (    ♦    VITESSE =    v                    [cham_no_sdaster])
```

#### 4.17.3 Operand

For AFFE_CHAR_THER and AFFE_CHAR_THER_F,

VITESSE =

Name of the velocity field at the time instant at which one performs the analysis.

This field is a cham_no concept of type cham_no_depl_r. It must have been defined on the whole model for which one performs the analysis.

### 4.18 Keyword SOUR_NL

#### 4.18.1 Purpose

Factor keyword usable to apply **volumetric sources depending on the temperature** (2D or 3D) to a **domain** defined by one or more mesh cells of **volume** type.

This type of flux is available only in the command AFFE_CHAR_THER_F and is used only by the commands THER_NON_LINE [U4.54.02](doc:u4.54.02) and THER_NON_LINE_MO [U4.54.03](doc:u4.54.03).

The values are supplied by a concept of type fonction. The function depends on the temperature, to the exclusion of any other parameter. Moreover, it must necessarily be a tabulated function and not a formula.

#### 4.18.2 Syntax

```text
SOUR_NL = _F    (
    ♦    /    TOUT =            'OUI',
    /    GROUP_MA =            lgma,            [l_gr_maille]

    ♦    SOUR =                sf,                [fonction]
    )
```

#### 4.18.3 Operands

This loading applies to the following mesh-cell types and modellings:

| **Mesh cell** | **Modelling** |
| --- | --- |
| HEXA8, HEXA20, HEXA27 PYRA5, PYRA13, PENTA6, PENTA15 TETRA4, TETRA10 | 3D |
| TRIA3, TRIA6, QUAD4, QUAD8, QUAD9 | PLAN, AXIS |
| HEXA8, PYRA5, PENTA6, TETRA4 | 3D_DIAG |
| TRIA3, QUAD4 | PLAN_DIAG, AXIS_DIAG |

```text
/    ♦    SOUR = s,
```

Value of the source depending on the temperature and assumed constant on the element.

### 4.19 Keyword EVOL_CHAR

```text
EVOL_CHAR =    evch
```

The factor keyword EVOL_CHAR is usable to apply loadings that evolve in time, of type evol_char, produced by LIRE_RESU [U7.02.01](doc:u7.02.01) or CREA_RESU [U4.44.12](doc:u4.44.12) and containing fields of coefficients corresponding either:

- to a loading of type ECHANGE (see § 4.8): the field T_EXT corresponds to the parameter TEMP_EXT and the field COEF_H corresponds to the parameter COEF_H.
- to a loading of type FLUX_REP (see § 4.5): the field FLUN corresponds to the parameter of the same name.
