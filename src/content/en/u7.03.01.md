# u7.03.01 Macro-command MACR_ADAP_MAIL

## 1 Purpose

Adapt a mesh with the HOMARD software.

This operation is possible for a mesh made up of point mesh cells, segments, triangles, quadrangles, tetrahedra, hexahedra and pentahedra. A field driving the adaptation may possibly have been computed. Depending on its value mesh cell by mesh cell or node by node, or depending on a geometric directive, the HOMARD software will modify the mesh. It is also possible to interpolate fields, from the old mesh to the new one.

One may chain analysis and adaptation as one goes along, in a process of improvement of the analysis. This process may take place in a single pass, or be split into several stages by a POURSUITE.

One finds in it a description of the technique used to modify the meshes, as well as examples.

To find out more about HOMARD, one may refer to the documents cited in the bibliography.

Any external reference to HOMARD must be made with:

1. Nicolas and T. Fouquet, « *Adaptive Mesh Refinement for Conformal Hexahedral Meshes* », Finite Elements in Analysis and Design, Vol. 67, pp. 1-12, 2013, doi:10.1016/j.finel.2012.11.008

## 3 Description of a mesh adaptation

### 3.1 General scheme of an adaptation

The general principle of an analysis with mesh adaptation is the following:

| Phase 1: | Reading of the initial mesh, M0 Definition of the materials |
| --- | --- |
| Phase 2: | definition of the model, of the loadings on this mesh M0 analysis producing a result RESU0 analysis, where appropriate, of a field driving the refinement, CHAMP0 |
| This initial phase is the standard phase of any analysis |  |
| Phase 3: | Adaptation of the mesh M0. One obtains a new mesh, M1 |
| Phase 4: | definition of the model, of the loadings on the mesh M1, analysis producing a result RESU1, analysis, where appropriate, of a field driving the refinement, CHAMP1. |

Phase 4 is similar to phase 2. The only thing which has changed is the mesh. Because of this, all the concepts which depend on it must be rebuilt. Today, there is no possibility either of reusing the old concepts, or of destroying them automatically.

Then, one may continue, as many times as one wishes, the phase 3/phase 4 pair. This is done either by duplicating the instructions, or by writing a Python loop.

See reference [bib1] for a general presentation of mesh adaptation and of HOMARD, accompanied by examples.

### 3.2 Operation of the macro-command

Phase 3 carries out the adaptation of the mesh. It is activated by the macro-command MACR_ADAP_MAIL, described in this document. Its essential argument is the name of the concept of the current mesh and the name which will be given to the concept of the future mesh. The other mandatory datum is the type of adaptation which one wishes: free refinement or coarsening, that is to say according to the values taken by a field on the mesh cells of the mesh, or according to a geometric zone, or uniform refinement or coarsening, that is to say that all the mesh cells are treated in the same way.

The other data then depend on the options retained.

In addition to the adaptation, HOMARD can supply on request reports on the quality or the diameter of the mesh cells of the mesh, the connectivity of the analysis domain, the characteristic sizes, the over-constrained elements or a check of the non-interpenetration of the mesh cells. This information is obtained by activating the associated keywords. One will profitably look at the command MACR_INFO_MAIL [U7.03.02](doc:u7.03.02), which makes it possible to obtain all this information, independently of any analysis.

### 3.3 Some comments

The adapted mesh contains the same groups as the input mesh, with the following rule: a group defines the same geometric location in the two meshes.

- Using a node group amounts to defining point locations. The group in the adapted mesh will be the list of the same nodes, neither more nor less, in order to represent the same points; only their numbers may have changed.
- Using a group of segments amounts to defining lines. The group in the adapted mesh will be the list of the segments which represent the same lines. Depending on the adaptation mode, these segments will be either the same, up to the numbering, or the halves of the initial segments.
- Using a group of triangles and/or quadrangles amounts to defining surfaces. The group in the adapted mesh will be the list of the triangles and/or quadrangles which represent the same surfaces. Depending on the adaptation mode, these mesh cells will be either the same, up to the numbering, or the fractions of the initial 2D mesh cells.
- Likewise, using a group of 3D mesh cells amounts to defining volumes. The group in the adapted mesh will be the list of the 3D mesh cells which represent the same volumes. Depending on the adaptation mode, these mesh cells will be either the same, up to the numbering, or the fractions of the initial 3D mesh cells.

The consequence is the following. The loadings of the mechanical or thermal analysis must exclusively be defined by groups of the dimension consistent with the phenomenon which one wants to model.

Any other operation will lead to an error in the analysis on the adapted mesh. Using mesh cells defined by their number is impossible because the numbering will change. Using node groups or mesh-cell groups of the wrong dimension will not completely describe the location.

For a more detailed and illustrated explanation, see:

[https://www.code-aster.org/outils/homard/usage/regles.fr.htm#CL](https://www.code-aster.org/outils/homard/usage/regles.fr.htm#CL)

When one wants to adapt a mesh several times in succession, it is fundamental to respect the chain of meshes properly. At the first iteration, the input mesh of MACR_ADAP_MAIL is the initial mesh of the case which one is treating. Then, the input mesh of a MACR_ADAP_MAIL must be the output mesh of the previous MACR_ADAP_MAIL. Warning: it is not enough to give a mesh which is formally the same, following a copy for example. It is imperative to supply the same concept (see also IDENTIFICATION). If one does not proceed in this way, one will lose the refinement history of the mesh cells and it will be impossible to coarsen later. More seriously, HOMARD no longer having knowledge of the additional cuttings which were introduced in order to ensure conformity, one will be led to cut mesh cells while strongly degrading their quality. If this bad data setup appears, an alarm is emitted.

Mesh adaptation is possible in POURSUITE mode. The data necessary for the restart are automatically archived and then re-read in the storage directory of the database necessary to *Code_Aster*. Using HOMARD in restart is therefore done in the same way as using *Code_Aster* in restart.

In general, the essential printouts supplied by HOMARD are inserted into the "mess" file in the course of the execution. In the event of an error or in information mode 3 or 4, more detailed printouts take place.

## 4 Operands

### 4.1 Operand ADAPTATION

```text
♦    ADAPTATION=    /    'RAFF_DERA'
/    'RAFFINEMENT'
/    'DERAFFINEMENT'
/    'RAFF_DERA_ZONE'
/    'RAFFINEMENT_UNIFORME'
/    'DERAFFINEMENT_UNIFORME'
/    'RIEN'
/    'MODIFICATION'
/    'LECTURE'
```

This operand makes it possible to define the type of adaptation wished for.

In the first place, one finds the adaptation modes which are driven by a field. In other words, the decision to refine or coarsen a mesh cell is taken according to the value of a field computed beforehand on this mesh cell. The choice may be made between three variants:

- 'RAFF_DERA': the mesh is refined and coarsened according to the field. This is the recommended option.
- 'RAFFINEMENT': only the refinement function is activated. No mesh cell will be coarsened.
- 'DERAFFINEMENT': it is the opposite; only the coarsening function is activated. No mesh cell will be refined.

In the second place, one may decide to adapt the mesh in geometric zones defined by boxes. All the mesh cells of which at least two nodes are present in one of these boxes will be retained. This makes it possible to carry out refinements or coarsenings *a priori*, without having performed an analysis.

- 'RAFF_DERA_ZONE': the mesh cells of each of the boxes defined are refined or coarsened.

Finally, one may activate a uniform adaptation of a mesh. In other words, all the mesh cells of the mesh are treated in the same way. The choice may be made between three variants:

- 'RAFFINEMENT_UNIFORME': all the mesh cells are refined,
- 'DERAFFINEMENT_UNIFORME': all the mesh cells are coarsened,
- 'RIEN': all the mesh cells are kept; the mesh is the same on output as on input.

**Notes:**

*When one applies a coarsening option, one only goes back on earlier refinements. This option must be understood as de-refinement. In particular, one will never be able to obtain a mesh coarser than the initial mesh.*

*The refinement or coarsening options may apply only to part of the mesh. This is obtained by the filtering option* GROUP_MA *or* GROUP_NO *.*

Two complementary options exist:

The first makes it possible to modify the mesh, in order to change the degree of the mesh:

- 'MODIFICATION': the mesh is modified globally.

The second makes it possible to read fields at the Gauss points which have been updated on the new mesh:

- 'LECTURE': the fields at the Gauss points are read.

### 4.2 Operand MAILLAGE_N

```text
♦    MAILLAGE_N    =    man
```

The mesh of type [maillage] to be adapted or modified. Warning, the adaptation can bear only on the following mesh cells: point mesh cells, segments, triangles, quadrangles, tetrahedra, hexahedra or pentahedra. If one supplies a mesh comprising other mesh cells, for example pyramids, two situations are possible: either a stop in error, or an adaptation on the authorised zone and an unchanged restitution of the rest of the mesh. The choice between these two modes of operation is made by the keyword ELEMENTS_NON_HOMARD.

The mesh is of degree 1 or 2, but it is not possible to mix the two.

In all cases, the presence of enriched HEXA27 mesh cells is forbidden.

When the choice has been made to read fields at the Gauss points, one gives here the mesh on which they lie.

### 4.3 Operand MAILLAGE_NP1

```text
◊    MAILLAGE_NP1    =    co (manp1)
```

The name of the concept of type [maillage] which will contain the mesh resulting from the adaptation. This name must respect the usual constraints on concept names (8 characters at most) and must not already have been used.

### 4.4 Operand MAILLAGE_NP1_ANNEXE

```text
♦    MAILLAGE_NP1_ANNEXE    =    co (manp1ann)
```

This operand makes it possible to produce a mesh analogous to the mesh obtained by the operand MAILLAGE_NP1, but of different degree. This is useful in thermo-mechanics, where the thermal analysis takes place on the mesh in degree 1 and the mechanics on the same mesh but in degree 2. This name must respect the usual constraints on concept names (8 characters at most) and must not already have been used.

### 4.5 Operand IDENTIFICATION

```text
◊    IDENTIFICATION    =    refmesh
```

Suppose that the mesh resulting from an adaptation (M1) is then slightly modified (into M1bis). If one adapts this modified mesh, one will naturally not be able to benefit from coarsening.

In this situation, it is possible to indicate that the modified mesh (MAILLAGE_N=M1bis) may be considered of the same lineage as M1 by indicating IDENTIFICATION=M1. Thus, the history of M1 will be able to serve to coarsen M1bis.

Of course, it is essential that the meshes be very close and that the result of the adaptation be checked carefully.

### 4.6 Choice of the field driving the adaptation

In the case of a free adaptation, the driving of the mesh cells to be refined or coarsened is carried out by a field. This field is contained either in a result data structure, or in a field of quantities (grandeurs). This field may be an error-indicator field in the numerical sense of the term (QIRE_ELEM for example) but this is not mandatory; any field may be used. One may for example drive the adaptation by the stress field or by a field built on purpose such as a distance or a damage criterion. It is enough that this field be defined by its name as described in the documents [U4.81.01](doc:u4.81.01), [U4.81.02](doc:u4.81.02) or [U4.81.03](doc:u4.81.03).

If the field is a field at the nodes, the refinement/coarsening decision will be taken on each edge according to the values of the field on its nodes. If the field is a field constant per element, it is this value which will drive the refinement/coarsening of the mesh cell. If the field is a field at the nodes per element or at the Gauss points, the algorithm will rely on the maximum value in the mesh cell in order to decide on the refinement/coarsening.

#### 4.6.1 Operand RESULTAT_N

```text
/    ◊    RESULTAT_N    =    resun
```

This operand makes it possible to designate the concept of type [resultat] which contains the field to be used for free adaptation.

##### 4.6.1.1 Operand NOM_CHAM

```text
◊    NOM_CHAM    =    nomsymb
```

One specifies here which field is used to drive the adaptation.

**Warning:**

*The field must be present in the result; if it is absent, it is not computed automatically.*

#### 4.6.2 Operand CHAM_GD

```text
/    ◊    CHAM_GD    =    cham_gd_i
```

This operand makes it possible to designate the concept of type [cham_gd] which contains the field to be used to drive the free adaptation.

#### 4.6.3 Operand NOM_CMP

```text
◊    NOM_CMP    =    l_cmp
```

Name of the component of the field which must be used to drive the mesh adaptation. If several components are wished for, give the list here.

If no component is defined here, the command will take all those which exist in the field transmitted.

The type of taking into account of the component or components is driven by USAGE_CMP.

#### 4.6.4 Selection of the time parameter of the field

If the result data structure contains the required field for only a single order number, nothing is to be specified. It is the values of the field at this order number which will be used.

Otherwise, one must specify which number is involved. This is done by the designation of an order number or of a value of time instant. Refer to the document [U4.71.00](doc:u4.71.00) for the details on these keywords.

#### 4.6.5 Operand USAGE_CMP

```text
◊    USAGE_CMP    =    /    'NORME_L2'            [DEFAUT]
/    'NORME_INFINIE'
/    'ABSOLU'
/    'RELATIF'
```

One specifies here how to treat the various components of the field driving the adaptation. One starts from the principle that the refinement bears on the large values examined and, symmetrically, the coarsening bears on the small values. By default, one will filter the refinement and the coarsening by examining the L2 norm of the components of the field on the mesh cells (or the nodes), that is to say the square root of the sum of the squares of the values of the components (the so-called Euclidean norm).

If several components have been retained, one may choose between two types of norm: either the L2 norm, the default choice, or the infinity norm, that is to say the greatest of the absolute values of the components.

If a single component is retained to drive the adaptation, the choices NORME_L2, NORME_INFINIE and ABSOLU are equivalent: one will examine the absolute value of the field. An alternative is possible: using RELATIF makes it possible to drive the adaptation with the raw values of the field. In that case, for a field whose values are negative, the refinement bearing on the maximum values, it will be the zones where the value is close to 0 which will be refined; symmetrically, the coarsening will bear on the zones where the value is very large and negative.

#### 4.6.6 Operand USAGE_CHAMP

```text
◊    USAGE_CHAMP=    /'MAILLE'        [DEFAUT]
                     /'SAUT'
```

By default, the driving of the adaptation is done by sorting the values of the field transmitted, mesh cell by mesh cell or node by node.

With the SAUT variant, HOMARD will sort on the jump of the field between mesh cells, according to the following procedure. For each mesh cell, HOMARD begins by computing the maximum of the absolute difference between the value of the field on the current mesh cell and its value on each of the neighbouring mesh cells. This maximum is assigned to the current mesh cell. Then, one sorts the mesh cells on these maximum differences according to the usual criteria.

In 2D, the neighbours examined are the triangles/quadrangles which share an edge with the mesh cell in progress.

In 3D, they are the volume mesh cells which share a triangular or quadrangular face with the current mesh cell.

If the field is defined by node, the neighbours are the nodes which share an edge with the current node.

**Note:**

*This option makes it possible to adapt the mesh easily, setting oneself the objective of a regular variation of a field from one mesh cell to the next. Thus, choosing the type* SAUT *and the field* SIEF_ELGA *makes it possible to obtain a mesh in which the strong variations of stresses from a mesh cell to its neighbour will be reduced.*

#### 4.6.7 Operand ADAP_INIT

```text
◊    ADAP_INIT    =     /    'GARDER'            [DEFAUT]
                        /    'RAFFINER'
                        /    'DERAFFINER'
```

When the field driving the adaptation is defined over the whole mesh, this option has no effect.

Otherwise, it makes it possible to specify how the regions where this field is not defined are treated.

With the GARDER variant, the mesh cells of the regions where the indicator is not defined are *a priori* kept as they are. This is the default option.

With the RAFFINER variant, the mesh cells of the regions where the indicator is not defined are *a priori* cut.

With the DERAFFINER variant, the mesh cells of the regions where the indicator is not defined are *a priori* reactivated.

Obviously, this is only an initialisation and these decisions may evolve in order to ensure the conformity of the mesh, taking into account the decisions applied to the neighbouring mesh cells.

**Note:**

*This option is particularly useful when one uses an indicator built from a field. For example, one uses the damage computed in a given region whereas elsewhere it is not defined. One will be able to choose not to touch the other mesh cells or to attempt to coarsen them.*

*For example: in excavation analyses, mesh cells are removed from the model in order to simulate the digging; those mesh cells no longer carry an indicator value. If one does nothing, they remain in the mesh. If one chooses the* DERAFFINER *variant, they will be coarsened as the excavation progresses.*

### 4.7 Operand CRIT_RAFF_xxxx

In the case of free adaptation involving mesh refinement, one must define a high refinement criterion. All the mesh cells for which the field is greater than this criterion will be refined. It is important to look afterwards at the shape of the distribution of the field. This is possible thanks to the printouts produced by HOMARD in the mess file. One will find there in particular a table presenting this distribution in the form of a histogram; see chapter 5 for a commented example.

For the choice of the criterion, four variants are possible:

#### 4.7.1 Operand CRIT_RAFF_PE

```text
◊    /CRIT_RAFF_PE=    crp
```

The criterion is defined by a proportion of mesh cells to be refined. It is a real number lying between 0 and 1. The process is the following:

- computation of the number of mesh cells n corresponding to the proportion defined by crp, that is n=crp x total number of mesh cells
- refinement of the n mesh cells with the highest value of the field.

#### 4.7.2 Operand CRIT_RAFF_ABS

```text
/CRIT_RAFF_ABS=    cra
```

The criterion is defined by an absolute value of the field. All the mesh cells with a value greater than this value will be refined.

#### 4.7.3 Operand CRIT_RAFF_REL

```text
/CRIT_RAFF_REL=    crr
```

The criterion is defined by a relative value of the field. It is a number lying between 0 and 1. The process is the following:

- computation of the minimum and maximum values of the indicator,
- computation of the value corresponding to the required proportion: v= vmin + crr(vmax-vmin),
- refinement of all the mesh cells where the field is greater than this value.

#### 4.7.4 Operand CRIT_RAFF_MS

```text
◊    /CRIT_RAFF_MS=    crms
```

The criterion is defined by an absolute value of the field, computed as a function of the mean and of the standard deviation of this field. All the mesh cells with a value greater than this value will be refined. The criterion equals: mean + n*sigma, where n is the coefficient supplied, strictly positive.

### 4.8 Operand CRIT_DERA_xxxx

In the case of free adaptation involving coarsening, one must define a low coarsening criterion. All the mesh cells where the field is less than this criterion will be coarsened. Three variants are possible.

#### 4.8.1 Operand CRIT_DERA_PE

```text
◊    /CRIT_DERA_PE=    cdp
```

The criterion is defined by a proportion of mesh cells to be coarsened. It is a number lying between 0 and 1. The process is the following:

- computation of the number of mesh cells n corresponding to the proportion defined by cdp, that is n=cdp x
- coarsening of the n mesh cells with the lowest field value.

#### 4.8.2 Operand CRIT_DERA_ABS

```text
/CRIT_DERA_ABS=    cda
```

The criterion is defined by an absolute value of the field. All the mesh cells with a field value less than this value will be coarsened.

#### 4.8.3 Operand CRIT_DERA_REL

```text
/CRIT_DERA_REL= cdr
```

The criterion is defined by a relative value of the field. It is a number lying between 0 and 1. The process is the following:

- computation of the minimum and maximum values of the indicator,
- computation of the error value *v* corresponding to the proportion cdr such that: v= vmin + cdr(vmax-vmin),
- coarsening of all the mesh cells where the field is less than this value.

#### 4.8.4 Operand CRIT_DERA_MS

```text
◊    /CRIT_DERA_MS=    cdms
```

The criterion is defined by an absolute value of the field, computed as a function of the mean and of the standard deviation of this field. All the mesh cells with a value less than this value will be coarsened. The criterion equals: mean - n*sigma, where n is the coefficient supplied, strictly positive.

### 4.11 Operand DIAM_MIN

```text
◊    DIAM_MIN= diamin
```

One recalls that the diameter of a mesh cell is the length of the longest segment which it is possible to draw inside it. For a triangle or a tetrahedron, the diameter is the length of the longest side. For a quadrangle, a hexahedron or a pentahedron, the diameter is the length of the longest diagonal.

Giving a value to diamin makes it possible not to make a mesh extremely fine. A mesh cell which would be selected as having to be refined because of the driving field or of the geometric zone, but whose diameter is already less than this minimum value diamin, will not be cut; it will be kept as it is. Warning: it is nevertheless possible that in the end it will be cut all the same if its neighbours are, in order to respect the conformity of the final mesh.

By default, no limit is given: one may obtain mesh cells as small as one wishes.

### 4.12 Operand NIVE_MAX

```text
◊    NIVE_MAX= nivmax
```

It is the maximum level of refinement of the mesh. In other words a mesh cell of the initial mesh will not be able to be divided more than nivmax times in the whole of the process. This makes it possible to ensure that the mesh will not become extremely fine in the neighbourhood of a singularity: the minimum size of an edge will be its initial size divided by 2nivmax.

By default, no limit is given: one may cut as much as one wishes.

### 4.13 Operand NIVE_MIN

```text
◊    NIVE_MIN=    nivmin
```

It is the minimum level of coarsening of the mesh. That is to say that only the mesh cells resulting from at least nivmin mesh cuttings may be coarsened. This makes it possible to ensure that one will not go back up too far in the coarsening: one thus keeps a minimum fineness in the mesh.

By default, no limit is given: one may coarsen until the initial mesh is recovered.

### 4.14 Keyword MAILLAGE_FRONTIERE

```text
◊    MAILLAGE_FRONTIERE= maf
```

The choice of this option allows the adaptation process to follow the curvature of the boundaries of the mesh. The option applies exclusively to 1D boundaries. For 2D boundaries, one must use the option FRONTIERE_ANALYTIQUE. One supplies here a *Code_Aster* concept of mesh type which contains a fine mesh of the one-dimensional boundaries of the geometry. This mesh is therefore formed *a priori* only of segments. Their lengths are very much smaller than those of the boundary segments of the mesh to be adapted. If the adaptation process is led to cut a boundary segment, the new node will be placed on the mesh of the boundary. Thus the angles will be smoothed as the adaptations proceed.

The identification of the various boundaries is done by the groups, with the following rules:

- the boundaries are described by groups of segments;
- a boundary is described by the same group name in the analysis mesh and in the mesh of the boundary;
- a boundary can have only zero or two ends;
- it is neither indispensable nor inadvisable to include the straight boundaries;
- the boundary may just as well be external, the most common case, as internal, in order to separate two materials.
- the boundary is not necessarily plane; it may be a curve in 3D space such as the intersection of two cylinders for example.

Put another way, a group of boundary segments must comprise a list of segments forming a line.

**Note:**

*One will look at the test cases* *zzzz121d,* *zzzz175a, zzzz175c and* *zzzz259a for examples of driving the boundary following, as well as the HOMARD web site for a graphical illustration of the result obtained.*

#### 4.16.5 Operand TYPE_MAJ

```text
◊    TYPE_MAJ    =    /    'AUTO'                [DEFAUT]
                      /    'ISOP2'
```

One specifies here the type of update wished for.

By default, the 'AUTO' operation is ... automatic: the interpolation is carried out according to the nature of the field.

For a field constant per element, if a mesh cell is cut, the value of the field is carried over as it is onto the child mesh cells.

For a field at the nodes, the interpolation takes place with the P1 or P2 shape functions according to the support of the field. A variant is possible for fields at the nodes expressed on a mesh of degree 2. By specifying 'ISOP2', the interpolation is carried out by P1 shape functions expressed on the sub-mesh-cells of the element. This technique guarantees that the interpolated field respects the extreme values of the initial field on a mesh cell.

For a field at the Gauss points, the update takes place only in the cases where the mesh-cell types are homogeneous between the input and the output: triangle or tetrahedron. For the quadrangles, the hexahedra or the pentahedra, nothing is done because one does not know how to define the families of Gauss points on the triangles or tetrahedra produced. For a mesh of triangles, one proceeds thus:

- for a triangle unchanged after the adaptation, the values at the Gauss points are carried over identically.
- for a triangle cut, into 2 or into 4, one computes the mean value of the field over all the Gauss points and this value is assigned to all the Gauss points of all the child triangles.
- for a triangle which disappears (in the case of coarsening), one computes the mean of the field over all the Gauss points of this triangle and of its siblings and this value is assigned to all the Gauss points of the parent triangle which reappears.

This mechanism makes it possible to guarantee that the extreme bounds are not crossed. The same technique is applied to the tetrahedra.

**Warning:**

*There can be no consistency check between the type requested and the true type of the field to be interpolated.*

#### 4.16.6 Operand CHAM_MAJ

```text
♦    CHAM_MAJ    =    co(chpmaj)                [:ref:`K8 <K8>`]
```

Name of the concept which will contain the field expressed on the new mesh. This concept must not exist. It will be created automatically.

A field at the nodes or at the elements will be read automatically by the macro-command which requests the adaptation or the modification of the mesh. It will be available in the analysis as soon as the execution of the macro-command is finished. On the other hand, this is not possible for a field expressed at the Gauss points because Code_Aster needs to know the model in order to read. For that, one must proceed in 3 stages. The field is computed by the macro-command which requested the adaptation or the modification of the mesh, as for a field at the nodes. Then, a new model must be applied to the new mesh by the command AFFE_MODELE. Finally, the reading will be done by a new invocation of MACR_ADAP_MAIL by means of the parameter ADAPTATION = 'LECTURE' and the supply of the mesh and of the model.

### 4.21 Operand QUALITE

```text
◊    QUALITE    =    /    'NON'                            [DEFAUT]
                     /    'OUI'
```

If the choice is 'OUI', a report of the quality of the mesh cells is printed on the message file. The quality of a triangle is defined as being the ratio between the length of the longest side and the radius of the inscribed circle. The quality of a quadrangle is defined as the quotient of the product of the greatest length and of the averages over the sides and the diagonals by the smallest of the areas of the triangles internal to the quadrangles. Likewise, the quality of a tetrahedron is defined as being the ratio between the length of the longest side and the radius of the inscribed sphere. These ratios are normalised so as to equal 1 in the case of an equilateral triangle, of a square, of an equilateral tetrahedron or of an equilateral hexahedron. For any non-equilateral element, the quality is greater than 1. See reference [bib1] for detailed explanations.

The result is presented in the form of tables, with the extreme values.

The interpretation of the values produced depends on the numerical method employed for the analysis. Depending on whether the problem is isotropic or not, depending on the rapidity of the spatial variation of the data, depending on the analysis technique, one and the same mesh cell may lead to a good Jacobian or not. The essential point in a first stage is to locate the frankly bad mesh cells. If one observes that the maximum of quality exceeds 100, or even 1,000 or 100,000, one must be concerned: one or several mesh cells are very distorted and the mesh is certainly to be redone. In a second stage, this quality information must make it possible to compare two a priori correct meshes, without a large value. If the problem is isotropic, one will have an interest in using the mesh with the quality distribution closest to 1.

One will find illustrations of quality values of various mesh cells in [Ref.5].

### 4.22 Operand DIAMETRE

```text
◊    DIAMTRE    =    /    'NON'                            [DEFAUT]
                     /    'OUI'
```

If the choice is 'OUI', a report of the diameters of the mesh cells is printed on the message file. The diameter of a mesh cell is defined as the length of the longest segment which it is possible to insert into the mesh cell.

For a triangle or a tetrahedron, the diameter corresponds to the length of the longest side.

For a quadrangle, a hexahedron, a pentahedron or a pyramid, the diameter is the maximum between the length of the longest side and the length of the longest diagonal.

The result is presented in the form of tables, with the extreme values.

### 4.32 Operand ELEMENTS_ACCEPTES

```text
◊    ELEMENTS_ACCEPTES    =    /    'HOMARD'        [DEFAUT]
                               /    'IGNORE_PYRA'
```

In its current version, HOMARD knows how to read all the types of mesh cells but makes the adaptation bear only on certain ones: point mesh cells, segments, triangles, quadrangles, tetrahedra, hexahedra or pentahedra. The mesh is of degree 1 or 2, but it is not possible to mix the two.

By retaining the option 'HOMARD', the transmission of a mesh containing something other than these types of mesh cells will lead to a stop in error. This is the default option.

By choosing the option 'IGNORE_PYRA', one will be able to transmit a mesh comprising pyramids. The adaptation will bear only on the zones authorised by HOMARD. If, as a consequence of the propagation of the refinement, a forbidden zone comes to be touched, there will be a stop in error. Otherwise, when the refinement is limited to the authorised zone, the other mesh cells are returned without change.

In all cases, the presence of enriched HEXA27 mesh cells is forbidden.

## 5 Example

One will profitably look at the command files associated with the test cases zzzz121a, b, c, d, e, f and zzzz175a, b. They express the mesh-adaptation processes either by chaining of the commands or in the form of a loop in the Python language.

Here is an example of parameter setting of the macro-command.

```text
MACR_ADAP_MAIL    (
ADAPTATION= 'RAFF_DERA',
MAILLAGE_N= mun,
MAILLAGE_NP1= CO ("mdeux"),
RESULTAT_N= remeun,
NOM_CHAM= 'QIRE_ELEM',
NOM_CMP= 'ERREST'
NUME_ORDRE= 3,
CRIT_RAFF_PE= 0.01,
CRIT_DERA_PE= 0.25,
NIVE_MAX= 5
MAJ_CHAM    = _F    (
RESULTAT= rethun,
NOM_CHAM= 'TEMP',
TYPE_CHAM= 'NOEU_TEMP_R',
INST= 12.5,
CHAM_MAJ= CO ("tempdeux")
),
QUALITE= 'OUI',
)
```

This sequence will adapt the mesh contained in the concept mun and return a mesh concept of name mdeux. The adaptation is done by free refinement and coarsening, according to the field contained in the field QIRE_ELEM of the result remeun, at the 3rd time instant; the component used is ERREST. The mesh cells will be classified according to their decreasing error level. The first % will be refined; the last 25% will be candidates for coarsening. No mesh cell of the final mesh must result from more than 5 refinements.

The field TEMP of the result rethun at time instant 12.5 is expressed on the mesh mun. It will be expressed on the mesh mdeux in the form of the nodal temperature field tempdeux.

A summary of the quality of the mesh cells of the new mesh is produced. One does not check the interpenetration of the mesh cells.

Here is an example of the table presenting the distribution of the field driving the adaptation of the mesh.

![Figure](/figures/u7.03.01/sortie_tableau.png)

The diagnosis of the distribution of the field driving the mesh adaptation first recalls the extreme values encountered in the current analysis. Here the minimum is 0.353585x10-5 and the maximum is 0.33395x10-3. The mean value, 0.66371x10-4, and the standard deviation, 0.51323x10-4, are given. Then the distribution by equidistant interval starting from the optimum value, 0, is presented. One sees that for 880 triangles, the value of the field is less than 1.70x10-4, that is 94.02 % of the total number of triangles. Then, for 21 triangles the value of the field lies between 1.70x10-4 and 1.87x10-4, that is 2.24 % of the total number of triangles. Cumulatively, one therefore observes that for 901 = 880 + 21 triangles, the value of the field is less than 1.87x10-4, that is 96.26 % of the total. And so on. For example, for 99.79 % of the mesh cells, the value of the field is less than 2.55x10-4.

![Figure](/figures/u7.03.01/100000000000038C0000027CCFBF9B92587A26D1.png)

On the previous figure, one can see the representation, in the form of a histogram, of the percentages of mesh cells in each of the value ranges concerned. As one could also observe in the previous table, one observes that very few mesh cells concentrate the high values.

By displaying a representation of the cumulative percentage of mesh cells in a given value range, one has the following figure.

![Figure](/figures/u7.03.01/1000000000000393000002974145C471FA3E8626.png)

From this distribution of the values, one can deduce two consequences for the refinement strategies.

If one requests a refinement on a relative criterion of the value of the field, keyword CRIT_RAFF_REL, this amounts to selecting the mesh cells which lie to the right of the vertical line passing through this criterion. For example if one requests CRIT_RAFF_REL = 0.77, one will select all the mesh cells whose error is greater than 0.35358x10-5 + 0.77x(0.33395x10-3-0.35358x10-5), that is 2.58x10-3. One observes that this corresponds to very few mesh cells: only 2 exceed this value, that is 0.21% of the total. One had the impression of requesting an important refinement, 0.77 that is roughly a quarter, but in fact one refines almost nothing.

If one requests a refinement on a percentage of mesh cells, keyword CRIT_RAFF_PE, this amounts to selecting the mesh cells which lie above the horizontal line passing through this criterion. For example if one requests CRIT_RAFF_PE = 0.10, one will select the 10% worst mesh cells, that is 93 mesh cells. This is the horizontal line at 90%. Among those mesh cells, the «least bad» ones carry a value less than 1.36x10-4, that is 40% of the maximum value. This is fairly effective since one will have trapped the large discrepancies.

The consequence of these notes is that it is appropriate to carry out a first analysis of the distribution of the values of the field before choosing the type and the values of the refinement criteria. It is indeed useless, or even costly in terms of increase of the mesh size, to refine in zones where the field is not very strong. The adaptation will be all the more efficient if one has been able to reduce the mesh cells with a high value until a balance is obtained in the mesh.
