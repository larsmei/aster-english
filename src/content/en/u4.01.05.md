# 1 **u4.01.05** New features and modifications of version 9

**Summary:**

The purpose of this document is to provide an overall view of the syntax modifications and of the new possibilities of the *Code_Aster* commands introduced during the development of version 9, that is, since version 8.4.

Revision index B of this document thus reports the changes introduced since **version 9.1** of June 2007 and valid for **version 9.2** of December 2007.

Paragraph 2 deals with the syntactic changes which occurred between version 8.4 (December 2006) and version 9.1 (June 2007).

For further details, one should consult the documentation of the commands and the histor file of the corresponding sub-version (e.g.: [9.1.7], section *Support/Histor* of the site www.code-aster.org).

The commands affected are listed in alphabetical order.

## 1 New features between 9.1 and 9.2

### 1.1 New commands

#### 1.1.1 CALCUL

The purpose of this new command is to compute the elementary tangent matrices and the elementary internal forces, and to integrate the constitutive law (cf. [9.1.7]).

Its principle is: knowing U-, SIGMA-, VARI- and dU, one computes:

- SIGMA+, VARI+, the elementary tangent matrices, the elementary residual vectors if OPTION=('COMPORTEMENT', 'FORC_INT_ELEM', 'MATR_TANG_ELEM')
- SIGMA+, VARI+, the elementary residual vectors if OPTION=('COMPORTEMENT', 'FORC_INT_ELEM')

#### 1.1.2 FACTORISER and RESOUDRE replace FACT_GRAD/FACT_LDLT and RESO_GRAD/RESO_LDLT

The commands FACT_GRAD and FACT_LDLT have been merged into a single one: FACTORISER.

Likewise for RESO_GRAD and RESO_LDLT, which have been merged into RESOUDRE (cf. [9.1.14]).

The keyword MATR_FACT of RESO_LDLT becomes MATR.

The keyword MATR_ASSE of RESO_GRAD becomes MATR, and MATR_FACT becomes MATR_PREC.

### 1.2 General modifications

#### 1.2.1 Command variables

The use of temperature as a command variable in mechanics must now be done using AFFE_MATERIAU / AFFE_VARC / NOM_VARC=’TEMP’ instead of AFFE_CHAR_MECA / TEMP_CALCULEE.

The former syntax TEMP_CALCULE will have disappeared in the next version.

See the note concerning the reference temperature, § AFFE_MATERIAU/TEMP_REF.

#### 1.2.2 Constitutive behaviour ELAS_VMIS_PUIS

This constitutive behaviour, equivalent to VMIS_ISOT_PUIS in linear elasticity, has been available since 9.1.15.

The keyword ELAS_VMIS_PUIS (analogue of ELAS_VMIS_TRAC) appears in the commands STAT_NON_LINE, DYNA_NON_LINE and CALC_G.

#### 1.2.3 Distributed parallel MUMPS solver

This change consists in calling the MUMPS solver in distributed parallel version, as opposed to the centralised parallel version. In both cases, the solution of the linear system is performed in parallel on several nodes and processors of the machine. In the distributed version, the computation of the elementary matrices is distributed over the various processors, then the assembly, and finally the solution of the system. The distribution mode is chosen via the keyword PARALLELISME.

The operators concerned are DYNA_LINE_TRAN, DYNA_NON_LINE, MECA_STATIQUE, THER_LINEAIRE, THER_NON_LINE, STAT_NON_LINE.

Friction is excluded from the scope of use. The development is still undergoing validation

The solver is available only on the centralised server for the moment (cf. [9.1.16]).

### 1.3 Removals

#### 1.3.1 FACT_GRAD/FACT_LDLT and RESO_GRAD/RESO_LDLT

Replaced by FACTORISER and RESOUDRE (cf. [9.1.14]).

### 1.4 Modified commands

#### 1.4.1 AFFE_CHAR_CINE

**EVOL_IMPO new:**

- Makes it possible to define the result of a previous analysis as a kinematic loading. The intended application is the structural zoom, in which the displacements obtained during the first analysis are imposed on the boundary of the zoom (cf. [9.1.14]).

#### 1.4.2 AFFE_CHAR_MECA / AFFE_CHAR_MECA_F

**PRES_REP / FISSURE new:**

- Makes it possible to apply a pressure on an unmeshed crack, defined by DEFI_FISS_XFEM (cf. [9.1.8]).

**CONTACT / GROUP_MA_FOND new:**

- Together with the use of METHODE=’VERIF’, this keyword makes it possible to define the crack tip on which it is unnecessary to check interpenetration (cf. [9.1.11]).

**LIAISON_SOLIDE / TRAN, ANGL_NAUT, CENTRE new:**

- These keywords make it possible to impose the displacement of a non-deformable part of the model (cf. [9.1.13]).

**APPL_FORC_xxxx removed:**

- These keywords were used for the loading GRAPPE_FLUIDE (cf. [9.1.22]).

#### 1.4.3 AFFE_MATERIAU

**AFFE_VARC / FONC_INST new:**

- This keyword has been added in order to apply a loading, thermal for example, whose time evolution is different from that of the mechanical analysis. For example, the mechanical analysis can cycle over a thermal evolution. The function supplied then makes it possible to pass from the time of the loading to the time of the mechanical analysis (cf. [9.1.5]).

**TEMP_REF no longer has a default value:**

In order to avoid the risk of wrong results with an incorrect account taken of the reference temperature, an analysis is considered as thermo-mechanical if a temperature field exists on the finite element in question. In that case it is compulsory to supply both the reference temperature AND the thermal expansion coefficient. If one of these two values is absent, the code will stop in fatal error with a warning message for the user (cf. [9.1.15]).

#### 1.4.4 AFFE_MODELE

**MODELISATION: GRILLE_EXCENTRE replaces** **GRILLE:**

- Account taken of the offset (cf. [9.1.4]).

**MODELISATION: xx_XFEM_CONT new:**

- The finite elements xx_XFEM no longer have a degree of freedom for contact, in order to treat efficiently the problems without contact. The finite elements xx_XFEM_CONT are added for that purpose (cf. [9.1.11]).

#### 1.4.5 CALC_FONCTION

**FRACTILE new:**

- Computation of the fractile of nappes or of functions (cf. [9.1.8]).

**PUISSANCE / EXPOSANT real:**

- It is now possible to take the real power of a function (cf. [9.1.9]).

#### 1.4.6 CALC_MATR_ELEM

**MECA_GYRO new:**

- Computation of the gyroscopic damping matrix for the analysis of shaft lines (cf. [9.1.16]).

#### 1.4.7 CALC_TABLE

**VALE_xxx modified:**

- In IMPR_TABLE and CALC_TABLE, it is possible to filter the rows of a table. By repeating the factor keyword FILTRE, one applies an AND between the filters. One can now apply an OR by giving several values to the keywords VALE_xxx (cf. [9.1.3]).

#### 1.4.8 COMB_SISM_MODAL

**MULTI_APPUI new:**

- Allows account to be taken of correlated excitations in the multi-support case. The user now has the choice between MONO_APPUI=’OUI’, MULTI_APPUI=’CORRELE’ (new option) or ’DECORRELE’, which corresponds to the option available previously (cf. [9.1.18]).

#### 1.4.9 CREA_MAILLAGE

**HEXA20_27 new:**

- Makes it possible to transform the HEXA20 elements of a mesh into HEXA27 elements (cf. [9.1.6]).

#### 1.4.10 CREA_RESU

**OPERATION=’ASSE’ new:**

- Makes it possible to assemble several thermal analysis results, possibly translating them. This operation can also be supplemented with AFFE_MATERIAU/AFFE_VARC, FONC_INST in order to repeat a thermal loading (cf. [9.1.5]).

#### 1.4.11 DEBUT and POURSUITE

**RESERVE_CPU new default value:**

- This keyword makes it possible to reserve a fraction of the total time of a study (requested in astk) at the end of the run for the system tasks (compression, file copy…). The value is set by default to 10% of the time requested, with a limit of 900 seconds (cf. [9.1.20).

#### 1.4.12 DEFI_FONCTION

**ABSCISSE / ORDONNEE new:**

- Equivalents of the keywords LIST_PARA and LIST_RESU, except that one passes lists of values instead of list_r8 concepts (cf. [9.1.9]).

#### 1.4.13 DEFI_LIST_ENTI

**OPERATION = ‘NUME_ORDRE’ new:**

- This makes it possible to extract the order numbers of a resultat concept in a given interval. One can then use this list in all the commands which accept the keyword LIST_ORDRE (cf. [9.1.16]).

#### 1.4.14 DEFI_MATERIAU

**RELATION_KIT / THM_DIFFU new:**

- For unsaturated models and the coupling laws LIQU_xxx_GAZ, the user can define the law by choosing either HYDR_UTIL as before, or HYDR_VGM: Mualem–Van Genuchten law. In the latter case, five parameters must be defined (cf. [9.1.4]).

**LETK new:**

- This is a viscoplastic law of Laigle and Klein for modelling the constitutive behaviour of argillite, the host rock of a storage site (cf. [9.1.17]).

**HUJEUX new parameters:**

- This is the extension of the Hujeux law to the cyclic case (cf. [9.1.18]).

#### 1.4.15 DYNA_TRAN_MODAL

**NB_MODE_DIAG removed:**

- This keyword was not used (cf. [9.1.11]).

#### 1.4.16 FORMULE

**VALE_C new:**

- Offers the possibility of defining a formula with a complex value (cf. [9.1.1]).

#### 1.4.17 IMPR_RESU

**PARTIE extended:**

- Makes it possible to select the real or imaginary part which will be printed (cf. [9.1.2]).

**GMSH / TYPE_CHAMP new:**

- Makes it possible to choose the type of field and the components to be printed in GMSH format: scalar (the default), vector (VECT_2D, VECT_3D) or tensor (TENS_2D, TENS_3D) (cf. [9.1.10]).

#### 1.4.18 IMPR_TABLE

Cf. CALC_TABLE.

#### 1.4.19 LIRE_RESU

**TYPE_RESU=’EVOL_VARC’ new:**

- Makes it possible to read, in MED format, fields which will then be used as command variables: temperature, irradiation… (cf. [9.1.17]).

**COMP_INCR new:**

- When one reads a result, the keyword COMP_INCR makes it possible to recreate the constitutive-behaviour information which cannot be stored in MED format (cf. [9.1.18]).

#### 1.4.20 MACRO_MODE_MECA and NORM_MODE

**MASS_INER removed:**

- In order to facilitate the use of the command and avoid the risks of error, the mass is computed by NORM_MODE (cf. [9.1.18]).

#### 1.4.21 MACR_CARA_POUTRE

**GROUP_NO new:**

- Same operation as the existing keyword NOEUD (cf. [9.1.9]).

#### 1.4.22 POST_CHAM_XFEM

**NOM_CHAM extended:**

- Possibility of post-processing the internal-variable fields (cf. [9.1.4]).

#### 1.4.23 POST_ELEM

**MINMAX new:**

- Makes it possible to extract the extrema of a component of a field into a table, possibly in the course of time. The table contains the location (mesh cell or node) of the extrema (cf. [9.1.18]).

#### 1.4.24 POST_MAIL_XFEM

**PREF_NŒUD_X/M/P, PREF_MAILLE_X new:**

- Makes it possible to impose the prefix of the names of the nodes created by the command (cf. [9.1.5]).

#### 1.4.25 POST_RCCM

**NUME_PASSAGE removed:**

- The use of NUME_PASSAGE is no longer possible for the type TUYAUTERIE. In *Code_Aster*, only simple passage paths are treated for the moment (cf. [9.1.22]).

#### 1.4.26 TEST_FICHIER (developer command)

**NB_CHIFFRE, EPSILON removed,** **TYPE_TEST, NB_VALE, VALE new:**

- See the documentation of the command (cf. [9.1.21]).

#### 1.4.27 THER_LINEAIRE, THER_NON_LINE, THER_NON_LINE_MO

**Alignment of the syntax with** **STAT_NON_LINE** (cf. [9.1.19]):

- TEMP_INIT/NUME_INIT becomes ETAT_INIT/NUME_ORDRE.
- Under INCREMENT, NUME_INIT and NUME_FIN become NUME_INST_INIT and NUME_INST_FIN.

Time-step subdivision is available and works under the same conditions as STAT_NON_LINE (cf. **SUBD_METHODE** ).

For THER_NON_LINE only, **OBSERVATION** is available with the same syntax and the same operation as in STAT_NON_LINE.

In THER_NON_LINE_MO, the only modification concerns ETAT_INIT/NUME_ORDRE (because there is no list of time steps).

## 2 New features between 8.4 and 9.1

### 2.1 New commands

#### 2.1.1 DEFI_GEOM_FIBRE

Within the framework of multi-fibre beam modellings, this operator defines fibre groups making up the cross-section of the beams. A material and a constitutive behaviour are then assigned to each fibre group via DEFI_COMPOR (cf. [9.0.10]).

#### 2.1.2 MACRO_EXPANS

The aim of this macro-command is to perform an expansion of experimental data onto a numerical model. For that purpose, it chains the commands PROJ_MESU_MODAL, REST_BASE_PHYS and PROJ_CHAMP (cf. [9.0.4]).

#### 2.1.3 MACRO_VISU_MEIDEE

This macro-command takes up the features of the MEIDEE tool developed by EDF R&D/MF2E, which performs identification of fluid forces. The macro-command is composed of a GUI with which the user interacts in order to adjust the analysis/test correlation (cf. [9.0.4]).

#### 2.1.4 OBSERVATION

This is a macro-command which facilitates the projection of the results between the numerical model and the experimental model, taking into account assumptions on the sensors (single-axis, for example), and managing the changes of frame (cf. [9.0.23]).

### 2.2 General modifications

#### 2.2.1 Command variables

The use of temperature as a command variable in mechanics must now be done using AFFE_MATERIAU / AFFE_VARC / NOM_VARC=’TEMP’ instead of AFFE_CHAR_MECA / TEMP_CALCULEE.

#### 2.2.2 Substructuring

Homogenisation of the vocabulary for substructuring: MAILLE is replaced by SUPER_MAILLE in CALC_VECT_ELEM, DYNA_NON_LINE, STAT_NON_LINE in order to be consistent with DEFI_MAILLAGE.

#### 2.2.3 Keyword SOLVEUR

**ELIM_LAGR2 new**

- Within the framework of the use of the MUMPS solver, this keyword makes it possible to eliminate the 2nd Lagrange degree of freedom. This is the new default behaviour (cf. [9.0.2]).

**REAC_RESI new**

- For the FETI method, this keyword determines the frequency of updating of the computation of the residual of the GCPC of FETI (cf. [9.0.17]).

#### 2.2.4 Version of homard

The version of homard compatible with *Code_Aster* 9.1 is version 8.7.

### 2.3 Removals

#### 2.3.1 DYNA_TRAN_EXPLI

The command DYNA_TRAN_EXPLI has been removed. The explicit transient analysis is available in DYNA_NON_LINE.

#### 2.3.2 IMPR_CLASSI

The command made it possible to print the results of a modal analysis for the code CLASSI.

### 2.4 Modified commands

#### 2.4.1 AFFE_CARA_ELEM

**AFFE_SECT, AFFE_FIBRE replaced by** **MULTIFIBRE, GEOM_FIBRE:**

- These new keywords make it possible to assign fibre groups (coming from DEFI_GEOM_FIBRE, from the mesh of the beam cross-section) to the beam elements (cf. [9.0.10]).

#### 2.4.2 AFFE_CHAR_MECA / AFFE_CHAR_MECA_F

**PRE_COND, COEF_RESI new**

- Make it possible to choose the preconditioner and its convergence criterion for the Projected Conjugate Gradient algorithm of contact, method GCP (cf. [9.0.4]).

**RECH_LINEAIRE new (experimental)**

- This keyword has an effect on the way of moving along the search direction: does one remain inside the convex set of admissible stresses, or not? (cf. [9.0.4]).

**ALGO_CONT/ALGO_FROT new**

- Makes it possible to choose (finely!) the formulation of the continuous contact/friction method (Lagrangian, stabilised Lagrangian or augmented Lagrangian) (cf. [9.0.9]).

**USURE new**

- Makes it possible to take into account an Archard-type wear model of the slave surface (cf. [9.0.9]).

**MODL_AXIS removed**

- The axisymmetric modelling is checked from the model and not from this keyword (cf. [9.0.17]).

**CONTACT_XFEM / METHODE=’XFEM’ new**

- Definition of contact on the lips of cracks (unmeshed) modelled with the XFEM method. Note that the contact GLISSIERE is now available with X-FEM (cf. [9.0.21]).

#### 2.4.3 AFFE_MATERIAU

**AFFE_COMPOR new**

- Makes it possible to assign a multi-fibre beam constitutive behaviour (cf. [9.0.10]).

**NOM_VARC / LIST_NOM_VARC addition of** **‘TEMP’**

- Addition of temperature as a command variable under AFFE_VARC (cf. [9.0.15]).

#### 2.4.4 AFFE_MODELE

**C_PLAN_XFEM, D_PLAN_XFEM replace** **C_PLAN_X, D_PLAN_X**

- Homogenisation of the names of the modellings (cf. [9.0.11]).

**3D_INCO_GD, AXIS_INCO_GD, D_PLAN_INCO_GD new modellings**

- New nearly incompressible modellings in large strains (cf. [9.0.11]).

**3D_JOINT new modelling**

- Extension to 3D of the joint elements and of the constitutive law CZM_EXP_REG (cf. [9.0.13]).

**New HH and HH2 modellings**

- Unsaturated hydraulic modellings of HH and HH2 type (cf. [9.0.26]).

Exhaustive list: 3D_HHS, 3D_HHD, 3D_HH2S, 3D_HH2D, AXIS_HHS, AXIS_HHD, AXIS_HH2S, AXIS_HH2D, D_PLAN_HHS, D_PLAN_HHD, D_PLAN_HH2S, D_PLAN_HH2D

#### 2.4.5 CALC_ELEM

**ERRE_THM / LONGUEUR, PRESSION, TEMPERATURE new**

- Characteristic values making it possible to non-dimensionalise the computation of the error indicator in THM (cf. [9.0.20]).

#### 2.4.6 CALC_FONCTION

**METHODE=’COMPLET’ for the FFT**

- Activates the algorithm which accepts an arbitrary number of samples for the computation of the FFT (cf. [9.0.9]).

#### 2.4.7 CALC_NO

**OPTION=’ARCO_NOEU_SIGM’**

- Computation of the arch and cantilever stresses (cf. [9.0.10]).

#### 2.4.8 CREA_RESU

**OPERATION=’PREP_VRC1’/’PREP_VRC2’**

- Make it possible to compute the temperature in the layers of multi-layer shells, either from a field of functions of time and of space (PREP_VRC1), or from a temperature computed on a shell model containing TEMP/TEMP_INF/TEMP_SUP (cf. [9.0.15]).

#### 2.4.9 DEBUT and POURSUITE

**DYNAMIQUE new (experimental)**

- Objects of a size greater than that specified are not allocated in the jeveux common, but dynamically in an independent memory area. Experimental, because the release of the memory is not yet managed ideally (cf. [9.0.11]).

#### 2.4.10 DEFI_CABLE_BP

**MAILLAGE removed**

- The mesh is recovered by the command from the MODELE supplied (cf. [9.0.15]).

#### 2.4.11 DEFI_COMPOR

**GEOM_FIBRE, MATER_SECT, MULTIFIBRE new**

- Make it possible to define the constitutive behaviour by fibre group and the material of the section to be homogenised. One can thus take several materials into account (one per fibre group) on a multi-fibre beam element (POU_D_EM, POU_D_TGM) (cf. [9.0.10]).

#### 2.4.12 DEFI_FISS_XFEM

**CONTACT removed**

- The definition of contact on the crack lips is done in AFFE_CHAR_MECA, keyword CONTACT, METHODE=’XFEM’ (cf. [9.0.21]).

**FORM_FISS new**

- Makes it possible to define simply the shape of the crack, elliptical only for the moment, by giving a few geometrical parameters (cf. [9.0.23]).

#### 2.4.13 DEFI_FOND_FISS

**NOEUD_EXTR, GROU_NO_EXTR replace** **MAILLE_ORIG,GROU_MA_ORIG**

- Definition of the crack-tip node (cf. [9.0.12]).

#### 2.4.14 DEFI_MAILLAGE

**MACR_ELEM replaces** **MACR_ELEM_STAT**

- Static macro-elements and dynamic macro-elements are now accepted (cf. [9.0.13]).

#### 2.4.15 DEFI_MATERIAU

**Becomes re-entrant**

- One can now enrich a material (for example, add mechanical parameters to an initially thermal material). On the other hand, one cannot replace a constitutive behaviour which is already present (cf. [9.0.1]).

**DIS_ECRO_LINE new**

- Parameters for the viscoelastic constitutive law with mixed hardening on discrete elements (cf. [9.0.3]).

**DIS_VISC new**

- Parameters for the viscous-damper type law on discrete elements (cf. [9.0.3]).

**HUJEUX new**

- Parameters for the Hujeux THM law (cf. [9.0.10]).

**Constitutive behaviours** **ROUSS_PR, ROUSS_VISC:** **VISC_SINH_FO, BETA, DP_MAXI new**

**KOCKS_RAUCH new**

- Parameters for the viscoplastic constitutive law of Kocks & Rauch for the single crystal (cf. [9.0.12]).

**A_AMORC, B_AMORC, D_AMORC, R_AMORC new**

- Coefficients required for the computation of the initiation factor according to the RCCM (cf. [9.0.16]).

**ZETA_F, RG0, TOLER_ET, ZETA_G new**

- Parameters for the integration of swelling and of creep under irradiation for the constitutive law IRRAD3M (cf. [9.0.20]).

**NON_LOCAL/PENA_LAGR new**

- Penalty coefficient for the new algorithm concerning models with a gradient of internal variables (cf. [9.0.23]).

**ELAS_2NDG new**

- Parameters of second-gradient elasticity, modelling with a gradient of volumetric strain (cf. [9.0.26]).

**ARCHIVAGE, MODELISATION, SIGM_IMPOSE, EPSI_IMPOSE new**

- For the analysis at a material point, these keywords make it possible to archive only part of the results, to apply loading paths in 2D, and to define the loading path in imposed stresses or strains (cf. [9.0.5]).

**COMP_ELAS, RECH_LINEAIRE, SIGM_INIT, EPSI_INIT, VARI_INIT new**

- Make it possible to extend the use to non-linear elastic constitutive behaviours, to activate the line search and to define a non-zero initial state (cf. [9.0.20]).

**VARI_REFE new**
