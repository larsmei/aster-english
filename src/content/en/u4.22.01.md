# u4.22.01 Operator DEFI_GROUP

## 1 Purpose

Define, in an existing mesh, new node groups or mesh-cell groups. This can make it easier to define new geometric loci for data input or for post-processings.

To create new groups, one uses topological, logical or geometric criteria.

Modifies a data structure of type maillage, squelette or grille.

## 3 Operands

### 3.1 General points on the operands

This command treats in the same way the concepts of type maillage or squelette. In what follows one will use the vocabulary "mesh".

This command makes it possible to define new mesh-cell groups (or node groups) in an existing mesh: one enriches the mesh ma. No new mesh cell and no new node are created. They must already be present in the mesh in order to be able to be used.

The definition of a new group can be done in several ways:

- by a Boolean operation on existing groups: intersection (INTERSEC), union (UNION) or difference (DIFFE),
- according to a geometric criterion: mesh cells of which a node belongs to a given sphere, …
- for the node groups, by referring to existing mesh-cell groups. The node group thus defined contains **all** the nodes of the mesh cells of the original mesh-cell group (keywords TOUT_GROUP_MA and GROUP_MA).

The operator treats first the keyword CREA_GROUP_MA so that one can use the mesh-cell groups thus defined in the keyword CREA_GROUP_NO.

At each occurrence of a keyword CREA_GROUP_MA(_NO) one defines a new named group (keyword NOM). This new group can then be reused in the following occurrences to define new groups by intersection, union, ...

The keywords DETR_GROUP_MA and DETR_GROUP_NO make it possible to "destroy" mesh-cell groups or node groups. The mesh cells and the nodes of these groups are not removed; it is only the definitions of the groups that are erased. These keywords are useful for example in Python loops when one wishes to create a group at each iteration of the loop: one begins by destroying this group then one recreates it under the same name. This avoids changing the group name at each iteration.

One may note that most of the functionalities of DEFI_GROUP can be done directly in the SMESH module of SALOME, namely:

- Boolean operation on existing groups,
- creation of a group by mesh-cell type (SMESH filter Type),
- according to a geometric criterion (SMESH filter LyingOn),
- according to a normal-angle criterion for surface mesh cells (SMESH filter Coplanar),
- for the mesh-cell groups resting on node groups (SMESH function 'Group based on nodes of other groups'),
- for the node groups, by referring to existing mesh-cell groups (SMESH function 'Group based on nodes of other groups'),
- deletion of groups.

### 3.2 Operands MAILLAGE and GRILLE

```text
| MAILLAGE= ma
```

ma is the name of the mesh that one wishes to "enrich".

gr is the name of the auxiliary grid that one wishes to "enrich".

### 3.3 Keywords DETR_GROUP_MA and DETR_GROUP_NO

These two factor keywords make it possible to remove the definition of mesh-cell groups or of node groups. These keywords are sometimes necessary because the code stops with a fatal error if one attempts to create a group whose name is already used. The group must be destroyed before its name can be reused. The behaviour of the two keywords is similar and we shall speak here only of DETR_GROUP_MA.

```text
DETR_GROUP_MA=_F(NOM=(gm1,gm2, ...)),
```

The factor keyword DETR_GROUP_MA is in principle repeatable but this is never necessary because the keyword NOM makes it possible to indicate a list of names of groups to destroy (gm1, gm2, …).

It is important to know that all the occurrences of the keyword DETR_GROUP_MA are treated **before** those of the keyword CREA_GROUP_NO, because the aim of this keyword is to be able to reuse the destroyed name. One must also know that the destruction of a non-existent group does not lead to any alarm message. These choices make it possible for example to do, in a Python loop:

```python
for i in range(n) :

    DEFI_GROUPE(reuse=MA, MAILLAGE=MA,

    DETR_GROUP_MA=_F(NOM('GM1',),

    CREA_GROUP_MA=_F(NOM='GM1', ...
```

During the first iteration, the group 'GM1' does not exist; one requests its destruction but no alarm message is issued.

**Note:**

| *As the destructions take place at the start of the command, it is impossible to modify a group by making a single call to* *DEFI_GROUP* *. For example, one cannot make a group 'grow' (in a loop) by adding a small group (* *b1* *) to it:* *for i in range(n):* *b1=new group ...* *DEFI_GROUP(reuse=MA,MAILLAGE=MA,* *CREA_GROUP_MA=_F(NOM='tout', UNION=('tout','b1'),),)* *To do this, one must call* *DEFI_GROUP* *twice:* *for i in range(n):* *b1=new group ...* *DEFI_GROUP(reuse=MA,MAILLAGE=MA,* *DETR_GROUP_MA=_F(NOM='tout2'),* *CREA_GROUP_MA=_F(NOM='tout2', UNION=('tout','b1'),),)* *DEFI_GROUP(reuse=MA,MAILLAGE=MA,* *DETR_GROUP_MA=_F(NOM='tout'),* *CREA_GROUP_MA=_F(NOM='tout', UNION=('tout2','b1'),),)* |
| --- |

### 3.4 Keyword CREA_GROUP_MA

```text
|    CREA_GROUP_MA
```

One occurrence of this factor keyword makes it possible to define a new mesh-cell group.

#### 3.4.1 Operand NOM

```text
NOM= gma
```

One gives here the name (with "quotes") of the new mesh-cell group.

#### 3.4.2 Operand TYPE_MAILLE

```text
TYPE_MAILLE=    /'TOUT'/'3D'/'2D'/'1D' (DEFAUT='TOUT')
/'SEG2'/'TRIA3'/'QUAD4'/.../'PYRAM13'
```

This keyword makes it possible to filter the mesh cells that one will put into the new mesh-cell group. By default, there is no filter, but if the user writes for example: TYPE_MAILLE='2D', the group created will contain only surface mesh cells.

The user may also filter the group to be created for a particular mesh-cell type (TRIA3, HEXA27, …). All the mesh-cell types (POI1, SEG2, SEG3, SEG4, …, PYRAM13) are allowed.

Examples:

CREA_GROUP_MA=_F(NOM='VOLUM', 'TOUT='OUI', TYPE_MAILLE='3D')

makes it possible to create the group of all the volume mesh cells (HEXA, PENTA, ...) of the mesh.

CREA_GROUP_MA=_F(NOM='VOLH27', 'GROUP_MA='GMA1', TYPE_MAILLE='HEXA27')

makes it possible to create the group of all the mesh cells of type 'HEXA27' contained in the GROUP_MA. GMA1.

#### 3.4.3 Operand TOUT

```text
TOUT= 'OUI'
```

This keyword makes it possible to define a group containing all the mesh cells of the mesh.

#### 3.4.4 Operand INTERSEC

```text
INTERSEC= (gma1, gma2, gma3,...),
```

The new mesh-cell group will be obtained by taking all the mesh cells of gma1 that also belong to gma2, gma3,.... The order of the mesh cells remains that of gma1.

#### 3.4.5 Operand UNION

```text
UNION= (gma1, gma2, gma3,...)
```

The new mesh-cell group will be obtained by taking all the mesh cells of gma1, then by adding the mesh cells of gma2 that do not belong to gma1, then those of gma3 that belong neither to gma1 nor to gma2, and so on.

#### 3.4.6 Operand DIFFE

```text
DIFFE = (gma1, gma2, gma3,...)
```

The new mesh-cell group will be obtained by taking all the mesh cells of gma1 that do not belong to the other groups of the list. The order of the mesh cells remains that of gma1.

#### 3.4.7 Sub-group of an existing group: keywords GROUP_MA / POSITION / NUME_INIT / NUME_FIN

One can create a new mesh-cell group by selecting certain mesh cells of an existing group.

**1st possibility:**

One creates a group **of a single mesh cell** by specifying, with the keyword POSITION, the mesh cell sought.

**Example:**

```text
CREA_GROUP_MA= _F (    GROUP_MA= G1    ,    POSITION= 'INIT' ,    NOM= G1I )
```

The group G1I contains the 1st mesh cell of the group G1.

**2nd possibility:**

One creates a group containing the mesh cells lying between the ranks nuini and nufin (inclusive) in an existing group.

**Example:**

```text
CREA_GROUP_MA=_F (GROUP_MA= G1,    NUME_INIT= 3    ,    NUME_FIN = 7,    NOM = G1P)
```

The group G1P contains mesh cells 3, 4, 5, ..., 7 of G1.

**Warning:**

*These keywords use the notion of the order of the mesh cells in a mesh-cell group. This order is often unknown to the user. It may depend on the pre-processor. It is the order of the mesh cells at the time of the definition of the GROUP_MA in the Aster mesh file.*

#### 3.4.8 Operand OPTION = 'FACE_NORMALE'

```text
OPTION = 'FACE_NORMALE'
```

This option makes it possible to define a GROUP_MA made up of surface mesh cells whose normal is parallel to the direction of the vector defined by its components if one uses the keyword VECT_NORMALE, or to that of the first vector of the new basis defined by the change of frame due to the nautical angles.

In 3D, one assumes that the surface mesh cells are plane facets. They are of type TRIA3, TRIA6, QUAD4, QUAD8 or QUAD9. If one calls ${X}_{1}$ , ${X}_{2}$ , and ${X}_{3}$ the position vectors of the first three vertex nodes of the element, the normal is determined by the vector product: $({X}_{2}-{X}_{1})\mathrm{\wedge }({X}_{3}-{X}_{1})$ .

In 2D, one assumes that the surface mesh cells are straight segments. They are of type SEG2 or SEG3. If one calls ${X}_{1}$ and ${X}_{2}$ the position vectors of the two end nodes of the element, the normal is defined by $({X}_{2}-{X}_{1})\mathrm{\wedge }z$ where $z$ is the unit vector perpendicular to the plane and where 0. has been assigned as the third component of $({X}_{2}-{X}_{1})$ .

**Note:**

*A "facet" mesh cell will be retained if its normal is collinear with the normal vector defined by* *VECT_NORMALE. This condition must be satisfied to within a certain precision (keyword* *ANGL_PREC).*

*When one chooses an* *ANGL_PREC (for example 30. degrees), one in fact defines the group of the mesh cells whose normal belongs to the cone of axis* *VECT_NORMALE and of apex angle* *ANGL_PREC.*

*This can be used (for example) to group the mesh cells of a half spherical envelope (ANGL_PREC= 90.).*

##### 3.4.8.1 Operand ANGL_NAUT

```text
ANGL_NAUT =    a        en 2D
               (a,b)    en 3D
```

The nautical angles (a, b), defined in degrees, are the angles making it possible to pass from the global frame of definition of the coordinates of the nodes to a frame whose first vector designates the direction along which the normal of the surface mesh cells that one wishes to recover is oriented.

For the definition of the nautical angles, see the operator AFFE_CARA_ELEM [U4.42.01](doc:u4.42.01), operand ORIENTATION.

##### 3.4.8.2 Operand VECT_NORMALE

```text
VECT_NORMALE =    (x, y)        en 2D
                  (x, y, z)    en 3D
```

The coordinates x, y, z are those giving the direction along which the normal of the surface mesh cells that one wishes to recover is oriented.

##### 3.4.8.3 Operand ANGL_PREC

```text
ANGL_PREC =    a
```

It is the tolerance, in degrees, that one accepts on the angle formed by the vector supplied by the user and the vector normal to the surface element in order to assert that these two vectors have the same direction.

The default value of a is $0.5$ degree.

##### 3.4.8.4 Operand VERI_SIGNE

```text
VERI_SIGNE =        'NON'    ,
                    'OUI'    ,        [DEFAUT]
```

If one assigns the value 'NON' to VERI_SIGNE, the GROUP_MA will be made up of the surface mesh cells whose normal is parallel to the vector given by the user.

If one assigns the value 'OUI', the GROUP_MA will be made up of the surface mesh cells whose normal is parallel and has the same orientation as the vector given by the user.

The default value is 'OUI'.

##### 3.4.10.2 Operand GROUP_NO_CENTRE

The nautical angles a, b, defined in degrees, are the angles making it possible to pass from the global frame of definition of the coordinates of the nodes to a frame whose first vector designates the direction of the axis of the cylinder.

```

```

Let us call this list lno1.

    / 'AU_MOINS_UN' : la maille sera retenue au moins un de ses nœuds appartient à lno1
    / 'MAJORITE' : la maille sera retenue si plus de la moitié deses nœuds appartiennent à lno1
```

```

For a precise definition of the notions of Heaviside mesh cell and Crack-tip mesh cell, see R7.02.12, §3.2.5.

### 3.5 Keyword CREA_GROUP_NO

```text
|    CREA_GROUP_NO
```

One occurrence of this factor keyword makes it possible to define a new node group (for the keywords GROUP_MA and TOUT_GROUP_MA, one creates several node groups "at one go").

#### 3.5.1 Operand NOM

```text
NOM= gno
```

One gives here the name (with "quotes") of the new node group.

#### 3.5.2 Operand INTERSEC

```text
INTERSEC= (gno1, gno2, gno3,...)
```

The new node group will be obtained by taking all the nodes of gno1 that also belong to gno2, gno3,.... The order of the nodes remains that of gno1.

#### 3.5.3 Operand UNION

```text
UNION= (gno1, gno2, gno3,...)
```

The new node group will be obtained by taking all the nodes of gno1, then by adding the nodes of gno2 that do not belong to gno1, then those of gno3 that belong neither to gno1 nor to gno2, and so on.

#### 3.5.4 Operand DIFFE

```text
DIFFE= (gno1, gno2, gno3,...)
```

The new node group will be obtained by taking all the nodes of gno1 that do not belong to the other groups of the list. The order of the nodes remains that of gno1.

#### 3.5.5 Sub-group of an existing group: keywords GROUP_NO / POSITION / NUME_INIT / NUME_FIN

One can create a new node group by selecting certain nodes of an existing group.

**1st possibility:**

One creates a group **of a single node** by specifying, with the keyword POSITION, the node sought.

**Example:**

```text
CREA_GROUP_NO= _F ( GROUP_NO= G1    ,    POSITION= 'INIT' ,    NOM= G1I )
```

The group G1I contains the 1st node of the group G1.

**2nd possibility:**

One creates a group containing the nodes lying between the ranks nuini and nufin (inclusive) in an existing group.

**Example:**

```text
CREA_GROUP_NO=_F(GROUP_NO= G1,    NUME_INIT= 3    NUME_FIN = 7 , NOM = G1P)
```

The group G1P contains nodes 3, 4, 5, ..., 7 of G1.

**Warning:**

*These keywords use the notion of the order of the nodes in a node group. This order is often unknown to the user. It may depend on the pre-processor. It is the order of the nodes at the time of the definition of the GROUP_NO in the Aster mesh file.*

#### 3.5.6 Operand OPTION = 'ENV_SPHERE'

```text
OPTION = 'ENV_SPHERE'
```

This option makes it possible to define a GROUP_NO made up of the nodes situated on the envelope of a sphere, to within a given precision.

##### 3.5.6.1 Operand POINT

```text
POINT =    (x, y)    ,        en 2D
           (x, y, z),    en 3D
```

x y z are the coordinates of the centre of the sphere.

##### 3.5.6.2 Operand GROUP_NO_CENTRE

```text
GROUP_NO_CENTRE    = grno
```

This keyword makes it possible to define the node coinciding with the centre of the sphere.

##### 3.5.6.3 Operand RAYON

```text
RAYON =    r
```

r is the radius of the sphere.

##### 3.5.6.4 Operand PRECISION

```text
PRECISION =    eps
```

eps is the tolerance with which one defines the belonging of a node to the envelope of the sphere. This tolerance is to be taken in the following sense:

if $d$ is the distance from a node to the centre of the sphere, one says that this node belongs to the group if:

$∣d-r∣\le \text{eps}$

#### 3.5.7 Operand OPTION = 'ENV_CYLINDRE'

```text
OPTION =    'ENV_CYLINDRE'
```

This option makes it possible to define a GROUP_NO made up of nodes situated on the envelope of a cylinder, to within a given precision.

This option has meaning only in 3D.

##### 3.5.7.1 Operand POINT

```text
POINT =    (x, y, z)
```

x y z are the coordinates of a point belonging to the axis of the cylinder.

##### 3.5.7.2 Operand GROUP_NO_CENTRE

```text
GROUP_NO_CENTRE    = grno
```

This keyword makes it possible to define a node belonging to the axis of the cylinder.

##### 3.5.7.3 Operand RAYON

```text
RAYON =    r
```

r is the radius of the cylinder.

##### 3.5.7.4 Operand ANGL_NAUT

```text
ANGL_NAUT =    (ab)
```

The nautical angles a, b, defined in degrees, are the angles making it possible to pass from the global frame of definition of the coordinates of the nodes to a frame whose first vector designates the direction of the axis of the cylinder.

For the definition of the nautical angles, see the operator AFFE_CARA_ELEM [U4.42.01](doc:u4.42.01), operand ORIENTATION.

##### 3.5.7.5 Operand VECT_NORMALE

```text
VECT_NORMALE =    (x, y, z)
```

x y z are the coordinates of a vector orienting the axis of the cylinder.

##### 3.5.7.6 Operand PRECISION

```text
PRECISION =    eps
```

eps is the tolerance with which one defines the belonging of a node to the envelope of the cylinder.

This tolerance is to be taken in the following sense:

if $d$ denotes the distance from the current point to the axis of the cylinder, one says that the current point belongs to the envelope of the cylinder if:

$∣d-r∣\le \text{eps}$

#### 3.5.8 Operand OPTION = 'PLAN'

This option makes it possible to define a GROUP_NO made up of nodes situated on a straight line (in 2D) or in a plane (in 3D), to within a given precision.

##### 3.5.8.1 Operand POINT

```text
POINT =    (x, y)    ,        en 2D
           (x, y, z),    en 3D
```

x y z are the coordinates of a point belonging to the plane (to the straight line).

##### 3.5.8.2 Operand GROUP_NO_CENTRE

```text
GROUP_NO_CENTRE    = grno
```

This keyword makes it possible to define a node belonging to the plane (to the straight line).

##### 3.5.8.3 Operand ANGL_NAUT

```text
ANGL_NAUT =    a    ,    en 2D
               (a, b),    en 3D
```

The nautical angles a, b, defined in degrees, are the angles making it possible to pass from the global frame of definition of the coordinates of the nodes to a frame whose first vector is orthogonal to the 'mid' plane of the band.

For the definition of the nautical angles, see the operator AFFE_CARA_ELEM [U4.42.01](doc:u4.42.01), operand ORIENTATION.

##### 3.5.8.4 Operand VECT_NORMALE

```text
VECT_NORMALE =    (x, y)    ,        en 2D
                  (x, y, z),    en 3D
```

x y and z are the components of a vector perpendicular to the plane (to the straight line).

##### 3.5.8.5 Operand PRECISION

```text
PRECISION =    eps
```

eps is the tolerance with which one defines the belonging of a node to the plane (or to the straight line).

This tolerance is to be taken in the following sense:

if $d$ denotes the distance from the node to the plane (or to the straight line), one says that this node belongs to this plane (or to this straight line) if:

$∣d∣\le \text{eps}$

#### 3.5.9 Operand OPTION = 'SEGM_DROI_ORDO'

This option is used to order a set of nodes situated approximately on a straight-line segment AB.

```text
GROUP_NO    = gno2,
```

One defines the set of the nodes that one wishes to order.

```text
GROUP_NO_ORIG    = gnoA    ,

GROUP_NO_EXTR    = gnoB    ,
```

One defines the nodes $A$ and $B$ , origin and end of the segment $\mathrm{AB}$ .

```text
PRECISION =    prec,

CRITERE =        'RELATIF'    ,
                 'ABSOLU'    ,
```

These two arguments are safeguards; they are used to check that the nodes that one is seeking to order (lno2 or gno2) do indeed lie on the segment $\mathrm{AB}$ . If the deviation of a node from $\mathrm{AB}$ is greater than prec the code stops with a fatal error.

If the criterion chosen is 'RELATIF', the distance of a node from $\mathrm{AB}$ will be divided by the length of $\mathrm{AB}$ .

#### 3.5.10 Operand OPTION = 'NOEUD_ORDO'

This option is used to create an **ordered** group_no containing the nodes of a set of mesh cells formed of segments (SEG2, SEG3 or SEG4). The set of these mesh cells must form a continuous line. The line may be "open" (with 2 ends) or "closed" (it is then a simple loop).

```text
GROUP_MA=    gmaAB
```

Name of the group_ma whose nodes one wishes to order.

The mesh cells of gmaAB must form an open line.

```text
GROUP_NO_ORIG    = gnoA    ,

GROUP_NO_EXTR    = gnoB    ,
```

The keywords make it possible to define the nodes $A$ and $B$ , origin and end of the line $\mathrm{AB}$ .

The node $A$ will be numbered first, then one uses the topology of the mesh cells of gmaAB to number the nodes step by step.

If the node $A$ is not supplied by the user, the program will choose as "origin" node the first node of gmaAB that belongs to only a single segment mesh cell. The origin is therefore arbitrary: the program could just as well have fallen upon the other end.

One checks that the last numbered node is indeed $B$ (if the latter is given).

##### 3.5.10.1 Case of closed lines

If the line is a loop, one cannot determine its ends automatically. To define the origin of the curvilinear abscissae, the user may fill in the origin and end nodes. These 2 nodes must be identical. But one may also write: ORIGINE='SANS'. The "origin" node will then be taken at random on the closed line.

To orient a closed line, one cannot use the knowledge of the origin and end nodes. If so wished, the user may then fill in the keyword VECT_ORIE (2 or 3 coordinates according to the dimension of the space). One will choose, as the direction of travel of the loop, the mesh cell of gmaAB that touches the origin node and that minimises the angle with the vector supplied by VECT_ORIE.

#### 3.5.11 Operand OPTION = 'TUNNEL'

This option is used to create the group_no formed of the nodes situated inside a "tunnel" whose axis and radius one supplies. The nodes retained will be those whose distance to the axis is less than the radius.

The axis of the "tunnel" is defined by the linear mesh cells supplied via the keyword GROUP_MA_AXE.

The axis of the tunnel must have an "origin" defined by the keyword GROUP_NO_ORIG.

The keyword RAYON is used to define the "radius" of the tunnel.

One can limit the tunnel by giving its length with the keyword LONGUEUR. This length is measured from the origin of the tunnel.

The nodes that are candidates to form part of the tunnel are those carried by the mesh cells defined by the keywords: TOUT='OUI' and GROUP_MA.

#### 3.5.12 Operand OPTION = 'INCLUSION'

```text
OPTION    =    'INCLUSION' ,
GROUP_MA = lgma    ,            [l_group_ma]
CAS_FIGURE =     / '2D'
                / '3D'
                / '2.5D'
 DISTANCE_MAX = distma
GROUP_MA_INCL = lgma_inc    ,    [l_group_ma]
 MAILLAGE_INCL = ma_inc    ,        [maillage]
```

This option makes it possible to create the group of the nodes of the mesh cells of lgma that are geometrically inside the mesh cells of lgma_inc.

If MAILLAGE_INCL is not supplied, lgma_inc is a list of GROUP_MA of the mesh that one is enriching (ma). Otherwise they are GROUP_MA of ma_inc.

The keyword CAS_FIGURE is mandatory; it is used to determine which are the mesh cells of lgma_inc that must be used to determine the inclusion:

'2D': one is interested only in the surface mesh cells (TRIA and QUAD) of a 2D mesh (plane $\mathrm{XOY}$ ).

'3D': one is interested only in the volume mesh cells (TETRA, PENTA, …)

'2.5D': one is interested only in the surface mesh cells (TRIA and QUAD) of a 3D mesh (shell).

The keyword DISTANCE_MAX is optional. It is used to give a small tolerance in order to define whether a node is included in a mesh cell. Indeed, a node situated "just" on an interface between 2 mesh cells risks being considered as "outside" the 2 mesh cells and therefore as not forming part of the inclusion. This is why a default value of distma is taken by the code. One has chosen 1% of the length of the smallest edge of the mesh ma_inc.

In the case of a mesh of "shell" type (2.5D), if the surface is not plane, it is virtually impossible for a facet element to be geometrically included in other mesh cells: there is almost always a gap in the direction "normal" to the surface. One will therefore in general, in this case, have to supply a value of distma greater than the default value.

#### 3.5.13 Operand OPTION = 'INTERVALLE_VALE'

This option is used to create the group_no formed of the nodes whose value of a component (cmp) of a field at the nodes (cham_no) lies between two values (vmin and vmax).

The field and the component that will be used to select the nodes are given by the keywords CHAM_GD and NOM_CMP.

The values vmin and vmax are supplied via the keyword VALE.

Example:

DEFI_GROUP( reuse = MAIL, MAILLAGE = MAIL,

CREA_GROUP_NO = _F(NOM='GN700', OPTION='INTERVALLE_VALE',

CHAM_GD=TEMPER, NOM_CMP='TEMP', VALE=(700., 800.),),);

The GROUP_NO 'GN700' will be formed of all the nodes of the mesh MAIL whose temperature in the field TEMPER lies between 700. and 800.

#### 3.5.14 Operand OPTION = 'FISS_XFEM'

This option makes it possible to recover the group of the nodes of XFEM type specified by the keywords TYPE_GROUP.

```text
    FISSURE    =    (fiss1, fiss2, ...)

    TYPE_GROUP    =
        / 'XFEM' : le nœud sera retenu si c'est un nœud enrichi
        / 'HEAVISIDE' : le nœud sera retenu si c'est un nœud enrichi de type Heaviside
        / 'CRACKTIP' : le nœud sera retenu si c'est un nœud enrichi de type Cracktip
        / 'MIXTE' : le nœud sera retenu si c'est un nœud enrichi de type Mixte (Heaviside et Cracktip)
        :ref:`3.2 <RefNumPara__15136_1529317046>`
        / 'ZONE_MAJ' : le nœud sera retenu si il est contenu dans la zone de mise à jour des level sets. Dans le cas où le maillage de la fissure est passé par le mot-clé MAILLAGE(§), la zone de mise à jour coïncide:

*   en présence d'une grille auxiliaire associée à la fissure, avec le domaine de projection entre grille et maillage, indépendamment du domaine de calcul utilisé sur la grille.
```

**3.2**

In the case where a grid is passed by the keyword GRILLE(§), the update zone always coincides with the analysis domain used on the grid.

/ 'TORE': the node will be retained if it is contained in a torus built around the crack front, of radius given by the keyword RAYON_TORE.  CRIT_NOEUD =

#### 3.5.19 Operand ALARME = 'OUI' [DEFAULT] / 'NON'

if ALARME= 'NON', the code does not issue an alarm; for example when it is asked to create a GROUP_NO and this group is empty. The default value of this keyword is 'OUI'.

if INFO= 2, one prints in the 'MESSAGE' file the number of groups created and, for each group, the name of the group, the number of entities constituting it, then the list of the entities constituting the group or groups.

## 4 Examples

**Example 1 (topological and logical criteria):**

Let ma be a mesh already containing the mesh-cell groups:

```text
M1 M2 M3
```

and the node groups:

```text
N1 N2 N3
```

```text
ma = DEFI_GROUP (reuse = ma,    MAILLAGE= ma,
CREA_GROUP_MA= (    _F    (    NOM= NM1,    GROUP_MA=    (GMA7, GMA9,...)    ),
_F    (    NOM= NM2,    UNION=    (M1, NM1) ),
_F    (    NOM= NM3,    DIFFE=    (NM2, M2) ),),
CREA_GROUP_NO= _F    (    TOUT_GROUP_MA= 'OUI'),                    )
```

```text
ma = DEFI_GROUP (reuse = ma, MAILLAGE= ma,
CREA_GROUP_MA= _F    (    NOM= NM4,    GROUP_MA=    (GMA7, GMA11, GMA13))
CREA_GROUP_NO= (_F    (    NOM= NN1,    INTERSEC=    (NM1, N1)),
_F(    GROUP_MA= NM4)))
```

After these two calls to the command DEFI_GROUP, the mesh then contains:

- the mesh-cell groups:
- M1, M2, M3 (initial)
- NM1 = (mesh cells: MA7, MA9, ...)
- NM2 = M1 "union" NM1
- NM3 = NM2 "minus" M2
- NM4 = (MESH CELLS: MA7, MA11, MA13)
- the node groups:
- N1, N2, N3 (initial)
- M1, M2, M3, NM1, NM2, NM3: group_no containing the nodes of the group_ma of the **same names**. These group_no are created by the 1st command DEFI_GROUP.
- NN1 = NM1 "intersection" N1
- NM4 = (nodes of the group_ma NM4)

**Example 2 (geometric criteria):**

```text
ma = DEFI_GROUP    (reuse = ma, MAILLAGE= ma,
CREA_GROUP_MA=    (_F    ( NOM= facesup    ,    OPTION =    'FACE_NORMALE' ,
VECT_NORMALE = (0., 0., 1.)),
_F    ( NOM= S01    ,        OPTION =    'SPHERE' ,
POINT = (0., 0., 0.),    RAYON = 1.),),
CREA_GROUP_NO=(_F    ( NOM = BO_S01    ,    OPTION =    'ENV_SPHERE' ,
POINT=(0.,0.,0.),RAYON=1.,PRECISION=0.01),
_F    ( NOM = S01_1    ,    GROUP_MA =    S01),
_F    ( NOM = S01_2    ,    OPTION = 'ENV_SPHERE' ,
POINT=(0.,0.,0.),RAYON=0.5,PRECISION=0.5),),
)
```

After DEFI_GROUP the mesh ma will contain 2 new GROUP_MA and 3 new GROUP_NO:

- facesup contains the facets whose normal is oriented along $\mathrm{OZ}$ (towards $Z>0$ ),
- S01 contains **all** the mesh cells of which **one of the nodes** belongs to the sphere of radius 1. centred at $O$ (origin of the axes),
- B0_S01 is the group of the nodes that are found in the neighbourhood of the envelope of the previous sphere (S01),
- S01_1 is the group of all the nodes of the mesh cells of the mesh-cell group S01; warning: certain nodes of this group may be outside the sphere!
- S01_2 is the group of the nodes included in the sphere S01: $∣d(M,O)-0.5∣\le 0.5$
