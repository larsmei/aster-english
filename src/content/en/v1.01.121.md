# v1.01.121 ZZZZ121 - mesh adaptation with HOMARD

**Summary**

This series of validated computer-based case-tests of mesh adaptation with HOMARD. On a single mesh, either in 2D or 3D, a static mechanics or thermal calculation is launched, with the production of an error indicator. From there, a call to the HOMARD software will result in a modification of the mesh. On this new mesh, a new calculation is activated, corresponding to the same physical problem.

These test cases are not examples of the relevance of mesh adaptation and have no physical significance. They are only used as non-regression tests of functionality in the various possible configurations.

## 1 General

### 1.1 Background

The objective is only to test the non-regression of future evolutions of *Code_Aster* and HOMARD. Even if the test cases are realistic of the physical point to represent real studies, it is not necessary to attach importance to the value of the results.

In particular, there is no need to infer from this the performance of the mesh error/adaptation indicator torque.

These test cases validate the operation of the two MACR_INFO_MAIL and MACR_ADAP_MAIL macro-commands that drive the entire process.

Specifically, the functions tested are:

- mesh and MED format fields and readings. These are IMPR_RESU, LIRE_CHAMP and LIRE_MAILLAGE commands with keyword MED as format,
- writing the data file for HOMARD,
- start the HOMARD execution procedure. This is the EXEC_LOGICIEL command; it calls a script with a variable number of arguments,
- control of the entire process by the python: macr_adap_mail_ops.py.

The process is a priori insensitive to the Modelling envisaged. The important points that cause different processing in the data exchange between HOMARD and *Code_Aster* are the types d-elements, the adaptation control and the updating of fields on the new mesh. We thus envisage 4 modellings which are distributed as follows:

| **Modelling** | **Dimension** | **Update of fields** |
| --- | --- | --- |
| A | 2D, triangles | No |
| C | 2D, triangles | Yes |
| D | 2D, quadrangles | Yes |
| E | 3D, hexahedrons | Yes |
| F | 3D, pentahedrons | No |

The non-regression is tested on the value of the displacement, stress or temperature field in a free node. The test takes place for several resolutions, those with meshes from the first and at least another adaptation. Indeed, the data transmissions and the control of HOMARD are not the same for the first adaptation and the following ones. Therefore, we must test at least two passages.

**For mechanical problem:**

Boundary conditions and loadings are the same as model A.

The temperature is originally imposed: TEMP = 200.

A convective exchange with the outside is applied to the right edge.

```text

```

A volumetric source shall be applied:

MOITIE1 : SOUR = 18 000

MOITIE2 : SOUR = 22 000

The thermo-mechanical calculation is transient, with mesh adaptation every 2 time step. The first thermal calculation is initialized by a stationary calculation. ## 7 Summary of the results

This test case has the sole purpose of controlling the non-regression, so no comment is made on the value of the results. The reference is that of the calculation *Code_Aster* on the day of the first restitution and must be found afterwards.

When examining the command files, it should be noted that the loadings must be done on entities of the appropriate size.

- a node for a punctual load; e.g. a displacement imposed on a corner,
- a segment for a linear load; e.g. a 2D pressure distribution,
- a triangle for a load on the surface; for example, a force in 3D.

Furthermore, it should be noted that these loads must be expressed on groups of nodes or mesh cells and not on nodes or mesh cells. Indeed, after adaptation of the mesh, the groups are reconstituted. The loading control is therefore the same, regardless of the mesh.

By respecting these two rules on loadings, mesh adaptation is possible.
