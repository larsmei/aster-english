# u4.65.03 Operator NUME_DDL_GENE

## 1 Purpose

Number the degrees of freedom of the global structure from the numbering of the substructures.

Within an analysis using the dynamic substructuring methods (modal or harmonic analysis), the operator NUME_DDL_GENE defines the bijection between, on the one hand, the numbers of the generalised degrees of freedom of each substructure and the numbers of the connection degrees of freedom of each connection and, on the other hand, the numbers of the final degrees of freedom (that is, the row or column indices of the generalised matrices). Once the numbering has been carried out, the operator builds, according to the Morse storage mode, the addressing arrays necessary for the effective storage of the terms of the generalised matrices assembled with this numbering. A storage of full "skyline" type or diagonal "skyline" type is possible in order to compute a full added matrix or to solve a transient problem on a modal basis coming from a concept of type mode_meca.

Produces a data structure of type nume_ddl_gene.

## 2 Syntax

```text
nume_ddl_gene = NUME_DDL_GENE(
    ◆ / MODELE_GENE = modele_gene,
      / BASE = mode_gene / mode_meca,
    # Si: exists("MODELE_GENE")
        ◇ STOCKAGE = / "LIGN_CIEL" (par défaut),
                     / "PLEIN",
        ◇ METHODE = / "INITIAL",
                    / "CLASSIQUE" (par défaut),
                    / "ELIMINE",
    # Si: exists("BASE")
        ◇ STOCKAGE = / "DIAG",
                     / "PLEIN" (par défaut),
        ◇ NB_VECT = int,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Operand MODELE_GENE

```text
◊    MODELE_GENE = mo_gene
```

Name of the concept of type modele_gene produced by the operator DEFI_MODELE_GENE [U4.65.02](doc:u4.65.02) from which the numbering is carried out.

### 3.2 Operand METHODE

```text
◊    METHODE =
```

| /'CLASSIQUE' | Builds a generalised numbering making it possible to take the connection equations into account by the method of double Lagrange multipliers [R4.06.02](doc:r4.06.02). |
| --- | --- |

| /'ELIMINE' | Builds a generalised numbering making it possible to take the connection equations into account by the constraint-elimination method [R4.06.02](doc:r4.06.02). |
| --- | --- |

| /'INITIAL' | Initialises the numbering for the generalised operators in order to allow the construction of a numbering whose size can be driven from Python. The matrices (built with ASSE_MATR_GENE) and the vectors (built with ASSE_VECT_GENE) are of a suitable size, but initialised to zero. |
| --- | --- |

### 3.3 Storage of the matrices

```text
◊    STOCKAGE =
```

Choice of a storage mode for the matrices that one is going to assemble with this numbering. 3 options are available:

| /'LIGN_CIEL' | "skyline" storage by blocks; the assembled matrix will be stored block of columns by block of columns, starting from the 1st term liable to be non-zero for each column. |
| --- | --- |

In the assembled matrix, a term $A(i,j)$ is liable to be non-zero if and only if the degree of freedom $i$ and the degree of freedom $j$ (respectively the $i$-th and $j$-th modes of the global structure) come from the same substructure or are linked by at least one LAGRANGE degree of freedom of two substructures connected by a connection.

| /'PLEIN' | 'skyline' storage of the assembled generalised matrices by blocks, but with a full profile (one stores all the elements of the upper triangular part of the matrix). This type of storage must be used if one wants to compute the generalised added matrices (mass, stiffness, damping), which are full, as well as all the generalised matrices to which they are added. For the stiffness and damping matrices, the assembly is always done from a nume_ddl_gene coming from a mode_meca. |
| --- | --- |

| /'DIAG' | 'skyline' storage of the diagonal terms of the matrices projected onto a modal basis. This type of storage is to be used when the basis onto which one reduces the problem is orthogonal with respect to the matrices used (the mass, stiffness and damping matrices). This storage makes it possible to improve the performance of the computation operators (DYNA_VIBRA, for example). Warning: this can lead to incorrect results if the orthogonality is not satisfied, for example when one uses a modal basis composed of static modes. Indeed, the static modes are not orthogonal to one another. |
| --- | --- |

### 3.4 Operand BASE

This operand serves to identify the modal basis onto which one projects the matrices.

### 3.5 Operand NB_VECT

Under this keyword, one expects the number of projection-basis vectors, possibly smaller than the number of modes defined in the basis specified by the keyword BASE. By default, this number is equal to the number of modes of the basis.

## 4 Execution phase

No bandwidth optimisation is carried out during the numbering. The order of appearance of the substructures in the numbering corresponds to the order of their definition in the generalised model (operator DEFI_MODELE_GENE). The user can therefore limit the bandwidth by defining the substructures of the generalised model in a judicious order.

The degrees of freedom coming from the double dualisation are then assembled on either side of the generalised degrees of freedom of the second substructure assembled (among the two substructures involved in the connection).
