# u4.14.02 Operator COPIER

## 1 Purpose

Duplicate a user concept under another name.

This command is rarely useful and it has the disadvantage of doubling the "disk" space of the concept in the user's global database. The concept produced can be destroyed (command DETRUIRE) in order to recover the disk space.

Only certain types of concept are accepted.

## 2 Syntax

```text
/ cabl_precont
/ evol_elas
/ evol_noli
/ evol_ther
/ fonction
/ listis
/ listr8
/ maillage
/ modele
/ nappe
/ table = COPIER(
    ◇ reuse = <objet de CONCEPT>,
    ◆ CONCEPT = cabl_precont / evol_elas / evol_noli / evol_ther / fonction / listis / listr8 / maillage / modele / nappe / table,
    ◇ INFO = / 1 (par défaut),
             / 2,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Keyword CONCEPT

```text
♦        CONCEPT = co1
```

Name of the concept that one wishes to duplicate.

The result of the command is of the same type as the duplicated concept.

### 3.3 Notes

The need to duplicate a concept is rare because it is in principle useless to have the same object under two different names.

The concept produced (co2) corresponds to a "deep" copy of the initial concept (co1), that is to say that ALL the JEVEUX objects of co1 have been duplicated.

The "volume" of co2 in the global database is identical to that of co1.

Use of the command therefore always leads to a loss of disk space.

### 3.4 Operand INFO

```text
◊    INFO = info
```

This keyword has no influence.

## 4 Example

```text
Lr1    =    DEFI_LIST_REEL (    …    )

```
