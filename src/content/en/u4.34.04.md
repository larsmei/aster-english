# u4.34.04 Operator DEFI_LIST_FREQ

## 1 Purpose

To create a list of reals, possibly refining around frequency values supplied by the user.

It produces a data structure of type listr8.

## 2 Syntax

```text
DEFI_LIST_FREQ(
    ◇ / VALE = float,
      / DEBUT = float,
    ◇ / INTERVALLE = _F(
           ◆ JUSQU_A = float,
           ◆ / NOMBRE = int,
             / PAS = float,
        ),
    ◇ RAFFINEMENT = _F(
         ◆ LIST_RAFFINE = float,
         ◇ NB_POINTS = int (défaut: 5),
         ◇ PAS_MINI = float (défaut: 0.001),
         ◇ CRITERE = / "RELATIF" (par défaut),
                     / "ABSOLU",
                     / "LARGEUR_3DB",
         # Si: (equal_to("CRITERE", 'RELATIF') or equal_to("CRITERE", 'ABSOLU'))
             ◇ DISPERSION = float (défaut: 0.01),
         # Si: (equal_to("CRITERE", 'LARGEUR_3DB'))
             ◆ / AMOR_REDUIT = float,
               / LIST_AMOR = listr8,
      ),
    ◇ EQUI_MODES = _F(
         ◇ TYPE_SAISIE = / "LISTE" (par défaut),
                         / "MATR_ASSE",
         ◆ FREQ_MIN = float,
         ◆ FREQ_MAX = float,
         # Si: (equal_to("TYPE_SAISIE", 'LISTE'))
             ◇ LIST_FREQ = listr8,
         # Si: (equal_to("TYPE_SAISIE", 'MATR_ASSE'))
             ◇ MATR_RIGI = matr_asse_depl_r,
             ◇ MATR_MASS = matr_asse_depl_r,
         ◇ NB_MODES = int (défaut: 40),
         ◇ NB_POINTS_INIT = int (défaut: 10),
         ◇ NB_POINTS_SUPP = int (défaut: 1),
         ◇ ITER_MAXI = int (défaut: 20),
         ◇ TOLERANCE = float (défaut: 0.01),
      ),
    ◇ INFO = / 1 (par défaut),
             / 2,
    ◇ TITRE = text,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Operands VALE, DEBUT, INTERVALLE, JUSQU_A, TITRE, INFO

These keywords are used directly by [DEFI_LIST_REEL](doc:u4.34.01)
to define the initial list of frequencies.

**Note**

All the values requested in the base list are automatically in the final list at the output of DEFI_LIST_FREQ.

### 3.2 Keyword RAFFINEMENT

#### 3.2.1 Operand LIST_RAFFINE

List of the frequencies around which one wishes to refine.

This list can be built from a Python list.

This keyword is particularly useful in the case of a harmonic analysis of a structure (operator [DYNA_VIBRA](doc:u4.53.03)), because it will make it possible to compute the harmonic response around the eigenfrequencies of the structure and thus to recover the local extrema. It is possible to recover the eigenfrequencies directly in a data structure of type mode_XXX coming from a modal analysis carried out for example with the command [CALC_MODES](doc:u4.52.02). To do this, it is enough to use the method LIST_VARI_ACCES().

**Example:**

```python
modes = CALC_MODES(
    MATR_RIGI=matassr,
    MATR_MASS=matassm,
    OPTION="AJUSTE",
    CALC_FREQ=_F(FREQ=(5.0, 10.0, 15.0, 20.0, 24.0, 27.0)),
)

list_freq = modes.LIST_VARI_ACCES()['FREQ']
```

list_freq is thus a Python list containing the list of the eigenfrequencies present in the result modes.

#### 3.2.2 Operand PAS_MINI

If the gap between two values is smaller than PAS_MINI then one of them is removed.
With this rule, the removed value may be a value present in the initial list (VALE) or in the list of refinement points (LIST_RAFFINE).

#### 3.2.3 Operand DISPERSION

DISPERSION is the width of the interval surrounding each frequency of LIST_RAFFINE where one wants to refine.

#### 3.2.4 Operand CRITERE

The width of the interval $df$ surrounding each frequency $freq_{i}$ of LIST_RAFFINE where one wants to refine is determined from the value of DISPERSION and is equal to:

- If CRITERE='RELATIF':
  $df = disp . freq_{i}$
- If CRITERE='ABSOLU':
  $df = disp$

If CRITERE='LARGEUR_3DB', one supplies the list of damping values with the
keywords AMOR_REDUIT or LIST_AMOR.
This is the list of reduced dampings ($\eta_{1}$, $\eta_{2}$, ..., $\eta_{n}$) corresponding to each eigenmode of the system in the form of a list of reals.

Name of the concept of type listr8 containing the list of reduced dampings ($\eta_{1}$, $\eta_{2}$, ..., $\eta_{n}$).

**Note**

If the number of reduced dampings given is smaller than the number of basis vectors used in the modal basis, the dampings of the additional vectors are taken equal to the last damping of the list.

If the damping $\eta_{i}$ is non-zero, the frequency $freq_{i}$ used
to compute the length of the interval $df$ is the frequency $freq_{i}$
of LIST_RAFFINE shifted to the resonance frequency of a forced system,
that is $freq_{i} = freq_{i} \sqrt{(1-2{\eta}_{i}^{2})}$.

The length of the interval $df$ surrounding each frequency $freq_{i}$ where one wants to refine is equal to:

- If $\eta_{i} \ne 0$ :
  $df = 2{\eta}_{i} freq_{i}$
- If $\eta_{i} \ne 0$ :
  $df = 0.01 freq_{i}$

#### 3.2.5 Operand NB_POINTS

NB_POINTS is the number of points that one wants to add around the frequencies of the list LIST_RAFFINE.

The added points are uniformly distributed in the interval $df$.
Therefore if NB_POINTS is an odd number, the frequencies of LIST_RAFFINE will be in
the final list.

If CRITERE='LARGEUR_3DB' and NB_POINTS is an even number, one keeps the frequency $freq_{i}$
of LIST_RAFFINE and one adds the resonance frequency of a forced system such that
$freq_{i} = freq_{i} \sqrt{(1-2{\eta}_{i}^{2})}$ .

### 3.3 Keyword EQUI_MODES

This keyword concerns the parameterisation of an algorithm for balancing frequency bands,
upstream of a multi-band modal analysis via the operator [CALC_MODES](doc:u4.52.02).

This algorithm aims to determine the ends of frequency bands, so that the latter
contain a comparable, and limited, number of eigenfrequencies (*i.e.*, of the order of $\mathcal{O}(10^{1})$).
This makes it possible in particular to improve the robustness and the performance of a multi-band modal analysis (see [R5.01.04](doc:r5.01.04)).
To do this, the aforementioned algorithm relies on an iterative procedure, aiming to carry out several calls
to an eigenvalue-counting procedure, so as to “discover” sufficiently the distribution of the
eigenvalues of the problem and thus propose a cutting into balanced frequency bands.

When the keyword EQUI_MODES is used, the operator DEFI_LIST_FREQ returns a list of reals comprising
the ends of the optimised frequency bands. This list can then be supplied to the operator
CALC_MODES, via the operand FREQ of the keyword CALC_FREQ with `OPTION = 'BANDE'`. The aforementioned algorithm
takes into account two types of input data:

- a list of reals comprising eigenfrequencies computed beforehand,
- stiffness and mass matrices. In such a case, the aforementioned algorithm is based on the
eigenvalue-counting procedure of the operator [INFO_MODE](doc:u4.52.01).

#### 3.3.1 Operands FREQ_MIN and FREQ_MAX

The operands FREQ_MIN and FREQ_MAX make it possible to define the ends of the interval in which the procedure
of balancing frequency bands is carried out.

#### 3.3.2 Operand TYPE_SAISIE

The mode of use of the frequency-band balancing algorithm is defined via TYPE_SAISIE.
The case `TYPE_SAISIE = 'LISTE'` corresponds to the specification of a list of
precomputed eigenfrequencies. The specification of assembled stiffness and mass matrices can be done by supplying
`TYPE_SAISIE = 'MATR_ASSE'`.

#### 3.3.3 Operand LIST_FREQ

The operand LIST_FREQ makes it possible to specify a list of reals corresponding to
precomputed eigenfrequencies, in the case `TYPE_SAISIE = 'LISTE'`.

#### 3.3.4 Operands MATR_RIGI and MATR_MASS

In the case of the specification of assembled matrices (`TYPE_SAISIE = 'MATR_ASSE'`),
the stiffness and mass matrices are supplied via the operands MATR_RIGI and MATR_MASS.
It is important to note that the frequency-band balancing algorithm is implemented
only in the case of standard real symmetric generalised eigenvalue problems (see [R5.01.01](doc:r5.01.01)).
Consequently, only **real symmetric** assembled matrices can be used.

#### 3.3.5 Parameters of the balancing algorithm

The keyword EQUI_MODES also makes it possible to specify (optional) parameters relating to the algorithm
for balancing frequency bands, namely:

- NB_MODES, corresponding to the desired number of eigenfrequencies per band.
It is set by default to 40, based on the recommendations stated in
the reference document [R5.01.04](doc:r5.01.04).
- ITER_MAXI, making it possible to set the maximum number of iterations of the algorithm,
- NB_POINTS_INIT, making it possible to set the initial number of eigenfrequency search intervals
used by the algorithm,
- NB_POINTS_SUPP, making it possible to define the number of additional search intervals in the course
of an iteration of the algorithm.
- TOLERANCE, making it possible to define the stopping criterion of the algorithm. In the case of the balancing of $B$ frequency bands,

  $N_i$ denoting the number of eigenfrequencies in band $i$, $N_b$ the desired number of eigenfrequencies
per band (NB_MODES), and $N$ the total number of eigenfrequencies lying in the interval

#### 3.3.6 Description of the result and use in a modal analysis

In the case where the frequency-band balancing algorithm is used, the data
structure produced by the operator DEFI_LIST_FREQ is a table (`table_sdaster`), whose columns
gather information relating to the results of the algorithm, namely:

- NUME_BANDE, corresponding to the numbers of each frequency band obtained,
- FREQ_MIN and FREQ_MAX, corresponding respectively to the minimum and maximum ends of each band,
- NB_MODES, corresponding to the number of eigenfrequencies contained in each band,
- NB_CIBLE, corresponding to the desired number of eigenfrequencies per band (*i.e.* NB_MODES in EQUI_MODES),
- ERR_REL, corresponding to the relative error $\left|\varepsilon_i\right|$ associated with each band,
- NB_ITER, corresponding to the number of iterations carried out,
- ITER_MAXI, corresponding to the maximum number of iterations permitted (*i.e.* ITER_MAXI in EQUI_MODES).

This table can then be used to carry out a multi-band modal analysis with the operator
[CALC_MODES](doc:u4.52.02), via the extraction of the frequency bands in `Python`. An example of use is given below:

```python
table = DEFI_LIST_FREQ(
                       EQUI_MODES=_F(TYPE_SAISIE="MATR_ASSE",
                                     FREQ_MIN=0.0,
                                     FREQ_MAX=500.0,
                                     MATR_RIGI=matassr,
                                     MATR_MASS=matassm,
                                    ),
                      )

list_freq = [table.EXTR_TABLE().values()["FREQ_MIN"][0]] + table.EXTR_TABLE().values()["FREQ_MAX"]

modes = CALC_MODES(
                   MATR_RIGI=matassr,
                   MATR_MASS=matassm,
                   OPTION="BANDE",
                   CALC_FREQ=_F(FREQ=list_freq),
                  )
```

## 4 Examples

Let us imagine that one wants to create the base list:
$(1., 3., 5., 10., 15.)$

And that one wants to refine around the frequency $3.5$ with the criterion 'ABSOLU'.

One writes:

```python
lr = DEFI_LIST_FREQ(
    DEBUT=1.0,
    INTERVALLE=(_F(JUSQU_A=5.0, NOMBRE=2), _F(JUSQU_A=15.0, PAS=5)),
    RAFFINEMENT=(
        _F(LIST_RAFFINE=3.5, PAS_MINI=0.001, NB_POINTS=5, CRITERE="ABSOLU", DISPERSION=0.02),
    ),
)
```

One then obtains a list containing the values:
$(1.0, 3.0, 3.49, 3.495, 3.5, 3.505, 3.51, 5.0, 10.0, 15.0)$

Using the criterion 'RELATIF' for the refinement, one can write:

```python
lr = DEFI_LIST_FREQ(
    VALE=(1.0, 3.0, 5.0, 10.0, 15.0),
    RAFFINEMENT=_F(
        LIST_RAFFINE=(3.5,), PAS_MINI=0.001, NB_POINTS=6, CRITERE="RELATIF", DISPERSION=0.03
    ),
)
```

One then obtains a listr8 list containing the values:
$(1., 3., 3.4475, 3.4685, 3.4895, 3.5105, 3.5315, 3.5525, 5., 10., 15.)$
