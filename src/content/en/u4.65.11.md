# u4.65.11 Operator CREA_ELEM_SSD

## 1 Purpose

The purpose of this operator is to make the user's task easier for the creation of a dynamic macro-element. CREA_ELEM_SSD computes the projection-basis vectors, defines the interfaces and creates the dynamic macro-element.

It produces a concept of type macr_elem_dyna.

The dynamic macro-element created is ready to be assembled with other dynamic macro-elements in order to obtain a generalised model. The creation of this generalised model can be done with the operator ASSE_ELEM_SSD.

This operator is not intended to be able to create all the possible macro-elements. It makes it possible to create the standard real macro-elements which correspond to the majority of cases. The basis vectors of these macro-elements are of type CLASSIQUE, or else Ritz basis vectors with interface modes.

For particular projection bases, the user is invited to create them manually with the help of the standard operators.

## 3 Course of the analysis

This operator makes it possible to create easily a real dynamic macro-element (without damping) by supplying only the mechanical characteristics of the model and the interfaces associated with the substructure.

It chains the following operations:

- creation of the stiffness and mass matrices of the substructure,
- computation of the normal modes of the substructure,
- definition of the interfaces associated with the substructure,
- computation of the static modes or of the interface modes,
- definition of the projection basis,
- computation of the dynamic macro-element.

For its implementation, the user may draw inspiration from the modellings «e» and «f» of the test case SDLD106. These modellings correspond respectively to the modellings «b» and «d» of the same test case.

### 3.1 Operand MODELE

```text
♦ MODELE = modele
```

modele: the model which contains the elements constituting the substructure.

### 3.2 Operand NUME_DDL

```text
◊ NUME_DDL = nu
```

nu: numbering of the degrees of freedom assigned to the substructure.

**Note:**

*This numbering is necessary if one wants to compute the response of the assembled structure due, for example, to a loading applied to the substructure. One needs the numbering in order to be able to assemble the elementary vector according to the numbering of the degrees of freedom of the substructure.*

*One then writes:* NUME_DDL = CO('nume') *, where* nume *designates the numbering that one wishes to give to the degrees of freedom of the substructure.*

### 3.3 Operand CHAM_MATER

```text
♦ CHAM_MATER = chmat
```

chmat: name of the material field in which the characteristics of the materials are defined.

### 3.4 Operand CARA_ELEM

```text
◊ CARA_ELEM = carele
```

carele: elementary characteristics of the beam or shell elements, or of the discrete elements, if the substructure contains any.

### 3.5 Operand CHARGE

```text
◊ CHARGE = chg
```

chg: loading applied to the substructure.

### 3.6 Keyword INTERFACE

The factor keyword INTERFACE makes it possible to define the interface or the interfaces associated with the substructure. The keywords associated with this factor keyword are identical to the factor keyword INTERFACE of the operator DEFI_INTERF_DYNA [U4.64.01](doc:u4.64.01). One also enters here the value of the frequency used for the computation of the harmonic constraint modes. The default value for this frequency is equal to 1.

One applies the overloading rule. If the value of the frequency differs between the various interfaces, then one informs the user by means of an alarm which specifies the value of the frequency actually taken into account.

### 3.7 Keyword BASE_MODALE

The factor keyword BASE_MODALE makes it possible to specify the type of basis onto which the substructure is projected.

#### 3.7.1 Operand TYPE

```text
Cette opérande définit le type de la base de projection.

♦ TYPE=    / 'CLASSIQUE'
/ 'RITZ'
```

A basis of type CLASSIQUE is constituted of normal modes and of constraint modes or of attachment modes, depending on the type of the interface. The computation of the normal modes is done according to the indications supplied in the factor keyword CALC_FREQ.

#### 3.7.2 Operand TYPE_MODE

```text
◊ TYPE_MODE=    / 'INTERFACE'            [DEFAUT]
/ 'STATIQUE'
```

The option TYPE = 'RITZ' makes it possible to specify the type of modes to add to the normal modes. The user may choose modes of type STATIQUE (static readings at the degrees of freedom of the interface nodes) or of type INTERFACE (interface modes). For the particular case in which one does not wish to use normal modes, one chooses OPTION = 'SANS' in the keyword CALC_FREQ.

#### 3.7.3 Operand NMAX_MODE_INTF

◊ NMAX_MODE_INTF=    / 10            [DEFAUT]

> / nmintf

NMAX_MODE_INTF corresponds to the number of interface modes to take into account. One considers here the first nmintf interface modes (nmintf > 0).

### 3.8 Keyword CALC_FREQ

This factor keyword makes it possible to choose the frequency content of the normal modes. The operands associated with this factor keyword are identical to those defined for CALC_MODES [U4.52.02](doc:u4.52.02). A particularity for the option BANDE: the operand FREQ makes it possible to enter a list of frequencies, and one carries out the modal computations on the various intervals of the list.

One chooses OPTION = 'SANS' if one does not wish to compute normal modes.

The keyword STOP_ERREUR makes it possible to indicate to the operator whether it must stop ('OUI') or continue ('NON') in the case where one of the criteria for checking the quality of the computed modes is not satisfied. This keyword is equivalent to the keyword STOP_ERREUR of the factor keyword VERI_MODE of CALC_MODES.

**Note:**

*In order not to overload the command, this factor keyword does not make it possible to enter the parameters* COEF_DIM_ESPACE *,* NMAX_ITER_SHIFT *,* PREC_SHIFT *,* SEUIL_FREQ *and* STOP FREQ_VIDE *. On the other hand, the user may enter the dimension of the subspace (* DIM_SOUS_ESPACE *) if need be. The values chosen for the computation of the normal modes are the default values of these parameters in* CALC_MODES *.*

### 3.9 Keyword SOLVEUR

Optional keyword, see [U4.50.01](doc:u4.50.01).

### 3.10 Operand INFO

This operand makes it possible to print more or less information on the macro-element created in the file 'MESSAGE'.

## 4 Example of use

This example is taken from the test case SDLS106e.

MACEL1 = CREA_ELEM_SSD(

MODELE = MODELE1,

CHARGE = CHARGE_1,

CHAM_MATER = CHAMAT1,

CARA_ELEM = PARAM1,

INTERFACE = _F( NOM = 'GAUCHE',

TYPE = 'CRAIGB',

GROUP_NO = 'GAUCHE',

MASQUE = ('DX','DY'),),

BASE_MODALE = _F( TYPE = 'RITZ',

NMAX_MODE_INTF = 20,),

CALC_FREQ = _F(NMAX_FREQ = 6,),

)
