# u7.05.32 Procedure IMPR_RESU in ‘GMSH’ format

## 1 Purpose

Write a field of a quantity (grandeur) or a result concept in the 'GMSH' format.

At present this procedure makes it possible to write, as one chooses:

- fields at the nodes (of displacements, of temperatures, of eigenmodes, of static modes, …),
- fields by element at the nodes (of stresses, of generalised forces, of internal variables…).

For concepts of type resultat, one can print only part of the information, by selecting the fields and the order numbers that one wishes to exploit.

It is possible to select the topological entities (mesh cells or mesh-cell groups) on which one wants to print the results.

## 3 Keyword RESU

This factor keyword makes it possible to specify the results to be printed and the format according to which one wants to print them.

### 3.1 Operand MAILLAGE

This operand makes it possible to choose the mesh that one wishes to print. The simultaneous printout of the mesh and of fields is impossible.

### 3.2 Selection of the data to be printed

The values of the computed fields are stored in data structures called fields of quantities (grandeurs). These fields of quantities (grandeurs) may be directly accessible (concept CHAM_GD) or be found in a data structure grouping several fields of quantities (grandeurs) (concept resultat).

- A field of a quantity (grandeur) is a data structure which makes it possible to store fields defined at the nodes (cham_no_* ) or fields defined by element (cham_elem_* ). For the fields by element, one distinguishes the fields defined at the nodes of the elements and the fields defined at the Gauss points of the elements.
- A result concept is composed of one or more fields of quantities (grandeurs). For example, at each analysis step one stores in the resultat data structure the field of the quantity (grandeur) displacement. This structure is therefore a matrix structure of order 2, one index of which is, for example, the list of the analysis time instants and the other the set of the computed fields (displacements, stresses, strains, ...).

One accesses in this case a field of a quantity (grandeur) by specifying a value of an access variable (order number, time instant, frequency, mode number, ...) and a field name ('DEPL', 'SIGM_ELNO',...). There exist several types of result concept: evol_elas, evol_noli, mode_meca,.... To each one corresponds a list of fields and a list of licit access variables.

Given the resultat data structure, one easily understands that the printout possibilities available are those of the fields of quantities (grandeurs), supplemented by specific possibilities.

**Warning**

*One cannot print in the same file the MAILLAGE and the RESULTAT/CHAM_GD, GMSH does not know how to read such a file. The command therefore stops if the two keywords are present.*

#### 3.2.1 Operand CHAM_GD

For the CHAM_NO, the components of the field at the nodes are split into a vector field grouping the components DX, DY, DZ and into as many scalar fields as there are other components.

**Example**: In the case of a field at the nodes of quantity (grandeur) DEPL and whose modelling is of beam type, one writes:

- 1 vector field (grouping the set of the translation components),
- 3 scalar fields (one field per degree of rotation).

For the CHAM_ELEM, one prints only the fields by element at the nodes (_ELNO_). A field by element at the nodes is split into as many scalar fields as there are components.

**Note**

*When one writes a result in the GMSH format, the title of the fields, which appears in GMSH, consists of the name of the Aster result + the name of the field + the component.*

*Example:* *RESU_DEPL_DX: the component* *'DX'* *of the field* *'DEPL' of the result* *'RESU'*

*If one writes a derived field, one inserts the name of the sensitivity parameter with respect to which one differentiates, between the name of the result and the name of the field.*

*Example:* *RESU_PS1_DEPL_DX: the derivative with respect to* *'PS1'* *of the component* *'DX' of the field* *'DEPL' of the result* *'RESU'.*

#### 3.2.2 Operand RESULTAT

The operand RESULTAT makes it possible to print the fields contained in a result concept. One can for example choose to print only certain fields (Cf. the keyword: NOM_CHAM).

The result concept is written field of quantity (grandeur) by field of quantity (grandeur) as described in [§4.1].

## 5 Selection of the geometrical zones and of the components

In order to reduce the volume of the printouts, it is sometimes necessary to print only part of the result. To do this one can print a field at the nodes or a field by element only on certain elements.

This selection, which one will denote "selection on topological entities", is possible in the 'GMSH' format.

### 5.1 Operand MAILLE

This keyword makes it possible to indicate the list of the mesh cells on which one wishes to print a cham_elem. For a cham_no, it makes it possible to indicate the list of the nodes, vertices of the mesh cells, at which one wishes to print the cham_no.

### 5.2 Operand GROUP_MA

This operand makes it possible to indicate the list of the mesh-cell groups on which one wishes to print a cham_elem. For a cham_no, it makes it possible to indicate the list of the nodes, vertices of the mesh cells, at which one wishes to print the cham_no.

### 5.3 Operand TYPE_CHAM

GMSH because it is capable of visualising vectors and tensors; it is thus possible to visualise things other than each of the components independently. This operand makes it possible to choose the type of field to be printed ('VECT_2D', 'VECT_3D', 'SCALAIRE', 'TENS_2D' or 'TENS_3D'). The default value is 'SCALAIRE'.

### 5.4 Operand NOM_CMP

This operand makes it possible to choose the list of the components that one wishes to print according to the type of field chosen.

If one has chosen to print scalar fields it is not necessary to supply NOM_CMP; in this case, each of the components will be printed independently of one another.

### 5.5 Operand PARTIE

One cannot print complex fields in the GMSH format; one must therefore, for such fields, select the REEL (real) part or the IMAG (imaginary) part to be printed.

## 6 Operand VERSION

The mesh cells accepted by GMSH (in post-processing) are, since version 1.35, the mesh cells of type POI1, SEG2, TRIA3, QUAD4, TETRA4, HEXA8, PENTA6, PYRAM5, which corresponds to:

VERSION = ‘1.2’ which is the default value

If one needs to visualise the fields with an old version of GMSH or if one wishes to cut all the mesh cells into POI1, SEG2, TRIA3 and TETRA4, one uses VERSION = ‘1.0’.

In order to be able to visualise the views with GMSH, the mesh is modified so as to have only GMSH mesh cells. At present, the PYRAM13 mesh cells are not processed.

- the SEG3 is decomposed into 2 SEG2,
- the SEG4 is decomposed into 3 SEG2,
- the TRIA6 is decomposed into 4 TRIA3,
- the TRIA7 is decomposed into 4 TRIA3,
- the QUAD4 is decomposed into 2 TRIA3 (cut only if VERSION=’1.0’),
- the QUAD8 is decomposed into 6 TRIA3,
- the QUAD9 is decomposed into 6 TRIA3,
- the TETRA10 is decomposed into 8 TETRA4,
- the PENTA6 is decomposed into 3 TETRA4 (cut only if VERSION=’1.0’),
- the PENTA15 is decomposed into 16 TETRA4,
- the PYRAM5 is decomposed into 2 TETRA4 (cut only if VERSION=’1.0’),
- the HEXA8 is decomposed into 6 TETRA4 (cut only if VERSION=’1.0’),
- the HEXA20 is decomposed into 24 TETRA4,
- the HEXA27 is decomposed into 48 TETRA4.

**Note 1**

*The* *TRIA7* *(respectively* *QUAD9) is cut like the* *TRIA6 (resp.* *QUAD8) because the central node does not carry a displacement degree of freedom in modelling* *COQUES_3D.*

**Note 2**

*With the recent versions of* *GMSH (* $>1.60$ *), one could avoid cutting the elements. The choice is not available in Code_Aster because it is possible to read the MED format in GMSH since version 2.0.*

## 7 Operand UNITE

UNITE makes it possible to choose on which file the results will be written. By default, UNITE = 37 in the 'GMSH' format.

One can thus print results on different files at each IMPR_RESU command.

The natural suffix of the GMSH post-processing files is .pos and the usual logical unit (by default in astk) is 37.

## 8 Operand PROC0

The operand PROC0, whose default value is 'OUI', makes it possible to restrict the printout to the processor of rank 0. If one assigns it the value 'NON', the printouts will be carried out on all the processors.
