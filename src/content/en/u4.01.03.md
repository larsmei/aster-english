# 1 **u4.01.03** New features and changes of version 7

**Summary:**

The purpose of this document is to give an overall view of the syntax changes and of the new possibilities of the *Code_Aster* commands which have occurred between each version since version 7.0.

Index A of this document thus reports the changes introduced since **version 7.3** of April 2004 and valid for **version 7.4** of December 2004.

For further details, consult the command documentation and the histor file of the corresponding sub-version (e.g.: [7.3.12], *Development* section of the site www.code-aster.org).

The commands affected are listed in alphabetical order.

## 1 New features between 7.3 and 7.4

### 1.1 Changes to the environment

#### 1.1.1 Med

*Code_Aster* now relies on the MED 2.2 library. To read files in med 2.1.5 format, they must be converted with the med_import tool (there is no tool in the opposite direction).

#### 1.1.2 Homard

Following the change of version of med, homard has also evolved in order to support the same library level. homard 7.1 also brings other new features (cf. [U7.03.xx]).

### 1.2 New commands

#### 1.2.1 CREA_TABLE

This command makes it possible to create a table from a function or from several lists of integers, of reals or of character strings. One can create a full table or a table with gaps by indicating the rows one wishes to fill in.

#### 1.2.2 DEFI_COMPOR

This command makes it possible to define a monocrystalline or polycrystalline behaviour.

#### 1.2.3 DEFI_PART_FETI

This command makes it possible to create a partitioning into subdomains with a view to a solution by the Feti method.

#### 1.2.4 IMPR_FONCTION

This new command replaces IMPR_COURBE, and it handles only functions (hence the change of name); tables are handled by IMPR_TABLE (cf. [7.3.13]).

#### 1.2.5 MACR_ECLA_PG

This macro-command replaces the ECLA_PG options of the two commands CREA_MAILLAGE and CREA_RESU. Consistency between the two commands is thus ensured.

#### 1.2.6 MODI_MODELE_XFEM

This command makes it possible to create finite elements with enriched degrees of freedom required for the XFEM method.

### 1.3 Withdrawn commands

#### 1.3.1 DEFI_VALEUR

Since the content of the Python objects is saved (in the file pick.1) “alongside” the Aster database (file glob.1), it is no longer necessary to have a specific command to define a parameter.

For example (see also [U3.01.0x]):

deuxpi = 2.*pi

#### 1.3.2 IMPR_COURBE

Replaced by IMPR_FONCTION (cf. [7.3.13]).

#### 1.3.3 POST_GOUJ2E

This command had not been withdrawn at the same time as the associated macros MACR_GOUJ2E_MAIL/CALC. The analysis methodology is kept in the test cases zzzz120a and zzzz120b (cf. [7.2.14]).

### 1.4 Changes common to several commands

#### 1.4.1 Keywords FICHIER and UNITE

Depending on the type of command, one had to use either UNITE (reading commands), where a logical unit number was expected, or FICHIER (post-processing commands), behind which one expected not a file name but a “label” (ddname) which was associated with a logical unit by default or assigned via the command DEFI_FICHIER (formerly DEFUFI).

The notion of a label disappears; the commands all work with UNITE and those which know how to use a genuine file name also accept the keyword FICHIER.

The risk of confusion is reduced: one supplies to UNITE the logical unit entered in astk and to FICHIER a complete unix file name (see also the use of REPE_IN/REPE_OUT in the astk documentation [U1.04.00](doc:u1.04.00)).

#### 1.4.2 Post-processing commands CALC_ELEM, CALC_NO, CALC_G_LOCAL_T, CALC_G_THETA_T, POST_ELEM

**MODELE, CHAM_MATER, CARA_ELEM, EXCIT** **become optional:**

- The result data structure (coming from STAT_NON_LINE, THER_LINEAIRE…) keeps these 4 parameters in memory; it therefore becomes optional to supply them to these post-processing operators. One may however enter these keywords in certain particular cases; one then checks that they are the same ones which were used for the analysis; if this is not the case, an alarm is issued or one stops in error (case of MODELE) (cf. [7.3.7], [7.3.24]).

### 1.5 Modified commands

#### 1.5.1 AFFE_CARA_ELEM

**ANGL_L, POUR_CENT_L, POUR_CENT_T** **removed,** **SECTION_L** **renamed to** **SECTION:**

- These keywords are no longer of interest since the introduction of new membrane grid elements, which make it possible to model the reinforcement grids in a given direction, and which can be used together with a 3D modelling of the concrete. Likewise the grid elements (usable with "shell") now work in a single direction. The orientation of the reinforcements is defined under ANGL_REP (cf. [7.3.10]).

**POUTRE/VARI_SECT modified:**

- To guide the user among the possible choices, one now chooses a value for SECTION, then for VARI_SECT (new choice: CONSTANT by default), which makes it possible to limit the list of what is possible for CARA (cf. [7.3.23]).

**PREC_AIRE, PREC_INERTIE new:**

- The consistency of the information (area and inertia of the multi-fibre beams) supplied under the keywords POUTRE and AFFE_SECT is checked to the accuracy indicated by these keywords (cf. [7.3.28]).

#### 1.5.2 AFFE_CHAR_MECA / AFFE_CHAR_MECA_F

**FORMULATION** **new:**

- When solving a contact problem with the continuous method, one has the choice between a displacement formulation (value DEPL) or a velocity formulation (value VITE, numerically well suited to the treatment of impacts) (cf. [7.3.18]).

**TOLE_PROJ** **replaced by TOLE_PROJ_EXT, TOLE_PROJ_INT** **new:**

- In the case of the symmetric pairing MAIT_ESCL_SYME, it is necessary to have a projection tolerance for the detection of zero pivots (cf. [7.3.23]).

**ITER_MULT_MAXI new:**

- ITER_MULT_MAXI multiplied by the number of slave nodes gives the maximum number of contact iterations (cf. [7.3.23]).

**COEF_MULT_2,** **VECT_NORM_2,** **DIST_1,** **DIST_2** **replaced by** **COEF_MULT_ESCL,** **VECT_NORM_ESCL,** **DIST_MAIT** **and DIST_ESCL:**

- Standardisation of the vocabulary following the renaming of GROUP_MA_1/2 to GROUP_MA_MAIT/ESCL (cf. [7.3.24]).

**GRAPPE_FLUIDE new keywords:**

- Several keywords making it possible to locate the forces according to their type and their zone of application have been added (APPL_FORC_xxxx, DIRE_FORC_FPLAQ, UNITE_IMPR_xxxx) (cf. [7.3.23]).

**ARLEQUIN** **changes:**

- Improvement of the Arlequin method (cf. reference document) and addition of the keywords COND_LIM, COLLAGE, POIDS_GROSSIER, POIDS_FIN (cf. [7.3.28]).

#### 1.5.3 AFFE_MATERIAU

**SECH_REF** **new:**

- Makes it possible to enter the value of the reference drying; at this concentration, the desiccation shrinkage is zero. The user must remember to enter K_DESSIC if his drying field is variable (cf. [7.3.2]).

#### 1.5.4 CALC_FATIGUE

**MODELE** **removed:**

- The keyword was not used (cf. [7.3.2]).

#### 1.5.5 CALC_FONCTION

**METHODE** **new:**

- Improvement of the computation of the FFT by adding the method PROL_ZERO, in which the signal is padded with zeros (cf. [7.3.14]).

#### 1.5.6 CALC_G_LOCAL_T and CALC_G_THETA_T

**EXCIT** **replaces** **CHARGE:**

- The multiplicative coefficient of the loads was not taken into account. This is now the case; CHARGE, FONC_MULT and TYPE_CHARGE are added under EXCIT. Same change in CALC_G_THETA_T (cf. [7.3.6]). By default, it is in fact not necessary to supply EXCIT, which is stored in the result data structure (cf. [§1.4.2]).

**VITE, ACCE** **new:**

- Make it possible to take the inertia terms into account in the computation of G (cf. [7.3.4]).

#### 1.5.7 CREA_MAILLAGE

**NOM_CHAM** **new:**

- In order to explode the elements (ECLA_PG), one needs to know the Gauss-point family used. For this, one must supply the name of the field (cf. [7.3.19]).

#### 1.5.8 CREA_RESU

**MODELE, CHAM_MATER, CARA_ELEM new:**

- Make it possible to create a result of type elas_mult (MACRO_ELAS_MULT) (cf. [7.3.7]).

#### 1.5.9 DEBUT

**FORMAT_HDF=’OUI’/’NON’** **replaces the factor keyword** **HDF:**

- Databases in HDF format (portable binary format between machines of different architectures) are now supported by astk; it is therefore enough to specify whether or not one wishes to read a database in this format (cf. [7.3.8]).

**VISU_EFICAS new:**

- Makes it possible to indicate (in the test cases) whether a command file is readable in Eficas or not (cf. [7.3.5]).

#### 1.5.10 DEFI_FICHIER

**FICHIER** **replaces** **NOM_SYSTEME:**

- In the spirit of the simplification of the keywords UNITE and FICHIER (cf. [7.3.14]).

**Returns a free logical unit** (essentially for the macros)**:**

- In order not to cause a conflict by choosing a logical unit already in use, DEFI_FICHIER returns a free unit number (cf. [7.3.23]).

#### 1.5.11 DEFI_MATERIAU

**LEMA_SEUIL/_FO** **new:**

- Introduction of a constitutive law derived from the Lemaître law: below the threshold the law is elastic; from the threshold onwards, it behaves as a particular case of the Lemaître law (cf. [7.3.27]).

**GRANGER_FP_INDT** **new:**

- This is a Granger law under isothermal conditions (cf. [7.3.24]).

**ENDO_ORTH_BETON new:**

- Orthotropic constitutive law of concrete with damage taken into account (cf. [7.3.23]).

**DRUCK_PRAGER/_FO** **new (former** **DRUCKER_PRAGER):**

- Addition of the possibility of computing the sensitivity in 2D and 3D of the Drucker-Prager model; the addition of _FO made it necessary to rename the model in order to avoid name conflicts (cf. [7.3.21]).

**VISC_SINH replaces** **ROUSS_VISC:**

- With the addition of the viscoplastic constitutive laws VISC_ISOT_TRAC and VISC_ISOT_LINE, the viscous model being the one already used by ROUSS_VISC, the keyword has been renamed in order to be more general (cf. [7.3.19]).

**JOINT_BA** **new:**

- New constitutive law for the steel–concrete connection in 2D (cf. [7.3.8]).

**BARCELONE - ALPHAB** **new:**

- If it is not supplied, the parameter is computed by the code (cf. [7.3.6]).

**ECOU_VISC i, ECOU_ISOT i, ECOU_PLAS i, ECOU_CINE i** **new:**

- Make it possible to define the parameters of the monocrystalline behaviours (cf. [7.3.1]).

#### 1.5.12 DEFI_MODELE_GENE

**OPTION=’REDUIT’** **new:**

- This option makes it possible to use dynamic substructuring by an interface-mode method in order to reduce the size of the generalised modes; associated keywords: GROUP_MA_MAIT_1/2, MAILLE_MAIT_1/2 (cf. [7.3.18]).

#### 1.5.13 DETRUIRE

**ALARME** **new:**

- To be used only in the macro-commands, this keyword makes it possible not to issue an alarm when one attempts to delete a concept which does not exist (cf. [7.3.27]).

**CLASSE** **new:**

- Makes it possible to delete an Aster object on the volatile database (cf. [7.3.8]).

#### 1.5.14 DYNA_NON_LINE

**TETA_METHODE new:**

- Introduction of a velocity formulation for the integration of contact in dynamics. The value of  (parameter of the time-integration scheme) may be chosen between 0.5 and 1.; this makes it possible, when solving a contact problem with the continuous method, to vary the dissipation during the separation phase (cf. [7.3.18], [7.3.22]).

**REAC_ITER_ELAS new:**

- Parameter to control the frequency of updating of the secant matrix (cf. [7.3.21]).

#### 1.5.15 DYNA_TRAN_EXPLI

*It should be noted that this command will be merged with* *DYNA_NON_LINE in version 8.1.*

**REAC_ITER_ELAS new:**

- Parameter to control the frequency of updating of the secant matrix (cf. [7.3.21]).

#### 1.5.16 FIN / POURSUITE

**FORMAT_HDF=’OUI’/’NON’** **replaces the factor keyword** **HDF:**

- Databases in HDF format (portable binary format between machines of different architectures) are now supported by astk; it is therefore enough to specify whether or not one wishes to read/write a database in this format (cf. [7.3.8]).

#### 1.5.17 FORMULE

**NOM_PARA, VALE** **new:**

- Formulae are now arbitrary Python expressions (it is enough that they can be evaluated, all the same!). The parameter names and the expression are defined under these two distinct keywords (cf. [7.3.21] and [U4.31.05](doc:u4.31.05)).

#### 1.5.18 IMPR_FICO_HOMA

**UNITE_CONF, UNITE_DONN replace** **FICHIER_CONF, FICHIER_DONN:**

- In the same spirit as in paragraph [§ 1.4.1 ] (cf. [7.3.23]).

## 2 New features between 7.2 and 7.3

### 2.1 New commands

#### 2.1.1 MACR_FIABILITE

This macro-command computes the probability that a physical variable (displacement, stress, ...) exceeds a threshold defined by the user as a function of a certain number of parameters which will have been defined as sensitive by the user. These sensitive parameters may be Young's modulus, Poisson's ratio, a pressure, etc.

The macro-command calls the MEFISTO software, which is external to *Code_Aster*, and which implements the FORM method (cf. [7.2.11]).

#### 2.1.2 STANLEY

Stanley, an interactive post-processing tool, was already present in version 7; this macro-command simplifies calling it, since it is now launched as an ordinary command (cf. [7.2.25]).

#### 2.1.3 TEST_FICHIER

This macro-command makes it possible to test the non-regression of the commands which produce files, intended for developers (cf. [7.2.25]).

### 2.2 Withdrawn commands

#### 2.2.1 FACT_INTE_SPEC

This command has been merged with GENE_FONC_ALEA (cf. [7.2.3]).

#### 2.2.2 MACR_GOUJ2E_MAIL and MACR_GOUJ2E_CALC

These two macro-commands are withdrawn. The analysis methodology is kept in the command files zzzz120a and zzzz120b which validated these functionalities (cf. [7.2.14]).

### 2.3 Modified commands

#### 2.3.1 AFFE_CARA_ELEM

**RIGI_MISS_3D** **new:**

- Makes it possible to assign the terms of a soil impedance matrix computed by MISS3D for a given extraction frequency (cf. [7.2.2]).

#### 2.3.2 AFFE_MODELE

***_HH2D** **new modellings:**

- These modellings make it possible to take into account two phases in the two constituents; the dissolved-air pressure is related to the dry-air pressure by Henry's law (cf. [7.2.7]).

**GRILLE_MEMBRANE** **new modelling:**

- This is a new reinforcement-layer element which works only in membrane, with no rotation degree of freedom (cf. [7.2.21]).

#### 2.3.3 AFFE_CHAR_MECA / AFFE_CHAR_MECA_F

**GRAPPE_FLUIDE** **new:**

- Makes it possible to take into account the fluid forces due to the displacement of the cluster in the fluid which bathes the internal elements of the core (cf. [7.2.2]).

**TOLE_PROJ** **new:**

- Makes it possible to adjust the projection of the slave nodes onto the master mesh cells (cf. [7.2.1]).

**CONTACT** **keywords renamed:**

- GROUP_MA_MAIT, MAILLE_MAIT, GROUP_MA_ESCL, MAILLE_ESCL respectively replace GROUP_MA_1, MAILLE_1, GROUP_MA_2, MAILLE_2 (cf. [7.2.4]).

#### 2.3.4 ASSE_MAILLAGE

**OPERATION, MAILLAGE_1, MAILLAGE** **new:**

- Three types of operation are now available: SOUS_STR, SUPERPOSE, COLLAGE (cf. [7.2.4]).

#### 2.3.5 CALC_CHAM_ELEM / CALC_ELEM

**Duplication:**

- These two commands duplicated each other on most of the options computed; only a few options remain in CALC_CHAM_ELEM (cf. [7.2.17]).

#### 2.3.6 CALC_FATIGUE

**TYPE_CHARGE** **new:**

- Defines the type of loading (periodic or not); under the keyword CRITERE, the choice is thus restricted according to the type of loading (cf. [7.2.5]).

**CRITERE=’DOMM_MAXI’, PROJECTION, DELTA_OSCI** **new:**

- These keywords are associated with the new criterion suited to non-periodic loadings; it is a variable-amplitude criterion based on a critical plane selected according to the maximum induced damage (cf. [7.2.5]).

**CRITERE=’DANG_VAN__MODI_AC’ / ‘DANG_VAN_MODI_AV’** **new:**

- This is a variable-amplitude criterion based on a critical plane selected from the maximum damage. This criterion, which is suited to the case in which the loading is non-periodic, is an evolution of the original DANG VAN criterion. ‘AC’ for constant amplitude, ‘AV’ for variable amplitude (cf. [7.2.11]).

#### 2.3.7 CALC_G_THETA_T

**New type for the** **** **field:**

- One can now supply a  field of type cham_no_depl_r (and build it to suit!) instead of the one supplied by CALC_THETA (cf. [7.2.8]).

#### 2.3.8 CALC_NO

**GROUP_MA_RESU, GROUP_NO_RESU, MAILLE_RESU, NOEU_RESU new:**

- Make it possible to specify the zone on which the field by element will be reduced before computing the values at the nodes, because incorrect results could be obtained when a node is on the boundary of two modellings (cf. [7.2.7]).

#### 2.3.9 CREA_MAILLAGE / CREA_RESU

**ECLA_PG** **new possibilities:**

- One can now explode a mesh (by creating one element per Gauss point) over only part of a mesh; and, in 2D, give a fictitious thickness to flat elements.

**Warning:**

*The parameters supplied to* *CREA_MAILLAGE and* *CREA_RESU* must be consistent: the same mesh-cell groups given in the same order (cf. [7.2.25]).

#### 2.3.10 DEFI_FONCTION

**NOM_PARA** **new values:**

- Parameter names added: NORM and DSP (cf. [7.2.4]).

#### 2.3.11 DEFI_GROUP

**CREA_GROUP_NO/** **TOUT=’OUI’** **limited to the** **TUNNEL** **option:**

- The use of TOUT=’OUI’ is not available for all the options, only for the TUNNEL option (cf. [7.2.8]).

#### 2.3.12 DEFI_MATERIAU

**BARCELONE** **new behaviour for** **KIT_HHM** **and** **KIT_THHM:**

- Mechanical and hydraulic constitutive law of unsaturated soils. This model involves two criteria, a mechanical plasticity criterion which is that of CAM_CLAY and another, hydraulic, criterion controlled by the suction (cf. [7.2.21]).

**GLRC / GLRC_FO** **new behaviour:**

- Constitutive law of reinforced-concrete plates written in generalised forces; associated finite element DKTG (on TRIA3 and QUAD4 mesh cells) (cf. [7.2.4]).

**CORR_ACIER** **new:**

- Damageable elastoplastic model of a steel in which the plastic strain at rupture depends on the corrosion rate (cf. [7.2.23]).

**VISC_IRRA_LOG** **new behaviour:**

- Viscoelastic constitutive law for the axial creep of the guide tubes under irradiation (cf. [7.2.1]).

**DRUCKER_PRAGER new behaviour:**

- Constitutive law for soil mechanics (cf. [7.2.7]).

**LIQU_AD_GAZ_VAPE** **new:**

- Coupling law for dissolved air for THM (Henry's law), which relates the dissolved-air pressure to the dry-air pressure (cf. [7.2.7]).

**DOMM_A, DOMM_B, COEF_CISA_TRAC new:**

- Associated with the fatigue criterion DOMM_MAXI of CALC_FATIGUE (cf. [7.2.5]).

**EPSP_SEUIL, EXP_S** **new:**

- Associated with the fatigue criterion DOMMA_LEMAITRE of CALC_FATIGUE (cf. [7.2.19]).

**LAMBDA** **and** **D_LAMBDA_TEMP removed under THM_*:**

- The thermal conductivity is now defined as the product of three functions of the temperature (LAMB_T), of the saturation (LAMB_S) and of the porosity (LAMB_PHI) plus a constant (LAMB_CT), as well as the three derivatives of the functions (D_LB_T, D_LB_S, D_LB_PHI) (cf. [7.2.10]).

In the thermal case, only LAMB_T is mandatory, the other functions then being taken equal to one and their derivatives zero.

#### 2.3.13 GENE_FONC_ALEA / GENE_MATR_ALEA / GENE_VARI_ALEA

- These commands have been completely reworked; FACT_GENE_ALEA has been withdrawn in favour of GENE_FONC_ALEA. Refer to the documentations of the commands for the new syntax of use (cf. [7.2.3]).

#### 2.3.14 IMPR_RESU

**FORMAT=’GMSH’ / VERSION** **new default:**

- The default version of the GMSH file is now 1.2 (in which GMSH knows how to post-process quadrangles): the quadrangles are not cut into triangles (cf. [7.2.9]).

#### 2.3.15 INCLUDE_MATERIAU

**New materials available in the material catalogue:**

- Z3CN20-09M, Z6NCTDV25-15 (cf. [7.2.10], see on the *Code_Aster* intranet under Utilisation/Matériaux).

#### 2.3.16 MACR_RECAL

**POIDS** **new:**

## 3 New features between 7.0 and 7.2

One finds here the syntax changes consequent on the developments introduced in versions 7.1 and 7.2 (version 7.0 being similar to 6.4).

### 3.1 New commands

#### 3.1.1 CALC_PRECONT

This command makes it possible to define and apply the prestressing of the cables of a reinforced-concrete structure, taking into account different types of anchorage, and making it possible to tension each cable individually while complying with the BPEL standards (cf. [7.0.14]).

#### 3.1.2 CREA_TABLE

This command makes it possible to create a table from a function or from two lists (cf. [7.1.17]).

#### 3.1.3 DYNA_TRAN_EXPLI

This is the first version of the explicit dynamics operator, in which not all the possibilities have yet been introduced (master–slave contact, for example) (cf. [7.1.16]).

#### 3.1.4 EXTR_TABLE

This command makes it possible to recover the content of a cell of a table; only the type MATR_ASSE_GENE_R is handled for the moment (cf. [7.1.17]).

#### 3.1.5 MACR_CABRI_MAIL – MACR_CABRI_CALC

These commands make it possible to mesh flanges automatically, and to launch analyses on these meshes (cf. [7.1.5]).

### 3.2 Withdrawn commands

### 3.3 Renamed commands

- DEFI_FICHIER replaces DEFUFI and FERMER (the latter will be withdrawn in version 7.3). In addition, DEFI_FICHIER makes it possible to access a file by indicating its system name (and not only with its fortran logical unit number) (cf. [7.1.16]).

**In the commands** **CALC_FORC_AJOU,** **CALC_MATR_AJOU,** **DYNA_NON_LINE, MACR_ASCOUF_CALC, MACR_ASPIC_CALC, MACRO_MATR_AJOU, MECA_STATIQUE, STAT_NON_LINE, THER_LINEAIRE, THER_NON_LINE, THER_NON_LINE_MO**

#### 3.5.7 CALC_ELEM

**EQUI_ELNO_SIGM different computation method:**

The equivalent stresses (Von Mises, Tresca, ...) were computed from the stresses extrapolated to the nodes. The equivalent stresses are now computed by extrapolation of the equivalent stresses computed at the Gauss points (as for the internal variables). The only stress fields supplied are therefore SIEF_ELGA_DEPL in linear analysis and SIEF_ELGA in non-linear analysis.

On the other hand, for shell elements, the way of computing the equivalent stresses has not changed: the user must compute the stress field at a point through the thickness (SIGM_ELNO_DEPL in linear analysis and SIGM_ELNO_COQU in non-linear analysis), and the option EQUI_ELNO_SIGM computes the invariants of this field at the nodes.
