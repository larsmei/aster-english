# u4.72.04 Operator CREA_CHAMP

## 1 Purpose

Create a field of type cham_no, carte or cham_elem. One can create a field:

- by assigning values on nodes or mesh cells,
- by assembling (and/or combining) pieces of existing fields,
- by evaluating the functions of a field of functions in order to make a field of reals,
- by modifying the geometric representation of a field (passage from nodes $\iff$ Gauss points, for example),
- by extracting a field from a data structure of type SD_RESULTAT (evol_ther, evol_noli, mode_meca, ...).
- from the values contained in a data structure of type TABLE,
- ...

One can also use this command to combine several fields linearly, but one can make more “complicated” combinations: multiplication of fields ...

Produces a data structure of type cham_no or carte or cham_elem

Note: The command is not re-entrant except for the operations ASSE and COMB.

In this case, the keyword CHAM_GD is mandatory.

## 3 Operands

### 3.1 General operands

#### 3.1.1 Operand TYPE_CHAM, assignment of a type to the result field

This keyword (mandatory) serves first to type the result field of the command. It is formed of 2 “words” linked by an underscore (_):

TYPE_CHAM= 'XXXX_GD' where:

```text
XXXX=        / 'NOEU'            Champ aux nœuds                           (cham_no)
             / 'CART'            Champ constant par maille                 (carte)
             / 'ELNO'            Champ par éléments aux nœuds              (cham_elem)
             / 'ELGA'            Champ par éléments aux points de Gauss    (cham_elem)
             / 'ELEM'            Champ constant par élément                (cham_elem)
```

```text
GD=            / 'DEPL_R'        déplacement
               / 'SIEF_R'        contrainte
               / 'TEMP_R'        température
               / 'FLUX_R'        flux
               / ...
```

The type of the result field is deduced from this information given by the user. For example:

```text
TYPE_CHAM= 'NOEU_DEPL_R'            ->        cham_no      (DEPL_R)

TYPE_CHAM= 'CART_SIEF_R'            ->        carte        (SIEF_R)

TYPE_CHAM= 'ELNO_EPSI_R'            ->        cham_elem    (EPSI_R)

TYPE_CHAM= 'ELGA_VARI_R'            ->        cham_elem    (VARI_R)
```

This keyword also serves to specify (for the command) what the nature of the field wanted as a result must be. It is indispensable for the operations 'AFFE', 'ASSE' and 'DISC'.

Examples:
```text
OPERATION= 'AFFE' + TYPE_CHAM= 'CART_DEPL_R'    => une carte de DEPL_R.

OPERATION= 'ASSE' + TYPE_CHAM= 'NOEU_EPSI_R'    => un cham_no de EPSI_R.

OPERATION= 'DISC' + TYPE_CHAM= 'NOEU_SIEF_R'    => un cham_no de SIEF_R.
```

There are only two operations for which this keyword is a useless (but mandatory!) constraint for the user (OPERATION='EVAL' and OPERATION='EXTR') because, for these two operations, the nature of the result field is imposed by the choice of the operation.

Supplying the keyword TYPE_CHAM is (unfortunately) tedious for OPERATION='EXTR'. It is deduced from the keyword NOM_CHAM. The correspondence is given in [ 3.9.1 ].

**Important note**

*The possibility of creating* *cham_elem of any quantity is conditioned by the state of (software) development of the finite-element types of the model. Not everything is yet possible; for example, to create a* *cham_elem of* *FLUX_R on a model containing the elements* *DKT, this finite element must have provided for doing so (which is not the case today).*

*One cannot give here the precise list of the quantities allowed for each finite-element type. One will content oneself with saying approximately:*

- *for the isoparametric elements of mechanics, the quantities allowed are:* *GEOM_R,* *INST_R,* *NEUT_R,* *NEUT_F,* *EPSI_R,* *SIEF_R,* *VARI_R,* *DOMMAG and* *HYDR_R,*
- *for the isoparametric elements of thermal analysis, the quantities allowed are:* *GEOM_R,* *INST_R,* *NEUT_R and* *NEUT_F.*

#### 3.1.2 Operand CHAM_GD

With the operations ASSE and COMB, one can reuse an existing field. In this case, one must indicate here which field is reused.

#### 3.1.3 Operand MAILLAGE = mailla

When one creates a CHAM_NO or a CARTE, one must in general specify on which mesh this field will be supported. For that, one uses the keyword MAILLAGE.

#### 3.1.4 Operand PROL_ZERO

When one creates a CHAM_ELEM, the values existing in the field are determined by the finite elements of the model. For example, a field SIGM_ELGA on a 2D model **must** contain the 4 components SIXX, SIYY, SIZZ and SIXY.

If the construction of the field does not make it possible to compute all the expected values, one is faced with a problem. If the keyword PROL_ZERO is 'OUI', the missing values will be set to zero.

If the keyword PROL_ZERO is 'NON', the code will stop in error.

This problem also concerns (but more rarely) the CHAM_NO when one wants to impose the numbering of their components (see the keywords NUME_DDL and CHAM_NO).

#### 3.1.5 Operands MODELE, OPTION

When one creates a CHAM_ELEM, one must specify on which finite elements the field will be defined. For that, one uses the keyword MODELE.

To describe the structure of a CHAM_ELEM, it is not enough to give (via the MODELE) an element type for each mesh cell, because an element type may know several “forms” for a given quantity. To create the desired field, the user may use the keyword OPTION. If, for example, he or she writes: X= CREA_CHAMP(... MODELE=mo, OPTION='SIEF_ELGA', ...) , the field created by CREA_CHAMP will have the same form as if it had been computed by CALC_CHAMP / CONTRAINTE='SIEF_ELGA'. If the user does not use the keyword OPTION, CREA_CHAMP will choose (if it can) a default form.

Note: for the operation 'ASSE', when one assembles cham_elem, it is in general better not to supply the keyword OPTION. The option that will be chosen will be that of the field supplied in the 1st occurrence of the factor keyword ASSE if the quantity associated with this field is the same as that of the result field.

#### 3.1.6 Keywords AFFE_SP / CARA_ELEM

The (non-repeatable) factor keyword AFFE_SP makes it possible to request the creation of a cham_elem with “sub-points” (for the structural elements: multilayer shells, multi-fibre beams, …).

In the cham_elem produced, each point (node or Gauss point) will be represented by n sub-points (n being determined by the user's choices in the command AFFE_CARA_ELEM).

The n sub-points of a point will carry the same components (with the same values).

The keyword CARA_ELEM is mandatory: it is the name of the data structure of type cara_elem which makes it possible to determine the number of sub-points.

#### 3.1.7 Keywords NUME_DDL and CHAM_NO

These two keywords make it possible to impose a numbering for the result field (if the latter is a CHAM_NO). One gives via these keywords a numbering “model” for the result field.

If one gives NUME_DDL= nu, one will take as numbering that of nu. This possibility is valid only for displacement fields (phenomenon 'MECANIQUE') or for temperature fields (phenomenon 'THERMIQUE') or acoustic pressure fields (phenomenon 'ACOUSTIQUE').

If one gives CHAM_NO= chno, one will take the numbering of chno.

In this last case, the numbering supplied (object of type PROF_CHNO) is duplicated so that the field created is self-supporting.

If Lagrange multipliers coming from dualised boundary conditions are present, a check is made by the operator. Indeed, if the fields considered do not satisfy the same boundary conditions, they are not compatible. An alarm is then issued: the Lagrange multipliers will be set to zero in the resulting field.

#### 3.1.8 Operand TITRE = titr

Title that one wishes to give to the result field [U4.03.01](doc:u4.03.01).

#### 3.1.9 Operand INFO = /1 /2

INFO = 1

No printout.

INFO = 2

Printout on the 'MESSAGE' file of the result field.

### 3.2 Operand OPERATION = /'AFFE' / 'ASSE' / 'EVAL' / 'DISC' / 'EXTR' / 'R2C' / 'C2R' / 'COMB'

This operand serves to choose the “mode” of manufacture of the result field. One can create a field:

- by assigning values on nodes or mesh cells (OPERATION='AFFE'),
- by assembling pieces of fields defined on pieces of meshes (OPERATION='ASSE'),
- by modifying the geometric representation (discretisation) of a field (passage from nodes <-> Gauss points, for example) (OPERATION='DISC'),
- by extracting a field from an SD of type SD_RESULTAT (evol_ther, evol_noli, mode_meca, ...) (OPERATION='EXTR').
- by extracting numerical values from a table whose columns have predefined names: ‘MAILLE’, ‘NOEUD’…
- by combining fields linearly (OPERATION='ASSE'),
- by “combining” (multiplication, exponential, ...) fields (OPERATION='EVAL'),
- by evaluating the functions of a field of functions in order to make a field of reals (OPERATION='EVAL'),
- by transforming a real field at the nodes into a complex field (or conversely) (OPERATION='R2C'/'C2R'),
- by making a linear combination of several cham_no having the same numbering (OPERATION='COMB'). Unlike the operation 'ASSE', the result field will keep the Lagrange degrees of freedom associated with the dualisation of the boundary conditions.

### 3.3 Operands for OPERATION = 'AFFE'

This operation makes it possible to assign values (real, integer, complex or function) on geometric entities (nodes or mesh cells) of a mesh.

The quantity associated with the field is implicitly given by the keyword TYPE_CHAM (above).

#### 3.3.1 Factor keyword AFFE

The operands are grouped under the factor keyword AFFE. This keyword is repeatable. The overloading principle is applied between the different occurrences of the keyword AFFE: if a geometric entity is assigned several times, the last assignment wins.

#### 3.3.2 Operands TOUT='OUI', GROUP_MA and GROUP_NO

The geometric entities that one wants to assign are given by the operands TOUT='OUI', GROUP_MA and GROUP_NO.

If TYPE_CHAM='NOEU_xxx', one assigns nodes; the use of the operand GROUP_MA is possible and means that one assigns all the nodes of the specified mesh cells.

If TYPE_CHAM:'EL.._xxx' (or 'CART_xxx'), one assigns mesh cells; the use of the operand GROUP_NO is then forbidden.

Note:

For the factor keyword AFFE, the keyword TOUT='OUI' means:

- “all the nodes of the mesh” for the cham_no,
- “all the mesh cells of the mesh” for the cartes,
- “all the elements of the model” for the cham_elem,

#### 3.3.3 Operand NOM_CMP

The names of the components that one wants to assign are given by the operand NOM_CMP.

If the quantity is 'VARI_R', the components must be named 'V1', 'v2', 'V3', …

If the quantity is 'VARI_R', and if one chooses PROL_ZERO='OUI', the components whose number is lower than the highest number assigned are set to zero. For more details see the document [U2.01.09](doc:u2.01.09).

#### 3.3.4 Operands VALE, VALE_I, VALE_C or VALE_F

The values to be assigned are given by the operands VALE, VALE_I, VALE_C or VALE_F according to the nature (real, integer, complex, function (or formula)) of the components of the quantity (DEPL_R: real, DEPL_C: complex, TEMP_F: function / formula, ....).

#### 3.3.5 Note

The persistence rule (see U1.03.00) applies to the different components that one may assign.

#### 3.3.6 Examples

Creation of a field at the nodes of displacement. One wants to impose the numbering of the field (that of cnomod):
```text
DEPL1 = CREA_CHAMP( OPERATION= 'AFFE',
                    TYPE_CHAM='NOEU_DEPL_R' , MAILLAGE = MA    , CHAM_NO= CNOMOD,
                    AFFE= (
                           _F    (TOUT='OUI', NOM_CMP=('DX','DY','DZ'), VALE=(0.,0.,0.),),
                           _F    (GROUP_MA=('GM1',’GM2’) , NOM_CMP= 'DX' , VALE= 3.5e-2),
                           _F    (GROUP_NO=('GN5',’GN7’,’GN9’) , NOM_CMP= 'DY' , VALE= 1.6e-2),
                          )
)
```

Creation of a temperature map (functions):
```text
TEMPF = CREA_CHAMP( OPERATION= 'AFFE',
                    TYPE_CHAM='CART_TEMP_F' , MAILLAGE = MA,
                    AFFE=( _F( TOUT='OUI', NOM_CMP=('TEMP'),VALE_F= F1),
                           _F( GROUP_MA=(‘GM1’,’GM2’),NOM_CMP=('TEMP' ),VALE_F= F2),)
)
```

### 3.4 Operands for OPERATION = 'ASSE'

#### 3.4.1 General points

This operator “assembles” “pieces of fields” in order to manufacture a new one. Each occurrence of the keyword ASSE defines a piece of field. One calls a piece of field the restriction of an existing field (carte, cham_no or cham_elem) to a set of geometric entities (mesh cells or nodes) and to a set of components.

There is an overloading principle for the occurrences of the keyword ASSE if the pieces overlap one another.

Currently, one can manufacture:

- a cham_no by assembling pieces of cham_no.
- a cham_elem by assembling pieces of cham_elem and/or of cartes.
- a carte by assembling pieces of cartes and/or of cham_elem/ELEM.

The operation 'ASSE' also makes it possible to change the quantity associated with a field; for example to transform a strain field (EPSI_R) into a stress field (SIEF_R). For that one must use the keywords NOM_CMP and NOM_CMP_RESU.

The assembly of the pieces of fields can be done by accumulating the pieces (keywords `CUMUL` and `COEF_R`). This makes it possible to use this command to make linear combinations of CHAM_NO or of CHAM_ELEM.

#### 3.4.2 Operands MAILLAGE, MODELE

Same use as for `OPERATION= 'AFFE'` [§3.3.1] and [§3.3.2].

#### 3.4.3 Operands for the factor keyword ASSE

Each occurrence of the factor keyword ASSE makes it possible to define a piece of field which one assembles into the result field.

##### 3.4.3.1 Operand CHAM_GD = ch1

ch1 is the (existing) field with which one wants to manufacture a piece of field.

##### 3.4.3.2 Operands TOUT ='OUI', GROUP_MA and GROUP_NO

These operands serve to define the geometric restriction of the field ch1. If ch1 is a `CHAM_NO`, one can use all these operands. If ch1 is a `CHAM_ELEM` (or a `CARTE`), one cannot use the operand `GROUP_NO`.

The keyword TOUT='OUI' means here: “all the nodes, mesh cells or elements which carry components (of the list `NOM_CMP`) in the field ch1”.

##### 3.4.3.3 Operands NOM_CMP and NOM_CMP_RESU

The operand `NOM_CMP` serves to define the components on which one wants to restrict the field ch1. If `NOM_CMP` is absent, one takes all the components of `ch1`.

The operand `NOM_CMP_RESU` serves to rename (if one wishes) the components of `ch1`. If `NOM_CMP_RESU` is supplied, `NOM_CMP` must be supplied as well and the two lists in correspondence must be of the same length.

Example 1: transform a field of EPSI_R into a field of VARI_R
```text

                  MODELE=MO,
                  ASSE=_F(
                      CHAM_GD=CHEPSI ,TOUT='OUI',
```

##### 3.4.3.4 Operands CUMUL , COEF_R and COEF_C

The operand *CUMUL='OUI'* means that the values of the occurrence concerned will be added to any values already existing.

If `CUMUL='NON'`, the assigned value replaces the value possibly already present (`CUMUL='OUI'` is invalid for “text” fields (`k8/k16`, ...) of course).

The operand `COEF_R = coefr` makes it possible to multiply the piece of field by the real coefficient coefr before assembling it into the result field.

Example:

Manufacture the cham_elem: ch3 = 2. * ch1 + 3. * ch2
```text
CH3= CREA_CHAMP(OPERATION= 'ASSE',
                MODELE = MO,
                TYPE_CHAM ='ELGA_EPSI_R',
                ASSE = (_F(
                            CHAM_GD = CH1 , TOUT ='OUI',
                            CUMUL='OUI', COEF_R = 2.),
                        _F(
                            CHAM_GD = CH2 , TOUT ='OUI',
                            CUMUL='OUI', COEF_R = 3.),
                        )
)
```

**Note concerning complex fields**

The keyword `COEF_C` is accepted only in the case where the result field (`CH3`) and the argument fields (`CH1` and `CH2`) are all complex. To make a linear combination with complex coefficients of real fields, one must beforehand transform the real fields into complex fields. See `OPERATION = 'R2C'`.

*Example 1*

### 3.5 Operands for the factor keyword COMB

This keyword makes it possible to compute the linear combination of several `cham_no` having the same numbering. Unlike the operation 'ASSE', the result field will also contain the Lagrange coefficients corresponding to the dualisation of the boundary conditions.

Each occurrence of the factor keyword `COMB` makes it possible to define one element of the linear combination.

#### 3.5.1 Operand CHAM_GD = ch1

`ch1` is the (existing) `cham_no` that one wants to combine linearly.

#### 3.5.2 Operand COEF_R = coefr

coefr is the real coefficient applied to ch1 for the combination.

### 3.6 Operands for OPERATION = 'EVAL'

This operation serves to transform a field of functions into fields of reals by evaluating the functions of the field of functions.

The field of functions is necessarily a field of the quantity `'NEUT_F'` and the result field will always be a field of `'NEUT_R'`. This field may be transformed into a field of any other quantity by calling the command `CREA_CHAMP / OPERATION='ASSE'` a second time.

An example of the use of the operation `EVAL` is given in the document [U2.01.09](doc:u2.01.09) “Analytical definition of a stress field ...”

#### 3.6.1 Operand CHAM_F= chf

`chf` is the name of the field of functions to be evaluated (`CHAM_NO`, `CARTE` or `CHAM_ELEM`).

#### 3.6.2 Operand CHAM_PARA= l_chpara

*l_chpara* is the list of the “parameter” fields for the evaluation of the functions. All the fields of *l_chpara* must be discretised in the same way as *chf*. For example, if `chf` is a `CHAM_ELEM/ELGA`, all the fields of `l_chpara` must also be `CHAM_ELEM/ELGA`.

The list of parameter fields must be sufficient to allow the evaluation of all the functions referenced in `chf`, and no component of a parameter field must be present in another parameter field of the list either.

Note: Thus, for element fields, it is for example not possible to supply two fields of quantity `NEUT` even if it is not the same components that must be taken into account on the two fields, because each field has the components X1 to X30.

#### 3.6.3 Examples

##### 3.6.3.1 Example 1

One wants to create a `cham_elem` (`SIEF_R`) at the Gauss points whose components are analytical functions of the geometry and of time. For this example, one assumes that one has already manufactured two fields at the Gauss points, `CHGEOMG`: geometry field and `CHINSTG`: field of time instants.
```text
RHO=1000.
G=10.
KP=3.
SIZZ = FORMULE (NOM_PARA = 'Z', VALE = 'RHO*G*Z')
SIXX = FORMULE (NOM_PARA = ('Z','INST'), VALE = 'KP*SIZZ(Z)+3.*INST')

# Affectation des fonctions :
# -----------------------------------------------

SIG1=CREA_CHAMP(OPERATION='AFFE', TYPE_CHAM='ELGA_NEUT_F',
                MODELE=MO , PROL_ZERO='OUI',
                AFFE=_F(TOUT='OUI', NOM_CMP=('X1','X2'),
                        VALE_F=('SIXX','SIZZ'),
                        )
                )

# Evaluation des fonctions :
# -----------------------------------------------

SIG2= CREA_CHAMP(OPERATION='EVAL' ,TYPE_CHAM='ELGA_NEUT_R',
                 MODELE=MO ,CHAM_F=SIG1 , CHAM_PARA=( CHGEOMG,CHINSTG),
                 )

# transformation du champ de NEUT_R en SIEF_R :
# -----------------------------------------------

SIG3=CREA_CHAMP(OPERATION='ASSE', TYPE_CHAM='ELGA_SIEF_R',
                MODELE=MO , PROL_ZERO='OUI',
                ASSE=_F(TOUT='OUI', CHAM_GD=SIG2,
                        NOM_CMP= ('X1' ,'X2' ),
                        NOM_CMP_RESU=('SIXX','SIZZ'),
                        )
            )
```

##### 3.6.3.2 Example 2

One wants to compute a temperature field at the nodes ($\mathrm{CH3}$ ) containing the product of 2 other temperature fields at the nodes ($\mathrm{CH1}$  and $\mathrm{CH2}$ )

### 3.7 Operands for OPERATION = 'DISC'

This operation serves to modify the “discretisation” of an existing field. For example, to transform a field at the nodes into fields at the Gauss points.

The two fields (input and result) are associated with the same quantity. There is one exception: the case of the operation `DISC` which makes it possible to transform a `cham_no_VAR2_R` (or a `carte_VAR2_R`) into a `cham_elem_VARI_R` (see for example the test hplp100b).

The discretisation wanted by the user for his or her result field is indicated by the keyword `TYPE_CHAM`.

Only the following cases are currently processed by the command:

| CARTE | -> CHAM_ELEM / ELNO |
| --- | --- |
| CARTE | -> CHAM_ELEM / ELGA |
| CARTE | -> CHAM_ELEM / ELEM |
| CARTE | -> CHAM_NO |
| CHAM_NO | -> CHAM_ELEM / ELNO |
| CHAM_NO | -> CHAM_ELEM / ELGA |
| CHAM_NO | -> CHAM_ELEM / ELEM |
| CHAM_ELEM / ELNO | -> CHAM_NO |
| CHAM_ELEM / ELGA | -> CHAM_ELEM / ELNO |
| CHAM_ELEM / ELGA | -> CHAM_NO |
| CHAM_ELEM / ELEM | -> CHAM_ELEM / ELGA |
| CHAM_ELEM / ELEM | -> CHAM_ELEM / ELNO |

The ingredients of the processings are:

`CARTE / ELEM -> ELxx`:

- The (unique) value carried by a mesh cell is copied onto all the points of the mesh cell.

`NOEU -> ELxx`:

- the passage from the values at the nodes to the internal points of the mesh cell is done by using the shape functions of the finite elements of the model.

`ELGA -> ELNO`:

- the passage from the values at the internal points to the nodes of the mesh cell is done by using the Gauss->nodes extrapolation matrix.

`ELNO -> NOEU`:

- the passage to the values at the nodes of the mesh is done by arithmetic mean of the values carried by the nodes of the elements meeting there.

#### 3.7.1 Operand CHAM_GD= ch1

ch1 is the field whose “discretisation” one wants to modify.

#### 3.7.2 Keyword MODELE

Same use as for `OPERATION = 'AFFE'` [3.3.2]

#### 3.7.3 Example
```text
# CHXG = CHAMP DE GEOMETRIE AUX POINTS DE GAUSS :
# ---------------------------------------------------------

                 NOM_CHAM='GEOMETRIE', MAILLAGE=MA
                 )

                 MODELE=MO , CHAM_GD= CHXN
                 )
```

### 3.8 Operands for OPERATION = 'NORMALE'

This operation serves to compute the “normal” vectors to the facets of a model. The user must indicate, with the keywords `MODELE` and `GROUP_MA`, the name of the model concerned as well as the “facets” whose normals he or she wishes to compute. The “facets” may be “skin” elements of a 3D mesh or plate / shell elements.

For 2D meshes, the “facets” are line elements.

The field produced is a cham_no (quantity GEOM_R) whose components are named X, Y, Z. The normal carried by a node is obtained by averaging the normals of the facets meeting at that node. The “normal” vector has length 1.

#### 3.9.2 Operand TABLE
```text
♦    TABLE = tabl
```

Name of the table concept containing the values to be stored in the field. The names of the parameters of the table must comply with certain rules. The names of the mesh cells and of the nodes must be coded on 8 characters; the tables printed in 'TABLEAU' format print the strings on 24 characters by default, so it is preferable to use the 'ASTER' format when re-reading the tables in order to specify the format of the character strings and to indicate K8 for the parameters NOEUD and MAILLE.

The columns containing the values of the field (reals) must be identified by their component name in the quantity. For example: DX, DY, DZ for the displacement (DEPL_R).

The other columns to be supplied depend on the type of field to be created:

| Type of the field | Column 1 | Column 2 | Column 3 |
| --- | --- | --- | --- |
| NOEUD_XXXX | NOEUD |  |  |
| ELEM_XXXX | MAILLE | [SOUS-POINT] |  |
| ELNO_XXXX | MAILLE | NOEUD | [SOUS-POINT] |
| ELGA_XXXX | MAILLE | POINT | [SOUS-POINT] |

The parameter `NOEUD` contains the name of the node.

The parameter `MAILLE` contains the name of the mesh cell.

The parameter `POINT` contains the number of the Gauss point in the mesh cell.

The parameter `SOUS_POINT` (necessary only for fields with “sub-points”) contains the number of the sub-point in the Gauss point (or the node).

Warning: the table must not contain any column other than the expected columns (for example: `NUME_ORDRE`, `INST`, …). If the table contains useless columns, one must delete them by means of the command `CALC_TABLE + OPERATION='EXTR'`.

#### 3.9.3 Operand RESULTAT
```text
♦    RESULTAT = resu
```

Name of the result concept in which one wants to recover a field.

#### 3.9.4 Operand NOM_CHAM
```text
♦    NOM_CHAM
```

This keyword specifies the symbolic name of the field to be extracted [U4.71.00](doc:u4.71.00).

#### 3.9.5 Operands NUME_ORDRE / NUME_MODE / NOM_MODE / ... / INTERPOL

These keywords serve to specify **the** order number of the SD_RESULTAT that one wants to extract.

The choice of the keywords to be used depends on the type of SD_RESULTAT [U4.71.00](doc:u4.71.00).

**Notes**

When one uses* INTERPOL = 'LIN', the extracted field will be an interpolation between two fields of the SD_RESULTAT. This interpolation does not always have a “physical” meaning; for example on eigenmodes. This keyword should be used only for SD_RESULTAT of type “evol_xxxx”

When one uses an access of “real” type (INST or FREQ), one looks for a field in a given interval. If one finds several fields in the interval, the program stops in fatal error.

#### 3.9.6 Computation of a field containing the “extrema” of an SD_RESULTAT

The idea is to create a field containing, at each point of space, the extreme value encountered during a transient (or the time instant at which this value was encountered).

Today this paragraph concerns only the results of type `evol_ther`, `evol_elas`, `evol_noli` and `dyna_trans`. The fields are always of “real” type.

One must specify:

- the order numbers defining the transient: `TOUT_ORDRE`, `LIST_INST`,
- the type of extremum chosen: `TYPE_MAXI = 'MAXI', ...,'MINI_ABS', 'NORM_TRAN'`,
- what one wants: the extreme value, the time instant or the order number at which this value is reached (`TYPE_RESU`).

##### 3.9.6.1 Operand TYPE_MAXI

| / 'MAXI' | one considers the maximum reached by the components during the transient, |
| --- | --- |
| / 'MAXI_ABS' | one considers the maximum reached by the absolute value of the components during the transient, |
| / 'MINI' / 'MINI_ABS' | likewise for the minima, |
| / 'NORM_TRAN' | one considers the maximum reached by the quantity: DX**2 + DY**2 + DZ**2. |

- for the 4 values: `'MAXI'`, ...,'`MINI_ABS'`, the components of the field are processed independently of one another: the extreme values may not be reached at the same time instant,
- the fifth possible value: `'NORM_TRAN'` is possible only for the fields of `depl_R`. At a given point, one looks for the time instant at which the norm of the translation vector is maximum and one copies into the result field all the components of the field at the time instant found.

##### 3.9.6.2 Operand TYPE_RESU

| / 'VALE' , | the result field contains the extreme values encountered during the transient, |
| --- | --- |

**Note:**

*Even if the extremum was obtained with an absolute value ('MAXI_ABS' or* *'MINI_ABS'), the stored value is algebraic.* *One must use* *VALE_ABS in order to have the absolute value.*

| / 'INST' , | the result field contains the values of the time instants at which the extreme values were encountered. |
| --- | --- |

| / 'NUME_ORDRE' , | the result field contains the values of the order numbers at which the extreme values were encountered. |
| --- | --- |

**Note:**

*If,* for example:

- NOM_CHAM = 'FLUX_ELNO',
- TYPE_RESU = 'INST',

*The result field is a field of type FLUX_R which contains values of time instants!*

| / 'VALE_ABS' , | available only with an absolute TYPE_MAXI ('MAXI_ABS' or 'MINI_ABS'), the result field then contains the extreme absolute values encountered during the transient. |
| --- | --- |

##### 3.9.6.3 Operands TOUT_ORDRE / LIST_INST / LIST_FREQ / PRECISION / CRITERE

These keywords make it possible to specify the extent of the transient to be examined.

If TOUT_ORDRE = 'OUI' one goes through all the order numbers.

If LIST_INST = linst one considers only the time instants specified.

#### 3.9.7 Examples

##### 3.9.7.1 Extraction of a temperature field from a result concept of type evol_ther
```text
temp10 =    CREA_CHAMP(OPERATION='EXTR',
                       NOM_CHAM = 'TEMP',
                       TYPE_CHAM = 'NOEU_TEMP_R',
                       RESULTAT = evoth,
                       INST = 10. )
```

temp10 is the temperature field extracted from the result evoth (of type evol_ther) at time instant 10.

##### 3.9.7.2 Extraction of a displacement field from a result concept of type mode_meca
```text
mode4 =    CREA_CHAMP(OPERATION='EXTR'    ,
                      NOM_CHAM = 'DEPL'    ,
                      TYPE_CHAM = 'NOEU_DEPL_R',
                      RESULTAT = modes,
                      NUME_MODE = 4 )
```

mode4 is the 4th eigenmode of the result modes (of type mode_meca).

##### 3.9.7.3 Extraction of the “temperature” field containing the time instants at which the maximum temperature was reached during a transient
```text
instmax = CREA_CHAMP(OPERATION='EXTR',
                     NOM_CHAM = 'TEMP',
                     TYPE_CHAM = 'NOEU_TEMP_R',
                     RESULTAT = evoth,
                     TYPE_MAXI = 'MAXI',
                     TYPE_RESU = 'INST'
                     )
```

##### 3.9.7.4 Extraction of a stress field from a table

Consider the file (fort.81) containing the image of the following table:
```text
#DEBUT_TABLE
#TITRE CONTRAINTE `ELNO'
MAILLE POINT       SIXX       SIYY      SIZZ
    K8     I          R          R         R
    M1     1 -1.632E+03 -2.553E+02 6.788E-01
    M1     2 -5.302E+03 -9.663E+01 6.018E+01
    M1     3 -3.638E+03 -1.058E+02 5.669E+01
    M2     1  5.632E+01  1.553E+02 3.788E-01
#FIN_TABLE
```

One can extract a field of “stresses” at the nodes from this table by doing:
```text
# lecture de la table :
TA=LIRE_TABLE(UNITE=81, TYPE_TABLE='TABLE', SEPARATEUR=' ')

# extraction du champ dans la table :
CH=CREA_CHAMP(OPERATION='EXTR', TYPE_CHAM='ELNO_SIEF_R', TABLE='TA',
              MODELE=MO, PROL_ZERO='OUI', OPTION='SIEF_ELNO_DEPL')
```

##### 3.9.7.5 Computation of the field of “normals” on a group of boundary mesh cells
```text
nor_DNOR = CREA_CHAMP(TYPE_CHAM = 'NOEU_GEOM_R',
                      OPERATION= 'NORMALE', MODELE= MO, GROUP_MA= 'FE' );
```
