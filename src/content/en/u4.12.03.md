# u4.12.03 Procedure DEFI_FICHIER

## 1 Purpose

Open or close a file associated with a logical-unit number. This number may be indicated in the procedure or else obtained in return from the latter. This action may be carried out at any moment during the work. This procedure makes it possible to associate a logical-unit number with a FORTRAN file of ASCII type, but this notion may also apply, with certain restrictions, to files of binary type.

## 2 Syntax

```text
entier = DEFI_FICHIER(
    ◇ ACTION = / "ASSOCIER" (par défaut),
               / "LIBERER",
               / "RESERVER",
    # Si: equal_to("ACTION", 'ASSOCIER')
        ◆ | UNITE = unit,
          | FICHIER = text,
        ◇ TYPE = / "ASCII" (par défaut),
                 / "BINARY",
                 / "LIBRE",
        # Si: equal_to("TYPE", 'ASCII')
            ◇ ACCES = / "NEW" (par défaut),
                      / "APPEND",
                      / "OLD",
        # Si: not equal_to("TYPE", 'ASCII')
            ◇ ACCES = / "NEW" (par défaut),
                      / "OLD",
    # Si: equal_to("ACTION", 'RESERVER')
        ◆ | UNITE = unit,
          | FICHIER = text,
        ◇ TYPE = "ASCII",
        ◇ ACCES = "APPEND",
    # Si: equal_to("ACTION", 'LIBERER')
        ◆ / UNITE = unit,
          / FICHIER = text,
    ◇ INFO = / 1,
             / 2,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Behaviour of DEFI_FICHIER

Input/output on ASCII files from *Code_Aster* is carried out, for the most part, by means of FORTRAN instructions using the notion of a **logical unit**; it is an integer varying from 1 to 99 associated, by means of an instruction of "open" type, with a file. By default this number xx is associated with the name fort.xx, but it is possible to associate it with any file name. The logical-unit number is used in the astk access interface to the code in order to copy the input and output files.

In the *Aster* command file the various operators carrying out reads or writes accept the keyword UNITE as an argument.

Logical unit 6 is reserved by the code during the initialisation phase. It is not permitted to modify this logical-unit number 6, which makes it possible to trace the progress of an execution.

| **logical unit** | **file name** | **modification allowed** |
| --- | --- | --- |
| 6 | MESSAGE | no |

The user may wish to add or **modify** associations by means of the procedure DEFI_FICHIER in order, for example, to use new file names, to print certain results or to group them differently in files. The procedure DEFI_FICHIER also makes it possible to designate directly the file of ASCII type that will be associated with the specified logical unit. It may be specified either by an absolute name (limited to 255 characters) if the file is located on the machine, or by a relative name in an agreed directory (./REPE_IN or ./REPE_OUT) when the interface is responsible for the remote and global transfer of all the files located under the directory (type repe in astk). A named Fortran OPEN is then carried out on the files of ASCII type. The command also makes it possible to position oneself either at the head of the file or at the end of the file.

The code manages internally a data structure gathering all the associations logical unit – file name – file type – access type.

## 4 Operands

The modification or modifications of the logical-unit–file-name association concern the **output** files and the **input** files.

### 4.1 Operand ACTION

```text
◊    ACTION= 'ASSOCIER'
```

The logical-unit number is associated, when this is permitted, with the name defined after the keyword FICHIER if it is filled in, and with the name fort.xx otherwise.

It is not possible to redefine the associations of the logical numbers 6 and 9.

```text
◊    ACTION= 'LIBERER'
```

The logical-unit number is released; it is no longer valid to use this unit number. The associated file, when it is of ASCII type, is the subject of a close order by means of the Fortran CLOSE instruction. It then becomes possible to reuse the logical-unit number with an action of type ‘LIBERER’. This mechanism is essential if one wishes to be able to reuse immediately the content of the associated file in the command file in progress; indeed the buffers must have been completely flushed and the file must be accessible, possibly during a call to a piece of software from a Python command of type os.system.

```text
◊    ACTION= 'RESERVER'
```

This type of action is used in the macro-commands and makes it possible to avoid conflicts of logical-unit number between Fortran and Python.

The logical-unit number is associated, when this is permitted, with the name defined after the keyword FICHIER if it is filled in, and with the name fort.xx otherwise. There is no instruction of OPEN type executed; it is up to the macro-command to carry out the various necessary actions.

### 4.2 Operand FICHIER

```text
◊    FICHIER= nomfic
```

Physical name of the file (< 255 characters) that one wishes to associate with a logical unit. This file will be created under the execution directory of the code, but one may indicate directly a file name (complying with UNIX conventions) in the user's directory. Under the execution directory, it is possible to use an additional level of directory tree of conventional name REPE_IN (data files) or REPE_OUT (result files) recognised by the astk access interface to the code. This name must be placed between quotes. Although they are not associated with a logical unit by a Fortran OPEN order, binary files (for example MED) may be treated with this mechanism; one must nevertheless specify the access type NEW or OLD in order to activate the copy (by a system call from the code) from the data directory or towards the result directory.

When the operand is absent, it is by default the file name fort.ul, where ul is the unit number, that is associated with the logical unit defined after UNITE.

For files of ASCII type, a Fortran OPEN instruction is executed on the name associated with the logical unit.

### 4.3 Operand UNITE

```text
◊    UNITE= numul
```

Associated logical-unit number; its value for the ASCII files opened by instructions lies between 1 and 99 inclusive.

It is possible to reuse a number already assigned, but in this case one must take the precaution of releasing the latter beforehand. Certain logical-unit numbers cannot be redefined from the Aster commands; these are the numbers 6 and 9, which are allocated respectively to the files MESSAGE and ERREUR.

This number may then be used in all the Aster commands that have the operand UNITE (IMPR_RESU, IMPR_TABLE, IMPR_FONCTION, etc.).

The operand UNITE may sometimes be omitted; it is then the code that will choose to assign a number, according to availability. One must then necessarily specify the operand FICHIER; the code then takes care internally of associating the logical-unit number and the associated file. It is then possible to recover an integer value on output from the operator.

### 4.4 Operand TYPE

```text
◊    TYPE= 'ASCII'
```

The file associated with the logical unit is of ASCII type.

```text
◊    TYPE= 'LIBRE'
```

The file associated with the logical unit is of a type undetermined in the Fortran sense; this makes it possible to manage access to the file more flexibly. This type is used essentially for access to MED files. The logical unit is not really used in this case, but this makes it possible to have the naming convention fort.ul on the file and to be able to transmit it easily through the access interface to the code.

```text
◊    TYPE= 'BINARY'
```

The file associated with the logical unit is of BINARY type.

### 4.5 Operand ACCES

```text
◊    ACCES= 'NEW'
```

The file of "ASCII" type is opened and one positions oneself at the head; a Fortran instruction of REWIND type is executed. If it exists, the file is overwritten. To be used for a result file.

```text
◊    ACCES= 'OLD'
```

The file of "ASCII" type is opened and one positions oneself as it is, that is to say possibly at the position at which one was during the last access.

To be used for a data file.

```text
◊    ACCES= 'APPEND'
```

The file is opened and one positions oneself at the end of the file. Used only in the case of files of ASCII type.

To be used for a data file that one wishes to complete (which will therefore a priori be a result file).

### 4.6 Operand INFO

```text
◊    INFO= inf
```

Makes it possible to print in the MESSAGE file the list of the logical units opened with the command DEFI_FICHIER together with the associated parameters. If INFO = 1, there is no printout.

## 5 Declaration in the access interface to the code of the logical unit used in DEFI_FICHIER

Generally the user will call DEFI_FICHIER with a view to carrying out post-processings when the need is felt to create physically several result files according to the load cases, the quantities, the steps or time instants of the evolution of the analysis.

The user must declare the physical names of the files and the associated logical units. This declaration is made, in the astk interface, before the launching of the execution of the work. The files must be added to the study profile by selecting the type **libr** and associating with them the chosen logical-unit number.

The type repe is used in the astk interface to transmit or receive the whole content of a file directory; it is up to the user to call DEFI_FICHIER in the command file in order to carry out the association with the logical-unit number.

By convention the data files are transmitted in the local directory named REPE_IN, and the result files are transmitted in the local directory named REPE_OUT.

In the command DEFI_FICHIER, the name passed after FICHIER is of the form: ./REPE_IN/mon_fichier.

For a data file, one will for example do:

DEFI_FICHIER(FICHIER='./REPE_IN/file.data',

ACCES='OLD',

UNITE=11)

LIRE_FONCTION(UNITE=11, ...)

**Note**

INCLUDE *cannot be used with a logical unit associated with a particular file name.*
