# u4.64.01 Operator DEFI_INTERF_DYNA

## 1 Purpose

Define the interfaces of a structure and assign a type to them.

Used within modal recombination methods, or dynamic substructuring by modal synthesis. It also lists, without computing them (a task carried out by the operator DEFI_BASE_MODALE [U4.64.02](doc:u4.64.02)), the static deflected shapes corresponding to the defined interfaces.

Produces a data structure of type interf_dyna_clas.

## 2 Syntax

```text
interf_dyna_clas = DEFI_INTERF_DYNA(
    ◆ NUME_DDL = nume_ddl,
    ◆ INTERFACE = _F(
         ◇ & NOM = text,
           & TYPE = / "MNEAL",
                    / "CRAIGB",
                    / "CB_HARMO",
                    / "AUCUN",
         ◆ / GROUP_NO = grno,
         ◇ MASQUE = text,
      ),
    ◇ FREQ = float (défaut: 1.0),
    ◇ INFO = / 1 (par défaut),
             / 2,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Operand NUME_DDL

```text
♦    NUME_DDL = nu
```

Name of the nume_ddl concept of the structure.

### 3.2 Keyword INTERFACE

```text
♦    INTERFACE
```

Factor keyword for the definition of the interfaces.

#### 3.2.1 Operand NOM

```text
◊    NOM = ’nom_int’
```

Name of the interface. **It is mandatory for each interface**. If, for an occurrence of the factor keyword INTERFACE, no name is given, then this occurrence completes the definition of the previously named interface (concatenation of the list of nodes onto those already existing). This makes it possible to use the keyword GROUP_NO for one and the same interface, or else to give different arguments to the keywords MASQUE and DDL_ACTIF within the same interface.

#### 3.2.2 Operand TYPE

```text
◊    TYPE=
```

It makes it possible to specify the kind of modal basis corresponding to the interface.

```text
'MNEAL':
```

Interface corresponding to a modal basis of MAC-NEAL type, which comprises eigenmodes and attachment modes. The attachment modes are counted, at the interface, only on the degrees of freedom that are neither fixed nor masked.

```text
'CRAIGB':
```

Interface corresponding to a modal basis of CRAIG-BAMPTON type, which comprises eigenmodes and constraint modes. The constraint modes are counted, at the interface, only on the degrees of freedom fixed by dualisation and not masked.

```text
'CB_HARMO':
```

Interface corresponding to a modal basis of harmonic CRAIG-BAMPTON type, which comprises eigenmodes and harmonic constraint modes (imposed harmonic unit displacement). The frequency used is that given as the argument of the frequency keyword 'FREQ'.

The harmonic constraint modes are counted, at the interface, only on the degrees of freedom fixed by dualisation and not masked.

```text
'AUCUN':
```

Free interface. No static deflected shape will be computed; the modal basis will comprise only eigenmodes.

#### 3.2.3 Operand GROUP_NO

```text
◊    GROUP_NO= ’lgno’
```

Ordered list of the node groups of the mesh making up the interface. The final list of nodes is obtained by the union of the node groups in the order given by the user, when the groups are defined.

#### 3.2.4 Operand MASQUE

```text
◊    MASQUE= ’lddl’
```

List of the degrees of freedom, for the current nodes, which must not generate static deflected shapes (masked degrees of freedom).

### 3.3 Operand FREQ

```text
◊    FREQ= val_freq
```

Value of the frequency used for the computation of the harmonic constraint modes.

### 3.4 Operand INFO

```text
◊    INFO=
```

Level of information supplied in the file 'MESSAGE':

| 1 | no printout, |
| --- | --- |
| 2 | writing of the definitions of the interfaces (kind, nodes), and of the static deflected shapes listed (makes it possible to check the list of the static deflected shapes before their actual computation). |

### 3.5 Case of a node common to several interfaces

When a node is common to several interfaces (for example the centre of a circular structure), this often leads to a singular system in the computation of the eigenmodes of the complete structure. One gets around this problem by eliminating the common node. This of course leads to an error on the global modes, but if the mesh is fine enough it is not noticeable (see the test case SDLS01).
