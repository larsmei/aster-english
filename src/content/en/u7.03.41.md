# u7.03.41 Procedure MACR_ECREVISSE

**Summary:**

The purpose of the macro-command MACR_ECREVISSE is to compute the flow rate of fluid (air/steam/liquid) through one (or several) through-crack(s) in a structure modelled in 2 dimensions. To do this, at each time step, it carries out the chaining of two codes:

- *Code_Aster*  which makes it possible to know the thermo-mechanical state of the structure
- Ecrevisse which carries out the thermo-hydraulic analysis of the flow through the crack.

In practice, the macro-command takes care of carrying out successively, for all the time steps:

- a linear thermal analysis
- a quasi-static mechanical analysis
- calling the macro-command CALC_ECREVISSE, which will be in charge of:

  - recovering the crack profile
  - calling a third macro-command MACR_ECRE_CALC which will generate the command file and launch Ecrevisse
  - extracting and copying the results
  - checking that the imposed criteria are satisfied and, if necessary, subdividing the time step.

The main output concept is the result data structure of the mechanical analysis (evol_noli). It is also possible to obtain the result data structure of the thermal analysis, as well as 2 tables, one containing the flow rates at each time instant, the other summarising the data concerning the cracks. By creating an output directory in the study profile, one will be able to recover there all the outputs concerning Ecrevisse.

It is possible to perform restarts of the analysis.

**Note**

*It is necessary to specify the keyword* DEBUG=_F(HIST_ETAPE='OUI') *in* DEBUT *or* POURSUITE *in order to use* MACR_ECREVISSE *.*

## 1 Purpose

This command makes it possible to chain Code_Aster with the ECREVISSE software. The principle is based, for each time step, on a successive call to:

- THER_LINEAIRE in order to obtain the thermal state of the structure
- STAT_NON_LINE in order to obtain the mechanical state of the structure
- the ECREVISSE code in order to know the flow conditions of the fluid.

**Note**

*It is necessary to specify the keyword* DEBUG=_F(HIST_ETAPE='OUI') *in* DEBUT *or* POURSUITE *in order to use* MACR_ECREVISSE *.*

### 3.17 Keyword MODELE_ECRE

```text
♦ MODELE_ECRE
```

This keyword makes it possible to specify the models which will be used by Ecrevisse to compute the flow of the fluid.

#### 3.17.1 Operand IVENAC

```text
◊ IVENAC    =     0 ou 1,
```

When this operand is activated (IVENAC=1), the ECREVISSE analysis is carried out taking the vena contracta into account (pressure loss at the inlet). Otherwise (default case), the analysis will be carried out without this modelling option.

#### 3.17.2 Operand ECOULEMENT

```text
♦ ECOULEMENT    =     / 'SATURATION',
/ 'GELE'
```

In the absence of air and in the presence of water (operand FLUIDE_ENTREE=1 or 2), this operand makes it possible to choose between the homogeneous equilibrium model and the «GELE» flow model characterised by a non-zero fraction of metastable liquid.

#### 3.17.3 Operand PRESS_EBULLITION

Boiling pressure ($\mathit{Pa}$ ) to be supplied only for the frozen-flow model.

#### 3.17.4 Operand FROTTEMENT

The aim here is to define how the friction is computed. The valid values are: $-14,-12,-11,-4,-3,-2,-1,0,1,2,3,4,11,12,14,21,22,23,24$ .

The value $0$ corresponds to an analysis without friction.

For the negative values, the user fixes the value of the friction coefficient for the turbulent flows.

For the positive values, the friction in turbulent flow is computed from the roughness coefficient. In particular, the options $21,22,23,24$ correspond to the friction relation of Greiner and Ramm  [Bib.6] for the flow in a crack in concrete; the roughness is in this case the diameter of the largest aggregate. Moreover, for the values greater than $10$ , the law used for laminar flow (friction proportional to the inverse of the Reynolds number) is connected with that in turbulent flow (constant value of the friction coefficient). Otherwise, a discontinuity is present.

The second digit (1,2,3,4) of each option (units) determines the option for computing the dynamic viscosity for the two-phase flows, cf. Ecrevisse documentation  [Bib.1]  [Bib.2]  [Bib.3]  [Bib.4]  [Bib.5] .

#### 3.17.5 Operands REYNOLDS_LIM / FROTTEMENT_LIM

Limit Reynolds coefficient and imposed friction coefficient for a Reynolds number greater than the limit Reynolds number.

To be supplied only if FROTTEMENT < 0.

#### 3.17.6 Operand TRANSFERT_CHAL

This operand makes it possible to define whether or not one wants to take into account heat transfer by convection between the fluid and the wall. The valid values are: $-12,-11,-2,-1,0,1,2,11,12$ .

The value 0 corresponds to an analysis without heat transfer (adiabatic).

The other values correspond to different options for the computation of the convection coefficient (differences only for the laminar regime). Refer to the Ecrevisse documentation.

#### 3.17.7 Operands XMINCH / XMAXCH

This operator only makes sense in the two-phase cases, if TRANSFERT_CHAL < 0. It makes it possible to specify the value of the gas mass fractions delimiting the transition zone between the models for computing the convection coefficient, cf. Ecrevisse documentation.

### 3.18 Keyword CONV_CRITERE

The macro-command computes at each time instant three criteria making it possible to estimate the importance of the changes which have occurred between two time steps and thus the validity of the chaining carried out. In order to compute these criteria, the user must define reference values for the pressure and the temperature, making it possible to quantify the acceptable deviation.

$\begin{array}{c}{e}_{T}=\frac{\mathit{Max}({T}_{t}-{T}_{\text{t-1}})}{{T}_{\text{REF}}}\\ {e}_{P}=\frac{\mathit{Max}({P}_{t}-{P}_{\text{t-1}})}{{P}_{\text{ref}}}\\ {e}_{G}=\sqrt{{e}_{T}^{2}+{e}_{P}^{2}}\end{array}$

Then, if he wishes, he may activate the subdivision of the time step if the value of the criterion is lower than a given value.

Experience gained shows however that it is better to try to optimise the list of time instants than to rely on the subdivision of the time step, because the Ecrevisse analyses are relatively long.

.

#### 3.18.1 Operand CRITERE

Makes it possible to define the nature of the criterion used to manage the time steps in the macro-command. The possible values are:

- EXPLICITE: no subdivision whatever the value of the indicators
- TEMP: there will be subdivision according to the value of ${e}_{T}$
- PRES: there will be subdivision according to the value of ${e}_{P}$
- TEMP_PRES: there will be subdivision according to the value of ${e}_{G}$

#### 3.18.2 Operand TEMP_REF

Reference temperature for the computation of the temperature criterion of the macro-command.

#### 3.18.3 Operand PRES_REF

Reference pressure for the computation of the pressure criterion of the macro-command.

#### 3.18.4 Operand PREC_CRIT

Value with which one compares the error obtained in order to activate or not the subdivision of the time step (1 by default). For example for the temperature: ${e}_{T}<\text{PREC\_CRIT}$

#### 3.18.5 Operand NUME_ORDRE_MIN

Order number from which the error criterion is taken into account. Convergence is forced on the lower order numbers. One often uses this operand to start the activation of the error criterion from the second time step and to force convergence on the first step, which is often delicate to treat, since one imposes abrupt loadings at the initial time instant.

#### 3.18.6 Operand SUBD_NIVEAU

Number of subdivisions of the time step allowed. Beyond this value, one no longer subdivides and one leaves the macro-command.

#### 3.18.7 Operand SUBD_PAS_MINI

Time step below which one no longer subdivides.

### 3.19 Keyword CONVERGENCE_ECREVISSE

#### 3.19.1 Operand KGTEST

Parameter of the iterative algorithm of Ecrevisse.

Must lie between $0$ and $1.$ . Set by default to $0,5$ , one may be led to put a slightly lower value if difficulties of convergence on the flow rate are observed.

#### 3.19.2 Operand ITER_GLOB_MAXI

Maximum number of iterations allowed for the computation of the flow rate (400 by default).

#### 3.19.3 Operand CRIT_CONV_DEBI

Precision used for the convergence of the computation of the flow rate. It is the value against which Ecrevisse tests the max and min flow rate in its computation procedure.

$\frac{{G}_{max}-{G}_{min}}{G}⩽\text{CRIT\_CONV\_DEBI}$

By default at ${10}^{\text{-5}}$ , values up to ${10}^{\text{-2}}$ improve the computation time without losing much precision.

## 4 Operation of the coupling

### 4.1 Principle

This macro-command was developed in a precise framework: estimating the flow rates of a crack in a concrete mass modelled in 2D, possibly containing steels modelled in the form of a bar (not taken into account in the thermal analysis). Use in any other framework must therefore be made with the greatest caution. However, there are in fact 3 nested macro-commands, which may make it possible to use only part of the functionalities.

The algorithm is the following:

| Start of the macro Loop over the list of time instants MACR_ECREVISSE.py Recovery of the thermal and mechanical loading Execution of THER_LINEAIRE Projection of the thermal loading and definition of the loadings coming from Ecrevisse Execution of STAT_NON_LINE Entry into CALC_ECREVISSE.py Recovery of the crack opening (POST_RELEVE_T) Recovery of the temperature at the crack edge Entry into MACR_ECRE_CALC.py Execution of ECREVISSE Recovery of the computed flow rate and of the result tables Extraction and copying of the outgoing data (BCs, thermal, Ecrevisse result...) Evaluation of the convergence criterion (error in temperature and/or pressure) Possible subdivision of the time step or even a stop according to the conditions Recovery of the information and concepts (loading,...) |
| --- |

The detail of the intermediate macro-commands, CALC_ECREVISSE and MACR_ECRE_CALC, is given in the annex.

### 4.2 Units

One can usually do without units in *Code_Aster*  by remaining consistent. However, for the needs of Ecrevisse, it is important here to respect the international system of units (SI), in particular for the lengths ($m$ ), the pressures ($\mathit{Pa}$ ), and the temperatures ($°C$ ).

### 4.3 A few recommendations for use

The *mesh*  must be in 2 dimensions, and the crack meshed explicitly. For the analysis to be of good quality, it is necessary to optimise the mesh so that it is compatible with the phenomena which one wants to represent: the mechanical loadings, the thermal loadings but also the flow of the fluid. It is thus important to refine the mesh sufficiently at the edges of the crack if one wants to see the material heat up. At the inlet of cracks, the thermal and hydraulic phenomena are rapid, so it is necessary there too to refine the mesh sufficiently.

The *time discretisation*  is also very important and must be sufficiently fine, failing which there will be large deviations in the responses. It is better to try to optimise this list of time instants rather than to rely solely on the criteria in order to subdivide, because this strategy is much more costly in time.

For *analyses with* *condensation*  of the steam on the cracking path, the convection coefficient may increase by up to two orders of magnitude on passing to the liquid state. As the condensation takes place over a very small zone in space, the variation of the convection coefficient and therefore of the heat flux transferred to the wall may be very rapid (see the ).

This may give rise to spatial oscillations in the temperature of the mass.

![Figure](/figures/u7.03.41/10000201000005F0000003FBBFE054338AB85860.png)

Figure 4.3-1: Convection coefficients at several time instants of an analysis with condensation of the steam.

*The macro-command may be re-entrant* . The thermal and mechanical results will indeed be enriched, but on the other hand new output tables will be created for the new list of time steps.

**Note :**

| *The loadings are destroyed at each time step, as well as the material field, the possible post-processings are in fact limited (displacement, stress and internal variables at the Gauss points).* |

### 7.4 Operands specific to MACR_ECRE_CALC

#### 7.4.1 Keyword FISSURE

##### 7.4.1.1 Operand ANGLE

Angle of the flow with respect to the upward vertical (degrees).

##### 7.4.1.2 Operand LONGUEUR

Defines the actual length of the crack (taking its tortuosity into account)

##### 7.4.1.3 Operand LISTE_COTES_AH

LISTE_COTES_AH makes it possible to specify the curvilinear abscissae at which one gives the dimension of the major axis of the crack.

##### 7.4.1.4 Operand LISTE_VAL_AH

LISTE_VAL_AH makes it possible to specify the values of the major axis of the section of the crack / of the duct. According to the value of the operand SECTION:

> ELLIPSE :    List of the values of the points defining the major axis of the section;
> RECTANGLE : List of the values of the points defining the length of the section.

#### 7.4.2 Keyword TEMPERATURE

##### 7.4.2.1 Operand GRADIENT

Model of the temperature gradient:

> Supplied :        Supplied temperature distribution;
> Imposed :    Imposed temperature distribution;
> Computed :    Computed temperature profile;

##### 7.4.2.2 Operand LISTE_COTES_TEMP

List of the coordinates for the temperatures.

##### 7.4.2.3 Operand LISTE_VAL_TEMP

List of the temperature values.

##### 7.4.2.4 Operand TEMP1

Temperature gradient of the wall along the flow.

##### 7.4.2.5 Operand TEMP2

Wall temperature at the inlet.

##### 7.4.2.6 Operand EPAISSEUR_PAROI

Thickness of the wall.

##### 7.4.2.7 Operand CONVECTION_AMONT

Convection coefficient at the surface of the wall on the upstream side.

##### 7.4.2.8 Operand CONVECTION_AVAL

Convection coefficient at the surface of the wall on the downstream side.

##### 7.4.2.9 Operand LAMBDA

Thermal conduction of the wall.

##### 7.4.2.10 Operand TEMP_FLUIDE_AVAL

Temperature of the fluid on the downstream side.
