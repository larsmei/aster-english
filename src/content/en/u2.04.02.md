# u2.04.02 Advice on the implementation of non-linear analyses

> **Summary.**

The aim of this document is to give advice to a user wishing to carry out non-linear analyses with *Code_Aster*. The user of linear analyses will also find useful information and advice in it.

The following aspects will be addressed:

- mesh and modelling,
- loadings and boundary conditions,
- materials and constitutive laws,
- non-linear solution,
- memory/time management and optimisation,
- error control and quality.

This document does not deal with questions specific to dynamics.

## 1 Mesh and modelling

The choice of the finite elements has a direct influence on the solution. By choice, one means the choice of the degree of the finite-element approximation as well as the choice of a formulation. The degree of the approximation being generally linked to the degree of the mesh cells, the following paragraphs deal with the choice of the degree of the mesh and the choice of a finite-element formulation, with a particular point for incompressibility problems.

### 1.1 General points on the choice of the degree of the mesh and the choice of the finite elements

In general, the use of a linear mesh is advised in thermal analysis and the use of a quadratic mesh is advised in mechanics. The command CREA_MAILLAGE (LINE_QUAD and QUAD_LINE) makes it possible to pass from a linear mesh to a quadratic mesh and vice versa, but it does not make it possible to generate quadratic elements with curved edges. It is moreover preferable to generate the quadratic elements directly with the meshing tool (the meshing module of Salome-Meca, for example). For fracture mechanics, the use of Barsoum elements at the crack tip improves the quality of the result (command MODI_MAILLAGE / NOEUD_QUART).

The choice of the finite elements is made in the command AFFE_MODELE. In thermal analysis, it is advisable to use lumped elements (_DIAG). In mechanics, the finite elements classically used are the isoparametric elements (3D, D_PLAN, C_PLAN, AXIS). However, these elements are ill-suited to quasi-incompressible problems. The choice of a formulation answering this problem is the subject of the following paragraph.

For more details, see
[u2.01.10](doc:u2.01.10)

### 1.2 Choice of a formulation to treat quasi-incompressible problems

A problem is quasi-incompressible if the Poisson's ratio is close to 0.5 ($\nu >0,45$) or if the plastic strain rate is high. This results in an oscillation of the trace of the stresses. There are 6 formulations for treating this problem in *Code_Aster*, the choice of which depends on the type of mesh cells, on the strain model and on the quality/computation-cost ratio.

The possible formulations are:

- in small strains: _SI, _INCO_UP, _INCO_UPG, INCO_UPO
- in large strains: _INCO_UP, _INCO_UPG.

All the formulations are compatible with the modellings 3D, D_PLAN and AXIS, but in plane stresses (C_PLAN) only the under-integrated formulation (_SI) is possible.

The table below presents the compatibility between quasi-incompressible formulation and type of mesh cell (limited to the main 3D mesh cells).

|  | _SI | _INCO_UP | _INCO_UPG | _INCO_UPO |
| --- | --- | --- | --- | --- |
| HEXA20 | X | X | X |  |
| PENTA15 |  | X | X |  |
| PYRAM13 |  |  |  |  |
| TETRA10 | X | X | X |  |
| HEXA8 | X |  |  | X |
| PENTA6 |  |  |  | X |
| PYRAM5 |  |  |  | X |
| TETRA4 |  | X |  | X |

In the general case, it is therefore necessary to mix different formulations in order to cover all the types of mesh cell (for example, as no formulation handles the PYRAM13 mesh cells, an isoparametric modelling must also be assigned).

In the case where one remains in small strains, it is advisable to use a mixture of formulations (the mesh being able to contain several types of mesh cell):

|  | quality | cost |
| --- | --- | --- |
| MODELISATION=('3D', '3D_INCO_UPG', '3D_INCO_UPO') | +++ | +++ |
| MODELISATION=('3D', '3D_INCO_UP' , '3D_INCO_UPO') | ++ | ++ |
| MODELISATION=('3D', '3D_SI' , '3D_INCO_UPO') |  |  |

For more details, see
[u2.01.10](doc:u2.01.10)

## 2 Loadings, boundary conditions, initial conditions

### 2.1 Core of the problem

The loadings and boundary conditions are important for a good modelling. Their influence on the results is most of the time direct, so that their application can be checked by a simple preliminary analysis, for example by means of MECA_STATIQUE, or by visualising the boundary conditions *via* the keyword CONCEPT of IMPR_RESU in MED format.

As regards the boundary conditions, it is often a matter of introducing the minimum of them in order to block the rigid-body displacements, and thus to avoid having floating bodies in the structure, which would cause a zero pivot or a singular matrix during the solution.

Certain boundary conditions are non-linear, for example unilateral contact. Their verification therefore cannot be done by means of a first linear analysis (MECA_STATIQUE): the various objects in contact must not have a rigid-body motion
[u2.04.04](doc:u2.04.04). If this is the case, zero pivots can be avoided by adding discrete elements (springs) of low stiffness.

The loadings (other than the blockings) may consist either of imposed-displacement conditions, or of imposed forces, or of an imposed initial-field type.

In every case, it is important to represent reality well. The conditions of symmetry or of antisymmetry may usefully be used [1].

In general, a condition of imposed-displacement type does not give the same results as a condition of imposed-force type: an imposed displacement on a part of the boundary imposes that the (imposed) displacement be constant in space on that part, and therefore brings stiffness, or even singularities. Take the example of the punch indentation of a solid mass: the imposed displacement on the edge of the punch induces stress singularities of the same nature as those encountered at the tip of a crack.

Take for example the punch indentation (see and ): the response in terms of the resultant force on the punch as a function of the displacement shows that the closer the imposed force gets to the limit load, the more difficult the convergence will be, until it becomes impossible beyond the limit load. If the correct modelling requires an imposed force to be applied, the problem can be solved *via* the piloting of the imposed force with respect to the displacement of a point or of a set of points (continuation method or arc-length method) (see
[r5.03.80](doc:r5.03.80)

### 2.2 Precautions for the application of the loadings

It is useful, for the application of the loadings, to go through the various keywords of
[u4.44.01](doc:u4.44.01)
[u4.44.01](doc:u4.44.01). Beware of the vocabulary: in particular, the loadings of type FORCE_FACE, PRES_REP, FORCE_CONTOUR, FORCE_ARETE, FORCE_INTERNE, FORCE_COQUE, FORCE_TUYAU correspond to distributed forces (line, surface, volume) and **are expressed in units of stress** (for example $\mathit{Pa}$ in SI units). Only the FORCE_NODALE are expressed in units of force ($N$), and the distributed forces of beams (FORCE_POUTRE) in units of force divided by a length.

As regards the pressures (PRES_REP, FORCE_COQUE/PRES), the pressure applied is positive in the direction opposite to the normal to the element. It is strongly advisable to reorient these normals *via* the operator MODI_MAILLAGE, keywords ORIE_PEAU_*, ORIE_NORM_COQUE.

For 2D and 3D continuous media, the use of point forces (FORCE_NODALE) is to be avoided, because it always leads to singularities.

The application of loads which are a function of time can be carried out in two ways:

- either by defining constant loads, then by applying a multiplying coefficient which is a function of time to these loads during the solution (keyword FONC_MULT under EXCIT in STAT_NON_LINE),
- or by defining directly loads which are a function of time via AFFE_CHAR_MECA_F.

In the case where the loadings are of imposed-displacement type, they can be introduced either by AFFE_CHAR_MECA(_F), or by AFFE_CHAR_CINE(_F). The use of this latter command allows a saving in computation time which can be appreciable in non-linear analysis (because it does not add Lagrange multipliers, so there are fewer equations to solve).

The command variables are not part of the commands AFFE_CHAR_MECA(_F). They are nevertheless, in many modellings, comparable to loadings: for example thermal expansion can by itself generate states of stress and of strain leading to non-linearities of the constitutive behaviour. The command variables are applied via AFFE_MATERIAU.

A modelling precaution concerning these command variables must however be pointed out here: indeed, as soon as the analysis is incremental, STAT_NON_LINE uses at each time step the increment of the command variable in order to compute the corresponding strains (cf. for example
[r5.03.02](doc:r5.03.02)). In general, it is preferable that at the initial time instant the structure be unstressed and unstrained. If this is not the case, a preliminary time instant must be added at which the structure is at rest; see for example the test FORMA30
[v7.20.101](doc:v7.20.101). If stresses due to the command variables are detected at the initial time instant, the following alarm is obtained:

<A> <MECANONLINE2_97>:

-> The initial command variables induce incompatible stresses:

the initial state (before the first computation time instant) is such that the command variables (temperature, hydration, drying...) lead to unbalanced stresses.

-> Risk & Advice: in the case of an incremental solution, only the variation of the command variables between the previous time instant and the current time instant is considered. Possible incompatible stresses due to these initial command variables are therefore not taken into account.

To take these stresses into account you can:

- start from an earlier fictitious time instant at which all the command variables are zero or equal to the reference values
- choose suitable reference values

For more information, see the documentation of STAT_NON_LINE (U4.51.03) keyword EXCIT, and the test FORMA30 (V7.20.101).

### 2.3 The various types of boundary condition

The simplest boundary conditions serve mainly to introduce symmetry conditions, on the one hand, and to prevent rigid-body motions, on the other. When they are of imposed degree-of-freedom type, one can use either AFFE_CHAR_MECA or (in order to optimise the computation time) AFFE_CHAR_CINE
[u2.01.02](doc:u2.01.02).

A methodological piece of advice: it is always preferable to apply the boundary conditions on mesh-cell groups rather than on node groups or on lists of nodes or of mesh cells. Indeed, the mesh-cell groups correspond to geometric zones, and are preserved during a refinement of the mesh (manual or by means of Homard), whereas the node groups are modified. This is why in AFFE_CHAR_MECA the keywords DDL_IMPO, FACE_IMPO, LIAISON_UNIF, as well as all the keywords of AFFE_CHAR_CINE, include the keyword GROUP_MA, which is therefore to be preferred.

It is sometimes necessary to impose linear relations between degrees of freedom. The keywords LIAISON_* of AFFE_CHAR_MECA make it possible to introduce this type of relation. The elementary relations can be defined by means of LIAISON_DDL, but this becomes tedious if the equations to be written are numerous. Higher-level features are available, for example:

- LIAISON_SOLIDE to rigidify a part of the structure, (in small strains and small displacements only)
[r3.03.02](doc:r3.03.02);
- LIAISON_UNIF to ensure that a part of the boundary will keep the same displacement (unknown a priori);
[u4.44.01](doc:u4.44.01)
[u4.44.01](doc:u4.44.01)
- LIAISON_MAIL, LIAISON_GROUP to connect two edges,
- and other keywords specific to AFFE_CHAR_MECA.

In addition it is possible to connect (in the energy sense) modellings of different natures, via LIAISON_ELEM and several options (in small strains and small displacements only)

- '2D_POU','3D_POU', beams or discrete elements with 2D or 3D elements
[r3.03.03](doc:r3.03.03);
- 'COQ_TUYAU','3D_TUYAU', pipe elements with plates and shells, 3D;
- 'COQ_POU', beams or discrete elements with plates and shells
[r3.03.06](doc:r3.03.06).

**Note**: in certain cases, the boundary conditions or the loadings of imposed-displacement type are not suitable because they bring too much local stiffness. It may be of interest to replace these conditions by a relation between the part of the boundary concerned and a discrete element, on which the imposed-displacement conditions or a resultant wrench of imposed forces will be applied. This means that the displacements of the boundary will be equal on average to the displacement of the discrete element, without introducing parasitic stresses. On the other hand, this procedure introduces additional degrees of freedom (Lagrange multipliers), so the solution of the linear systems can be more costly.

Unilateral contact, with or without friction, is a particular type of boundary condition. It is strongly non-linear, and its treatment in STAT_NON_LINE / DYNA_NON_LINE requires additional iterations in order to obtain convergence. It is strongly advisable to consult the document
[u2.04.04](doc:u2.04.04)
[u2.04.04](doc:u2.04.04)
[u2.04.04](doc:u2.04.04) in order to model these phenomena correctly.

### 2.4 The initial conditions

In AFFE_CHAR_MECA, it is possible to define loadings of mean strains or of mean stresses, globally uniform (keywords PRE_EPSI, PRE_SIGM).

These loadings must not be confused with the initial strains and stresses used in non-linear analysis, because these quantities do not intervene directly in the expression of the constitutive law, but only on the right-hand side.

The initial fields of stresses, displacements and internal variables are to be supplied directly in STAT_NON_LINE (keyword ETAT_INIT). In order to build these fields, it may be useful to consult the document
[u2.01.09](doc:u2.01.09).

The choice of the constitutive law depends of course on the material being modelled, but also on the phenomena to be treated: for example, one and the same steel will be elastoplastic at low temperature, and viscoplastic at high temperature. The values of the parameters of these laws (in DEFI_MATERIAU) are often identified over a range of strain, of rate and of temperature which is quite specific.

#### 3.2.2 ALGO_INTE, ITER_INTE_MAXI, RESI_INTE_RELA, ITER_INTE_PAS

Makes it possible to specify the type of integration scheme used to solve the non-linear equation or system of equations formed by the constitutive equations of the constitutive models with internal variables. A default solution method is provided for each constitutive behaviour. However, it is possible to modify the default solution method for a certain number of constitutive behaviours (see
[u4.51.11](doc:u4.51.11)).

In the case of an iterative solution (that is if ALGO_INTE is not ANALYTIQUE), the keywords ITER_INTE_MAXI and RESI_INTE_RELA define the maximum number of iterations and the relative residual for integrating the constitutive behaviour. If this integration fails, it is possible to subdivide the time step, either locally (keyword ITER_INTE_PAS) or globally (command DEFI_LIST_INST). The default value of ITER_INTE_MAXI is 20. This may be insufficient for certain constitutive behaviours (MONOCRISTAL, for example). Do not hesitate in this case to increase this parameter (100, for example). On the other hand it is strongly inadvisable to increase RESI_INTE_RELA (${10}^{-6}$ by default), otherwise unconverged solutions will be obtained.

Local subdivision of the time step is a means of improving the robustness of the local integration; on the other hand it does not make it possible to supply a consistent tangent matrix (loss of the quadratic convergence of the global problem).

#### 3.2.3 POST_ITER='CRIT_RUPT'

Definition of a failure criterion in critical stress, in post-processing of the Newton iterations, at each time step. If the largest mean principal stress in an element exceeds a given threshold ${\sigma}_{c}$, Young's modulus is divided at the following time step by a coefficient. These two coefficients are defined under the keyword CRIT_RUPT of the operator DEFI_MATERIAU.

#### 3.2.4 RESI_RADI_RELA

Measure of the error due to the discretisation in time, linked directly to the rotation of the normal to the yield surface. The angle between the normal to the plasticity criterion at the beginning of the time step and the normal to the plasticity criterion computed at the end of the time step is calculated. The time step is cut (*via* DEFI_LIST_INST) if the error is greater than the tolerance defined by the user.

This criterion is operational for the elastoplastic Von Mises constitutive behaviours with isotropic, linear kinematic and mixed hardening, and for the elasto-visco-plastic Chaboche constitutive behaviours.

## 4 Non-linear solution

The 3 main types of non-linearity in *Code_Aster* are the following:

- non-linearity linked to the constitutive behaviour of the material (for example plastic);
- non-linearity linked to the geometry (for example in large displacements);
- non-linearity linked to frictional contact.

The general advice on the solution of non-linear problems is the subject of a specific document, the reading of which is strongly recommended:
[u2.04.01](doc:u2.04.01)
[u2.04.01](doc:u2.04.01)
[u2.04.01](doc:u2.04.01).

Before any non-linear analysis, it is essential to make sure that the analysis works correctly in linear elasticity. The non-linearities can then be added one after another.

The major advice on the time discretisation and the numerical parameters of the non-linear solution is recalled briefly in the following paragraphs.

### 4.1 Non-linearity and time discretisation

The solution of a non-linear problem generally requires the external loading to be applied progressively, by load increment. Thus time (or pseudo-time in quasi-statics) is discretised into time steps and to each time step there corresponds a load increment (see § 2.2). The smaller the time step, the less non-linear the problem and therefore the easier it is to solve. In order to allow the subdivision of the time step in the event of a failure of convergence, it is essential to use the command DEFI_LIST_INST (for more details on the management of the list of time instants, see paragraph §3.1 of the document
[u2.04.01](doc:u2.04.01))

In order to check the consistency of the data (system of units, boundary conditions, elementary characteristics, effect of the command variables), it is always useful to carry out a first linear elastic analysis (STAT_NON_LINE/RELATION='ELAS', or MECA_STATIQUE), before any non-linear study, and then to add the non-linearities one after another.

### 4.2 Numerical parameters for the non-linear solution algorithm

By default, the non-linear solution algorithm is based on the Newton–Raphson method (STAT_NON_LINE / METHODE='NEWTON').

It is advisable to use a tangent matrix updated at each Newton iteration: REAC_ITER=1, in order to facilitate the convergence of the algorithm (see paragraph §2.2 of the document
[u2.04.01](doc:u2.04.01)).

It is strongly recommended not to relax the convergence criterion of Newton's method (RESI_GLOB_RELA=$10^{-6}$ by default). Other convergence criteria are also available (see paragraph §3.3 of the document
[u2.04.01](doc:u2.04.01)).

Notes:

- For softening problems, *Code_Aster* offers the possibility of using a method alternative to the Newton–Raphson method: this is the IMPLEX method, which is a robust but approximate method (see paragraph §4.5 of the document
[u2.04.01](doc:u2.04.01)).
- For an optimisation of the computation time, *Code_Aster* offers the possibility of using an inexact Newton method (provided that the linear solver chosen is an iterative solver): this is the NEWTON_KRYLOV method.

## 5 Memory/time management and optimisation

Before speaking of optimisation, the first question which arises is how to choose the execution parameters in Astk: total memory and time, so that the first launching of the run finishes correctly. Then, once the run has gone through a first time, it will always be possible to try to optimise it according to the information recovered from the 1st run.

### 5.1 First execution of a run

Knowledge of the size of the memory available is necessary. The answer depends of course on the execution machine: centralised server, local machine.... On a local machine, it is always possible to allow the maximum memory available, whereas on the centralised server it may be opportune not to request too much memory, otherwise one has to wait for the associated job class to become free.

**Estimate of the memory required**: in quasi-statics, the total memory is generally a function of the size of the linear system or systems to be solved. For the isoparametric finite elements, it is fairly easy to estimate the global size of these systems. The number of degrees of freedom can be estimated by the relation: (number of nodes of the mesh) x (dimension of the problem (2 or 3))

This relation does not take into account the degrees of freedom relating to the dualised boundary conditions. But in general this share is small. If the finite elements are not isoparametric (mixed formulations, for example), this estimate is more delicate.

In any event, the size of the linear systems is displayed at each solution in the .mess file: total number of equations, or the matrix is of size n equations. It is **important to know this number** (although on its own it is not always a totally reliable indicator, because the memory and the time required to solve a linear system depend on many other parameters: bandwidth, number of non-zero terms in the matrix, renumberer... but that would take us too far). Therefore, if one does not know how to estimate the size of the linear system, it is useful to **launch the study a first time in degraded mode**: reading of the mesh, assignment of the finite elements, of the material, and solution (MECA_STATIQUE or STAT_NON_LINE) with the direct solver MUMPS. Launch the simplified study in interactive mode with interactive monitoring, then stop the run once the information on the size of the system is known.

In the ideal case 1, one must have about 30 GB available in order to get through a run with one million degrees of freedom (the case of the cube meshed with HEXA8, one face of which is clamped by dualisation), the minimum memory 2 being 9 GB. The table below gives orders of magnitude of the “ideal” (or optimal) memory and of the minimum memory for solving a system of a given size (with the direct solver MUMPS).

| Number of degrees of freedom | Minimum memory | “Ideal” memory |
| --- | --- | --- |
| 200000 | 1 GB | 4 GB |
| 400000 | 2.5 GB | 9 GB |
| 600000 | 4 GB | 15 GB |
| 800000 | 6 GB | 23 GB |
| 1000000 | 9 GB | 31 GB |

Once the memory required has been estimated, the complete run can be launched with the direct solver MUMPS. Following this 1st run, it is very useful to look at:

- In the .mess file, the total memory (JEVEUX + python + external libraries) used by the run: this information is displayed at the end of the file: see MAXIMUM DE MEMOIRE UTILISEE PAR LE PROCESSUS;
- In the .resu file: the solution time (MECA_STATIQUE / STAT_NON_LINE) relative to the total time of the run.

### 5.2 Optimisation of a run

The optimisation of a run on the aspects of time and memory is an interesting operation but a somewhat delicate one, because there is no miracle recipe. Moreover it is not always easy to distinguish between optimisation of the memory and optimisation of the computation time, so in the following paragraphs some lines of optimisation are given “in the broad sense” and the reader is referred to the appropriate documents.

**Parallelism**

The use of parallelism is certainly the easiest and safest solution for reducing the computation time (and sometimes also the memory required). Parallelism consists in executing operations on several processors at the same time. Setting up parallelism is effective only if the time spent in STAT_NON_LINE is predominant with respect to the total time of the run. For this, it is sufficient to choose a suitable solver (example: MUMPS, PETSC), an MPI version of *Code_Aster* and to specify the number of processors in Astk (Options/mpi_nbcpu menu). On the centralised server aster4, it is advisable to begin by choosing mpi_nbcpu=2, to observe the gain in time, then to start again with mpi_nbcpu=4, then possibly mpi_nbcpu=8. It is possible to choose mpi_nbcpu=16, but one risks waiting a long time before all these processors are available, and therefore before the run starts (it all depends on the machine load!).

A great deal of advice on parallelism is given in the document
[u2.08.06](doc:u2.08.06). Finer information on the times spent in each part of the solution is also displayed, and can serve to parameterise the run better (time, memory, number of processors...). For this, the reader is referred to the documentation
[u1.03.03](doc:u1.03.03).

**The linear solver**

Depending on the size of the matrix, the use of an iterative solver (such as PETSC) in place of a direct solver will allow a gain in time. For information, an iterative solver is considered to be faster than a direct solver (the default) from about 200000 equations in 3D. But this depends on the type of structure 3. The counterpart of the use of an iterative solver is that robustness is not guaranteed. It should be noted that the use of PETSC requires an MPI version of *Code_Aster* (even if only one processor is used). From a certain problem size (a few million degrees of freedom), the use of a direct solver becomes impossible and it is essential to use an iterative solver.

In the event of failure of the solution by an iterative solver, the levers for action are the choice of another preconditioner (simple-precision direct preconditioner LDLT_SP by default, incomplete preconditioner LDLT_INC, …), and the choice of another iterative algorithm (GMRES by default, CG, CR, …).

A great deal of advice on the choice of the solver is given in
[u2.08.03](doc:u2.08.03).

**Management of the global database**

In the event of the memory limit being exceeded, one can act on the archiving of the results. Archiving (factor keyword ARCHIVAGE of STAT_NON_LINE) makes it possible to reduce appreciably the size of the databases by selecting the time instants saved. By default, everything is archived (even the time instants coming from the subdivision of the time step). During the phase of setting up a study, this can prove useful, but too costly in memory. The observation and the monitoring of certain quantities can answer the archiving need in an effective manner (see §3.4 of
[u2.04.01](doc:u2.04.01)). Once the study has been set up, archiving can be restricted to a limited number of time steps (post-processing time instants, for example).

In order to reduce the bulk of the resultat data structure, it is possible to choose *a posteriori* the fields to be archived, either by indicating the fields to be kept, or by indicating the fields to be excluded (command EXTR_RESU). The extraction can also be done on a part of the mesh or of the model. The command DETRUIRE can also be used to destroy a concept. Following these extraction or deletion operations, RETASSAGE='OUI' must be specified in the command FIN in order actually to recover the disk space associated with the global database.

To reduce the size of the result files in MED format (.rmed): use IMPR_RESU/RESTREINT.

With a view to a restart, one can in certain cases replace the database by the printout of MED fields. The “restart” will then begin with the commands DEBUT then LIRE_RESU.

A cube penalises the direct solver, whereas a thin or slender structure gives an advantage to the direct solver

## 6 Quality control

In general, the overall quality of a study depends on several factors. Among the causes which can impair the quality of a study, one can distinguish in particular:

- the uncertainties on the data,
- the modelling choices (passage from the physics to the numerical model),
- the discretisation errors, once the data have been established and the modelling chosen.

### 6.1 Uncertainties on the data

On this point the uncertainties can be multiple, because they can concern each of the following aspects.

- The material data: once the constitutive law has been chosen, and its parameters correctly identified on appropriate characterisation tests, an uncertainty may remain on the values of the parameters of this law, due to the variability of the materials.
- The exact geometry of the structure to be modelled may contain uncertainties: the real dimensions are not those planned at the design stage, or else the degradation of the shape of a part leads to a poorly controlled geometry (quite apart from any aspect of discretisation).
- The loadings (including thermal ones, or those due to other command variables: irradiation, hydration, drying, etc.) and the boundary conditions may present numerous uncertainties.
- The initial conditions, in particular those due to manufacture (residual stresses, initial hardening).

For each of the uncertain parameters mentioned above, it will sometimes be necessary to carry out a sensitivity analysis:

- either the user carries out a few simulations for extreme values of the uncertain parameters, which is sufficient in the case of a monotonic variation of the result with these parameters (but this is not always the case: for example the dependence of the stresses on the extreme values of temperature, with material coefficients which are a function of them, is not trivial.)

**Let us point out in this connection the possibility of carrying out parametric analyses very simply with *Code_Aster* (cf.**

[u2.08.07](doc:u2.08.07))

- or, in the case of highly variable parameters, the user carries out a mechanical reliability analysis, with OpenTurns (
[http://www.openturns.org](http://www.openturns.org/)) coupled to *Code_Aster*, in the Salome-Meca platform
sv1.04.01).

### 6.2 Modelling choices and verification of the data

Even if the data are reliable, the quality of the results also depends on choices made by the user relating to the simulation to be carried out. The preceding paragraphs describe these choices. Let us recall a few general pieces of advice:

- Beyond the mesh, it may be useful to check the data of the analysis, for example to visualise the boundary conditions and loadings (sense and place of application), the assignments of the materials, and the elementary characteristics (orientation of the beams, thicknesses, sections). For this, use IMPR_RESU/CONCEPT.
- Other checks can be carried out directly in the command file; for example, to check the consistency of the system of units, the boundary conditions and the elementary characteristics, it is always useful to carry out a first elastic analysis, before any non-linear study.
- In order to check the material data, it may be useful to carry out, with the *Code_Aster* data setup, a test simpler than the study, for example on a material point (SIMU_POINT_MAT). Does one recover the tension–compression curve?
- The computation of the mass (or of the volume) of the structure is also among the checks which are simple but sometimes useful.

### 6.3 Controlling the errors due to the spatial discretisation

On this point, a few general remarks are recalled here, but reading
[u2.08.01](doc:u2.08.01) is more than advisable.

Independently of any wish to carry out mesh adaptation, it is advisable to check the initial mesh with the command MACR_INFO_MAIL
[u7.03.02](doc:u7.03.02)
[u7.03.02](doc:u7.03.02). This command makes it possible to carry out, at low cost, the following checks:

- check the agreement of the mesh with the initial geometry (in dimension, in volume);
- list the GROUP_MA and GROUP_NO, for a good modelling of the boundary conditions;
- diagnose possible problems (connectivity, holes, interpenetration of mesh cells);
- supply quality criteria for the mesh cells (evaluated mesh cell by mesh cell).

In order to control more easily the effect of the quality of the mesh, an automatic mesh-adaptation strategy is operational: it relies on the mesh-adaptation software Homard, which can be called directly from the *Code_Aster* command file or in the Salome-Meca platform, and uses either error indicators making it possible to drive the adaptation, or the values of a field, or the jump of a field from one element to another. Several motivations appear for adapting a mesh:

- The mesh is very complicated to produce: one starts from a simple version and entrusts to an automatic process the task of refining it.
- One wants to make sure of the convergence of the numerical solution: rather than producing by hand meshes which are finer and finer, one lets the software itself look for the places where the mesh ought to be refined in order to increase the accuracy of the result.
- The conditions of the analysis change in the course of its progress: the zones which must be meshed finely move. If one meshes finely everywhere from the start, the mesh is too large. By adapting as one goes along (refinement – coarsening), the mesh will be fine only at the places where this is necessary: its size will be reduced and the quality of the solution will be good.

The zones to be refined can be located:

- Either with an error indicator. Note that the simplest ones (ZZ1, of Zhu-Zienkiewicz type) are very robust, available in 2D and 3D, and even if they do not supply the best upper bounds of the error, their variations are sufficient to drive the adaptation. The estimators in quantity of interest are more relevant for supplying a bound on the error committed.
- Or with a relevant field (strain, internal variable). Caution: in plasticity, the Von Mises stress is not always one. One can use:
- either the extreme values of this field (for example asking to refine the 5% of elements which have the highest value),
- or drive the adaptation by the jump of the values of this field at the boundary between two finite elements.
- Or by boxes (uniform refinement in geometric zones).

For more information, see
[u2.08.01](doc:u2.08.01)

### 6.4 Time-discretisation errors

For most of the non-linearities (constitutive behaviour, contact, large strains) the time discretisation influences the result. Convergence results exist (fortunately) in all the classical cases (elasto-visco-plasticity, contact), but it nevertheless remains to make sure that, for a chosen time step, the solution is sufficiently close to the solution which is continuous in time.

The simplest solution is similar to uniform refinement for mesh adaptation: it consists in refining the time step uniformly over the whole transient and re-launching STAT_NON_LINE. This can be automated thanks to a feature of DEFI_LIST_INST (see
u2.04.01 and
:ref:`u4.34.03).

Another criterion for controlling the time step is subdivision as a function of a quantity of interest: DEFI_LIST_INST / DELTA_GRANDEUR indeed makes it possible to re-cut the time step if the maximum variation of a given quantity (for example a plastic-strain component) is greater than a threshold supplied.

In addition, for the elastoplastic constitutive behaviours, it is possible to estimate directly the error due to the discretisation in time, in a manner analogous to RESI_RADI_RELA (cf. 3.2.4). If this criterion was not taken into account during the analysis, it is possible to compute it in post-processing, in CALC_CHAMP: the component ERR_RADI of the option DERA_ELGA contains the error estimate at each time instant and at each integration point.
