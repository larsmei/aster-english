# u4.31.02 Operator DEFI_FONCTION

## 1 Purpose

Define a real or complex function of a real variable. This operator makes it possible to define, for example, material characteristics as a function of temperature, or boundary conditions which depend on a space variable or on time.

The concept produced by this operator is of type fonction.

## 3 Operands

### 3.1 Operand NOM_PARA

```text
♦    NOM_PARA = np
```
Designates the name of the parameter (variable or abscissa) of the function.

The possible values for np are:

| ’ABSC’: | Curvilinear abscissa |
| --- | --- |
| ’AMOR’: | Damping |
| ’DRX’: | Rotation about the x-axis |
| ’DRY’: | Rotation about the y-axis |
| ’DRZ’: | Rotation about the z-axis |
| ’DSP’: |  |
| ’DX’: | Displacement along the x-axis |
| ’DY’: | Displacement along the x-axis |
| ’DZ’: | Displacement along the x-axis |
| ’ENDO’: | Damage |
| ’EPAIS’: | Thickness |
| ’EPSI’: | Strain |
| ’FREQ’: | Frequency |
| ’HYDR’: | Hydration |
| ’INST’: | Time instant |
| ’META’: |  |
| ’NEUT1’: | Neutral parameter 1 |
| ’NEUT2’: | Neutral parameter 2 |
| ’NEUT3’: | Neutral parameter 3 |
| ’NORM’: |  |
| ’NUME_ORDRE’: | Order number |
| ’PAD’: |  |
| ’PCAP’: | Capillary pressure |
| ’PGAZ’: | Gas pressure |
| ’PLIQ’: | Liquid pressure |
| ’PORO’: | Porosity |
| ’PULS’: | Pulsation |
| ’PVAP’: | Vapour pressure |
| ’SAT’: | Saturation |
| ’SECH’: | Drying |
| ’SIGM’: | Stress |
| ’TEMP’: | Temperature |
| ’TSEC’: |  |
| ’VITE’: | Velocity |
| ’X’: | x-coordinate |
| ’Y’: | y-coordinate |
| ’Z’: | z-coordinate |
| ’XF’: | Final x-coordinate, in the case of a follower loading. |
| ’YF’: | Final y-coordinate, in the case of a follower loading. |
| ’ZF’: | Final z-coordinate, in the case of a follower loading. |
| VITE_[X\|Y\|Z] | Velocity of the structure, in the case of a follower loading. |
| ACCE_[X\|Y\|Z] | Acceleration of the structure, in the case of a follower loading. |

### 3.2 Operand NOM_RESU

```text
◊    NOM_RESU = nr
```
Designates the name of the result (8 characters). The function thus created is nr = f(np).

**Note:**

*Some commands (CALC_FONCTION,* *DEFI_MATERIAU…) check the consistency of the names of the parameter and of the result according to their context. For example, one expects a tension curve defined by a function for which* *NOM_PARA=’EPSI’ and* *NOM_RESU=’SIGM’.*

### 3.3 Operand VALE

```text
/    VALE = lv
```
lv is the list of values (x1, y1, …, xn, yn) with, in order:

- x1, y1 (the first value of the parameter and the corresponding value of the result),
- ... ,
- xn, yn (the last value of the parameter and the corresponding value of the result).

**Note:**

*The list* *lv of values must be described in the order of increasing abscissae (x).*

### 3.4 Operand VALE_C

```text
/    VALE_C = lv
```
lv is the list of values (x, y, z, …, xn, yn, zn) with:

- xi values of the parameter
- ... ,
- yi, zi the real part and the imaginary part of the complex function for this parameter.

### 3.5 Operands ABSCISSE / ORDONNEE

```text
/    ABSCISSE = labs

/    ORDONNEE = lord
```
The values of the abscissae and of the ordinates of the function are supplied separately in the form of lists of real values (x1, x2, …, xn) for ABSCISSE and (y1, y2, …, yn) for ORDONNEE. The two lists must have the same cardinality.

### 3.6 Operand VALE_PARA / VALE_FONC

```text
/    VALE_PARA = la

/    VALE_FONC = lo     nom [:ref:`ref 1 <ref 1>`]
```
Same operation as ABSCISSE, ORDONNEE except that the lists are supplied in the form of a listr8 concept produced by DEFI_LIST_REEL [U4.34.01](doc:u4.34.01).

VALE_PARA and VALE_FONC must have identical cardinalities, otherwise the command stops in error.

### 3.7 Operand NOEUD_PARA

```text
/    NOEUD_PARA = lno
```
lno list of nodes making it possible to define the values of the abscissae of the function to be defined.

The abscissae will be equal to the curvilinear abscissae of the nodes on the curve which they define.

### 3.8 Operands PROL_DROITE and PROL_GAUCHE

```text
◊    PROL_DROITE et PROL_GAUCHE =
```
Define the type of extension to the right (to the left) of the domain of definition of the variable:

| ’CONSTANT’ | for an extension with the last (or first) value of the function, |
| --- | --- |
| ’LINEAIRE’ | for an extension along the first segment defined (PROL_GAUCHE) or the last segment defined (PROL_DROITE), |
| ’EXCLU’ | if the extrapolation of the values outside the domain of definition of the parameter is forbidden (in this case if an analysis requests a value of the function outside the domain of definition, the code will stop in fatal error). |

For example:

- PROL_DROITE = ’CONSTANT’ , PROL_GAUCHE = ’CONSTANT’

![Figure](/figures/u4.31.02/1000100A000015B400000E29AB3CD3C92C3049F5.svg)

- PROL_DROITE = ’LINEAIRE’, PROL_GAUCHE = ’EXCLU’

![Figure](/figures/u4.31.02/100010000000163900000DBFF8606CBAD8F58F83.svg)

**Note:**

The type of extension and of interpolation are independent of one another.

### 3.9 Operand INTERPOL

```text
◊    INTERPOL=
```
Type of interpolation of the function between the values of the domain of definition of the function: one type for the interpolation of the parameter and one for the interpolation of the function. This is obtained by supplying a list of texts among:

```text
INTERPOL = (’LIN’, ’LOG’)
```
| ’LIN’: | linear, |
| --- | --- |
| ’LOG’: | logarithmic, |

**Note:**

*If only one value is specified, it is taken into account both for the interpolation of the parameter and for that of the function.* *INTERPOL = ’LOG’ is equivalent to (’LOG’, ’LOG’).*

### 3.10 Operand INFO

```text
◊    INFO= Précise les options d’impression sur le fichier MESSAGE.
```
| 1: | no printout (default option) |
| --- | --- |
| 2: | printout of the parameters plus the list of the first 10 values in increasing order of the parameter |

### 3.11 Operand VERIF

```text
◊    VERIF=
```
The operator DEFI_Fonction checks that the values of the abscissae are strictly increasing. If this is not the case, an error is triggered. This is the default behaviour, VERIF is equal to ’Croissant’.

The user has the possibility of not carrying out this check by indicating VERIF=’NON’. In this case, the function is reordered by increasing abscissae. An alarm is emitted if the abscissae of the function were not increasing.

On the other hand, the abscissae must imperatively be strictly monotonic.

### 3.12 Operand TITRE

```text
◊    TITRE = ti
```
Title attached to the concept produced by this operator [U4.03.01](doc:u4.03.01).

### 3.13 Operands MAILLAGE and VALE_Y

These two keywords must be supplied if one defines the function from NOEUD_PARA.

```text
MAILLAGE = ma
```
Name of the mesh associated with the node list lno.

VALE_Y = lv

List of the values of the ordinates of the function to be defined.

## 4 Definition of a function depending on time

### 4.1 The function and the variables are entered in the form of reals

Definition of a function (piecewise linear) which depends on time (parameter INST).

![Figure](/figures/u4.31.02/10001842000069D5000022BA2F3F22B1D165723A.svg)

### 4.2 The function and the variables are entered in the form of listr8 concepts

It is possible to define this function by means of concepts of type listr8 created through the operator DEFI_LIST_REEL [U4.34.01](doc:u4.34.01):

```text
ABSCISSE = DEFI_LIST_REEL    (    DEBUT = 0. ,
INTERVALLE = ( _F ( JUSQU_A = 1., NOMBRE = 1,),
_F ( JUSQU_A = 3., NOMBRE = 1,),
_F ( JUSQU_A = 6., NOMBRE = 1,),)
)

ORDONNEE = DEFI_LIST_REEL    (    DEBUT = -1. ,
INTERVALLE =     ( _F (JUSQU_A = 0., NOMBRE = 1,),
_F (JUSQU_A = 1., NOMBRE = 1,),
_F (JUSQU_A = 2., NOMBRE = 1,),)
)

EX_2 = DEFI_FONCTION    (    NOM_PARA = ’INST’,
VALE_PARA = ABSCISSE,
VALE_FONC = ORDONNEE,
PROL_DROITE = ’CONSTANT’,
PROL_GAUCHE = ’LINEAIRE’,
)
```
**Note:**

*This example is obviously very complicated for defining the function proposed.*

*We only wished to highlight the principle of use of the possibility offered.*

*This becomes interesting when one uses functions defined at a large number of points.*

*Another reason for using the definition by* *DEFI_LIST_REEL is when the lists are necessary as an argument for another operator: (list of the time instants of a transient analysis* *THER_LINEAIRE,* *DYNA_VIBRA,* *…); this then avoids the duplication of information.*
