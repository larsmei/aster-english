# u3.04.01 Interface of the GIBI mesh file with Code_Aster

**Summary:**

The use of GIBI (mesher of CASTEM 2000) can be done on a Unix/Linux workstation, according to the versions available.

The principle of the interface which makes it possible to use in *Code_Aster* a file coming from CASTEM 2000 is described here.

This interface is implemented in *Aster* by the command PRE_GIBI [U7.01.11](doc:u7.01.11).

## 1 Use of GIBI

CASTEM 2000 is a structural analysis code based on finite elements, which has a set of functionalities dedicated to meshing in 2D and 3D. The whole of these meshing functions is known under the name GIBI.

In the remainder of this document, the name GIBI will denote the set of meshing functions as well as the set of commands for the visualisation and the exploitation of the results.

GIBI is available on a certain number of Unix/Linux platforms. It is a version distributed by EDF R&D/AMA within the framework of a contract with the CEA; it is available for download on the site
[https://www.code-aster.org](https://www.code-aster.org/).

The memory allocated by GIBI is 20 mega-words by default. For certain applications it is necessary to increase this memory size. In order to do this, the variable ESOPE_PARAM must be defined in the following way:

setenv ESOPE_PARAM 'ESOPE=x000000,NTRK=1024,LTRK=1048576'

or according to the shell used:

export ESOPE_PARAM='ESOPE=x000000,NTRK=1024,LTRK=1048576'

where x is the number of millions of words that one wishes.

The CEA produces a new version of GIBI every year. Before being put into service on the centralised server and being distributed, this version is tested by the code team on the whole set of the Aster tests. Thus the "standard" version is currently GIBI version 2000, launched interactively by the command gibi2000.x.

## 2 Documentation on the use of GIBI

The documentation of GIBI can be obtained by executing GIBI with the following data file:

```text
NOTICE ;

FIN ;
```

One then recovers, in the job listing, the list of the chapters corresponding to all the operators of GIBI.

GIBI has on-line documentation which makes it possible to obtain the syntax of each operator by the command:

INFO name of the command ;

but also the possibility of knowing the whole set of the operators dedicated to meshing, grouped by functionality (operators for the creation of points, of line entities, of surface entities and of volume entities …) by the command:

INFO DEBU ;

This information is also available from an Internet browser (the location depends on the local installation).

## 3 Advice on the use of GIBI for Aster

- Do not forget that each command ends with a ";",
- *Code_Aster* can reread the files created by GIBI having level 3, 4, 5, 6, 8, 9, 10, 11 or 13. This level is linked to the change of format,
- bear in mind that it is not possible to force the mesh to pass through a point or a line which does not appear on the outer contour. Plan the partitioning of the geometry accordingly,
- bear in mind that GIBI orients the different mesh cells with its own conventions. Elements may thus be "turned over" (hence negative Jacobians and pressures the wrong way round!). In GIBI, the user has the operators INVERSE and ORIENTER available in order to modify the orientation of elements. One will advantageously refer to the command MODI_MAILLAGE ([U4.23.04](doc:u4.23.04), keywords ORIE_PEAU_2D/3D) in order to act on the orientation of the mesh cells in *Aster*,
- the operator PRE_GIBI assumes that GIBI has been run without error, that is to say that the second line of the .mgib file is "NIVEAU NIVEAU ERREUR 0 DIMENSION …"

Otherwise, one carries out the interface all the same, while issuing an alarm,

- the file containing the GIBI mesh must be produced by the command "SAUVER FORMAT maillage"; this is the only format reread by the interface PRE_GIBI.

## 4 Interface with Aster

The interface with *Aster* is activated by the command PRE_GIBI [U7.01.11](doc:u7.01.11).

## 5 GIBI and Aster meshing entities

The GIBI mesher handles typed and named objects (cf. the GIBI user's guide).

The types used are:

- the integer, real, text constants, …,
- the POINTS,
- the MAILLAGES (set of mesh cells).

The command PRE_GIBI has the effect:

- of writing the points (GIBI) in the form of nodes (*Aster*): the names of the *Aster* nodes are of the form: ${N}_{i}$ where $i$ is the GIBI number of the corresponding point,
- of writing the mesh cells (*Aster*) contained in the meshes (GIBI): the names of the *Aster* mesh cells are of the form: ${M}_{j}$ where $j$ is the order number of the GIBI mesh cell in the GIBI result file,
- of writing GROUP_MA (*Aster*) corresponding to the meshes (GIBI) and with the same names,

**Note:**

*The mesh-cell groups contain only the mesh cells which actually define the GIBI mesh. They do not contain the mesh cells of the objects referenced in this mesh (the edges, for example).*

- of writing GROUP_NO (*Aster*) reduced to a single node and whose names are the names of the GIBI points.

One notes that PRE_GIBI does not generate any GROUP_NO containing several nodes. This would sometimes be very useful in order to impose boundary conditions on all the nodes of an edge. In order to do this, the user has available in Aster the command DEFI_GROUP, which makes it possible to create node groups from mesh-cell groups.

The keyword CREA_GROUP_NO of the operator DEFI_GROUP [U4.22.01](doc:u4.22.01) makes it possible to get round this obstacle.

One therefore finds in the *Aster* mesh GROUP_MA of names: $\mathit{AB}$ , $\mathit{CARRE}$ , $\mathit{C1}$ , …, $\mathit{C4}$

**Note:**

*The interface writes only once mesh cells which may be identical (which sometimes happens with the "ET" operator of GIBI). This has the consequence that the names of the mesh cells* ${M}_{j}$ *may have a "numbering with holes". One must not be concerned about it.*

- The orientation of the mesh cells is that given by GIBI. This may be of importance for certain changes: pressure, …

### 6.1 Note concerning the POIN command of GIBI

This command can produce results of a different type:

- if this command makes it possible to recover a single point,

for example:

```text
PA = toto    POIN    PROC    A    ;
```

or

```text
PA = toto    POIN    INITIAL    ;
```

then $\mathit{PA}$ is a named GIBI point.

For *Aster*, one will have a GROUP_NO of name $\mathit{PA}$ which contains only one node.

- if this command makes it possible to recover several points:

for example:

```text
PA = toto    POIN    DROIT    A    B    1.0D-2    ;
```

then $\mathit{PA}$ is a named GIBI mesh:

This mesh is made up of POI1 mesh cells.

For *Aster*, one will have a GROUP_MA of name $\mathit{PA}$ which contains several POI1. In order to use this object as a GROUP_NO, one will have to use the factor keyword CREA_GROUP_NO of the command DEFI_GROUP.

### 6.2 GIBI command file

```text
OPTI DIME 2 ELEM TRI3 ;

*

* POINTS NOMMES:

*

A = 0.0 0.0 ;

B = 1.0 0.0 ;

*

* MAILLAGES:

*

AB = DROI 2 A B ;

CARRE = AB TRAN 1 (0. 1.);

C1 C2 C3 C4 = COTE CARRE ;

*

SAUVER FORMAT CARRE ;

FIN;

*

-------------------------------------------------------------------
```
