# u4.61.21 Macro-command ASSEMBLAGE

## 1 Purpose

Compute one or more assembled matrices (stiffness, mass, damping …) as well as one or more assembled vectors.

This command is recommended in order to create the concepts necessary for dynamic analyses, whether matrices or vectors. It avoids tedious calls to the “basic” commands: CALC_MATR_ELEM [U4.41.01](doc:u4.41.01), NUME_DDL [U4.61.01](doc:u4.61.01), ASSE_MATRICE [U4.61.22](doc:u4.61.22), CALC_VECT_ELEM [U4.61.02](doc:u4.61.02), ASSE_VECTEUR [U4.61.23](doc:u4.61.23).

Produces one or more data structures of type matr_asse_* and cham_no plus, possibly, a data structure of type nume_ddl.

## 3 Operands

### 3.1 Concepts created by the macro-command

This macro-command creates several typed concepts:

- one matr_asse_* at each occurrence of the factor keyword MATR_ASSE (keyword MATRICE),
- one cham_no at each occurrence of the factor keyword VECT_ASSE (keyword VECTEUR),
- possibly a nume_ddl (keyword NUME_DDL) if it does not already exist.

For example, the sequence:

```text
...

# nu n'est pas un concept encore existant.

ASSEMBLAGE    (MODELE = mo , ...
NUME_DDL = CO("nu"),
MATR_ASSE = ( _F( MATRICE= CO("K"), OPTION='RIGI_MECA'),
VECT_ASSE = ( _F( VECTEUR= CO("F"), OPTION='CHAR_MECA'))

ASSEMBLAGE    (MODELE = mo , ...
NUME_DDL = nu,
MATR_ASSE = (    _F(MATRICE=CO("M"),OPTION='MASS_MECA'),
_F(MATRICE=CO("A"),OPTION='AMOR_MECA'),

),)
```

| the 1st call to ASSEMBLAGE creates | 1 MATR_ASSE: K |
| --- | --- |
|  | 1 VECT_ASSE: F |
|  | 1 NUME_DDL: nu |
| the 2nd call to ASSEMBLAGE creates | 2 MATR_ASSE: M and A |

**Note:**

*On the 2nd call, the concept* *nume_ddl is supplied (it exists; it was created by the 1st call). In this case, it is assumed to be suitable for the 2* *matr_asse to be created; it is therefore important that the* *nume_ddl be first computed for an option of type "RIGIDITE" in order to contain the Lagrange nodes of the fixing loads (cf.* *CALC_MATR_ELEM* [U4.61.01](doc:u4.61.01)).

*In the previous example, the 3* *matr_asse K,* *M and* *A and* *the vector* *F* *are based on the same numbering of the unknowns (nu). This is a necessary condition for the eigenmode search algorithms.*

### 3.2 Operands MODELE / CHAM_MATER / CARA_ELEM / INST

```text
♦    MODELE = mo
```

This operand is used to indicate the elements for which the elementary analyses must be performed: one recalls that the finite elements are for the most part defined in the model.

There are a few exceptions:

1. The elements of dualisation of the DIRICHLET conditions, that is the elements making it possible to impose conditions on the displacement degrees of freedom in mechanics, the temperature degrees of freedom in thermal analysis and the pressure degrees of freedom in acoustics.
2. The elements of nodal loading, of thermal exchange between walls, ...

These elements are defined in the concepts of type char_meca, char_ther or char_acou.

One must therefore supply the argument l_char for the computation of the assembled stiffness matrices: RIGI_MECA, RIGI_THER, RIGI_ACOU, RIGI_MECA_HYST and RIGI_THER_CONV(_D).

```text
◊    CHAM_MATER = chmater
```

Name of the material field in which the material characteristics of the elements are defined.

This argument is almost always necessary.

In practice, one can do without it:

- for the discrete elements whose elementary matrices are defined in the concept cara_elem. See AFFE_CARA_ELEM [U4.42.01](doc:u4.42.01),
- for the computation of the stiffnesses due to the dualisation of the boundary conditions.

```text
◊    CARA_ELEM = carac
```

The elementary characteristics carac are necessary if there exist in the model structural elements (beam, shell or discrete elements) or non-isotropic continuous-medium elements.

```text
◊    INST= tps
```

The argument tps is used when the material characteristics or the loadings depend on time. A fairly frequent case is that of a mechanical material depending on the temperature which itself depends on time.

### 3.3 Operands CHARGE

```text
◊    CHARGE = l_char
```

This operand has several distinct functions:

1. specify the elements for which the elementary stiffness analyses are done (DIRICHLET conditions),
2. for the options 'RIGI_THER_CONV(_D)': give the value of the convection velocity,
3. for the option 'IMPE_MECA': give the value of the acoustic impedance of the mesh cells of the edge,
4. for the option 'ONDE_FLUI': give the value of the pressure of the incident wave,
5. for the option 'RIGI_ROTA': give the value of the rotation imposed on the model.

**Note:**

*Warning* for the two *operands* CHARGE *:* The one *under* VECT_ASSE *cannot replace* the one under ASSEMBLAGE *.* If one fills in CHARGE only *under* VECT_ASSE *,* the loadings are not taken into account in the functions below.

*When calling the macro-command for the assembly of the vectors in the case where the concept nume_ddl is an input (under the keyword* NUME_DDL *), the value of the keyword* CHARGE l_char *must be identical to that used for the creation of the nume_ddl.*

*For example, the following sequence:*

```text
...

# nu n'est pas un concept encore existant.

ASSEMBLAGE    (MODELE = mo , CHARGE = (char_1,char_2),...
NUME_DDL = CO("nu"),
MATR_ASSE = ( _F( MATRICE= CO("K"), OPTION='RIGI_MECA'))

# nu existe et est un concept entrant.

ASSEMBLAGE    (MODELE = mo , CHARGE = (char_1,char_2),...
NUME_DDL = nu,
VECT_ASSE = (    _F(VECTEUR=CO("F"),OPTION='CHAR_MECA',
CHARGE=CHAR_F),),)
```

### 3.4 Operand CHAR_CINE

```text
◊    CHAR_CINE = lchci
```

This operand makes it possible not to “dualise” certain Dirichlet boundary conditions (fixings). These will be eliminated.

### 3.5 Operand NUME_DDL

```text
♦    NUME_DDL    =    nu
```

The user of the macro must always give a concept name after the keyword NUME_DDL. If the concept does not exist, it is created.

If the concept exists, it is used to number the matrices.

### 3.6 Keyword MATR_ASSE

This factor keyword makes it possible to request the computation of an assembled matrix (at each occurrence).

The name of the assembled matrix is given by the operand MATRICE and the “nature” of the matrix is defined by the operand **OPTION**.

The possible options: 'RIGI_MECA', 'MASS_MECA', … are described in [U4.61.01](doc:u4.61.01).

The choice of the option determines the type of the resulting matr_asse_* [U4.61.01](doc:u4.61.01).

#### 3.6.1 Operands specific to certain options

##### 3.6.1.1 Operand MODE_FOURIER

```text
◊    MODE_FOURIER = nh
```

Positive or zero integer indicating the FOURIER harmonic on which one computes the matrices.

By default: nh = 0

##### 3.6.1.2 Operand SIEF_ELGA (option 'RIGI_GEOM')

```text
♦    SIEF_ELGA = sig
```

The stress field sig given for the computation of the option 'RIGI_GEOM' must have been computed with the option 'SIEF_ELGA' (stress field at the GAUSS points of the elements) (cf. commands CALC_CHAM_ELEM [U4.81.03](doc:u4.81.03) or CALC_CHAMP [U4.81.04](doc:u4.81.04)).

##### 3.6.1.3 Operand GROUP_MA (options 'MECA_GYRO' and 'RIGI_GYRO')

```text
◊    GROUP_MA =    grma

On peut restreindre le calcul des options 'MECA_GYRO'et 'RIGI_GYRO'sur les mailles spécifiées par GROUP_MA.
```

##### 3.6.1.4 Operands AMOR_FLUI, VNOR and TYPE_AMOR

> ◊    AMOR_FLUI =

This option makes it possible for us to deactivate the contribution of the absorbing fluid boundaries ('3D_FLUI_ABSO', '2D_FLUI_ABSO' and 'AXIS_FLUI_ABSO'). In particular, if one uses the fluid formulation $u-p-\phi$ in a harmonic analysis, one has the possibility of taking into account the contribution of the absorbing fluid boundaries via the computation of a third-order matrix (with the option IMPE_MECA). This third-order matrix is usable only in a harmonic analysis (operand MATR_IMPE_PHI in DYNA_VIBRA) and makes it possible for us to symmetrise the matrix (unlike the computation of this contribution via AMOR_MECA). The option AMOR_FLUI = ‘NON’ saves us from computing this contribution twice. By default, AMOR_FLUI = ‘OUI’. This operand is available exclusively for the option AMOR_MECA.

◊    VNOR=

This option makes it possible for us to take into account the case of an emitting boundary. The most common case is the radiative one (or partially radiative if one defines a reflection coefficient $\alpha \ne 0$ ). In the case of a radiative boundary VNOR= 1. (option activated by default). In the case of an emitting boundary VNOR= -1. This coefficient is multiplied by the value of the impedance of the absorbing fluid boundaries ('3D_FLUI_ABSO', '2D_FLUI_ABSO' and 'AXIS_FLUI_ABSO'). This operand is available exclusively for the options AMOR_MECA, IMPE_MECA and AMOR_ACOU.

◊    TYPE_AMOR=

This option makes it possible for us to compute all the sources of damping present in the model or only the source linked to the absorbing-boundary elements (fluid or not). The default option (TYPE_AMOR= ‘TOUT’) takes into account the possible Rayleigh damping, the damping coming from the discrete elements and that coming from the absorbing-boundary elements. In this case one is obliged to supply either the mass and stiffness matrices for the Rayleigh damping (and the material field), or the characteristics of the discrete elements. If one is in the presence of only the damping coming from the absorbing-boundary elements, one must specify TYPE_AMOR= ‘ABSO’ and supply as input only the material field. This operand is available exclusively for the option AMOR_MECA.

### 3.7 Keyword VECT_ASSE

This factor keyword makes it possible to request the computation of an assembled vector (at each occurrence).

The name of the assembled vector is given by the operand VECTEUR.

Among the possible options for elementary computation and assembly of vectors, only certain possibilities among all those proposed in the commands CALC_VECT_ELEM and ASSE_VECTEUR are proposed here: 'CHAR_MECA' for the mechanical phenomena, 'CHAR_THER' and 'CHAR_ACOU' for the thermal and acoustic phenomena respectively.

The set of options and associated operands is described in [u4.61.02](doc:u4.61.02) and [u4.61.23](doc:u4.61.23).

**Note:**

*The option 'FORC_NODA' and the taking into account of a model containing substructures under the option 'CHAR_MECA', often used in the case of statics, are not available in this macro-command.*

#### 3.7.1 Operands specific to certain options

##### 3.7.1.1 Operand MODE_FOURIER

```text
◊    MODE_FOURIER = nh
```

Positive or zero integer indicating the FOURIER harmonic on which one computes the vectors in the case of the mechanical phenomena.

By default: nh = 0

##### 3.7.1.2 Operand CHARGE

```text
◊    CHARGE = l_char_v
```

```text
Cette opérande permet d'accéder aux informations de chargement spécifiques à chaque vecteur. Les valeurs de l_char_v complètent ( par addition ) les charges l_char spécifiées sous le mot-clé CHARGE en dehors du mot clé VECT_ASSE.
```

**Note:**

*Duplicates in the loads given in l_char and in* *l_char v are forbidden.*

*Warning* for the two *operands* of CHARGE *:* The one *under* VECT_ASSE *cannot replace* the one under ASSEMBLAGE *.* If one fills in CHARGE only *under* VECT_ASSE *,* the loadings are not taken into account in the functions mentioned in chapter 3.3.

Example of the treatment of the loadings:

```text
ASSEMBLAGE    (MODELE = mo , …
CHARGE = (char_1,char_2),
NUME_DDL = CO("nu"),
MATR_ASSE = ( _F( MATRICE= CO("K"), OPTION='RIGI_MECA'),
VECT_ASSE = ( _F( VECTEUR= CO("F1"),                                                                         OPTION='CHAR_MECA',CHARGE=char_A ),
_F( VECTEUR= CO("F2"),                                                                         OPTION='CHAR_MECA',CHARGE=char_B ),
_F( VECTEUR= CO("F3"),    OPTION='CHAR_MECA'),)

Dans l'exemple ci-dessus, les charges assemblées pour chaque vecteur sont:
```

| **Vector** | **Assembled loads** |
| --- | --- |
| F1 | char_1, char_2, char_A |
| F2 | char_1, char_2, char_B |
| F3 | char_1, char_2 |

### 3.8 Operand TITRE

```text
◊    TITRE
```

Title which one wants to give to the result [U4.03.01](doc:u4.03.01).

## 4 Examples

### 4.1 Computation of mechanical eigenmodes

```text
ASSEMBLAGE    (    MODELE = mo    ,        CHARGE = ch_blocage ,
CHAM_MATER = chmat    ,    CARA_ELEM = carac ,
NUME_DDL = CO("nu")    ,
MATR_ASSE = (_F    (MATRICE = CO("K"), OPTION = 'RIGI_MECA'),
_F    (MATRICE = CO("M"), OPTION = 'MASS_MECA'),),)

modes = CALC_MODES ( MATR_RIGI = K,

MATR_MASS = M,

...)
```

### 4.2 Computation of Euler buckling modes

```text
# chsief est le champ de contraintes lié au chargement
```

```text
ASSEMBLAGE    (    MODELE = mo    ,        CHARGE = ch_blocage ,
CHAM_MATER = chmat    ,    CARA_ELEM = carac ,
NUME_DDL = CO("nu"),

MATR_ASSE = (    _F(MATRICE= CO("K"), OPTION='RIGI_MECA'),
_F(MATRICE= CO("KG"), OPTION='RIGI_GEOM',                                                SIEF_ELGA=chsief),),)

modflamb = CALC_MODES ( MATR_RIGI = K,

MATR_MASS = KG,

…)
```

### 4.3 Computation of a forced response

```text
ASSEMBLAGE    (    MODELE = mo    ,        CHARGE = ch_blocage ,
CHAM_MATER = chmat    ,    CARA_ELEM = carac ,
NUME_DDL = CO("nu")    ,
MATR_ASSE = (_F    (MATRICE = CO("K"), OPTION = 'RIGI_MECA'),
_F    (MATRICE = CO("M"), OPTION = 'MASS_MECA'),),
VECT_ASSE = ( _F( VECTEUR= CO("F"),                                                                         OPTION='CHAR_MECA',CHARGE=char_A ),)

reponse = DYNA_VIBRA ( MATR_RIGI = K,    MATR_MASS = M,
EXCIT = _F( VECT_ASSE = F, ...)...)
```
