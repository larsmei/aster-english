# u4.23.04 Operator MODI_MAILLAGE

## 1 Purpose

Carry out modifications on an existing mesh. The possible modifications are:

- reorient boundary mesh cells used to apply a pressure,
- check the orientation of the normals on the shell elements,
- reorient the mesh cells of a single layer of joint elements,
- reorient the x-axis in the parametric space of the biquadratic hexahedral elements,
- update the mesh from a deformed shape computed previously,
- in a mesh with a crack front, move the mid-edge nodes of the edges touching the crack front to a quarter of these edges,
- translate a mesh,
- impose one or more rotations about arbitrary axes on a mesh,
- generate a mesh symmetric with respect to a plane in 3D or a straight line in 2D.
- compute the curvilinear abscissa along a line formed of line elements (SEG)
- modify the coordinates of the nodes randomly

Produces a data structure of type maillage or modifies the data structure (re-entrant operator).

## 2 Syntax

```text
maillage = MODI_MAILLAGE(
    ◆ reuse = <objet de MAILLAGE>,
    ◆ MAILLAGE = maillage,
    ◆ | ORIE_FISSURE = _F(
           ◆ GROUP_MA = grma,
        ),
      | DEFORME = _F(
           ◆ OPTION = "TRAN" (ou non renseigné),
           ◆ / DEPL = cham_no,
             / ALEA = float,
        ),
      | ORIE_PEAU = _F(
           ◆ GROUP_MA_PEAU = grma,
           ◇ GROUP_MA_INTERNE = grma,
        ),
      | ORIE_NORM_COQUE = _F(
           ◆ GROUP_MA = grma,
           ◇ VECT_NORM = float,
           # Si: exists("VECT_NORM")
               ◇ GROUP_NO = grno,
        ),
      | ORIE_INTERF_POU = _F(
           ◆ GROUP_MA = grma,
           ◆ VECT_ORIE = float,
        ),
      | MODI_MAILLE = _F(
           ◆ OPTION = "NOEUD_QUART" (ou non renseigné),
           ◆ | GROUP_MA_FOND = grma,
             | GROUP_NO_FOND = grno,
        ),
      | TRANSLATION = float,
      | ROTATION = _F(

           ◇ / POIN_2 = float,

      | MODI_BASE = _F(
           ◆ VECT_X = float,
           ◇ VECT_Y = float,

      | SYMETRIE = _F(
           ◆ POINT = float,

           ◇ VECT_TANG = float,
           # Si: exists("VECT_TANG")

           ◆ / TOUT = "OUI" (ou non renseigné),
             / GROUP_MA = grma,
           ◇ GROUP_NO_ORIG = grno,

             / 2,

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
```

## 3 Operands

### 3.1 Operand MAILLAGE

> ♦    MAILLAGE = ma,

Mesh of type [maillage] to which the modifications and/or checks will apply.

*Note:*

*It is possible to apply a 3D modification to an initially two-dimensional mesh.*

### 3.2 Operand INFO

> ◊    INFO =

Indicates the printout level of the results of the operator,

| 1 = | no printout, |
| --- | --- |
| 2 = | printout of the mesh cells whose connectivity has been modified, including the printout of the old and new connectivities. |

The printouts are made in the file 'MESSAGE'.

### 3.3 Keyword ORIE_FISSURE

> ◊    ORIE_FISSURE =

This keyword is used to reorient (if necessary) the mesh cells of a group forming a "single layer" of elements. It works in 2D or in 3D, with a linear or quadratic mesh [Figure 3.4-a].

![Figure](/figures/u4.23.04/Shape1.gif)

**Figure 3.4-a**

At present, this keyword is used to reorient the joint elements and the interface elements (modellings AXIS_xxx, PLAN_xxx and 3D_xxx with xxx=JOINT or INTERFACE).

The user specifies (with the keyword GROUP_MA) which mesh cells are candidates for reorientation (the "single layer").

These mesh cells must be "prisms" (QUAD in 2D, HEXA and PENTA in 3D).

![Figure](/figures/u4.23.04/10000000000003C0000002D0419776ED27192559.png)

The direction "transverse" to the layer is determined topologically (and not according to a flatness criterion). In order to be able to be reoriented, the elements of the layer must be supported (via the bases of the prisms) on other mesh cells of the same dimension (2D or 3D) which do not belong to the group of mesh cells to be reoriented.

Consider the (2D) mesh opposite.

One wishes to reorient the group of the 3 mesh cells A, B and C.

For the mesh cells A and B, the support mesh cells (above and below) determine an unambiguous transverse orientation (vertical).

On the other hand, mesh cell C has 3 support mesh cells (top, bottom, right) and one cannot determine the transverse direction.

The reorientation algorithm will fail.

**Note:**

The "reorientation" referred to here consists in reality in modifying the definition of the connectivity of the mesh cells. For example, in 2D, the convention is that sides 2 and 4 of the quadrangles are transverse to the layer.

```text
♦    GROUP_MA= l_gm,
```
List of the mesh-cell groups whose orientation one wishes to check (and possibly modify).

### 3.4 Keyword DEFORMEE

♦    DEFORME / OPTION='TRAN'

Option making it possible to add to the initial geometry of the mesh ma:

- the values of TRANslation (dx, dy (+ dz in 3D)) of the displacement field depl given by the keyword DEPL;
- Or a random quantity.

```text
/    DEPL= depl ,
```
Displacement field used to update the geometry

```text
/    ALEA= epsi ,
```
One adds to each coordinate of each node of the mesh a random quantity (delta).

This quantity is obtained by the formula: delta=epsi*dim*alea()

Where:

- epsi is a number supplied by the user (1.e-8 for example)
- dim is the dimension of the mesh in the direction concerned by the component (X, Y or Z)
- alea() is a function returning a pseudo-random number in the interval
- [-1,1].

*Note:*

*The possibility of modifying the coordinates of a mesh randomly is, a priori,* *a "developer" functionality. It is dangerous in certain situations: very flat mesh cells (joints, ...)*

### 3.5 Keyword ORIE_PEAU

> ◊    ORIE_PEAU=

This keyword is used to reorient boundary mesh cells so that their normals are consistent (towards the outside of the material). This keyword is valid for a two-dimensional (2D) or three-dimensional (3D) study. It is an indispensable preliminary if, for example, one wishes to apply a pressure loading on this "skin".

> ♦    GROUP_MA_PEAU=    lgrma,                [l_gr_ma]

Mesh-cell groups to be reoriented.

The mesh cells are oriented in such a way that the normal is outward. For each boundary mesh cell (edge or face), one looks for the "volume" mesh cell which it "borders". One orients it in such a way that its normal is in the opposite direction to the vector joining its first node to the barycentre of the volume mesh cell.

It sometimes happens that the "skin" one wishes to orient is inserted in the material (for example, when one carries out an analysis for which mesh cells are progressively added to or removed from the model: modelling of an excavation, or of a construction by layers). The orientation algorithm described above then fails, because one generally finds 2 volume mesh cells on either side of the skin mesh cell. One does not then know which one to use to orient the skin mesh cell.

For this purpose, the optional keyword GROUP_MA_INTERNE has been introduced. This keyword allows the user to specify which "internal" mesh cells are to be used to orient the skin mesh cells.

Example:

Let there be 1 skin mesh-cell group (GPEAU) which one wishes to orient with a normal directed outwards. One must indicate that it is the skin of the "volume" mesh-cell group GV2.

One will write:

ORIE_PEAU=_F(GROUP_MA_PEAU='GPEAU', GROUP_MA_INTERNE='GV2'),

### 3.6 Keyword ORIE_NORM_COQUE

> ◊    ORIE_NORM_COQUE= _F(

This keyword is used to check that, in a list of surface mesh cells (shells), the normals are consistent with one another. Otherwise, certain mesh cells are reoriented.

> ♦    GROUP_MA=    lgrma,                [l_gr_ma]

Groups of surface mesh cells to be reoriented. The mesh cells of lgrma must form a "connected" group in order that one may reorient them by continuity.

One may impose the sense of the orientation by means of the keywords GROUP_NO/VECT_NORM. If one does not do so, the orientation retained will be that of the 1st mesh cell of lgrma, but this is not necessarily the 1st mesh cell of the 1st GROUP_MA! It is therefore recommended always to use the keyword VECT_NORM.

> ◊    VECT_NORM= (n1, n2, [n3]),    [l_R]

ni: 2 or 3 components (according to the dimension) of the normal vector. One must also specify the support node of this normal:

> ◊    GROUP_NO    =    grno,        [gr_no]

> grno must be a GROUP_NO containing only one node.
> The normal chosen will be the one which makes an acute angle with the vector given by VECT_NORM.

**Note:** if GROUP_NO is not given by the user, the code will automatically choose one of the nodes of GROUP_MA. One must therefore be careful in the definition of the latter, so that the normal is well defined over the whole set of mesh cells. In particular, one must avoid cases where the group does not define an almost plane topological zone.

### 3.7 Keyword ORIE_INTERF_POU

> ◊    ORIE_INTERF_POU= _F(

This keyword is used to check that, in a list of biquadratic volume mesh cells (HEXA27), the vector x in its parametric space is oriented along the direction and the sense of the axis passing through the nodes in positions 25 and 27 in the connectivity table of the element and forming an acute angle with the orientation vector VECT_ORIE. Otherwise, certain mesh cells are reoriented.

> ♦    GROUP_MA=    lgrma,                [l_gr_ma]

Groups of biquadratic volume mesh cells (HEXA27) to be reoriented. The mesh cells are not reoriented by continuity, each one being oriented individually. It is therefore not necessary that the mesh cells of lgrma form a "connected" group.

The sense of the orientation is imposed by means of the keyword VECT_ORIE.

> ♦    VECT_ORIE= (n1, n2, n3),    [l_R]

The axis chosen for the orientation is the one which makes an acute angle with the vector given by VECT_ORIE.

### 3.8 Keyword ORIE_LIGNE

> ◊    ORIE_LIGNE= _F(

This keyword is used to check that, in a list of line mesh cells (beams), the tangents are consistent with one another. Otherwise, certain mesh cells are reoriented.

> ♦    GROUP_MA=    lgrma,                [l_gr_ma]

Groups of line mesh cells to be reoriented. The mesh cells of lgrma must form a "connected" group in order that one may reorient them by continuity.

One may impose the sense of the orientation by means of the keywords GROUP_NO/VECT_TANG. If one does not do so, the orientation retained will be that of the 1st mesh cell of lgrma, but this is not necessarily the first mesh cell of the first GROUP_MA! It is therefore recommended always to use the keyword VECT_TANG.

> ◊    VECT_TANG= (n1, n2, [n3]),    [l_R]

ni: 2 or 3 components (according to the dimension) of the tangent vector. One must also specify the support node of this normal:

> ◊    GROUP_NO    =    grno,        [gr_no]

> grno must be a GROUP_NO containing only one node.
> The tangent chosen will be the one which makes an acute angle with the vector given by VECT_TANG.

### 3.9 Keyword MODI_MAILLE

> ♦    OPTION= 'NOEUD_QUART' ,

Activates the displacement of the mid-edge nodes of the edges touching the crack front to a quarter of these edges (towards the crack front).

> ♦    /    GROUP_MA_FOND=    lgma_fo,    [l_gr_ma]

```text
/    GROUP_NO_FOND=    lgno_fo,    [l_gr_no]
```
In 2D, one enters the node of the crack front (by GROUP_NO_FOND).

In 3D, one enters either the nodes of the crack front, or the SEG3 mesh cells of the crack front (and not the mesh cells of the lips of the crack or the material mesh cells backed against the front).

### 3.10 Keyword TRANSLATION

**Caution**

*One may combine this functionality with* *ROTATION, but these operations are not commutative. The translation is always executed before the rotation.*

*One cannot combine this functionality with* *SYMETRIE.*

```text
◊    TRANSLATION= (n1, n2, [:ref:`n3 <n3>`]),        [l_R]
```
Simple keyword for the translation of a mesh along a vector.

### 3.11 Keyword ROTATION

**Caution**

*One may combine this functionality with* *TRANSLATION, but these operations are not commutative. On the other hand, it is not allowed to use* *ROTATION,* *MODI_BASE and* *SYMETRIE at the same time. The translation is always executed before the rotation.*

```text
◊    ROTATION=
```
Factor keyword for the rotation of a mesh about an arbitrary axis.

> ♦    POIN_1        =    (ni, n2, [n3]),        [l_R]

Coordinates of the first point used to define the axis of rotation.

> ♦    /    POIN_2    =    (ni, n2, [n3]),        [l_R]

```text
/    DIR        =    (ni, n2, [:ref:`n3 <n3>`]),        [l_R]
```
Coordinates of the second point or direction used to define the axis of rotation completely.

```text
♦    ANGLE        =    a,                        [R]
```
Angle of rotation expressed in degrees.

The rotation is carried out in the positive direction, with respect to its oriented axis. This axis passes through the point POIN_1 and its orientation is given either by the vector DIR, or by the vector with origin POIN_1 and end POIN_2.

The rotation is defined by:

Let $\text{M}(x,y,z)$ be a point in space; one imposes on it a rotation of angle $\alpha$ (in radians) whose axis passes through $\text{P}(\mathit{px},\mathit{py},\mathit{pz})$ and has for direction $\text{D}(\mathit{dx},\mathit{dy},\mathit{dz})$ . Then $\text{M}$ becomes $\text{M}’$ after the rotation:

$\text{M'}=\text{P}+\cos\alpha .\text{PM}+(1-\cos\alpha ).(\text{PM}.\text{D}).\text{D}+\sin\alpha (\text{D}\mathrm{\wedge }\text{PM})$

### 3.12 Keyword ECHELLE

**Caution**

*This functionality may be used with* *TRANSLATION and* *ROTATION. The scaling, when it is requested, is always done after* *TRANSLATION and* *ROTATION.*

*One cannot combine this functionality with* *SYMETRIE.*

```text
◊    ECHELLE= n1,                            [R]
```
Simple keyword for the scaling of a mesh according to a real number.

Let $\text{M}(x,y,z)$ be a point of the mesh,

it will become, by this transformation of ratio $\mathit{n1}$ : $\text{M}’(\mathit{n1}\cdot x,\mathit{n1}\cdot y,\mathit{n1}\cdot z)$ .

### 3.13 Keyword MODI_BASE

**Caution**

*This functionality is not allowed with* *ROTATION and* *SYMETRIE.*

```text
◊    MODI_BASE=
```
Factor keyword for the change of basis in which the coordinates of a mesh are expressed. The change of frame always takes place between 2 orthonormal bases.

> ♦    VECT_X    =    (n1, n2, [n3]),        [l_R]

Coordinates of the first vector of the new basis, of arbitrary norm.

> ◊    VECT_Y    =    (n1, n2, [n3]),        [l_R]

Coordinates of the second vector of the new basis (not used in 2D), also of arbitrary norm.

In 2D, it is enough to give the axis VECT_X, and *Code_Aster*  automatically constructs the second vector in order to define a direct orthogonal basis. A test checks whether VECT_X has a non-zero norm.

In 3D, one checks that VECT_X and VECT_Y have a non-zero norm and one checks that they are orthogonal. The third vector which completes the basis is constructed as the cross product of VECT_X with VECT_Y. One thus ensures the construction of a direct orthogonal basis.

Then, in all cases (2D and 3D), the vectors of the basis are normalised to 1; the user therefore does not have to worry about it. One therefore finally has a direct orthonormal basis.

### 3.14 Keyword SYMETRIE

**Caution**

*One cannot combine this functionality with* *TRANSLATION,* *ROTATION,* *ECHELLE and* *MODI_BASE.*

```text
♦    POINT        =    (n1, n2, [:ref:`n3 <n3>`])        [l_R]
```
Coordinates of a point belonging to the straight line in 2D or to the plane in 3D.

```text
♦    AXE_1    =    (n1, n2, [:ref:`n3 <n3>`])            [l_R]
```
Direction vector of the straight line in 2D or 1st vector making it possible to describe the plane.

```text
◊    AXE_2    =    (n1, n2, n3)                [l_R]
```
2nd vector making it possible to describe the plane.

In 2D, the symmetry is carried out with respect to a straight line, which is in the plane $\mathit{OXY}$ . In order to define this straight line one must give the direction vector of the straight line (AXE_1) and a point (POINT) belonging to this straight line.

In 3D, the symmetry is carried out with respect to a plane. In order to define this plane, one must give 2 vectors of the plane (AXE_1, AXE_2) and a point (POINT) belonging to this plane.

In all cases (2D or 3D), the symmetry is carried out with respect to a plane. In 2D, the second vector necessary for the definition of the plane is fixed at AXE_2 = (0.0, 0.0, -1.0).

The algebraic distance $\delta$ between a point $\text{M}(x,y,z)$ and a plane passing through the point $\text{Mo}(\mathit{xo},\mathit{yo},\mathit{zo})$ with perpendicular vector $\text{V}=\text{AXE\_1}\mathrm{\wedge }\text{AXE\_2}=(a,b,c)$ is:

$\delta =\frac{a(x-{x}_{0})+b(y-{y}_{0})+c(z-{z}_{0})}{\sqrt{{a}^{2}+{b}^{2}+{c}^{2}}}$

The coordinates of the point $\text{M}'$ symmetric to the point $\text{M}$ with respect to the plane are given by:

$\mathit{OM}'=-2\delta .\frac{V}{\mathrm{\parallel }V\mathrm{\parallel }}+\mathit{OM}$

### 3.15 Keyword ABSC_CURV

```text
◊    ABSC_CURV = _F (...),
```
Computes the curvilinear abscissa for the set of SEG mesh cells supplied via the keywords GROUP_MA or TOUT='OUI'.

For each of the nodes of the mesh cells concerned, one computes its curvilinear abscissa taking account of its possible curvature.

The keyword GROUP_NO_ORIG allows the user to choose the origin of the curvilinear abscissae (the node where the abscissa is zero). The origin must be one of the ends of the line on which one wishes to compute the curvilinear abscissa.

This option is necessary, for example, in order to carry out a modal analysis for a tube with external and internal fluid, when the density of the external fluid is defined as a function of the curvilinear abscissa.

![Figure](/figures/u4.23.04/10000000000004B9000001E023CD5F4CB1972B7B.png)

Notes:

- All the mesh cells concerned must be of type SEG2, SEG3 or SEG4.
- Mesh cells of type SEG2 are considered to be straight and the mesh cells SEG3 and SEG4 are assumed to be in the shape of an arc of a circle.
