# u4.63.22 Operator REST_SPEC_PHYS

## 1 Purpose

Compute the response of a structure in the physical basis. The analysis is carried out from a modal-response interspectrum, at certain selected nodes of the mesh.

The operator carries out the computation, with four variants, of the response spectra in the physical basis. The user may choose a response in displacements, velocities, accelerations and, under certain conditions, in generalised forces, stresses or nodal forces. The result produced is a concept of type interspectre.

## 2 Syntax

```text
interspectre = REST_SPEC_PHYS(
    ◆ | BASE_ELAS_FLUI = melasflu,
      | MODE_MECA = mode_meca,
    # Si: exists("BASE_ELAS_FLUI")
        ◆ VITE_FLUI = float,
        ◇ PRECISION = float (défaut: 0.001),
    ◇ BANDE = float,
    ◇ NUME_ORDRE = int,
    ◇ TOUT_ORDRE = / "OUI",
                   / "NON" (par défaut),
    ◆ INTE_SPEC_GENE = interspectre,
    ◆ / GROUP_NO = grno,
    ◇ GROUP_MA = grma,
    ◆ NOM_CMP = text,
    ◆ NOM_CHAM = / "DEPL",
                 / "VITE",
                 / "ACCE",
                 / "EFGE_ELNO",
                 / "SIPO_ELNO",
                 / "SIGM_ELNO",
                 / "FORC_NODA",
    ◇ MODE_STAT = mode_meca,
    ◇ EXCIT = _F(
         ◆ | GROUP_NO = grno,
         ◆ NOM_CMP = text,
      ),
    ◇ MOUVEMENT = / "RELATIF",
                  / "ABSOLU" (par défaut),
                  / "DIFFERENTIEL",
    ◇ OPTION = / "DIAG_TOUT",
               / "DIAG_DIAG" (par défaut),
               / "TOUT_TOUT",
               / "TOUT_DIAG",
    ◇ TITRE = text,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Operand BASE_ELAS_FLUI

```text
BASE_ELAS_FLUI = baseflui
```

Concept of type melasflu produced by the operator CALC_FLUI_STRU [U4.66.02](doc:u4.66.02), which defines a set of modal bases associated with the various flow velocities of the fluid. The modal response of the structure for a flow velocity considered is decomposed on the basis corresponding to this velocity. One must then specify the fluid velocity vitefl for which one wants to carry out the analysis.

#### 3.1.1 Keyword VITE_FLUI

The operand VITE_FLUI must be supplied if one uses a basis of type melasflu.

♦    VITE_FLUI = vitefl

Fluid flow velocity for the response analysis.

#### 3.1.2 Keyword PRECISION

◊    PRECISION = prec

Precision on the fluid flow velocity (by default 1.E-3).

### 3.2 Operand MODE_MECA

```text
MODE_MECA = base
```

This operand makes it possible to define the basis on which the modal response is decomposed. Concepts of type mode_meca produced by the operators CALC_MODES [U4.52.02](doc:u4.52.02) or DEFI_BASE_MODALE [U4.64.02](doc:u4.64.02) are accepted.

**Note:**

*The operands* *BASE_ELAS_FLUI and* *MODE_MECA may be used simultaneously in the case where one wishes to compute a stress response of a beam structure subjected to the action of a flow.*

*This analysis case is determined by the supply of a concept of type* *melasflu under the operand* *BASE_ELAS_FLUI, defining the modal bases of the structure at the various flow velocities, and the choice of the physical response field* *'SIPO_ELNO' under the operand* *NOM_CHAM. The complementary supply of a concept of type* *mode_meca under the operand* *MODE_MECA then becomes mandatory, in order to define the field of the modal stresses at the* *nodes of the structure.*

*The modal stresses are computed upstream by the operator* *CALC_CHAMP* [U4.81.04](doc:u4.81.04), option *'SIPO_ELNO', with the aid of the* **normalised** *modal mode shapes.* *The operator* *NORM_MODE* [U4.52.11](doc:u4.52.11) *makes it possible to carry out beforehand the normalisation of the modal mode shapes.*

### 3.3 Operands NUME_ORDRE, TOUT_ORDRE and BANDE

These operands must be used only in the case where the basis on which the modal response is decomposed is defined by a concept of type mode_meca.

```text
◊    /    NUME_ORDRE = l_nuor
```

List of the order numbers of the modes which are actually taken into account for the computation of the physical response.

```text
◊    /    TOUT_ORDRE = /    ’NON’,                        [DEFAUT]
/    ’OUI’,
```

If one wishes to take all the modes of the basis for the computation of the physical response, one may choose TOUT_ORDRE = 'OUI' instead of giving the list.

```text
/    BANDE = (f1, f2)
```

The modes which are taken into account for the computation of the physical response are the modes of the concept of type mode_meca whose frequency lies in the band defined by (f1 f2).

### 3.4 Operand INTE_SPEC_GENE

```text
♦    INTE_SPEC_GENE = repmoda
```

Concept of type interspectre produced by the operator DYNA_SPEC_MODAL [U4.53.23](doc:u4.53.23) or DYNA_ALEA_MODAL [U4.53.22](doc:u4.53.22), which defines the modal-response interspectra, i.e. the interspectra of generalised displacements.

### 3.5 Operand GROUP_NO

```text
♦    GROUP_NO             =    l_gr_no_rep,                    [l_gr_no]
```

List of the node groups of the mesh where the physical-response interspectra are computed.

If the keyword GROUP_NO is supplied, the length of the list of nodes must be equal to that of the list of components to be recovered (keyword NOM_CMP).

If several components are to be recovered and the keyword GROUP_NO is supplied, it is imperative to have as many node groups as components; each group must contain a single node.

If one component is to be recovered for several nodes, it is possible to supply under the keyword GROUP_NO one or more groups of as many nodes as required; it is therefore no longer required in this case that the groups contain a single node.

### 3.6 Operand GROUP_MA

```text
◊    GROUP_MA         =    l_gr_ma_rep,                    [l_gr_ma]
```

List of the mesh-cell groups of the mesh where the physical-response interspectra are computed, in the case where the response field is an element field (XXXX_ELNO). The list of mesh cells must be consistent, in length and in order, with respect to the list of node groups supplied by the user under the keyword GROUP_NO.

**Note:**

*In the case of a fluid-structure interaction analysis, that is if the keyword BASE_ELAS_FLUI is supplied, the keyword* GROUP_MA *is not taken into account and the quantities recovered at a node from the element fields (type ELNO) are in reality only the arithmetic means of the field values on the mesh cells in the neighbourhood of this* node.

### 3.7 Operand NOM_CHAM

```text
♦    NOM_CHAM =    ’DEPL’ ou ’VITE’ ou ’ACCE’ ou ’EFGE_ELNO’ ou
’SIPO_ELNO’ ou ’SIGM_ELNO’ ou ’FORC_NODA’
```

Name of the physical response field to be computed.

**Note:**

*The choice of the physical response field* *'SIPO_ELNO' for a beam structure under flow requires the simultaneous use of the operands* *BASE_ELAS_FLUI and* *MODE_MECA* (cf [§3.1]).

### 3.8 Operand NOM_CMP

```text
♦    NOM_CMP = ’DX’ ou ’DY’ ou ’DZ’ ou ’SMFY’ ou ’SMFZ’
```

Names of the components of the physical response field which are actually to be computed.

**Note:**

*The components* *'DX',* *'DY', and* *'DZ' are valid for the fields* *'DEPL',* *'VITE' or* *'ACCE'. The components* *'SMFY' and* *'SMFZ' are valid for the field* *'SIPO_ELNO'.*

### 3.9 Operand MODE_STAT

```text
◊    MODE_STAT = modestat
```

Concept of type mode_meca produced by the operator MODE_STATIQUE [U4.52.14](doc:u4.52.14), which defines the static modes taken into account in the case of a multi-support seismic analysis where the excitation is applied on the degrees of freedom.

### 3.10 Keyword EXCIT

```text
◊    EXCIT
```

Factor keyword making it possible to define the degrees of freedom on which the excitation is applied, in the case of a multi-support seismic analysis.

```text
♦    GROUP_NO = l_grno
```

List of the node groups where the excitation is applied.

```text
♦    NOM_CMP = l_ncmp
```

List of the components on which the excitation is applied.

**Note:**

*These components must correspond to degrees of freedom of the* *support nodes. Example:* *'PRES',* *'DRZ',* *'PHI',...*

*In every case, there must be as many arguments under the operand* *GROUP_NO as under the operand* *NOM_CMP.*

*For fluid sources, it is the component* *'PRES' which is excited.*

### 3.11 Operand MOUVEMENT

```text
◊    MOUVEMENT = 'ABSOLU' ou 'RELATIF' ou 'DIFFERENTIEL'
```

Indicator characterising the physical response to be computed, in the case of a multi-support seismic analysis: absolute response ('ABSOLU') by default, dynamic contribution ('RELATIF') or differential contribution ('DIFFERENTIEL') of the response.

### 3.12 Operand OPTION

```text
◊    OPTION = 'DIAG_DIAG' ou 'DIAG_TOUT' ou 'TOUT_DIAG' ou 'TOUT_TOUT'
```

Indicator specifying the choice of the computation to be carried out:

- computation of the auto-spectra at the nodes by means of the modal auto-spectra;
- computation of the auto-spectra at the nodes by means of all the modal interspectra;
- computation of all the interspectra at the nodes by means of the modal auto-spectra;
- computation of all the interspectra at the nodes by means of all the modal interspectra.

**Note:**

*In the case where the modal response has been computed by* *DYNA_SPEC_MODAL* [U4.53.23](doc:u4.53.23), the choice of computation must be consistent with the one retained upstream in this operator. Indeed, the options *'DIAG_TOUT' or* *'TOUT_TOUT' cannot be executed if one has chosen* *'DIAG' in* *DYNA_SPEC_MODAL* [U4.53.23](doc:u4.53.23).

*The default choice is therefore* *'DIAG_DIAG', which corresponds to the simplest analysis case that can be carried out whatever the choice retained upstream.*

### 3.13 Operand TITRE

```text
◊    TITRE = titre
```

Argument of text type defining the title attached to the output concept interspectre.
