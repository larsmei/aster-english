# A simple example of use

> **Summary.**

This document describes a very simple example of use of *Code_Aster*. The data-setup files are those of the test case FORMA00, available in the test-case base of Code_Aster:

| Salomé script for generating the CAD and the mesh | forma00.datg |
| --- | --- |
| Code_Aster command file | forma00.comm |

On the basis of this simple analysis of a thin tank under hydrostatic pressure, modelled as axisymmetric, the "essential" commands are commented on.

## 1 Modelling a mechanical problem with Code_Aster

The problem to be modelled is a thin cylindrical tank of constant thickness (thickness $0.1m$, internal radius $R=1m$, height $L=4m$) subjected to an internal pressure varying with the height, corresponding to a hydrostatic pressure.

![Figure](/figures/u1.05.00/Object_4.svg)

Given the symmetries of the geometry and of the loading, a two-dimensional axisymmetric modelling is chosen. It is therefore sufficient to represent a vertical slice of this cylinder (in the plane $XY$). The two stages to be planned are:

- creation of the mesh

- writing of the command file

## 2 Building the mesh: what to plan for?

![Figure](/figures/u1.05.00/Object_2.svg)

Whatever meshing software is used, one must plan, from the creation of the mesh, to name the topological zones which will be used in the analysis to assign elementary characteristics, boundary conditions, loadings, materials... Indeed, although it is possible to use node numbers and mesh-cell numbers directly in the command file, it is preferable to use named entities (node groups, mesh-cell groups). This makes it possible to have a command file independent of the degree of refinement of the mesh, and of any renumbering of the nodes or of the elements. In practice, these entities are groups:

- node groups (possibly containing a single node, as with the points $A$, $B$, $C$, $D$ in the example),

- mesh-cell groups corresponding to subdomains of the mesh, or else mesh cells used to apply the loadings: here, for example, the mesh-cell group LDA contains linear mesh cells (skin mesh cells) which will be used to apply the pressure. The simple script generating the geometry (a rectangle) and the mesh can be read in the file forma00.datg.

## 3 How to write the command file?

### 3.1 Starting from nothing?

When one wants to model a new thermomechanical problem, one does not in general start from a blank sheet: it is useful to take inspiration from a command file of a modelling close to the one to be treated. How are these files obtained? The sources are various:

- the test base of *Code_Aster*, together with its documentation, is often an important help, because it covers a large part of the features of the code (these tests can be found in the astest directory of the code installation),

- training courses make it possible to learn in depth the whole set of commands relating to types of modelling: linear statics, thermal analysis, dynamics, thermoplasticity, post-processing… In particular, the practical work of the training courses consists of tests: FORMA***. The associated validation documents (V) contain the titles and the solutions of this practical work.

Writing this command file will be made much easier by using the command-file editor EFICAS.

### 3.2 A few essential commands

We shall now detail the commands needed to carry out the analysis under consideration.

| **Command file** | **Explanations** |
| --- | --- |
| # Thin cylinder under hydrostatic pressure | Comments are preceded by the # sign, |
| **DEBUT ( ) ;** | Compulsory command in order to begin. |
| **mail = LIRE_MAILLAGE** **( FORMAT='MED' ) ;** | Reading of the mesh in MED format in the file associated by default with the mesh: logical unit 20. Creation of the concept mail containing the mesh in Aster format |
| # Definition of the model |  |
| **modl=AFFE_MODELE(MAILLAGE=mail,** **AFFE=_F(TOUT='OUI',** **PHENOMENE='MECANIQUE',** **MODELISATION='AXIS',),);** | A model is a concept, here named modl, containing the types of finite element useful to the analysis. Axisymmetric mechanical finite elements are assigned to all the mesh cells of the mesh. Note: one and the same command may continue over several lines |
| # Definition of the material |  |
| **acier=DEFI_MATERIAU(ELAS=_F(E=210000000000.0,** **NU=0.3,),);** | Definition of a particular material, which we have chosen to name acier here, and of its characteristics: Young's modulus and Poisson's ratio for the case of an elastic material. |
| # Assignment of the material to the mesh |  |
| **chmat=AFFE_MATERIAU(MAILLAGE=mail,** **AFFE=_F(TOUT='OUI',** **MATER=acier,),);** | Assignment of the material acier to the mesh mail. Here the material is the same for the whole mesh. One could of course assign different materials to particular mesh-cell groups. |
| # Definition of the boundary conditions |  |
| **clim=AFFE_CHAR_MECA(MODELE=modl,** **FACE_IMPO=_F(GROUP_MA='LAB',** **DY=0,),);** | Boundary conditions may apply to nodes, node groups, mesh cells or mesh-cell groups. Here the nodes of the mesh-cell group LAB (boundary mesh cells) are assigned the following condition: $mathrm{DY}=0$ which means: "displacement along $y$" zero for all the nodes of the group LAB |
| # Definition and assignment of the loading: pressure as a function of $y$ |  |
| **f_y=DEFI_FONCTION(NOM_PARA='Y',** **VALE=(0.0,200000.0,** **4.0,0.0,),);** | Functions are defined point by point (affine variation between two points by default). Here, the pressure varies between: $200000mathit{Pa}$ for $y=0$ and $0$ for $y=L$ |
| **charg=AFFE_CHAR_MECA_F(MODELE=modl,** **PRES_REP=** **_F(GROUP_MA=('LFA','LDF',),** **PRES=f_y,),);** | Assignment of the pressure (a function of $y$) on the edge made up of the mesh-cell groups LFA and LDF |
| # Solution |  |
| **res1=MECA_STATIQUE(MODELE=modl,** **CHAM_MATER=chmat,** **EXCIT=(_F(CHARGE=charg,),** **_F(CHARGE=clim,),),);** | Global command for the solution of static problems in linear thermoelasticity. Association with the model, the material field(s) and the loading(s) previously defined. res1 is the name of the result concept produced by the command. It contains in particular the computed displacement field. |
| # Computation of the stresses |  |
| **res1=CALC_CHAMP(reuse =res1,** **RESULTAT=res1,** **CONTRAINTE='SIGM_ELNO',);** | reuse=res1 means that one "enriches" the concept. res1: the stress field will be stored in addition to the displacement field already present in the concept. The name 'SIGM_ELNO' means "stresses computed at the nodes of each element from the displacements" |
| # Printout of the results |  |
| **IMPR_RESU(FORMAT='MED',** **RESU=_F(RESULTAT=res1,),);** | Printout of the results in MED format: displacements/stresses over the whole mesh |
| **IMPR_RESU(RESU=_F(RESULTAT=res1,** **GROUP_NO='A',),);** | Printout of the results in text format for the single node group "A". |
| **FIN();** | Compulsory command to close an execution |

## 5 And the other files produced by the analysis?

### 5.1 The message file

This file contains the echo of the commands and gives additional information on the execution of each command:

for example MECA_STATIQUE:

#-------------------------------------------------------------------------

# Command No : 0009 Concept of type : evol_elas

#-------------------------------------------------------------------------

res1=MECA_STATIQUE(EXCIT=(_F(TYPE_CHARGE='FIXE',

CHARGE=charg),

_F(TYPE_CHARGE='FIXE',

CHARGE=clim)),

INFO=1,

OPTION='SIEF_ELGA',

SOLVEUR=_F(RENUM='METIS',

STOP_SINGULIER='OUI',

METHODE='MULT_FRONT',

NPREC=8),

INST=0.0,

MODELE=modl,

CHAM_MATER=chmat,);

The linear system to be solved contains 51 nodes, of which:

- 43 nodes carrying physical degrees of freedom

- 8 nodes carrying Lagrange degrees of freedom

For a total of 94 equations.
