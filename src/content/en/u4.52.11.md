# u4.52.11 Operator NORM_MODE

## 1 Purpose

The role of the command is to normalise eigenmodes according to a criterion chosen by the user.

The modal analysis operator CALC_MODES [U4.52.02](doc:u4.52.02) produces a concept of type mode_meca or mode_meca_c whose real or complex eigenmodes are normalised in such a way that the largest of the components which is not a LAGRANGE multiplier is equal to 1.

The operator NORM_MODE allows the user to choose another normalisation method, for example generalised mass, generalised stiffness ...

Depending on the normalisation chosen, the modal parameters (participation factor, effective mass, ...) are updated.

Re-entrant operator.

## 2 Syntax

```text
/ mode_flamb
/ mode_meca
/ mode_meca_c = NORM_MODE(
    ◇ reuse = <objet de MODE>,
    ◆ MODE = mode_flamb / mode_meca,
    ◆ / NORME = / "EUCL",
                / "EUCL_TRAN",
                / "MASS_GENE",
                / "RIGI_GENE",
                / "TRAN",
                / "TRAN_ROTA",
      / GROUP_NO = grno,
      / AVEC_CMP = text,
      / SANS_CMP = text,
    # Si: exists("GROUP_NO")
        ◆ NOM_CMP = text,
    ◇ MODE_SIGNE = _F(
         ◆ / GROUP_NO = grno,
         ◆ NOM_CMP = text,
         ◇ SIGNE = / "NEGATIF",
                   / "POSITIF" (par défaut),
      ),
    ◇ MASSE = matr_asse_depl_r / matr_asse_gene_r / matr_asse_pres_r,
    ◇ RAIDE = matr_asse_depl_c / matr_asse_depl_r / matr_asse_gene_r / matr_asse_pres_r,
    ◇ AMOR = matr_asse_depl_r / matr_asse_gene_r,
    ◇ TITRE = text,
    ◇ INFO = / 1 (par défaut),
             / 2,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Operand MODE

```text
♦    MODE =    m_in
```

Name of the concept of type mode_* whose eigenmode normalisation one wants to change. If m_out is identical to m_in and if the keyword 'reuse' is activated with the value m_out, the renormalisation is done in place.

### 3.2 Operand NORME

```text
◊ /    NORME =
```

Symbolic name of the chosen norm.

- `'MASS_GENE'` :
The modes are normalised to unit generalised mass.
- `'RIGI_GENE'` :
The modes are normalised to unit generalised stiffness.
- `'TRAN'` :
The modes are normalised to 1. for the largest of the translation components (components: DX, DY, DZ).
- `'TRAN_ROTA'` :
The modes are normalised to 1. for the largest of the translation and rotation components (components: DX, DY, DZ, DRX, DRY, DRZ).
- `'EUCL'` :
The modes are normalised to the Euclidean norm of the components which are not Lagrange multipliers (component: LAGR).
- `'EUCL_TRAN'` :
The modes are normalised to the Euclidean norm of the translation components (components: DX, DY, DZ).

### 3.3 Operands GROUP_NO and NOM_CMP

```text
◊    GROUP_NO = grno
```

Name of the group of one node $\mathit{grno}$ where one normalises.

*|* *Warning: the node group* $\mathit{grno}$ *must contain a single node.*

```text
♦    NOM_CMP = cmp
```

Name of the normalisation component at the node $\mathit{no}$ or at the group of one node $\mathit{grno}$ . This operand is mandatory if GROUP_NO is supplied.

The modes are normalised to $1.$ for the component $\mathit{cmp}$ of the node $\mathit{no}$ or of the group of one node $\mathit{grno}$ .

### 3.4 Operands AVEC_CMP/SANS_CMP

```text
◊    /    AVEC_CMP = a_cmp
```

a_cmp list of the names of the components used for the normalisation.

The modes are normalised to $1.$ for the largest of the components of the list a_cmp whatever the node.

```text
/    SANS_CMP = s_cmp
```

s_cmp list of the names of the components which are not used for the normalisation.

The modes are normalised to $1.$ for the largest of the components which is not in the list s_cmp.

### 3.5 Factor keyword MODE_SIGNE

This factor keyword makes it possible to impose, for all the modes, the sign of a component of a node stipulated by the user. This factor keyword can be used only for real modes (generalised problem).

```text
♦        GROUP_NO = grnd
```

Name of the group of one node where one imposes the sign of a component.

*|* *Warning: the node group* $\mathit{grnd}$ *must contain a single node.*

```text
♦        NOM_CMP = cmp
```

Name of the component of the group of one node $\mathit{grnd}$ where the sign is imposed.

```text
◊        SIGNE =    / 'POSITIF'
                    / 'NEGATIF'
```

Imposed sign of the component: 'POSITIF' or 'NEGATIF'.

### 3.6 Case of the normalisation of a collection of modes coming from DEFI_BASE_MODALE

If one wants to normalise a collection of modes (modal base) coming from DEFI_BASE_MODALE, one must supply the two matrices, of mass and of stiffness, making it possible to update the modal parameters:

```text
◊    MASSE        =    masse                        [matr_asse_depl_r]
                                         ou         [matr_asse_gene_r]
                                         ou         [matr_asse_pres_r]

◊    RAIDE        =    masse                        [matr_asse_depl_r]
                                         ou         [matr_asse_depl_c]
                                         ou         [matr_asse_gene_r]
                                         ou         [matr_asse_pres_r]
```

Indeed, in this case, the information on the mass and stiffness matrices (and possibly the damping matrix) on which the modal base is based has been lost, or the modes may come from different sets of matrices. It is therefore necessary to recall them to the operator NORM_MODE.

In the case of a base of complex modes, one must in addition give a damping matrix if one wants to normalise with respect to the generalised mass or to the generalised stiffness (cf paragraph 4.2).

### 3.7 Operand TITRE

```text
◊    TITRE =    t
```

Title associated with the concept produced by this operator [U4.03.01](doc:u4.03.01).

### 3.8 Operand INFO

```text
◊    INFO = 1 ou 2
```

For each mode, the name of the old norm and the name of the new norm are indicated in the MESSAGE file. The printed names of the norms correspond to the keywords described in paragraphs 3.2, 3.3, 3.4.

## 4 Formulation of the normalisation rules

The various norms used as well as the definition of the various modal parameters are listed in the reference documentation [R5.01.03](doc:r5.01.03).

### 4.1 Real eigenmodes

For modes of type mode_meca_r (real eigenmodes) the associated generalised eigenvalue problem is: $(K-{\omega}^{2}M)x=(K-{(2\pi f)}^{2}M)x=0$

where $K,M$ are respectively the mass matrix and the stiffness matrix of the mechanical system.

For the modellings ‘MECANIQUE’, one defines the components of the eigenvector:

- translation components ${u}^{T}$
- rotation components ${u}^{R}$
- components of the LAGRANGE multipliers $\lambda$
- other components (fluid pressure and potential) ${p}_{f}$

One calls:

- ${u}^{\mathrm{TR}}$ the translation and rotation components,
- $u$ the components other than LAGRANGE multipliers.

which leads to:

${u}^{\text{*}}=\left[\begin{array}{}u\\ \lambda \end{array}\right]=\left[\begin{array}{}{u}^{T}\\ {u}^{R}\\ {p}_{f}\\ \lambda \end{array}\right]$

For models with translation and rotation components, the eigenmode ${\phi }_{i}$ supplied by the modal-analysis algorithms is by default:

${\Phi}_{i}=\frac{{u}^{\text{*}}}{maxu}=\frac{{u}^{\text{*}}}{max{u}^{\mathit{TR}}}={{\Phi}_{i}}^{\mathit{TR}}$

which is equivalent to the normalisation obtained by the keyword ‘TRAN_ROTA’.

With the keyword ‘TRAN’ the mode obtained is defined by:

${\Phi}_{i}=\frac{{u}^{\text{*}}}{max{u}^{T}}={{\Phi}_{i}}^{T}$

For models with translation components only, the normalisation is by default:

${{\Phi}_{i}}^{T}=\frac{{u}^{\text{*}}}{maxu}=\frac{{u}^{\text{*}}}{max{u}^{T}}$

> which is equivalent to the normalisation obtained by the keyword ‘TRAN’.

The default normalisation leads to the following generalised parameters:

- generalised stiffness ${}^{T}\Phi _{i}K{\Phi}_{i}={\gamma}_{i}$
- generalised mass ${}^{T}\Phi _{i}M{\Phi}_{i}={\mu}_{i}$
- hence the eigen angular frequency ${{\omega}_{i}}^{2}=\frac{{\gamma}_{i}}{{\mu}_{i}}$

The normalisation to unit generalised mass is obtained by the keyword ‘MASS_GENE’:

${{\Phi}_{i}}^{M}=\frac{{\Phi}_{i}}{\sqrt{{\mu}_{i}}}$ hence ${}^{T}{\Phi}_{i}^{M}M{{\Phi}_{i}}^{M}=1.$ and ${}^{T}{\Phi}_{i}^{M}K{{\Phi}_{i}}^{M}={{\omega}_{i}}^{2}$

That to unit generalised stiffness is obtained by the keyword ‘RIGI_GENE’:

${{\Phi}_{i}}^{K}=\frac{{\Phi}_{i}}{\sqrt{{\gamma}_{i}}}$ hence ${}^{T}{\Phi}_{i}^{K}M{{\Phi}_{i}}^{K}=\frac{1}{{{\omega}_{i}}^{2}}$ and ${}^{T}{\Phi}_{i}^{K}K{{\Phi}_{i}}^{K}=1.$

The normalisation of the eigenmode to the Euclidean norm ‘EUCL’ is obtained naturally by:

${{\Phi}_{i}}^{\mathrm{\parallel }u\mathrm{\parallel }}=\frac{{u}^{\text{*}}}{\mathrm{\parallel }u\mathrm{\parallel }}=\frac{{u}^{\text{*}}}{\sqrt{\sum_{j}{({u}_{j})}^{2}}}$

The normalisation of the eigenmode to the Euclidean norm ‘EUCL_TRAN’ is:

${{\Phi}_{i}}^{\mathrm{\parallel }{u}^{T}\mathrm{\parallel }}=\frac{{u}^{\text{*}}}{\mathrm{\parallel }{u}^{T}\mathrm{\parallel }}=\frac{{u}^{\text{*}}}{\sqrt{\sum_{j}{({u}_{j}^{T})}^{2}}}$

### 4.2 Complex eigenmodes

For modes of type mode_meca_c (complex eigenmodes) coming from the solution of a quadratic eigenvalue problem ${\lambda}^{2}M+\lambda C+K=0$ where $C$ is the damping matrix of the mechanical system, one normalises the modes $\Phi$ with respect to the associated linearised problem:

$(\lambda \left[\begin{array}{cc}0& M\\ M& C\end{array}\right]+\left[\begin{array}{cc}-M& 0\\ 0& K\end{array}\right])(\begin{array}{c}\lambda \Phi \\ \Phi \end{array})=0$

The eigenmode is normalised to unit generalised mass (‘MASS_GENE’), if ${\Phi}_{i}$ satisfies:

$(\lambda {}^{T}\Phi _{i}{}^{T}\Phi _{i})\left[\begin{array}{cc}0& M\\ M& C\end{array}\right](\begin{array}{}\lambda {\Phi}_{i}\\ {\Phi}_{i}\end{array})=1.$

to unit generalised stiffness (‘RIGI_GENE’), if ${\Phi}_{i}$ satisfies:

$(\lambda {}^{T}\Phi _{i}{}^{T}\Phi _{i})\left[\begin{array}{cc}-M& 0\\ 0& K\end{array}\right](\begin{array}{}\lambda {\Phi}_{i}\\ {\Phi}_{i}\end{array})=1.$

For the other norms, the definitions are equivalent to those defined for the real modes; it is sufficient to replace the scalar product by the Hermitian product.

## 5 Updated modal parameters

A concept of type mode_meca can contain, for each mode, the following modal parameters (visible for example by printing the concept with the command IMPR_RESU in FORMAT='RESULTAT' with the option TOUT_PARA='OUI'):

| Parameter heading in Code_Aster | Definition |
| --- | --- |
| FREQ | Eigenfrequency (damped, where applicable) |
| AMOR_GENE | Generalised modal damping |
| AMOR_REDUIT | Reduced modal damping |
| FACT_PARTICI_D* (* = X or Y or Z) | Participation factor of the mode in the direction D* |
| MASS_EFFE_D* (* = X or Y or Z) | Effective modal mass in the direction D* |
| MASS_EFFE_UN_D* (* = X or Y or Z) | Unit effective modal mass in the direction D* |
| MASS_GENE | Generalised mass of the mode |
| OMEGA2 | Eigen angular frequency (damped, where applicable) squared |
| RIGI_GENE | Generalised stiffness of the mode |

Table 5.1: list of the modal parameters.

These parameters are defined mathematically in the reference documentation [R5.01.03](doc:r5.01.03).

The operator NORM_MODE computes or updates the following modal parameters, which depend on the normalisation chosen: FACT_PARTICI_D* , MASS_GENE and RIGI_GENE. It also enriches the data structure with the parameters MASS_EFFE_UN_D* (independent of the normalisation).

The other parameters are independent of the normalisation.

## 6 Examples for real modes

For modes of type mode_meca (real eigenmodes) coming from the solution of a generalised eigenvalue problem $(K-\lambda M)x=0$ :

- normalising an eigenvector $x$ to unit generalised stiffness is equivalent to $x$ satisfying ${x}^{T}Kx=1$

Normalisation with duplication of the mode_meca concept:

```text
mo_2     = NORM_MODE(MODE = mo_1, NORME='RIGI_GENE');
```

- normalising an eigenvector $x$ to unit generalised mass is equivalent to $x$ satisfying ${x}^{T}Mx=1$

Normalisation to unit generalised mass, with overwriting of the mode_meca concept:

```text
mo = NORM_MODE(reuse = mo, MODE = mo, NORME = 'MASS_GENE');
```
