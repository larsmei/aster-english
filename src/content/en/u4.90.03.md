# u4.90.03 Macro-command OBSERVATION

## 1 Purpose

The macro-command OBSERVATION uses the operators PROJ_CHAMP, CREA_CHAMP, CREA_RESU, MODI_REPERE and POST_RELEVE_T in order to:

    - project a field from a numerical model onto an experimental model,
    - modify the local frames,
    - select the «measurement» degrees of freedom,

    - compute the mean value of a strain field in order to obtain the equivalent of the information delivered by a strain gauge

This macro-command accepts as input a concept evol_elas, dyna_trans, dyna_harmo or a mode_meca. The concept produced is of the same type as the input concept. Warning: *Code_Aster*  does not store the frames in which the fields are written. The result of this macro-command must therefore not be used in subsequent *Code-Aster*  analyses. It can be used for post-processing in Python, or for visualisations.

## 3 Operands

The first simple keywords are those used in the operator PROJ_CHAMP. Some of these concepts are however reused in the following phases of the macro-command (modification of the frames and filtering of the degrees of freedom). In the macro-command, the operator PROJ_CHAMP is used by default with the method 'COLOCATION' (cf [U4.72.04](doc:u4.72.04)). But one can explicitly use the point-cloud method by adding the necessary keywords detailed in the documentation of this operator.

The concept produced is of the same type as the input concept, defined by the keyword RESULTAT.

### 3.1 Keyword RESULTAT

```text
♦    RESULTAT
```

Data structure that one wishes to manipulate. At present, only structures of type evol_elas, dyna_trans, dyna_harmo and mode_meca can be given as input.

### 3.2 Keyword MODELE_1

```text
♦    MODELE_1
```

Structure of type modele_sdaster associated with the result concept. It is in general the supporting numerical model.

### 3.3 Keyword MODELE_2

```text
♦    MODELE_2
```

Structure of type modele_sdaster. It is in general the model associated with the experiment. Warning: PROJ_CHAMP works only if the degrees of freedom of the nodes of model 1 are the same as those of model 2. For example, if model 1 is 3D, and therefore has only translational degrees of freedom, one cannot take a POU_D_T modelling (Timoshenko beam, with translational and rotational degrees of freedom) for model 2. One will choose in this case a modelling of type BARRE.

### 3.4 Keyword PROJECTION

```text
◊     PROJECTION    =    /    'OUI'                                [DEFAUT]
/    'NON'
```

This keyword makes it possible to carry out, or not, the projection of the results of the processing onto model 2.

If no projection is carried out, the results of the processing overload the results already present on model 1.

### 3.5 Operand CAS_FIGURE

This keyword (optional) is used to direct the program towards one of the following 4 cases:

    - "3D" The only mesh cells of mesh "1" that will be used for the projection are the volume mesh cells: hexahedra, pentahedra, tetrahedra and pyramids. The nodes have 3 coordinates $(X,Y,Z)$.
    - "2D" The only mesh cells of mesh "1" that will be used for the projection are the surface mesh cells: quadrilaterals and triangles. The mesh is assumed to be plane. The nodes have 2 coordinates $(X,Y)$.
    - "2.5D" The only mesh cells of mesh "1" that will be used for the projection are the surface mesh cells: quadrilaterals and triangles. The mesh is 3D. The nodes have 3 coordinates $(X,Y,Z)$. This is the case of "shells" immersed in 3D.
    - "1.5D" The only mesh cells of mesh "1" that will be used for the projection are the line mesh cells: segments. The mesh may be 2D or 3D. The nodes have 2 or 3 coordinates $(X,Y,Z)$.

### 3.6 Keyword VIS_A_VIS

One may refer to [U4.72.04](doc:u4.72.04) (documentation of the operator PROJ_CHAMP) for the use of this optional keyword, which makes it possible to declare explicitly the links between entities of model 1 and of model 2 for the projection.

There is nevertheless a specificity to the use of VIS_A_VIS in this command: the mesh-cell groups placed face to face must bear the same name in the two models. Otherwise, an error is issued.

### 3.7 Operand TYPE_CHAM = 'NOEU'

This keyword is used to force the projected fields to be fields «at the nodes». This keyword is used systematically (for example) by the command MACR_LIGN_COUPE because one does not know how to create fields by elements on the «fictitious» beam model created by this visualisation macro-command.

### 3.8 Selection of the field names

The keyword NOM_CHAM = l_noch makes it possible to choose which fields of the data structure RESULTAT one wants to project. This keyword is mandatory. One can also project the fields by elements "ELNO" and "ELEM" (but not "ELGA").

### 3.9 Operands MATR_RIGI, MATR_MASS

These 2 keywords make it possible to associate (for a data structure of type «mode») their matr_asse with the data structure produced. They also make it possible to recover the numbering of the degrees of freedom. They are necessary if one wishes to use the result of the command in subsequent analyses (commands REST_GENE_PHYS, PROJ_BASE, MAC_MODES, …).

### 3.10 Selection of the order numbers

See [U4.71.00](doc:u4.71.00).

### 3.11 Operand MODI_REPERE

```text
◊ MODI_REPERE = _F(

Mot-clé facteur permettant de définir un repère local pour les entités (nœuds ou mailles) du modèle 2 sélectionnées.
```

#### 3.11.1 Keywords TYPE_CHAM/NOM_CMP

The operator MODI_REPERE must know the components to be transformed. One generally uses a displacement field as input, which is why the entries 'VECT_3D' and ('DX','DY','DZ') are proposed by default. But if one wishes, for example, to treat the case of a strain field (measured by means of strain gauges), one will write TYP_CHAM ='TENS_3D' and NOM_CMP=('EXX','EYY'…)

#### 3.11.2 Keywords REPERE/VECT_X/VECT_Y/ANGL_NAUT/ORIGINE/AXE_Z

- REPERE = 'UTILISATEUR'

The user may himself define the local frame associated with a node by giving the three nautical angles. A definition of the nautical angles will be found in [U4.42.01-I1], U4 documentation of AFFE_CARA_ELEM, paragraph 10.4.

- REPERE = 'CYLINDRIQUE'

To define a cylindrical frame, one must give the origin (keyword ORIGINE) and the direction of the vertical axis (keyword AXE_Z).

- REPERE = 'NORMALE'

The axes of the local frame are denoted $(\mathrm{X1},\mathrm{Y1},\mathrm{Z1})$. In general, the sensors, for a measurement, have the axis $\mathrm{Z1}$ along the normal to the wall of this structure. This option makes it possible to compute a frame associated with this normal:

- computation of the field of vectors normal to model 1 (the most accurate); these vectors will be the axes $\mathrm{Z1}$ of the local frame,
- projection of this field onto the selected entities of model 2,
- explicit data of the second vector of the frame; if one wishes the vector $\mathrm{Y1}$ to be the same vector as $Y$ in the global frame, one writes VECT_Y = (0.0,1.0,0.0)
- One therefore needs two equations to compute the local frame: one of them is given by the normal vector, the other is given by the keyword VECT_X or VECT_Y, according to whether the additional condition concerns the vector $\mathrm{X1}$ or $\mathrm{Y1}$ of the local frame.
- REPERE = 'DIR_JAUGE'

The user may define the local frame associated with the strain gauge by filling in VECT_X and/or VECT_Y. These two vectors correspond to the first two basis vectors of the local frame.

### 3.12 Operand FILTRE

◊ FILTRE = _F(

Keyword describing, for all the entities (nodes, mesh cells, node groups, …), the degrees of freedom to be kept.

#### 3.12.1 Keyword DDL_ACTIF

◊ DDL_ACTIF = liste_ddl

List of the degrees of freedom to be kept for the result.

#### 3.12.2 Keywords GROUP_NO/GROUP_MA

Each degree-of-freedom filter corresponds to a topological entity to be chosen (by default, the whole structure is selected).

#### 3.12.3 Keyword NOM_CHAM

♦ NOM_CHAM = noch

Symbolic name of the field to be filtered. This keyword is mandatory. It makes it possible, among other things, to distinguish the component DX of the displacement field from the component DX of the velocity field.

### 3.13 Operand EPSI_MOYENNE

◊ EPSI_MOYENNE = _F(

Factor keyword making it possible to compute the mean value of the strain field on a given topological entity. This mean value of the strain field can be seen as the information that a strain gauge bonded onto the surface considered would have delivered. This is valid if the field is not too variable over the surface onto which the gauge is bonded. The user is warned if the fluctuation of the strain field is too large.

Each occurrence of this keyword corresponds to a computation of the mean on the designated entities. The values computed are then projected onto model 2, unless the user explicitly specifies PROJECTION = 'NON'. In that case, one overloads the input concept resu_in and one stores the results of the analysis in resu_out.

#### 3.13.1 Keywords GROUP_NO/GROUP_MA

This keyword indicates the topological entity on which one wants to compute the mean.

#### 3.13.2 Keyword MASQUE

```text
◊MASQUE = lcmp
```

This keyword makes it possible to list unmeasured components of the strain field.

#### 3.13.3 Keyword SEUIL_VARI

```text
◊ SEUIL_VARI = seuil
```

One gives here a relative threshold value above which the user is warned if the fluctuation of one of the components of the field, not masked, departs too far from the computed mean value. The value taken by default is equal to $0.1$.

```text
◊ TITRE = titr,
```
