# u4.63.34 Operator REST_SPEC_TEMP

## 1 Purpose

Return of result fields, in generalised coordinates or in the physical basis, from the frequency domain to the time domain and conversely, by fast Fourier transform (FFT).

This operator makes it possible, from a transient-evolution result on a system in generalised coordinates or in the physical basis, to obtain a frequency-evolution result on the same basis by direct Fourier transformation of each of the transient-evolution functions at each point and each component of the selected kinematic fields (displacements, velocities or accelerations). And conversely, from a frequency-evolution result on a system in generalised coordinates or in the physical basis, one obtains a transient-evolution result on the same basis by inverse Fourier transformation of each of the harmonic-evolution functions at each point and each component of the selected kinematic fields.

For each transformed evolution, the operation is analogous to that produced by the call to the operator CALC_FONCTION[U4.32.04] with the keyword FFT.

The concept produced is a concept of type:

·     dyna_trans if the starting result transformed by FFT is of type dyna_harmo,

·     dyna_harmo if the starting result transformed by FFT is of type dyna_trans,

·     tran_gene if the starting result transformed by FFT is of type harm_gene,

·     harm_gene if the starting result transformed by FFT is of type tran_gene.

## 2 Syntax

```text
/ tran_gene
/ dyna_trans
/ harm_gene
/ dyna_harmo = REST_SPEC_TEMP(
    ◇ INFO = / 1 (par défaut),
             / 2,
    ◆ / RESU_GENE = tran_gene / harm_gene,
      / RESULTAT = dyna_trans / dyna_harmo,
    ◇ METHODE = / "PROL_ZERO" (par défaut),
                / "TRONCATURE",
    ◇ SYMETRIE = / "OUI" (par défaut),
                 / "NON",
    ◇ TOUT_CHAM = "OUI" (ou non renseigné),
    ◇ NOM_CHAM = / "DEPL",
                 / "VITE",
                 / "ACCE",
    # Si: equal_to("METHODE",'PROL_ZERO' )
        ◆ N_PUIS = int,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Operands RESU_GENE / RESULTAT

```text
♦/ RESU_GENE= tg
```

This keyword may be used if the concept to be transformed by direct or inverse FFT is a transient evolution result in generalised coordinates of type tran_gene or a frequency evolution result of type harm_gene.

```text
/ RESULTAT = resu
```

This keyword may be used if the concept to be transformed by direct or inverse FFT is a transient evolution result on the physical basis of type dyna_trans or a frequency evolution result of type dyna_harmo.

### 3.2 Operands TOUT_CHAM / NOM_CHAM

```text
◊/ TOUT_CHAM = 'OUI'
```

Makes it possible to transform by direct or inverse FFT the fields of symbolic name DEPL, VITE and ACCE contained in the generalised result (tran_gene, harm_gene) or on the physical basis (dyna_trans, dyna_harmo).

```text
◊/ NOM_CHAM = nomcha
```

List of the symbolic names of the fields that one wishes to transform by direct or inverse FFT: 'DEPL', 'VITE', 'ACCE'.

### 3.3 Operand METHODE

```text
◊METHODE =
```

The FFT algorithm accepts as input only a signal whose number of samples, in time or in frequency according to the case, is a power of 2.

The method 'PROL_ZERO' (by default) proposes to extend the input signal with zeros until one has a total number of samples which is the first power of 2 whose value is greater than the initial number of samples.

The method 'TRONCATURE' will consider only the first samples whose total number is the greatest power of two whose value is less than the initial number of samples.

For example, on a signal of 601 values, the method 'PROL_ZERO' will complete the signal in order to have 1024 samples, whereas the method 'TRONCATURE' will consider only the first 512 time instants.

If the input signal has a number of samples which is a power of 2, the two methods are obviously equivalent: one takes the signal into account without modifying it.

#### 3.3.1 Operand N_PUIS

```text
◊N_PUIS = n,
```

Keyword which must be specified only in the case where one applies METHODE = 'PROL_ZERO'. This option makes it possible to extend the input signal with zeros until one has a total number of samples which is the first power of 2 whose value is greater than the initial number of samples + N_PUIS. In practice, one may choose any power of 2 in order to complete the signal with zeros. At a minimum, if one wishes to use METHODE = 'PROL_ZERO' in its classical way, one must enter N_PUIS = 0. An example is given in order to show the use of N_PUIS:

- One considers a time signal which goes up to ${T}_{max}=20.475s$ with a time step $\Delta t=0.005s$;
- If one transforms this signal with, for example, CALC_FONCTION (option FFT, method PROL_ZERO) one ends up with a Fourier transform which has a frequency step $\Delta f=1/(\Delta t+{T}_{max})$ with a maximum frequency ${f}_{max}=100\mathit{Hz}$;
- Now, if one carries out, for example, a harmonic analysis on the physical basis (with the aid of DYNA_VIBRA) for a number of frequencies greater than 1024 but less than 2048 (while keeping the same frequency step of the Fourier transform), one would have a maximum analysis frequency greater than $50\mathit{Hz}$. Then, if one returns to the time domain via the operator REST_SPEC_TEMP, with METHODE = 'PROL_ZERO', one completes up to 2048 frequencies (that is 100 Hz). The Fourier transforms (direct and inverse) therefore have the same normalisation and the analysis is correct;
- If, on the other hand, one decides to truncate the harmonic analysis at $30\mathit{Hz}$ (entirely legitimate for a seismic analysis, for example) one would have a number of frequencies less than 1024 (but greater than 512) and with the PROL_ZERO of REST_SPEC_TEMP one will complete up to $50\mathit{Hz}$. The signal at the output of REST_SPEC_TEMP would therefore have a factor of 2 with respect to the correctly normalised solution;
- In order to output the correct solution (if one decides to truncate the analysis at $30\mathit{Hz}$) one would have to complete not only up to 1024 but reach 2048. For that, it is therefore enough to add one extra power of 2, that is simply to enter the option N_PUIS = 1.

For a concrete example of the use of this keyword, one refers to modelling C of the test case sdls119.

### 3.4 Operand SYMETRIE

```text
◊SYMETRIE =
```

Keyword which applies only to the inverse Fourier transform (from the frequency domain to the time domain). The (complex) spectrum supplied as input to the inverse FFT must comply with certain rules (in particular in order to recover a real time function): with respect to its mid-point, its real part must be symmetric and its imaginary part antisymmetric. In general, if this spectrum comes from an FFT computation, then these symmetry conditions are satisfied (except for a voluntary truncation). On the other hand if one has only half of the spectrum, then this must be indicated to the FFT computation operator.

This information on the symmetry of the spectrum is handled by the keyword SYMETRIE. If the spectrum is complete and therefore satisfies the symmetries, then the user must specify SYMETRIE = 'OUI'. Conversely, if the spectrum is truncated, then one should choose SYMETRIE = 'NON'. The spectrum is then symmetrised: this leads to a multiplication by 2 of its number of samples and therefore of its maximum frequency.

Consequently, this operand applies only if the result to be transformed is a generalised frequency evolution (harm_gene) or one on the physical basis (dyna_harmo).
