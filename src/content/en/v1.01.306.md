This test validates the programming of the ecla2d.f and ecla3d.f routines

  - Hexahedron / FPG27

  - Tetrahedron / FPG1 → XFEM90

## 1 Test principle

For each model, the mesh is very simple: formed from 1 to 4 elements.

An analytical field (CH1) is created on the Gauss points of the elements using a formula dependent on the $(X,Y,Z)$ coordinates.

The field (CH1) is then projected to the same mesh. This produces the field (CH2).

## 2 Validation

### 2.1 modellings A à E

For each model, the value of TOUS is tested for Gauss points of the integration diagrams.

CH1 values tested in 'NON_REGRESSION'

CH2 values tested in 'ANALYTIQUE'

### 2.2 Modelling F

This Modelling projects a field from a mesh cell tetrahedron FEM to a mesh cell ttetrahedron X-FEM. The CH1 field is therefore stored on a single point Gauss, while the CH2 field is stored on a family of 90 Gauss points. Furthermore, the interface considered corresponds to the cutting of the element tetrahedron into 4 sub-tetrahedrons, which implies that only 60 Gauss points out of the 90 available actually store a value.

$C$ is the value stored by the unique point Gauss in the CH1 field. The first 60 Gauss points in the CH2 field store the $C$ value, while the last 30 Gauss points store the 0 value, so the sum of the CH2 calors is equal to $60C$ and the largest stored value is $C$.

In order not to overburden the command file using 90 analytical value tests:

- The only value of CH1 is tested in 'NON_REGRESSION',
- The sum of the CH2 values and the highest CH2 value are tested in 'ANALYTIQUE'.
