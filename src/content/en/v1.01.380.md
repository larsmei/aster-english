# v1.01.380 ZZZZ380 - Adding fictitious degrees of freedom for multigrill solvers

**Summary:**

This test shows the value of adding fictitious degrees of freedom when using PETS c multigrill solvers and dualized kinematic conditions requiring the use of the ELIM_LAGR='OUI' keyword.

## 1 Test principle:

A simple mechanical problem with boundary conditions type LIAISON_MAIL is solved.

The dualization of these boundary conditions prevents the use of multigrill solvers of PETS c

(because of the degrees of freedom of Lagrange).

So you have to use the ELIM_LAGR='OUI' feature.

But the code, to eliminate each degree of freedom from Lagrange is forced to eliminate a physical degree of freedom.

Ultimately, some nodes have less degrees of freedom than others, which theoretically prevents the efficient use of multigrill solvers.

In this case, the code adds fictitious degrees of freedoms so that all nodess in the model have the same number of degrees of freedoms and can be used more efficiently with 'GAMG', 'BOOMER' and 'ML' solvers.

This test shows that this strategy is interesting: the number of iterations to converge is very much reduced by adding fictitious degrees of freedom:

| Solver | BOOMER | ML | GAMG |
| --- | --- | --- | --- |
| Without degrees of freedom | 375 | 38 | 478 |
| With degrees of fictitious freedom | 50 | 24 | 41 |

This documentation is deliberately succinct.
