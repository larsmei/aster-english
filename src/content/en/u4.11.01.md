# u4.11.01 Procedure DEBUT

## 1 Purpose

Assign the memory, disk and file resources.

The execution consists of a set of commands beginning with DEBUT and ending
with [FIN](doc:u4.11.02).
See also the procedure [POURSUITE](doc:u4.11.03).

The command DEBUT carries out the following tasks:

- Definition of the characteristics of the databases (managed by JEVEUX) and
allocation of the associated files,
- Reading of the catalogues of the elements and of the commands.

The apparently complex syntax of this procedure should not worry the user;
calling it with the default operands, sufficient in most cases, is: DEBUT().

## 2 Syntax

```text
DEBUT(
    ◇ IMPR_MACRO = / "NON" (par défaut),
                   / "OUI",
    ◇ BASE = _F(
         ◆ FICHIER = / "GLOBALE",
                     / "VOLATILE",
         ◇ TITRE = text,
         ◇ CAS = text,
         ◇ NMAX_ENRE = int,
         ◇ LONG_ENRE = int,
         ◇ LONG_REPE = int,
      ),
    ◇ CATALOGUE = _F(
         ◆ FICHIER = text,
         ◇ UNITE = unit,
      ),
    ◇ CODE = / "NON",
             / "OUI",
    ◇ ERREUR = _F(
         ◇ ERREUR_F = / "ABORT",
                      / "EXCEPTION",
         ◇ ALARME = / "ALARME",
                    / "EXCEPTION",
      ),
    ⟐ DEBUG = _F(
         ◇ JXVERI = / "NON" (par défaut),
                    / "OUI",
         ◇ SDVERI = / "NON" (par défaut),
                    / "OUI",
         ◇ JEVEUX = / "NON" (par défaut),
                    / "OUI",
         ◇ ENVIMA = "TEST" (ou non renseigné),
         ◇ VERI_BASE = / "GLOBALE",
                       / "VOLATILE",
         ◇ VERI_BASE_NB = int (défaut: 125),
      ),
    ⟐ MESURE_TEMPS = _F(
         ◇ NIVE_DETAIL = / 0,
                         / 1 (par défaut),
                         / 2,
                         / 3,
         ◇ MOYENNE = / "NON" (par défaut),
                     / "OUI",
      ),
    ⟐ MEMOIRE = _F(
         ◇ TAILLE_BLOC = float (défaut: 800.0),
         ◇ TAILLE_GROUP_ELEM = int (défaut: 1000),
      ),
    ⟐ RESERVE_CPU = _F(
         ◇ / VALE = int,
           / POURCENTAGE = float,
      ),
    ⟐ RESERVE_MEMOIRE = _F(
         ◇ / VALE = int,
           / POURCENTAGE = float,
      ),
    ◇ IGNORE_ALARM = list[text],
    ◇ LANG = text,
    ◇ INFO = / 1 (par défaut),
             / 2,
    ◇ MODE = / "AUTO" (par défaut),
             / "DEBUT",
             / "POURSUITE",
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Displays

At the start of the execution, a header is displayed. It contains:

- The precise identification of the version used: version number, date of the
latest modifications,
- The date and time of the start of the execution,
- The name, the architecture and the operating system of the machine,
- The language used for the display of the messages,
- The type of parallelism available (MPI/OpenMP), the number of processors allocated,
- The version of the libraries used (when it is available) for hdf5, med, mumps, scotch,
- Then several pieces of information on the distribution of the memory. For example:

```text
Mémoire limite pour l'allocation dynamique : 1894.40 Mo
  ajouté à l'initialisation du processus : 1125.45 Mo
         Limite cible du processus : 3019.85 Mo
```

This means:

- 1894.40 Mo is the quantity of memory reserved for the internal objects.
In detail: the user requested 1536.00 Mo. 10% was removed (default value of
RESERVE_MEMOIRE/POURCENTAGE), leaving 1382.40 Mo. 512.00 Mo is always added for the internal Jeveux objects, giving 1894.40 Mo.
- 1125.45 Mo is consumed simply by starting the execution (loading of the executable,
of the associated dynamic libraries, and so on). It is a measured value.
- 3019.85 Mo is the sum of the two previous values. It is the total quantity of memory
that must not be exceeded.

During the execution, depending on the dynamic allocations carried out, when this
value varies by more than 10% (upwards or downwards), a message of this type informs
the user:

```text
La mémoire consommée actuellement hors JEVEUX est de 214.08 Mo.
La limite de l'allocation dynamique JEVEUX est fixée à 41.92 Mo.

En fin d'exécution, un bilan indique si le même calcul peut être relancé avec moins de mémoire:

La mémoire demandée au lancement est surestimée, elle est de 256 Mo.
Le pic mémoire utilisée est de 216.02 Mo.
```

or if more memory is necessary (indeed, depending on the platforms, the maximum limit
may be exceeded without the system having interrupted the analysis):

```text
La mémoire demandée au lancement est sous-estimée, elle est de 256 Mo.
Le pic mémoire utilisée est de 273.22 Mo.
```

## 4 Operands

### 4.1 Keyword IMPR_MACRO

Allows or disallows the displays produced by the macros in the message file.
Reading the message files can be tedious when they contain all of
the echoes of the sub-commands generated by the macro itself. By default, only the echo
of the commands explicitly called by the user in the command set will appear.

### 4.2 Keyword LANG

It makes it possible to choose the display language of the messages issued by the code.

If the keyword is not set, it is the environment variables that determine
the language of the messages (reference:
[gettext manual](http://www.gnu.org/software/gettext/manual/gettext.html)).
One may for example define in the file ~/.bashrc: export LANG=fr_FR.UTF-8.

The encoding (UTF-8 or ISO-8859-1) makes it possible to display accented characters correctly.

The keyword LANG expects a two-letter value, for example 'FR' (for French)
or 'EN' (for English).

When a language is chosen (whether by the environment or by LANG), the
translated message file (.mo file) must still be available. This file is
expected under this name:

:file:`$ASTER_ROOT/share/locale/<lang>/LC_MESSAGES/aster_<version>.mo`

where $ASTER_ROOT is the main directory of the installation (e.g.: /aster or /opt/aster),
lang is the lower-case name of the language (e.g. en, fr, de...) and version is the name of
the version used (e.g. stable, testing, unstable).

If the translation file cannot be read, French is used.

**Note**

Even if the translation file exists, when a message has not been translated,
it is displayed in French (the language in which the messages are written in the source code).

### 4.3 Keyword BASE

The purpose of this keyword is to redefine the values of the parameters of the
direct-access files associated with the "databases" in the case where one does not wish to use
those set by default.

Default values of the parameters associated with the databases.

| **GLOBALE** |  |
| --- | --- |
| NMAX_ENRE | 62914 |
| LONG_ENRE | 100 Kwords |
| LONG_REPE | 2000 |
| **VOLATILE** |  |
| NMAX_ENRE | 62914 |
| LONG_ENRE | 100 Kwords |
| LONG_REPE | 2000 |

The word is worth 8 bytes on a 64-bit platform, 4 bytes on a 32-bit platform.

Under 64-bit Linux, with the default values, the procedure DEBUT will allocate a direct-access file of at most 62914 records of 100 Kwords (K is worth 1024) for the 'GLOBALE' database.

**Note**

The real size of the file is dynamic; it depends on the volume of information
actually to be stored.
The information is stored in files not exceeding 12 Go each.
This value can be modified by passing an argument on the command line
of the executable after the keyword `--max_base=taille`, where taille is a
real value measured in Mo.
For the Globale database, which can be saved and reused as input to an analysis,
the initial maximum size in POURSUITE is kept as it is if the parameter
`--max_base` is not used, but it may be redefined if needed in this way.
In practice, this option is not useful, the maximum size being 2 To.

#### 4.3.1 Operand FICHIER

Symbolic name of the database concerned.

#### 4.3.2 Operands LONG_ENRE / NMAX_ENRE / LONG_REPE

Definition of the parameters of the database (direct-access files).

LONG_ENRE is the length of the records, in Kwords, of the direct-access files used.

**Note**

The JEVEUX memory manager uses this parameter to determine two types
of object: the large objects, which will be split into as many records as
necessary, and the small objects, which will be accumulated in a buffer the size
of one record before being unloaded.

NMAX_ENRE is the default number of records; this value is determined from
LONG_ENRE and from an operational parameter on the Linux 64 reference platform,
set to 2 To for the maximum total size of a database, if this value has not been modified by the use of the keyword `--max_base`
on the command line of the executable.

**Note**

The two operands LONG_ENRE and NMAX_ENRE must be used with care,
incorrect use being able to lead to an abrupt stop of the program by saturation of the
direct-access files. Consistency between the maximum size of the file and
the value resulting from the product of the two parameters LONG_ENRE and NMAX_ENRE is
checked at the start of the execution.

LONG_REPE is the initial length of the directory (maximum number of objects addressable by JEVEUX);
it is managed dynamically by the memory manager, which extends the size of the directory
and of all the associated system objects as needs arise.

**Note**

The user's choice to modify these various parameters definitively determines
certain characteristics of the GLOBALE database, which can no longer be
modified in POURSUITE.

### 4.4 Keyword CODE

This keyword is intended only for the command files of the test cases.
It modifies the behaviour in the event of an error or an exception, and activates the coverage
of the keywords...

### 4.5 Keyword ERREUR

Makes it possible to modify the behaviour of the code in the event of an <F> error.

#### 4.5.1 Operand ERREUR_F

In the event of an error, the code interrupts the normal execution of the command set.

By default, an exception is then raised (for the detailed definition of a Python exception,
one should refer to the Python documentation or to that of the supervisor, cf. [U1.03.01](doc:u1.03.01)).
In this case, the code executes the command FIN (cf. [U4.11.02](doc:u4.11.02)), which then closes the database so as to allow a possible restart of the analysis. It will be noted that, although the initial error is said to be "fatal" (<F>), the diagnosis is <S>_ERROR because the exception is "caught" by FIN.
This database will then be copied by the study manager. This is the behaviour when ERREUR_F='EXCEPTION'.

If ERREUR_F='ABORT', this means that one explicitly asks the code to interrupt definitively the execution of the command set in the event of a fatal error (<F>). The command FIN is not executed, the database is therefore not closed correctly, it is not copied and no restart of the analysis is possible.

**Notes**

For the execution of the test cases by the developers, stopping by ABORT is automatic and is the default. This is activated by the presence of the factor keyword CODE (unless ERREUR_F specifies something else).

In the event of a lack of CPU time or of memory, for all errors of type <S> and for exceptions, the behaviour is that described when ERREUR_F='EXCEPTION'.

### 4.6 Keyword IGNORE_ALARM

Allows the user to suppress the display of certain alarms (whose origin is known) in order to identify more easily the other alarms that might appear.

During the execution of the command FIN, a summary table of the alarms issued during the execution (and the number of occurrences) is systematically displayed. The alarms ignored by the user are preceded by '*' to distinguish them (and they appear even if they have not been issued).

The alarms are designated from the nomenclature appearing between the characters < and >, for example: IGNORE_ALARME = ('MED_2', 'SUPERVIS_40',...).

### 4.7 Keyword DEBUG

Debugging option (reserved for developers and for maintenance of the code).

#### 4.7.1 Operand JXVERI

Makes it possible to check the integrity of the memory segments between two consecutive command executions. By default the execution is carried out without "DEBUG". This option is systematically activated in the presence of the keyword CODE.

#### 4.7.2 Operand ENVIMA

Makes it possible to display the values of the parameters defined in the routine ENVIMA characterising the machine [D6.01.01](doc:d6.01.01).

#### 4.7.3 Operand JEVEUX

Makes it possible to activate the debug operating mode of the JEVEUX memory manager: non-deferred unloading to disk and assignment of the value segments to an undefined value [D6.02.01](doc:d6.02.01).

#### 4.7.4 Operand SDVERI

Use of this keyword is intended for developers. Warning: this functionality can cause a non-negligible extra cost during the execution.

This keyword triggers the checking of the data structures produced by the operators. It is used within the code development procedures in the non-regression tests. If the keyword CODE is present, this keyword takes the default value 'OUI'.

### 4.8 Keyword MESURE_TEMPS

The keyword MESURE_TEMPS makes it possible to choose the level of detail of the CPU time printouts that will be displayed in the message file by the commands carrying out elementary computations, resolutions of linear systems, unloading of objects to disk or MPI communications.

#### 4.8.1 Operand NIVE_DETAIL

```text
◊    NIVE_DETAIL    =    0 aucune impression.
                    =    1 impressions par défaut.
                    =    2 impressions plus détaillées:
                    =    3 impressions plus détaillées et impression
                           incrémentale pour chaque pas de temps.
```

#### 4.8.2 Operand MOYENNE

The keyword MOYENNE makes it possible to control the display of additional statistics
exclusively for parallel analyses. These are the mean of the measurements over all
the processors and the standard deviation of these measurements.

Each displayed time is then completed as follows:

```text

(moyenne....diff..procs) CPU (USER+SYST/SYST/ELAPS): 0.30 0.00 0.47
(écart-type.diff..procs) CPU (USER+SYST/SYST/ELAPS): 0.01 0.00 0.05
```

### 4.9 Keyword MEMOIRE

The allocation of the various data structures is a dynamic allocation;
the user indicates the resource limits when launching the executable in the access interface.

#### 4.9.1 Operand TAILLE_GROUP_ELEM

This parameter gives the maximum number of finite elements of the same type that will be grouped
in a group of elements.

This parameter influences the memory and CPU performance of the elementary computations and of the assemblies.

When tgrel is increased, one should in general gain CPU time. On the other hand, the
JEVEUX objects are larger, which may require more memory.

#### 4.9.2 Operand TAILLE_BLOC

This parameter gives the size of the blocks of the factorised matrices for the LDLT solver.
This size is given in kiloR8 (1 kiloR8 = 1024 reals). This parameter affects the
number of input/output operations and therefore the assembly and resolution time.
By default this value is set to 800 kiloR8, that is 8 records by default
on the direct-access file associated with the JEVEUX database.

### 4.10 Keyword CATALOGUE

This keyword is reserved for developers; it is used during the operation of compiling
the element catalogues in order to obtain the file in the form of a JEVEUX database.

#### 4.10.1 Operand FICHIER

Can only take the value 'CATAELEM'.

#### 4.10.2 Operand UNITE

Number of the logical unit associated with the element catalogues. In the procedures for
building the element catalogue, the value 4 is used. The file fort.4
is obtained from the content of the source directory by means of a Python procedure.

### 4.11 Keyword RESERVE_CPU

Makes it possible to reserve a share of the CPU time allocated to the job in order to terminate the execution cleanly
in the event of a stop for lack of CPU time detected by a command.
This mechanism is useful only in the case of a batch execution.
The value of this reserve may be given as an absolute value or else in the form
of a percentage of the total CPU time.

When the keyword CODE is present, that is for all the tests,
a CPU time reserve of 10 seconds is systematically imposed if the keyword VALE is absent.

At the end of the execution, it may be necessary to carry out compression operations
before transfer of the result files or of the Globale database, which are sometimes very costly.

#### 4.11.1 Operand VALE

This is the value, expressed in seconds, subtracted from the total CPU time, on which
certain global commands rely in order to stop the execution cleanly.

#### 4.11.2 Operand POURCENTAGE

Percentage subtracted from the total CPU time, on which certain global commands rely in order to stop the execution cleanly.

### 4.12 Keyword RESERVE_MEMOIRE

Makes it possible to reserve a share of the memory allocated to the job for the objects other than the internal Jeveux objects (those whose size cannot be measured precisely).
This mechanism is useful only in the case of a batch execution.
The value of this reserve may be given as an absolute value or else in the form
of a percentage of the memory requested initially.

#### 4.12.1 Operand VALE

This is the value expressed in Mo (1024 ko, that is 1024 x 1024 bytes) that will be subtracted from the quantity of memory requested initially.

#### 4.12.2 Operand POURCENTAGE

Percentage of the memory requested initially that will be allocated to the reserve and therefore not available for the Jeveux objects.
