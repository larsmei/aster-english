# u4.81.04 Operator CALC_CHAMP

## 1 Purpose

Create or complete a result by computing fields by element or at the nodes (stresses, strains, …).

The result concept produced is either created or modified, that is, the call to CALC_CHAMP is made in the following way:

```python
resu = CALC_CHAMP(reuse=resu, RESULTAT=resu, ...)
```

or else

```python
resu1 = CALC_CHAMP(RESULTAT=resu, ...)
```

## 3 Operands RESULTAT/MODELE/CHAM_MATER/CARA_ELEM/EXCIT

### 3.1 Operands RESULTAT

```text
♦    RESULTAT=    resu
```

Name of the result data structure to be enriched. This argument may be the same as that used for the concept enriched by the operator, or a different name, which will create a new result data structure.

**Notes**

In the majority of situations, the data structure resu contains all the information required for the computation of the options: the model, the material field, the elementary characteristics, the loadings. The keywords MODELE, CHAM_MATER, CARA_ELEM and EXCIT are therefore useless;

A notable exception, however, concerns the dynamic data structures produced by DYNA_VIBRA, for which the user must himself ensure the consistency of the keywords between the analysis operator and CALC_CHAMP. An alarm warns him of this.

### 3.2 Operands MODELE / CHAM_MATER / CARA_ELEM.

```text
◊    MODELE= mo
```

Name of the model on which the forces, the stresses, the strains, and so on, are computed.

It is optional because it can be extracted from the result.

```text
◊    CHAM_MATER= chmater
```

Material field associated with the model mo. This keyword is optional and must be supplied only in exceptional cases (deliberate modification of the material, for example).

```text
◊    CARA_ELEM= carac
```

Elementary characteristics associated with the model mo if it contains structural elements or if the isoparametric elements are affected by a local anisotropy frame.

This keyword is optional because it can be extracted from the result.

### 3.3 Keyword EXCIT

This factor keyword (optional) makes it possible to specify the thermal or mechanical loadings to be used for the computation of the options, in place of those which were used in the analysis of the data structure specified under the keyword RESULTAT.

The definition of this keyword is identical to that of the commands which built the data structure resu: see the commands MECA_STATIQUE [U4.51.01](doc:u4.51.01), STAT_NON_LINE [U4.51.03](doc:u4.51.03), DYNA_VIBRA [U4.53.03](doc:u4.53.03).

## 4 Selection of the mesh cells concerned by the analysis

The keywords TOUT and GROUP_MA allow the user to choose the mesh cells on which he wishes to perform his elementary post-processing computations.

```text
/    TOUT = 'OUI'
```

All the mesh cells (carrying finite elements) will be processed. This is the default value.

```text
/    GROUP_MA    =    l_grma
```

Only the mesh cells included in l_grma will be processed.

## 5 Selection of the order numbers

The use of the keywords TOUT_ORDRE, NUM_ORDRE, INST, FREQ is described in the document [U4.71.00](doc:u4.71.00).

In the case where there are many order numbers, it may be more efficient (in memory in particular) to call the command several times on sub-lists of the order numbers.

## 6 Localisation of the fields

In the remainder of the document one will not state explicitly the localisation of the fields. Indeed, the localisation is given in the name of the field (and therefore of the option):

- Field by element: x_ELEM
- Field at the Gauss points by element: x_ELGA
- Field at the nodes by element: x_ELNO
- Field at the nodes: x_NOEU

The fields are, for the most part, computed natively at the Gauss points ( x_ELGA).

The fields at the nodes by element ( x_ELNO) are obtained by extrapolation from the field at the Gauss points (method detailed in [R3.06.03](doc:r3.06.03)).

The fields at the nodes ( x_NOEU) are obtained from the fields at the nodes by element by taking a simple arithmetic mean (not weighted by the size of the mesh cells) of the values encountered on the elements at a given node.

**Note 1**

For the computation of the equivalents, the fields at the nodes by element ( x_ELNO) are not obtained by extrapolation from the field at the Gauss points. The extrapolation is done on the stress or strain field and then one computes the equivalent field.

**Note 2**

The averages at the nodes of fields computed in local frames are licit only if the angles between these frames are small. Otherwise, they have no meaning.

![Figure](/figures/u4.81.04/10000201000002230000016B7DC9A07AEB355496.png)

**Note 3**

When the keyword GROUP_MA is filled in for the computation of an option x_NOEU, the arithmetic mean is taken over the selected mesh cells. Thus this result is different from that obtained by performing a global computation and then restricting it to the selected mesh cells only.

Example: One considers a structure whose shear stress ${\sigma}_{xy}$ is:

In the global computation, ${\sigma}_{xy}$ is zero on $\mathit{M1}\cap \mathit{M2}$ as the average of two opposite values. These values are far from being zero, as the computation on $\mathit{M1}$ alone shows. The values on the boundary of the requested domain must therefore be interpreted with care.

For the structural elements which have sub-points (plates, shells, multi-fibre beams, pipes), the fields of type x_ELGA and x_ELNO are computed on all the sub-points. In order to obtain a field on a single sub-point (one layer and one level, for example), one must perform an extraction via the operator POST_CHAMP (options EXTR_COQUE, EXTR_PMF and EXTR_TUYAU). Moreover this intermediate operation is indispensable in order to compute a field of type x_NOEU for these structural elements: the fields of type x_NOEU indeed never have a sub-point.

Finally the energy-computation options never produce fields with sub-points. Indeed, for the structural elements, the field is integrated through the thickness (integration carried out on the sub-points).

## 7 Dependence of the fields

The computation of a field may require the prior computation of one or more other fields. Thus, for example, in order to compute a field x_NOEU it is necessary to have available the same field by element at the nodes x_ELNO and at the Gauss points x_ELGA.

This dependence is resolved by the operator CALC_CHAMP, which automatically carries out the computation of the intermediate fields. It is therefore not necessary for the user to know the dependence tree of the options.

Only the fields explicitly requested by the user are saved in the result data structure.

## 8 Operands for the mechanical options

### 8.1 Options for the computation of the stresses (Operand CONTRAINTE)

The components of the stress fields and of the generalised forces are detailed in the document [U2.01.05](doc:u2.01.05).

```text
|    'EFGE_ELGA'
|    'EFGE_ELNO'
|    'EFGE_NOEU'
```

Computation of the generalised forces (structural elements).

It is either an extraction of the forces contained in the field SIEF_ELGA/STRX_ELGA (the case of the beam/pipe elements or of the discrete elements), or a computation by integration of the stresses (the case of the multi-fibre beam elements or of plates and shells).

**Note 1**

The field EFGE_ELNO is not always an extrapolation of the field EFGE_ELGA; in particular for a linear analysis where this field is computed directly from the displacement. This is why certain components are not computed (set to zero) in non-linear analysis.

**Note 2**

For the offset plates, the forces are computed in the «plane» of the mesh. If one wishes these forces in the mean «plane» of the plate, one must use the command POST_CHAMP / COQUE_EXCENT.

```text
|    'SIEF_ELGA'
|    'SIEF_ELNO'
|    'SIEF_NOEU'
```

Computation of the stress state (stresses or generalised forces depending on the modelling) from the displacements (linear elasticity), see [U2.01.05](doc:u2.01.05).

For the incompressible formulations (INCO_UP, INCO_UPO and INCO_UPG), this tensor contains, in addition to the components SIXX, SIYY, SIZZ, SIXY, SIYZ and SIXZ in 3D, the component SIP which is the hydrostatic pressure. This component is computed from the trace of the stresses (part of the constitutive law) and from the unknowns PRES and GONF (for INCO_UPG) of the field of the nodal unknowns. The components SIXX, SIYY and SIZZ are then the purely deviatoric contributions of the stress tensor.

**Note**

The field 'SIEF_ELGA' is computed natively by the non-linear solution operators. It is always present in a result data structure of type evol_noli.

```text
|    'SIGM_ELGA'
|    'SIGM_ELNO'
|    'SIGM_NOEU'
```

Computation of the stress state.

It is in reality an extraction of the stresses contained in the field SIEF_ELGA, see [U2.01.05](doc:u2.01.05).

```text
|    'SIMY_ELGA'
```

Computation of the stress state averaged by element (component by component).

```text
|    'SIPO_ELNO'
|    'SIPO_NOEU'
```

Computation of the stresses in the beam section broken down into contributions of each generalised force.

List of the components of the field:

| SN | Contribution of the normal force $N$ to ${\sigma}_{xx}$ , ${\sigma}_{xx}=\frac{N}{A}$ |
| --- | --- |
| SMFY | Contribution of the bending moment $\mathit{MFY}$ to ${\sigma}_{xx}$ , ${\sigma}_{xx}=z\frac{\mathit{MFY}}{{I}_{Y}}$ |
| SMFZ | Contribution of the bending moment $\mathit{MFZ}$ to ${\sigma}_{xx}$ , ${\sigma}_{xx}=-y\frac{\mathit{MFZ}}{{I}_{Z}}$ |

These fields are evaluated from a stress field computed on the volume mesh cells (MODELISATION=‘3D’ or ‘3D_SI’) or surface mesh cells (MODELISATION=‘D_PLAN’ or ‘D_PLAN_SI’). For volume mesh cells, the procedure is the following:

- Identification of the volume mesh cells corresponding to the facets of the surface mesh-cell group. For each facet (surface mesh cell), one chooses the volume mesh cell located on the «-» side of the normal to the facet. If there is no volume mesh cell on the «-» side of the facet, one does not compute SIRO_ELEM on this facet;
- Recovery of the 3D stresses in order to assign them to the nodes of the faces;
- Average of each of the components of the stress tensor at the centre of the element faces;
- One places oneself in a frame composed of the normal vector $\overrightarrow{n}$ to the facet and the plane of the facet. One obtains a tensor denoted $[\sigma \text{}]$ .
- One evaluates $[\sigma \text{}]\overrightarrow{n}=\overrightarrow{\sigma}{\rbrace _{n}+\overrightarrow{\sigma}{\rbrace _{t}$ , $\overrightarrow{\sigma}{\rbrace _{n}$ being a vector collinear with $\overrightarrow{n}$ . $\overrightarrow{\sigma}{\rbrace _{t}$ is then a vector representing the shear, which is negligible in the case of the upstream/downstream facings of a dam. One writes $\overrightarrow{\sigma}{\rbrace _{n}={\mathit{SIG}}_{N}\overrightarrow{n}$ and ${\mathit{SIG}}_{N}$ indicates the presence of tension if it is positive and of compression if it is negative.
- One places oneself under the assumption of negligible shear, hence $[\sigma \text{}]=\left[\begin{array}{cc}\sigma {\rbrace _{\mathrm{2D}}& 0\\ 0& {\mathit{SIG}}_{N}\end{array}\right]$ One looks for the principal-stress vectors corresponding to $\sigma {\rbrace _{\mathrm{2D}}$ : one therefore obtains the vectors $\vec{\sigma}{\text{\%}}_{t1}$ and $\overrightarrow{\sigma}{\rbrace _{\mathit{t2}}$ which lie in the plane of the facet and the eigenvalues ${\mathit{SIG}}_{\mathit{T1}}$ and ${\mathit{SIG}}_{\mathit{T2}}$

For surface mesh cells, the procedure for evaluating the field SIRO_ELEM is the same as for the volume mesh cells, taking the following conventions into account:

- $\vec{{\sigma}_{t2}}$ collinear with the Z direction (a D_PLAN model being defined exclusively in the XY plane), $\vec{{\sigma}_{t1}}$ therefore lying in the XY plane.
- SIG_NZ = SIG_TZ = 0. and SIG_T1Z = SIGT2X = SIGT2Y = 0.
- ${\mathit{SIG}}_{\mathit{TN}}$ is the value of the shear stress in the XY plane.

**Note 1**

In the case of facets/edges immersed in the volume/surface, the user has the possibility, by means of the command MODI_MAILLAGE / ORIE_PEAU_3D / GROUP_MA_VOLU or MODI_MAILLAGE / ORIE_PEAU_2D / GROUP_MA_SURF, of reorienting this normal as he wishes. He can thus choose the volume mesh cell which will be used for the computation.

If, on the «-» side, one finds a «joint» mesh cell (which is a volume/surface mesh cell), the computation of SIRO_ELEM is impossible because the stresses stored in the joint elements do not allow the detailed computation above.

**Note 2**

If one fills in TOUT='OUI', the list of mesh cells is filtered so as to keep only the skin/edge mesh cells.

### 12.1 Operand FORCE

```text

```

Computation of the generalised nodal forces from the stresses at the Gauss points. List of the components of the field:

| DX DY DZ | Nodal forces |
| --- | --- |

Additional components for the thermo-hydro-mechanical modellings:

| PRE1 PRE2 TEMP | Nodal forces (hydraulic / thermal) |

| DRX DRY DRZ | Nodal forces (moments) |
| --- | --- |

The nodal forces correspond, in the finite-element sense, to the internal forces taking part in the equilibrium equations. The computation of the generalised nodal forces ${F}_{K}$ is done in the following way:

$$
\sum_{K}{\mathrm{F}}_{K}.{\mathrm{v}}_{K}={\int}_{\Omega}\sigma .\epsilon ({\mathrm{v}}_{K})d\Omega =\sum_{K}\underset{K}{\int}{\sigma}^{K}.\epsilon ({\mathrm{v}}_{K})\mathit{dK}=\sum_{K}\underset{K}{\int}{\sigma}^{K}.\mathrm{B}.{\mathrm{v}}_{K}\mathit{dK}
$$

With:

- ${\sigma}^{K}$ stresses at the Gauss points of the element $K$ ;
- $\mathrm{B}$ the finite-element operator of generalised strains (matrix relating the first-order strains to the generalised displacements);
- ${\mathrm{v}}_{K}$ generalised unit elementary displacement.

Hence:

$$
{\mathrm{F}}_{K}=\left\lbrace \underset{K}{\int}{}^{t}\mathrm{B}.{\sigma}^{K}\mathit{dK}\right\rbrace
$$

The dimension of the nodal forces is dual to that of the ${v}_{K}$ so as to give a work (in joules). For the solid elements (3D, 2D and bars), the FORC_NODA in general have the dimension of a force. It is a field on the nodes of the mesh in which the value at a node is obtained from the stresses computed on the elements meeting at that node; their values therefore vary when the mesh changes. In the absence of a distributed loading, equilibrium imposes that they be zero at an interior node, whereas they correspond to the reaction on the supports where a kinematic relation is imposed (the case of an imposed displacement).

**Two-dimensional case**

For the axisymmetric elements, the integration in $\theta$ is done over a sector of $1\mathit{radian}$ . If one wants the integral of the surface force over the whole disc one must therefore multiply by $2\pi$ .

For the plane-strain elements, the computation is done on a strip of unit width. The computed nodal forces are therefore in fact forces per unit length. If one wants to compute the nodal forces acting on a structure of width $l$ , one must multiply the result in D_PLAN by $l$ , except that the plane-strain assumption is not valid near the two faces. One will therefore have an approximate result.

**Case of the structural elements**

For the beam elements and the discrete elements, the stresses at the Gauss points are in fact the generalised nodal forces in the frame of the element (obtained by the product of the stiffness matrix of the element by the displacement and taking into account the forces of thermal origin and the distributed forces). The computation of the nodal forces is done by projecting the nodal forces contained in the field of symbolic name 'SIEF_ELGA' into the global frame. The summation above over the elements is then applied. The components DX, DY and DZ give the forces and DRX, DRY and DRZ the moments.

In the case of the shells, the components DX, DY and DZ give the FORC_NODA (of the dimension of a force) in the global frame of the mesh. These components are built with the normal and shear forces in the shell. The components DRX, DRY and DRZ give the FORC_NODA (of the dimension of a moment) in the global frame of the mesh, built with the bending moments in the shell. In the case of homogenised shell constitutive behaviours of type ELAS_COQUE, it is preferable to look at EFGE_NOEU.

**Case of thermo-hydro-mechanics (THM)**

In thermo-hydro-mechanics, cf. §8, [R7.01.10](doc:r7.01.10), the generalised nodal forces associated with each component correspond to the mechanical forces and to the fluxes. If one denotes by ${Q}^{T}{\sigma}_{0}$ the result of FORC_NODA, for the hydraulic equations, then for a time step $\Delta t$ , one has:

$$
\int_\Omega Q^T\sigma_0\cdot p^*d\Omega =-\int_\Omega \Delta m p^*d\Omega +
\Delta t\int_\Omega M^+\cdot \nabla {p}^*d\Omega.
$$

The fluxes are taken at the time instant $t^+=t^-+\Delta t$.

If one denotes by $q$ the thermal flux, $Q$ the heat supply, $M_w$, $M_{vp}$, $M_{as}$ and $M_{ad}$ the hydraulic fluxes of liquid water, of vapour, of dry air (or any other component) and of dissolved air, and by $m_w$, $m_{vp}$, $m_{as}$ and $m_{ad}$ their respective mass supply [R7.01.10](doc:r7.01.10), then the expression of FORC_NODA is the following:

- with the degree of freedom PRE1 is associated the water flux

$$
-\int_\Omega (\Delta m_w + \Delta m_{vp}) p^*d\Omega +\Delta t\int_\Omega (M_w^++{M}_{vp}^+)\cdot\nabla {p}^*d\Omega
$$

- with the degree of freedom PRE2 is associated the flux of the gaseous component

$$
-\int_\Omega (\Delta m_{as} + \Delta m_{ad}) p^*d\Omega+\Delta t\int_\Omega(M_{as}^++M_{ad}^+)\cdot\nabla {p}^*d\Omega
$$

- with the degree of freedom TEMP is associated the thermal flux

$$
-\int_\Omega \Delta Q T^*d\Omega+\Delta t\int_\Omega q^+\cdot \nabla {T}^{*}d\Omega
$$

Computation of the generalised nodal reaction forces at the nodes, from the stresses at the Gauss points and the loadings. List of the components of the field:

| DX DY DZ | Nodal reactions |
| --- | --- |
| Additional components for the structural elements: |  |
| DRX DRY DRZ | Nodal reactions (moments) |

The generalised nodal reactions correspond, in the finite-element sense, to the forces exerted on the supports (boundary conditions) taking part in the equilibrium equations.

**Case of statics**

In statics, for the result concepts of type evol_elas, mult_elas, fourier_elas or evol_noli, the computation of the generalised nodal reactions ${R}_{K}$ is done by:

$$
\sum_{K}{\mathrm{R}}_{K}.{\mathrm{v}}_{K}=\sum_{K}{\mathrm{F}}_{K}.{\mathrm{v}}_{K}-\mathrm{L}({\mathrm{v}}_{K})
$$

With:

- $\sum_{K}{\mathrm{F}}_{K}.{\mathrm{v}}_{K}$ the expression of the nodal forces (option FORC_NODA, see () and ());
- ${v}_{K}$ generalised unit elementary displacement.

And one therefore has:

$$
L({v}_{K})=\underset{\Omega}{\int}f\cdot {v}_{K}d\Omega +\underset{\Gamma}{\int}{F}_{s}\cdot {v}_{K}d\Gamma +\sum_{i}{F}_{i}\cdot {{v}_{K}}_{i}
$$

With:

- $f$ are the body forces;
- ${F}_{s}$ the generalised surface forces;
- ${F}_{i}$ the generalised point forces at the node $i$ .

The vector of the generalised nodal reactions on the element $K$ is therefore obtained from the generalised nodal forces:

$$
{\mathrm{R}}_{K}={\mathrm{F}}_{K}-\underset{K}{\int}\mathrm{f}\mathit{dK}-\underset{\partial K}{\int}\mathrm{F}\partial K-\sum_{i}{{\mathrm{F}}_{i}}_{K}
$$

in other words, one subtracts from the nodal forces the generalised external forces applied to the element $K$ .

**Note**

It is to be noted that the temperature loading does not appear in the external forces: it enters the expression of the stresses via the constitutive law.

**Case of non-linear transient dynamics**

For the result concepts of type evol_noli coming from non-linear transient dynamic analyses, in order to obtain the nodal reactions, one must in addition remove the inertia forces (acceleration) and the damping forces linked to the velocity:

$$
\sum_{K}{\mathrm{R}}_{K}.{\mathrm{v}}_{K}=\sum_{K}{\mathrm{F}}_{K}.{\mathrm{v}}_{K}+(\mathrm{M}\ddot{\mathrm{u}})\cdot {\mathrm{v}}_{K}-\mathrm{L}({\mathrm{v}}_{K})
$$

Where:

- $\sum_{K}{\mathrm{F}}_{K}.{\mathrm{v}}_{K}$ the expression of the nodal forces (option FORC_NODA, see () and ());
- ${v}_{K}$ generalised unit elementary displacement.
- $M$ is the mass matrix;
- $\ddot{u}$ the generalised acceleration field;
- $L$ the vector of the applied generalised external forces (equation ()).

**Notes**

The contributions of the damping linked directly to the velocity on the nodal reactions are neglected;

The computation of the inertia forces requires the presence of the acceleration field ACCE in the data structure resultat. In the case of a structure of type evol_noli, it is not possible for the code to check its presence; one must therefore take care.

**Case of modal dynamics**

For the result concepts of type mode_meca (coming from modal analyses) the formula is:

$$
\sum_{K}{R}_{K}.{v}_{K}=\underset{\Omega}{\int}\sigma (\varepsilon (u)).\varepsilon ({v}_{K})d\Omega -{\omega}^{2}(M\cdot u)\cdot {v}_{K}
$$

Where:

- $\sigma (\varepsilon (u))$ are the generalised modal stresses;
- $M$ is the mass matrix;
- $\omega$ the eigen angular frequency;
- $u$ the generalised displacement field of the mode;
- ${v}_{K}$ generalised unit elementary displacement.

**Case of linear transient dynamics**

For the result concepts of type dyna_trans coming from linear transient dynamic analyses (DYNA_VIBRA/TYPE_CALCUL='TRAN') or of type dyna_harmo coming from harmonic analyses (DYNA_VIBRA/TYPE_CALCUL='HARM') the expression of the generalised nodal reactions is obtained by:

$$
\sum_{K}{\mathrm{R}}_{K}.{\mathrm{v}}_{K}=\sum_{K}{\mathrm{F}}_{K}.{\mathrm{v}}_{K}+(\mathrm{M}\ddot{\mathrm{u}})\cdot {\mathrm{v}}_{K}-\mathrm{L}({\mathrm{v}}_{K})
$$

Where:

- $\sum_{K}{\mathrm{F}}_{K}.{\mathrm{v}}_{K}$ the expression of the nodal forces (option FORC_NODA, see () and ());
- ${v}_{K}$ generalised unit elementary displacement.
- $M$ is the mass matrix;
- $\ddot{u}$ the generalised acceleration field;
- $L$ the vector of the applied generalised external forces (equation ()).

**Use of** GROUP_MA **in** FORC_NODA **and** REAC_NODA

If the keyword GROUP_MA is filled in, ${F}_{K}$ (option FORC_NODA) is computed only on the requested elements and then assembled. The result is different from a global computation over the whole domain then reduced to the requested elements. The implemented method makes it possible to measure the reaction of one piece of the model on another.

**Caution! The computation of 'REAC_NODA' on a subset of the model (via the keyword GROUP_MA) must be done with care. Example 4 below illustrates this type of computation.**

For results of type dyna_harmo, 'REAC_NODA' is computed only on the model as a whole. The computation on a subset of the model can be carried out manually by performing a computation of 'FORC_NODA' on the mesh-cell group in question and then subtracting the external force from the results obtained.

**Notes**

The nodal reactions are zero at every interior point of the model and are not zero a priori at a point of the boundary subjected to a kinematic boundary condition (or to contact forces);

Neglecting the contribution of the **damping in dynamics** may create a slight discrepancy with respect to the exact result;

Only the resultant of the forces or of the nodal reactions on a node group has a physical meaning (this group must correspond to at least one element of the model, for example a boundary subjected to a boundary condition). It may be computed with POST_RELEVE_T [U4.81.21]. Locally, the field FORC_NODA or REAC_NODA must not be interpreted, because the value at a node is directly linked to the fineness of the mesh. Moreover the sign of these forces on the nodes of one and the same element may be counter-intuitive, whereas it is perfectly in agreement with the theory of finite elements (for example on QUAD8 mesh cells located at the interface of a zone in pure compression, the signs of the nodal forces at the vertices and at the mid-sides are opposite);

The computation of REAC_NODA takes into account the distributed loadings on the beams. As soon as one varies this loading over a non-linear analysis (change of EXCIT from one time step to the next), the computation of REAC_NODA is forbidden. It is necessary to divide one's post-processing into «batches» of order numbers, for which the loading is constant (that is, it uses the same AFFE_CHAR_MECA concept in EXCIT).

Some loadings are not taken into account during the computation of this option; they are: INTE_ELEC, FORCE_SOL and RELA_CINE_BP.

**Case of the HHO modellings**

In the case of the HHO modellings, the fields FORC_NODA and REAC_NODA are not forces but stresses.
Moreover, this field is not defined at the nodes and is continuous.

## 13 Computation of a user field

The factor keyword CHAM_UTIL makes it possible to compute arbitrary fields, called «user» fields because of the name which will be assigned to them in the result concept.

There may be several occurrences of CHAM_UTIL in order to chain the computation of several fields.

The processing being carried out at the end of the command CALC_CHAMP, the fields computed by the preceding keywords (CONTRAINTE, DEFORMATION...) are available here.

Either one requests the computation of a predefined criterion, or one applies one or more formulae in order to compute another field.

### 13.1 Operand NOM_CHAM

This is the field from which one performs the computations. The field produced will have the same type: ELGA, ELNO or NOEU.

### 13.2 Operand CRITERE

Requests the computation of a predefined criterion. The criteria are (paragraph  2.6.5 provides the expressions of each criterion):

- VMIS (for the stress fields),
- INVA_2 (for the strain fields),
- TRACE (for the stress or strain fields).

Each of these criteria produces one component (named X1).

One of the advantages is to be able to compute INVA_2 of any strain field.

### 13.3 Operand FORMULE

This makes it possible to compute any expression as a function of the components of the field supplied for NOM_CHAM.

The field produced will contain as many components as formulae supplied: the component X1 will correspond to the first formula, X2 to the second, and so on. Up to 30 components may thus be created.

The output field is systematically extended by zero on the other components and where the input field is not defined.

Examples of formulae making it possible to recover the criteria VMIS and INVA_2 can be found in the second part of the test sslv104a.

### 13.4 Operand NORME

Requests the computation of a predefined norm. The norms are:

- L2: norm ${L}_{2}$ of a tensor
- FROBENIUS: Frobenius norm of a tensor

The computed norm is a quantity integrated (in the weak sense) over an element ${\Omega}_{e}$ . For a tensor $A$ , the ${L}_{2}$ norm is:

$$
{N}_{{L}_{2}}={\int}_{{\Omega}_{e}}\sqrt{(A:A)}.d{\Omega}_{e}
$$

The Frobenius norm on the components ${A}_{ij}$ of a tensor $A$ :

$$
{N}_{F}={\int}_{{\Omega}_{e}}{\sum}_{i,j}∣{A}_{ij}∣.∣{A}_{ij}∣.d{\Omega}_{e}
$$

Each of these norms produces one component (named X1) on an element. It is therefore an ELEM field. It is to be noted that the difference between the two norms comes from the cross terms (off-diagonal).

### 13.5 Operand NUME_CHAM_RESU

The field produced must be stored, in a unique way, in the result concept. The «user» fields are therefore numbered using NUME_CHAM_RESU and the type of the field.

The name of the field will therefore be of the type UT01_ELGA, UT22_NOEU, and so on.

### 13.6 Example of computation of a user field

## 14 Operand for the sub-points

'DEPL_ELGA'

Computation of the displacements at the sub-points.

In order to visualise a CHAMP_ELGA on the "deformed" structure, a field DEPL_ELGA is computed from the field DEPL (at the nodes) by means of the shape functions of the element.

For the elements with sub-points, knowledge of the shape functions is not sufficient; one must also know the position of the sub-points as well as the kinematic equations relating the displacements of the support element to the displacements of the sub-points. This information is available only via the CARA_ELEM.

The field DEPL_ELGA has as components DX, DY, DZ.

'TEMP_ELGA'

Computation of the temperature at the sub-points. This option makes it possible to know the temperature which is used during a mechanical analysis in the constitutive law.

For the elements with sub-points, it is necessary to know the position of the sub-points. This information is available only via the CARA_ELEM.

The field TEMP_ELGA has as component TEMP.

## 16 Performance of the analyses: parallelism in space or in time?

By default, when MPI parallelism is activated 1
(cf. [U2.08.06](doc:u2.08.06)), the computation options generally benefit here from a **so-called «in space» parallelism**. That is, the computations are distributed over the parallel processes by batches of mesh cells. An MPI process will handle, for all the time steps, the elementary computations required by a given mesh-cell group.

But, besides the fact that this parallelism is not very efficient for the options involving directly few or no elementary computations (such as the options REAC/FORC_NODA and xxx_NOEU), it also gives rise to large and repeated MPI communications 2.

For the options mentioned above, one therefore prefers the **so-called «in time» parallelism**, which, for its part, distributes, for all the mesh cells, the computations (elementary or not) required by a batch of time steps. The communications are therefore less costly 3
and the parallelism is extended to portions of code beyond the elementary computations.

With this parallelism, the speed-ups may range from X5 to X50 depending on the configuration of the analyses. The activation of this parallelism is carried out in a given CALC_CHAMP 4
and it concerns all the computation options liable to benefit from it: REAC/FORC_NODA and xxx_NOEU and all the underlying computation options 5.

On a costly CALC_CHAMP, comprising REAC/FORC_NODA or xxx_NOEU computations on long transients and/or on large models, one therefore advises activating this parallelism in time: PARALLELISME_TEMPS='OUI'. And, unlike the one in space, it does not need a minimum granularity 6
in order to be effective. From about ten time steps per MPI process, the speed-up provided by the parallelism in time may be significant 7
.

The type of active parallelism (in space, in time or none) is stated, option by option, in the message file. For more details one may consult the user's guide of parallelism [U2.08.06](doc:u2.08.06).

```python
CALC_CHAMP(EFGE_ELGA, REAC_NODA, ETOT_ELGA, EPSI_NOEU, PARALLELISME_TEMPS='OUI')
```

```python
CALC_CHAMP(EFGE_ELGA, ETOT_ELGA)
CALC_CHAMP(REAC_NODA, EPSI_NOEU, PARALLELISME_TEMPS='OUI')
```
