# u4.90.11 Operator CALC_MAC3COEUR

## 1 Purpose

Macro-command dedicated to fuel assemblies. The aim is to evaluate:

- either the deformation of the fuel assemblies subjected to thermal, hydraulic and neutronic loadings;
- or the inter-assembly water gaps at the beginning or at the end of a reactor cycle.

## 2 Syntax

```text
evol_noli = CALC_MAC3COEUR(
    ◆ TYPE_COEUR = / "MONO",
                   / "MONO_FROID",
                   / "TEST",
                   / "900",
                   / "1300",
                   / "N4",
                   / "LIGNE900",
                   / "LIGNE1300",
                   / "LIGNEN4",
    # Si: is_in("TYPE_COEUR", ("LIGNE900","LIGNE1300","LIGNEN4"))
        ◆ NB_ASSEMBLAGE = int,
    ◆ TABLE_N = table,
    ◇ MAILLAGE_N = maillage,
    ◇ RESU_DEF = co,
    ◇ FLUENCE_CYCLE = float,
    ◇ TYPE_DEFORMATION = "RIGI_GEOM",
    ◇ ETAT_INITIAL = _F(
         ◇ UNITE_THYC = unit,
         ◆ NIVE_FLUENCE = float,
         ◇ TYPE_MAINTIEN = "DEPL_PSC",
         ◇ MAINTIEN_GRILLE = / "OUI",
                             / "NON" (par défaut),
         ◇ ARCHIMEDE = "OUI",
      ),
    ◇ LAME = _F(
         ◆ UNITE_THYC = unit,
         ◇ COEF_MULT_THV = float (défaut: 1.0),
         ◇ COEF_MULT_THT = float (défaut: 1.0),
      ),
    # Si: exists("TYPE_COEUR") and TYPE_COEUR.startswith('MONO')
        ◇ DEFORMATION = _F(
             ◇ RESU_INIT = resultat,
             ◆ NIVE_FLUENCE = float,
             ◆ UNITE_THYC = unit,
             ◇ MAINTIEN_GRILLE = / "OUI",
                                 / "NON" (par défaut),
             ◆ TYPE_MAINTIEN = / "FORCE",
                               / "DEPL_PSC",
             # Si: equal_to("TYPE_MAINTIEN", 'FORCE')
                 ◆ FORCE_MAINTIEN = float,
             ◆ ARCHIMEDE = / "OUI",
                           / "NON",
          ),
    # Si: exists("TYPE_COEUR") and not TYPE_COEUR.startswith('MONO')
        ◇ DEFORMATION = _F(
             ◇ RESU_INIT = resultat,
             ◇ TEMP_IMPO = float,
             ◆ NIVE_FLUENCE = float,
             ◆ UNITE_THYC = unit,
             ◇ MAINTIEN_GRILLE = / "OUI",
                                 / "NON" (par défaut),
             ◇ TYPE_MAINTIEN = "DEPL_PSC",
             ◇ ARCHIMEDE = "OUI",
          ),
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Operand TYPE_COEUR

Name of the type of core to be processed.

The case 'TEST' represents a fictitious core with five fuel assemblies, arranged in a cross.

The case 'MONO' represents a single assembly (that is, a fictitious single-assembly core, without taking into account contact with the reactor-vessel internals) at «hot core» temperature.

The case 'MONO_FROID' represents a single assembly (that is, a fictitious single-assembly core, without taking into account contact with the reactor-vessel internals) at ambient temperature.

The cases 'LIGNEXXX' (with XXX='900','1300' or 'N4') represent a row analysis for each plant-series design.

One should refer to the reference documentation [R7.06.01](doc:r7.06.01), in particular for everything concerning the loadings and the various frames used.

### 3.2 Operand NB_ASSEMBLAGE

In the case of a core of type 'LIGNEXXX' (with XXX='900','1300', 'N4' or 'EPR'), this keyword makes it possible to specify the length of the line.

### 3.3 Operand TABLE_N

Table (in DAMAC format) containing the assembly information (mainly position, design and deformation).

For a 'DEFORMATION' analysis, this is the composition of the core of the simulated cycle. For a 'LAME' analysis, this is the DAMAC from which one wants to compute the water gaps. For an 'ETAT_INITIAL' analysis, this is the DAMAC that one seeks to reproduce.

### 3.4 Operand MAILLAGE_N

Mesh corresponding to the description of the core: the design of the assemblies in the mesh must correspond to the design supplied in 'TABLE_N'.

### 3.5 Operand FLUENCE_CYCLE

«Flat-rate» fluence used to take into account the initial irradiation of the assemblies: the initial irradiation of each assembly is taken equal to $N$ times 'FLUENCE_CYCLE', with $N$ the number of cycles already undergone by the assembly, given in 'TABLE_N'.

With a value of FLUENCE_CYCLE=0, all the assemblies will therefore have a zero initial irradiation.

Note: this keyword is not taken into account for a DEFORMATION analysis with RESU_INIT, because in that case the initial irradiation of each assembly comes from the result given in RESU_INIT.

### 3.6 Operand TYPE_DEFORMATION

Makes it possible to choose how the kinematics are taken into account. The only option available is 'RIGI_GEOM', which corresponds to an analysis in PETIT with the option RIGI_GEOM='OUI'.

### 3.7 Operand DEFORMATION

Factor keyword which specifies that the macro-command is used here to compute the deformations of the fuel assemblies in the core configuration.

#### 3.7.1 Operand RESU_INIT

Possibility of giving a result as the initial state. This keyword is useful when several irradiation cycles are carried out.

#### 3.7.2 Operand UNITE_THYC

Logical unit in which the THYC file is supplied as input to CALC_MAC3COEUR, containing the axial and transverse hydraulic loadings.

#### 3.7.3 Operand TEMP_IMPO

Value of the constant temperature. Activates the analysis of the simple thermal expansion of the reactor (without contact/friction or hydraulic loadings).

#### 3.7.4 Operand NIVE_FLUENCE

Value of the fluence received by the assemblies during the cycle (in ${10}^{24}\mathit{neutrons}/{m}^{2}$).

#### 3.7.5 Operand MAINTIEN_GRILLE

Makes it possible to activate the option of locking the grids

#### 3.7.6 Operand TYPE_MAINTIEN

For multi-assembly cores (other than 'MONO' or 'MONO_FROID'), this keyword is optional and allows only the value 'DEPL_PSC' (default value) explained below. The hold-down force is then produced by the displacement imposed by the Upper Core Plate (PSC) on the hold-down system of each assembly. The value of this displacement is given in the geometric data file (datg) of each of the cores considered.

In the single-assembly case ('MONO' or 'MONO_FROID'), the keyword TYPE_MAINTIEN is mandatory, with no default value, and may take the values 'DEPL_PSC' or 'FORCE':

- 'DEPL_PSC': the hold-down force is then produced by an imposed displacement as described above; in this case the keyword FORCE_MAINTIEN is not expected;
- 'FORCE': the hold-down force is then introduced by a fixed imposed force whose value is given by the keyword FORCE_MAINTIEN. This option makes it possible to reproduce faithfully the experimental tests that are used in particular to recalibrate the model.

#### 3.7.7 Operand FORCE_MAINTIEN

In the single-assembly case ('MONO' or 'MONO_FROID'), this keyword makes it possible to supply the value (in Newtons) of the hold-down force in the case TYPE_MAINTIEN='FORCE'.

#### 3.7.8 Operand ARCHIMEDE

In the single-assembly case, the keyword ARCHIMEDE is mandatory, with no default value, and may take the values 'OUI' or 'NON'. This keyword makes it possible to choose whether Archimedes' buoyancy is activated or not.

For multi-assembly cores (other than 'MONO' or 'MONO_FROID'), this keyword is optional and allows only the value 'OUI' (default value): Archimedes' buoyancy is always activated.

### 3.8 Operand LAME

Factor keyword which specifies that the macro-command is used here to determine the water gaps from a core made up of deformed assemblies. For an end-of-cycle water-gap analysis (EOC in English), it is sufficient to supply the measured DAMAC in 'TABLE_N'. For a beginning-of-cycle water-gap analysis (BOC in English), one must supply a «reconstructed» DAMAC from the known DAMACs and from the core loading pattern; this «reconstructed» DAMAC is the user's responsibility, and must be supplied in 'TABLE_N'. The hydraulic forces are taken into account by the loading defined in 'UNITE_THYC'.

#### 3.8.1 Operand UNITE_THYC

Logical unit in which the THYC file is supplied as input to CALC_MAC3COEUR, containing the axial and transverse hydraulic loadings.

#### 3.8.2 Operands COEF_MULT_THV and COEF_MULT_THT

Multiplicative coefficients for the axial and transverse hydraulic loadings.

### 3.9 Operand ETAT_INITIAL

Factor keyword which specifies that the macro-command is used here to reconstruct the mechanical state from the observation of the deformations at the end of the cycle: this mechanical state can then be used as the initial state in a later analysis.

#### 3.9.1 Operand UNITE_THYC

Same use as in § 3.8.1

#### 3.9.2 Operand NIVE_FLUENCE

Same use as in § 3.7.4 .

#### 3.9.3 Operand TYPE_MAINTIEN

Same use as in § 3.7.6  in the case other than 'MONO'.

#### 3.9.4 Operand ARCHIMEDE

Same use as in § 3.7.8  in the case other than 'MONO'.

### 3.10 Operand RESU_DEF

When the operand 'LAME' is used, the result is supplied on the mesh initially deformed by the given deformations (see [R7.06.01](doc:r7.06.01) for the details of this operation): the displacements supplied by the result concept are therefore to be understood as the displacement relative to this deformed mesh and as the displacement relative to the mesh supplied with the «straight» assemblies. In practice, it is therefore complicated to use such displacements. CALC_MAC3COEUR / LAME therefore provides the operand 'RESU_DEF', which makes it possible to recover a result concept that contains the displacement on the initial undeformed mesh, which makes it easy to post-process the displacements.

On the other hand, for post-processing of the «water gap» type, the results supplied by the result concept of CALC_MAC3COEUR are perfectly usable.

The recommendation for a water-gap analysis is therefore to proceed as follows:

**RESU** = CALC_MAC3COEUR(

> […]
> **RESU_DEF = CO('RESUDEPL'),**
> LAME=_F(

> […]

> )

> )

# post-processing of the water gaps on RESU

POST_MAC3COEUR(

> RESULTAT = **RESU** ,
> […]
> **LAME** =_F(

> […]
> ),

> )

# post-processing of the displacements on RESUDEPL

POST_MAC3COEUR(

> RESULTAT = **RESUDEPL** ,
> […]
> **DEFORMATION** =_F(

> […]
> ),

> )
