# u4.52.01 Operator INFO_MODE

## 1 Purpose

This command makes it possible to **count** and to save (in an sd_table) **the number of eigenvalues contained** in:

- An **interval of the real axis** (for the standard generalised GEPs with real symmetric matrices).
- A **disc of the complex plane** (for all the other cases, other GEPs and all the quadratic problems QEPs).

When one treats standard GEPs, the execution of this procedure generally requires only one LDLT factorisation per mode. When they are scattered in the complex plane, the procedure is much more costly. In this case, it is therefore rather to be reserved for simplified problems of small size (fewer than 1000 degrees of freedom).

Calling this operator is recommended as an *a priori* **check/calibration** **of the model.** It also makes it possible to define **balanced search intervals containing a reasonable number** **of eigenvalues** (typically a few tens). And this, in order to optimise the costs of the subsequent modal operators and not to degrade the accuracy of their results.

*In order to treat a standard GEP efficiently* 1
, one proposes to proceed in several steps:

- **Calibrate** the zones of interest by pre-analyses using only INFO_MODE (in sequential mode or, if possible, in parallel) on given lists of frequencies (resp. critical loads);
- **Relaunch** one or more CALC_MODES analyses with OPTION='BANDE' split over several sub-bands, on the basis of these initial calibrations.

For intensive computation, the operator INFO_MODE 2
, can benefit from two levels of parallelism. The gains in time can reach a factor of 70 on a hundred processors, and the gains in peak memory a factor of 2. The implementation of the parallelism is described in the dedicated paragraph of the documentation [U2.06.01](doc:u2.06.01).

This operator produces a concept sd_table.

As a first approach one can simply supply the parameters: MATR_* , TYPE_MODE and FREQ (or CHAR_CRIT or *_CONTOUR).

This operator is complementary to the operator CALC_MODES [U4.52.02](doc:u4.52.02).

Currently, the very great majority of cases.

Just as CALC_MODES with OPTION='BANDE' split over several sub-bands.

## 3 Operands

### 3.1 Principles

This command makes it possible to count the number of eigenvalues contained in (cf. figure 3ab):

- An interval of the real axis (for the standard generalised GEPs with real symmetric matrices): keyword TYPE_MODE='DYNAMIQUE' or 'MODE_FLAMB' or 'GENERAL'.
- A disc of the complex plane (for all the other cases, other GEPs and all the quadratic problems QEPs): keyword TYPE_MODE='MODE_COMPLEXE' or 'GENERAL'.

This number of eigenmodes is traced in the message file for each interval of the real axis or for the chosen portion of the complex plane (cf. figure 1). One also recalls the characteristics of these zones of interest.

Calling this operator is recommended as an *a priori* check/calibration of the model. It also makes it possible to define search intervals containing a reasonable number of eigenvalues (typically about forty modes) in order to optimise the costs of the subsequent modal operators and not to degrade the accuracy of their results.

Typically, one advises searching for the modes in packets of about forty 3
. Beyond that, the consumptions in time and in memory are no longer optimal and the quality of the modes obtained is degraded. It is then better to use several frequency bands (or critical-load bands) directly with CALC_MODES and the option 'BANDE' split over several sub-bands, or by several calls to CALC_MODES [U4.52.02](doc:u4.52.02).

**Ideally, in order to treat a standard GEP efficiently**, one proposes to proceed in several steps:

- **Calibrate** the zones of interest by pre-analyses using only INFO_MODE (in sequential mode or, if possible, in parallel) on given lists of frequencies (resp. critical loads);
- **Relaunch** one or more CALC_MODES analyses with OPTION='BANDE' on the basis of these initial calibrations.

To save time, one can even **share** (and this is strongly recommended!) part of the computational cost of the initial INFO_MODE by notifying to CALC_MODES the name of the sd_table generated. This chaining can thus make the extra cost of INFO_MODE negligible and guide the modal analysis effectively.

On the intensive-computation side, the operator INFO_MODE, just as CALC_MODES with the option 'BANDE' split into several sub-bands, potentially benefits from two levels of parallelism (cf. keyword NIVEAU_PARALLELISME). Hence gains in time by a factor of up to 70 on a hundred processors and gains in peak memory of up to a factor of 2.

![Figure](/figures/u4.52.01/1000020000000259000000EDD2CF47D4C2C09C82.png)

*Figure 3ab._ Two distinct counting problems: in a segment of the real axis and in a finite portion of the complex plane (for the moment only a disc).*

In the first case, when one seeks to count the eigenvalues strictly included in a segment of the real axis, one uses the so-called “Sturm” method; in the second case the APM method. Their theories and algorithms are detailed in the reference documentation [R5.01.04](doc:r5.01.04).

When one treats standard GEPs, the execution of this procedure generally 4
requires only one LDLT factorisation per mode (METHODE='STURM'). When they are scattered in the complex plane, the procedure is much more costly (METHODE='APM') because it requires, in general, hundreds of factorisations. In this case, it is therefore rather to be reserved for simplified problems of small size (fewer than 1000 degrees of freedom).

Note that this latter APM method is still the subject of active research. Its robustness is therefore, for the moment, not guaranteed. It is to be used only after having taken care to read the associated documentation.

### 3.2 Characteristics of the modal problem: operands MATR_RIGI / MATR_A / MATR_MASS / MATR_RIGI_GEOM / MATR_B / MATR_AMOR / MATR_C

The table below represents the operands to be used according to the type of the keyword TYPE_MODE.

| TYPE_MODE |  |  |  |
| --- | --- | --- | --- |
| 'DYNAMIQUE' | 'MODE_FLAMB' | 'MODE_COMPLEXE' | 'GENERAL' |
| ♦ MATR_RIGI = A | ♦ MATR_RIGI = A | ♦ MATR_RIGI = A | ♦ MATR_A = A |
| ♦ MATR_MASS = B | ♦ MATR_RIGI_GEOM = B | ♦ MATR_MASS = B | ♦ MATR_B = B |
| Not applicable | Not applicable | ◊ MATR_AMOR = C | ◊ MATR_C = C |

These operands make it possible to supply the matrices (assembled or generalised 5
) characterising the modal problem. These matrices may be symmetric or not. They are real except the matrix $\mathrm{A}$ which may be either real or complex.

Supplying $\mathrm{A}$ and $\mathrm{B}$ makes it possible to define the generalised modal problem (GEP) (cf. [R5.01.01](doc:r5.01.01)) studied

$\mathrm{A}\mathrm{u}=\lambda \mathrm{B}\mathrm{u}({\mathrm{GEP}}_{\mathrm{dynamique}})$

In the classical case of dynamics (TYPE_MODE='DYNAMIQUE'), $\mathrm{A}$ is the stiffness matrix (real symmetric) and $\mathrm{B}$ is the mass matrix (real symmetric). The eigenvalue $\lambda$ is then related to the eigenfrequency $f$ by the formula: $\lambda ={(2\pi f)}^{2}$ . It is real and positive.

In the case of the linear buckling theory (TYPE_MODE='MODE_FLAMB'),

$\mathrm{A}\mathrm{u}-\lambda \mathrm{B}\mathrm{u}=0({\mathrm{GEP}}_{\mathrm{flambement}})$

$\mathrm{A}$ is the stiffness matrix (real symmetric) and $\mathrm{B}$ the geometric stiffness matrix (real symmetric). The eigenvalue $\lambda$ is called the critical load. It is real.

As mentioned in the previous table, these matrices will be supplied, respectively, for dynamics by MATR_RIGI / MATR_MASS and, in buckling, by MATR_RIGI / MATR_RIGI_GEOM. Only the so-called 'STURM' method is valid in these two cases.

When one of the two matrices is no longer symmetric or contains complex terms (for example to take hysteretic damping into account), the eigenvalues are potentially complex. To treat this problem one must initialise TYPE_MODE to 'MODE_COMPLEXE' and only the APM method is then valid.

Supplying $\mathrm{A}$ **,** $\mathrm{B}$ and $\mathrm{C}$ makes it possible to define the quadratic modal problem (QEP) (cf. [R5.01.02](doc:r5.01.02)) studied

$(\mathrm{A}+\lambda \mathrm{C}+{\lambda}^{2}\mathrm{B})\mathrm{u}=0(\mathrm{QEP})$

In this case, the eigenvalues are potentially complex. To treat this problem one must initialise TYPE_MODE to 'MODE_COMPLEXE'. Often $\mathrm{A}$ is the stiffness matrix, $\mathrm{C}$ a matrix taking into account viscous damping and/or gyroscopic effects and $\mathrm{B}$ the geometric stiffness matrix. As mentioned in the previous table, these matrices will be supplied by MATR_RIGI / MATR_MASS / MATR_AMOR and only the APM method is valid.

TYPE_MODE='GENERAL' makes it possible to solve an eigenvalue problem in the general case. One then assigns to the matrices $\mathrm{A}$ **,** $\mathrm{B}$ and/or $\mathrm{C}$ the role that one wishes. As mentioned in the previous table, these matrices will be supplied by MATR_A / MATR_B / MATR_C. Depending on the case, only the Sturm method (if MATR_C is not supplied and if the other two matrices are real symmetric) or the APM method (all the other cases) is valid.

### 3.3 Operand TYPE_MODE

```text
◊    TYPE_MODE=    /    ‘DYNAMIQUE’            [DEFAUT]
                   /    ‘MODE_FLAMB’
                   /    'MODE_COMPLEXE'
                   /    'GENERAL'
```

This keyword makes it possible to define the nature of the modal problem to be treated: pre-estimate the spectrum of vibration frequencies (classical case of 'DYNAMIQUE'), do so in terms of critical loads (case of the linear buckling theory 'MODE_FLAMB') or calibrate that of a non-standard GEP or of a QEP in a portion of the complex plane ('MODE_COMPLEXE'). One can also search for the eigenvalues and the associated modes of a general matrix system ('GENERAL'). For further details one may refer to the description of §3.2.

Following this choice, the user must specify the characteristics of the control zone:

- for 'DYNAMIQUE': list of frequencies *via* FREQ,
- for 'MODE_FLAMB': list of critical loads *via* CHAR_CRIT,
- for 'MODE_COMPLEXE': zone of the complex plane *via* TYPE/RAYON/CENTRE_CONTOUR,
- for 'GENERAL': depending on the case, either one proceeds as for 'MODE_FLAMB' (if MATR_C is not supplied and if the other two matrices are real symmetric), or as for 'MODE_COMPLEXE' (all the other cases).

### 3.4 Operand FREQ

```text
♦    FREQ = l_f
```

List of frequencies (in Hertz) defining the intervals that one wants to calibrate $\text{l\_f}={({f}_{i})}_{i}$ (one denotes by nb_freq the number of frequencies of this list). One then searches for the number of eigenvalues in the sub-bands $[{\lambda}_{i},{\lambda}_{\text{i+1}}]$ with ${\lambda}_{\text{*}}={(2\pi {f}_{\text{*}})}^{2}$ . This list must contain at least two values. These values must be arranged in strictly increasing order and all positive.

This keyword must be used if TYPE_MODE=‘DYNAMIQUE’. Only the counting method of type STURM is then valid.

**Notes:**

- *Each frequency is treated only once: as the lower bound of the first sub-band for the first of the list, as the upper bound of the following sub-bands for the other frequencies. In particular, if this frequency is judged too close to an eigenvalue, one shifts it (possibly several times cf. parameters* PREC_SHIFT/NMAX_ITER_SHIFT *etc.). This “shift” offset is always operated towards the outside of the sub-band under consideration.*
- *If the shift of the lower bound makes it larger than the upper bound, the process stops in* ERREUR_FATALE *.*
- *This mode of shifting makes the subsequent reuses of this* sd_table *by one or more* CALC_MODES *more robust and consistent. One avoids in particular the overlaps of sub-bands that could occur up to V10.*
- The initial bounds of each of these sub-bands *are saved in the fields* FREQ_MIN/MAX *of each row of the table produced (cf. figure 2a). For each of these pairs, one mentions the bounds actually used by the Sturm test (that is to say after possible shifts),* BORNE_MIN/MAX_EFFECT *, as well as the number of modes found:* NB_MODE *.*

### 3.5 Operands CHAR_CRIT

```text
CHAR_CRIT = l_c
```

List of critical loads defining the intervals that one wants to calibrate $\text{l\_c}={({\lambda}_{i})}_{i}$ (one denotes by nb_mode_flamb the number of critical loads of this list). One then searches for the number of eigenvalues in the sub-bands $[{\lambda}_{i},{\lambda}_{\text{i+1}}]$ . This list must contain at least two values. These values must be arranged in strictly increasing order. They must be of real type.

This keyword must be used if TYPE_MODE=‘MODE_FLAMB’ or if TYPE_MODE=‘GENERAL’ (if MATR_C is not supplied and if the other two matrices are real symmetric). Only the counting method of type STURM is valid.

**Notes:**

- *Each critical load is treated only once: as the lower bound of the first sub-band for the first of the list, as the upper bound of the following sub-bands for the other frequencies. In particular, if this load is judged too close to an eigenvalue, one shifts it (possibly several times cf. parameters* PREC_SHIFT/NMAX_ITER_SHIFT *etc.). This “shift” offset is always operated towards the outside of the sub-band under consideration.*
- *If the shift of the lower bound makes it larger than the upper bound, the process stops in* ERREUR_FATALE *.*
- *This mode of shifting makes the subsequent reuses of the* sd_table *by one or more* CALC_MODES *more robust and consistent. One avoids in particular the overlaps of sub-bands that could occur up to V10.*
- The initial bounds of each of these sub-bands *are saved in the fields* CHAR_CRIT_MIN/MAX *of each row of the table produced (cf. figure 2b). For each of these pairs, one mentions the bounds actually used by the Sturm test (that is to say after possible shifts),* BORNE_MIN/MAX_EFFECT *, as well as the number of modes found:* NB_MODE *.*

### 3.6 Operands TYPE / RAYON / CENTRE_CONTOUR

If TYPE_MODE=‘MODE_COMPLEXE’ or if TYPE_MODE=‘GENERAL’ (if MATR_C is supplied and/or if one of the matrices is non-symmetric or complex)

```text
◊    TYPE_CONTOUR    =                    'CERCLE'    [DEFAUT]
♦    RAYON_CONTOUR    =                    rayon        [R]
◊    CENTRE_CONTOUR    =            /    centre        [C]
                                    /    0.0+0.0j    [DEFAUT]
```

These keywords define the type of contour inside which one searches for the eigenvalues as well as its characteristics. For the moment one can choose only a contour of type 'CERCLE' (which therefore delimits the control disc). One mentions its centre (a complex number) and its radius (a positive real).

Notes:

- Strictly speaking, this radius must be greater than the “modal zero”. That is to say greater than the value below which one considers that an eigenvalue is zero or that two eigenvalues are coincident if one is speaking of their separation.
- *Unlike the values of* *FREQ, the units are not here in frequency, but in angular frequency if one makes the analogy with the* *DYNAMIQUE problem. As for a* *TYPE_MODE='MODE_FLAMB', the unit of the characteristics of the contour undergoes no transformation. This allows the APM method to treat all types of problems.*
- *The table produced with the option* TYPE_MODE='MODE_COMPLEXE' *contains, in addition to the number of eigenvalues (* NB_MODE *), three reals making it possible to describe the search criteria for the APM method. The first two are* CENTRE_R and CENTRE_I, *the real and imaginary parts of the complex number that corresponds to the centre of the search disc. The third parameter,* RAYON, *is the radius (strictly positive real >1.D-2) of the disc.*

### 3.7 Factor keyword COMPTAGE

Once the type of control zone (segment or disc) has been defined, it remains to set the counting method and its parameters.

```text
◊    METHODE =    /    ‘AUTO’,        [DEFAUT]
                  /    ‘STURM’,
                  /    'APM'.

Si on traite un problème de type 'DYNAMIQUE' ou 'MODE_FLAMB', seule les méthodes 'STURM' et 'AUTO' sont autorisées.

De même pour 'MODE_COMPLEXE' et 'APM'/'AUTO'.

Dans le cas 'GENERAL', les trois méthodes sont disponibles et la valeur 'AUTO' prend alors tout son sens ! Elle choisit pour l'utilisateur entre STURM et APM suivant les caractéristiques du problème modal:
```

- Either it is a standard GEP (two real symmetric matrices): STURM method.
- In all the other cases (atypical GEP with a non-symmetric and/or complex matrix or QEP): APM method.

```text
Si on laisse le mode 'AUTO' paramétré par défaut, l'opérateur choisit automatiquement la méthode suivant le type d'étude choisie. On a laissé sciemment cette valeur, même dans les cas qui ne comportent qu'une seule alternative, pour faciliter l'ergonomie.

Si on se trompe de METHODE, une alarme apparaît et l'opérateur choisit automatiquement la méthode la plus appropriée ou s'arrête en ERREUR_FATALE, suivant les cas de figure.
```

Note:

- *One can use the* *APM method to count the modes of a standard GEP by setting* *TYPE_MODE='MODE_COMPLEXE'. This makes it possible to compare and validate the two counting methods (cf. test case SDLL123a).*

```text
# Si TYPE_MODE=‘DYNAMIQUE’

◊    SEUIL_FREQ =            /    f_seuil         [R]
                             /    0.01            [DEFAUT]
◊     PREC_SHIFT =           /    p_shift         [R]
                             /    0.05            [DEFAUT]
◊     NMAX_ITER_SHIFT =      /    n_shift         [I]
                             /    3               [DEFAUT]

# Si TYPE_MODE=‘MODE_FLAMB’ ou 'GENERAL' (si MATR_C n'est pas renseignée et si les deux autres matrices sont symétriques réelles)

◊    SEUIL_CHAR_CRIT =      /    c_seuil        [R]
                            /    0.01           [DEFAUT]
◊     PREC_SHIFT =          /    p_shift        [R]
                            /    0.05           [DEFAUT]
◊     NMAX_ITER_SHIFT =     /    n_shift        [I]
                            /    3              [DEFAUT]
```

These parameters are used only by the STURM method.

The parameters SEUIL_* make it possible to define the “modal zero”, that is to say the value below which one considers that the eigenvalue is zero. If one is in dynamics one transforms this value into an angular frequency

$\mathit{omecor}={(2\pi \text{f\_seuil})}^{2}$

whereas in buckling one keeps it as it is

$\mathit{omecor}=\text{c\_seuil}$.

The other parameters, PREC_SHIFT and NMAX_ITER_SHIFT, are linked to the algorithm for shifting the bounds of the interval (cf. [R5.01.04](doc:r5.01.04) §3.2) when one notices that they are very close to an eigenvalue. Roughly, these bounds ${f}_{\min}`(ou ${\lambda}_{\min}$en flambement) ou ${f}_{\max}$(resp. :math:`{\lambda}_{max}$) are then shifted towards the outside of the segment by p_shift%. If the dynamic matrix thus rebuilt is still judged “numerically singular”, one shifts again after having issued an ALARME. One attempts this shift n_shift times.

${{lambda}^{-}}_{min}={lambda}_{min}-max(mathit{omecor}{,2}^{(i-1)}text{x}{p}_{mathit{shift}}text{x}∣({lambda}_{min})∣)$(ith attempt)

${{lambda}^{-}}_{max}={lambda}_{max}+max(mathit{omecor}{,2}^{(i-1)}text{x}{p}_{mathit{shift}}text{x}∣({lambda}_{max})∣)$(ith attempt)

In fact, in dynamics as in buckling the shift is operated in the same way. Strictly speaking, in dynamics it is therefore not the frequencies that one shifts, but the angular frequencies.

Another detail: the shift is in fact, for the sake of efficiency, dichotomic: p_shift% the first time, 2xp_shift% the second time etc. This process must make it possible to move quickly away from the “singularity zone” at lower cost. Conversely, one must not increase the values of these parameters too much, because by dint of shifts, the resulting bounds may turn out to be very different from the initial bounds.

Furthermore, in order to remain consistent with the “modal zero” (denoted here omecor):

- One does not shift by a value smaller than this minimum (hence the max in the formulae above),
- If from the outset the assessed bound is smaller than this “zero” $∣{\lambda}_{\text{*}}∣<\mathit{omecor}$ (in absolute value) one sets it to plus or minus this value (according to whether this bound is positive or negative). One then no longer allows any shift.

Notes:

- *A bound of the interval* $\sigma$ *is close to an eigenvalue when the LDLT factorisation of the dynamic matrix associated with this bound (for example that of a GEP is written* $\mathrm{Q}(\sigma ):=\mathrm{A}-\sigma \mathrm{B}$ *), leads to a loss of decimals of more than* *NPREC digits (value set under the keyword* *SOLVEUR). By adjusting the value of this parameter (NPREC=7, 8 or 9), one can then avoid the costly refactorisations implied by these shifts when this numerical singularity is not very pronounced.*
- *Likewise, by adjusting the numerical parameters of the linear solvers (for example:* METHODE, RENUM, PRETRAITEMENTS *...), one can also influence this singularity criterion.*

```text
# Si TYPE_MODE=‘MODE_COMPLEXE’ ou 'GENERAL' (si MATR_C est renseignée ou/et si une des deux autres matrices est non symétrique ou complexe)

◊    NBPOINT_CONTOUR =    /    nb_point        [I]
/    40                [DEFAUT]
◊     NMAX_ITER_CONTOUR =    /    n_contour        [I]
/    3                [DEFAUT]
```

These parameters are used only by the APM method.

The two preceding parameters, NB_POINT_CONTOUR and NMAX_ITER_CONTOUR, are used only with the APM method. They are crucial for its robustness and they size its computation time (an analysis with nb_point=80 will last longer than an analysis with nb_point=40).

The value nb_point gives the number of discretisation points that are positioned along the contour. This discretisation must be fine enough to “capture” all the spectral information. Ideally, this value must be set to at least six times the number of modes that one expects to find in the circle. If one has no *a priori* idea of this number, one must set it to a value that is not too small: for example, 40 or 60.

Note:

- *Warning, if this figure is too large (for example 1000), depending on the size of the problem, since it implies as many LDLT factorisations, the analysis can be very long!*

> The APM algorithm implemented will converge only when 3 successive evaluations of the number of eigenvalues provide the same result. The differences between these three evaluations lie solely in the degree of discretisation of the contour. One starts by discretising with ${k}_{-}=\text{nb\_point}/2$, then with $k=\text{nb\_point}`et enfin avec :math:`{k}_{+}=2\text{nb\_point}$. If these three levels of discretisation of the contour produce an identical estimate of the number of eigenvalues, the algorithm is considered to have converged. Its result is then this integer.

Otherwise, one doubles these three levels of discretisation according to the following permutation

${k}_{-}\leftarrow k$, $k\leftarrow {k}_{+}`et :math:`{k}_{+}\leftarrow 2{k}_{+}$ 6

If they are identical, convergence is reached, otherwise one continues. One repeats this dichotomic heuristic at most n_contour times.

If this process has not converged or if its result is inconsistent (strictly negative integer), one stops in ERREUR_FATALE.

### 3.11 Operand NIVEAU_PARALLELISME

```text
◊    NIVEAU_PARALLELISME =    /    'COMPLET'            [DEFAUT]
/    'PARTIEL'
```

When one treats problems **of medium or large size** (> 0.5M degrees of freedom) and/or when one seeks a **good part of their spectra** (> 50 modes), the use of parallelism provides appreciable gains in time and in memory. And this, with a functional behaviour and result accuracies unchanged with respect to sequential mode.

The natural splitting of the INFO_MODE analysis into nb_sbande independent parts (number of sub-bands = nb_freq-1 or nb_mode_flamb-1) provides a first level of parallelism that is very efficient (in time). It does not affect the memory consumptions 8
.

Furthermore, since the essential part of the computational cost is due to the numerical factorisation stage 9
of the linear solver, if one parallelises this stage *via* MUMPS (METHODE='MUMPS'), one adds notable gains in time and in memory. This is a second level of parallelism that can be activated.

With the default value of this keyword (NIVEAU_PARALLELISME='COMPLET'), when the analysis is parallel, the two levels of parallelism are combined. Since the second (that of the linear solver) is less efficient than the first, it is triggered only if the number of processors allows it (nb_proc>nb_sbande) and if the linear solver selected supports MPI parallelism (SOLVEUR=_F(METHODE='MUMPS')).

If one selects the other value of the keyword (NIVEAU_PARALLELISME='PARTIEL'), one benefits only from the parallelism of the linear solver (the second level). This may be of interest for testing methods or for focusing the gains on the reduction of the memory peak (after having tried the other levers proposed in the keyword SOLVEUR).

For further information on the implementation of parallelism, one should refer to the documentation [U2.08.06](doc:u2.08.06) or to the dedicated paragraph of the documentation [U2.06.01](doc:u2.06.01).

### 4.1 Example no. 1

**Comparison of the two methods** **STURM and** **APM on the standard GEP of** **SDLD02a** (for STURM the bounds are given in frequency).
