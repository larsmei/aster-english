# u2.08.07 Parametric analyses - Distribution of analyses

**Summary:**

Certain studies lead one to carry out a more or less large number of analyses (sometimes several thousand), corresponding to the variations of the parameters. The use of standard analyses, consisting in modifying or creating the command file for each of the parameter sets, is tedious, difficult to manage and a source of error. The method presented in this document makes it possible to facilitate the implementation of such parametric studies by carrying out a minimum of interventions.

From the standard study and a file containing the parameter set, the analyses are derived and executed automatically.

The parametric analyses being independent of one another, it is possible to use the machine resources available by submitting the analyses in parallel.

## 1 General points

### 1.1 Presentation

A **parametric study** is a standard study (ETUDE tab) in which one wishes to vary one or several parameters, such as for example:

- Material parameters     : Young's modulus, elastic limit,...
- Geometric parameters     : thickness of the shell, cross-section of a beam,...
- Loading parameters     : pressure, orientation of a force, ...
- ...

If one carries out these analyses as a standard analysis, the number of analyses to be carried out can become very large, several thousand analyses, and their implementation becomes very tedious.

The aim of this document is to describe the methodology to be implemented in *Code_Aster* in order to carry out this type of study with the minimum of intervention.

Overall, a parametric study is the data of a nominal study (command file common to each parameter) and of a parameter set: *Code_Aster* will derive the nominal study into several studies according to the parameters supplied, then will execute each derivation taking into account the machine resources available.

### 1.2 Purpose of the tutorial

The aim of the tutorial is to supply the user with as much information as possible to allow him or her to implement parametric studies.

This document answers the following questions:

- How to prepare a parametric study (files,...),
- How to launch a parametric study (directories, options,...),

In this document, one assumes that the user is familiar with standard *Code_Aster* analyses. Otherwise he or she is invited to consult the following documents [U1.04.00](doc:u1.04.00), ... and to begin by carrying out a classical study.

## 2 Mode of operation of the parametric analyses

### 2.1 Principle

The implementation of parametric studies in *Code_Aster* is relatively simple. Nevertheless it is important that:

- your standard study runs without problem before undertaking this type of analysis.
- you have properly defined beforehand the parameters that you wish to vary:

  - their names,
  - their values,
  - the analysis scenarios to be executed.

In the case of a standard study you have at least:

- As input:

  - a command file (.comm)
  - the necessary data files (.mail, .med,...)
  - the parameters (time and memory)
- As output:

  - a message file (.mess)
  - a result file (.resu, .med,...)

To carry out a parametric study you need in addition:

- As input:

  - a file describing the parameter set (.distr)
  - a results directory (.repe)
  - an Astk option distrib=oui. Depending on the server, one may need to specify the batch class in which the analyses will be submitted.
  - the parameters (time/memory) are the same for all the analyses; those of the master job can be fixed independently of the study by the plugin mechanism (cf. [U1.04.00](doc:u1.04.00)).
- As output:

  - a results directory (.repe)

In the following paragraphs we take up all these points in detail.

### 2.2 Implementation

The actions to be undertaken in order to implement a parametric analysis are the following:

1. Writing of a parameter set,
2. Use of the parameters in the command file,
3. Under Astk, ETUDE tab: definition of the results directory and addition of the parameter set,
4. Under Astk, OUTILS menu: definition of the type of analysis

#### 2.2.1 Writing of a parameter set

The description, in the python language, of the parameter set is carried out in the '.distr' file, in which one finds

- the list of the parameters,
- the values that these parameters will take successively (analysis scenarios).

Example:

```text
# young, temp_impo : nom des variables

# la variable young aura comme valeur 2.1E11 et 7.E10

# la variable temp_impo aura comme valeur 100 et 273

VALE=(

_F(young=2.1E11, temp_impo = 100.),# scénario de calcul n°1

_F(young=7.0E10, temp_impo = 273.), # scénario de calcul n°2

)
```

Figure 2.2.1-а: Example of an explicit ''distr'' file

In this example, one has two analysis scenarios (no. 1 and no. 2) with the parameters young and temp_impo, which will take successively as value $(2.1E11,100)$ and $(7.0E10,273)$ .

At this stage, although the name of the parameters is sufficiently explicit, nothing makes it possible to say how they will be used. For the parameter young, this suggests that it will be used during the definition of the material, but nothing for the moment makes it possible to assert this.

From the point of view of the python language, the '.distr' file contains a list of dictionaries named VALE (each dictionary corresponding to an analysis). One uses _F as in the command file to define these dictionaries.

The definition of the parameters of the analysis scenarios can be given explicitly or in a computed manner.

*Note*

*In the previous example, the definition of the parameters and the analysis scenarios are given explicitly. It is possible to call upon the functionalities of the python language in order to define them automatically; a practical example is presented in §*  3.2.2 *). The name of the parameters is defined by the user; it is advisable to use explicit names.*

#### 2.2.2 Use of the parameters in the command file

In paragraph § 2.2.1 , one has defined the parameter set (name, values and analysis scenarios); the aim now is to use these parameters in the command file, at the desired place.

The taking into account of these parameters in the command file is carried out in two stages:

1. declaration of the python variables: the parameters
2. use of these variables in the command file.

    - **Declaration of the parameters (python variables)**

Before any use in a command or in any expression, it is **obligatory** that the parameters be known. The aim is not to initialise them once again, but simply to declare them as python variables.

Example: in the previous .distr file, one has defined the parameters young and temp_impo. One will therefore find in the command file the following lines:

```text
DEBUT()

...

young = 0.

temp_impo = 0.

...

FIN()
```

Figure 2.2.2-а: Declaration of the parameters

*Notes:*

*The values assigned in the command file will not be used; they will be replaced automatically by those defined in the* 'distr' *file, for each of the analysis scenarios.*

*Avoid choosing a parameter name identical to a keyword of Code_Aster. The substitution being made by the regular expression* '^(*)nom*=*', there could be confusion. *The case being significant, using names in lower case makes it possible to avoid this pitfall.*

    - **Use of the parameters**

The use of the parameters in the command file is carried out in the classical manner, within the commands, the mathematical expressions, ...

Example:

```text
DEBUT()

...

young=0.

temp_impo=0.

...

mat=DEFI_MATERIAU(ELAS=_F(E=young,...))

...

t0 = AFFE_CHAR_CINE=(THER_IMPO=_F(TEMP=temp_impo,

GROUP_NO='CHAUD',..)

...

FIN()
```

**Figure** 2.2.2-б **: Command file**

#### 2.2.3 Type of the parameters

The type of the parameters may be arbitrary. Then, one must bear in mind that the replacement is textual at the time of the instantiation of the command set for a given parameter set.

*Example:*

Let the parameter set be:

VALE=(_F(    young    =    2.1e11,            indice    =    4,            nomp    =    "'INST'",            objf    =    'FON1',),...)

and the header of the command set:

young    =    2.e11indice    =    0nomp    =    'X'objf    =    FON0...

The command set derived for the parameter set will be:

young    =    2.1e11indice    =    4nomp    =    'INST'objf    =    FON1...

The difference is visible for the last two parameters, where one sees that one has used the text of the character string of nomp and objf (and not the representation of the latter, so a pair of quotation marks has disappeared).

This makes it possible to parameterise the use of concepts. Here, one uses the function FON1 as the parameter objf.

#### 2.2.4 Parameters of file type

In the cases where the variable parameter is a file (for example in order to read a different mesh), it is a matter of making variable the name of this file (text string or else file number) and of using DEFI_FICHIER.

Example which mixes a file name in the form of a character string and the same thing using a mesh number:

Let the parameter set be:

VALE=(    _F(    fname    =    "'/tmp/maillage_01.mmed'",            indice    =    1,),        _F(    fname    =    "'/tmp/maillage_02.mmed'",            indice    =    2,),...)

and the command file:

fname    =    'nom_de_fichier_med'indice    =    0# using the file name DEFI_FICHIER(ACTION='ASSOCIER', UNITE=20, FICHIER=fname)meshA = LIRE_MAILLAGE(FORMAT='MED', UNITE=20)# using a file index (one constructs the name# of the file from the index over 2 characters# with leading zeros)filename = '/tmp/maillage_{i:0>2}.mmed'.format(i=indice)DEFI_FICHIER(ACTION='ASSOCIER', UNITE=21, FICHIER=filename)meshB = LIRE_MAILLAGE(FORMAT='MED', UNITE=21)

### 2.3 Launching of the studies: Astk

The launching of the parametric studies is managed directly by Astk. This launching is identical to that of a classical study subject to the addition of complementary information such as:

- addition in the study profile of a line to take into account the 'distr' file
- addition in the study profile of a line to define the results directory of type 'repe'
- initialisation, in the option menu, of the parameter distrib to 'OUI'.

#### 2.3.1 Management of the analyses and of the results

The analysis directory is the same as that of the results: it is defined in the study profile under the type 'repe'. After the execution of the parametric analyses, one finds in this directory as many calc_i directories as analyses launched. One also finds a flash directory. The detail of each of these directories is presented below.

##### 2.3.1.1 Management of the analyses

The command files corresponding to each of the scenarios are derived automatically from the nominal command file and from the parameter set. These files are stored in the calc_i directories.

The output files (message and error) of each analysis are stored in a single directory, the flash directory. All the information concerning the progress of each execution is found in this directory.

##### 2.3.1.2 Management of the results

As for a classical analysis, the user has the possibility of generating output files (tables, graphs, ...). He or she will have to define them in the standard command file. These outputs will be common to all the analysis scenarios.

For example, suppose that the user wants to print a table in the file of logical unit 38 and a result in med format in the file of logical unit 39. He or she will have to define, in the nominal command file, the name of each of the output files so that they can be stored in the directory REPE_OUT produced automatically by *Code_Aster.* The extract from the command file below illustrates this definition:

```text
DEFI_FICHIER(UNITE=38,FICHIER='./REPE_OUT/table.out')

IMPR_TABLE(TABLE=SIYY,UNITE=38,NOM_PARA=('NOEUD','SIYY'));

DEFI_FICHIER(UNITE=39,FICHIER='./REPE_OUT/poutre.rmed')

IMPR_RESU(FORMAT='MED',UNITE=39,RESU=_F(RESULTAT=depl))
```

**Figure** 2.3.1.2-а **: definition of the output files and of their logical units**

*Notes:*

*In the case of a parametric study the files* *.mess and* *.resu are not created. However, consultation of the files of the* *flash directory makes it possible to gather the information ordinarily issued in the* *.mess* .

#### 2.4.4 Distribution of analyses

In the case of parametric studies, the analyses are independent of one another. It is therefore possible to use the machine resources available at the time of the distribution of the analyses. One must therefore create a file of type 'hostfile' defining the machine resources. In it one defines:

- the name of the node on which the jobs will be submitted,
- the maximum number of jobs to be submitted at the same time,
- the total memory allocated.

*Note:*

*On a shared server, it is advisable to use the file defined by the administrator and therefore not to redefine one's own resources file.*

*If the* hostfile *file is not present in the study profile, it is the file* batch_distrib_hostfile *present in the directory* etc/codeaster *which will be used by default.*

    - For example on the centralised server, the resources are managed by the batch software. In this case, the hostfile file simply declares the number of analyses which will be submitted at the same time. Here one can submit up to 32 analyses on each front-end node (the memory is indicated as *infinite*, that is to say that one leaves the batch software to manage it):

```text
[:ref:`ataster1 <ataster1>`]

cpu=32

mem=9999999

[:ref:`ataster2 <ataster2>`]

cpu=32

mem=9999999
```

**Figure** 2.4.4-a **: Example of a** hostfile **file with a batch server**

For your resources file to be taken into account, it is sufficient to add it in your study profile, specifying the type 'hostfile'.

In the case of the use of a set of machines available interactively, the hostfile file could look like:

```text
# nom du nœud

[:ref:`machine1 <machine1>`]

# nombre de CPU disponible

cpu=4

# mémoire totale de la machine en Mo

mem=4000

# nom du nœud

[:ref:`machine2 <machine2>`]

# nombre de CPU disponible

cpu=8

# mémoire totale de la machineen Mo

mem=4000
```

**Figure** 2.4.4-b **: Example of an interactive** hostfile **file**

One will be able to have up to 12 analyses executed simultaneously, according to the memory available, distributed over the two machines. If each analysis requires 2 GB of memory, there will be at most two analyses per machine so as not to exceed the total amount of memory available.

#### 2.4.5 Pre/post-processings common to all the analyses

One has 4 keywords in the “distr” file: PRE_CALCUL, UNITE_PRE_CALCUL, POST_CALCUL, UNITE_POST_CALCUL.

PRE_CALCUL (resp. POST_CALCUL) defines a text (a set of Aster commands) which will be included just after DEBUT (resp. just before FIN).

UNITE_PRE_CALCUL (resp. UNITE_POST_CALCUL) offers the same functioning except that one supplies a logical-unit number.

This modification is made for all the files of type “comm” present in the profile.

This possibility is used in particular by the recalibration command MACR_RECAL in order to add a post-processing to each slave analysis.

## 3 Examples of application

### 3.1 Presentation

The example chosen to present the implementation of parametric studies is presented in the figure below. It is a beam clamped at one end and subjected to a distributed pressure at the other end. The aim of this parametric study is to determine the evolution of the von Mises equivalent stress along the upper line of the beam as a function of the orientation $\alpha$ .

The data files are those of the test case distr01a.

![Figure](/figures/u2.08.07/Shape20.gif)

The analyses will be carried out every $22.5°$ , for an angle $\alpha$ varying from $0°$ to $90°$ . The number of analysis scenarios to be carried out is therefore 5. In the table below we present the values that the parameters $\mathit{FX}$ and $\mathit{FY}$ will take successively.

| Scenario no. | Angle $\alpha$ | $\mathit{FX}=P.\cos(a)$ | $\mathit{FY}=P.\sin(a)$ |
| --- | --- | --- | --- |
| 1 | 0.0° | ${10}^{6}$ | $0.$ |
| 2 | 22.5° | $9.23879\times {10}^{5}$ | $-3.82683\times {10}^{5}$ |
| 3 | 45.0° | $7.07106\times {10}^{5}$ | $-7.07106\times {10}^{5}$ |
| 4 | 67.5° | $3.82683\times {10}^{5}$ | $-9.23879\times {10}^{5}$ |
| 5 | 90.0° | $0.$ | $-{10}^{6}$ |

Table 3.1-1: Values of the parameters

The command file of the nominal study is distr01a.comm.

In the remainder of this presentation, we shall detail the implementation of this type of analysis, namely:

- the generation of the 'distr' file
- the use of the parameters in the command file.

### 3.2 Definition of the parameter set and of the analysis cases

It is possible to define the parameters in the '.distr' file in two ways:

- Explicitly: in this case the user supplies all the values that the parameters can take.
- Computed: in this case the user resorts to python programming

  - to compute these parameters automatically, in conditional form or not,
  - to define these analysis scenarios automatically, for example by sweeping all the possible combinations of parameters or by choosing the min/mean/max values of the parameters.

#### 3.2.1 Explicit 'distr' file

In this case, one writes explicitly the values of the parameters in the 'distr' file. In the case of the example, it appears in the following form (file distr01a.50 of the test case):

```text
VALE=(

_F(F_Norm=1.E6, F_Tang=0.), # cas de calcul n°1

_F(F_Norm=9.23879E5,F_Tang=-3.82683E5), # cas de calcul n°2

_F(F_Norm=7.07106E5,F_Tang=-7.07106E5), # cas de calcul n°3

_F(F_Norm=3.82683E5,F_Tang=-9.23879E5), # cas de calcul n°4

_F(F_Norm=0., F_Tang=-1.E6), # cas de calcul n°5

)
```

**Figure** 3.2.1-а **:** **Explicit** 'distr' **file**

#### 3.2.2 Computed 'distr' file

In this case, the writing of the 'distr' file is less simple; one calls upon the programming of the python language. For this example, it appears in the following form (file distr01a.51 of the test case):

```text
from math import pi, cos, sin

import numpy

VALE = []

n = 5

list_theta = numpy.arange(n) * 22.5 * pi / 180.

P = 1.e6

for a in list_theta:

VALE.append(_F(F_Norm = P*cos(a),

F_Tang = P*sin(a),))
```

**Figure** 3.2.2-а **: Computed** 'distr' **file**

### 3.3 Use of the parameters in the command file

It is sufficient to reference, in the nominal command file, the names of the parameters present in the 'distr' file.

```text
DEBUT()

# Initialisation (ici apparaitront les valeurs des paramètres)

F_Norm=0.

F_Tang=0.

...

CHAR=AFFE_CHAR_MECA(MODELE=MODE,

FORCE_CONTOUR=_F(GROUP_MA = 'Press',

FX = F_Norm,

FY = F_Tang),)
```

## 4 Advice on use

Here is some advice:

- The standard study must be valid before being derived over the parameter set. It must run without error.
- Before being derived over the parameter set, it is also important to optimise the analyses by reducing the execution time, ...
- Check that the parameter file 'distr' is correct.
- Beware of the disk space: if the number of analyses and their size are large, the saving of the databases can take up a great deal of space.
- Check the definition of the variables in the command file: is it correct?
- Test the correct functioning of your parametric study by using a 'distr' file which defines only a single parameter set.

| Where does one define the parameters? | In the file: * .distr: one defines there their names and their values * .comm: one defines there the python variable name |
