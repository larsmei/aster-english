# u4.44.13 Operator DEFI_CONT

**Summary:**

One defines in this operator the unilateral contact and friction conditions for its (exclusive) use in the operator [MECA_NON_LINE](doc:u4.51.04)

For contact in [STAT_NON_LINE](doc:u4.51.03) and [DYNA_NON_LINE](doc:u4.53.01), refer to the documentation of [DEFI_CONTACT](doc:u4.44.11).

This documentation is provisional, the operator cannot be used in
the AIP studies and it is outside the scope of qualification.

## 1 Purpose

Assign unilateral contact and friction conditions in mechanics. The following points are detailed:

- control of the pairing for the facing boundaries;
- the physical and numerical parameters, useful for the various formulations available.

## 3 Data setup

### 3.1 Principles

The command makes it possible to describe the zones subjected to unilateral contact conditions with or without friction. The description is made at two levels:

- The global parameters, such as the parameters for controlling the non-linear solution algorithm (fixed-point or Newton loops, parameters specific to the solver), are to be supplied in the command [MECA_NON_LINE](doc:u4.51.04)
- The local parameters specific to each contact zone.

The concept produced by `DEFI_CONT` is then supplied as a parameter in the simple keyword CONTACT of the command [MECA_NON_LINE](doc:u4.51.04). Each zone comprises two surfaces which may come into contact, and which are described by the data of the mesh-cell groups which constitute them.

The sets of mesh cells potentially in contact are skin mesh cells: surface and linear in dimension 3 (QUAD9, QUAD8, QUAD4, TRIA7, TRIA6, TRIA3, SEG3, SEG2), linear and point in dimension two (SEG3, SEG2 and POI1).

The structures studied may undergo large sliding relative to one another.

### 3.2 General parameters

#### 3.2.1 Keyword MODELE

The keyword MODELE expects a concept produced by the operator [AFFE_MODELE](doc:u4.41.01) in which are defined the
types of finite elements assigned on the mesh. The model is necessarily of type MECANIQUE.

#### 3.2.2 Keyword INFO

The keyword `INFO` manages the level of the printouts in the message file. This printout can produce very large text files; it should therefore be used with caution on large-sized studies.

### 3.3 Zonal parameters

#### 3.3.1 Definition of a zone

A contact **zone** is defined by two groups: a group of slave mesh cells and a group of master mesh cells given by the keywords `GROUP_MA_MAIT` and `GROUP_MA_ESCL`.

In order to facilitate the compatibility of the methods using Lagrange multipliers, it is possible to exclude contact nodes by the keywords  `SANS_GROUP_MA` and `SANS_GROUP_NO`. In this case it is a matter of excluding the nodes carrying Lagrange multipliers. These keywords therefore concern the *slave* surfaces.

#### 3.3.2 Pairing

The first phase of carrying out contact-friction is the *pairing* phase. The pairing operation consists in finding which mesh cells and which nodes are potentially in a contact situation.

When `APPARIEMENT="MORTAR"` must be used, several pairing methods are available:

- if `TYPE_APPA="PANG"`, one uses the PANG method implemented in `DEFI_CONTACT`, which is based on a traversal of the mesh cells by the neighbours (in the sense of the edges);
- if `TYPE_APPA="RAPIDE"`, one uses a method inspired by the historical PANG method. This approach is used by default;
- if `TYPE_APPA="FORCEBRUTE"`, one uses a brute-force type algorithm, in which one performs a double loop over the slave and master mesh cells. This algorithm is sub-optimal in terms of computational cost, but it is the most numerically robust.

Two additional parameters may be supplied by the user in the case of this pairing, `APPA_TOLE` and `AIRE_TOLE`.
These two quantities correspond to numerical tolerances used in all of the pairing algorithms mentioned above. `APPA_TOLE`
is a tolerance used in the Newton algorithms, whereas `AIRE_TOLE` is a criterion on the computed intersection area.
For this latter criterion, one allows oneself not to consider intersection areas that are "too small". Mathematically, this amounts to keeping
only mesh cells satisfying:

$$
|\Omega_{inter}| > \delta_{area} |\texttt{F}^s|
$$

where $\Omega_{inter}$ is the intersection obtained, $\delta_{area}$ the tolerance given by `AIRE_TOLE`, and
$\texttt{F}^s$ the initial slave mesh cell considered.

#### 3.3.3 Additional parameters related to pairing

The parameter `COEF_MULT_APPA` makes it possible to improve the pairing phase by pre-detecting whether two mesh cells are potentially in contact. One defines the distance $d_{\text{cell}}$ between two cells defined by

$$
d_{\text{cell}}
=
\Vert
    \vector{X}_b^{\text{s}}
    -
    \vector{X}_b^{\text{m}}
\Vert
$$

with $\vector{X}_b^{\text{s}}$, (respectively $\vector{X}_b^{\text{m}}$) is the vector of the coordinates of the barycentre of the slave mesh cell (respectively master).

The mesh cells are *potentially* paired if, and only if:

$$
d_{\text{cell}}
\le
2 \, d_{r} \, \max \left( d^{\text{s}} -  d^{\text{m}} \right )
$$

with $d^{\text{s}}$ (respectively $d^{\text{m}}$) the diameter of the slave mesh cell (respectively master) and $d_{r}$ the coefficient given by `COEF_MULT_APPA`.
If `COEF_MULT_APPA` is negative, this preliminary sorting is deactivated.

The keyword `VERI_NORM` checks the orientation of the normals to the surface mesh cells in 3D (skin mesh cells TRIA or QUAD) and to the linear mesh cells in 2D (skin mesh cells SEG). If a normal is not outward, a fatal error message is emitted.

In order to reorient the mesh cells so as to have outward normals, one must use the command [MODI_MAILLAGE](doc:u4.23.04), keyword `ORIE_PEAU`. No check is possible on the shells or the plates. In order to check their orientation, one also refers to the command [MODI_MAILLAGE](doc:u4.23.04), keyword ORIE_NORM_COQUE.

The keyword `CONTACT_INIT` makes it possible to set the contact status at the initial state.
By default, only the links with zero gap, or which are interpenetrated, are activated by the algorithm (`CONTACT_INIT="INTERPENETRE"`). It is nevertheless possible to force the algorithm to activate all the links without exception (`CONTACT_INIT="OUI"`). The value `CONTACT_INIT="INTERPENETRE"` is mandatory in the case of a restart of the analysis with an initial state. It is also possible to deactivate any initial contact by `CONTACT_INIT="NON"`.

- It is important to check that the connectivity of these mesh cells is such that the normal to the structure is outward (to do this, use [MODI_MAILLAGE](doc:u4.23.04)
- The intersection between the slave surface and the master surface of one and the same zone must be disjoint, or else the common nodes must be excluded
- The slave surfaces must imperatively be pairwise disjoint in the continuous formulation

**Notes**

#### 3.3.4 Integration method

In the case of a pairing of type `MORTAR`, once it has been carried out, several integration methods are available.
The keyword `TYPE_INTE` makes it possible to choose the integration method to be used for the integration over the contact integrals. The case
`TYPE_INTE="SEG_BASE"` consists in intersecting the slave and master mesh cells, and in remeshing the intersection area obtained from the barycentre.
This option is the one chosen by default. The case `TYPE_INTE="ELEM_BASE"` consists in retaining only the intersection points of the slave mesh cell which
are projected into the intersection computed beforehand.

#### 3.3.5 Modifications of the gap

The gap is always computed as being the minimum distance between the slave node and the projection onto the nearest master mesh cell. It is however possible to define gap values “hard-coded”, for example in order to simulate the presence of a hole or of a bump not represented by the mesh, or in order to take account of the geometric characteristics of the structural elements which use the notion of neutral fibre or of mean surface.

The keyword `DIST_SUPP` makes it possible to modify the gap between the two surfaces. The keyword accepts functions or formulae.
A negative value makes it possible to “hollow out” a surface virtually (master as well as slave). Conversely, a positive value makes it possible to “thicken” a surface.

The quantities supplied are necessarily functions of the space variables or of time ($\left( X, Y, Z,\text{INST} \right)$ ). If the user desires a fixed value, a constant function must be defined (see [DEFI_CONSTANTE](doc:u4.31.01)).

The keywords `DIST_POUTRE` and `DIST_COQUE` make it possible to introduce a fictitious gap which rests on the description of the structural elements in the concept produced by [AFFE_CARA_ELEM](doc:u4.42.01), which the user has mandatorily supplied:

- for the beam elements (modelling POU_*), the keyword `DIST_POUTRE` stipulates that the code must take account of an additional gap corresponding to the radius of the **circular** section of the beam.
- for the plate or shell elements (modelling DKT or COQUE_3 for example), the keyword `DIST_COQUE` stipulates that the code must take account of an additional gap corresponding to the half-thickness about the mean sheet of a shell.

Caution: when one uses these keywords, the fictitious gap is added only on the slave surface. If one models a contact between two structural elements, one will therefore also have to use `DIST_MAIT`.

When one uses one of these keywords, it is necessary to supply `CARA_ELEM`.

#### 3.3.6 Contact algorithms

The contact method is chosen by the keyword `ALGO_CONT`. There are two possibilities:

- Augmented Lagrangian methods (`LAGRANGIEN`), which solve the problem by dualisation and introduction of Lagrange multipliers (on the nodes of the slave surface)
- Penalisation method (`PENALISATION`), which is a method that solves the problem by regularisation (and therefore in an approximate manner). It is a *non-consistent* penalisation method, that is to say that it introduces an error on the solution which does not fade when one refines the mesh. One must then adapt the penalisation coefficient in order to improve the accuracy of the resolution
- Nitsche method (`NITSCHE`), which is a method that solves the problem by regularisation (and therefore in an approximate manner). The Nitsche method is a *consistent* penalisation method, that is to say it converges towards the solution when one refines the mesh. It is available only in 2D and for isotropic elastic constitutive behaviours

There exist variants. For the augmented Lagrangian method, the keyword `VARIANTE` makes it possible to choose between the classical method of Alart and Curnier (CLASSIQUE) and the method developed by Poulios and Renard (ROBUSTE).

In both cases, the keyword `COEF_CONT` makes it possible to set the augmentation parameter, which acts on the speed of convergence but not on the quality of the result (the method is *exact* and respects the unilateral condition).

For the Nitsche method, there exist three variants according to the choice of a coefficient which one generally denotes $\theta$.
The keyword `SYME` makes it possible to choose between the variant producing a *symmetric* matrix (case $\theta=1$) and a *non-symmetric* matrix (cases $\theta=0$ and $\theta=-1$). In this latter situation, the keyword `VARIANTE` makes it possible to choose the value of the coefficient $\theta$. The case $\theta=0$ corresponds to the value `RAPIDE` of this keyword and the case $\theta=-1$ corresponds to the value `ROBUSTE`.

It should be noted that the coefficient $\theta$ makes it possible to bring out several variants, but that it is independent of the penalisation coefficient necessary for Nitsche and given by the keyword `COEF_CONT`.

For the augmented Lagrangian method, the keyword variante makes it possible to choose between the formulation of Alart and Curnier (`VARIANTE="CLASSIQUE"`) or the formulation of Poulios and Renard (`VARIANTE="ROBUSTE"`).
The classical method uses an approximation of the tangent matrix by perturbation. The keyword `TYPE_MATR_TANG` makes it possible, on the other hand, to choose between an approximation of the matrix by `PERTURBATION` or `ANALYTIQUE` for the Poulios-Renard formulation.

#### 3.3.7 Friction algorithms

In order to assign Coulomb friction to the contact zones, use the keyword `FROTTEMENT="OUI"`. The parameter `COULOMB` makes it possible to set the friction coefficient.
In this case, the formulations by augmented Lagrangian and by penalisation are available, that is `ALGO_FROT="LAGRANGIEN"` or `ALGO_FROT="PENALISATION"`.

For the formulation by augmented Lagrangian, one has the choice between the classical formulation (`VARIANTE="CLASSIQUE"`) or the Poulios-Renard formulation (`VARIANTE="ROBUSTE"`). The parameter `COEF_FROT` makes it possible to set the augmentation coefficient only in the classical case, because the Poulios-Renard formulation uses the same augmentation coefficient for the contact and for the friction.

For the formulation by penalisation, the same augmentation coefficient is used for the contact and for the friction.

#### 3.3.8 Parameters and algorithms used

When using the penalisation algorithms (`ALGO_CONT="PENALISATION"`) or the augmented Lagrangian (`ALGO_CONT="LAGRANGIEN"`), it is necessary to define the penalisation or augmentation coefficients.

The number of parameters to be supplied depends on the formulation chosen:

- **Formulations with a single parameter** (coming from the formalism of Poulios & Renard):

A single coefficient (common to the contact and to the friction) must be supplied via the keyword `COEF_CONT`. This case concerns the following configurations:

  - `ALGO_CONT="LAGRANGIEN"` associated with `VARIANTE="ROBUSTE"`,
  - `ALGO_CONT="PENALISATION"`.
- **Other formulations**:

Two distinct keywords must be supplied:

  - `COEF_CONT` for the parameter related to the contact.
  - `COEF_FROT` for the parameter related to the friction (if the latter is taken into account).
