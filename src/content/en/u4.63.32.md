# u4.63.32 Operator REST_SOUS_STRUC

## 1 Purpose

Recover in the physical basis results in generalised coordinates.

This operator makes it possible, from results on a system in generalised coordinates obtained by modal recombination methods tran_gene, cyclic substructuring methods mode_cycl, dynamic substructuring mode_gene or harmonic substructuring harm_gene, to recover the results in the initial physical system.

The concept produced is a concept of type:

- dyna_trans if the generalised results come from an analysis by modal recombination or following the extrapolation of experimental measurement results onto a numerical model (the input concept is of type tran_gene) or following the recovery of a concept dyna_trans on a new visualisation mesh,
- mode_meca following an analysis by cyclic substructuring (mode_cycl), by dynamic substructuring (mode_gene) or if the analysis corresponds to the recovery of a concept mode_meca on a new visualisation mesh,
- dyna_harmo following an analysis by harmonic substructuring (harm_gene),
- evol_noli following a non-linear analysis mixed with a modal analysis on its non-linear part

## 2 Syntax

```text
/ dyna_trans
/ dyna_harmo
/ evol_noli
/ mode_meca = REST_SOUS_STRUC(
    ◆ / RESULTAT = evol_noli / dyna_trans / mode_meca,
      / RESU_GENE = mode_gene / tran_gene / harm_gene / mode_cycl,
    ◆ / SQUELETTE = squelette,
    ◇ NUME_DDL = nume_ddl,
    ◇ MODE_MECA = mode_meca,
    ◇ / TOUT_ORDRE = "OUI" (ou non renseigné),
      / NUME_ORDRE = int,
      / INST = float,
      / LIST_INST = listr8,
      / TOUT_INST = "OUI" (ou non renseigné),
      / NUME_MODE = int,
      / FREQ = float,
      / LIST_FREQ = listr8,
    ◇ CRITERE = / "ABSOLU",
                / "RELATIF" (par défaut),
    # Si: (equal_to("CRITERE", 'RELATIF'))
        ◇ PRECISION = float (défaut: 1e-06),
    # Si: (equal_to("CRITERE", 'ABSOLU'))
        ◆ PRECISION = float,
    ◇ INTERPOL = / "NON" (par défaut),
                 / "LIN",
    ◇ TOUT_CHAM = "OUI" (ou non renseigné),
    # Si: not exists("TOUT_CHAM")
        ◇ NOM_CHAM = / "DEPL",
                     / "VITE",
                     / "ACCE" (par défaut),
                     / "ACCE_ABSOLU",
                     / "EFGE_ELNO",
                     / "SIPO_ELNO",
                     / "SIGM_ELNO",
                     / "FORC_NODA",
    ◇ / GROUP_NO = grno,
    ◇ GROUP_MA = grma,
    ◇ CYCLIQUE = _F(
         ◇ NB_SECTEUR = int,
         ◇ NUME_DIAMETRE = int,
         ◇ RESULTAT2 = evol_char / dyna_trans / evol_noli / evol_elas / mode_meca,
      ),
      / SOUS_STRUC = text,
      / SECTEUR = int,
    ◇ TITRE = text,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Operands RESU_GENE / RESULTAT

/    RESU_GENE = tg

| <string>:12: (INFO/1) Unexpected possible title overline or transition. Treating it as ordinary text because it's so short./ | concept of type tran_gene containing, for various time instants, generalised vectors of type displacement, velocity and acceleration of the transient response computed by substructuring. |
| --- | --- |
|  |  |
| <string>:12: (INFO/1) Unexpected possible title overline or transition. Treating it as ordinary text because it's so short./ | concept of type mode_cycl containing the generalised vectors of the modes computed by cyclic substructuring. |
|  |  |
| <string>:12: (INFO/1) Unexpected possible title overline or transition. Treating it as ordinary text because it's so short./ | concept of type mode_gene containing the generalised vectors of the modes computed by dynamic substructuring. |
|  |  |
| <string>:12: (INFO/1) Unexpected possible title overline or transition. Treating it as ordinary text because it's so short./ | concept of type harm_gene containing the generalised vectors of type displacement, velocity and acceleration of the harmonic response of a structure computed by substructuring. |

/    RESULTAT

This keyword may be used when one first recovers a result coming from an analysis by dynamic substructuring on a first skeleton (visualisation mesh). One then defines an enriched skeleton in which one has merged the nodes at the interfaces of the substructures and recovered all or part of the node or mesh-cell groups of the initial mesh. The keyword RESULTAT then corresponds to the recovery of a concept mode_meca, dyna_trans, evol_noli on a new enriched skeleton (cf. example in [§4]).

### 3.2 Operand MODE_MECA

```text
◊    MODE_MECA = mode
```

Concept of type mode_meca containing a basis of eigenmodes obtained by dynamic substructuring.

This operand is used in the case of a recovery in the physical system of a transient-analysis result carried out on a modal basis computed by dynamic substructuring. The modal basis contained in the concept mode_meca was obtained by a previous REST_SOUS_STRUC.

In this case, one must supply the same recovery support (keyword SQUELETTE or SOUS-STRUC) used for the recovery of the modal basis.

### 3.3 Operand NUME_DDL

```text
◊    NUME_DDL = numeddl
```

Concept of type nume_ddl containing a numbering corresponding to a reduced model in the case of an analysis with dynamic condensation when the user wishes a recovery on the degrees of freedom belonging to this reduced model.

This operand thus makes it possible to obtain, following the recovery, a concept mode_meca which could be used subsequently for an analysis on the model.

### 3.4 Operands TOUT_ORDRE / NUME_ORDRE / TOUT_INST / LIST_INST / INST

```text
◊    /    TOUT_ORDRE = 'OUI'
```

In order to recover on all the modes of the concept mode_cycl or mode_gene.

```text
/    NUME_ORDRE = num
```

List of integers containing the numbers of the modes on which the recovery is carried out.

```text
/    NUME_MODE = num
```

List of integers containing the numbers of the modes in the global spectrum on which the recovery is carried out.

```text
/    TOUT_INST = 'OUI'
```

If one wishes to recover on all the time instants contained in the generalised result (tran_gene).

/ LIST_INST = list

List of increasing reals of type listr8 containing the time instants for which one wishes to carry out the recovery.

/ INST = inst

List of reals containing the time instants on which the recovery is carried out.

For a transient analysis, one checks that the time instants requested by the option LIST_INST do indeed lie in the domain of definition of the tran_gene.

The results at an arbitrary time instant may be obtained by linear interpolation between the results at two analysis time instants actually contained in the tran_gene.

### 3.5 Operands FREQ / LIST_FREQ

These operands are used in the case of a recovery of generalised harmonic analyses (harm_gene).

```text
/    FREQ = freq
```

Frequency at which one wishes to recover the harmonic analysis

```text
/    LIST_FREQ = list
```

List of reals containing the frequencies for which one wishes to carry out the recovery.

For each frequency indicated, one recovers the fields obtained at the nearest analysis frequency. There is no interpolation.

### 3.6 Operands TOUT_CHAM / NOM_CHAM

```text
◊    /    TOUT_CHAM = 'OUI'
```

Makes it possible to recover the fields of symbolic name DEPL, VITE and ACCE contained in the generalised result (tran_gene, harm_gene).

```text
/    NOM_CHAM = nomcha
```

List of the symbolic names of the fields that one wishes to recover: 'DEPL', 'VITE', 'ACCE'.

### 3.7 Operand INTERPOL

```text
◊    INTERPOL =
```

| 'LIN': | an interpolation is allowed between two time instants; this interpolation can be used only between two analysis time instants, but may lead to errors if the two archiving time instants [U4.53.03](doc:u4.53.03) are separated by a time which is very long with respect to the periods of the phenomena studied. |
| --- | --- |
| 'NON' : | the recovery must be carried out stricto sensu. |

### 3.8 Operands PRECISION / CRITERE

```text
◊    PRECISION = prec
```

```text
◊    CRITERE =
```

When INTERPOL is 'NON', indicates with what precision the search for the time instant to be recovered must be carried out

| 'ABSOLU': 'RELATIF': | search interval [Inst - prec, Inst +prec], search interval [(1 - prec).Inst, (1 + prec) .Inst] Inst being the recovery time instant. |
| --- | --- |

### 3.9 Operand SECTEUR

```text
◊    /    SECTEUR
```

Number of the sector of the cyclic structure on which the result (of type mode_cycl) will be recovered in the physical system in cyclic substructuring.

### 3.10 Operand SQUELETTE

```text
/    SQUELETTE
```

Name of the skeleton mesh of the global structure on which the result will be recovered: see the operator DEFI_SQUELETTE [U4.24.01](doc:u4.24.01).

### 3.11 Operand SOUS_STRUC

```text
/    SOUS_STRUC = nom_sstruc
```

Name of the substructure on which the result will be recovered: see the operator DEFI_MODELE_GENE [U4.65.02](doc:u4.65.02).

### 3.12 Operand GROUP_NO

```text
◊    /    GROUP_NO = lgrno
/    GROUP_MA = lgrma
```

After a transient dynamic analysis on a modal basis, the user may recover kinematic fields on only part of the nodes or mesh cells of the mesh.

List of the node/mesh-cell groups corresponding to the locations where the user wants to recover kinematic fields.

### 3.13 Operand CYCLIQUE

```text
◊     CYCLIQUE = _F(
◊NB_SECTEUR = ns                    [I]
◊NUME_DIAMETRE = nl                [I]

◊RESULTAT2 = res                     [evol_elas]

[evol_noli]

[dyna_trans]

[evol_char]
[mode_meca]
)
```

The operator DEFI_SQUELETTE [U4.24.01](doc:u4.24.01) makes it possible to regenerate the complete mesh of a structure with cyclic symmetry from the mesh of one sector of this structure.

The option CYCLIQUE in REST_SOUS_STRUC makes it possible to recover on this new skeleton mesh the fields at the nodes computed on the model of the single sector and taking cyclic symmetry into account (with LIAISON_MAIL or LIAISON_CYCL for example).

The action of this option of REST_SOUS_STRUC consists in:

> 1/ in the static case (a single field at the nodes supplied) rotating this field at the nodes onto the skeleton mesh
> 2/ in the dynamic case (2 fields at the nodes supplied, RESULTAT and RESULTAT2) combining the fields at the nodes and rotating them onto the new mesh.

### 3.14 Operand TITRE

```text
◊    TITRE = titre
```

Title attached to the concept produced by this operator [U4.03.01](doc:u4.03.01).

## 4 Example: Recovery of a mode_meca on an enriched skeleton, use of the keyword RESULTAT

An example of use of the keyword RESULTAT is given below. The complete command file corresponds to the test case SDLS106A.

First step: computation of the generalised eigenmodes (obtained by dynamic substructuring) of the global structure

```text
resgen = CALC_MODES (MATR_RIGI = risgen,

MATR_MASS = masgen,

OPTION = 'PLUS_PETITE',

CALC_FREQ = _F( NMAX_FREQ = 6 ) )
```

% definition of the first visualisation mesh of the computed quantities

```text
squel = DEFI_SQUELETTE (MODELE_GENE = modege,

SOUS_STRUC = _F(NOM = 'carre1', TOUT ='OUI' ),

SOUS_STRUC = _F(NOM = 'carre2', TOUT ='OUI' ) )
```

% recovery of the mode_gene on this first skeleton:

```text
modglo = REST_SOUS_STRUC (RESU_GENE = resgen,

SQUELETTE = squel,

TOUT_ORDRE = 'OUI', TOUT_CHAM = 'OUI')
```

% definition of the enriched skeleton in which one has merged the nodes at the interfaces of the substructures and recovered all or part of the node or mesh-cell groups of the initial mesh:

```text
squelbis = DEFI_SQUELETTE (MODELE_GENE = modege,

SQUELETTE = squel,

RECO_GLOBAL =_F ( TOUT='OUI', DIST_REFE = 0.1))
```

% recovery of the first mode_meca on the new skeleton:

```text
modglbis = REST_SOUS_STRUC (SQUELETTE = squelbis,

RESULTAT = modglo)
```
