# u4.42.05 Macro-command CALC_PRECONT

**Summary**

This macro-command makes it possible to tension the cables in a structure, in such a way that, at the end of this analysis, the structure is in equilibrium and the tension is equal to the tension given by the BPEL91 rules, computed by the command DEFI_CABLE_BP.

It also makes it possible:

- to apply the prestressing progressively, so as to be able to treat the case in which the concrete will plasticise or be damaged according to the constitutive model adopted,
- to carry out the phasing of the prestressing, that is to say the tensioning of the cables in a sequential way.

In this tensioning phase, the constitutive behaviour of the steel is considered as purely elastic.

For more details on the model implemented by the command, consult the documentation entitled: “Modelling of prestressing cables” [R7.01.02](doc:r7.01.02).

## 2 Operands

### 2.1 Operands MODELE / CHAM_MATER / CARA_ELEM

```text
♦    MODELE = mo
```

Name of the model whose elements are the subject of the mechanical analysis.

```text
♦    CHAM_MATER = chmat
```

Name of the material field assigned on the mesh. Warning: all the mesh cells of the model must be associated with a material.

```text
♦    CARA_ELEM = carac
```

Name of the characteristics of the shell, beam, pipe, bar, cable and discrete elements assigned on the model mo.

### 2.2 Operand DOUBLE_LAGRANGE

This keyword makes it possible to say whether or not the user wishes to double the Lagrange multipliers
used in order to define the dualisation of the boundary conditions in the assembled matrix.

Concretely, doubling the Lagrange multipliers makes it possible to use linear solvers which do not
allow pivoting. Not doubling the Lagrange multipliers makes it possible to reduce the number of degrees of
freedom of the problem (and therefore the size of the problem to be solved), but its use is limited to the
solvers MUMPS and Petsc.

Note that the two Lagrange multipliers associated with the relation will be such that the first
will be located before all the terms involved in the relation and the second after, in the assembled
matrix. This choice has the advantage of having an assembled matrix whose storage size is
smaller, but has the disadvantage of being able to make a singularity appear in the matrix.
The numbering being in any case liable to be modified by the renumberer of the external solver
chosen, this detail therefore remains purely technical.

### 2.3 Keyword EXCIT

```text
♦    EXCIT =
```

This factor keyword makes it possible to describe, at each occurrence, a load. One must supply the boundary conditions for the structure, possibly instantaneous loadings such as gravity, as well as the kinematic links linked to the cables which have already been tensioned by a previous call to CALC_PRECONT. In no case must one include the loading of the cable (or cables) that one wants to tension by the call to this macro-command, nor the loadings linked to the cable (or cables) declared inactive.

#### 2.3.1 Operands CHARGE

```text
♦    CHARGE = chi
```

chi is the mechanical loading specified at the $i$-th occurrence of EXCIT.

### 2.4 Keyword COMPORTEMENT

The syntax of this keyword, common to the command STAT_NON_LINE, is described in document [U4.51.11](doc:u4.51.11).

### 2.5 Keyword INCREMENT

```text
♦    INCREMENT =
```

Defines the time intervals taken in the incremental method.

> **♦**     If LIST_INST = litps             [list_inst]

The analysis time instants are those defined in the concept litps by the operator DEFI_LIST_INST [U4.34.03].


In the case of bonded cables (ADHERENT=’OUI’ in DEFI_CABLE_BP), even if the analysis is carried out with several time steps, only the last time step is stored in the result concept.

*In the course of the process of tensioning the cables, time instants are generated automatically in addition to those supplied by the user. It is therefore entirely normal to see* *appear, in the message file, analyses with* *STAT_NON_LINE at time instants that the user has not specified. These time instants are* *also* *stored in the result concept.*

#### 2.5.2 Operands INST_INIT / INST_FIN

```text
◊        INST_INIT        =     instini
```

The initial time instant of the analysis (which therefore is not (re)computed) must be designated by its value.

If this initial time instant is not specified, the default is computed in the following way:

- if an initial state is specified (operand ETAT_INIT) and if it defines a corresponding time instant (by EVOL_NOLI or INST_ETAT_INIT), then the initial time instant is that defined by the initial state,
- if there is no initial state, or if it does not define a corresponding time instant (the fields are given in ETAT_INIT without specifying INST_ETAT_INIT), then one takes the first time instant of the list of time instants litps (NUME_INST_INIT =0).

```text
◊        INST_FIN            =     instfin
```

The final time instant (last step computed) is designated in the same way as the initial time instant, except that it is not possible to refer to the time instant of the initial state.

### 2.15 Keyword ENERGIE

This keyword makes it possible to activate the computation of the energy balance and its display in the course of the analysis of the stages of prestressing of the concrete and of the switch-over of the external forces into internal forces (see document [R4.09.01](doc:r4.09.01)).

This balance is stored in the table of name PARA_CALC, from which it can be extracted with the help of the command RECU_TABLE [U4.71.02]. The balance at the last time instant corresponds only to the energy balance of the stage of the switch-over of the external forces into internal forces. As mentioned in the doc [R7.01,02], this stage is a numerical device serving to make it possible to continue the analysis afterwards, and therefore the energy balance there is negligible. The energy balance at the end of the prestressing phase is that observed at the previous time instant.
