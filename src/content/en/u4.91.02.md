# u4.91.02 Procedure IMPR_GENE

## 1 Purpose

Write the result of a dynamic analysis in generalised variables to a file, in the 'RESULTAT' format.

At present this procedure makes it possible to write results in generalised variables coming from the following concepts:

- tran_gene,
- vect_asse_gene,
- harm_gene,
- mode_gene.

## 3 Keyword GENE

This factor keyword makes it possible to specify the results to be printed. At least one factor block of the keyword is necessary for each result that one wishes to print.

## 4 Operand RESU_GENE

This keyword makes it possible to specify the user name of the concept of type tran_gene, vect_asse_gene, harm_gene or mode_gene to be printed.

## 5 Access variables if the concept is of type vect_asse_gene

The keyword TOUT_CMP_GENE indicates that one wants or does not want to print the fields for all the numbers of generalised components (except those which correspond to Lagrange degrees of freedom).

The keyword NUME_CMP_GENE indicates that one wants to print the fields which correspond to a list of numbers of generalised components.

## 6 Access variables if the concept is of type mode_gene or harm_gene

### 6.1 Extraction of a result field: operands TOUT_CHAM / NOM_CHAM

The keyword TOUT_CHAM indicates that one wants to print all the fields actually computed.

The keyword NOM_CHAM makes it possible to choose a list of symbolic field names from among all the possible ones.

### 6.2 Extraction of a parameter: operands TOUT_PARA / NOM_PARA

The keyword TOUT_PARA indicates that one wants or does not want to print all the values of the parameters attached to the concept considered.

The keyword NOM_PARA makes it possible to choose a list of symbolic parameter names from among all the possible ones.

These keywords are available only for the concept of type mode_gene.

### 6.3 Operands TOUT_CMP_GENE / NUME_CMP_GENE

The keyword TOUT_CMP_GENE indicates that one wants to print the fields for all the numbers of generalised components (except those which correspond to Lagrange degrees of freedom).

The keyword NUME_CMP_GENE indicates that one wants to print the fields which correspond to a list of numbers of generalised components.

### 6.4 Operands TOUT_ORDRE / NUME_ORDRE / LIST_ORDRE

The keyword TOUT_ORDRE indicates that one wants to print the fields for all the order numbers.

The keywords NUME_ORDRE and LIST_ORDRE make it possible to print only the fields corresponding to a list of order numbers lordre or lent defined by DEFI_LIST_ENTI [U4.34.02](doc:u4.34.02) (lent is therefore a concept of type listis).

### 6.5 Operands TOUT_MODE / NUME_MODE

The keyword TOUT_MODE indicates that one wants to print the fields for all the mode numbers.

The keyword NUME_MODE indicates that one wants to print the fields corresponding to a list of mode numbers lmode. These numbers are those assigned by the analysis algorithm.

This keyword can be used only for a concept of type mode_gene.

### 6.6 Operands FREQ / LIST_FREQ

The keyword FREQ indicates that one wants to print the fields corresponding to a list of frequencies lfreq.

The keyword LIST_FREQ indicates that one wants to print the fields corresponding to a list of frequencies lreel, defined by the operator DEFI_LIST_REEL [U4.34.01](doc:u4.34.01) (lreel is therefore a concept of type listr8).

This keyword can be used for a concept of type harm_gene, and possibly mode_gene.

### 6.7 Operands CRITERE / PRECISION

The keyword PRECISION indicates with what precision one must carry out the search for the analysis frequency.

The keyword CRITERE indicates with what type of precision interval the search for the interpolation frequency must be carried out:

| 'ABSOLU': | search interval [fr-prec, fr+prec] |
| --- | --- |
| 'RELATIF': | search interval [(1-prec)fr, (1+prec)fr] |

## 7 Access variables if the concept is of type tran_gene

### 7.1 Extraction of a result field

- Operands TOUT_CHAM / NOM_CHAM

See [§6.1].

- Operands TOUT_CMP_GENE / NUME_CMP_GENE

See [§6.3]

- Operands TOUT_ORDRE / NUME_ORDRE / LIST_ORDRE

See [§6.4].

### 7.2 Operands INST / LIST_INST / CRITERE / PRECISION

The keyword INST indicates that one wants to print the fields corresponding to a list of time instants linst.

The keyword LIST_INST indicates that one wants to print the fields corresponding to a list of time instants lreel, defined by the operator DEFI_LIST_REEL [U4.34.01](doc:u4.34.01) (lreel is therefore a concept of type listr8).

For CRITERE / PRECISION see [§6.7] (replacing frequency by time instant).

## 8 Parameters for the printout of the results

### 8.1 Operand SOUS_TITRE

This argument makes it possible to print a comment title.

### 8.2 Operand FORMAT

Print format of the results in the output file.

For the moment only the RESULTAT format is available.

### 8.3 Operand INFO_GENE

When printing a generalised concept, one may have forgotten the exact content of the data structure. The operand INFO_GENE makes it possible to print this content (number of order numbers, list of the symbolic names of the fields actually computed, list of the symbolic names of the parameters actually computed, ...).

### 8.4 Extraction of a genealogy of the generalised model: operand INFO_CMP_GENE

This keyword indicates that one wants or does not want to print, for each generalised component, the name of the base_modale or mode_meca concept from which the mode corresponding to this component comes, its type (eigen or constrained), its frequency and the node of application of this mode if it is constrained.

### 8.5 Execution phase

For the concepts tran_gene and harm_gene, one checks that the time instants (frequencies) of extraction requested by the operands NUME_ORDRE, LIST_ORDRE, INST, LIST_INST, (FREQ, LIST_FREQ) are in the domain of definition of the concept. One also checks that the fields stipulated by the keywords TOUT_CHAM, NOM_CHAM have indeed been computed.

For the concept mode_gene, one checks that the names of the parameters specified by the keyword NOM_PARA are indeed admissible. If the mode number is selected by the operand NUME_MODE, one checks that this number is smaller than the total number of modes which define the mode_gene.

## 9 Examples

### 9.1 Printout of a vect_asse_gene

```text
IMPR_GENE     ( GENE =         _F(    RESU_GENE        = fgen,
NUME_CMP_GENE    = ‘OUI’        ),
_F(    RESU_GENE        = fgen,
INFO_CMP_GENE    = ‘NON’,
NUME_CMP_GENE    = 1            )
)
```

One obtains the following printout:

```text
CONCEPT    FGEN            DE TYPE VECT_ASSE_GENE
```

```text
NUME_CMP    VALEUR            BASE_MODALE    TYPE_MODE        FREQUENCE        APPLICATION
1        1.00000E+00    BAM01_CL        PROPRE            2.25079E-01
2        5.00000E-01    BAM01_CL        CONTRAINT        0.00000E+00    N03        DX
3        0.00000E+00    BAM02_CL        PROPRE            2.25079E-01
4        0.00000E+00    BAM02_CL        CONTRAINT        0.00000E+00    N01        DX

CONCEPT    FGEN            DE TYPE VECT_ASSE_GENE

NUME_CMP    VALEUR
1        1.00000E+00
```

### 9.2 Operand UNITE

◊    UNITE        =    / unit,                                        [I]

```text
/ 8,                     [DEFAUT]
```

The results are written, by default, to the file of logical unit 8. The user can define another output file whose logical unit he or she indicates.

### 9.3 Printout of a mode_gene

```text
IMPR_GENE     ( GENE =    _F(    RESU_GENE        = resgen,
INFO_GENE        = ’OUI’,
NUME_ORDRE    = 1,
NOM_PARA    = (‘FREQ’,‘MASS_GENE’,‘RIGI_GENE’),
INFO_CMP_GENE    = ‘NON’    ),
_F(    RESU_GENE        = resgen,
NUME_CMP_GENE    = (1, 3),
NUME_ORDRE = 1,
NOM_PARA    = (‘FREQ’,‘MASS_GENE’,‘RIGI_GENE’),
INFO_CMP_GENE    = ‘OUI’    )
)
```

The results are written, by default, to the file associated with logical unit 8. But the user can define another output file whose logical unit he or she indicates. [U4.12.01](doc:u4.12.01).
