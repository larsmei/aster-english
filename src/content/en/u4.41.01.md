# u4.41.01 Operator AFFE_MODELE

## 1 Purpose

Define the physical phenomenon modelled (mechanical, thermal or acoustic) and the type of finite elements.

This operator makes it possible to assign modellings over all or part of the mesh, which defines:

- the degrees of freedom on the nodes (and the associated conservation equation or equations),
- the types of finite elements on the mesh cells,

The capabilities of the finite elements that can be chosen are described in the [U3] booklets.

The types of mesh cells are described in document [U3.01.00](doc:u3.01.00).

This operator also makes it possible to define a distribution of the finite elements with a view to
parallelising the elementary analyses and the assemblies.

Produces a data structure of type modele.

## 3 Operands

### 3.1 Choice of the mesh

The keyword `MAILLAGE` gives the mesh associated with the study, on which one assigns the finite elements.

**Note**

For the axisymmetric modellings, the axis of revolution is the axis $Y$ of the mesh.
The whole structure must be meshed in $X\ge 0$. The axis ${Ox}$ therefore designates the
radial direction. The components of the computed fields will therefore be: $X$ for the radial
direction, $Y$ for the axial direction and $Z$ for the orthoradial
(circumferential) direction.

### 3.2 Assignment of the finite elements

The keyword `AFFE` defines the types of finite elements which will be assigned on the chosen mesh entities. For each occurrence, one specifies a modelling.

- the assignments are made by superposing the effects of the different keywords
- in the event of a conflict, the last keyword specified prevails over the previous ones.

**Note**

One recalls that the overloading rule is applied (see [U1.03.00](doc:u1.03.00)):

The mesh entities are specified by the keyword `TOUT = 'OUI'`, which assigns all
the mesh cells of the mesh, and `GROUP_MA = g_mail`, which assigns a list of mesh-cell groups.

The type of finite element is specified by the following keywords:

- `PHENOMENE`: physical phenomenon modelled (associated conservation equation)
- `MODELISATION`: type of interpolation and of discretisation
- `FORMULATION`: type of formulation in certain cases

The first two keywords `PHENOMENE` and `MODELISATION` are mandatory for each occurrence of the factor keyword `AFFE`. This pair of keywords defines in a one-to-one way the type of element assigned to a type of mesh cell.

In certain cases, it may be necessary to specify the `FORMULATION` used:

- For the discretisation of HHO type (`3D_HHO`, `AXIS_HHO` or `D_PLAN_HHO`), one can
specify whether it is a constant (`CONSTANTE`), linear (`LINEAIRE`), quadratic
(`QUADRATIQUE`), cubic (`CUBIQUE`) or quartic (`QUARTIQUE`) approach; see the documentation [R3.06.14](doc:r3.06.14).
There may exist limitations depending on the physics. For example, the constant approach
is available only in thermal analysis;
- For the discretisations in fluid or in fluid–structure interaction, one can specify whether
it is a formulation with three variables $(U,P,\varphi )$, with two variables
$(U,P)$ or $(U,\psi )$; see the documentation [R4.02.02](doc:r4.02.02).
- For the second-gradient modellings in mechanics, one can specify whether it is the
historical formulation of the second-gradient model that must be used (`DIL`)
or the incompressible formulation (`DIL_INCO`).
- For the stabilised mixed modellings, one can specify whether it is the
standard formulation of the model that must be used (`STA`)
or the incompressible formulation (`STA_INCO`).

- the keyword `PHENOMENE` must have the same value for all the occurrences of the factor keyword
`AFFE`.
- by assigning the finite elements on the volume mesh cells (and/or surface mesh cells) of the mesh-cell group
`g_mail`, if this mesh-cell group also contains the boundary mesh cells (and/or edge mesh cells) of the
volume mesh cells (and/or surface mesh cells), then one also automatically assigns on the latter
the finite elements necessary for certain analysis options (assignment of external loadings,
for example). If one needs to assign additional modellings on these interfaces,
one must then provide duplicated mesh cells in the mesh: this is for
example the case in fluid–structure interaction.

### 3.4 Assignment of the macro-elements

The keyword `AFFE_SOUS_STRUC` can be used only for a model using static substructures (or macro-elements or super-elements).

`SUPER_MAILLE` is the list of the super-mesh cells that one wants to assign in the model. As for the finite elements, it is not mandatory to assign all the mesh cells of the mesh. It is `AFFE_MODELE` which confirms which substructures will be used in the model. The difference with the classical finite elements is that, on the super-mesh cells, one chooses neither the `MODELISATION` nor the `PHENOMENE`, because the macro-element (built by the operator [MACR_ELEM_STAT](doc:u4.62.01)) which will be assigned on the super-mesh cell has its own modelling and its own phenomenon (those which served to compute it).

Warning! Your model must contain at least one finite element (keyword `AFFE`) when you use static substructures defined from a physical mesh (read by [LIRE_MAILLAGE](doc:u4.21.01)), because it is not possible to have only macro-elements in this case.

If `TOUT = 'OUI'`, all the (super) mesh cells are assigned.

### 3.5 Checks

The keyword `VERI_JACOBIEN` serves to check that the mesh cells of the model are not too distorted. One computes the Jacobian of the geometric transformation which transforms the reference element into each real mesh cell of the model. If, at the different integration points of a mesh cell, the Jacobian changes sign, this means that this mesh cell is very “badly shaped”. An alarm is then emitted.

The keyword `VERI_NORM_IFS` serves to check that all the normals on the fluid–structure interfaces (modelling of type `FLUI_STRU`) are indeed oriented in the same direction. If this is not the case, an alarm is emitted and the user is invited to reorient these normals either directly in the mesh, or via the command [MODI_MAILLAGE](doc:u4.23.04).

The keyword `VERI_PLAN` serves to check that the mesh cells of type `QUAD4` used in the plate formulations (`DKT`, `DST`, etc.) are indeed plane.
One builds a plane on the first three nodes of the element, then one computes the distance of the fourth point with respect to this plane.
If the distance is greater than $1,0 \times 10^{-4}$, then the alarm is emitted with the list of the mesh cells concerned.

The keyword `VERI_FORMULATION_IFS` serves to check that one uses the same `FORMULATION` for the fluid mesh cells and `FLUI_STRU`. Nevertheless, one can lift this check in certain situations. Typically, if the mesh cells assigned by the fluid (or the interface) are not connected to one another (by their nodes), one can assign different formulations.

### 3.6 Factor keyword `GRANDEUR_CARA`

The factor keyword `GRANDEUR_CARA` serves to define a few physical quantities characteristic of the problem treated. These quantities are currently used to “non-dimensionalise” certain terms of the error estimators in HM. See [R4.10.05](doc:r4.10.05).

### 3.7 Distribution of the mesh cells

#### 3.7.1 Principles

The factor keyword `DISTRIBUTION` makes it possible to distribute the finite elements of the model for the parallelism of the elementary analyses, of the assemblies and of certain linear solvers; see [User's guide to parallelism](doc:u2.08.06).

It defines how the mesh cells/elements will be distributed (or not) for the parallelised phases. The user therefore has the possibility of driving this distribution among the processors.

The parallelism operates:

- on the elementary analyses and on the assemblies of matrices and vectors (this is what the
factor keyword `DISTRIBUTION` makes it possible to control),
- at the solution of the linear system if the solver is parallelised ([Keyword SOLVEUR](doc:u4.50.01)).

**Note**

In the case of the parallelism mode (parallel mesh of type `maillage_p`), the distribution mode is
necessarily `CENTRALISE`, because the mesh has already been distributed and it is not
possible to redistribute the analyses again. If another distribution mode is chosen
for this parallelism mode, it will automatically be switched to mode `CENTRALISE` without
warning the user.

It is possible to modify the distribution mode in the course of one's study. It is sufficient to use the command [MODI_MODELE](doc:u4.41.02).

It can be convenient to restart a parallel analysis with a number of processors different from that used for the initial analysis. In particular, one may want to carry out certain post-processings in sequential mode. It is recommended to use the command
[MODI_MODELE](doc:u4.41.02) to define the distribution to be used on restart. More precisely, when the initial analysis has used parallelism by groups of elements (`GROUP_ELEM` or `SOUS_DOMAINE`), the command [MODI_MODELE](doc:u4.41.02) is useless.
On the other hand, when the initial analysis has used parallelism “by elements” (`MAIL_CONTIGU` or `MAIL_DISPERSE`), the command [MODI_MODELE](doc:u4.41.02) is mandatory. If one forgets it, one is stopped during the analysis by an error message.

#### 3.7.2 Choice of the method

There exist different modes of distribution of the mesh cells, controlled by the keyword `METHODE`.

When one chooses the method `METHODE='CENTRALISE'`, the parallelism begins only at the level of the linear solver. Each processor builds and supplies to the solver the whole of the system to be solved. The elementary analyses are not parallelised. This is the mandatory distribution method in the case of a parallel mesh of type `maillage_p`.

The distribution method `METHODE='GROUP_ELEM'` allows a perfect load balancing (in terms of numbers of elementary analyses) *a priori*, that is to say that each processor will carry out, for a given element type, the same number of elementary analyses (to within one). Obviously this in no way prejudges the final load balancing, in particular in non-linear analyses where the cost of an elementary analysis depends on parameters other than the element type.

In this mode, the elements of the model are grouped by “group” in order to pool certain analyses, which makes it possible to gain in efficiency. The number of elements per group can be chosen in the command [DEBUT](doc:u4.11.01).

Furthermore, this is the only mode able to distribute the elementary analyses induced by the late elements, that is to say by the loadings such as the dualised boundary conditions or the contact.

The distribution by `METHODE='MAIL_DISPERSE'` operates on the mesh cells. They are distributed evenly over the different processors available. The mesh cells are distributed over the different processors as one does when one deals cards to several players. One also speaks of a “cyclic” distribution.

For example, with a model comprising 8 mesh cells, run on 4 processors, one obtains the
following distribution:

| Distribution mode | Mesh cell 1 | Mesh cell 2 | Mesh cell 3 | Mesh cell 4 | Mesh cell 5 | Mesh cell 6 | Mesh cell 7 | Mesh cell 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| MAIL_DISPERSE | Proc. 0 | Proc. 1 | Proc. 2 | Proc. 3 | Proc. 0 | Proc. 1 | Proc. 2 | Proc. 3 |

One sees that, with this distribution mode, a processor will treat mesh cells regularly spaced in the order of the mesh cells of the mesh. The advantage of this distribution is that, “statistically”, each processor will treat as many hexahedra, pentahedra, …, and triangles.

The workload for the elementary analyses will in general be well distributed. On the other hand, the matrix assembled on a processor will be very “scattered”, unlike what happens for the following mode `MAIL_CONTIGU`.

The distribution by `METHODE='MAIL_CONTIGU'` operates on the mesh cells. They are distributed in packets of contiguous mesh cells over the different processors available.

For example, with a model comprising 8 mesh cells, a machine with 4 processors available, one
obtains the following distribution:

| Distribution mode | Mesh cell 1 | Mesh cell 2 | Mesh cell 3 | Mesh cell 4 | Mesh cell 5 | Mesh cell 6 | Mesh cell 7 | Mesh cell 8 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| MAIL_CONTIGU | Proc. 0 | Proc. 0 | Proc. 1 | Proc. 1 | Proc. 2 | Proc. 2 | Proc. 3 | Proc. 3 |

#### 3.7.3 Control of the load

For the distribution modes by elements, the workload for the elementary analyses may be less balanced. For example, a processor may have to treat only “easy” boundary mesh cells. On the other hand, the matrix assembled on a processor is in general more compact.

The keyword `CHARGE_PROC0_MA` is accessible only for the distribution modes `MAIL_DISPERSE` and `MAIL_CONTIGU`. Indeed these distribution modes do not in general share the analysis load fairly, because of the dualised boundary conditions, whose elementary analyses are treated by processor 0.

If one wishes to relieve processor 0 (or on the contrary to overload it), one can use the keyword `CHARGE_PROC0_MA`. It allows the user to choose the percentage of load that one wishes to assign to processor 0.

For example, if the user chooses `CHARGE_PROC0_MA=80`, processor 0 will treat 20% fewer elements than the other processors, that is 80% of the load that it should bear if the sharing were fair among the processors.

#### 3.7.4 Decomposition of the mesh

The distribution by the method `METHODE='SOUS_DOMAINE'` of the mesh cells is based on a decomposition of the mesh into subdomains, built by an external partitioning tool defined by the keyword `PARTITIONNEUR`.

The number of subdomains can be determined by the user, via the keyword `NB_SOUS_DOMAINE`.

By default, the number of subdomains is taken equal to the number of processors involved in the analysis.

The finite-element model elements carried by the mesh cells of each subdomain are then distributed by groups of similar elements (as in the distribution corresponding to the method `GROUP_ELEM`), in order to balance the elementary analyses as well as possible.

The prior partitioning of the mesh into subdomains makes it possible to ensure that all the elements of a group of finite elements belong to a single subdomain.

## 4 Execution phase

From the keywords `PHENOMENE`, `MODELISATION` and `FORMULATION`, one creates a data structure specifying the type of element attached to each mesh cell.

A brief reminder of the assignments is printed systematically (`INFO=1`) in the message file.

## 5 Example

For a modelling of the phenomenon 'MECANIQUE', one assigns on the mesh-cell group `gma` of the mesh `ma` isoparametric 3D finite elements.

If the mesh-cell group `gma` also contains the boundary mesh cells and/or the edge mesh cells of the volume mesh cells, then one also assigns on them the isoparametric finite elements necessary for certain analysis options (assignment of external loadings for example, cf. [AFFE_CHAR_MECA](doc:u4.44.01)).

```python
mo = AFFE_MODELE(MAILLAGE=ma, AFFE=(_F(GROUP_MA=gma, PHENOMENE="MECANIQUE", MODELISATION="3D")))
```
