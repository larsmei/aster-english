# u4.32.02 Operator LIRE_FONCTION

## 1 Purpose

Read a data file containing real values representing a function. Produces a concept of type fonction [U4.31.02](doc:u4.31.02) or nappe [U4.31.03](doc:u4.31.03).

## 3 Operands

### 3.1 Operand UNITE

```text
♦    UNITE = u
```

Integer, logical unit number for reading, defining the file in which the data are read.

### 3.2 Operand FORMAT

```text
◊    FORMAT = 'LIBRE' ou 'NUMPY',
```

Indicates the format of the file to be read. The NUMPY format indicates that the file was produced by numpy.save; in LIBRE format, it is a simple text file.

### 3.3 Operand SEPARATEUR

```text
◊    SEPARATEUR =    'None'ousep
```

Character separating the columns of numbers in the file to be read.

The default value 'None' means one or more blank characters. For the other separators, blank characters are tolerated between the numbers and the separator sep itself.

It is not used in NUMPY format.

### 3.4 Operands PROL_DROITE/PROL_GAUCHE / NOM_PARA / NOM_RESU / INTERPOL / VERIF / TITRE / INFO

The numerical values are read in the file indicated, then the function is actually created by lire_fonction by calling DEFI_FONCTION or DEFI_NAPPE.

Thus, these keywords are taken over unchanged from DEFI_FONCTION or DEFI_NAPPE and make it possible to specify the characteristics of the function produced: interpolation, prolongations, names of the access parameters.

### 3.5 Operand INDIC_PARA

```text
◊    INDIC_PARA =         /    [:ref:`indice1,indice2 <indice1,indice2>`]
```

This keyword is identical in principle to the keyword VALE_PARA of the command DEFI_FONCTION. It makes it possible to choose the column of numbers in the file read which will define the abscissae of the function, that is the values of the parameter.

One necessarily expects a list of two integers: the first designating the number of the 'block' in the file (cf. paragraph [§4] Examples), the second designating the column number. To identify the blocks of the file, any line which would not contain exclusively numbers and column separators is considered as a block separator. The columns are defined by the presence of the column separators which bound them (keyword SEPARATEUR).

The default value is [1,1]: one reads the first column of the first block.

In NUMPY format, there is only one "block", so the first index is always 1.

### 3.6 Operand TYPE

```text
◊    TYPE        =         /    'FONCTION' ,                [DEFAUT]
/    'FONCTION_C' ,
/    'NAPPE' ,
```

Specifies the type of function read and created: 'FONCTION', 'FONCTION_C' (call, in the macro-command, to DEFI_FONCTION) or 'NAPPE' (call to DEFI_NAPPE).

### 3.7 Case of a real function: TYPE='FONCTION'

```text
◊    INDIC_RESU =         /    [:ref:`indice1,indice2 <indice1,indice2>`]
```

Operating in the same way as INDIC_PARA, this keyword makes it possible to choose the column of numbers in the file read defining the ordinates of the function, that is the values of the result.

The default value is [1,2]: one reads the second column of the first block.

In NUMPY format, there is only one "block".

### 3.8 Case of a complex function: TYPE='FONCTION_C'

```text
◊    FORMAT_C    = 'REEL_IMAG'

♦    INDIC_REEL =         /    [:ref:`indice1,indice2 <indice1,indice2>`]

♦    INDIC_IMAG =         /    [:ref:`indice1,indice2 <indice1,indice2>`]

◊    FORMAT_C    = 'MODULE_PHASE'

♦    INDIC_MODU =         /    [:ref:`indice1,indice2 <indice1,indice2>`]

♦    INDIC_PHAS =         /    [:ref:`indice1,indice2 <indice1,indice2>`]
```

In the case of a complex function, two columns of numbers (real values) are to be identified in the file read in order to define the list of complex values of the result. One may thus read, as one chooses, real part/imaginary part or modulus/phase. The phase is expressed in radians.

The default values are respectively [1,2] and [1,3]: one reads the second and third columns of the first block. The first column read by default having been the value of the parameter (INDIC_PARA).

### 3.9 Case of a nappe: TYPE='NAPPE'

```text
♦    NOM_PARA_FONC        =     cf mot clé NOM_PARA

♦    INDIC_ABSCISSE    =         [:ref:`indice1,indice2 <indice1,indice2>`] ,

◊    INTERPOL_FONC        =    cf mot clé INTERPOL

◊    PROL_DROITE_FONC    =    cf mot clé PROL_DROITE

◊    PROL_GAUCHE_FONC    =     cf mot clé PROL_GAUCHE

◊    DEFI_FONCTION        =     _F(

♦    INDIC_RESU    =         [:ref:`indice1,indice2 <indice1,indice2>`] ,
```

The principle is the same as that of DEFI_NAPPE[U4.31.03]: the list of possible values of the parameter (second variable) having been defined by INDIC_PARA, it remains to identify the functions in the file read by the factor keyword DEFI_FONCTION (analogous to the factor keyword FONCTION of DEFI_NAPPE). Caution: the number of functions identified (occurrences of the factor keyword) must be identical to the cardinality of the values read by INDIC_PARA.

Unlike nappes in general, one imposes that the functions share the same list of abscissa values INDIC_ABSCISSE, which is why only INDIC_RESU is present under the factor keyword DEFI_FONCTION.

The '_FONC' keywords apply to the functions of the nappe (cf. DEFI_NAPPE, factor keyword DEFI_FONCTION [U4.31.03](doc:u4.31.03)).

## 4 Examples of use

Consider the following text file, containing the information to be read. It is composed of columns of numbers, here separated by blank characters, defining blocks, themselves delimited by free text.

Any line comprising characters other than numbers and the predefined separator is considered as delimiting free text. There are therefore 4 blocks in the following file:

```text
aaa bbb ccc

ddd

eee fff

0. 0. 0.

0.1 1. 10.

0.2 2. 20.

0.3 3. 30.

xxx yyy

www zzz

0.4 4. 40. 400.

0.5 5. 50. 500.

0.6 6. 60. 600.

xxx

70. 700.

80. 800.

90. 900.

ppp qqq

8.8

9.9
```

### 4.1 Reading of a simple function

Using the default values for the choice of columns:

```text
F=LIRE_FONCTION(    UNITE = 38,

NOM_PARA = ‘INST’, )
```

The function thus created is:

```text
Abscisses    = [:ref:`0., 0.1, 0.2, 0.3 <0., 0.1, 0.2, 0.3>`]

Ordonnées    = [:ref:`0., 1. , 2. , 3.  <0., 1. , 2. , 3. >`]
```

By associating, for the abscissae and the ordinates, columns taken from different blocks:

```text
F=LIRE_FONCTION(    UNITE = 38,

NOM_PARA = ‘INST’,

INDIC_PARA = [:ref:`2,4 <2,4>`],

INDIC_RESU = [:ref:`3,1 <3,1>`],
```

The function thus created is:

```text
Abscisses    = [:ref:`400., 500., 600. <400., 500., 600.>`]

Ordonnées    = [:ref:` 70., 80., 90. < 70., 80., 90.>`]
```

Caution: the command then checks that the cardinalities of the columns defined by INDIC_PARA and INDIC_RESU are indeed identical. This would not have been the case here with, for example, INDIC_PARA = [1,3].

### 4.2 Reading of a complex function

Using the default values for the choice of columns:

```text
F=LIRE_FONCTION(    UNITE        = 38,

NOM_PARA    = ‘INST’,

TYPE        = ‘FONCTION_C’,

FORMAT_C    = ‘REEL_IMAG’, )
```

The function thus created is:

```text
Abscisses    = [:ref:`0., 0.1, 0.2, 0.3 <0., 0.1, 0.2, 0.3>`]

Ordonnées    = [:external:ref:`(0.,0.) , (1.,10.) , (2.,20.) , (3.,30.) <(0.,0.) , (1.,10.) , (2.,20.) , (3.,30.)>`]
```

One could of course have specified columns for INDIC_REEL and INDIC_IMAG other than the default ones. Take care, however, to point to columns of the same cardinality.

### 4.3 Reading of a nappe

Using the default values for the choice of columns:

```text
F=LIRE_FONCTION(    UNITE                = 38,

NOM_PARA            = ‘INST’,

INDIC_PARA        = [:ref:`4,1 <4,1>`],

NOM_PARA_FONC        = ‘FREQ’,

INDIC_ABSCISSE    = [:ref:`2,2 <2,2>`],

DEFI_FONCTION        = (    F(    INDIC_RESU = [:ref:`3,1 <3,1>`], ),
F(    INDIC_RESU = [:ref:`2,3 <2,3>`], ), ) )
```

The nappe thus created is:

For the parameter value INST=8.8, the function:

```text
Abscisses    = [:ref:`4. , 5. , 6. <4. , 5. , 6.>`]

Ordonnées    = [:ref:`70. , 80. , 90. <70. , 80. , 90.>`]
```

For the parameter value INST=9.9, the function:

```text
Abscisses    = [:ref:`4. , 5. , 6. <4. , 5. , 6.>`]

Ordonnées    = [:ref:`40. , 50. , 60. <40. , 50. , 60.>`]
```

The consistency checks on the cardinalities of the columns of abscissae and of ordinates are carried out by the command.
