# u4.11.03 Procedure POURSUITE

## 1 Purpose

Restart a study from the database save carried out by FIN.

This command is retained for compatibility reasons.
Indeed, one may simply use DEBUT(), whether to start a study or to resume the execution. In the presence of the database, the *restart* of the previous analysis is performed automatically. **New since version 17**.

The syntax is therefore identical to that of the command DEBUT,
even if some keywords have no effect in POURSUITE.

## 2 Syntax

The syntax is identical to that of the command DEBUT,
even if some keywords have no effect in POURSUITE.

## 3 Operating principle

The restart carries out the following tasks:

- definition of the logical units of the files used for printout,
- allocation of the files associated with the databases managed by JEVEUX,
- reading of the command catalogues but not of the element catalogues, which were copied onto the database during the first execution.

The simple Python concepts (of variable type) created during a previous execution are kept in a file associated with the JEVEUX database (pick.* ). During the execution of the procedure POURSUITE these concepts are regenerated and can therefore be used under the name with which they were created.

**Note**

Objects of class, function and type kinds are not saved by Python
when FIN is called and will therefore not be available in a restart.

See paragraph u4.11.03-exemples.

## 4 Operands

For the Globale database, which can be saved and reused as input to an analysis, the initial maximum size in POURSUITE is kept as it is if the argument `--max_base` is not used, but it may be redefined if needed in this way.

## 5 Examples of use

The standard use of this procedure is:

```python
POURSUITE()
```

Python does not save the functions and classes defined in the main file (it merely remembers in which Python module they were defined). This is therefore the case for the code_aster command file.

To use functions or classes and recover them in a restart, they must be defined in an external module:

- Either the module userpkg/usermod.py:

```
def pyfunc(x):
    return x * 2
```
- One would do, in the first command set:

```
DEBUT()

from userpkg import usermod

form = FORMULE(NOM_PARA='X', VALE='pyfunc(X)', pyfunc=usermod.pyfunc)
assert form(2) == 4

FIN()
```
- Then:

```
POURSUITE()

assert form(2) == 4

FIN()
```

For this, it is enough to add to the study the directory `userpkg` of type `nom`.

One must understand that, on re-reading, Python will try to import the module `userpkg.usermod`. It must therefore find it in the same place.

Moreover, by importing this module, Python executes the instructions it finds there.

For this reason, **it is not recommended to create concepts in the main body of an imported module** (because they will be created on every import and will clutter the database). This must be done in functions that will be executed only on request.
