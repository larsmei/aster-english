# u4.90.02 Macro-command MACRO_EXPANS

## 1 Purpose

The macro-command MACRO_EXPANS makes it possible to carry out the expansion of experimental data onto a numerical model from an expansion basis. It consists of the succession of the operators EXTR_MODE, PROJ_MESU_MODAL, REST_GENE_PHYS and PROJ_CHAMP.

## 2 Syntax

```text
/ dyna_harmo
/ mode_meca = MACRO_EXPANS(
    ◆ MODELE_CALCUL = _F(
         ◆ MODELE = modele,
         ◆ BASE = mode_meca,
         ◇ NUME_MODE = int,
         ◇ NUME_ORDRE = int,
      ),
    ◆ MODELE_MESURE = _F(
         ◆ MODELE = modele,
         ◆ MESURE = mode_meca_c / dyna_trans / dyna_harmo / mode_meca,
         ◇ NOM_CHAM = / "DEPL" (par défaut),
                      / "VITE",
                      / "ACCE",
                      / "SIEF_NOEU",
                      / "EPSI_NOEU",
         ◇ NUME_MODE = int,
         ◇ NUME_ORDRE = int,
      ),
    ◇ NUME_DDL = nume_ddl,
    ◇ RESU_NX = co / dyna_harmo / mode_meca,
    ◇ RESU_EX = co / dyna_harmo / mode_meca,
    ◇ RESU_ET = co / dyna_harmo / mode_meca,
    ◇ RESU_RD = co / dyna_harmo / mode_meca,
    ◇ RESOLUTION = _F(
         ◇ METHODE = / "LU" (par défaut),
                     / "SVD",
         # Si: equal_to("METHODE", 'SVD')
             ◇ EPS = float,
         ◇ REGUL = / "NON" (par défaut),
                   / "NORM_MIN",
                   / "TIK_RELA",
         # Si: not equal_to("REGUL", 'NON')
             ◇ / COEF_PONDER = float,
               / COEF_PONDER_F = formule / nappe / fonction,
      ),
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Keyword MODELE_CALCUL

```text
♦ MODELE_CALCUL
```

Factor keyword gathering all the keywords relating to the expansion basis, generally obtained by analysis (hence the name).

#### 3.1.1 Keyword MODELE

♦ MODELE = modelnum

*modele_sdaster* denoting the model onto which the measurement will be expanded

#### 3.1.2 Keyword BASE

♦ BASE = base

*mode_meca*  serving as the basis for the expansion.

The basis must not contain collinear vectors, and the number of modes used must be smaller than the number of measurement degrees of freedom (preferably, nmodes << nmes); otherwise, the system to be solved is under-determined, which may lead to a fatal error and a stop of the code.

#### 3.1.3 Keyword NUME_ORDRE/NUME_MODE

List of the order numbers or of the modal positions of the modes that one wishes to use for the expansion.

### 3.2 Keyword MODELE_MESURE

```text
♦ MODELE_MESURE
```

Factor keyword gathering all the keywords relating to the experimental basis that one wishes to expand

#### 3.2.1 Keyword MODELE

♦ MODELE = modelexp

*modele_sdaster* denoting the model associated with the experimental mesh. Knowledge of the nodes is in general sufficient to determine an experimental mesh. The associated model can then be defined as follows:

MODELEXP = AFFE_MODELE( MAILLAGE = MAIEXP,

AFFE = _F( GROUP_MA = 'CAPTEURS',

PHENOMENE = 'MECANIQUE',

MODELISATION = 'DIS_T',),);

CAREXP = AFFE_CARA_ELEM( MODELE = MODELEXP,

DISCRET = _F( GROUP_MA = 'CAPTEURS',

REPERE = 'GLOBAL',

CARA = 'K_T_D_N',

VALE = (100.0,100.0,100.0,),

),);

The stiffness values given are arbitrary; they are not used in the analysis.

NB: in order to use the operator PROJ_CHAMP in the macro, one needs to generate a nume_ddl associated with this mesh. To do so, one must in addition assign a material to the model, compute the elementary matrices (stiffness, for example) and create the numbering with NUME_DDL.

#### 3.2.2 Keyword MESURE

♦ MESURE = mes

*dyna_harmo*  or *mode_meca*  to be expanded. These data are in general imported from a measurement result (.unv file) with the operator LIRE_RESU.

#### 3.2.3 Keyword NUME_ORDRE/NUME_MODE

List of integers. Makes it possible to select the modes that one wishes to expand.

#### 3.2.4 Keyword NOM_CHAM

♦NOM_CHAM = ‘DEPL’…

Experimental quantity to be expanded.

### 3.3 Keyword RESOLUTION

Two solution techniques are proposed for the inverse problem: truncated SVD, LU method.

For the SVD, one may choose to truncate the smallest singular values in order to improve the conditioning of the problem (choice of 'eps'), or use a Tikhonov-type regularisation.

One may refer to the documents [U4.73.01](doc:u4.73.01) (documentation of PROJ_MESU_MODAL) and [R6.03.01](doc:r6.03.01) (reference document on the singular-value decomposition).

### 3.4 Keyword NUME_DDL

Makes it possible to impose the numbering to be used for the operator PROJ_CHAMP. For more detail, refer to the documentation of PROJ_CHAMP [U4.72.05](doc:u4.72.05).

### 3.5 Keywords RESU_XX

The keywords RESU_XX make it possible to pre-declare the names of the output concepts:

- RESU_NX is the truncation of the numerical basis (keyword BASE under the factor keyword MODELE_CALCUL) to the modes chosen in NUME_MODE,
- RESU_EX is the truncation of the experimental basis (keyword MESURE under the factor keyword MODELE_MESURE) to the modes chosen in NUME_MODE,
- RESU_ET is the result of the expansion,
- RESU_RD is the reprojection onto the experimental model of the expanded basis: it is useful to check whether the reprojection of the expanded result is comparable to the initial experimental data.
