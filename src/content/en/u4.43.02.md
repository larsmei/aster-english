# u4.43.02 Operator INCLUDE_MATERIAU

## 1 Purpose

Retrieve the characteristics of a predefined material from the Material Catalogue.

The files of the Material Catalogue are located in the subdirectory share/aster/materiau of the installation directory.

These catalogues are not distributed in the open-source version of code_aster.

## 3 Aster Material Catalogue

*Code_Aster*  has a Material Catalogue whose objectives are:

- to supply users with the material data required in order to carry out numerical studies,
- to ensure the preservation of the information,
- to guarantee the reliability and the consistency of the available data,
- and to facilitate and to automate access to the data.

In *Code_Aster* , the material is defined by a set of characteristics required for the implementation of a constitutive law, which are introduced by the general command DEFI_MATERIAU.

In the Material Catalogue, the material is listed by its designation in the AFNOR standard.

The Material Catalogue distinguishes two types of material according to the type of study:

- the "**reference material**" for generic studies. It corresponds to a set of products manufactured according to one and the same well-defined specification. It is characterised by median, minimum and maximum values typical of the population concerned. This is the material which it is advisable to use if one does not have a perfect description of the material to be modelled,
- the "**particular material**" for specific studies. It corresponds to a clearly identified product or to a given material concept. This material is characterised by specific values of its properties, together with extreme values linked to the heterogeneity of the material and/or to the uncertainty on the values. This material is finely documented in order to avoid its systematic use without precaution.

Moreover, one may list different materials (reference or particular) corresponding to the same AFNOR designation. The RCC-M distinguishes, for one and the same AFNOR designation, the material characteristics according to the reference technical specification, the type of product (forged, rolled, tube, plate, ...) and the dimensions of the component. In order to take this additional dimension into account, in the Material Catalogue one associates a letter of the alphabet with each material.

To summarise, in the Material Catalogue the materials are listed by a character string which consists of the concatenation of:

- the designation in the AFNOR standard,
- the word REF (if reference material) or PAR (if particular material),
- a letter of the alphabet.

For example: 18MND5_REF_A

The Material Catalogue is presented in two distinct forms:

- a "files" form usable by *Code_Aster*  through the command INCLUDE_MATERIAU. It is a set of files whose name is the character string described previously (for example 18MND5_REF_A) and whose extension is one of the following character strings: NOMI (for the median values), MINI (for the minimum values) and MAXI (for the maximum values),
- a "sheets" form, in which the user can consult the material characteristics in the form of tables and obtain the origin of the characteristics. This form of the catalogue is accessible on the *Code_Aster*  site:
[www.code-aster.org](https://www.code-aster.org/) (EDF intranet only, in the Documentation M section). Each material sheet is the subject of an independent validation by the MMC department.

Finally, the command INCLUDE_MATERIAU makes it possible to use files outside the Material Catalogue and therefore outside the qualified domain.

## 4 Operands NOM_AFNOR / TYPE_MODELE / VARIANTE / TYPE_VALE or FICHIER

The classical use of the Material Catalogue consists in using the first 4 keywords.

These operands make it possible to choose the material to be used and therefore to define its name according to the rule presented in the previous section.

> ♦    NOM_AFNOR            =    nomafnor,                                    [Kn]

Makes it possible to specify the designation of the material in the AFNOR standard (for example: 18MND5).

```text
♦    TYPE_MODELE        =    / 'REF',
/ 'PAR',
```

Makes it possible to specify whether it is the characteristics of the reference material or those of the particular material that one wishes to use.

```text
♦    VARIANTE            =    / 'A',
......
/ 'Z',
```

Makes it possible to specify the variant of the material that one wishes to use (the characteristics are in general different according to the thickness or the diameter, and this for one and the same designation in the AFNOR standard). The section describing the material on the material sheet makes it possible to know the variant of interest to the user.

```text
♦    TYPE_VALE            =    / 'NOMI',

/ 'MAXI',

/ 'MINI',
```

Makes it possible to specify whether one wants to use the median, minimum or maximum values.

The keyword FICHIER, for its part, makes it possible to include the values of material properties stored in any file outside the Material Catalogue and therefore outside the qualified scope.

One supplies to this keyword the full name of the file (absolute or relative) to be included.

## 5 Keyword EXTRACTION

The values of material characteristics contained in the Material Catalogue are generally tables of values depending on the temperature. Consequently, only certain factor keywords of the command DEFI_MATERIAU have been entered in the Material Catalogue: those for which the operands are defined by functions (for example: ELAS_FO, THER_NL, ...). On the other hand, the factor keywords for which the operands are defined by reals (for example: ELAS, ...) are not entered in the various files making up the "files" form of the Material Catalogue.

One can nevertheless generate these keywords in the command DEFI_MATERIAU by the keyword EXTRACTION, by specifying the constitutive behaviour or the constitutive behaviours that one wishes to generate and by specifying the value of the temperature at which one wishes to extract the values of the function.

### 5.1 Operand COMPOR

```text
♦    COMPOR            = l_compor                                [:ref:`l_K16 <l_K16>`]
```

Designates the name of the factor keywords of DEFI_MATERIAU which will be extracted. For example, 'ELAS' or 'THER'.

### 5.2 Operand TEMP_EVAL

```text
♦    TEMP_EVAL        = temp                                        [R]
```

Temperature at which one wishes to extract the values of the material characteristics. For example, one creates, in the command DEFI_MATERIAU, the operand E = E0 under the factor keyword ELAS by interpolating the value at T0 of the operand E = E(T) defined in the catalogue. The type of interpolation is determined by the corresponding function of the catalogue. In general, the interpolation is linear; extrapolations are not recommended (or even forbidden).

## 6 Operand UNITE_LONGUEUR

```text
◊    UNITE_LONGUEUR    =    /    'M'        ,                        [DEFAUT]
/    'MM'    ,
```

Makes it possible to use the data of the material catalogue with the millimetre as the unit of length.

The values given in the material catalogue are and remain in metres. If the user specifies UNITE_LONGUEUR = 'MM' in the command INCLUDE_MATERIAU, this means that the user wishes to handle units of length in millimetres, and the command INCLUDE_MATERIAU carries out the transformation of the units.

## 7 Operand COEF_MULT

```text
◊    COEF_MULT    =    /    1,                                        [DEFAUT]
```

Makes it possible to enrich the evaluation context of the material file with an object coef_mult. By default it is equal to 1 and it is not used in the material catalogue.

This argument is hidden and serves mainly for the development of business tools of the CALC_MAC3COEUR type.

## 8 Operand OPTION

```text
◊    OPTION
```

Makes it possible to enrich the evaluation context of the material file with an optional argument of type str.

This argument is hidden and serves mainly for the development of business tools of the CALC_MAC3COEUR type.

## 9 Prolongation of the domain of definition

The material properties are defined, in the absence of the keyword EXTRACTION, by functions of the temperature whose domain of definition is strict (equivalent to an EXCLU prolongation).

It sometimes happens that, in the course of the iterations of the solution of the problem (in the case of a thermal shock, for example), the properties are evaluated outside this domain. This leads to the analysis being stopped.

The user may then choose to authorise the prolongation, constant or linear, of the functions to the left and/or to the right of the domain of definition. He must then make sure that the results are valid and, in particular, that the values of the temperature at convergence do indeed lie within the initial bounds.

PROL_GAUCHE (resp. PROL_DROITE) makes it possible to define the type of prolongation to the left (resp. to the right), that is to say for the values lower than (resp. greater than) the domain of definition.

In this case, all the functions are prolonged in the same way.

It is possible that certain materials do not allow the prolongation.

## 10 Operand INFO

```text
◊    INFO =    / 1,                                                [DEFAUT]
/ 2,
```

| 1 | no printout of the contents of the included file, |
| --- | --- |
| 2 | printout of the contents of the included file, in the 'MESSAGE' file. |

## 12 Defining one's own material

*This section is halfway between use and development. One uses an unqualified overload which is the responsibility of the user/developer.*

One deals here with the definition of a catalogue for a given material by a user.

The catalogue thus developed will be able to join the catalogue managed under configuration control after the required qualification, but in the meantime it may be used as an overload.

For this, it is sufficient to define a particular directory in which the new catalogue will be stored, and to use the argument -rep_mat [directory name] when launching the study (*cf.*  [u1.04.00]).

### 12.1 Management of the length unit of the mesh

In order to manage the change of unit, one has the function coef_unit.

coef_unit(n) is equal to 1. if UNITE_LONGUEUR is equal to 'M', and is equal to ${10}^{n}$ if UNITE_LONGUEUR is equal to 'MM'.

For example, for a quantity in MPa, one will write:

E = 2.1e11 * coef_unit(-6)

### 12.2 Extraction and evaluation as a function of the temperature

In the writing of the catalogue, one must determine which keywords are returned in the presence of EXTRACTION and which are not.

Example: if one does not request the extraction at a given temperature, one wishes to obtain the elastic properties depending on the temperature, keyword ELAS_FO. Whereas if one requests these properties at 20°C, one wishes to obtain the factor keyword ELAS.

One will write extraction=True (in the catalogue) to indicate that the factor keyword must be kept if EXTRACTION is present (in the command file), and extraction=False to indicate that it must be kept if EXTRACTION is absent. If extraction is not filled in, the keyword is kept in both cases.

One indicates which function must be evaluated as a function of the temperature (the only command variable currently supported) by using the function temp_eval:

E = temp_eval(_A2) where _A2 is a function defined beforehand.

#### 12.2.1 Syntax, reserved words

The catalogue does not itself call DEFI_MATERIAU; it defines only the list of keywords.

For this, one must use the function defi_motscles and name motscles the result of this function:

motscles = defi_motscles( ... )

A material catalogue is not a macro-command. However, it obeys the same rules concerning the naming of the intermediate concepts (functions of the temperature-dependent properties in particular). In order not to cause conflicts with the concepts of the user's command file, one must take care to prefix the intermediate concepts of the catalogue with a '_' (*cf.*  [d5.01.02](doc:d5.01.02)) and to destroy the concepts which can be destroyed.

Finally, a limited number of commands are usable in a catalogue: essentially those which handle the functions (consult the file bibpyt/Macro/include_materiau_ops.py for the exhaustive list).
