# u4.42.04 Macro-command DEFI_CABLE_BP

> **Summary**

The objective of this command is to compute the initial tension profiles along the prestressing cables of a concrete structure. The data of the analysis are the tension applied at the ends and other parameters characteristic of the anchorages and of the materials. The relations used are those prescribed by the BPEL 91 or by the ETCC. It also makes it possible to create kinematic relations between the nodes of the cable and the nodes of the concrete in which it is embedded.

The concept cabl_precont produced can then be used:

- either by the operator AFFE_CHAR_MECA [U4.44.01](doc:u4.44.01), operand RELA_CINE_BP, to define the mechanical loadings linked to the presence of the cable (kinematic relations and/or tension in the cables). These loadings will be taken into account by the operator STAT_NON_LINE [U4.51.03](doc:u4.51.03);
- or by the operator CALC_PRECONT [U4.42.05](doc:u4.42.05) for a progressive tensioning of the cables and the possibility of carrying out phasing;
- or by the operator DEFI_GROUP (CREA_GROUP_NO/OPTION = ’RELA_CINE_BP’) to create node groups corresponding to the links created and to allow a visual check of these kinematic relations.

Produces a data structure of type cabl_precont.

## 1 Syntax

```text
cabl_precont = DEFI_CABLE_BP(
    ◆ MODELE = modele,
    ◆ CHAM_MATER = cham_mater,
    ◆ CARA_ELEM = cara_elem,
    ◆ GROUP_MA_BETON = grma,
    ◆ TYPE_ANCRAGE = / "ACTIF",
                     / "PASSIF",
    ◇ ADHERENT = / "OUI" (par défaut),
                 / "NON",
    # Si: (equal_to("ADHERENT", 'OUI'))
        ◆ / DEFI_CABLE = _F(
               ◇ / GROUP_MA = grma,
                 / | TABL_CABLE = table,
                   | GROUP_NO_ANCRAGE = grno,
            ),
          / MODI_CABLE_RUPT = _F(
               ◆ GROUP_MA = grma,
               ◆ GROUP_NO_ANCRAGE = grno,
               ◆ TENSION = table,
            ),
        ◇ TYPE_RELAX = / "SANS" (par défaut),
                       / "BPEL",
                       / "ETCC_DIRECT",
                       / "ETCC_REPRISE",
        # Si: equal_to("TYPE_RELAX", 'BPEL')
            ◆ R_J = float,
        # Si: equal_to("TYPE_RELAX", 'ETCC_DIRECT')
            ◆ NBH_RELAX = float,
        # Si: equal_to("TYPE_RELAX", 'ETCC_REPRISE')
            ◇ MODI_CABLE_ETCC = _F(
                 ◆ GROUP_MA = grma,
                 ◆ GROUP_NO_ANCRAGE = grno,
                 ◆ TENSION = table,
              ),
            ◆ NBH_RELAX = float,
        ◇ CONE = _F(
             ◆ RAYON = float,
             ◆ LONGUEUR = float,
             ◆ PRESENT = / "OUI",
                         / "NON",
          ),
    # Si: (not exists("MODI_CABLE_RUPT"))
        ◆ TENSION_INIT = float,
        ◆ RECUL_ANCRAGE = float,
    # Si: (equal_to("ADHERENT", 'NON'))
        ◆ DEFI_CABLE = _F(
             ◆ GROUP_MA = grma,
             ◆ GROUP_NO_ANCRAGE = grno,
          ),
    ◇ TITRE = text,
    ◇ INFO = / 1 (par défaut),
             / 2,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 2 Operands

### 2.1 Operand MODELE

```text
♦    MODELE = modèle
```

Concept produced by the operator AFFE_MODELE [U4.41.01](doc:u4.41.01) making it possible to define the types of finite elements assigned to the mesh cells of the mesh.

### 2.2 Operand CHAM_MATER

```text
♦    CHAM_MATER = chmat
```

Concept produced by the operator AFFE_MATERIAU [U4.43.02](doc:u4.43.02) making it possible to assign materials to the mesh cells of the mesh.

### 2.3 Operand CARA_ELEM

```text
♦    CARA_ELEM = caelem
```

Concept produced by the operator AFFE_CARA_ELEM [U4.42.01](doc:u4.42.01) making it possible to assign mechanical and geometric characteristics to the elements of the structure studied.

### 2.4 Operand GROUP_MA_BETON

```text
♦    GROUP_MA_BETON = grmabe
```

Name of the mesh-cell group (or groups) of the mesh representing the concrete structure. One thus defines precisely the geometric locus of projection of the cables, a preliminary step to the determination of the kinematic relations between the degrees of freedom of the nodes of the cables and the degrees of freedom of the nodes of the concrete structure.

**Notes:**

*1- It is possible to supply here a list of mesh-cell groups, in particular for the case in which all the concrete mesh cells surrounding the cable do not have the same constitutive behaviour. However, it is indispensable that all the concrete mesh cells concerned have the same characteristics* BPEL_BETON *.*

*2- The mesh cells modelling the concrete can only be 3D mesh cells or 2D mesh cells in the case of a plate modelling (* DKT,Q4GG) *.*

### 2.5 Definition of the cable

#### 2.5.1 Keyword DEFI_CABLE [DEFAUT]

```text
DEFI_CABLE
```

Factor keyword making it possible to define a cable by designating the topological entities of the mesh which represent it. Multiple occurrences are allowed, in order to be able to define several cables. The cables can be defined individually or via the supply of a table (see test SSNV229a)

```text
/ ♦    GROUP_MA = grmaca
```

Name of the mesh-cell group of the mesh representing the cable.

```text
♦    GROUP_NO_ANCRAGE = l_gnoa
```

List of node groups defining the anchorages. The cardinal of this list must be less than or equal to 2. In each node group, one will retain as anchorage only the first node of the group.

```text
/ ♦    TABL_CABLE = table
```

When the number of cables is large, it may be easier to have defined them via a table containing 3 columns, defining the mesh-cell group of the cables and the name of the 2 node groups defining the anchorages. The columns must be named GROUP_MA, GROUP_NO1, GROUP_NO2.

This table can be defined outside Code_Aster (Excel, python) and read with the command LIRE_TABLE.

Example:

#LISTE CABLE

GROUP_MA GROUP_NO1 GROUP_NO2

CAB1 CAB1_I CAB1_F

CAB3 CAB3_I CAB3_F

#### 2.5.2 Keyword MODI_CABLE_ETCC

```text
◊    MODI_CABLE_ETCC
```

Factor keyword making it possible to define a cable by designating the topological entities of the mesh which represent it and supplying, for each of the cables, the short-term initial tension in order to make it possible to compute the losses by relaxation of the steel according to the ETCC (**bonded cable only**). Multiple occurrences are allowed, in order to be able to define several cables. In order to use it, one must have specified TYPE_RELAX=’ETCC_REPRISE’.

```text
♦    GROUP_MA = grmaca
```

Name of the mesh-cell group of the mesh representing the cable.

```text
♦    GROUP_NO_ANCRAGE = l_gnoa
```

List of node groups defining the anchorages. The cardinal of this list must be less than or equal to 2. In each node group, one will retain as anchorage only the first node of the group.

```text
♦    TENSION = table
```

Table containing the tension in the cable for all the curvilinear abscissae (table with 2 columns). This table is used to compute the losses by relaxation of the steel in the case where the user has opted for the option TYPE_RELAX = ’ETCC_REPRISE’. This table is obtained via a POST_RELEVE_T on the nodes of the cable studied, after a first static analysis.

#### 2.5.3 Keyword MODI_CABLE_RUPT

```text
◊    MODI_CABLE_RUPT
```

Factor keyword making it possible to define a cable by designating the topological entities of the mesh which represent it. This keyword makes it possible to bypass the tension computation by recovering the table supplied under the keyword TENSION. The technique makes it possible to simulate the failure of a cable with re-anchoring (**bonded cable only**).

Multiple occurrences are allowed, in order to be able to define several cables.

```text
♦    GROUP_MA = grmaca
```

Name of the mesh-cell group of the mesh representing the cable.

```text
♦    GROUP_NO_ANCRAGE = l_gnoa
```

List of node groups defining the anchorages. The cardinal of this list must be less than or equal to 2. In each node group, one will retain as anchorage only the first node of the group.

```text
♦    TENSION = table
```

Table containing the tension in the cable for all the curvilinear abscissae (table with 2 columns) and which will become the reference tension. This table is obtained via a POST_RELEVE_T on the nodes of the cable studied after a first analysis, then modified as the user wishes.

### 2.6 Operand ADHERENT

```text
♦    ADHERENT =    / ’OUI’            [DEFAUT]
/ ’NON’
```

This keyword makes it possible to indicate whether one wishes to model cables bonded to the concrete (ADHERENT = ’OUI’) or sliding or frictional cables (ADHERENT = ’NON’). For the non-bonded cases, one must use, in order to represent the steel, the modelling CABLE_GAINE and the constitutive law CABLE_GAINE_FROT. The bonded case can be simulated with the modellings BARRE or CABLE_GAINE.

**Note:**

In the case ADHERENT = ’NON’, the tension profile is computed even if it is not used afterwards (neither in AFFE_CHAR_MECA/RELA_CINE_BP, *nor in* CALC_PRECONT).

### 2.7 Operand TYPE_ANCRAGE

```text
♦    TYPE_ANCRAGE = l_tya
```

List of arguments of text type characterising the anchorages of the cable: ‘ACTIF’ or ‘PASSIF’ (the only admissible arguments). This list must contain 2 arguments, no more and no less, and must be ordered with respect to the list of the nodes defining the anchorages (operand GROUP_NO_ANCRAGE above). Note that if several cables are defined in DEFI_CABLE then the first argument of TYPE_ANCRAGE applies to all the first nodes which define the anchorages. *Likewise* for the second argument.

**Notes:**

*1- The operator reconstructs the connected path leading from the first to the second anchorage of the cable by traversing the mesh cells which represent it. The non-existence of a connected path between the two anchorages causes the program to stop in fatal error.*

*2- The active anchorages are those at which one applies an initial tension.*

### 2.8 Operand TENSION_INIT

```text
♦    TENSION_INIT = f0
```

Value of the initial force applied to the active anchorages of the cables.

This value must be positive.

### 2.9 Operand RECUL_ANCRAGE

```text
♦    RECUL_ANCRAGE = delta
```

Value of the anchorage slip at the active anchorages of the cables.

This value must be positive.

### 2.10 Choice of the type of analysis for taking into account the relaxation of the steels

◊    TYPE_RELAX    =    /'SANS',                            [DEFAUT]

```text
/'BPEL',
/'ETCC_DIRECT',
/'ETCC_REPRISE',
```

Keyword making it possible to define whether or not one takes into account the tension losses by relaxation of the steel by the regulatory method, and if so which one (ETCC or BPEL). This factor keyword being optional, by default the tension losses by relaxation of the steel are not taken into account.

#### 2.10.1 TYPE_RELAX='SANS'

This is the default value. In this case, one does not take this type of loss into account by a regulatory method. On the other hand, one can take it into account by using the viscoelastic constitutive law RELAX_ACIER for the cable (cf. [R5.03.09](doc:r5.03.09)).

#### 2.10.2 TYPE_RELAX=’BPEL’

In this case, the BPEL formula is applied, and the keyword R_J must be specified (cf. § 2.11 for the detail).

#### 2.10.3 TYPE_RELAX=’ETCC_DIRECT’

In this case, the ETCC formula is applied, but the force used takes into account only the losses by friction and by anchorage slip (cf. § 4).

It is necessary to specify the keyword NBH_RELAX (cf. § 2.12).

#### 2.10.4 TYPE_RELAX=’ETCC_REPRISE’

In this case, the exact formula of the ETCC is applied. This implies carrying out a first analysis without relaxation and recovering the tension in the cable. Then one should define the cable as a function of MODI_CABLE_ETCC instead of DEFI_CABLE.

It is necessary to specify the keyword NBH_RELAX (cf. § 2.12).

### 2.11 Operand R_J

◊    R_J = $\mathit{rj}$

Parameter to be specified only if TYPE_RELAX=’BPEL’.

Value of the dimensionless function $r(j)$ characterising the evolution of the relaxation of the steel in time and of the steel only (this coefficient does not apply to the losses by creep or shrinkage of the concrete specified under BPEL_BETON in DEFI_MATERIAU); for example the BPEL 91 recommends:

$r(j)=\frac{j}{j+9\times {r}_{m}}$ with $j$ in days

and ${r}_{m}=\frac{\text{aire de la section de béton}}{\text{périmètre de la section de béton}}\equiv \text{rayon moyen}$

This value must be positive or zero.

$j$ corresponds to the date (in days) for which one wants to estimate the stress state in the structure. For the case in which, in the structural analysis, the bars would be modelled with a constitutive behaviour of creep type, this keyword must not be specified in DEFI_CABLE_BP.

### 2.12 Operand NBH_RELAX

◊    NBH_RELAX = $\mathit{nh}$

Parameter to be specified only if TYPE_RELAX=’ETCC_DIRECT’ or ’ETCC_REPRISE’.

Time considered for taking into account the losses by relaxation of the steel in the ETCC, expressed as a number of hours.

The formula applied is the following:

$\Delta {F}_{\mathit{pr}}=0,66.{\rho}_{1000}.{e}^{9,1\frac{\tilde{F}(s)}{{P}_{\mathit{pk}}}}.{\left(\frac{\mathit{nh}}{1000}\right)}^{0,75(1-\tilde{F}(s)/{P}_{\mathit{pk}})}.{10}^{-5}\tilde{F}(s)$

where:

${\rho}_{1000}$ is the value of the relaxation coefficient of the steel at 1000 hours in %, specified under ETCC_ACIER.

${P}_{\mathit{pk}}$ is the maximum tension of the steel at failure, computed from the datum F_PRG under ETCC_ACIER.

$\tilde{F}$ is equal to the tension computed according to the ETCC taking into account the losses by friction and by anchorage slip if TYPE_RELAX=’ETCC_DIRECT’, or the tension supplied by the user under MODI_CABLE_ETCC/TENSION in the other case.

### 2.13 Keyword CONE

```text
♦    CONE
```

This factor keyword makes it possible to define a geometric volume around the anchorages, and to assign, on output from AFFE_CHAR_MECA keyword RELA_CINE_BP, to all the nodes (concrete and cable) contained in this volume, a kinematic relation of type LIAISON_SOLIDE (rigid body). The definition of this volume makes it possible to attenuate the stresses which the tensions at the ends of the cables produce on the concrete. In reality, this phenomenon is avoided thanks to the installation of a stress-diffusion cone (material harder than the concrete) which distributes the prestressing force over a large area of the concrete. In practice, the cone being practically straight, one defines a cylindrical volume.

Note that several cones, and therefore several rigid blocks, are defined if the keyword PRESENT contains two ‘OUI’ (one block per end of the cable) or if several cables are defined under DEFI_CABLE.

**Note:**

In practice, the cylinder is defined by the command DEFI_GROUP option TUNNEL. The methodology for extracting the nodes contained in the cone is described in document [U4.22.01](doc:u4.22.01) (command DEFI_GROUP).

```text
♦    RAYON = rayon
```

Radius of the cone.

```text
♦    LONGUEUR = longueur
```

Length of the cone, in the sense of the curvilinear abscissa on the cable. One defines the cone as a succession of cylinders, stopping when the total length of the cylinders is equal to the parameter longueur.

```text
♦    PRESENT = l_pre
```

This list must contain 2 arguments, no more and no less, and must be ordered with respect to the list of the nodes defining the anchorages (operand GROUP_NO_ANCRAGE above).

The only valid arguments are ‘OUI’ or ‘NON’; they make it possible to define the cone on the two anchorages (PRESENT=(‘OUI’,‘OUI’,)), on the first anchorage (PRESENT=(‘OUI’,‘NON’,)) or on the second anchorage (PRESENT=(‘NON’,‘OUI’,)). Note that if several cables are defined in DEFI_CABLE then the first argument of PRESENT applies to all the first nodes which define the anchorages. Likewise for the second argument.

### 2.14 Operand TITRE

```text
◊    TITRE = l_titr
```

List of arguments of text type defining a title attached to the concept [cabl_precont].

## 3 Theoretical complement: estimation of the tension losses in a prestressing cable according to the prescriptions of the BPEL

In the case where the user has defined the material characteristics BPEL_BETON and BPEL_ACIER, the evolution of the tension (in newtons) along a prestressing cable is computed using the relations prescribed by the BPEL. These relations are the following.

### 3.1 Evolution of the tension in the vicinity of the anchorage

The tension is written:

$$
F(s)=\tilde{F}(s)-\lbrace {x}_{\mathit{flu}}\times {F}_{0}+{x}_{\mathit{ret}}\times {F}_{0}+r(j)\times \frac{5}{100}\times {\rho}_{1000}\left[\frac{\tilde{F}(s)}{{S}_{a}\times {\sigma}_{y}}-{\mu}_{0}\right]\times \tilde{F}(s)\rbrace
$$

where $s$ designates the curvilinear abscissa along the cable. The parameters introduced in this expression are:

| ${F}_{0}$ | initial tension (N); |
| --- | --- |
| ${x}_{\mathrm{flu}}$ | lump-sum rate of tension loss by creep of the concrete, with respect to the initial tension; |
| ${x}_{\mathrm{ret}}$ | lump-sum rate of tension loss by shrinkage of the concrete, with respect to the initial tension; |
| ${\rho}_{1000}$ | relaxation of the steel at 1000 hours, expressed in %; |
| ${S}_{a}$ | area of the cross-section of the cable defined in AFFE_CARA_ELEM; |
| ${\sigma}_{y}$ | elastic limit stress of the steel; |
| ${\mu}_{0}$ | dimensionless relaxation coefficient of the prestressed steel. |

$r(j)$ is a dimensionless function characterising the evolution of the relaxation in time:

$r(j)=\frac{j}{j+9\times {r}_{m}}$ with j in days and ${r}_{m}=\frac{\text{aire de la section de béton}}{\text{périmètre de la section de béton}}\equiv \text{rayon moyen}$

The function $r(j)$ depending on the geometry of the structure, the value used is defined in the operator DEFI_CABLE_BP.

$\tilde{F}(s)$ is the evolution of the tension in the vicinity of the anchorage after taking into account the loss by anchorage slip and the losses by contact between the cable and the concrete.

$\tilde{F}(s)$ is defined by the relation: ${F}_{c}(s)\times \tilde{F}(s)={\left[{F}_{c}(d)\right]}^{2}$

${F}_{c}(s)$ designates the evolution of the tension along the cable after taking into account the losses by contact between the cable and the concrete: ${F}_{c}(s)={F}_{0}\exp\left(-f\alpha -\varphi s\right)$

$\alpha$ designates the cumulative angular deviation and the parameters introduced in the expression of its ${F}_{c}(s)$ t:

$f$ coefficient of friction between the cable and the sheath in the curved part, in rad–1;

$\varphi$ coefficient of friction between the cable and the sheath in m-1.

**Notes:**

- *The coefficients* $f,\varphi ,{\rho}_{1000,}{\sigma}_{y},{\mu}_{0}$ *are to be specified in the operator* *DEFI_MATERIAU under the keyword* *BPEL_ACIER,*
- ${x}_{\mathit{flu}}$ *and* ${x}_{\mathit{ret}}$ *are to be specified in the operator* *DEFI_MATERIAU under the keyword* *BPEL_BETON.*

The length $d$ appearing in the expression of $\tilde{F}(s)$ is the length over which the tension loss by anchorage slip applies. This length is estimated with the help of the relation:

$$
{E}_{a}{S}_{a}\Delta ={\int}_{0}^{d}\left({F}_{c}(s)-\tilde{F}(s)\right)\mathit{ds}
$$

where ${E}_{a}$ is the Young's modulus of the steel and $\Delta$ the value of the anchorage slip. Thus ${E}_{a}{S}_{a}\Delta$ represents the strain energy (of the cable) due to the anchorage slip.

### 3.2 Evolution of the tension beyond the length over which the tension losses by anchorage slip apply

This tension is written:

$$
F(s)={F}_{c}(s)-\lbrace {x}_{\mathit{flu}}\times {F}_{0}+{x}_{\mathit{ret}}\times {F}_{0}+r(j)\times \frac{5}{100}\times {\rho}_{1000}\left[\frac{\tilde{F}(s)}{{S}_{a}\times {\sigma}_{y}}-{\mu}_{0}\right]\times \tilde{F}(s)\rbrace
$$

with the same notations as those introduced in the previous paragraph.

## 4 Theoretical complement: estimation of the tension losses in a prestressing cable according to the prescriptions of the ETCC

In the case where the user has defined the material characteristics ETCC_BETON and ETCC_ACIER, the evolution of the tension (in newtons) along a prestressing cable is computed using the relations prescribed by the ETCC. However, the losses due to the elastic strain of the concrete and to the strains due to the shrinkage and to the creep of the concrete are not taken into account in the analysis. If one wants to take them into account, one should:

- tension the cables in 2 families in order to recover the losses due to the elastic strain of the concrete

  - impose on the concrete the shrinkage and creep strains, after the tensioning of the cables.

The relations implemented are the following.

### 4.1 Evolution of the tension in the vicinity of the anchorage

It is written:

$$
F(s)=\tilde{F}(s)-0,8\Delta {F}_{\mathit{pr}}(s)
$$

with

$\tilde{F}(s)$ is the evolution of the tension in the vicinity of the anchorage after taking into account the loss by anchorage slip and the losses by contact between the cable and the concrete.

$\tilde{F}(s)$ is defined by the relation: ${F}_{c}(s)\times \tilde{F}(s)={\left[{F}_{c}(d)\right]}^{2}$

${F}_{c}(s)$ designates the evolution of the tension along the cable after taking into account the losses by contact between the cable and the concrete: ${F}_{c}(s)={F}_{0}{\exp}^{-\mu (\alpha +ks)}$

$\alpha$ designates the cumulative angular deviation and the parameters introduced in the expression of its ${F}_{c}(s)$ are:

- $\mu [:ref:`{\mathit{rad}}^{-1} <{\mathit{rad}}^{-1}>$]` the coefficient of friction between the cable and the sheath;

$k[{\mathit{rad}}^{-1}.{m}^{-1}]$ the coefficient of loss per unit length.

The length $d$ appearing in the expression of $\tilde{F}(s)$ is the length over which the tension loss by anchorage slip applies. This length is estimated with the help of the relation:

$$
{E}_{a}{S}_{a}\Delta ={\int}_{0}^{d}({F}_{c}(s)-\tilde{F}(s))\mathrm{ds}
$$

where

${E}_{a}$ is the Young's modulus of the steel and $\Delta$ the value of the anchorage slip. Thus ${E}_{a}{S}_{a}\Delta$ represents the strain energy (of the cable) due to the anchorage slip.

$\Delta {F}_{\mathit{pr}}$ are the losses due to the relaxation of the cables, estimated by the following formula

$$
\Delta {F}_{\mathit{pr}}(s)=0,66.{\rho}_{1000}.{e}^{9,1\frac{\tilde{F}(s)}{{P}_{\mathit{pk}}}}.{\left(\frac{\mathit{nh}}{1000}\right)}^{0,75(1-\tilde{F}(s)/{P}_{\mathit{pk}})}.{10}^{-5}\tilde{{F}_{(s)}}
$$

$s$ designates the curvilinear abscissa along the cable. The parameters introduced in this expression are:

| ${\rho}_{1000}$ | Relaxation of the steel at 1000 hours, expressed in %. |
| --- | --- |
| ${P}_{\mathit{pk}}$ | Force at failure in the steel (computed from the parameter F_PRG specified in DEFI_MATERIAU/ETCC_ACIER) |
| $\mathit{nh}$ | The number of hours after the prestressing at which the losses are computed. |

**Notes:**

- *The coefficients* $\mu ,k,{\rho}_{1000,}{F}_{\mathit{prg}}$ *are to be specified in the operator* *DEFI_MATERIAU under the keyword* *BPEL_ACIER,*
- $\mathit{nh}$ *is to be specified in the operator* *DEFI_CABLE_BP.*

### 4.2 Evolution of the tension beyond the length over which the tension losses by anchorage slip apply

One writes the following relation:

$$
F(s)={F}_{c}(s)-0,8\ast 0,66{\rho}_{1000}.{\exp}^{9,1{F}_{c}(s)/{F}_{\mathit{prg}}}.{\left(\frac{\mathit{nh}}{1000}\right)}^{0,75(1-{F}_{c}(s))/{F}_{\mathit{prg}}}.{10}^{-5}{F}_{c}(s)
$$

With the same notations as those introduced in the previous paragraph.
