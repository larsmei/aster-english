# u4.63.11 Macro-command PROJ_BASE

## 1 Purpose

Project assembled matrices and/or vectors onto a modal basis or onto a RITZ basis. The resulting projected matrices and vectors will be used by the analysis algorithms in generalised components (DYNA_VIBRA [U4.53.03](doc:u4.53.03) for example).

This macro-command replaces the following successive commands:

- NUME_DDL_GENE [U4.65.03](doc:u4.65.03) which establishes the numbering of the generalised degrees of freedom,
- one or more occurrences of PROJ_MATR_BASE [U4.63.12](doc:u4.63.12) in order to project one or more assembled matrices,
- one or more occurrences of PROJ_VECT_BASE [U4.63.13](doc:u4.63.13) in order to project one or more assembled vectors.

> Table of contents

## 2 Syntax

```text
/ matr_asse_gene_c
/ matr_asse_gene_r
/ nume_ddl_gene
/ tran_gene
/ vect_asse_gene = PROJ_BASE(
    ◆ BASE = mode_gene / mode_meca,
    ◇ NB_VECT = int,
    ◇ STOCKAGE = / "DIAG",
                 / "PLEIN" (par défaut),
    ◇ NUME_DDL_GENE = co / nume_ddl_gene,
    ◆ | MATR_ASSE_GENE = _F(
           ◆ MATRICE = co,
           ◆ / MATR_ASSE = matr_asse_depl_c / matr_asse_depl_r,
             / MATR_ASSE_GENE = matr_asse_gene_c / matr_asse_gene_r,
        ),
      | VECT_ASSE_GENE = _F(
           ◆ VECTEUR = co,
           ◆ TYPE_VECT = / "ACCE",
                         / "DEPL",
                         / "FORC",
                         / "VITE",
           ◆ / VECT_ASSE = cham_no,
             / VECT_ASSE_GENE = vect_asse_gene,
        ),
      | RESU_GENE = _F(
           ◆ RESULTAT = co,
           ◆ TYPE_VECT = / "ACCE",
                         / "DEPL",
                         / "FORC",
                         / "VITE",
           ◆ RESU = dyna_trans,
        ),
    ◇ INFO = / 1 (par défaut),
             / 2,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Operand BASE

```text
♦    BASE = ba
```

Concept of type mode_meca or mode_gene (for substructuring), which contains the vectors defining the projection subspace.

### 3.2 Operand NB_VECT

```text
◊    NB_VECT = nm
```

Number of vectors used in the basis (one takes the first nm). One checks that the number nm is indeed less than the number of vectors of the basis; otherwise, all the vectors supplied are used.

### 3.3 Operand STOCKAGE

```text
◊    STOCKAGE    =    /'PLEIN'        [DEFAUT]
                      /'DIAG'
```

See NUME_DDL_GENE[U4.65.03].

If one matrix has a profile 'DIAG' and another a profile 'PLEIN', two numberings will be created with NUME_DDL_GENE.

The use of the keyword STOCKAGE='DIAG' is legitimate when the basis onto which the matrices are projected is composed of eigenmodes. In this case, the projected matrices are indeed diagonal, and it is not necessary to save the other terms of the matrix, which are zero.

Warning, if the basis is composed of other types of vectors (static modes for example), then the use of the keyword STOCKAGE='DIAG' leads to incorrect results.

In the case of analyses using the fluid-structure operators, the analysis must be carried out with the diagonal storage option.

### 3.4 Operand NUME_DDL_GENE

```text
◊     NUME_DDL_GENE     =     /numgen               [nume_ddl_gene]
                              /CO('numgen'),        [nume_ddl_gene]
```

Numbering associated with the generalised model. This operand may be a concept that already exists or not (CO('numgen')).

### 3.5 Keyword MATR_ASSE_GENE

```text
◊    MATR_ASSE_GENE
```

Factor keyword defining the name of the resulting projected matrix and the name of the matrix to be projected. This keyword must be repeated as many times as there are matrices to project.

#### 3.5.1 Operand MATRICE

```text
♦    MATRICE = CO('mt')
```

Concept of type matr_asse_gene_r or matr_asse_gene_c, real or complex resulting generalised matrix.

#### 3.5.2 Operands MATR_ASSE / MATR_ASSE_GENE

```text
♦    /    MATR_ASSE = ma
```

Concept of type matr_asse_depl_r or matr_asse_depl_c, real or complex assembled matrix that one wishes to project.

```text
/    MATR_ASSE_GENE = ma
```

Concept of type matr_asse_gene_r or matr_asse_gene_c, real or complex assembled matrix, coming from substructuring, that one wishes to project.

### 3.6 Keyword VECT_ASSE_GENE

```text
◊    VECT_ASSE_GENE
```

Factor keyword defining the name of the resulting projected vector and the name of the vector to be projected. This keyword must be repeated as many times as there are vectors to project.

#### 3.6.1 Operand VECTEUR

```text
♦    VECTEUR = CO('vt')
```

Concept of type vect_asse_gene, resulting generalised vector.

#### 3.6.2 Operand TYPE_VECT

```text
♦    TYPE_VECT =    typ
```

Character string describing the type of the field represented by the assembled vector. The available values are 'FORC', 'DEPL', 'VITE' and 'ACCE'. The processing differs according to whether one uses the option FORC or the others.

- With the option FORC, one carries out the simple projection ${\Phi}^{T}f$ , where $\Phi$ is the modal basis and $f$ the force,
- With the other options, one computes by an inverse problem the modal participation coefficients associated with a given displacement. One assumes that the displacement $x$ can be written in the form $x={\eta}^{T}\Phi$ . One then computes $\eta ={\Phi}^{T}{({\Phi}^{T}\Phi )}^{-1}x$ (Moore-Penrose pseudo-inverse).

#### 3.6.3 Operands VECT_ASSE / VECT_ASSE_GENE

```text
♦    /    VECT_ASSE = va
```

Concept of type cham_no_DEPL_R, assembled vector that one wishes to project.

```text
/    VECT_ASSE_GENE = va
```

Concept of type vect_asse_gene, assembled vector coming from substructuring, that one wishes to project.

### 3.7 Keyword RESU_GENE

```text
◊    VECT_ASSE_GENE
```

Makes it possible to project a result data structure of type dyna_trans (coming from a linear dynamic analysis, or from the reading of a data file). This keyword must be repeated as many times as there are vectors to project.

#### 3.7.1 Operand RESULTAT

```text
♦    RESULTAT = CO('res')
```

Concept of type resu_gene, resulting generalised vector.

#### 3.7.2 Operand TYPE_VECT

```text
♦    TYPE_VECT =    typ
```

Character string describing the type of the field represented by the assembled vector. The available values are 'FORC', 'DEPL', 'VITE' and 'ACCE'. The processing differs according to whether one uses the option FORC or the others.

- With the option FORC, one carries out the simple projection ${\Phi}^{T}f$ , where $\Phi$ is the modal basis and $f$ the force,
- With the other options, one computes by an inverse problem the modal participation coefficients associated with a given displacement. One assumes that the displacement $x$ can be written in the form $x={\eta}^{T}\Phi$ . One then computes $\eta ={\Phi}^{T}{({\Phi}^{T}\Phi )}^{-1}x$ (Moore-Penrose pseudo-inverse).

#### 3.7.3 Operands RESU

```text
♦    /    RESU = res
```

Concept of type dyna_trans, result data structure that one wishes to project.

### 3.8 Operand INFO

```text
◊    INFO    =    / 1 [DEFAUT]
                  / 2
```

Level of information printout for the command NUME_DDL_GENE (see [U4.65.03](doc:u4.65.03)).

## 4 Example of use

```text
# dynamique transitoire sur base modale système masse et ressort

PROJ_BASE( BASE=MODES,

MATR_ASSE_GENE=(

_F(MATRICE = CO(’MASSEGEN’),

MATR_ASSE = MATRMASS),

_F(MATRICE = CO(’RIGIDGEN’),

MATR_ASSE = MATRRIGI),

_F(MATRICE = CO(’AMORTGEN’),

MATR_ASSE = MATRAMOR,

STOCKAGE = 'PLEIN')),

VECT_ASSE_GENE=

_F(VECTEUR = CO(’EFFOGENE’),

VECT_ASSE = VECTASS) )

);
```
