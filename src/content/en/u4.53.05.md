# u4.53.05 Operator DYNA_LINE

## 1 Purpose

DYNA_LINE is the unified operator making it possible to carry out a transient or harmonic response analysis on a physical or generalised basis. It can also treat localised non-linearities for transient response analyses, soil-structure interaction or fluid-structure interaction on a generalised basis.

The advantage of the operator DYNA_LINE, compared with the operators DYNA_VIBRA or CALC_MISS, is that the user does not have to deal with the steps of assembly of the matrices. The construction of a relevant projection basis for the solution of the problem on a generalised basis is carried out automatically by the operator from the information supplied.

The concept produced depends on the type of analysis carried out (dyna_trans, dyna_harmo).

## 3 Indirection operands

### 3.1 TYPE_CALCUL

This keyword makes it possible to choose between a transient analysis (TYPE_CALCUL='TRAN') and a harmonic analysis (TYPE_CALCUL='HARM').

### 3.2 BASE_CALCUL

This keyword makes it possible to choose between an analysis on a physical basis (BASE_CALCUL='PHYS') and an analysis on a generalised basis (BASE_CALCUL='GENE').

## 4 Operands common to every type of analysis

The following operands, common to every type of analysis, make it possible to define the finite-element model.

### 4.1 MODELE

♦    MODELE      =    mo,                                    [modele]

Defines the physical model used for the dynamic analysis

### 4.2 CHAM_MATER

◊    CHAM_MATER =    chmat,                                [cham_mater]

Material field used for the analysis.

### 4.3 CARA_ELEM

◊    CARA_ELEM     =    carac,                                [cara_elem]

Geometric and elementary characteristics used for the analysis.

### 4.4 CHARGE

♦    CHARGE         =    charge,                            [char_meca]

Loading of the Dirichlet conditions making it possible to restrain the structure.

## 5 Additional output concepts on a generalised basis

The data structure produced by the operator DYNA_LINE is always restored onto the physical basis, including in the case of an analysis on a generalised basis. The user therefore in principle does not need to recover the basis or the generalised result which was used for the analysis. However, these objects may prove useful for certain advanced post-processings.

### 5.1 BASE_RESU

◊    BASE_RESU =    base_resu,                        [mode_meca]

Makes it possible optionally to recover the analysis basis built by the operator and which was used for the dynamic analysis on a generalised basis. The output concept is of type [mode_meca].

### 5.2 RESU_GENE

◊    RESU_GENE =    resu_gene,                        [tran_gene]

The operand RESU_GENE makes it possible optionally to recover the result on a generalised basis. The output concept is of type [tran_gene, harm_gene] depending on the type of analysis (TYPE_CALCUL).

## 6 Computation of the static enrichment

### 6.1 ENRI_STAT

◊    ENRI_STAT        =     /'OUI',                            [DEFAUT]

> /'NON',

In the case of an analysis on a generalised basis, a static correction is set up by default *via* the computation of the static modes, which are added to the modal basis.

Static modes are computed for each loading assigned under the factor keyword EXCIT (see § 9), according to strategies which depend on the types of loading. Static modes are also computed for the non-linear constitutive behaviours assigned under the factor keyword COMPORTEMENT (see § 11.1).

The static modes are then assembled with the dynamic modes in order to form the generalised analysis basis.

The keyword ENRI_STAT cannot be used in the case of an analysis with fluid-structure interaction (IFS='OUI') (see § 12).

### 6.2 ORTHO

◊    ORTHO            =    /'NON',                    [DEFAUT]

> /'OUI',

Makes it possible to orthogonalise the assembled basis of the dynamic modes and of the static modes. The orthogonalisation is carried out by means of an eigenvalue problem made up of the stiffness and mass matrices projected onto this assembled basis.

### 6.3 FREQ_COUP_STAT

◊    FREQ_COUP_STAT        = fc_stat                        [R]

Cut-off frequency (expressed in Hz) used for the modal analysis which makes the orthogonalisation possible. If the keyword FREQ_COUP_STAT is not defined by the user, no cut-off is taken into account.

#### 7.1.1 Keyword BANDE_ANALYSE

◊    BANDE_ANALYSE     =    [f_min, f_max],

Makes it possible to define the frequency band in which one wishes to carry out the dynamic analysis. In the case of an analysis on a generalised basis, the values of the band are used for the computation of the dynamic modes. This keyword may contain only a single value; in that case this value will correspond to the maximum frequency f_max, the minimum frequency f_min being set to zero.

If the keyword BANDE_ANALYSE is not supplied, in the case of a transient analysis, the minimum frequency f_min is set to zero, and the maximum frequency f_max will be computed automatically from the cut-off frequency of the input signals.

#### 7.1.2 Keyword PCENT_COUP

◊    PCENT_COUP     =    / pcent_coup,                        [R]

> / 90.

The cut-off frequency of an input signal is computed so as to contain PCENT_COUP% of the energy of the input signal. The value of the keyword PCENT_COUP must lie between 80 and 100.

The cut-off frequency corresponds to the maximum value of the cut-off frequencies of each of the signals. The maximum frequency f_max is then set to twice the cut-off frequency.

### 7.2 Operands FREQ, LIST_FREQ

◊    / FREQ            =    freq,                            [l_R]

> / LIST_FREQ    =    list_freq    ,                    [:ref:` listr8  < listr8 >`]

In the harmonic case, these keywords make it possible to define the frequencies for which the dynamic response will be computed.

### 7.3 Operands SCHEMA_TEMPS, INCREMENT, ETAT_INIT, ARCHIVAGE

The following keywords are useful in the case of a transient analysis.

#### 7.3.1 Factor keyword SCHEMA_TEMPS

◊    SCHEMA_TEMPS    = _F(...)

This factor keyword makes it possible to define the parameters concerning the time-integration scheme in the case of a transient analysis. One may refer to the documentation of DYNA_VIBRA [U4.53.03](doc:u4.53.03) for further information on the meaning of the simple keywords used.

Note that by default the operator DYNA_LINE uses the scheme DEVOGE, unlike DYNA_VIBRA, which uses the scheme DIFF_CENTRE by default.

#### 7.3.2 Factor keyword INCREMENT

♦     INCREMENT =_F(

> ◊    INST_INIT =    ti,                [R]
> ◊    PAS = dt,                [R]
> ♦     INST_FIN= tf,                    [R]

> ),

This factor keyword makes it possible to define the analysis increments in the case of a transient analysis. One may refer to the documentation of DYNA_VIBRA [U4.53.03](doc:u4.53.03) for further information on the meaning of the simple keywords used.

Note that, unlike the operator DYNA_VIBRA, it is not mandatory to specify the simple keyword PAS defining the analysis step. In that case, the analysis step is computed automatically. If the keyword BANDE_ANALYSE is present (see § 7.1.1), then the step is computed as follows:

$\Delta t=\frac{1}{5{f}_{max}}$

Otherwise, the step is computed directly from the cut-off frequency (see § 7.1.2), as follows:

$\Delta t=\frac{1}{5{f}_{c}}$

#### 7.3.3 Factor keyword ETAT_INIT

◊     ETAT_INIT = _F(...)

This factor keyword makes it possible to define an initial state. One may refer to the documentation of DYNA_VIBRA [U4.53.03](doc:u4.53.03) for further information on the meaning of the simple keywords used.

Note that, in the case of an analysis on a generalised basis, unlike what is provided for in the data setup of DYNA_VIBRA, the user cannot supply the vectors projected onto the generalised basis. One must then supply, in the same way as for an analysis on a physical basis, the fields at the nodes on the physical basis, which will automatically be projected by the operator onto the generalised basis if need be.

#### 7.3.4 Factor keyword ARCHIVAGE

◊    ARCHIVAGE    = _F(...)

This factor keyword makes it possible to control the archiving time instants. One may refer to the documentation of DYNA_VIBRA [U4.53.03](doc:u4.53.03) for further information on the meaning of the simple keywords used.

## 8 Definition of the damping

◊     AMORTISSEMENT = _F(...)

Factor keyword making it possible to introduce various types of damping.

### 8.1 TYPE_AMOR = 'RAYLEIGH'

♦    TYPE_AMOR = 'RAYLEIGH',

This option makes it possible to compute the Rayleigh damping matrix on the basis of the parameters (AMOR_ALPHA, AMOR_BETA) of the materials assigned in CHAM_MATER (see § 4.2) and of the discrete elements of type (A_T*) defined in CARA_ELEM (see § 4.3). This option also makes it possible to compute the contribution of the absorbing fluid boundaries, in the case where they are present in the model.

If one is in the presence of a harmonic analysis (TYPE_CALCUL = ‘HARMO’), one activates other options in order to handle the contribution of the absorbing fluid boundaries.

### 8.2 Operands VNOR and MATR_IMPE_PHI

These operands are activated exclusively in the case where TYPE_CALCUL = ‘HARMO’ and TYPE_AMOR = ‘RAYLEIGH’.

◊    VNOR=

This option allows us to take into account the case of an emitting boundary. The most common case is the radiating one (or partially radiating if one defines a reflection coefficient $\alpha \ne 0$). In the case of a radiating boundary VNOR = 1 (option activated by default). In the case of an emitting boundary VNOR = -1. This coefficient is multiplied by the value of the impedance of the absorbing fluid boundaries ('3D_FLUI_ABSO', '2D_FLUI_ABSO' and 'AXIS_FLUI_ABSO').

◊    MATR_IMPE_PHI=

If one uses the fluid formulation $u-p-\phi$ in a harmonic analysis, one has the possibility of taking into account the contribution of the absorbing fluid boundaries via the computation of a third-order matrix (with the option IMPE_MECA). This third-order matrix can be used only in a harmonic analysis (operand MATR_IMPE_PHI in DYNA_VIBRA) and allows us to symmetrise the matrix (unlike the computation of this contribution via AMOR_MECA). If one wishes to use this third-order matrix in place of the first-order term (computed via AMOR_MECA), one must set MATR_IMPE_PHI = ‘OUI’ (by default MATR_IMPE_PHI = ‘OUI’).

### 8.3 TYPE_AMOR = 'HYST'

♦    TYPE_AMOR = 'HYST',

This option is used in the case of a harmonic analysis (TYPE_CALCUL == 'HARM'). It makes it possible to compute the imaginary part of the stiffness matrix in the case:

- of a material possessing a hysteretic damping supplied by the parameter (AMOR_HYST) assigned in CHAM_MATER (see § 4.2) and of the discrete elements of type (A_T*) defined in CARA_ELEM (see § 4.3).
- of a viscoelastic material of type ELAS_VISCO_* assigned in CHAM_MATER (see § 4.2)

### 8.4 TYPE_AMOR = 'MODAL'

♦    TYPE_AMOR = 'MODAL',

In the case of an analysis on a generalised basis, it is sometimes simpler and more relevant to define the modal dampings. In that case, one must specify in AMOR_REDUIT the reduced dampings (percentages of the critical damping) corresponding to each mode of the system, in the form of a list of reals.

♦    AMOR_REDUIT =    l_amor    ,            [l_R]

If the number of reduced dampings given is less than the number of basis vectors used in the modal basis, the dampings of the additional vectors are taken equal to the last damping of the list l_amor.

## 9 Factor keyword EXCIT

◊     EXCIT =    F(...)

This factor keyword makes it possible to define a load at each occurrence. The operands have a meaning equivalent to those described in the document [U4.54.03](doc:u4.54.03), with the difference that, for the operator DYNA_LINE, it is not necessary to supply all the information concerning the right-hand sides, which are computed automatically by the operator.

### 9.1 Keyword CHARGE

Loading applied to the structure, defined beforehand by means of the operator AFFE_CHAR_MECA. The keyword CHARGE must appear only in the occurrence of the factor keyword if the keyword TYPE_APPUI is not present.

### 9.2 Keywords TYPE_APPUI, DIRECTION, GROUP_NO

Keywords used in the case of seismic loadings; one may refer to the document [U4.63.01](doc:u4.63.01) for further details. The keyword TYPE_APPUI must appear only in the occurrence of the factor keyword if the keyword CHARGE is not present.

#### 9.2.1 TYPE_APPUI = 'MONO'

◊     TYPE_APPUI = 'MONO'

The structure is excited uniformly at all the supports. One must specify the direction of excitation *via* the keyword DIRECTION.

#### 9.2.2 TYPE_APPUI = 'MULTI'

◊     TYPE_APPUI = 'MULTI'

The excitation is applied on only part of the supports. One must specify the direction of excitation *via* the keyword DIRECTION as well as the nodes concerned *via* the keyword GROUP_NO.

#### 9.2.3 Keyword DIRECTION

◊     DIRECTION = (dx, dy, dz, drx, dry, drz)

Component of a vector giving the direction of the earthquake in the global reference frame.

#### 9.2.4 Keyword GROUP_NO

◊     GROUP_NO = g_noeu

List of the node groups of the structure subjected to the excitation in the case with TYPE_APPUI. If TYPE_APPUI = 'MULTI', one must necessarily specify the keyword GROUP_NO. If TYPE_APPUI = 'MONO', the keyword GROUP_NO is not mandatory. However, the occurrences of the keyword GROUP_NO must be the same for all the occurrences of the factor keyword EXCIT.

### 9.3 Operands FONC_MULT, COEF_MULT, FONC_MULT_C, COEF_MULT_C, ACCE, VITE, DEPL, PHAS_DEG, PUIS_PULS

Coefficient or multiplying function of the assembled vector. In the transient case, one must necessarily supply a function of time. In the harmonic case, it is possible to supply a coefficient or a complex function depending on frequency. One should refer to the document [U4.53.03](doc:u4.53.03) for further details on the use of these keywords.

## 10 Soil-structure interaction

◊ISS            =    'OUI',

Activation of the taking into account of soil-structure interaction. In the case with soil-structure interaction, the seismic analysis will use parameters computed by means of MISS3D (*via* CALC_MISS).

### 10.1 Inputs and outputs of the soil analysis

#### 10.1.1 Keyword CALC_IMPE_FORC

◊    CALC_IMPE_FORC =    / 'OUI',                            [DEFAUT]

> /'NON',

By default, the operator CALC_MISS is called a first time using the option FICHIER, which makes it possible to launch an execution of MISS3D and to recover the results from it in files, defined on a logical unit.

The user may deactivate this step by setting CALC_IMPE_MISS='NON'. One must then in that case define the logical units which correspond to files which already exist.

#### 10.1.2 Keyword TYPE_EXCIT

One must declare the nature of the loading supplied by the user. Two choices are possible:

- 'INST' for a loading in the time domain
- 'FREQ' for a loading in the frequency domain

This information is necessary for the computation of the list of frequencies in the call to CALC_MISS.

#### 10.1.3 Keywords UNITE_RESU_IMPE, UNITE_RESU_FORC

♦    UNITE_RESU_IMPE= uresimp                            [I]

♦    UNITE_RESU_FORC = uresfor                            [I]

◊    UNITE_RESU_FORC = uresfor                            [I]

These keywords make it possible to define the logical units associated with the impedances and the equivalent seismic forces computed by MISS3D.

In the case CALC_IMPE_FORC == 'NON', these keywords are mandatory and correspond to files which already exist and which were generated beforehand.

In the case CALC_IMPE_FORC == 'OUI', these keywords are optional and make it possible to recover the impedances and the equivalent seismic forces computed by MISS3D.

#### 10.1.4 Keywords TABLE_SOL / MATER_SOL

♦    / TABLE_SOL = tabsol                                [table]

> / MATER_SOL = matsol

These keywords make it possible to define the soil stratification used in the MISS3D analysis.

One of these keywords must necessarily be defined if CALC_IMPE_FORC == 'OUI'.

One may refer to the document [U7.03.12](doc:u7.03.12) for further details concerning these keywords.

### 10.2 Soil-structure interface

#### 10.2.1 Keyword VERSION_MISS

♦    VERSION_MISS =     /    'V6.7',                    [DEFAUT]

> 'V6.6',
> 'V6.5',

Number of the version of MISS3D. The default value corresponds to the production version of MISS3D (version d'exploitation).

MISS3D analyses on large models (or with many frequencies) may be long and costly in memory. Fortunately they can be accelerated by activating one or two levels of parallelism. For further information one may consult the documentations [U2.06.07](doc:u2.06.07) and [U2.08.06](doc:u2.08.06).

#### 10.2.2 Keywords GROUP_MA_INTERF, GROUP_NO_INTERF

♦    GROUP_MA_INTERF    =    grma,                         [grma]

♦    GROUP_NO_INTERF    =    grno,                        [grno]

GROUP_MA_INTERF corresponds to the mesh-cell group constituting the soil-structure interface.

GROUP_NO_INTERF corresponds to the node group at which the coupling conditions are imposed. This consists in automatically clamping the degrees of freedom of the nodes concerned in order to compute the eigenmodes of the structure. The user must not add boundary conditions on this group, as in the case of CALC_MISS.

In the case of a rigid foundation, the user must define a LIAISON_SOLIDE via the keyword CHARGE and a GROUP_NO_INTERF containing a node corresponding to the centre of the foundation. In the case of a flexible foundation, no condition must be defined on the GROUP_NO_INTERF, which must contain all the nodes of the foundation.

#### 10.2.3 Keywords TYPE_MODE / NB_MODE_INTERF

TYPE_MODE            =     /'CRAIG_BAMPTON',                    [DEFAUT]

> /'INTERF',
> / 'PSEUDO',

Makes it possible to define the method of computation of the interface modes associated with GROUP_MA_INTERF.

If TYPE_MODE == 'CRAIG_BAMPTON', all the attachment modes or constrained modes associated with the soil-structure interface are computed.

If TYPE_MODE == 'INTERF', the user must specify the number of static modes to be computed via the keyword NB_MODE_INTERF.

If TYPE_MODE == 'PSEUDO', six rigid-body modes are computed.

### 10.3 Parameters of the soil analysis

◊    PARAMETRE= _F(

This factor keyword makes it possible to enter the parameters of the MISS3D analysis. One should refer to the document [U7.03.12](doc:u7.03.12) for further details.

### 10.4 Operands ACCE_X, ACCE_Y, ACCE_Z, DEPL_X, DEPL_Y, DEPL_Z

In the case of a transient analysis, these operands make it possible to supply the accelerograms by means of accelerations in one or several directions (ACCE_X, ACCE_Y, ACCE_Z) or of imposed displacements in one or several directions (DEPL_X, DEPL_Y, DEPL_Z).
