# u4.91.03 Procedure IMPR_TABLE

## 1 Purpose

Print the content of a table in a file.

The command makes it possible to print a subset of the table in various formats. The default format (TABLEAU) is convenient for processing by spreadsheet-type software; other formats allow direct visualisation with a curve plotter (for example xmgrace).

## 3 Operands

### 3.1 What is a table?

A table is a data structure of a computing nature making it possible to store a set of integer, real, complex or character-string values.

A table is comparable to the worksheet of a spreadsheet, that is to say that one can see it as a list of **columns** side by side. Each column has a field name, which we call a **parameter**, and contains similar data of type: I, R, C, K8, K16, K24 or K32.

**Example:**

| **NUME_ORDRE** | **INST** | **NOEUD** | **G** |
| --- | --- | --- | --- |
| 1 | 10  | N1 | 5  |
| 1 | 10  | N2 | 6  |
| 1 | 10  | N3 | 7  |
| 1 | 10  | N4 | 8  |
| 2 | 20  | N1 | 9  |
| 2 | 20  | N2 | 9  |
| 2 | 20  | N3 | 8  |
| 2 | 20  | N4 | 8  |
| 3 | 30  | N1 | 7  |
| 3 | 30  | N2 | 6  |
| 3 | 30  | N3 | 5  |


One can also see the table as a sequence of records (which we shall call **lines**). Not all the lines necessarily have the same structure (that is to say the same parameters). For example:

| **ACTION** | **NUME_ORDRE** | **INST** | **NOEUD** | **DX** | **DY** | **MAILLE** | **SIXX** |
| --- | --- | --- | --- | --- | --- | --- | --- |
| INTITULE 1 | 1 | 10  | N1 | 3  | 5  |  |  |
| INTITULE 1 | 1 | 10  | N2 | 6  | 7  |  |  |
| INTITULE 1 | 1 | 10  | N3 | 8  | 9  |  |  |
| INTITULE 1 | 2 | 20  | N1 | 11  | 12  |  |  |
| INTITULE 1 | 2 | 20  | N2 | 15  | 13  |  |  |
| INTITULE 1 | 2 | 20  | N3 | 19  | 18  |  |  |
| INTITULE 2 | 2 | 20  |  |  |  | MA1 | -12. |
| INTITULE 2 | 2 | 20  |  |  |  | MA2 | -14. |

To print the content of a table, the user will be able to:

- select the columns and the lines that he or she wants to print [§3.6]
- choose a criterion for the print order of the lines [§3.7]
- choose the print "format": in lines, in tables, ... [§3.8]

### 3.2 Operand TABLE

```text
♦    TABLE= matable
```

Name of the table that one wants to print

### 3.3 Operand TITRE

```text
◊    TITRE= titre
```

Character string which will be printed before the table (and before the title possibly attached to the table). This string can make it possible to distinguish better the printouts of tables placed one after another in the same file.

### 3.4 Selecting what one wants to print: the keywords FILTRE and NOM_PARA, TOUT_PARA

The user chooses the columns to print by means of the keywords NOM_PARA and TOUT_PARA. He or she chooses the lines to print by means of the factor keyword (repeatable at will) FILTRE.

#### 3.4.1 Keyword FILTRE

The factor keyword FILTRE makes it possible to retain in the table only the lines satisfying certain criteria imposed by the user. The **occurrences** of the keyword are added to one another as **successive filters** ("AND" filters). For each occurrence of this keyword, one specifies the name of the parameter for which one imposes a condition, the type of condition (equality, non-equality, smaller than, ...) as well as the value associated with the condition.

##### 3.4.1.1 Operand NOM_PARA

```text
◊    NOM_PARA= para
```

para is the name of the parameter to which the filtering constraint applies.

##### 3.4.1.2 Operand CRIT_COMP

```text
◊    CRIT_COMP= crit
```

crit is the type of the filtering constraint.

| EQ | 'equality' for the integers, the texts, the reals or the complexes. For the floating-point numbers (reals or complexes), this equality is evaluated with a certain tolerance given by the keywords PRECISION and CRITERE. |
| --- | --- |
| NE | 'non-equality' (see EQ) |
| LT | 'smaller than' Order relations: - natural for the integers and the reals - alphabetical for the texts - **invalid** for the **complexes** |
| GT | 'greater than' (see LT) |
| LE | 'smaller than or equal to' (see LT) |
| GE | 'greater than or equal to' (see LT) |
| VIDE | empty cell |
| NON_VIDE | non-empty cell |
| MAXI | the line retained will be the one which has the maximum value |
| MAXI_ABS | the line retained will be the one which has the maximum absolute value |
| MINI | the line retained will be the one which has the minimum value |
| MINI_ABS | the line retained will be the one which has the minimum absolute value |
| REGEXP | checks the regular expression supplied by VALE_K |

**Warning**

*In the extraction commands* EXTR_TABLE/RECU_FONCTION*, the criteria* MINI/MAXI *(and* MINI_ABS/MAXI_ABS*) select a single line satisfying the criterion, the last one.*

*Whereas in the commands which handle the tables* CALC_TABLE/IMPR_TABLE*, all the lines satisfying these criteria are retained.*

*The filter by regular expression is available only in* CALC_TABLE*.*

##### 3.4.1.3 Operands VALE / VALE_I / VALE_C / VALE_K

These various keywords are used according to the type of the column associated with the parameter to which the constraint applies: integer, real, complex or text.

One gives as argument the value associated with the constraint; for example 12 if one is interested only in order number 12. One can supply several values (valid for the equality or inequality tests) in order to apply an "OR" filter (cf. example below).

This operand is useless when one uses the constraint types: 'VIDE', 'NON_VIDE', 'MAXI', 'MINI', …

VALE_K is also used to supply the regular expression to be checked (CRIT_COMP='REGEXP'). Example: VALE_K='^N[MP]' in order to retain only the lines where, for the chosen parameter, the cell contains a character string which begins with an N (upper case) followed by an M or a P, then possibly by other characters (See the Python re module for more details on regular expressions).

##### 3.4.1.4 Operands CRITERE / PRECISION

When the constrained parameter is of floating type (real or complex) and the constraint type is equality (or non-equality), this equality is evaluated with a certain tolerance.

```text
PRECISION = eps,                eps est la tolérance

CRITERE=    /'RELATIF' ,        |x-xref| < eps*|xref|
            /'ABSOLU' ,         |x-xref| < eps
```

##### 3.4.1.5 Example of use of the keyword FILTRE

If one specifies:

```text
FILTRE= ( _F(NOM_PARA= 'NOEUD', VALE_K = ('N7', 'N12'),),

_F(NOM_PARA= 'INST' , CRIT_COMP= 'GT' , VALE= 3.0,),

_F(NOM_PARA= 'INST' , CRIT_COMP= 'LT' , VALE= 13.0,),

),
```

One thus selects the lines of the table such that the parameter NOEUD equals 'N7' or 'N12' and such that the parameter INST lies between 3. and 13.

#### 3.4.2 Operand NOM_PARA

If the keyword NOM_PARA is absent, one will print **all** the columns of the table.

If the user uses the keyword NOM_PARA = lpara, one will print only the parameters specified in the list lpara and in the order of the list.

### 3.5 Ordering the lines of a table: the factor keyword TRI

**A single** occurrence is accepted for the factor keyword TRI.

#### 3.5.1 Operand NOM_PARA = lpara

This keyword is used to specify the list of the parameters which will be used to order the lines of the table (there may be a need for several parameters). In the event of equality on the first parameter, one uses the next one…

**Note:**

*One can use for the sorting parameters that one does not print.*

#### 3.5.2 Operand ORDRE

This keyword is used to specify whether one must use an ascending or descending order. By default, one sorts in ascending order.

The order relations used are:

- the natural order for the integers and the reals,
- the alphabetical order for the texts and the concept names.

**Notes:**

*One cannot use a complex parameter to rank the lines of a table.*

*For parameters of type* *NOEUD (or* *MAILLE), the order is alphabetical because these parameters contain the name of the nodes (or of the mesh cells).*

#### 3.5.3 Example of use of the keyword TRI

If one specifies:

```text
TRI=_F (NOM_PARA= ('NOEUD','INST'), ORDRE= 'CROISSANT'),
```

One will print the lines of the table in the alphabetical order of the nodes. If several lines corresponding to a given node exist, the **second** sorting criterion (INST) will be used to rank these lines.

### 3.6 Choice of the print format: keywords FORMAT, PAGINATION, ...

By default the print format is the 'TABLEAU' format, that is to say a presentation in columns of the various selected parameters (as for the examples in this document). The EXCEL TM software offers a set of tools making it possible to exploit this type of file: sorting, filtering, dynamic tables, ...

#### 3.6.1 FORMAT = 'TABLEAU' or 'AGRAF'

An example of a table printed in the 'TABLEAU' format:

| NUME_ORDRE | INST | NOEUD | DX | DY |
| --- | --- | --- | --- | --- |
| 1 | 4  | N7 | 3.4 | 3.8 |
| 1 | 4  | N4 | 2.4 | 2.8 |
| 1 | 4  | N2 | 1.4 | 1.8 |
| 4 | 8  | N7 | 3.4 | 3.8 |
| 4 | 8  | N4 | 2.4 | 2.8 |
| 4 | 8  | N2 | 1.4 | 1.8 |
| 7 | 20  | N7 | 3.4 | 3.8 |
| 7 | 20  | N4 | 2.4 | 2.8 |
| 7 | 20  | N2 | 1.4 | 1.8 |

The only difference between the 'TABLEAU' format and the 'AGRAF' format is that for the latter, the "text" columns (for example NOEUD above) are preceded by a "".

**Note:**

*In the* *AGRAF format, no directive (*.digr *file) is produced; only the values (*.dogr *file) are.*

#### 3.6.2 Layout in the TABLEAU format

One can define here the appearance of the printed table: from a classic table in columns to a csv- or html-compatible format…

```text
◊    DEBUT_TABLE = texte
```

Defines the text printed before each table (by default, one prints a line of dashes).

```text
◊    FIN_TABLE = texte
```

Defines the text printed after each table (nothing by default).

```text
◊    SEPARATEUR = separ
```

Defines the separator used between two columns (a space by default).

```text
◊    COMMENTAIRE = com
```

Character inserted at the start of the line to indicate a comment line (or a title, # by default).

> COMM_PARA = comp

Character inserted in order to comment out the line of the labels (by default, no character is inserted).

```text
◊    DEBUT_LIGNE = deb
```

String inserted at the start of each line (empty by default).

```text
◊    FIN_LIGNE = fin
```

String inserted at the end of the line ('\n' by default).

#### 3.6.3 FORMAT = 'ASTER'

The difference between the 'ASTER' format and the 'TABLEAU' format is the header of the table and its last line. This difference is justified by the fact that a table printed in the 'ASTER' format can be re-read by *Code_Aster* (command LIRE_TABLE [U7.02.03](doc:u7.02.03)).

Example:

#DEBUT_TABLE

#TITRE ASTER 6.03.11 CONCEPT TAB_REAC CALCULE LE 12/07/2002

#TITRE TABL_POST_RELE

INTITULE RESU NOM_CHAM NUME_ORD INST DY

K8 K8 K16 I R R

MESSAGE RESU REAC_NODA 1 2.50000E-01 -2.25146E+00

MESSAGE RESU REAC_NODA 2 5.00000E-01 -4.44089E+00

MESSAGE RESU REAC_NODA 3 7.50000E-01 -6.59515E+00

MESSAGE RESU REAC_NODA 4 1.00000E+00 -8.65972E+00

MESSAGE RESU REAC_NODA 5 1.25000E+00 -1.06742E+01

MESSAGE RESU REAC_NODA 6 1.50000E+00 -1.26438E+01

MESSAGE RESU REAC_NODA 7 1.75000E+00 -1.45569E+01

#FIN_TABLE

#### 3.6.4 FORMAT='NUMPY'

Numpy is a Python module for handling arrays.

The printout in this format produces a file which can be re-read by the function numpy.load().

Only the real and integer parameters (columns) (automatically converted into reals) are printed. The other parameters are ignored.

Finally, the topology of the table is preserved: one finds a numpy array which has as many lines as the table and as many columns as there are real or integer parameters.

**Note**

*In the case of a parametric analysis, one expects a single line in the printed table. Use* CALC_TABLE *to filter the lines if need be.*

#### 3.6.5 FORMAT = 'TABLEAU_CROISE'

The 'TABLEAU_CROISE' format is reserved for double-entry tables. The printout is made in the form of a table whose column names and line names have been documented. This printout concerns tables having 3 parameters. One represents the values of one of the 3 parameters as a function of the other 2.

Example: DX as a function of NOEUD and INST:

| DX FONCTION DE NOEUD ET DE INST |  | 4  | 8  | 20  |
| --- | --- | --- | --- | --- |
| NOEUD/INST | N7 | 3.4 | 3.4 | 3.4 |
|  | N4 | 2.4 | 2.4 | 2.4 |
|  | N2 | 1.4 | 1.4 | 1.4 |

```text
NOM_PARA = ('INST', 'NOEUD', 'DX')
```

The parameter "filling" the table is the 3rd of the list indicated by the simple keyword NOM_PARA.

The "abscissa" parameter is the 2nd of the list indicated by the simple keyword NOM_PARA.

The "ordinate" parameter is the 1st of the list indicated by the simple keyword NOM_PARA.

**Note:**

*If the table contains more than 3 parameters, one can use the keyword* *PAGINATION to "enumerate" the values taken by the other parameters (see example 3).*

#### 3.6.6 FORMAT = 'XMGRACE'

This format makes it possible to produce a file that can be visualised directly in xmgrace in the form of a curve.

One has the same formatting functionalities as in IMPR_FONCTION.

If PILOTE is not specified, one produces a data file for xmgrace; if PILOTE is supplied and if the chosen driver is actually available on the machine, one can produce directly a postscript, png, … file.

Keywords for formatting the graph: see IMPR_FONCTION [U4.33.01](doc:u4.33.01).

#### 3.6.7 Operand PAGINATION

This keyword is used to print a table in pieces (as a set of smaller tables). One gives a list of parameters (lpagi) which will be enumerated and printed as titles of the small tables.

The list of the pagination parameters (lpagi) must be included in the complete list of the parameters that one wants to print (lpara).

If one wants to use pagination and the 'TABLEAU_CROISE' format, the list lpara, once the parameters of lpagi have been removed from it, must be formed of 3 residual parameters. These 3 parameters will be used for the presentation as a table [§3.4.3].

Example: FORMAT='TABLEAU', PAGINATION='NOEUD'

NOEUD: N7

| NUME_ORDRE | INST | DX | DY |
| --- | --- | --- | --- |
| 1 | 4  | 3.4 | 3.8 |
| 4 | 8  | 3.4 | 3.8 |
| 7 | 20  | 3.4 | 3.8 |

NOEUD: N4

| NUME_ORDRE | INST | DX | DY |
| --- | --- | --- | --- |
| 1 | 4  | 2.4 | 2.8 |
| 4 | 8  | 2.4 | 2.8 |
| 7 | 20  | 2.4 | 2.8 |

NOEUD: N2

| NUME_ORDRE | INST | DX | DY |
| --- | --- | --- | --- |
| 1 | 4  | 1.4 | 1.8 |
| 4 | 8 | 1.4 | 1.8 |
| 7 | 20  | 1.4 | 1.8 |

#### 3.6.8 Operand FORMAT_C

For the complexes, two print formats are available (modulus/phase by default or real part/imaginary part).

#### 3.6.9 Operand FORMAT_R

This keyword makes it possible to choose the number of decimal places printed for each floating-point number: (real or complex).

One uses for this the FORTRAN syntax.

For example, for the default value: 'E12.5', one will print each floating-point number on 12 characters, with 5 decimal places and in scientific notation (with an exponent).

#### 3.6.10 Operand IMPR_FONCTION

For tables containing in their cells names of functions, this keyword makes it possible to indicate that one also wants to print the **content** of the functions referenced in the table.

One first prints the table (as has been seen above) then one "loops" over all the functions contained in the printed part of the table and one prints these functions (as the command IMPR_FONCTION does).

### 3.7 Operand INFO

```text
◊    INFO = inf
```

Prints in the "message" file additional information if inf=2. Nothing happens if inf=1.

## 4 Examples

Example 1: to discover the structure of a table

```text
IMPR_TABLE(TABLE= post_rel)
```

Example 2: print a few parameters with filter and sorting

```text
IMPR_TABLE(TABLE= post_rel,

FILTRE=_F(NOM_PARA='inst', VALE= 0.,        CRITERE= 'absolu'),

TRI=_F(NOM_PARA=('absC_curv','coor_x'),ORDRE=('croissant'),

NOM_PARA= ('coor_x', 'temp'),

)
```

Example 3: use pagination and the tableau_CROISE format

```text
IMPR_TABLE(TABLE= post_rel,

NOM_PARA= ('coor_x', 'temp', 'absC_curv', 'inst', 'coor_y'),

PAGINATION= ('inst','coor_x'),

FORMAT= 'tableau_CROISE',

)
```

### 4.1 Operand UNITE

Makes it possible to choose the file in which one prints the table.

By default, the printout is carried out on the file associated with logical unit 8.

In the 'XMGRACE' format, the default value is 29, type dat in astk.
