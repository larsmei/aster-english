# u4.24.01 Operator DEFI_SQUELETTE

## 1 Purpose

Define the visualisation mesh of the results of a dynamic substructuring.

In the case of cyclic dynamic substructuring, the mesh is created by using all or part of the mesh cells (visualisation mesh) of the sector structure and then repeating it cyclically in order to reconstitute the global structure.

In the case of general dynamic substructuring, the mesh is created by using all or part of the mesh cells (visualisation mesh) of the various substructures and then associating them so as to reconstitute the global structure.

The mesh cells used (called visualisation mesh cells) are not necessarily the support of a finite element. This makes it possible to use a reduced number of visualisation mesh cells, different from the analysis mesh cells, and representing roughly the shape of the structure (skeleton).

One may also create a skeleton from another skeleton, some nodes of the interfaces of which will be merged according to a proximity criterion.

Restriction: the visualisation mesh cells must be defined from nodes supporting degrees of freedom of the analysis (there is no interpolation of the results).

*Warning:*

**Use of the operand** TOUT='OUI' **can lead to serious performance problems. Always prefer the call that specifies the mesh-cell groups involved in the skeleton, particularly when the meshes of the substructures constitute only a small part of the complete mesh.**

This operator creates a data structure of type squelette.

## 2 Syntax

```text
squelette = DEFI_SQUELETTE(
    ◆ / CYCLIQUE = _F(
           ◆ / MODE_CYCL = mode_cycl,
             / MAILLAGE = maillage,
           ◇ & NB_SECTEUR = int,
        ),
      / MODELE_GENE = modele_gene,
      / MAILLAGE = maillage,
    ◇ / SECTEUR = _F(
           ◇ GROUP_MA = grma,
           ◇ TOUT = "OUI" (ou non renseigné),
        ),
    ◇ SQUELETTE = squelette,
    ◇ RECO_GLOBAL = _F(
         ◇ / TOUT = "OUI" (ou non renseigné),
           / GROUP_NO_1 = grno,
         ◇ & SOUS_STRUC_1 = text,
         ◇ & SOUS_STRUC_2 = text,
         ◇ & GROUP_NO_2 = grno,
         ◇ PRECISION = float (défaut: 0.001),
         ◇ CRITERE = / "RELATIF" (par défaut),
                     / "ABSOLU",
         ◇ DIST_REFE = float,
      ),
    ◇ & NOM_GROUP_MA = _F(
           ◆ NOM = text,
           ◆ SOUS_STRUC = text,
           ◆ GROUP_MA = grma,
        ),
      / SOUS_STRUC = _F(
           ◆ NOM = text,
           ◆ / GROUP_MA = grma,
             / TOUT = "OUI" (ou non renseigné),
        ),
    ◇ EXCLUSIF = / "OUI",
                 / "NON" (par défaut),
    ◇ GROUP_MA = grma,
    ◇ TOUT = "OUI" (ou non renseigné),
    ◇ TRANS = float,
    ◇ ANGL_NAUT = float,
    ◇ TITRE = text,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```
## 3 Operands

### 3.1 Cyclic substructuring (factor keyword CYCLIQUE)

#### 3.1.1 Operand MODE_CYCL

```text
♦    MODE_CYCL = mocy
```
Concept mode_cycl resulting from an analysis in cyclic substructuring.

#### 3.1.2 Operand MAILLAGE/NB_SECTEUR

```text
♦    MAILLAGE = mail
```
Concept maillage_sdaster used to define the skeleton. It is accompanied by the keyword NB_SECTEUR, an integer which gives the number of repetitions of this mesh in order to obtain the complete structure of the skeleton.

#### 3.1.3 Keyword SECTEUR

```text
♦    SECTEUR
```
Factor keyword for the creation of a skeleton from a result of type mode_cycl produced by MODE_ITER_CYCL [U4.52.05](doc:u4.52.05). Makes it possible to define, on the base sector, the list of visualisation mesh cells which will be repeated cyclically.

##### 3.1.3.1 Operands TOUT / GROUP_MA

```text
◊ / TOUT
```
All the mesh cells of the mesh of the base sector will be visualisation mesh cells.

```text
◊ / GROUP_MA = grma
```
List of the visualisation mesh-cell groups of the base sector.

### 3.2 Classical substructuring

#### 3.2.1 Operand MODELE_GENE

```text
♦ MODELE_GENE = mogene
```
Name of the modele_gene concept coming from DEFI_MODELE_GENE [U4.65.02](doc:u4.65.02) defining the global structure on which one wishes to define the skeleton.

#### 3.2.2 Keyword SOUS_STRUC

```text
♦ SOUS_STRUC
```
Factor keyword for the creation of a skeleton following an analysis by classical dynamic substructuring.

Makes it possible to define, on each substructure of the generalised model, the list of visualisation mesh cells.

##### 3.2.2.1 Operand NOM

```text
◊ NOM = nom_struc
```
Name of the substructure. It must be identical to one of the names of the substructures defining the generalised model (see DEFI_MODELE_GENE [U4.65.02](doc:u4.65.02)).

##### 3.2.2.2 Operands TOUT / GROUP_MA

```text
◊ / TOUT
```
All the mesh cells of the mesh of the substructure will be visualisation mesh cells.

```text
◊ / GROUP_MA= grma
```
List of the visualisation mesh-cell groups of the substructure.

### 3.3 Keywords SQUELETTE and RECO_GLOBAL

The keyword SQUELETTE defines an initial concept of type squelette in which the nodes of the interfaces will be merged by the keyword RECO_GLOBAL, either all these nodes (TOUT= 'OUI'), or selectively a node group grno1 (operand GROUP_NO_1) of the substructure nom_sstru1 (operand SOUS_STRUC_1) with a node group grno2 (operand GROUP_NO_2) of the substructure nom_sstru2 (operand SOUS_STRUC_2).

These substructures must belong to the concept of type modele_gene supplied by the operand MODELE_GENE.

The skeleton modified by the merging will be the result of the operator DEFI_SQUELETTE.

#### 3.3.1 Operands DIST_REFE / CRITERE / PRECISION

The merging will be done according to a proximity criterion, either absolute (with respect to dist_ref) or relative (with respect to dist_ref*prec).

### 3.4 Keyword NOM_GROUP_MA

In the case where one modifies an initial concept of type squelette (entered by the keyword SQUELETTE) by a merging of the nodes of the interfaces (by means of the keyword RECO_GLOBAL), one may then recover mesh-cell groups (entered by the operand GROUP_MA) in the substructure nomsst (entered by the operand SOUS_STRUC) by assigning them a new mesh-cell group name (operand NOM) in the result skeleton.

### 3.5 Keyword EXCLUSIF

In the case of an analysis by classical substructuring, only. By setting EXCLUSIF='OUI', one deletes from the final skeleton the mesh-cell groups coming from the initial meshes.

## 4 Example

The command file which follows computes, by two substructuring methods, the bending modes of a plate clamped at its centre:

- cyclic method,
- classical method.

Then, by the command DEFI_SQUELETTE, a visualisation mesh is created (**skeleton** mesh). After the results have been expressed in physical space, the visualisation mesh and the results are written to a RESULTAT file in IDEAS format.

### 4.1 Command file

```text
#

# CALCUL PAR SOUS-STRUCTURATION CYCLIQUE

#

# CALCUL DES MODES PROPRES CYCLIQUES

#

mod_cy = MODE_ITER_CYCL (BASE_MODALE= bamo,

NB_MODE = 5, NB_SECTEUR = 4,

LIAISON = _F(DROITE ='DROITE', GAUCHE ='GAUCHE'),

CALCUL = _F(TOUT_DIAM ='OUI', NMAX_FREQ = 2),

INFO = 1)

#

# CREATION DU MAILLAGE DE CALCUL

#

squel1 = DEFI_SQUELETTE (MODE_CYCL= mod_cy,

SECTEUR = _F(GROUP_MA= ’CALCUL’))

#

# CREATION DU MAILLAGE DE VISUALISATION

#

squel2 = DEFI_SQUELETTE (MODE_CYCL= mod_cy,

SECTEUR = _F(GROUP_MA= ’VISUAL’))

#

# RESTITUTION DES RESULTATS SUR LES MAILLAGES SQUELETTES

#

modgl1 = REST_SOUS_STRUC (RESU_GENE= mod_cy,SQUELETTE= squel1)

modgl2 = REST_SOUS_STRUC (RESU_GENE= mod_cy,SQUELETTE= squel2)

#

…

# CALCUL PAR SOUS-STRUCTURATION CLASSIQUE

#

# CALCUL DU MACRO-ELEMENT

#

macele = MACR_ELEM_DYNA (BASE_MODALE= bamo)

#

# CALCUL DU MODELE GENERALISE

#

modege = DEFI_MODELE_GENE (

SOUS_STRUC=_F(NOM='CARRE1',

MACR_ELEM_DYNA= macele),

SOUS_STRUC=_F(NOM='CARRE2',

MACR_ELEM_DYNA= macele,

ANGL_NAUT=(90., 0., 0.)),

SOUS_STRUC=(NOM='CARRE3',

MACR_ELEM_DYNA= macele,

ANGL_NAUT=(180.,0.,0.)),

SOUS_STRUC=(NOM='CARRE4',

MACR_ELEM_DYNA= macele,

ANGL_NAUT=(270., 0., 0.)),

LIAISON=_F(SOUS_STRUC_1='CARRE1',

SOUS_STRUC_2='CARRE2',

INTERFACE_1 ='GAUCHE',

INTERFACE_2 ='DROITE'),

LIAISON=_F(SOUS_STRUC_1='CARRE2',

SOUS_STRUC_2='CARRE3',

INTERFACE_1 ='GAUCHE',

INTERFACE_2 ='DROITE'),

LIAISON=_F(SOUS_STRUC_1='CARRE3',

SOUS_STRUC_2='CARRE4',

INTERFACE_1 ='GAUCHE',

INTERFACE_2 ='DROITE'),

LIAISON=_F(SOUS_STRUC_1='CARRE4',

SOUS_STRUC_2='CARRE1',

INTERFACE_1 ='GAUCHE',

INTERFACE_2='DROITE'))

#

…

# CREATION DU MAILLAGE DE VISUALISATION

squel = DEFI_SQUELETTE (MODELE_GENE=MODEGE

SOUS_STRUC=_F(NOM ='CARRE1',

GROUP_MA= ’VISUAL’),

SOUS_STRUC=_F(NOM ='CARRE2',

GROUP_MA= ’VISUAL’),

SOUS_STRUC=_F(NOM ='CARRE3',

GROUP_MA= ’VISUAL’),

SOUS_STRUC=_F(NOM ='CARRE4',

GROUP_MA= ’VISUAL’))

#

# RESTITUTION DES RESULTATS SUR LE MAILLAGE SQUELETTE

#

modglo = REST_SOUS_STRUC ( RESU_GENE= resgen,

SQUELETTE= squel)

#
```
