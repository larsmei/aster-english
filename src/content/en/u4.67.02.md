# u4.67.02 Operator DEFI_DOMAINE_REDUIT

The purpose of the operator is to enrich an existing mesh with groups (of mesh cells or of nodes) which define a subdomain called the reduced integration domain (RID).

The operator relies on one or more result data structures of type mode_empi in order to determine specific nodes, called interpolation points, by applying the discrete empirical interpolation method (DEIM). The reduced integration domain is the set of mesh cells located in the neighbourhood of these interpolation points.

The operator enriches the mesh data structure by creating two groups:

- a mesh-cell group corresponding to the reduced domain;
- a node group corresponding to the interface between the reduced domain and the rest of the initial domain.

## 1 Syntax

```text
maillage = DEFI_DOMAINE_REDUIT(
    ◆ reuse = <objet de MAILLAGE>,
    ◆ BASE_PRIMAL = mode_empi,
    ◆ BASE_DUAL = mode_empi,
    ◆ NOM_DOMAINE = text,
    ◇ NB_COUCHE_SUPPL = int (défaut: 0),
    ◆ GROUP_NO_INTERF = text,
    ◆ MAILLAGE = maillage,
    ◇ DOMAINE_MINI = _F(
         ◇ GROUP_NO = grno,
         ◇ GROUP_MA = grma,
      ),
    ◇ DOMAINE_MAXI = _F(
         ◆ GROUP_MA = grma,
      ),
    ◇ CORR_COMPLET = / "NON" (par défaut),
                     / "OUI",
    # Si: (equal_to("CORR_COMPLET", 'OUI'))
        ◆ GROUP_NO_ENCASTRE = text,
        ◇ NB_COUCHE_ENCASTRE = int (défaut: 0),
    ◇ INFO = / 1 (par défaut),
             / 2,
    ◇ TITRE = text,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```
## 2 Operands

### 2.1 Operands BASE_PRIMAL and BASE_DUAL

```text
♦    BASE_PRIMAL        = base1,                [mode_empi]

♦    BASE_DUAL            = base2,                [mode_empi]

Nom desstructuresde données résultat de type mode_empi à analyser pour générer les points d'interpolation. Les deux bases base1 et base2 sont calculées à l'aide de l'opérateur DEFI_BASE_REDUITE [:ref:`U4.67.01 <U4.67.01>`]. Le calcul de la base base1 s'appuie sur un champ de température ou un champ de déplacement. Le calcul de la base base2 s'appuie sur un champ de flux ou un champ de contrainte.
```
### 2.2 Operand MAILLAGE

```text
♦     MAILLAGE            = mail,                [maillage]

La commande va enrichir un concept maillage déjà existant avec les nouveaux groupes de nœuds et de mailles définis par DOMAINE_INCLUS, GROUP_NO_INTERFACEet GROUP_NO_ENCASTRE.

Le mot-clef MAILLAGE est donc obligatoire.
```
### 2.3 Operand NOM_DOMAINE

```text
♦    NOM_DOMAINE        = nom_d

On précise le nom du groupe de mailles correspondant au RID.
```
### 2.4 Operand GROUP_NO_INTERF

```text
♦    GROUP_NO_INTERF        = nom_i

On précise le nom du groupe de nœuds contenus dans l'interface entre le RID et le reste du domaine.
```
### 2.5 Operand NB_COUCHE_SUPPL

```text
◊    NB_COUCHE_SUPPL    = nb_couche,            [I]

Par défaut, la commande construit le groupe RID en sélectionnant les mailles attachées aux points magiques (application de la dEIM, voir [:external:ref:`R5.01.05 <R5.01.05>`]). Quand on utilise le mot-clef NB_COUCH_SUPPL, on peut agrandir le RID en prenant nb_couched'éléments supplémentaires autour du RID initial. Par défaut, nb_couche =0.
```
### 2.6 Operand DOMAINE_MINI / DOMAINE_MAXI

> ◊    DOMAINE_MINI = _F(

```text
◊    GROUP_MA    =    lgma1,                        [l_gr_maille]
◊    GROUP_NO    =    lgno1,                        [l_gr_noeud]
)

Ce mot-clef facteur facultatif permet de mettre une partie du maillage dans le RID même si l''algorithme de recherche des points magiques par dEIM (voir [:external:ref:`R5.01.05 <R5.01.05>`]) ne le permet pas. C'est très utile en particulier pour «forcer» l'intégration d'une partie des conditions limites dans le RID. On peut soit ajouter des nœuds, soit ajouter des mailles.

◊    DOMAINE_MAXI = _F(
```
```text
◊    GROUP_MA    =    lgma1,                        [l_gr_maille]
)

De manière symétrique, il est possible de restreindre la taille du domaine réduit RID par le mot-clef DOMAINE_MAXI. Cette option est utile lors de la réalisation de modèles incrémentaux comme le soudage multi-passe ou excavation.
```
### 2.7 Operands CORR_COMPLET / GROUP_NO_ENCASTRE / NB_COUCHE_ENCASTRE

```text
**◊**     CORR_COMPLET        = /'NON'                            [DEFAUT]

                    /'OUI'

Si CORR_COMPLET = 'OUI'

    {

**♦**     GROUP_NO_ENCASTRE            = grno

        ◊    NB_COUCHE_ENCASTRE    = /0                [DEFAUT]

                                    /nb_couche,        [I]

    }
```
```text
Pour améliorer la qualité des résultats en hyper-réduction, il est possible de faire une correction du calcul hyper-réduit par un calcul élément fini détaillé avec CORR_COMPLET='OUI'. Pour celà, il est nécessaire de définir un groupe de noeuds servant à faire la liaison entre le RID et le reste du modèle avec le mot-clef GROUP_NO_ENCASTRE. Ce groupe de noeuds permet d'imposer les conditions limites de Dirichlet nécessaire à ce que le problème corrigé soit bien défini.

Par défaut (NB_COUCHE_ENCASTRE=0), ce groupe de noeuds est défini à l'intérieur du domaine réduit (mot-clef NOM_DOMAINE) en prenant les premiers noeuds contenus dans le domaine et liés aux noeuds définis par GROUP_NO_INTERF. Il est possible de rendre le domaine plus grand en utilisant le mot-clef NB_COUCHE_ENCASTRE.

De par la construction de ces groupes de noeuds, on a nécessairement NB_COUCHE_ENCASTRE inférieur ou égal à NB_COUCHE_SUPPL.
```
