# u4.91.01 Procedure IMPR_RESU in the 'RESULTAT' and 'ASTER' formats

## 1 Purpose

Write the mesh or the results of an analysis to a file in the 'RESULTAT' format, or the mesh in the 'ASTER' format.

At present this procedure makes it possible to write, as one chooses:

- a mesh,
- fields at the nodes (of displacements, of temperatures, of eigenmodes, of static modes, …),
- fields by element at the nodes or at the Gauss points (of stresses, of generalised forces, of internal variables…).

The procedure IMPR_RESU also makes it possible to write a mesh and/or results to a file with a view, in particular, to their graphical visualisation (cf. documents [U7.05.01](doc:u7.05.01) (format 'IDEAS'), [U7.05.21](doc:u7.05.21) (format 'MED') and [U7.05.32](doc:u7.05.32) (format 'GMSH')).

For concepts of type resultat, one can print only part of the information, by selecting the fields and the order numbers that one wishes to exploit.

For the printouts in the 'RESULTAT' format, it is possible to select the topological entities (node groups and mesh-cell groups) on which one wants to print the results. One can also reduce the number of pieces of information printed by requesting only the printout of certain components, of values lying in an interval chosen by the user or of extreme values. One can combine all the possibilities, for example in order to obtain the maximum value of a given component, on a particular topological entity and in an interval of values chosen by the user.

The 'RESULTAT' format must not be used as a basis for storing or exchanging results; its format is not fixed.

## 3 Typography in the IMPR_RESU documentation

In order to understand the documentation of IMPR_RESU properly, one must note that the term 'RESULTAT' covers in *Code_Aster* three rather different notions:

- a type of concept,
- a type of file,
- a write format.

Indeed, on the one hand, one designates as a result the quantities produced by an *Aster* analysis operator producing several fields (evolutionary analysis, eigenmode analysis, etc...).

These data (results) are contained in an *Aster* data structure of generic type called resultat. This generic type is subdivided into subtypes, for example mode_meca, evol_elas, etc., whose storage mode differs somewhat. A concept of type resultat has only one subtype. In the *Aster* documentation the names of the concept types are in lower-case Courier.

On the other hand, the results intended for printout, in particular those coming from IMPR_RESU, are placed in a file designated as the RESULTAT file (associated with unit 8, type resu in astk). The write format associated with this file intended for printout is itself also named RESULTAT.

**In summary**:

| résultat | data coming from the solution of the system, |
| --- | --- |
| resultat | generic designation of the concept type (of the data structure) which contains the result, |
| evol_ther mode_meca | name of the subtype of the result of type resultat, |
| FICHIER | (without quotes) designation of the file which contains the results, independently of the format of its content, |
| 'RESULTAT' | (with quotes) designation of the format (*Aster*) of the file which contains the results. |

## 4 Results that can be printed with IMPR_RESU

The operator [IMPR_RESU](doc:u4.91.01) makes it possible to print various types of results according to the format chosen
(`RESULTAT`, `MED`, `IDEAS`, `GMSH`, etc.).
The types of results handled depend on the write format, but always rest on a concept
of generic type `resultat` (see Typography).

The main results currently supported are the following:

- **Static or quasi-static results**

  - `EVOL_ELAS`: evolutionary elastic analyses (time evolution of the fields),
  - `STAT_NON_LINE`: results of static non-linear analyses,
  - `THER_NON_LINE`: results of static non-linear thermal analyses,
  - `MULT_ELAS`: linear combinations of elastic fields.
- **Modal or harmonic results**

  - `MODE_MECA`: results of a mechanical modal analysis,
  - `MODE_THER`: results of a thermal modal analysis,
  - `DYNA_HARMO`: results of a dynamic harmonic analysis,
  - `ACOU_HARMO`: results of a harmonic acoustic analysis.
- **Other types supported**

  - `EVOL_THER`: transient thermal evolution,
  - `EVOL_CHAR`: parameterised evolution of characteristic type,
  - `DYNA_NON_LINE`: non-linear dynamic results,
  - `SIMU_POINT_MAT`: results of a simulation at the material point,
  - `REST_GLOBALE`: global results coming from the recovery of quantities (grandeurs),
  - `CHAM_GD`: fields of computed quantities (grandeurs) independently of a `RESULTAT` concept.

The results of type `*_GENE` (for example `MODE_MECA_GENE` or `DYNA_HARMO_GENE`)
**cannot be printed** with [IMPR_RESU](doc:u4.91.01).
They must be handled with the aid of the operator [IMPR_GENE](doc:u4.91.02),
specifically designed for generalised results.

In summary:

| Type of result | Formats supported |
| --- | --- |
| EVOL_ELAS | RESULTAT, MED, IDEAS, GMSH |
| STAT_NON_LINE | RESULTAT, MED, IDEAS, GMSH |
| THER_NON_LINE | RESULTAT, MED, IDEAS, GMSH |
| MULT_ELAS | RESULTAT, MED (*+ TYPE_NOM=NOM_CAS*), IDEAS, GMSH |
| MODE_MECA | RESULTAT, MED, IDEAS, GMSH |
| MODE_THER | RESULTAT, MED, IDEAS, GMSH |
| DYNA_HARMO | RESULTAT, MED, IDEAS, GMSH (*PARTIE mandatory in MED/GMSH*) |
| ACOU_HARMO | RESULTAT, MED, IDEAS, GMSH (*PARTIE mandatory in MED/GMSH*) |
| EVOL_THER | RESULTAT, MED, IDEAS, GMSH |
| EVOL_CHAR | RESULTAT, MED, IDEAS, GMSH |
| DYNA_NON_LINE | RESULTAT, MED, IDEAS, GMSH |
| SIMU_POINT_MAT | RESULTAT, MED, IDEAS, GMSH |
| REST_GLOBALE | RESULTAT, MED, IDEAS, GMSH |
| CHAM_GD | RESULTAT, MED, IDEAS, GMSH |
| *_GENE | (Not supported) → use IMPR_GENE [U4.91.02] |

## 5 Operands FORMAT, PROC0, UNITE and INFO

The procedure IMPR_RESU makes it possible to write a mesh and/or result values in various formats with a view, in particular, to a graphical visualisation [U7.05.01](doc:u7.05.01), [U7.05.11](doc:u7.05.11), [U7.05.21](doc:u7.05.21) and [U7.05.31](doc:u7.05.31).

The operand FORMAT makes it possible to specify the print format of a result.

The default format is 'MED' (*cf.* [U7.05.21](doc:u7.05.21)). It makes it possible to print the mesh and/or the results in the form of a listing.

The operand PROC0, whose default value is 'OUI', makes it possible to restrict the printout to the processor of rank 0. If one assigns it the value 'NON', the printouts will be carried out on all the processors.

One specifies in which file the data will be written via the keyword UNITE (cf. command DEFI_FICHIER). By default, one uses the file of logical unit 8 in the 'RESULTAT' format and 26 in the 'ASTER' format.

The keyword INFO, when it is equal to 2, makes it possible to obtain information on the printouts carried out by the command.

## 6 Keyword RESU

This factor keyword makes it possible to specify the results to be printed and the format according to which one wants to print them.

## 7 Operands CHAM_GD and RESULTAT

The values of the computed fields are stored in data structures called fields of quantities (grandeurs). These fields of quantities (grandeurs) may be directly accessible (concept cham_gd) or be found in a data structure grouping several fields of quantities (grandeurs) (concept resultat).

- a field of a quantity (grandeur) is a data structure which makes it possible to store fields defined at the nodes (cham_no_*) or fields defined by element (cham_elem_*). For the fields by element, one distinguishes the fields defined at the nodes of the elements and the fields defined at the Gauss points of the elements,
- a result concept is composed of one or more fields of quantities (grandeurs). For example, at each analysis step one stores in the resultat data structure the field of the quantity (grandeur) displacement. This structure is therefore indexed by a matrix structure of order 2, one index of which is, for example, the list of the analysis time instants and the other the set of the computed fields (displacements, stresses, strains, ...).

One accesses in this case a field of a quantity (grandeur) by specifying the value of an access variable (order number, time instant, frequency, mode number ...) and a field name ('DEPL', 'SIGM_ELNO', ...). There exist several types of result concept: evol_elas, evol_noli, mode_meca, .... To each one corresponds a list of fields and a list of licit access variables.

On the other hand, with a result concept is also associated a certain number of complementary results (for example the generalised mass or the modal participation factors in a modal analysis (result concept of type mode_meca)), different for each value of the access variable. These complementary results are called parameters.

Given the resultat data structure, one easily understands that the printout possibilities available are those of the fields of quantities (grandeurs), supplemented by specific possibilities:

- information on the data structure (for example: list of the access variables, list of the fields actually computed, ...),
- selective access to a field of a quantity (grandeur) (for example, printout of the displacement field at the time instant $t=15.$ ),
- printout of the parameter values.

The operand RESULTAT makes it possible to print the fields contained in a result concept. One can for example choose to print only certain fields (see the following keyword: NOM_CHAM) on certain components of certain nodes (cf. NOEUD_CMP).

## 9 Parameters

### 9.1 Operand TOUT_PARA

This keyword indicates whether or not one wants to print all the values of the parameters attached to the concept of type resultat.

**Example:**

```text
IMPR_RESU(RESU=_F(RESULTAT=resu,
                  TOUT_PARA='OUI',
                  NUME_ORDRE=3))
```

One prints in the `RESULTAT` file the values of all the parameters, but only for the third analysis step of a `resultat` concept of type `mode_meca`:

Printout of the parameters of the concept resu for order number 3:

```text
NOM_MODE      3
FREQ          1.09787E+4
OMEGA2        4.75843E+09
AMOR_REDUIT   0.00000E+00
ERREUR        2.76853E-10
MASS_GENE     1.50009E-07
RIGI_GENE     7.13806E+02
........
........
NORME         SANS_CMP: LAGR
```

### 9.2 Operand NOM_PARA

This keyword makes it possible to choose a list of symbolic parameter names from among all the possible ones.
The keywords `TOUT_PARA` and `NOM_PARA` cannot be used simultaneously.

**Example:**

```text
IMPR_RESU(RESU=_F(RESULTAT=resu,
                  NOM_PARA=('NORME',),
                  NUME_ORDRE=3))
```

One prints in the `RESULTAT` file the value of the parameter of name `NORME`, but only for the third analysis step of a `resultat` concept of type `mode_meca`:

Printout of the parameters of the concept `resu` for order number 3:

```text
NORME        SANS_CMP: LAGR
```

### 9.3 Operand FORM_TABL

This keyword makes it possible to choose the print format of the parameter values.
Either in the form of a table each line of which is limited to 80 characters (`FORM_TABL='OUI'`),
or in the form of a table each line of which can reach 2000 characters (`FORM_TABL='EXCEL'`),
or in the form of a list (one parameter per line) (`FORM_TABL='NON'`).

By default, the parameters are printed in the form of a table.

**Example:**

1. `FORM_TABL = 'OUI'`

```
NUME_ORDRE   NUME_MODE   ITER_QR   ITER_BATHE
FREQ         OMEGA2      AMOR_REDUIT
MASS_GENE    RIGI_GENE   AMOR_GENE
MASS_EFFE_DY MASS_EFFE_DZ FACT_PARTICI_DX
FACT_PARTICI_DZ MASS_EFFE_UN_DX MASS_EFFE_UN_DY
NORME        METHODE
```

2. `FORM_TABL = 'EXCEL'`

```
NUME_ORDRE   NUME_MODE   ITER_QR   ITER_BATHE
```

## 10 Selection on the components

Another way of reducing the volume of the printouts is to print only the values of certain components (for example only the displacement along the axis X: component DX).

Note: the selection of the components does not work for the fields with sub-points.

### 10.1 Operand TOUT_CMP

This keyword makes it possible to indicate that one wishes to print all the components of the field.

### 10.2 Operand NOM_CMP

This keyword makes it possible to choose the list of the components of the cham_gd or of all the fields of the result concept that one wishes to print.

The keywords TOUT_CMP and NOM_CMP cannot be used simultaneously.

These components are described in the specific documentation of the elements.

## 11 Selection of the topological entities

In order to reduce the volume of the printouts, it is sometimes necessary to print only part of the result. To do this one can print a field at the nodes only at certain nodes, or a field by element only on certain elements.

Note: the selection of the topological entities does not work for the fields with sub-points.

### 11.1 Operand TOUT

This keyword indicates that one wishes to print the field over the whole structure (all the nodes for a field at the nodes, all the elements for a field by element).

### 11.2 Operand GROUP_NO

This keyword makes it possible to indicate the list of the node groups on which one wishes to print a cham_no. If this keyword is used in the case of the printout of a cham_elem, it is ignored, and the cham_elem is printed on all the mesh cells, specified elsewhere.

### 11.3 Operand GROUP_MA

This keyword makes it possible to indicate the list of the mesh-cell groups on which one wishes to print a cham_elem. For a cham_no, it makes it possible to indicate the list of the nodes, vertices of the mesh cells, at which one wishes to print the cham_no.

## 12 Selection on the values

It is also of interest to print only the extreme values of all or certain components, over all or part of the structure.

### 12.1 Operand VALE_MAX

This keyword indicates that one wishes to print the maximum value of each component of the field, possibly in a given interval specified by the arguments BORNE_SUP and/or BORNE_INF.

### 12.2 Operand VALE_MIN

This keyword indicates that one wishes to print the minimum value of each component of the field, possibly in a given interval specified by the arguments BORNE_SUP and/or BORNE_INF.

### 12.3 Operand BORNE_SUP

This keyword indicates the upper bound of the interval over which one wishes to print the field. One prints all the values of the field lower than this upper bound.

### 12.4 Operand BORNE_INF

This keyword indicates the lower bound of the interval over which one wishes to print the field. One prints the values of the field greater than this lower bound.

## 13 Printout of the coordinates: operand IMPR_COOR

This keyword makes it possible to specify whether one wishes to print the coordinates of a node when writing a cham_no in the 'RESULTAT' format.

Makes it possible to specify the write format of the real values in the 'RESULTAT' format.

> ◊    PARTIE    =    /    ‘REEL’,


Makes it possible to specify the print format of the complex numbers. If one specifies nothing, one will print the complex number. Otherwise one can print the real part (PARTIE='REEL'), the imaginary part (PARTIE='IMAG'), the modulus (PARTIE='MODULE') or the phase (PARTIE='PHASE').

## 16 Note concerning the fields with sub-points

In *Aster*, there exist cham_elem with sub-points (both for cham_elem at the nodes and for cham_elem at the Gauss points). In the 'RESULTAT' format, IMPR_RESU allows the printout of the cham_elem with sub-points.

If the same cham_elem has sub-points on certain mesh cells and not on others, the printout of the cham_elem will be done in two stages:

- first the printout of the cham_elem on all the mesh cells on which there are no sub-points,
- then the printout of the cham_elem on all the mesh cells on which there are sub-points.

A specific format is used for each of these printouts. The printout of the fields with sub-points is "basic": one systematically prints all the geometric entities, all the components and all the sub-points (one line per sub-point). The real numbers are always printed with 10 significant digits.

A trick for printing more significant digits for a field with sub-points consists in calling the command POST_CHAMP in order to extract the field on a particular sub-point and then in printing the new data structure with the keyword FORMAT_R.

## 17 Printout of the mesh: operands MAILLAGE / MODELE

This argument makes it possible to print the mesh with FORMAT='ASTER' or 'RESULTAT'. One then finds the format used for LIRE_MAILLAGE [U4.21.01](doc:u4.21.01) and defined in [U3.01.00](doc:u3.01.00).

By default, one prints the whole mesh.

The concept of type modele is optional in the majority of the printouts. However, it can be used in the case of the printout of a mesh in the 'ASTER' or 'RESULTAT' formats, in order to print only the part of the mesh whose mesh cells are assigned in the model.

If one chooses the 'ASTER' format, the mesh is written in a file of type .mail which can then be re-read by LIRE_MAILLAGE.

If one chooses the 'RESULTAT' format, the mesh is written, by default, in the .resu file and cannot be re-read by LIRE_MAILLAGE as it stands, because the .resu file also contains titles, subtitles and possibly other information.
