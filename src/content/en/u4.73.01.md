# u4.73.01 Operator PROJ_MESU_MODAL

## 1 Purpose

Extrapolate experimental measurements onto a numerical model in dynamics.

The experimental data may be displacements, velocities, accelerations, strains or stresses. They are defined as a function of time or of frequency, or in the form of a list.

The aim is to compute the generalised coordinates of the measurement relative to an expansion basis defined on the numerical model. This expansion basis (shapes, stresses or strains) is computed beforehand as a concept of type mode_meca. The basis vectors are then restricted to the measured degrees of freedom. The spatial association between the measurement points and the nodes of the numerical mesh can be carried out manually and/or automatically. The computation of the generalised coordinates is carried out by solving a least-squares minimisation problem, possibly regularised by the Tikhonov method.

Applicable to any type of model (1D, 2D and 3D).

Produces a data structure of type tran_gene, harm_gene or mode_gene.

## 2 Syntax

```text
/ mode_gene
/ tran_gene
/ harm_gene = PROJ_MESU_MODAL(
    ◆ MODELE_CALCUL = _F(
         ◆ MODELE = modele,
         ◆ BASE = mode_meca,
      ),
    ◆ MODELE_MESURE = _F(
         ◆ MODELE = modele,
         ◆ MESURE = mode_meca_c / dyna_trans / dyna_harmo / mode_meca,
         ◇ NOM_CHAM = / "DEPL" (par défaut),
                      / "VITE",
                      / "ACCE",
                      / "SIEF_NOEU",
                      / "EPSI_NOEU",
      ),
    ◇ CORR_MANU = _F(
         ◇ & NOEU_CALCUL = no,
           & NOEU_MESURE = no,
      ),
    ◇ NOM_PARA = text,
    ◇ RESOLUTION = _F(
         ◇ METHODE = / "LU" (par défaut),
                     / "SVD",
         # Si: equal_to("METHODE", 'SVD')
             ◇ EPS = float,
         ◇ REGUL = / "NON" (par défaut),
                   / "NORM_MIN",
                   / "TIK_RELA",
         # Si: not equal_to("REGUL", 'NON')
             ◇ / COEF_PONDER = float,
               / COEF_PONDER_F = formule / nappe / fonction,
      ),
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Factor keyword MODELE_CALCUL

This factor keyword groups the characteristics of the numerical model onto which one wants to extrapolate the measurement. It must appear only once.

#### 3.1.1 Operand MODELE

```text
♦    MODELE = mocalc
```

Name of the numerical model on which the expansion basis is built.

#### 3.1.2 Operand BASE

```text
♦    BASE = base
```

Name of the expansion basis. This basis is of type mode_meca. This concept has possibly been enriched, via the command CALC_CHAMP, by the modal strain and/or stress fields computed at the nodes.

### 3.2 Factor keyword MODELE_MESURE

This factor keyword groups the information on the measured (observed) field that one wishes to extrapolate onto the numerical model. It must appear only once.

#### 3.2.1 Operand MODELE

```text
♦    MODELE = mostru
```

Name of the model associated with the observation.

#### 3.2.2 Operand MESURE

```text
♦    MESURE = mesure
```

Name of the measured field.

This keyword determines the type of concept produced by the operator PROJ_MESU_MODAL. If mesure is of type dyna_trans, the concept produced is of type tran_gene. If mesure is of type dyna_harmo, the concept produced is of type harm_gene. If mesure is of type mode_meca, or mode_meca_c, the concept produced is of type mode_gene.

#### 3.2.3 Operand NOM_CHAM

```text
◊    NOM_CHAM =    | 'DEPL'                                    [DEFAUT]

| 'VITE'

| 'ACCE'

| 'SIEF_NOEU'

| 'EPSI_NOEU'
```

This keyword makes it possible to choose the field or fields to be read and extrapolated. The components of the field considered are those which have been measured (observed) and read in mesure. For the moment, one does not assign a weighting coefficient to the different components of the field: each component has the same weight during the inversion.

### 3.3 Operand NOM_PARA

```text
◊    NOM_PARA=    lpara
```

List of the symbolic names of the parameters of the measured data that one wishes to transmit to the generalised model.

### 3.4 Factor keyword CORR_MANU

This factor keyword allows the user to define (overload) manually the correspondence between the observation node and the analogous node of the numerical model. This factor keyword is optional, but it may appear as many times as necessary. On the other hand, the operands under this factor keyword go in pairs: a NOEU_MESURE must have its associated NOEU_CALCUL.

If this factor keyword is absent, the spatial association between the measurement points and the nodes of the numerical mesh is carried out automatically by using the shape function of the element of the numerical model in order to determine the value of the field at the measurement point.

#### 3.4.1 Operand NOEU_MESURE

```text
♦    NOEU_MESURE = no1
```

This keyword gives the name of the observation node that one wishes to associate with the node of the numerical model no2. In certain cases, the mesh file associated with the measurement is in universal format (Ideas format); one therefore cannot know a priori the Aster name associated with the node. It is therefore necessary, in this case, to read the mesh coming from PRE_IDEAS, by LIRE_MAILLAGE, in order to be able to assign the name of the node.

#### 3.4.2 Operand NOEU_CALCUL

```text
♦    NOEU_CALCUL = no2
```

This keyword gives the name of the node of the numerical model that one wishes to associate with the observation node no1.

### 3.5 Factor keyword RESOLUTION

One defines here the solution method to be used and the parameters associated with this method.

#### 3.5.1 Operand METHODE

```text
◊    METHODE =    / 'LU'
/ 'SVD'
```

One proposes the LU method (LU decomposition, Lower-Upper) and the SVD method (singular-value decomposition) for the computation of the inverse matrix. For the SVD method, the number of singular values to be taken into account depends on the value of eps that the user supplies under the operand EPS. By default, one adopts the LU method.

#### 3.5.2 Operand EPS

> This keyword is used if one chooses the SVD method.

```text
◊    EPS    =    / 0.
/ eps
```

This keyword gives the value from which a singular value is considered to be zero. It thus determines the number of singular values to be used during the solution. An eps equal to zero means that all the singular values are to be taken into account. An eps equal to 1 means that one considers only the largest singular value. By default, one chooses EPS = 0.

#### 3.5.3 Operand REGUL

```text
◊    REGUL    =    / 'NON'

/ 'NORME_MIN'
/ 'TIK_RELA'
```

REGUL makes it possible to specify the regularisation method that one wants to use. By default, one does not add any regularisation (no additional constraint on the solution: REGUL = 'NON').

Currently, two types of regularisation are available (minimum norm: REGUL = 'NORM_MIN' or Tikhonov of order 0, and “relative” Tikhonov: REGUL = 'TIK_RELA').

One seeks to minimise, for each order number of the measured field, the following functional with respect to $\eta$ :

${\mid {q}_{\exp}-{\bar{\Phi}}_{\mathrm{num}}\eta \mid }^{2}+{\alpha \mid \eta -{\eta}_{\mathrm{priori}}\mid }^{2}$

with:

- $\eta$ : generalised coordinates relative to the expansion basis ${\bar{\Phi}}_{\mathrm{num}}$ .
- ${q}_{\exp}$ : measured field along the observation degrees of freedom.
- ${\bar{\Phi}}_{\mathrm{num}}$ : expansion basis restricted to the observation degrees of freedom.
- $\alpha$ : weighting coefficients making it possible to specify the weight assigned to the a priori information on the solution.

Depending on the method used, the parameters of the previous functional are set out as follows:

Without regularisation: $\alpha =0$

Minimum norm (NORM_MIN): ${\eta}_{\mathrm{priori}}=0$

“Relative” Tikhonov (TIK_RELA): ${\eta}_{\mathrm{priori}}$ : solution found at the previous order number

It is not recommended to use this keyword when the measured field (mesure) is of type mode_meca.

#### 3.5.4 Operands COEF_PONDER and COEF_PONDER_F

This keyword corresponds to the weight assigned to the a priori information, $\alpha$ . It is used if one applies a regularisation to the solution $\eta$ .

```text
◊    /    COEF_PONDER        = coef
```

List of the weighting coefficients on the a priori solution (Tikhonov regularisation method) [bib3].

```text
/    COEF_PONDER_F    = coef_f
```

List of the weighting functions on the a priori solution (Tikhonov regularisation method). The variables of these functions are the same as those of the measured field (mesure). If the number of weighting coefficients or functions given is smaller than the number of basis vectors used in the expansion basis, the weighting coefficients or functions of the additional vectors are taken equal to the last coefficient or to the last function of the list.

## 4 Verification and execution phase

### 4.1 Computation of the expansion basis restricted to the measured degrees of freedom

First, the mesh of the measurement is projected onto the mesh of the numerical model. One then determines the participation of the nodes of the numerical model for each measurement node via the shape function of the element which contains the measurement node. The correspondence obtained between the nodes is supplied in the MESSAGE file of the Aster study.

The second processing consists in computing the component of the field (expansion basis) at the measurement node along the measured degrees of freedom.

### 4.2 Computation of the generalised coordinates

The solution of the minimisation equation is given by:

$\begin{array}{ccc}\eta (0)& =& {\left[{\bar{\Phi}}_{\mathrm{num}}^{T}{\bar{\Phi}}_{\mathrm{num}}\right]}^{-1}{\bar{\Phi}}_{\mathrm{num}}^{T}{q}_{\exp}(0)\\ \eta (i)& =& {\left[{\bar{\Phi}}_{\mathrm{num}}^{T}{\bar{\Phi}}_{\mathrm{num}}+\alpha (i)\right]}^{-1}({\bar{\Phi}}_{\mathrm{num}}^{T}{q}_{\exp}(i)+\alpha (i){\eta}_{\mathrm{priori}})\end{array}$

With:

- $\eta (i)$ : generalised coordinates for the order number i (ti or fi),
- ${q}_{\exp}(i)$ : measurement at the order number i,
- ${\bar{\Phi}}_{\mathrm{num}}$ : expansion basis restricted to the measurement degrees of freedom,
- $\alpha (i)$ : coefficients making it possible to specify the weight assigned to the a priori information at the order number i. These variables or functions are defined by the user in the operands COEF_PONDER or COEF_PONDER_F of the factor keyword RESOLUTION. They are introduced in the form of a list of reals or of functions and correspond, term by term, to each vector of the expansion basis retained.

Depending on the method used, the previous parameters are set out as follows:

Without regularisation: $\alpha =0$

Minimum norm (NORM_MIN): ${\eta}_{\mathrm{priori}}=0$

“Relative” Tikhonov (TIK_RELA): ${\eta}_{\mathrm{priori}}={\eta}_{i-1}$

**Note 1:**

*If a weighting coefficient is negative, the processing stops in fatal error.*

**Note 2:**

*If all the weighting coefficients are zero for a given order number and the number of measurements is strictly smaller than the number of basis vectors, an alarm message is issued in order to warn of the risk of a singular matrix (indeed, in this case, the solution is not unique).*

At the end of the analysis, the identified generalised coordinates are differentiated in order to compute the corresponding velocities and accelerations.

The result of the inversion is a concept of type tran_gene, harm_gene or mode_gene.

## 5 Example of use of PROJ_MESU_MODAL

For the examples of use, it is strongly recommended to refer to the test cases SDLD104 and SDLV122.

One presents in this paragraph the different steps for the expansion of the measurement onto the numerical model.

- Reading of the mesh made up of the measurement points:

The objective of this operation is to read the position of the measurement points in a file of mesh type. The format of this file must be readable by *Code_Aster* (GIBI format, universal (I-deas) format, or shortly MED). Mesh cells linking the measurement nodes may have been defined. They obviously have no physical meaning but will possibly make it possible to visualise the results during the post-processing phase.

In the majority of cases, the mesh comes from an experimental measurement code which supplies a file in universal format (I-deas format). To transform it into Aster format, one uses the operator PRE_IDEAS.

PRE_IDEAS(UNITE_IDEAS = 19, UNITE_MAILLAGE = 21,)

mailmesu = LIRE_MAILLAGE ( UNITE = 21,)

- Assignment of a mechanical model to the mesh:

The objective of this operation is to define the model of the support of the nodes of the mesh made up of the measurement points. Two cases may be envisaged: assignment of a modelling DIS_T (discrete in translation => 3 degrees of freedom per node: DX, DY and DZ) or assignment of a modelling DIS_TR (discrete in translation–rotation => 6 degrees of freedom per node: DX, DY, DZ, DRX, DRY and DRZ) in the case where rotation measurements are carried out.

```text
modlmesu = AFFE_MODELE    (    MAILLAGE    = mailmesu,
AFFE    = _F(    GROUP_NO    = 'noeumesu',
MODELISATION    = ‘DIS_T’,
PHENOMENE    = ‘MECANIQUE’,),

)
```

- Reading of the measurement:

The measurement can be read via the operator LIRE_RESU. This operator makes it possible to read a file in universal format (dataset 58). It recovers the component of the observed field and assigns it to the corresponding model.

```text
mesure = LIRE_RESU    (    FORMAT = 'IDEAS_DS58',

UNITE = 33,

MAILLAGE = mailmesu,

TYPE_RESU = 'DYNA_TRANS',

NOM_CHAM = 'SIEF_NOEU',)
```

- Definition of the expansion basis:

The expansion basis must be of type mode_meca. This concept may come from CALC_MODES or from DEFI_BASE_MODALE.

If one wants to extrapolate a strain or stress field, the basis must be enriched, via the command CALC_CHAMP, by the strain or stress fields computed at the nodes.

- Computation of the generalised coordinates:

The computation of the generalised coordinates relative to the expansion basis is carried out by the operator PROJ_MESU_MODAL.

```text
repgene = PROJ_MESU_MODAL    (

MODELE_CALCUL        =    _F(    MODELE = modlcalc,

BASE = base,),

MODELE_MESURE        =    _F(    MODELE = modlmesu,

MESURE = mesure,

NOM_CHAM = 'SIEF_NOEU',),

CORR_MANU            =    _F(    NOEU_MESURE = 'no1',

NOEU_CALCUL = 'no2',),

RESOLUTION        =    _F(    METHODE = 'SVD',

EPS = 1.E-4,),

)
```

- Expansion onto the numerical model:

This expansion consists in computing, on all the nodes of the numerical model, the field compatible with the field observed on the measured degrees of freedom. This expansion is carried out by the command REST_GENE_PHYS.

```text
reponse = REST_GENE_PHYS (    RESU_GENE = repgene,

TOUT_CHAM = 'OUI',)
```
