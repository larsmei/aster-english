# u4.23.01 Operator DEFI_MAILLAGE

## 1 Purpose

Define a mesh with the help of macro-elements.

This command makes it possible to define a new mesh from static or dynamic macro-elements. This new mesh (containing only the geometric supports of the macro-elements) can then be "assembled" with another mesh (containing for example "classical" mesh cells) thanks to the command ASSE_MAILLAGE [U4.23.03](doc:u4.23.03) and the option specific to substructuring.

Produces a data structure of type maillage.

## 2 Syntax

```text
super_mesh = DEFI_MAILLAGE(
    ◆ DEFI_SUPER_MAILLE = _F(
         ◆ MACR_ELEM = macr_elem_dyna / macr_elem_stat,
         ◇ SUPER_MAILLE = ma,
         ◇ TRAN = float,
         ◇ ANGL_NAUT = float,
         # Si: exists("ANGL_NAUT")
             ◇ CENTRE = float,
      ),
    ◇ RECO_GLOBAL = _F(
         ◆ / TOUT = "OUI" (ou non renseigné),
           / SUPER_MAILLE = ma,
         ◇ CRITERE = / "RELATIF" (par défaut),
                     / "ABSOLU",
         ◇ PRECISION = float (défaut: 0.001),
      ),
    ◇ RECO_SUPER_MAILLE = _F(
         ◆ SUPER_MAILLE = ma,
         ◆ GROUP_NO = grno,
         ◇ OPTION = / "GEOMETRIQUE" (par défaut),
                    / "NOEUD_A_NOEUD",
                    / "INVERSE",
         # Si: equal_to("OPTION", 'GEOMETRIQUE')
             ◇ CRITERE = / "RELATIF" (par défaut),
                         / "ABSOLU",
             ◇ PRECISION = float (défaut: 0.001),
      ),
     DEFI_NOEUD = _F(
        ◆ / TOUT = "OUI" (ou non renseigné),
          / NOEUD_INIT = no,
        # Si: exists("TOUT")
            ◇ PREFIXE = text,
            ◆ INDEX = int,
        # Si: exists("NOEUD_INIT")
            ◆ SUPER_MAILLE = ma,
            ◆ NOEUD_FIN = no,
     ),
    ◇ DEFI_GROUP_NO = _F(
         ◆ / TOUT = "OUI" (ou non renseigné),
           / SUPER_MAILLE = ma,
         ◇ & GROUP_NO_INIT = grno,
         ◆ | GROUP_NO_FIN = grno,
         ◇ PREFIXE = text,
           | INDEX = int,
      ),
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 General points

In the documentation of this command, one will speak of:

- macro-element: object of type macr_elem_stat or macr_elem_dyna,
- super mesh cell: geometric entity supporting a macro-element,
- **initial** mesh when one designates the mesh that was used to generate a macro-element,
- **final** mesh to designate the mesh produced by this command.

By extension these adjectives **initial/final** will apply to the entities attached to the meshes: node, mesh cell, node group.

In practice, to build the final mesh:

- one defines super mesh cells by positioning in space (2D or 3D) existing macro-elements (one and the same macro-element may generate several super mesh cells),
- one joins the super mesh cells to one another,
- one renames, if one wishes, certain nodes,
- one creates, if one wishes, certain node groups.

**Notes:**

*One can observe that the mesh created by this command is formed only of super mesh cells. One therefore cannot (for example) draw it with the usual post-processors. Possibilities of remedying this may exist with the command* *DEFI_SQUELETTE* [U4.24.01](doc:u4.24.01).

To mix "classical" finite elements and substructures, one must use the operator for "concatenation" of meshes [U4.23.03](doc:u4.23.03): *mag = ASSE_MAILLAGE ( MAILLAGE= (m1, m2))*

A mesh resulting from the operator DEFI_MAILLAGE contains:

- super mesh cells,
- nodes,
- node groups.

The super mesh cells are defined by translation/rotation of macro-elements.

Like a "classical" mesh cell, a super mesh cell is entirely defined by the list of its nodes. The coordinates of the nodes of the mesh cells are those of the external nodes of the macro-elements transformed by the geometric transformation: translation, rotation...

If one does not carry out any joining (cf. RECO_GLOBAL / RECO_SUPER_MAILLE), the mesh has as many nodes as the sum of the nodes of the super mesh cells.

**Convention C1:**

When one "joins" the super mesh cells, one eliminates certain nodes. By convention, when coincident nodes are eliminated, one keeps the node (and therefore its coordinates) that comes from the first mesh cell of the list l_mail (cf. RECO_GLOBAL / RECO_SUPER_MAILLE).

As in any *Aster* mesh, the nodes are **named**. By default, the names of the nodes are given by the program in the form: Nijk where ijk is a number between 1 and 999999.9.

The keyword DEFI_GROUP_NO allows the user to rename certain nodes and to define node groups.

## 4 Operands

### 4.1 Keyword DEFI_SUPER_MAILLE

```text
♦    DEFI_SUPER_MAILLE=
```

This factor keyword makes it possible to define the super mesh cells of the mesh with the help of the macro-elements.

#### 4.1.1 Operand MACR_ELEM

```text
♦    MACR_ELEM = l_se
```

l_se is the list of the names of the macro-elements that will generate the mesh cells.

#### 4.1.2 Operand SUPER_MAILLE

```text
◊    SUPER_MAILLE = l_mail
```

l_mail is the list of the names that one wishes to give to the mesh cells. This argument is optional. In its absence, the mesh cells will be given the names of the macro-elements (this is obviously impossible if one wishes to use the same macro-element several times).

#### 4.1.3 Operands for geometric transformations

```text
◊    |    ◊    TRAN=
```

This keyword defines the translation to apply to the macro-element:

- if one is in **2D**, one expects 2 reals: (tx, ty),
- if one is in **3D**, one expects 3 reals: (tx, ty, tz).

```text
|    ◊    ANGL_NAUT=
```

```text
◊    CENTRE=
```

These keywords define the rotation to apply to the macro-element.

If one is in **2D**, one expects 3 reals:

- a is the angle (in degrees) of rotation in the plane for ANGL_NAUT,
- px and py are the coordinates of the centre of rotation for CENTRE.

If one is in **3D**, one expects 6 reals:

- a, b, c are the nautical angles $(\alpha ,\beta ,\gamma )$ of the rotation (in degrees). (Cf. the operator AFFE_CARA_ELEM [U4.42.01](doc:u4.42.01)) for ANGL_NAUT,
- px, py and pz are the coordinates of the centre of rotation for CENTRE.

**Important note:**

*One knows that the order of the keywords is not significant for Aster. The translation/rotation operation is* **conventionally** *carried out in the order rotation* **then** *translation. These two operations do not commute in general.*

### 4.2 Keyword RECO_GLOBAL

```text
◊    |    RECO_GLOBAL=
♦    /    TOUT            = 'OUI' ,
/    SUPER_MAILLE= l_maille,
◊    |    CRITERE    =    /    'ABSOLU'    ,
/    'RELATIF'    ,                [DEFAUT]
|    PRECISION    =    /    prec,
/    1.D-3,                        [DEFAUT]
```

This keyword makes it possible to join **automatically** a set of super mesh cells (designated by the keyword SUPER_MAILLE or the keyword TOUT) with a criterion of geometric proximity: 2 nodes of 2 different super mesh cells m1 and m2 will be merged if the distance separating them is:

```text
<    prec                        (CRITERE = 'ABSOLU'),
<    prec*min(d(m1),d(m2))    (CRITERE = 'RELATIF').
```

where d(mi) denotes the smallest distance between 2 nodes of the super mesh cell mi.

**Notes:**

*Two nodes of one and the same mesh cell will never be joined.*

*If a mesh cell contains only a single node, one must use* *CRITERE='ABSOLU'.*

### 4.3 Keyword RECO_SUPER_MAILLE

```text
◊    RECO_SUPER_MAILLE =
```

This factor keyword makes it possible to join "**by hand**" certain super mesh cells designated by the user. The super mesh cells that one can join are those that have been defined by the keyword DEFI_SUPER_MAILLE. One then joins the super mesh cells via node groups. To say what one wishes to join one must therefore give pairs (mesh cell, node group (of the initial mesh)).

**Notes:**

*When one gives a pair (mesh cell,* *node group), one designates the list of the nodes of the node group that are external for the macro-element that defines the super mesh cell. It is in fact the intersection of the node group and of the boundary of the substructure. This list is ordered like the initial node group.*

*In principle, when one joins 2 mesh cells via 2 node groups, the set of the designated nodes must be joined (cf. the convention chosen by the keyword* *OPTION). An alarm message will be issued if this is not the case.*

#### 4.3.1 Operands SUPER_MAILLE/GROUP_NO

```text
◊    SUPER_MAILLE=
```

One gives here the list of the mesh cells to join. In general, one joins the mesh cells 2 by 2.

For the "corners", it may be convenient to join all the concurrent mesh cells in a single operation (for example the 4 super-cubes that share the same edge).

```text
◊    GROUP_NO=
```

One gives here the list of the node groups to join. This list is of the same length as the list of the mesh cells.

#### 4.3.2 Operand OPTION

```text
◊    OPTION=
```

This keyword makes it possible to choose the convention for joining the lists of nodes defined by the node groups.

- 'GEOMETRIQUE':

The program will make the nodes coincide by considerations of geometric proximity. (Cf. keyword: RECO_GLOBAL)

- 'NOEUD_A_NOEUD' / 'INVERSE':

![Figure](/figures/u4.23.01/Object_1.svg)

```text
Si OPTION = 'NOEUD_A_NOEUD'    ,    GROUP_NO = (G1, G2, G3)
```

![Figure](/figures/u4.23.01/Object_2.svg)

```text
Si OPTION = 'INVERSE'        ,    GROUP_NO = (G1, G2, G3)
```

![Figure](/figures/u4.23.01/Object_3.svg)

**Warning:**

*For the option* *'INVERSE', only the first node group of the list of* *GROUP_NO is "turned over".*

### 4.4 Keyword DEFI_GROUP_NO

```text
◊    DEFI_GROUP_NO=
```

This factor keyword makes it possible to define node groups from groups existing in the initial meshes of the macro-elements.

**Note:**

*An initial node group may contain nodes that do not belong to the boundaries of the macro-elements. These internal nodes therefore do not exist in the final mesh. For convenience, one adopts the convention of creating the group anyway, reduced to its intersection with the boundary of the macro-element.*

#### 4.4.1 Operands TOUT/SUPER_MAILLE/PREFIXE/INDEX

```text
|    ♦    /    TOUT        = 'OUI' ,
/    SUPER_MAILLE = mail,
◊    PREFIXE = pref,
♦    INDEX = (dm, fm, dn, fn),
```

These keywords make it possible to create all the node groups corresponding to the groups of the initial mesh associated with the mesh cell mail, or with all the mesh cells if:

TOUT= 'OUI'.

The renaming convention is the following (in pseudo FORTRAN):

gno_fin(k8) = pref//no_mail(dm:fm)//gno_ini(dn:fn)

Which means that the name of a node group will be formed by concatenating:

- the prefix possibly given by the user,
- a sub-string of characters extracted from the name of the mesh cell,
- a sub-string of characters extracted from the name of the group_no of the initial mesh.

It is therefore necessary that:

ltot = length(prefix) + (fm-dm+1) + (fn-dn+1) ≤ 8

A frequent case is the following: the meshes that gave rise to the macro-elements come from a pre-processor that generates names of the form GRNOijkl. If the user gives the super mesh cells names of 2 characters: SA, SB,...., the sequence:

```text
DEFI_GROUP_NO=_F(TOUT= 'OUI' , PREFIXE='GN' , INDEX=(1,2,5,8))
```

will generate node groups with the names:

```text
GNSA0001, GNSA0002,... , GNSB0001.
```

#### 4.4.2 Operands GROUP_NO_FIN/SUPER_MAILLE/GROUP_NO_INIT

```text
|    ♦    GROUP_NO_FIN =    gno_fin,
♦    SUPER_MAILLE =    mail,
♦    GROUP_NO_INIT=    gno_ini,
```

These keywords make it possible to create node groups **one by one**:

- gno_fin is the name that one wishes to give to the GROUP_NO,
- mail and gno_ini identify the initial GROUP_NO:
- mail is the name of the super mesh cell that carries the GROUP_NO,
- gno_ini is the name of the GROUP_NO of the initial mesh.

## 5 Example

Let the mesh be m1:

![Figure](/figures/u4.23.01/100000000000048D0000019D48E0300C78BC89B1.png)

```text
GROUP_NO :                                            GROUP_MA :
```

```text
AB = (N1 N2 N3)                                        grma1
BC = (N3 N4 N5)                                        grma2
CD = .....
......
```

On this mesh m1 one defines 2 macr_elem_stat.

```text
mo1 =    AFFE_MODELE        (    AFFE = _F (GROUP_MA = grma1)...)

mo2 =    AFFE_MODELE        (    AFFE = _F (GROUP_MA = grma2)...)

S1 =    MACR_ELEM_STAT    (    DEFINITION = _F    (MODELE = mo1...)
EXTERIEUR = _F    (GROUP_NO = (AB,BC,CD,DE,EA))
...)

S2 =    MACR_ELEM_STAT    (    DEFINITION = _F    (MODELE = mo2...)
EXTERIEUR = _F    (GROUP_NO = (BC,BG,FG,CF))
...)
```

One can then define the mesh m2:

![Figure](/figures/u4.23.01/10000A320000182F00000C81BE93398677387336.svg)

```text
m2 =    DEFI_MAILLAGE    (

DEFI_SUPER_MAILLE=(
_F(MACR_ELEM= S1)    ,
_F(MACR_ELEM= S2    ,    SUPER_MAILLE= S2,    ) ,

_F(MACR_ELEM= S2    ,    SUPER_MAILLE= S3,    TRAN= 3.),),

RECO_SUPER_MAILLE=(
_F(SUPER_MAILLE=(S1,S2),GROUP_NO=(BC,BC),OPTION='NOEUD_A_NOEUD'),
_F(SUPER_MAILLE=(S2,S3),GROUP_NO=(FG,BC),OPTION='INVERSE'),),

DEFI_GROUP_NO=

_F(GROUP_NO_FIN= FG, SUPER_MAILLE= S3,    GROUP_NO_INIT= FG), )
```

The mesh obtained contains:

- 3 super mesh cells    :    S1, S2, S3
- 26 nodes        :    A, S12, ..., S317
- 1 GROUP_NO    :    FG = (S315, S316, S317)

*The joining of the super mesh cells could have been done more simply by:*

*RECO_GLOBAL= _F (TOUT = 'OUI').*
