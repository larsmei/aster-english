# u4.32.21 Operator CALC_SPEC

## 1 Purpose

Build all or part of a cross-spectral or transfer matrix from functions or from a table of functions.

When the user chooses to enter a series of functions, these are used in full. When the user chooses to enter a table_fonction, the stored functions may be cut up, averaged and windowed, with a given overlap.

To clarify the point, suppose that the user has 2 functions $A$ and $B$ . If the user chooses to use the operator from functions, the definition of the cross-spectrum ${G}_{\mathrm{AB}}$ which will be calculated will necessarily be

${G}_{\mathrm{AB}}=\frac{1}{{N}_{A}}\mathrm{FFT}(A)\ast \mathrm{FFT}{(B)}^{\mathrm{H.}}$ .

Where ${N}_{A}$ is the number of points contained in the vector $A$ . If the user chooses to build a table_fonction with the functions $A$ and $B$ , it will be possible to extract $N$ sub-vectors ${A}_{1,}\mathrm{...},{A}_{N}$ from the vector $A$ (resp. ${B}_{1,}\dots ,{B}_{N}$ from the vector $B$ ), and to calculate an averaged cross-spectrum ${G}_{\mathrm{AB}}$ such that

${G}_{\mathrm{AB}}=\frac{1}{{N}_{A}}(\frac{1}{N}\sum_{k=1}^{N}\mathrm{FFT}({A}_{k})\ast \mathrm{FFT}{({B}_{k})}^{\mathrm{H.}})$ .

The functions read are of type sd_fonction.

The concept produced is of type interspectre.

It is possible to use this operator in a *Code_Aster* command file, but also interactively by means of the operator CALC_ESSAI (U4.90.01).

## 2 Syntax

```text
interspectre = CALC_SPEC(
    ◆ / TAB_ECHANT = _F(
           ◆ NOM_TAB = table,
           ◇ LONGUEUR_DUREE = float,
           ◇ LONGUEUR_POURCENT = float,
           ◇ LONGUEUR_NB_PTS = int,
           ◇ RECOUVREMENT_DUREE = float,
           ◇ RECOUVREMENT_POURCENT = float,
           ◇ RECOUVREMENT_NB_PTS = int,
        ),
      / ECHANT = _F(
           ◆ NUME_ORDRE_I = int,
           ◆ NUME_MES = int,
           ◆ FONCTION = fonction,
        ),
    ◆ / INTERSPE = _F(
           ◇ FENETRE = / "RECT" (par défaut),
                       / "HAMM",
                       / "HANN",
                       / "EXPO",
                       / "PART",
           # Si: FENETRE == 'EXPO' or FENETRE == 'PART'
               ◇ DEFI_FENE = float,
        ),
      / TRANSFERT = _F(
           ◇ ESTIM = / "H1" (par défaut),
                     / "H2",
                     / "CO",
           ◆ REFER = int,
           ◇ FENETRE = / "RECT" (par défaut),
                       / "HAMM",
                       / "HANN",
                       / "EXPO",
                       / "PART",
           # Si: FENETRE == 'EXPO' or FENETRE == 'PART'
               ◇ DEFI_FENE = float,
        ),
    ◇ TITRE = text,
    ◇ INFO = / 1 (par défaut),
             / 2,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Keywords

### 3.1 Keyword TAB_ECHANT

Defines the table_fonction of the time samples and the associated signal-processing parameters. It cannot be combined with the keyword ECHANT.

#### 3.1.1 Keyword NOM_TAB

Name of the table_fonction in which the samples are stored. Only one table_fonction name may be specified as input in order to carry out the calculations.

The functions stored in the table_fonction correspond to the results of measurements, real or simulated, which serve as the basis for the calculation of the spectral-density matrix. All the functions stored in the table_fonction must be defined with the same sampling frequency.

NB: the table_fonction must associate an order number and a measurement number with each function (see sections 3.2.2 and 3.2.3 for the meaning of these parameters)

#### 3.1.2 Keywords LONGUEUR_DUREE / LONGUEUR_POURCENT / LONGUEUR_NB_PTS

Defines the length of the sub-samples which will be retained for the signal processing. If the keyword is not supplied, the length of the smallest available sample is assigned by default. If the specified length is shorter than the length of the smallest sample, the total sample is cut into as many lengths as the specified length. This length may be specified in three different ways:

- LONGUEUR_DUREE: one defines the length of the samples by their duration, expressed in the same unit as that used for the vector defining the time instants.
- LONGUEUR_POURCENT: one defines the length of the samples as a percentage of the total length.
- LONGUEUR_NB_PTS: one defines the length of the samples from the number of points which one wishes to retain.

#### 3.1.3 Keyword RECOUVREMENT_DUREE / RECOUVREMENT_POURCENT / RECOUVREMENT_NB_PTS

Defines the overlap length between two sub-samples which will be retained for the signal processing. If the keyword is not supplied, there is no overlap; the initial sample corresponds to the juxtaposition of the sub-samples. This length may be specified in three different ways:

- RECOUVREMENT_DUREE: one defines the length of the samples by their duration, expressed in the same unit as that used for the vector defining the time instants.
- RECOUVREMENT_POURCENT: one defines the length of the samples as a percentage of the total length.
- RECOUVREMENT_NB_PTS: one defines the length of the samples from the number of points which one wishes to retain.

The figure illustrates the cutting and the windowing of an initial sample into windowed sub-samples.

### 3.2 Keyword ECHANT

Factor keyword in which the functions used for the signal processing are defined. It cannot be used together with the keyword TAB_ECH.

#### 3.2.1 Keyword FONCTION

Name of the function containing the time sample.

#### 3.2.2 Keyword NUME_ORDRE_I

Defines the order number of the time sample (for example, a sensor number, a measurement-channel number, or a point on a mesh). This mandatory keyword is used to locate the cross-spectra or the transfers in the resulting interspectre concept.

#### 3.2.3 Keyword NUME_MES

Defines the measurement number of the sample. This mandatory keyword is used to identify the measurements which would be carried out simultaneously, or with the same phase reference, so that averaging of the spectra is valid. If two samples have the same measurement number, this means that they were acquired simultaneously. It is then possible to compute cross-spectra and transfer functions of one with respect to the other. Otherwise, this is impossible, because of the absence of a phase reference between the two signals.

### 3.3 Keyword INTERSPEC

Calculates the spectral-density (or cross-spectral) matrix from the time samples supplied.

#### 3.3.1 Keyword FENETRE

Defines the type of window to be applied to the time sample. The size of the window is adapted to the length of the sample or of the sub-samples, depending on the case treated. Keyword to be chosen from among:

- RECT: defines a rectangular window on the sample.
- HAMM: defines a Hamming window.
- HANN: defines a Hanning window.
- EXPO: defines a decreasing exponential window. The keyword DEFI_FENE must then be supplied.
- PART: allows the user to define a window from a list of reals given in the keyword DEFI_FENE. The list must be of the same length as the samples or sub-samples considered.

#### 3.3.2 Keyword DEFI_FENE

Allows the user to supply the necessary information when the keyword FENETRE takes the values ‘EXPO’ or ‘PART’.

- ‘EXPO’: the list consists of exactly two values. The first corresponds to the number of points for which the window takes the value 1. The second corresponds to the slope of the exponential at the origin. These two quantities are illustrated in the figure.
- ‘PART’: the window is defined by a list of reals entered by the user.

![Figure](/figures/u4.32.21/10000200000001D00000015C49B540817D712AA6.png)

**Figure** 3.3.2-1 **: Definition of the parameters of DEFI_FENE: width (in number of points) of the initial plateau, and slope at the origin of the exponential.**

### 3.4 Keyword TRANSFERT

Calculates the transfer functions from the time samples supplied.

#### 3.4.1 Keyword ESTIM

Defines the estimator to be used for the calculation of the transfer functions. To be chosen from among:

- H1: uses the estimator $\mathrm{H1}$
- H2: uses the estimator $\mathrm{H2}$ .
- CO: calculates the coherence between the estimators $\mathrm{H1}$ and $\mathrm{H2}$ .

For the record, if one has two signals $A$ and $B$ , the estimator $\mathrm{H1}$ of the transfer function $A/B$ is defined by:

$\mathrm{H1}(A/B)={G}_{\mathrm{AB}}/{G}_{\mathrm{BB}}$ ,

And the estimator $\mathrm{H2}$ by:

$\mathrm{H2}(A/B)={G}_{\mathrm{AA}}/{G}_{\mathrm{AB}}$ ,

Where ${G}_{\mathrm{AB}}$ is the cross-spectrum between the signals $A$ and $B$ . The coherence is defined by:

$\mathrm{CO}(A/B)=\mid \mathrm{H1}/\mathrm{H2}\mid$ .

The estimator $\mathrm{H1}$ minimises the influence of noise on the measured outputs, and $\mathrm{H2}$ minimises the influence of the noise liable to appear on the measurements of the inputs.

#### 3.4.2 Keyword REFER

List of integers which define the reference measurements for the calculation of the transfers. The integers used correspond to the order numbers of the time samples.

#### 3.4.3 Keyword FENETRE

Defines the type of window to be applied to the time sample. See section 3.3.1.

#### 3.4.4 Keyword DEFI_FENE

Allows the user to supply the necessary information when the keyword FENETRE takes the values ‘EXPO’ or ‘PART’. See section 3.3.2.

### 3.5 Keyword TITRE

Defines the title associated with the interspectre data structure in which the results are stored.

## 4 Examples

These examples are taken from the test case zzzz241a.

### 4.1 Calculation of a cross-spectral matrix from a table_fonction

The time responses may be stored in the form of lists in a separate file, or built on the basis of an analysis. Suppose here that four responses are available, with the respective names REP_1, REP_2, REP_3 and REP_4. Suppose that all these measurements were carried out simultaneously. Otherwise, a measurement number would have to be defined for each batch of simultaneous acquisitions.

# These four responses are first stored in a table_fonction:

tab_rep=CREA_TABLE(LISTE=(_F(PARA='NOM_CHAM',LISTE_K='Rep_Temp',),

# One defines the various measurement numbers,

# associated with sensors, or with particular degrees of freedom

> _F(PARA='NUME_ORDRE_I',LISTE_I=(1,2,3,4),),

# One defines the measurement numbers. Here, the 4 measurements are simultaneous,

# they therefore have the same number:

> _F(PARA='NUME_MES',LISTE_I=(1,1,1,1),),

# One defines the functions from the time samples.

> _F(PARA='FONCTION',

> LISTE_K=('REP_1','REP_2','REP_3','REP_4'),),
> ),

> TITRE='',

> TYPE_TABLE='table_fonction',

> )

# One then chooses to calculate the cross-spectral matrix by

# cutting each sample into sub-samples 1201 points

# long, with an overlap of 6 seconds, each weighted by

# a Hanning window

SPEC=CALC_SPEC(TAB_ECHANT=_F(NOM_TAB=tab_rep,

> LONGUEUR_NB_PTS=1201,
> RECOUVREMENT_DUREE=6,),
> INTERSPE=(_F(FENETRE='HANN',),),

> )

### 4.2 Calculation of transfer functions from functions

The time responses may be stored in the form of lists in a separate file, or built on the basis of an analysis. Suppose here that two measurements carried out at different time instants are available. On the one hand, an excitation signal EXC_1 and a response REP_1 are acquired simultaneously. This may be the response to an impact, or to an excitation by a shaking table. On the other hand, an excitation signal EXC_2 and the associated response REP_2 are also acquired simultaneously. In both cases, the excitation signal was applied at the same point. The responses are measured at two different locations. The excitation point has order number 1, the point associated with the first measurement has number 2, and the point associated with the second measurement has number 3. The calculation of the transfer functions 2/1 and 3/1 is carried out as follows:

# Calculation of the transfer from the impulse response:

FRF1_IMP=CALC_SPEC(ECHANT=(

# Definition of the various time samples

> _F(NUME_ORDRE_I = 1,

> NUME_MES=1,
> FONCTION=REP_1,),

> _F(NUME_ORDRE_I = 2,

> NUME_MES=1,
> FONCTION=REP_1,),

> _F(NUME_ORDRE_I = 1,

> NUME_MES=2,
> FONCTION=EXC_2,),

> _F(NUME_ORDRE_I = 3,

> NUME_MES=2,
> FONCTION=REP_2,),
> ),

# Definition of the parameters for the calculation of the transfers:

# Choice of the estimator:

> TRANSFERT=(_F(ESTIM='H1',

# Choice of the window to be applied:

> FENETRE='EXPO',

# Complementary definition of the window:

> DEFI_FENE=(10,-0.02),

# Definition of the order numbers associated with the reference points:

> REFER=1,),

> ),

> )

By using the functions directly, rather than going through data setup in a table_fonction, the user does not have access to the possibilities of averaging over the length of the signal. In order to do so, either the user defines the sub-functions, keeping this same input formalism, or the user fills a table_fonction and uses the formalism presented in section 4.1.
