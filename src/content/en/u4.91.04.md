# u4.91.04 Procedure IMPR_CONCEPT

## 1 Purpose

Print, in a form that can be visualised, "data" fields from concepts assigned by the user with the commands AFFE_MATERIAU, AFFE_CARA_ELEM and AFFE_CHAR_MECA.

## 2 Syntax

```text
IMPR_CONCEPT(
    ◇ FORMAT = / "MED" (par défaut),
               / "RESULTAT",
    ◇ UNITE = unit (défaut: 80),
    # Si: equal_to("FORMAT", 'MED')
        ◇ VERSION_MED = / "3.3.1" (par défaut),
                        / "4.0.0",
                        / "4.1.0",
    ◆ CONCEPT = _F(
         ◆ / CHAM_MATER = cham_mater,
           / CARA_ELEM = cara_elem,
           / CHARGE = char_meca,
         # Si: exists("CARA_ELEM")
             ◇ REPERE_LOCAL = / "NON" (par défaut),
                              / "ELEM",
                              / "ELNO",
             # Si: not equal_to("REPERE_LOCAL", 'NON')
                 ◆ MODELE = modele,
      ),
    ◇ INFO = / 1 (par défaut),
             / 2,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Typography in the IMPR_CONCEPT documentation

The procedure IMPR_CONCEPT makes it possible to print, in a form that can be visualised, the quantities assigned by the user with the commands AFFE_MATERIAU, AFFE_CARA_ELEM and AFFE_CHAR_MECA.

This makes it possible to check that the overloading rules of the code lead to the desired assignments.

For example:

IMPR_CONCEPT( FORMAT=’MED’,

CONCEPT=(

_F(CHAM_MATER = CHAMPMAT),

_F(CARA_ELEM = CARA_ELE),

_F(CHARGE = CHARG1),),

)

The fields contained in these data structures are printed in two very different forms:

- Form "A" (the easiest to interpret graphically): each component is printed separately as a real number. For example, the thickness of the shell elements can be visualised as a scalar field (scalar map in Salomé).
- Form "B": one assigns to each mesh cell an integer code: 1, 2, 3, ... n. The mesh cells assigned the same code then have ALL their components identical. The "definition" of the codes, that is to say the values of these components, is printed in the message file. One can visualise the "codes" as a scalar field, which makes it possible to "see" the zones where "everything is constant".

Form "A" is used systematically for the "MED" format, except for the material field because this field contains the name of the material assigned on the mesh cells and this name is not a number.

Form "A" is not programmed in the "RESULTAT" format.

Form "B" is used systematically for the "RESULTAT" format and for the material field.

For form "B", the correspondence between the assigned quantities and the code is given in the .mess file.

For example, for the material field:

IMPRESSION D’UN CHAMP DE CONCEPT: Champ de MATERIAUX

NOM DU CHAMP: CHAMPMAT_CHAMP_MAT

CORRESPONDANCE VALEUR <-> CONTENU:

VALEUR = 1.

X1 = MAT_1

VALEUR = 2.

X1 = MAT_2

VALEUR = 3.

X1 = MAT_3

## 4 Operands FORMAT and UNITE and INFO

### 4.1 Operand FORMAT

The operand FORMAT makes it possible to specify the format of the file in which to write the result.

Two formats 'MED' and 'RESULTAT' are available. The 'MED' format is the default write format.

### 4.2 Operand UNITE

Defines the unit in which one writes the med file. By default, UNITE = 80 and corresponds to the default unit of type rmed in astk.

### 4.3 Operand INFO

The keyword INFO, when it is equal to 2, makes it possible to obtain information on the printouts carried out by the command.

### 4.4 Operand VERSION_MED

```text
◊    VERSION_MED    =    /’3.3.1’,                                [DEFAUT]
/’4.0.0’,
/’4.1.0’,
```

When a new file is created in med format, the printout is made in med format 3.3.1. If the file already exists, the med format level is retained.

One can change the MED file version with the keyword VERSION_MED.

## 5 Factor keyword CONCEPT

### 5.1 Operand REPERE_LOCAL

If REPERE_LOCAL has the value 'ELEM' or 'ELNO', the keyword MODELE is mandatory.

If REPERE_LOCAL has the value 'ELEM', the 3 vectors constituting the local frame of each element are printed, so that they can be visualised with the aid of ParaVis.

If REPERE_LOCAL has the value 'ELNO', the 3 vectors constituting the local frame of each element are stored in the form of a field at the nodes, so that they can then be used in the ParaVis calculator in combination with other fields at the nodes. In this case no other information coming from the concept CARA_ELEM is stored in the file.

When REPERE_LOCAL='ELNO' it is therefore possible to combine the local vectors with the components of the internal-force fields. This makes it possible to visualise the force vectors in 3D, and also to produce an animation of their evolution over the time instants of the analysis. To carry out this action several elementary operations are to be performed in ParaVis:

- Open the MED file containing the frames:

on the REPE-> Filter "ELNO Points"-> Filter "Merge blocs"

- Open the MED file containing the fields:

on the EFGE_ELNO-> Filter "ELNO Points"-> Filter "Merge blocs"

- selection of the 2 "Merge blocs" then "Append Attributes"

In "Calculator" one has access to the REPE vectors and to the field components.

The computation of the force vector (N, Vy, Vz) is done in the following way:

$\begin{array}{c}\mathit{Fint}=\\ \\ \end{array}\begin{array}{c}\text{CAREL\_\_\_.REPLC\_1}\ast \text{xxxxxxxxEFGE\_ELNO\_N +}\\ \text{CAREL\_\_\_.REPLC\_2}\ast \text{xxxxxxxxEFGE\_ELNO\_VY +}\\ \text{CAREL\_\_\_.REPLC\_3}\ast \text{xxxxxxxxEFGE\_ELNO\_VZ}\end{array}$

where 'xxxxxxxx' denotes the name of the result concept, produced by *Code_Aster*.

The computation of the Moment vector (Mt, My, Mz) is done in the following way:

$\begin{array}{c}\mathit{Mint}=\\ \\ \end{array}\begin{array}{c}\text{CAREL\_\_\_.REPLC\_1}\ast \text{xxxxxxxxEFGE\_ELNO\_MT +}\\ \text{CAREL\_\_\_.REPLC\_2}\ast \text{xxxxxxxxEFGE\_ELNO\_MFY +}\\ \text{CAREL\_\_\_.REPLC\_3}\ast \text{xxxxxxxxEFGE\_ELNO\_MFZ}\end{array}$

where 'xxxxxxxx' denotes the name of the result concept, produced by *Code_Aster*.
