# u4.23.03 Operator ASSE_MAILLAGE

## 1 Purpose

Assemble two meshes to form a new one.

The two meshes to be assembled may come from the operators: LIRE_MAILLAGE [U4.21.01](doc:u4.21.01), DEFI_MAILLAGE [U4.23.01](doc:u4.23.01), ASSE_MAILLAGE [U4.23.03](doc:u4.23.03), ...

That is to say that they may contain ordinary mesh cells or super mesh cells carrying macro-elements.

Produces a data structure of type maillage.

## 2 Syntax

```text
/ super_mesh
/ maillage = ASSE_MAILLAGE(
    ◆ MAILLAGE_1 = maillage,
    ◆ MAILLAGE_2 = maillage,
    ◆ OPERATION = / "SOUS_STR",
                  / "SUPERPOSE",
                  / "COLLAGE",
    # Si: equal_to("OPERATION", 'COLLAGE')
        ◆ COLLAGE = _F(
             ◆ GROUP_MA_1 = grma,
             ◆ GROUP_MA_2 = grma,
          ),
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands MAILLAGE_1 and MAILLAGE_2

```text
♦    MAILLAGE_1 = ma1, MAILLAGE_2 = ma2,
```

ma1 and ma2 are the names of the two meshes to be assembled.

## 4 Operand OPERATION = 'SUPERPOSE'

With the choice 'SUPERPOSE', all the entities (mesh cells, nodes, mesh-cell groups and node groups) of the two meshes are retained. The only problem to be settled concerns the name of these entities (a name conflict is possible because the two meshes may contain, for example, nodes of the same name).

To resolve these possible name problems:

1. The nodes and the mesh cells are always renamed. This means that the user cannot know the name of the nodes and mesh cells of the result mesh. In general the user will have to use (which is always recommended) the names of mesh-cell groups and node groups. Or else the user will have to print the mesh in order to know the names that were chosen.
2. The names of the node groups and of the mesh-cell groups are retained as far as possible. If two mesh-cell groups (or two node groups) have the same name in the two meshes, the group coming from the 2nd mesh is renamed automatically and the name change is indicated in the message file.

## 5 Operand OPERATION = 'COLLAGE'

The operation 'COLLAGE' is used to connect two meshes which would have been meshed independently in two distinct files (for example by two different teams).

If the two meshes are not consistent on their interface (different discretisation), the user will have no choice other than to use the functionality AFFE_CHAR_* /LIAISON_MAIL in order to link the degrees of freedom of the two meshes, which will remain topologically disjoint. The user must then use the operation 'SUPERPOSE'.

If, on the other hand, the two meshes have been designed to be joined back together, the user will use the operation 'COLLAGE'. For that, the user will have had to take the precaution of naming the two mesh-cell groups (of the interface) which will make it possible to join the two meshes. Moreover these two mesh-cell groups must be geometrically coincident. The user will then write:

```text
OPERATION='COLLAGE', COLLAGE= _F(GROUP_MA_1='gma1', GROUP_MA_2='gma2',),
```

The mesh-cell groups gma1 and gma2 will then be merged. More precisely:

1. the mesh cells of gma1 and gma2 will be deleted,
2. the nodes of gma2 will remain (but will be orphans),
3. the nodes of gma1 will connect the two meshes.

Before merging the two mesh-cell groups gma1 and gma2, the code will check that the nodes of these two mesh-cell groups are indeed coincident (with a tolerance of $0,001$ times the length of the shortest edge of the two meshes).

The name conflicts of the entities of the two meshes are settled in the same way as for the operation 'SUPERPOSE' (see above).

## 6 Operand OPERATION = 'SOUS_STR'

In order to mix ordinary finite elements and macro-elements (or substructures) in one and the same model, one must have a mesh containing both ordinary mesh cells and super mesh cells. The operator ASSE_MAILLAGE / OPERATION = 'SOUS_STR' makes it possible to constitute this "mixed" mesh by assembling an ordinary (or mixed) mesh and a mesh containing super mesh cells (coming from DEFI_MAILLAGE).

This procedure uses the names of the nodes and of the mesh cells of the meshes; it is therefore applicable **only for meshes in the** **"ASTER" format.**

The meaning of the assembly is as follows:

- **All**  the entities of the two argument meshes ma1 and ma2 (mesh cells, super mesh cells, nodes, mesh-cell group and node group) are copied into the result mesh: mac.
- The only shared entities are the **nodes**  of **the same names**. It is these nodes which make it possible to assemble the two meshes.
- Treatment of the entities bearing the same name:
- nodes: the nodes of the second mesh bearing a name which exists in the first mesh are not added: it is assumed that they are the same. The coordinates of the retained node are those of the node of the first mesh. An alarm is emitted when the distance between the two coincident nodes is greater than:

${10}^{-6}.\text{d\_refe}$

where $\text{d\_refe}$ is a characteristic length of the mesh:

$\text{d\_refe}=\max(d(O,N))$

where $d(O,N)$ is the distance of the node $N$ from the origin of the global frame.

- mesh cells (or super mesh cells): if the mesh ma2 contains mesh cells of the same name as mesh cells of the first mesh ma1, the code stops in fatal error.
- mesh-cell group (or node groups): if the mesh ma2 contains a mesh-cell group of the same name as a mesh-cell group of ma1, the latter is ignored and the code emits an alarm message.
