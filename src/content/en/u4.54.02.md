# u4.54.02 Operator THER_NON_LINE

## 1 Purpose

Compute the thermal response with non-linearities of constitutive behaviour and of boundary conditions.

The heat equation is solved in the evolutionary regime (unless no list of time instants is supplied, in which case only the steady regime is computed). The non-linearities come either from the constitutive behaviour (material characteristics depending on the temperature), or from the boundary conditions (radiation in an infinite medium, non-linear flux, thermal source depending on the temperature). An enthalpy formulation has been chosen in order to take phase changes of the material into account more easily.

The evolutionary analysis can be initialised, at the first time instant, in three different ways (factor keyword ETAT_INIT):

- by a constant temperature,
- by a temperature field, defined beforehand, or extracted from a previous analysis,
- by a steady analysis.

In order to model the hydration of concrete, the operator also makes it possible to add to the heat equation a source term which is a function of the hydration variable. This term is then given by an evolution equation in which the temperature appears.

The concept produced by the operator THER_NON_LINE is of type evol_ther, as for a linear analysis by [THER_LINEAIRE](doc:u4.54.01).

## 3 General parameters

```text
◆ MODELE = modele,
◆ CHAM_MATER = cham_mater,
◇ CARA_ELEM = cara_elem,
◇ INFO = / 1,
        / 2,
◇ TITRE = text,
```

The general parameters describe the model, the material field and the elementary
characteristics (in particular for structural elements).

MODELE is the name of the model whose elements are the subject of the thermal analysis. The data structure comes from the command [AFFE_MODELE](doc:u4.41.01). It is always mandatory.

Linear thermal problems can be treated with models using 3D, 2D or AXIS finite elements.

CHAM_MATER is the name of the material field assigned to the model. The data structure comes from the command [AFFE_MATERIAU](doc:u4.43.01). All the main mesh cells of the
model must be associated with a material.

CARA_ELEM is necessary only in the case of a non-linear thermal solution with an orthotropic material (THER_NL_ORTH). It then makes it possible to transmit to the solution operator the definition of the local axes of the orthotropy reference frame in the 2D or 3D medium (command [AFFE_CARA_ELEM](doc:u4.42.01), keyword MASSIF).

### 3.1 Title

The keyword TITRE makes it possible to give a title which one wants to give to the result stored in temper, a data structure of type evol_ther [U4.03.01](doc:u4.03.01).

### 3.2 Management of verbosity

The keyword INFO makes it possible to produce various intermediate printouts in the message file.

## 4 Application of the loadings and of the boundary conditions

The factor keyword EXCIT makes it possible to define several loadings or boundary conditions. For each occurrence of the factor keyword, one defines CHARGE, possibly multiplied by a time function FONC_MULT.

The keyword CHARGE is a concept of type charge produced by [AFFE_CHAR_THER](doc:u4.44.02).
As for mechanics, it is also possible to define a load of the type “imposed degree of freedom”, here the temperature, by [AFFE_CHAR_CINE](doc:u4.44.03).

**Note:**

For each occurrence of the factor keyword EXCIT the various char concepts used must be built on the same model.

The keyword FONC_MULT is a multiplicative coefficient which is a function of time (concept of type fonction, nappe or formule) applied to the load.

**Note:**

The concomitant use of FONC_MULT with a load containing temperature-dependent thermal loadings (that is, for loadings of type ECHANGE, ECHANGE_PAROI, RAYONNEMENT, SOUR_NL or FLUNL) is forbidden.

## 5 Parametrisation of the analysis

### 5.1 Keyword TYPE_CALCUL

The analysis is transient if TYPE_CALCUL = TRAN or steady if TYPE_CALCUL=’STAT’. In the case of a transient analysis, the computation of the initial state must be specified in ETAT_INIT.

### 5.2 Keyword INCREMENT

The keyword INCREMENT makes it possible to define the analysis time instants which determine the time intervals taken in order to integrate the differential equation.

The operands of the keyword INCREMENT have the same meaning as in the operator [STAT_NON_LINE](doc:u4.51.03).

**Note:**

The list of time instants must contain at least two time instants, otherwise an error message appears. Nevertheless this requirement disappears when one performs a steady analysis (keyword STATIONNAIRE in ETAT_INIT). In this case the analysis result will contain only the initial time instant, computed under the stationarity assumption.

### 5.3 Keyword SCHEMA_TEMPS

This keyword is available only in the case of a transient analysis (TYPE_CALCUL = ’TRAN’).

The argument theta is the parameter $theta$ of the theta-method applied to the transient problem. It must lie between 0 (explicit method) and 1 (fully implicit method). In the absence of the keyword, the value used is $\theta =0.57$, slightly greater than $\theta =0.5$ corresponding to the Crank-Nicholson scheme. The effect of the choice of theta on the stability of the method is detailed in [R5.02.02](doc:r5.02.02).

## 6 Settings of the non-linear solvers

```text
◇ METHODE =/ "MODELE_REDUIT",
            / "NEWTON" (par défaut),
            / "NEWTON_KRYLOV",
            / "RASPEN",
```

The keyword METHODE makes it possible to choose the method for solving the non-linear incremental problem.

### 6.1 Newton methods

With METHODE='NEWTON', one uses the Newton-Raphson algorithm to solve the problem (see [R5.03.01](doc:r5.03.01)).

### 6.2 Reduced model

With METHODE='MODELE_REDUIT', one uses a model-reduction method to perform the non-linear analysis (see [R5.01.05](doc:r5.01.05)). It is necessary to have built a reduced basis beforehand (command [DEFI_BASE_REDUITE](doc:u4.67.01)).

The keywords MATRICE, PREDICTION, REAC_ITER and REAC_INCR have the same meaning and the same use as in the factor keyword NEWTON.

It is necessary to supply an empirical basis in the keyword BASE_PRIMAL built on the temperatures (by means of the operator [DEFI_BASE_REDUITE](doc:u4.67.01)). This basis must have been built on the same model and the same mesh as the THER_NON_LINE analysis.

Model reduction is not compatible with the following features:

- The line search;
- Dualised boundary conditions ([AFFE_CHAR_THER](doc:u4.44.02); one must use [AFFE_CHAR_CINE](doc:u4.44.03)).

It is possible to activate hyper-reduction, which uses a method of DEIM type, with DOMAINE_REDUIT = 'OUI'. In this case, the analysis is reduced to a restricted zone of the mesh (called the RID) and built with the help of the operator [DEFI_DOMAINE_REDUIT](doc:u4.67.02). One must give the node group on which the interface is defined, by means of the keyword GROUP_NO_INTERF.

### 6.3 Method `RASPEN`

The method `RASPEN` is based on a non-linear domain-decomposition method. It can be used only in the HPC context. It relies on 2 levels of non-linear solvers:

- a local level, where a non-linear problem is solved on each subdomain, without communication with its neighbours and therefore in a parallel and asynchronous manner;
- a global level, which exploits the previous local solutions in order to facilitate the solution of the problem under consideration.

As for the method `SNES`, the parameters are set by a list of options transmitted in the form of character strings by the keyword OPTION_PETSC of the factor keyword SOLVEUR. The options which concern the local solver are prefixed by `lsnes_`, whereas the options which concern the global solver are prefixed by `gsnes_`.
One can conveniently define these options as follows:

```python
myOptions = (
    # local snes
    "-prefix_push lsnes_ "
    + "-snes_monitor -snes_linesearch_type basic -snes_rtol 1.e-8 -snes_atol 1.e-50 -snes_max_it 5  "
    + "-ksp_type preonly  -pc_type lu -pc_factor_mat_solver_type mumps "
    + "-prefix_pop "
    # global snes
    + "-prefix_push gsnes_  "
    + "-snes_linesearch_type basic -ksp_monitor -ksp_rtol 1.e-7 -ksp_atol 1.e-50  -snes_max_it 20  "
    + "-prefix_pop "
)
```

The first line expresses the fact that one is going to set the parameters of the non-linear solver local to each subdomain, called "lsnes" ("l" for local, "snes" for Scalable Nonlinear Equations Solvers).
Next, one expresses that one wants to monitor the local non-linear solver, which by default is the Newton method; one specifies that the line search is not used (basic means that one uses a step of 1.) and one gives the relative and absolute convergence criteria as well as the maximum number of iterations.
Next one expresses that one wishes to use the MUMPS solver to solve the linearised problems.
One then does the same for the global non-linear solver, called "gsnes".

For any further detail, the reader is referred to [bib2]_.
Its use is reserved for advanced users.

## 7 Convergence settings

### 7.1 Convergence criterion

The factor keyword CONVERGENCE makes it possible to control the convergence parameters of the analysis, either with RESI_GLOB_RELA or with RESi_GLOB_MAXI.

**Note:**

If neither of the two following operands is present, then everything proceeds as if RESI_GLOB_RELA = 1.E-6

For RESI_GLOB_MAXI= $\varepsilon_{max}$, the algorithm continues the global iterations as long as

where ${F}^{n}$ is the residual of iteration ${n}$ (cf. [R5.03.01](doc:r5.03.01) for
more details). If this operand is absent, the test is not carried out.

For RESI_GLOB_RELA= $\varepsilon_{rel}$, the algorithm continues the global iterations as long as

$$
\underset{i=1, \dots , \mathrm{nbddl}}{\max} {F}^{n}
>
\varepsilon_{rel} . {\max} L
$$

where $L$ is the vector of the imposed loading.

### 7.2 Management of the iterations

The keyword ITER_GLOB_MAXI gives the maximum number of iterations carried out in order to solve the
global problem at each time instant. An excessive increase of this parameter
is generally the sign of a problem in the modelling or of an inadequate time discretisation.

### 8.1 Definition of an initial state

```text
◆ ETAT_INIT = _F(
        ◆ / STAT = "OUI" (ou non renseigné),

        # Si: exists("EVOL_THER")
            ◇ NUME_ORDRE = int,
            ◇ INST = float,
            # Si: exists("INST")
                ◇ CRITERE = / "ABSOLU",
                            / "RELATIF" (par défaut),
                # Si: (equal_to("CRITERE", 'RELATIF'))
                    ◇ PRECISION = float (défaut: 1e-06),
                # Si: (equal_to("CRITERE", 'ABSOLU'))
                    ◆ PRECISION = float,

```

The keyword ETAT_INIT makes it possible to define a reference initial state in the case of a transient analysis.
Unlike the mechanical case, this initial state is mandatory; there is no default value.

#### 8.1.1 Steady analysis

If STAT = "OUI", then the initial value of the temperature field is then the result of a preliminary steady analysis.
This is the default mode.

#### 8.1.2 Temperature field

The keyword VALE makes it possible to define an initial value of the temperature **constant** over the whole structure, whereas the keyword CHAM_NO defines it by a nodal temperature field (result of the operator [CREA_CHAMP](doc:u4.72.04)) for example.

One can also use the initial temperature field by extraction from an evol_ther result given by the keyword EVOL_THER.
One can then give the order number NUME_ORDRE or the time instant INST of the field to be extracted from this data structure. If NUME_ORDRE or INST are not filled in, one takes the last existing archived number in evol_ther.

**Note:**

Warning, this is the order number in the data structure read on restart by the preceding keyword EVOL_THER. If this data structure was computed with a list of time instants different from that used under the factor keyword INCREMENT of the current solution, it is imperative to fill in NUME_INST_INIT under INCREMENT, the same order-number value corresponding to different physical time instants. In the case where the two lists of time instants are identical, one can dispense with filling in the same order number twice, under ETAT_INIT and under INCREMENT.

The keywords PRECISION and CRITERE make it possible to select the field finely from the value of the time instant given by INST. See [U4.71.00](doc:u4.71.00).

### 8.2 Archiving of the fields

The keyword ARCHIVAGE is optional: by default, the set of fields computed for all the computed steps is archived in the resultat concept produced by the command. It is used to store certain order numbers in a resultat data structure and/or to exclude certain fields from storage.

This keyword is identical to its equivalent for the operator [STAT_NON_LINE](doc:u4.51.03).

**Note:**

In the event of the analysis stopping for lack of CPU time, the previously computed time steps are saved in the database.

The command [CALC_CHAMP](doc:u4.81.04) makes it possible to compute the heat fluxes, at the integration points or at the nodes, from the nodal temperature field thus obtained by THER_LINEAIRE.

## 10 Non-linear constitutive behaviours

```text
⟐ COMPORTEMENT = _F(
         ◇ RELATION = / "THER_HYDR",
                      / "THER_NL" (par défaut),
         ◆ / TOUT = "OUI" (ou non renseigné),
           / GROUP_MA = list[grma],
      ),
```

The non-linear constitutive behaviours are described by the repeatable factor keyword COMPORTEMENT.
The keyword GROUP_MA specifies the mesh cells on which the constitutive relation is applied.
Unlike mechanics, the constitutive behaviour 'THER_NL' is necessarily applied to the whole mesh, option TOUT: 'OUI', the default option, which is in fact, in the general case, transparent for the user.

There are three broad categories of non-linear constitutive behaviour:

- Non-linear thermal analysis
- The hydration analysis
- The drying analysis (treated by the operator [SECH_NON_LINE](doc:u4.56.01))

**Note:**

If the keyword COMPORTEMENT is absent, one performs a "standard" non-linear thermal analysis.

### 10.1 Non-linear thermal analysis

When RELATION='THER_NL', this is the standard non-linear thermal solution.

Supported modellings:

- 3D continuous media: 3D
- 2D continuous media: 2D and AXIS

### 10.2 Hydration analysis

When RELATION='THER_HYDR', one solves the heat equation with an additional source term $Q \dot{\xi}$ where $Q$ is the heat of hydration, assumed constant. The hydration variable $\xi$ is the solution of the non-linear evolution law, solved simultaneously with the thermal problem:

$$
\dot{\xi}
=
A(\xi ) \exp \left( -\frac{E}{RT} \right)
$$

One should refer to the documentation of the operator [DEFI_MATERIAU](doc:u4.43.01) for the meaning of the various parameters.

At the initial time instant of the analysis, the hydration variable takes as its value the field found under the name 'HYDR_ELNO' in the evol_ther data structure defined under ETAT_INIT. By default, the initial hydration state is taken as virgin, $\xi =0$ .

Supported modellings:

- 3D continuous media: 3D
- 2D continuous media: 2D and AXIS

## 11 Monitoring of the analysis

This section groups the various tools making it possible to monitor an analysis: observation and display.

### 11.1 Observation

The factor keyword OBSERVATION makes it possible to post-process certain fields at the nodes or at the elements on parts of the model at time instants of a list (known as the observation list), generally finer than the list of archived time instants defined in the keyword ARCHIVAGE (where one stores all the fields over the whole model). It is used essentially to save on storage.

This keyword is repeatable and makes it possible to create an observation table with the same name as the result concept of THER_NON_LINE.

For the description of the syntax of this factor keyword, refer to the documentation of the equivalent keyword of [DYNA_NON_LINE](doc:u4.53.01).

### 11.2 Displays

The factor keyword AFFICHAGE makes it possible to customise the display of the convergence table.

If this keyword is not filled in, the table is built according to the various analysis options and with INFO_RESIDU='NON'.

For the description of the syntax of this factor keyword, refer to the documentation of the equivalent keyword of [STAT_NON_LINE](doc:u4.51.03).
