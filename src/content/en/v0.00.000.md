# v0.00.000 Classification of Validation Documentation

**Summary:**

The Validation Manual consolidates the tests used to ensure the non-regression of the features available in *Code_Aster*. These tests are offered and maintained by the respective functionality managers.

This document presents the classification of the tests.

## 1 Reminder of documentation management principles

The Validation Manual consolidates the code validation documentation. The validation sheets it contains specify the area of guaranteed use and give confidence in the use of the code. They illustrate the use of different modelling options and are an essential complement to learning about structural calculations.

### 1.1 Identification of validation and codification manual fascicles

Each booklet is identified by a key on all pages. This key allows for the progressive management of documentation as it is written.

The manual is divided into ten parts** . The parts of the manual are materialized by cardboard interlayers, delivered with the binder. They are numbered from **0** to **9** .

The parts of the manual are made up of **fascicles** , software notes under A.Q. which comply with the rules for the presentation of D.E.R. technical notes (notes HI, HP, ...); a note may contain one or more fascicles. Each part of the manual may contain a priori one hundred booklets. Each specification is identified by a specification number between **00** and **99** .

A booklet can be cut, as required, into **documents** numbered from **0** .

Each validation test is accompanied by a coded reference which is unique to it (see attached table).

This coding, taken from the VPCS guide, consists of eight alphanumeric characters:

- takes into account the type of problem dealt with by the test (4 alphabetical characters),
- the serial number of the test in the list of tests of the same type (2 or 3 numeric characters).

The four alphabetical characters indicate in order:

| 1er | character | : | the scope, |
| --- | --- | --- | --- |
| 2nd | character | : | the type of analysis, |
| 3rd | character | : | the type of behaviour, |
| 4th | character | : | the type of model. |

**Example**: SDLA04 will be the 4th SDLA test

Document numbers between 01 and 99 correspond to tests from the VPCS guide.

The numbers between 100 and 299 correspond to the tests offered by the developers.

The numbers between 300 and 399 are reserved for tests resulting from the independent validation of version 3, between 400 and 499 to that of version 4,... For tests resulting from independent validation, only those included in the list of non-regression of *Code_Aster* are documented in the Validation Manual.

A test can be associated with several modellings. Each model is also coded by itself and is composed of eight characters. The first six or seven are made up of the coded reference of the test, the last character indicates the order number of the model in the list of modellings associated with the test.

By convention, the numbers will be taken in the following order:

A, B, C, ……, Y, Z

**Example**:

SDLA04C will be the coding relative to the 3rd model studied in the SDLA04 test.

If only one model is studied in a test, it will be indicated A.

**Example**: SDLA04A, SSLV101A.

By convention YYYY tests are performance tests and ZZZZ tests are tests to validate computer features. Other names not corresponding to the nomenclature exist. These tests are generally linked to trade tools.

### 1.2 Responsibilities of documentation

Each booklet or document is identified, on each page, by several information, in addition to the classification key:

- a title, truncated if it's too long,
- the date of publication,
- the name of the author responsible,
- page number, followed by the total number of pages,
- the document revision number, which materializes developments in documentation,
- the version number and, if applicable, subversion of the code for which the specification or document applies:
- default, documentation valid for the development version,
- 9.5 documentation valid for version 9.5.
