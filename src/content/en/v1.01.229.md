# v1.01.229 ZZZZ229 - Validation of the AFFE_CHAR_MECA / LIAISON_SOLIDE + TRAN + ANGL_NAUT command

**Summary:**

This problem tests the results obtained by applying translation and rotation with the operator AFFE_CHAR_MECA/LIAISON_SOLIDE.

## 1 Reference problem

### 1.1 Geometry

![Figure](/figures/v1.01.229/1000020000000121000000FBD0CAA0E895936E18.png)

The square is in $[0.,1.]\times [0.,1.]$ space.

Contact details of $(m)$ points:

> $A:(0.,0.)$
> $B:(1.,0.)$
> $C:(1.,1.)$
> $D:(0.,1.)$

### 1.2 Material properties

    - $E=1.0\mathrm{E5}N/{m}^{2}$
    - $\nu =0.3$
    - $\rho =9800.{\mathrm{kg.m}}^{-3}$

### 1.3 Boundary conditions and loads

    - Travel requirements:
  - Rotation of $90°$ around point $D$
  - $\mathrm{ABCD}$ : $\mathrm{DX}=-1m$ et $\mathrm{DY}=1m$

## 2 reference solution

The reference quantity used is the $X$ and $Y$ displacements of the point $C$ .

analytical solution :

- $90°$ Rotation around point $D$ : $C(1,1)\to C(0,2)$
- Translation of (-1,1): $C(0,2)\to C(-1,3)$

The reference displacements to point $C$ are derived from this:

- $\mathrm{DX}=-2m$
- $\mathrm{DY}=2m$

## 4 Summary of the results

This test case shows the correct functioning of the AFFE_CHAR_MECA operator used with the LIAISON_SOLIDE keyword in the case of rotation and translation.

> Remarks:

- If the rotation is null, you can do the same with DDL_IMPO.
- If the rotation is strong, the "solid" is really not distorted but the constraints are not necessarily zero (the hypothesis of small default transformations).
