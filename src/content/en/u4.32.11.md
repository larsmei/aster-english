# u4.32.11 Macro-command MACR_SPECTRE

## 1 Purpose

This macro-command makes it possible to carry out a fast and efficient post-processing analysis in order to determine the floor spectra of any building after a seismic dynamic analysis.

It may for example be used after a transient dynamic analysis of a building under earthquake loading, in which the connections between the soil and the raft in single-support or multi-support conditions are simulated by a soil stiffness (DYNA_VIBRA [U4.53.03](doc:u4.53.03), transient dynamic analysis on a reduced modal basis, calculated in the relative reference frame, concept produced: resu_gene) or after analyses coming from the *Code_Aster*–*ProMiss3D* coupling (CALC_MISS [U7.03.12](doc:u7.03.12), concept produced: tran_gene or harm_gene) or else following a non-linear transient dynamic solution (DYNA_NON_LINE, concept evol_noli, and on the observation table coming from an analysis of this type).

This macro-command executes successively:

  - the extraction of the relative acceleration at one or more nodes of the mesh in the result concept (RECU_FONCTION [U4.32.03](doc:u4.32.03));
  - the combination with the ground acceleration in order to obtain the absolute acceleration (CALC_FONCTION [U4.32.04](doc:u4.32.04));
  - the calculation of the acceleration response spectrum with several damping coefficients (CALC_FONCTION [U4.32.04](doc:u4.32.04));
  - the envelope function of the relative displacement or of the acceleration corresponding to a given floor.
  - the printout of the envelope spectra by floor and by direction.
  - the creation of a table for the envelope spectra of all the floors.

For practical examples of implementation, the reader may refer to the test cases SDNL131 (post-processing of a piping analysis), SDNV112 (civil-engineering building under multi-support seismic loading) or to the tests SDLX101, SDLX101, MISS01, MISS05 with a *Code_Aster*–*Miss3D* coupling analysis.

The macro-command produces a concept of type table_sdaster.

## 3 Operands

The classical post-processing of a seismic analysis in transient dynamics consists in carrying out the following calculations:

- The floor spectrum obtained from the absolute accelerations, for each direction $\text{X},\text{Y},\text{Z}$ , calculated at a specified node of the mesh (for example in the case of a «stick» model);
- The envelope of the floor spectrum, calculated at a few nodes of the same floor, for each direction $\text{X}$ , $\text{Y}$ , $\text{Z}$ and $\text{H}$ (maximum between $\text{X}$ and $\text{Y}$ ), (for example in the case of a 3D building structure);
- The envelope displacements of the structure relative to the ground motions.
- Three operators of *Code_Aster* can produce result concepts corresponding to transient dynamic analyses:
- DYNA_VIBRA [U4.53.03](doc:u4.53.03) produces a resu_gene concept, including the relative acceleration and displacement fields. In this case, the ground accelerations must be added in order to obtain the absolute accelerations, which are necessary for the calculation of the floor spectrum.
- CALC_MISS [U7.03.12](doc:u7.03.12) produces a tran_gene or harm_gene concept, including the absolute acceleration and displacement fields. In this case, the accelerations are used directly for the calculation of the floor spectrum; conversely, subtraction of the ground displacements is mandatory (to be read with the command LIRE_FONCTION [U4.32.02](doc:u4.32.02) from a specific file given by its logical unit) in order to obtain the relative displacements.
- DYNA_NON_LINE [U4.53.01](doc:u4.53.01). The treatment is then the same as for the previous point.

Here is a schematic of the calculation algorithm of this macro-command:

*Loop #1* *over the floors*

*Loop #2 over the floor nodes*

*Loop #3 over the 3 directions*  $>$

*Loop #4 over the results*

*•* *Recovery of the relative acceleration functions at the nodes:* *RECU_FONCTION*

*•* *If acceleration calculation:*

*◦* *Combination or not with the ground acceleration function:* *CALC_FONCTION/COMB*

*◦* *Calculation of the response spectrum, with specified values of frequencies and of damping with* *CALC_FONCTION/SPEC_OSCI*

*•* *If displacement calculation (absolute displacements):*

*◦* *The ground displacements are subtracted in order to obtain the relative displacements:* *CALC_FONCTION/COMB* *.*

*End of loop #4*

*•* *In the case of the acceleration calculation:*

*◦* *calculation of the mean value for a given node and a given direction:* *CALC_FONCTION/COMB*

*•* *In the case of the displacement calculation:*

*◦* *recovery of the maxima*

*End of loop #3*

*•* *Printout of the acceleration spectrum for each node and each direction* $>$ *:* *IMPR_FONCTION*

*End of loop #2*

*•* *Envelopes of the acceleration spectrum for a given floor, or maximum displacements* *CALC_FONCTION/ENVELOPPE*

*•* *Envelopes of the acceleration spectrum for each floor, for each direction* $>$ *IMPR_FONCTION*

*End of loop #1*

The table produced by the macro-command contains 3 types of entries:

- the calculated spectra:

  - in the case of a displacement calculation: the envelope spectra on each floor;
  - in the case of an acceleration calculation: the envelope spectra by floor and by specified damping values.
- the correspondence between the damping indices and the values of these dampings;
- the information (name, building, details) on the floors.

### 3.1 Keyword MAILLAGE

This keyword corresponds to the mesh read by the operator LIRE_MAILLAGE [U4.21.01](doc:u4.21.01).

This keyword is optional. Knowledge of the mesh is necessary only in the case where the user uses the simple keyword GROUP_NO of the factor keyword PLANCHER. Indeed, as described in the previous algorithm, the treatment is carried out on the nodes and, if the user gives directly the name of the nodes present in the table, the mesh is not necessary.

### 3.2 Keyword PLANCHER

This keyword is mandatory in order to define the names of the floors, where the spectra will be calculated. These names will be used to select or filter the display parameters in the table structure produced by the macro-command table_sdaster.

#### 3.2.1 Operand NOM

This mandatory operand makes it possible to name the floor considered.

#### 3.2.2 Operand BATIMENT

This optional operand makes it possible to supply the name of the building to which the floor belongs. This information will then appear in the output table.

#### 3.2.3 Operand COMMENTAIRE

This optional operand makes it possible to give a comment. This information will then appear in the output table. It must not exceed 24 characters.

#### 3.2.4 Operand GROUP_NO

This operand makes it possible to define the nodes making up the floor where the spectra will be calculated. It is available only if the mesh has been supplied.

### 3.3 Keyword CALCUL

This mandatory keyword makes it possible to define the nature of the transient dynamic analysis used for the post-processing: in the absolute reference frame ('ABSOLU') or the relative reference frame ('RELATIF').

### 3.4 Keyword ENVELOPPE

This mandatory keyword makes it possible to define whether the output spectra must be edited with or without (respectively `ENVELOPPE = 'OUI'` or `ENVELOPPE = 'NON'`) the envelope of the two horizontal directions. The two horizontal directions are commonly denoted `X` and `Y` and their envelope is denoted `H`.

### 3.5 Keyword NOM_CHAM

This mandatory keyword makes it possible to define the nature of the field used: accelerations ('ACCE') or displacements ('DEPL').

### 3.6 Case NOM_CHAM ='ACCE'

In this case, the user must supply the following data required for the calculation of the acceleration response spectrum: in the 3 directions $\text{X}$ , $\text{Y}$ , $\text{Z}$ (vertical) and $\text{H}$ (maximum horizontal value between the values along $\text{X}$ and $\text{Y}$ ).

#### 3.6.1 Operand AMOR_SPEC

This mandatory operand makes it possible to define the values of the reduced damping coefficient used in the calculation of the spectral response. See also CALC_FONCTION [U4.32.04](doc:u4.32.04), keyword SPEC_OSCI.

#### 3.6.2 Operand LIST_INST

This optional operand makes it possible to specify the list, produced by DEFI_LIST_REEL [U4.34.01](doc:u4.34.01), defining all the time steps for the transient dynamic analysis.

#### 3.6.3 Operand FREQ / LIST_FREQ

/ ◊      FREQ = L_FR

L_FR = (f1,f2, f3, ...) fi. frequencies.

/ ◊      LIST_FREQ = LFREQ

List of frequencies previously defined by a listr8 concept.

This optional operand makes it possible to define the frequency values; see also CALC_FONCTION [U4.32.04](doc:u4.32.04), keyword SPEC_OSCI.

#### 3.6.4 Operand NORME

♦    NORME = r

The response spectrum will be normalised by the value $\text{r}$ (pseudo-acceleration value). The analyses are carried out in most cases in units of the International System (USI) and the acceleration histories are often given in units . The response spectra are generally given with .

Thus, this mandatory operand NORME may be used as a unit-conversion factor between the calculated accelerations and the response spectrum; see also CALC_FONCTION [U4.32.04](doc:u4.32.04), keyword SPEC_OSCI.

#### 3.6.5 Keyword RESU

This mandatory keyword makes it possible to specify the names of the result concepts in which the nodal accelerations are considered.

The possible values are:

> /    'RESU_GENE'    = TG                [TRAN_GENE]

if the post-processing is carried out from a DYNA_VIBRA concept [U4.53.03](doc:u4.53.03) (transient dynamics on a reduced modal basis). However, this result must be calculated in the relative reference frame

or:

> /    'RESULTAT'    = RESU                [DYNA_TRANS]                                            [EVOL_NOLI]

if the post-processing is carried out from a transient-dynamics result (coming for example from CALC_MISS [U7.03.12](doc:u7.03.12), concept produced: tran_gene or harm_gene, or from DYNA_NON_LINE, concept produced: evol_noli).

or:

> /    'TABLE'        = TAB                [TABLE_SDASTER]

if the post-processing is carried out from a table containing the results to be read. Typically, an observation table derived from a transient dynamic analysis.

#### 3.6.6 Case CALCUL ='RELATIF'

♦     ACCE_X =     /AC_X                [FONCTION]

♦     ACCE_Y =     /AC_Y                [FONCTION]

♦     ACCE_Z =     /AC_Z                [FONCTION]

In this case, the user must supply the ground-acceleration functions, defined on the same list of time instants, in each spatial direction, in order to combine them with the relative accelerations so as to calculate the absolute accelerations.

#### 3.6.7 Case CALCUL ='ABSOLU'

◊ MULT_APPUI =     'OUI'

In this case, the user may specify whether it is a multi-support modelling. By default, it is a single-support modelling. Multi-support modelling is possible only when the result concept is of type resu_gene.

### 3.7 Keyword IMPRESSION

This optional keyword makes it possible to specify the nature of the results to be printed (spectra, envelopes). The outputs will be according to the directions 'X', 'Y', 'Z', 'H' and the damping values.

#### 3.7.1 Operand TRI

This optional keyword makes it possible to specify the nature of the curves to be printed, sorted according to: the value of the damping coefficient ('AMOR_SPEC') or the spatial direction ('DIRECTION').

#### 3.7.2 Operand FORMAT

This optional keyword makes it possible to specify the printout format of the curves: by printout in table format ('TABLEAU') or in a form readable by the Xmgrace software ('XMGRACE'). The scale of the abscissae (frequencies) is logarithmic.

#### 3.7.3 Operand UNITE

◊    UNITE =    U

Logical unit of the file in which the results are written (integer between 10 and 90). The default unit is 29. This unit number must be consistent with the declaration made in the astk interface for the file in question.

#### 3.7.4 Case FORMAT ='XMGRACE'

For more details, see the documentation of the command IMPR_FONCTION [U4.33.01](doc:u4.33.01).

#### 3.7.5 Operand TOUT

This optional operand TOUT='OUI' may be used to print the whole spectrum calculated at the end of loop #4: the mean values at each node, for all the directions and all the damping values.

### 3.8 Case NOM_CHAM ='DEPL'

In this case, the user must give the following data required for the calculation of the displacement envelope: in the 3 directions $\text{X}$ , $\text{Y}$ , $\text{Z}$ (vertical) and $\text{H}$ (maximum horizontal value along $\text{X}$ and $\text{Y}$ ).

#### 3.8.1 Operand LIST_INST

This operand makes it possible to specify the list, coming from DEFI_LIST_REEL [U4.34.01](doc:u4.34.01), defining all the time steps of the dynamic transient for the calculation of the envelope displacement.

#### 3.8.2 Keyword RESU

This mandatory keyword makes it possible to specify the names of the result concept from which the nodal accelerations are extracted. The associated operand may be:

> /    'RESU_GENE' = TG                    [TRAN_GENE]

if the post-processing is carried out from a DYNA_VIBRA concept [U4.53.03](doc:u4.53.03) (transient dynamics on a reduced modal basis). However, this result must be calculated in the relative reference frame.

or:

> /    'RESULTAT'    = RESU                [DYNA_TRANS]                                            [EVOL_NOLI]

if the post-processing is carried out from a transient-dynamics result (coming for example from LIRE_MISS3D [U7.02.31](doc:u7.02.31), concept produced: DYNA_TRANS, or from DYNA_NON_LINE, concept produced: evol_noli).

or:

> /    'TABLE'        = TAB                [TABLE_SDASTER]

if the post-processing is carried out from a table containing the results to be read. The table may be produced by:

- a transient dynamic analysis, and come from an observation table. In this case the names of the columns of the table are ('INST', 'NOEUD', 'NOM_CHAM', 'NOM_CMP', 'VALE') with 'NOM_CHAM'='ACCE'.
- any command producing a table. In this case the names of the columns of the table are necessarily ('INST', 'NOEUD', 'NOM_CHAM', 'DX', 'DY', 'DZ') with 'NOM_CHAM'='ACCE'.

#### 3.8.3 Case CALCUL ='ABSOLU'

♦DEPL_X =     /DE_X                [FONCTION]

♦DEPL_Y =     /DE_Y                [FONCTION]

♦DEPL_Z =     /DE_Z                [FONCTION]

In this case, one must introduce the ground entrainment-displacement functions, for each result concept, defined on the same list of time instants, in each spatial direction, which must be subtracted from the absolute displacements in order to obtain the relative displacements.

## 4 Examples

The following examples illustrate the calculation of an acceleration spectrum, as well as the calculation of the displacement envelope:

TAB=MACR_SPECTRE(

MAILLAGE = MAIL,

PLANCHER = _F(NOM = 'SOMMET', GROUP_NO = ('GTOP1',),),

NOM_CHAM = 'ACCE',

CALCUL = 'ABSOLU',

AMOR_SPEC = L_AMOR_S,

FREQ = L_FREQ,

NORME = 9.81,

RESU=(_F(RESU_GENE = RESUGENE,),),

)

TAB2=MACR_SPECTRE(

MAILLAGE = MA1,

PLANCHER = (

_F(NOM = 'NIV1', GROUP_NO = ('N4_NIV1','N5_NIV1','N6_NIV1','N7_NIV1',),),

_F(NOM = 'NIV8', GROUP_NO = ('N4_NIV8','N5_NIV8','N6_NIV8','N7_NIV8',),),

),

NOM_CHAM = 'DEPL',

CALCUL = 'RELATIF',

LIST_INST = LISTE,

RESU=(

_F(RESU_GENE = TRAN_GE1,),

_F(RESU_GENE = TRAN_GE2,),

_F(RESU_GENE = TRAN_GE3,),

),

),

TAB3=MACR_SPECTRE(

MAILLAGE = MA1,

PLANCHER = (

_F(NOM = 'NIV1',GROUP_NO = ('N4_NIV1',), ),

_F(NOM = 'NIV8',GROUP_NO = ('N4_NIV8','N5_NIV8',), ),

),

NOM_CHAM = 'ACCE',

CALCUL = 'ABSOLU',

AMOR_SPEC = L_AMOR_S,

LIST_FREQ = L_FREQ,

RESU=(_F(RESULTAT = DYNAT_K1,),

_F(RESULTAT = DYNAT_K2,),

_F(RESULTAT = DYNAT_K3,),),

IMPRESSION =_F(FORMAT ='TABLEAU', UNITE = 16,),

)

One may also refer to the test case SDNV112A for another example of use.
