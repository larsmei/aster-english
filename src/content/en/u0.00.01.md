# Reading guide to the User documentation

> **Summary.**

This document aims to offer help for a first access to the content of the User documentation.

## 1 Documentation of Code_Aster: organisation and access

### 1.1 A logical breakdown into Manuals: the ARDUV

The technical documentation of *Code_Aster* comprises:

- five manuals,

- a set of other documentary items which complement the basic technical documentation above.

| **User's** manual | **U** | Instructions for use of the commands, user data structures, examples of use |
| --- | --- | --- |
| **Reference** manual | **R** | Formulation of the modelled phenomena, analysis methods, numerical algorithms |
| **Programmer's** manual (Descriptif informatique) | **D** | Data structures, algorithms, the architecture, environment |
| **Validation** manual | **V** | Elementary test sheets in all areas of modelling |
| **Administration** manual | **A** | Quality plan, development and maintenance procedures, service commitments, versioning |

Other documentary items exist (the newsletters, the presentation brochure of the code, various talks, the presentations at the annual day …) and are all accessible on the website [https://www.code-aster.org](https://www.code-aster.org/).

The basic manuals for the user of *Code_Aster* are the **User's** manual, the **Reference** manual and the **Validation** manual. The User's manual frequently refers to the Reference manual. The Programmer's manual (Descriptif informatique) is reserved for developers; in principle it does not concern users. The same is true of the Administration manual. One major exception for the latter: the user has access to the Quality sheets and the Quality follow-up sheets, which indicate, for the production versions (version d'exploitation) and the development versions of the code, what the changes are, which identified errors have been corrected or not, and the workarounds.

The manual is subdivided into ten named parts (numbered from 0 to 9), the parts into booklets which are likewise named (00 to 99), and the booklets into documents (00 to 99).

#### 1.1.1 The document key

A document is located in the document space of the manuals by a document key:

**Manual_Part.Booklet_number.Document_number**

Example of a document key: **U1.02.00**

Naturally, a document is referred to by its document key. For convenience, two classes of documents are also designated by the *Aster* function which they document:

- the documents of the instructions for use of the commands (User's manual), designated by the **name of the command** documented,

- the documents describing the elementary test cases dedicated to validation of the code (Validation manual), designated by **the test-case code**.

**Examples**:

**U4.43.01** documents the command DEFI_MATERIAU; one calls it the document DEFI_MATERIAU.

**V7.90.04** documents the thermomechanical test case HNSV100: Thermoplasticity in simple tension; one calls it the document HNSV100.

Documentary items other than those contained in the manuals are not assigned the key just described.

#### 1.1.2 Which version of the code does the document apply to?

Each technical document of the manuals carries in its header a certain amount of bibliographic particulars (the title of the document, the name of the person responsible, the key, the summary, the version of the code). Among these, three deserve particular attention because they relate to the **Quality Assurance** of the code and to the updating of the documents:

- the version of the code concerned by the document,

- the revision index of the document,

- the date, which corresponds to the publication date of the revision of the document concerned.

At the top right of the page header of the document there is an indicator which specifies the version of Code_Aster to which the document applies. This indicator may take two kinds of value:

- "Development version" if the document is in the current production cycle, linked to the development version of Code_Aster. The document visible to the reader is then the latest published state, which replaces any earlier states attached to this version.

- A version number, "10" for example, when the document is attached to a production version (version d'exploitation) of Code_Aster. This number is then the major version number of Code_Aster. The documentation applies to the production sub-index then in force ("10.6" for example).

There are always at least 2 versions of the code available:

- The so-called production version (version d'exploitation), validated and qualified, which must be used for studies under quality assurance.

- The development version, not yet validated or qualified. The user of Code_Aster must at all times know which are officially the production version (version d'exploitation) and the development version.

These versions change every 2 years (increment of the version number). Each time a version and production or development sub-versions are brought into service, a Quality sheet and Quality follow-up sheets are brought into service. These documents list, for a given version or sub-version, the qualified areas (features) and the notes and the restrictions on the qualified areas. These sheets (which are documents from the Administration file) are available as A documents.

### 1.2 Accessing the User documentation of Code_Aster

The technical User documentation of *Code_Aster* is a subset of its general documentation.

#### 1.2.1 It is entirely electronic documentation

The documentation is published on the website of the code at:

**https://www.code-aster.org/**

Every night, an automatic process publishes on this site the documents which have been published in the document-management application **a-ged** during the previous day. In practice, the updates mainly concern the development version, whose documentation changes at the pace of the new developments integrated into the code each week.

### 1.3 General presentation of the User documentary resources

In practice the ordinary user will draw documentary resources **from 3 manuals**, in this order:

- **Manual U**, whose structure the user must keep clearly in mind

| **Documented features** | **Manual parts** |
| --- | --- |
| Instructions for use of the commands | U4: basic commands U7: commands for data exchange with other software |
| Characteristics of the modellings | U3 |
| User's guide to the modellings | U2 |
| Access to the code | U1 |

- **Manual R**: the finite elements, the formulation of the modellings of the phenomena

- **Manual V**: the validation test cases

## 2 Getting started

It is obviously out of the question to read the whole User's manual exhaustively. In May 2011, it comprised 338 documents (of which 242 concern the use of the commands proper) representing thousands of physical pages. Many documents probably do not concern the user at the time of a first modelling and a first analysis; it is nevertheless absolutely necessary to consult the documents describing the features which implement this first modelling. This is for two reasons:

- to avoid errors in use,

- but also to be aware of the capabilities of *Code_Aster* close to those being sought (workarounds) which might perhaps prove useful.

It is therefore advisable to consult the User documentation following the approach proposed below.

### 2.1 Can Code_Aster deal with the subject of my problem?

Four documents claim to answer this question. They are presented from the most concise to the most complete.

#### 2.1.1 For a quick answer

Consult the pages of the brochure presenting the modelling areas of the code, on the website, Product section, where the physical phenomena which can be modelled by the code are described concisely.

#### 2.1.2 For a more thorough answer

* *

Consult the document [U1.02.00](doc:u1.02.00) Introduction to **Code_Aster**, in particular chapters 1.3 (Phenomena, modellings, finite elements and constitutive behaviours) and 1.4 (Several analysis methods), where the phenomena which can be modelled by the code are described concisely.

#### 2.1.3 For a more up-to-date answer (taking the latest developments into account)

* *

Consult the slides of the latest presentation of the new features of the code at the annual users' day of *Code_Aster*, as of the publication date of this document: Product section of the website.

#### 2.1.4 For a still more developed answer ...

Here one enters an area of questioning where the answer can no longer be given directly by items present on the documentary server. For example, the answer may be YES and consist of subtleties of modelling or roundabout modelling paths. In any event, it is addressed to users who are already experienced. The **AOM** service ( **A** id to the **O** ptimisation of **M** odelling) of the Experience Feedback (REX) makes it possible to submit to the *Aster* Development Team (EDA) a particular modelling problem to be carried out with *Aster* resources. A person from the EDA is then assigned to help the requester carry out the modelling.

### 2.2 Has Code_Aster already dealt with a problem comparable (similar) to mine?

Two paths are proposed: the path of the elementary test cases, and the path of the industrial applications.

#### 2.2.1 The elementary test cases

The test-case base associated with Code_Aster is supplied with the local installations or can be consulted on the centralised server. These tests serve three purposes:

- verification of the programmed models by comparison with reference solutions (analytical or computed);

- computer verification of Code_Aster: exhaustive coverage of the software paths, verification of non-regression of operation when porting to different system solutions.

- the educational presentation of simple implementations: small studies which are quickly understood on reading the command files and the associated validation documents (V).

It is this third function of the test cases that is discussed here. The user will look to see whether an elementary test case deals with a problem similar to the user's own: documentary server, heading VALIDATION / *Test cases by name*; the list of the documentation of the test-case names (classified by area of application) is displayed, together with their titles; or else the Use/Examples section of the site.

#### 2.2.2 The industrial studies

A certain number of industrial studies (applications), carried out using *Code_Aster*, have been presented at the annual users' day.

These documented studies are available on the site, under Product/Applications. There one finds the collection of Study sheets from the periodical *ASTER* échos since its creation (10/91, 39 issues published as of 01/2003) and a collection of industrial studies in all the modelling areas of the code, presented on the occasion of the annual days of *Code_Aster*.

## 3 First use of code_aster

Consult the document [U1.01.04](doc:u1.01.04) describing **the graphical access interface astk**.

The simplest way to carry out an analysis with code_aster is to start from a similar example, which is often found among the elementary test cases described in the Validation manual. The command files associated with the test cases described in the validation documentation are located in the astest directory of the version used. On the centralised computing server of EDF R&D, they are in /aster/vx/STAx/astest where x is the number of the production version (version d'exploitation).

This way of proceeding by analogy, generally well appreciated by the community of mechanical engineers, must not completely replace a constructive approach. Very often many possibilities are available for doing the same work, and they are more or less well suited to each case.

One must therefore get into the habit of consulting this validation manual for every new need.

### 3.1 The main principles and the key stages of an analysis

A reading path is set out below, inspired by the major compulsory stages of a mechanical study with code_aster. In this approach, three documents are proposed for reading.

#### 3.1.1 The main principles of code_aster

Consult the document [U1.03.00](doc:u1.03.00) The main principles of code_aster, which briefly presents the operating principles and the main rules of use.

#### 3.1.2 Simple example of use of code_aster

Consult the document [U1.05.00](doc:u1.05.00) Simple example of use of code_aster: the "essential" commands, for an analysis of a thin cylindrical tank under hydrostatic pressure, axisymmetric modelling.

### 3.2 The mesh

The structure of the *Aster* mesh file is described in the document [U3.01.00](doc:u3.01.00) Description of the code_aster mesh file.

If the initial mesh comes from a mesher external to *Aster*, for example GMSH, GIBI or I-DEAS, the *Aster* interfaces and commands which create, from the objects produced by these pre-processors, objects of the *Aster* mesh (which are not a copy of the initial objects; their meaning may change, and new objects may be created) are described in the documents:

[U3.02.01](doc:u3.02.01) Interface of the GMSH mesh file with **Aster,**

[U3.03.01](doc:u3.03.01) Interface of the I-DEAS mesh file with **Aster,**

[U3.04.01](doc:u3.04.01) Interface of the GIBI mesh file with **Aster,**

[U7.01.01](doc:u7.01.01) Procedure **PRE_IDEAS,**

[U7.01.11](doc:u7.01.11) Procedure **PRE_GIBI,**

[U7.01.31](doc:u7.01.31) Procedure **PRE_GMSH,**

The mesh format recommended when using **code_aster** is the MED format (Data Exchange Model). It is the default format when reading meshes and writing results.

### 3.3 The commands

The descriptions of the commands of *Code_Aster* are contained in parts U4 and U7 of the User's manual. It is certainly to these 2 parts of the manual that the *Aster* user will turn most often. They are organised in manual U4 according to a scenario which logically follows the main stages of an analysis:

| **U4.1-** | Allocation of disk and memory resources, |
| --- | --- |
| **U4.2-, U7.01.- to U7.03.-** | Acquisition of the mesh data, |
| **U4.3-** and **U4.4-** | Modelling (assignment of the finite elements, of the materials, of the loadings, etc. ...), |
| **U4.5-** | Solution of the system of equations (analysis) |
| **U4.6-, U4.7-** , **U4.8-, U7.03 to U7.05.-** | Post-processing and examination of the results |

Finally, the document [U4.01.00](doc:u4.01.00) How to read the command documentation explains in particular the meaning of the meta-characters and of the typography encountered in the documentation of the command syntax.

### 3.4 The user's guides

A certain number of modellings or types of modelling (for example static substructuring, mechanical damping, thin shells, etc.) are the subject of user's guides. The related documents will be available on the server in part U2 of the User's manual.

### 3.5 The finite elements, the modellings of the phenomena

From the numerical point of view, the choice of finite elements for a type of modelling is the user's responsibility. The mathematical description of the modellings supported by finite elements is found in the **Reference manual**. The description of the degrees of freedom of these elements, as well as their modelling capabilities (supported loadings, fields produced, non-linear capabilities, etc.), is found in the documents:

**U3.1- : Mechanical modellings,**

**U3.2- : Thermal modellings,**

**U3.3- : Acoustic modellings.**

### 3.6 User data structures of type resultat

The *Aster* analysis operators (commands) create objects, and the structuring of the data which they contain must be absolutely known to users.

It is essential to read very carefully the documents devoted to the *Aster* commands dedicated to the printing of results (to a listing or to files).

First, two generic documents:

[U4.91.01](doc:u4.91.01) Procedure **IMPR_RESU (FORMAT='RESULTAT' and 'ASTER')**

Then five documents describing the commands which generate result files in MED format, in GMSH format and in the formats accepted by the I-DEAS post-processor:

[U7.05.01](doc:u7.05.01) Procedure **IMPR_RESU (FORMAT='IDEAS')**,

[U7.05.21](doc:u7.05.21) Procedure **IMPR_RESU (FORMAT='MED')**,

[U7.05.32](doc:u7.05.32) Procedure **IMPR_RESU (FORMAT='GMSH')**,

### 3.7 Errors in the command file

Building an *Aster* command file is a compulsory step for the user. At present, the user has the choice between writing this file by hand or building it with the graphical interface **EFICAS** "**E**ditor of the command **FI**le of **C**ommands **AS**ter...", which is fairly natural to use.

In addition, it gives direct access to the electronic documentation.

If the command file is built by hand and if *Aster* detects a syntactic, grammatical or even semantic error in this file, elements of an answer for remedying the errors encountered are found in [U1.03.01](doc:u1.03.01) Supervisor and command language.

### 3.8 Telephone assistance

*Aster* Technical Telephone Assistance for use is provided by an external provider, whose contact details appear on the website, under Services (intranet access required).

## 4 Questions and answers about the Code_Aster documentation

### 4.1 Do I have the most up-to-date version of the document?

If the document is consulted electronically on the server, the answer is **YES**.

### 4.2 Which documentation (the set of documents) applies to the current production version (version d'exploitation) of the code?

They are the documents contained on the server, even if they bear a code version number lower than the current version and bear old dates. For each Manual, the list of these documents (documents valid for the current version) appears under the **Synopsis** sub-heading.

### 4.3 May I contact the author of the document directly? ...

... because I do not understand something, or because I have found an error in it?

It is advisable to go first through Aster Telephone Assistance (see §3.8), which will answer most questions.

In the case of a complex request, it is possible to contact the author of a document, taking care to trace this action by issuing an AOM-type sheet (see §2.1.4) in the Experience Feedback.

### 4.4 Can I contribute to a better quality of the Aster documentation?

**YES**, (it is even recommended); errors and suggestions are to be reported by writing a **Documentation Evolution Sheet** in the Experience Feedback of the graphical interface for access to *Code_Aster*.

### 4.5 I want to improve my knowledge of the capabilities and the use of Aster

The technical documentation of *Code_Aster* (more generally, all the *Aster* documentary items present on the documentary server) are not the only tools that answer this concern. In addition to the documents discussed in the presentation of the reading path for the User documentation, one should turn to the following events:

- Training sessions: introduction to *Aster*, basic training in use, in thermoplasticity, in post-processing,

- newsletters and flash news published regularly on the *Code_Aster* site,

- Quarterly ordinary meeting of the *Aster* Users' Club,

- Annual *Aster* Users' Day, generally at the beginning of March.
