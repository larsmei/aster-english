# v2.03.139 SDLS139 - Identification of fluid forces on wired structure

**Summary:**

This test case is used as validation for CALC_ESSAI macro-command, which is an interactive operator to identify effort on wired structure. Several methods are proposed by the operator, and tested here:

1. expansion of experimental data on a digital model,

1. identification of turbulent forces by decomposition on a modal basis,

The test case simulates the data required for the use of the macro:

- a fuel pencil mesh, stiffened by a guide tube,
- a modal base associated with this structure,
- simulation of fluid-elastic forces, at rest, and in flow,
- simulation of an interspectrum of turbulent forces, using a model of CORCOS,
- simulation of the movement of the pencil induced by this effort, restitution on 19 "sensors",
- creation of models of observability (mesh with 19 sensors) and control (mesh with 3 nodes).

Then, the macro-command uses this input data to identify simulated forces (fluid-elastic forces and turbulent forces).

The macro is normally used in INTERACTIF mode. When this is not the case, as in this test case, the command is executed in the source code of the command, which performs the identification functions instead of the user.

## 1 Reference problem

### 1.1 Geometry

![Figure](/figures/v2.03.139/10000201000002D00000021CDDB93721ADEF81D3.png)

Geometry is a fuel pencil of height $4,5m$ , thickness $0,5\mathrm{mm}$ and diameter $0,9\mathrm{cm}$ , regularly attached, through the holding grids, to a guide tube, more rigid, thickness $0,5\mathrm{mm}$ and diameter $1,245\mathrm{cm}$ .

### 1.2 Material properties

The material is homogeneous, isotropic, linear elastic. The elastic coefficients are:

1. $E=98400\mathrm{MPa}$ , $\nu =0.3$ , and $\rho =6526{\mathrm{kg.m}}^{-3}$ for the guide,
2. $E=98400\mathrm{MPa}$ , $\nu =0.3$ , and $\rho =6526{\mathrm{kg.m}}^{-3}$ for pencil.

### 1.3 Mechanical modelling

The grids are elements stiffness DIS_TR type, the pencils are elements POU_D_T from Timoshenko.

### 1.4 Boundary conditions and loads

The pencil is clamped at its ends, and only $\mathrm{DX}$ moves are allowed.

## 2 Data simulation

### 2.1 Air base

The modal base, known as "air", is calculated with CALC_MODES. The modes are then normalized to the mass. From this simulation, we recover a *sd_result* *mode_meca* called MODEAIR.

### 2.2 Turbulent efforts

The effort is applied on two nodes, according to a two-component interspectrum. Each spectrum applied is in the shape of a Gaussian. Both excitations are decorated (the $(1,2)$ interspectrum is a null function).

The DYNA_ALEA_MODAL operator calculates the modal displacements from this effort for the MODEAIR base, and REST_SPEC_PHYS returns these movements on a physical basis, with only 19 points, that simulate the experimental measurement. This result is called SPECTR19.

### 2.3 Models of effort and commandability

The user must define the experimental mesh used during the experiment, as well as the positions of the point points on which he wishes to project the identified forces (commandability), with the associated degrees of freedom:

1. translation if one wishes to identify only one-off efforts,
2. translation and rotation if one wishes to identify effort and point moments.

## 3 Launch of CALC_ESSAI

The command used for the launch of the macro is as follows:

CALC_ESSAI( INTERACTIF = 'NON',

EXPANSION = _F(CALCUL = MODEAIR,

NUME_MODE_CALCUL = (1,2,3,4,5,6,7,8,),

MESURE = MODCRA,

NUME_MODE_MESURE = (1,2,3,4,5,6,7,8,)),

IDENTIFICATION = _F(ALPHA = 0.0,EPS = 0.0,

INTE_SPEC = SPECTR19,

OBSERVABILITE = OBS,

COMMANDABILITE = COM,

BASE = MODEAIR),

RESU_IDENTIFICATION = (_F(TABLE = CO("EFFORTS")),

_F(TABLE = CO("DEPL_PHY")),

_F(TABLE = CO("DEPL_SYN")),),

);

### 3.1 Meaning of keywords

#### 3.1.1 EXPANSION module

The EXPANSION module allows the MACRO_EXPANS macro to be launched, which expands experimental data on a digital model. It uses EXTR_MODE, PROJ_MESU_MODAL, REST_GENE_PHYS and PROJ_CHAMP operators.

In this test case, MODCRA modes 1, 2, 3, 4, 5 and 6 are extended using the MODEAIR base modes 1, 3, 4, 5, 6, 7 as the expansion base.

The new RESU_NX, RESU_EX, RESU_ET and RESU_RD concepts are created in the macro-command. In interactive mode, the naming can be done in an interactive way.

#### 3.1.2 FLUDELA module

The fludela module was removed in version 9 of Code_Aster. This was a feature to identify the mass coefficients, stiffness and damping added by comparison with each other of the modal bases of the structures identified in air, water and flow.

NB: At the end of the command file, we show how to simulate the watering and flow of the calculated mode base, with the operators DEFI_FLUI_STRU and CALC_FLUI_STRU (axial flow hypothesis).

#### 3.1.3 IDENTIFICATION module

The principle of the "IDENTIFICATION" tab is to identify an interspectrum effort from the interspectrum data of displacements measured on a structure.

- interspectrum: keyword INTE_SPEC, we take SPEC19,
- modal base: keyword BASE, RESU_ET is taken, obtained in the "correlation" tab,
- mesh d
- mesh commandability: keyword MODELE_COMMANDE, we take MODPROJ2,
- Regularization parameters: they are zero in the test case, but are intended to be adjusted when using actual (noise) measurement data.

In non-interactive mode, the output of the identification module is by default:

- the interspectrum of the identified efforts (called ‘EFFORTS'),
- the input displacement interspectrum (called "DEPL_PHY"),
- the interspectrum of re-synthesized movements (called "DEPL_SYNTH", to be compared with the previous).

Interspectres are sd_table_function data structures. Attention: This data structure is reserved for small interspectres, ideally for measured data (in the order of a few dozen max measuring points). They are not suitable for large numerical data. Interspectral matrices are indeed full square matrices of size ${\mathit{nb}}_{\mathit{ddl}}^{2}$ .

## 4 Audit of the quality of results

The quality of the identification performed is verified by calculating the RMS value of the difference between the measured and re-synthesized displacements.

The reference value to be reached is zero, with an accuracy of ${10}^{-3}$ , compared to the value of the RMS of the measured displacement (in the order of ${10}^{1}$ ).

This verification can be performed in the real case where we do not know the applied efforts (since we want to identify them), and that the only criterion of quality of the opposite problem result, is the ability of the efforts to recover the measured displacements. But we must not forget that several different inputs can lead to the same measured displacement. The choice of the priori location of the efforts is important. It is recalled that for the inverse problem to be over-determined, we must respect double-inequality ${\mathit{nb}}_{\mathit{mes}}>{\mathit{nb}}_{\mathit{modes}}>{\mathit{nb}}_{\mathit{act}}$ , or ${\mathit{nb}}_{\mathit{mes}}$ is the number of measuring points, ${\mathit{nb}}_{\mathit{modes}}$ is the number of modes used in the modal decomposition, and ${\mathit{nb}}_{\mathit{act}}$ is the number of locations of the forces chosen a priori.

In the case of an attempt to identify a fluid force applied to a linear structure, generally only an "equivalent" effort applied to an point of the structure is identified.
