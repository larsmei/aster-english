# v1.01.102 ZZZZ102 - Read accelerogram and oscillator spectrum

**Summary:**

This test concerns:

1. reading in different formats of an accelerogram on an external file (LIRE_FONCTION [U4.21.08](doc:u4.21.08)) and testing the attributes of the function and the maximum value,
2. verification of the calculation of the oscillator spectrum by CALC_FONCTION [U4.62.04](doc:u4.62.04) and the high frequency acceleration value ($>35.5\mathrm{Hz}$) as a function of the max value of the accelerogram,
3. playing a spectrum of free-format oscillators on an external file (LIRE_FONCTION [U4.21.08](doc:u4.21.08)).

There is no mesh or finite element model.

## 1 Reference problem

Several signal readings are to be performed:

- readout of an uncentered accelerogram (maximum amplitudes $>0$ and $<0$ different) expressed in $g$ ($9.81{\mathrm{m.s}}^{-2}$) and search for maximum amplitude,
- calculation of oscillator spectra for reduced depreciation $\xi =0.01$ ($1\text{\%}$ ) with calculation options:
- pseudo absolute acceleration and regain the high frequency drive acceleration ($f\ge 100\mathrm{Hz}$ ),
- relative displacement,
- reading a centered accelerogram (LBEW: Long Beach East West earthquake) and searching for maximum amplitude,
- calculation of the oscillator spectrum in absolute pseudoacceleration,
- reading a spectrum of oscillators in free format.

### 3.4 Remarks

![Figure](/figures/v1.01.102/1000000000000461000003183E025468D0247D0D.jpg)

The integration accuracy of the oscillator spectrum is not always satisfactory with the default frequent list (on the asymptotic value, the difference to reference solution reaches almost 10%). Indeed, this list cuts to $35,5\mathrm{Hz}$ , while the input signal has a significant frequency content up to more than $50\mathrm{Hz}$ ... As can be seen in the figure below (spectrum 2):

In general, the user is strongly advised to always check the frequency content (cut-off frequency, sampling) of the signal to be processed in advance. This will allow the best possible adjustment of the frequency list for the calculation of the oscillator spectrum.

This test case is precisely the example for which the frequency range needs to be expanded, in order to capture the high frequencies of the input signal.

In practice, a frequency list is defined from $0,1\mathrm{Hz}$ to $100\mathrm{Hz}$ by step of $0,05\mathrm{Hz}$ , which will be used for the calculation of the oscillator spectrum. the difference at the reference value for the pseudoacceleration asymptote then becomes less than 0.02%.

All of these attributes of the functions read or created are tested and accurate.

## 5 Summary of the results

The oscillator spectrum algorithm does not provide sufficient accuracy with the default integration frequency list. Indeed, the input signal has frequent content up to $50\mathrm{Hz}$ , while the default frequency list for CALC_FONCTION SPEC_OSCI stops at $35,5\mathrm{Hz}$ .

In this example, the frequency list must therefore be modified at the operator's input. It is therefore necessary to be careful about the spectral content of the signal and not to trust blindly the default values (the default list is well suited to the regulatory signals that are usually encountered in France with a lower cut-off frequency: from the order of $20$ to $30\mathrm{Hz}$). Similarly, if the input signal is characterized by particularly fine frequent discretization, it may be appropriate to use a correspondingly defined frequency list for the calculation of the oscillator spectrum. Again, the default values may prove inappropriate and cause a loss of precision on the results thus calculated.
