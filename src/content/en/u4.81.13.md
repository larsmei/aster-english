# u4.81.13 Operator MACR_LIGN_COUPE

## 1 Purpose

Extraction into a table of the values of a result on section lines defined by two points and an interval or by node groups.

The result may be mechanical (evol_elas, evol_noli, mode_meca, comb_fourier, mult_elas, fourier_elas, dyna_trans) or thermal (evol_ther).

Principle:

This macro-command creates a mesh which may be:

- straight, defined by the data of its end points and of a number of intervals making it up;
- curved, defined by the data of the centre and of the angle of a circle, of the first point of the section
line, of the number of points desired, and possibly of a vector normal to the plane containing
the section line (in 3D only);
- arbitrary, when the section line constitutes a path linking the nodes of a node group.

The fields of the result supplied (by default displacement or temperature) are projected onto this
mesh by means of the command PROJ_CHAMP.
The nodal values on the section line of the field to be post-processed are then recovered
in a table by POST_RELEVE_T. It is this table which is produced by the macro-command.

```text
♦    NOM_CHAM            =    /    'SIGM_NOEU',    [DEFAUT si mécanique]
```

**Note:**

*The macro-command processes all types of field:* *NOEUD,* *ELEM,* *ELNO.*

*It is not recommended to use the field type* *ELNO,* *because the result of the projection of an* *ELNO* *field by* *PROJ_CHAMP* *is sometimes a little disconcerting. For a node, its value is recovered in one of the mesh cells which contain this node. More detail in Chapter* *3.13*  [u4.72.05](doc:u4.72.05).

### 3.9 keyword LIGN_COUPE

```text
♦    LIGN_COUPE    =    _F(
```

repeatable keyword making it possible to define one or several section lines.

A section line is composed of segments with 2 nodes which can describe:

- either a straight line,
- or an arc of a circle or a circle,
- or an arbitrary broken line.

In the first case, the section line is composed of a straight segment, defined by its two
end points and a number of regular intervals cutting it up.

In the second case, the section line is composed of homogeneous straight segments, whose union
forms an arc of a circle, or, as a particular case, a circle.

In the third case, the section line is defined from node groups or mesh-cell groups
of the mesh: the section line is then the path defined by the succession of the nodes of the
group.

#### 3.9.1 Operand INTITULE

```text
♦    INTITULE    =        txt,    [Kn]
```

Heading label in the table making it possible to distinguish the different section lines.
If this keyword is not supplied, the heading label is equal to ‘l.coupe(n)’ where (n) is the
occurrence number of the section line.

#### 3.9.2 Operand TYPE

This keyword makes it possible to define the type of section line that one wishes to create.
It can be identified with SEGMENT, GROUP_NO, GROUP_MA or ARC.

##### 3.9.2.1 TYPE='SEGMENT'

The section line is identified with a straight segment, defined by its two end points and
a number of regular intervals cutting it up.

##### 3.9.2.2 TYPE='GROUP_NO'

The section line is defined by the data of node groups in the mesh supporting
the fields: the section line is then the path defined by the succession of the nodes of these groups.

##### 3.9.2.3 TYPE='GROUP_MA'

The section line is built from the nodes of a mesh-cell group made up of mesh cells
of type SEG. The section line is then the path defined by the succession of the reordered nodes
of this group. If the line is closed, this must be specified by designating the origin and
end nodes (for example with the keywords GROUP_NO_ORIG and GROUP_NO_EXTR). These 2 nodes must
be identical. To impose the orientation of the line, the keyword VECT_ORIE can be used.

For more details concerning these keywords, consult the documentation of the keyword NOEUD_ORDO
of the command DEFI_GROUP.

##### 3.9.2.4 TYPE='ARC'

The section line amounts to an arc of a circle or to a complete circle. It is defined by the
following data:

- a first point corresponding to the origin of the circular section line,
- a second point corresponding to the centre of the circle,
- an angle (expressed in degrees) making it possible to determine the end of the section line,
- a number of points constituting the section line,
- a vector normal to the plane containing the section line in 3D only.

#### 3.9.3 Operand NB_POINTS

```text
♦    NB_POINTS        =    nb,        [I]
```

Number of points of the section line.

#### 3.9.4 Operand COOR_ORIG

```text
♦    COOR_ORIG        =    (x1,y1,[z1]),    [l_R]
```

Coordinates of the first point of the section line: 2 reals in the plane, 3 in space.
This keyword is used for TYPE='SEGMENT' or TYPE='ARC'.

#### 3.9.5 Operand GROUP_NO_ORIG

```text
♦    GROUP_NO_ORIG    =    gnoA,        [group_no]
```

Name of the node group defining the first point of the section line. This group must
contain only one node. This keyword is used for TYPE='SEGMENT'.

#### 3.9.6 Operand COOR_EXTR

```text
♦    COOR_EXTR        =    (x2,y2,[z2]),    [l_R]
```

Coordinates of the last point of the section line: 2 reals in the plane, 3 in space.
This keyword is used for TYPE='SEGMENT'.

#### 3.9.7 Operand GROUP_NO_EXTR

```text
♦    GROUP_NO_EXTR    =    gnoB,        [group_no]
```

Name of the node group defining the last point of the section line.
This group must contain only one node. This keyword is used for TYPE='SEGMENT'.

#### 3.9.8 Operand GROUP_NO

```text
♦    GROUP_NO    =    gno,    [grno]
```

This keyword makes it possible to extract the values on a given node group. In the case of the processing
of fields at the nodes, this is perfectly analogous to POST_RELEVE_T. This keyword is used only
for TYPE='GROUP_NO'.

#### 3.9.9 Operands GROUP_MA and MAILLAGE

```text
♦    GROUP_MA    =    grma,    [l_grma]
```

This keyword makes it possible to pass the mesh-cell group of type SEG used in order to extract the
nodes from it so as to reorder them before the post-processing.

```text
♦    MAILLAGE    =    mail,    [maillage]
```

mail is the mesh concept containing the mesh-cell group grma.

These keywords are used for TYPE='GROUP_MA'.

#### 3.9.10 Operand DNOR

```text
◊    DNOR    =    (xa,ya,[za]),        [l_R]
```

The vector to be transmitted to this keyword must be normal to the plane containing the circular section line.

In 2D: it is unnecessary (DNOR = vector $Z$ of the global frame)

In 3D: it makes it possible to define the direction of travel of the section line (direct sense).

This keyword is used for TYPE = 'ARC'.

#### 3.9.11 Operand CENTRE

```text
♦    CENTRE        =    (x0,y0,[z0]),        [l_R]
```

Coordinates of the point corresponding to the centre of the circle supporting the circular section line.
This keyword is used for TYPE ='ARC'.

#### 3.9.12 Operand ANGLE

```text
♦    ANGLE    =     theta ,    [R]
```

It corresponds to the angle of the circle supporting the circular section line (expressed in degrees)
which, from its centre, from the origin point and from the plane containing the section line, determines
the end of the section line. This keyword is used for TYPE = 'ARC'.

#### 3.9.13 Operands DISTANCE_MAX and DISTANCE_ALARME

```text
◊     DISTANCE_MAX        =    distmax,    [R]

◊     DISTANCE_ALARME    =    distala,    [R]
```

These keywords are useful to the operator PROJ_CHAMP (a single PROJ_CHAMP for the whole command).

If the distance between a node of the section line and the cut mesh is greater than distmax,
then this node will be ignored (no recording of a value on this node).

If the distance between a node of the section line and the cut mesh is greater than distala,
an alarm will be issued.

The minimum values of DISTANCE_ALARME and DISTANCE_MAX are retained over all the
occurrences of LIGN_COUPE. If no value is supplied for all the LIGN_COUPE,
$0$ is taken by default.

The user is invited to consult the documentation [U4.72.05](doc:u4.72.05) for further information.

#### 3.9.14 Operands REPERE

```text
◇ REPERE = / "INITIAL" (par défaut),
           / "LOCAL",
           / "POLAIRE",
           / "UTILISATEUR",
           / "CYLINDRIQUE",
```

Makes it possible to define the frame in which one wishes to express the result produced.
INITIAL makes it possible to keep the frame of the original field.
The other options are valid only for fields expressed in the global frame.
For more details, see documentation [U4.81.21](doc:u4.81.21).

#### 3.9.15 Operands INVARIANT / ELEM_PRINCIPAUX / RESULTANTE / OPERATION / NOM_CMP / TRAC_NOR / TRAC_DIR / DIRECTION / VECT_Y/ REPERE

See documentation [U4.81.21](doc:u4.81.21).

Note: VECT_Y is useful only in 3D.
For sections of segment type in 2D, the tangent vector is obtained automatically by a rotation of $-\pi /2$ in the plane.

## 4 Example

```python
resu = STAT_NON_LINE (...);

tab1 = MACR_LIGN_COUPE(RESULTAT = resu,
                       LIGN_COUPE =(
                           _F(TYPE= ‘SEGMENT’,
                               NB_POINTS = 17,
                               COOR_ORIG = (0.,0.,0.),
                               COOR_EXTR = (10.,0.,0.),
                               INTITULE = ‘ligne1’, ),
                           _F(TYPE= ‘SEGMENT’,
                               NB_POINTS = 25,
                               COOR_ORIG = (-10.,0.,0.),
                               COOR_EXTR = (0.,20.,0.),
                               INTITULE = ‘ligne2’,),
                            )
                       );

IMPR_TABLE(TABLE=tab1)
```

In this example, the values of the displacement obtained in the result resu are recorded at all the
analysis time instants on two section lines.

The table tab1 contains the order numbers, the curvilinear abscissae, the coordinates of the points
and finally the values of the nodal quantity (grandeur) (on the nodes of the line) of the field processed,
here by default the displacement.

## 5 Visualisation

### 5.1 Output file

For results of extraction type, the user has the possibility of producing a file in
MED format by supplying the keyword UNITE_RESU.

The fields contained in this file are the following:

**CUT_AXE_X**

Vector X of the frame in which the results are expressed.

**CUT_AXE_Y**

Vector Y of the frame in which the results are expressed.

**CUT_AXE_Z**

Vector Z of the frame in which the results are expressed.

**CUT_AXE_MASK**

Field equal to 1.0 at the end nodes of the sections and 0.0 elsewhere (makes it possible to filter these
nodes).

**CUT_XXXX**

Field of the quantity (grandeur) post-processed in MACR_LIGN_COUPE.

For each section, a group named "CUT_" followed by the heading of the section is generated. It
can be used to filter the sections.

- It is not possible to write in continuation of an existing file (the .med file is reinitialised at
each call of MACR_LIGN_COUPE)
- The frames of the results are printed only when they are known with certainty
(see keyword REPERE_INIT)
