# u4.53.01 Operator DYNA_NON_LINE

## 1 Purpose

Compute the dynamic evolution of a structure whose material or geometry has a non-linear behaviour or frictional contact. The syntax of this command is very similar to that of the operator STAT_NON_LINE [U4.51.03](doc:u4.51.03).

The dynamic evolution is studied from an initial state, the reference configuration, which may be produced by a previous quasi-static analysis (operator STAT_NON_LINE [U4.51.03](doc:u4.51.03)) or a previous dynamic analysis (operator DYNA_NON_LINE).

The dynamic evolution may be studied in several successive jobs, by a restart from a time instant already computed, if a database has been defined in the user's study profile.

Produces a concept of type evol_noli.

### 3.3 Operands MODE_STAT/MASS_DIAG

```text
◊    MODE_STAT = modestat
```

Name of the static mode required in the case of an analysis with multi-support excitations [R4.05.01](doc:r4.05.01). They are computed beforehand by the operator MODE_STATIQUE [U4.52.14](doc:u4.52.14) with the option ‘MODE_STAT'.

```text
◊    MASS_DIAG =     /    'OUI',
/    'NON',
```

Option to be used with an explicit time scheme [bib2] and which makes it possible to solve with a lumped (diagonalised) mass matrix. This option is not available for all types of elements, in particular the discrete elements (in that case, one must solve with the consistent mass matrix). In the implicit case it is not possible to use a lumped matrix (a fatal error is emitted if the user is in that case).

### 3.4 Keyword EXCIT

```text
◊    EXCIT =_F
```

This factor keyword makes it possible to describe, at each occurrence, a load (excitations and boundary conditions), and possibly a multiplying coefficient and/or a type of load.

The operands have the same meaning as in the document [U4.51.03](doc:u4.51.03), but there are a few specific features related to dynamics.

**Important note for the time schemes:**

*If one imposes displacement boundary conditions which evolve in the course of time, one must take into account the primal unknown of the scheme used. These conditions are in fact imposed in acceleration in the explicit case (because that is the primal unknown). This means that one must enter in* *DYNA_NON_LINE the second derivative of the displacement signal which one wants to impose. This evolution of the imposed displacement must therefore be differentiable at least twice with respect to time.*

#### 3.4.3 Operands MULT_APPUI/ACCE/VITE/DEPL/DIRECTION/GROUP_NO

```text
◊    MULT_APPUI=    /'NON',                        [DEFAUT]
/'OUI',

♦    ACCE        =    ac,                                [fonction]

♦    VITE        =    vi,                                [fonction]

♦    DEPL        =    dp,                                [fonction]

◊    DIRECTION    =    (dx,dy,dz,drx,dry,drz),        [l_R]

◊    GROUP_NO    =    lgrno,                            [l_groupe_no]
```

It is pointed out that the multi-support analysis rests fundamentally on the additive superposition of the motions, cf. [R5.05.05, §2.6]; therefore, if the static, elastic modes are solutions which generate strains in the structure, then for the superposition to be valid, the constitutive behaviour of the constituent materials must be linear, and the kinematics must be linear as well.

The entrainment motions, which are functions of time, therefore produce inertia forces which are added to the other loads, and the solution produces a dynamic response under the assumption of fixed supports. These entrainment inertia forces are built with the operator CALC_CHAR_SEISME [U4.63.01](doc:u4.63.01) from the static modes and the mass matrix. Only the entrainment acceleration at each support is therefore used for the solution, and the velocities and displacements at each support serve only to reconstruct, by additive superposition, the complete solution in velocities and displacements. One notes that the damping forces come only from the velocities solved under the assumption of fixed supports, and not from the complete velocities reconstructed by superposition with the velocities at each support.

In the case of a multi-support excitation (MULT_APPUI= 'OUI'), the other operands have exactly the same meaning as in the factor keyword EXCIT of the operator DYNA_VIBRA [U4.53.03](doc:u4.53.03). In this case, the fields ‘DEPL’, ‘VITE’, ‘ACCE’ correspond respectively to the displacements, velocities and accelerations, functions of time, of the entrainment motion on the supports specified in ‘GROUP_NO’ and for the direction ‘DIRECTION’. The new fields ‘DEPL_ABSOLU’, ‘VITE_ABSOLU’, ‘ACCE_ABSOLU’ are then created in the concept of type evol_noli produced by the operator DYNA_NON_LINE and correspond respectively to the displacements, velocities and accelerations of the absolute motion, sums of the entrainment motion on the supports and of the relative motion with respect to this multi-support entrainment motion.

The linear elastic solutions associated with the unit entrainment motions on the supports, cf. [R5.05.05, §2.6], are described by the static modes MODE_STAT supplied under the corresponding keyword, see §3.3. If that is not the case, one must then describe the excitations by imposed displacements which are functions of time on all the supports, and the solution will be carried out in the absolute reference frame.

### 3.19 Description of the time-integration scheme [R5.05.05](doc:r5.05.05)

```text
♦    SCHEMA_TEMPS    =_F()
◊    STOP_CFL    =    /'OUI',                    [DEFAUT]
                      /'NON',
◊    FORMULATION=    /'DEPLACEMENT',
                     /'VITESSE',
                     /'ACCELERATION',
```

One may use the implicit methods of Newmark (keyword SCHEMA='NEWMARK', or modified average acceleration: SCHEMA='HHT' with MODI_EQUI = 'NON'), or of Hilber-Hughes-Taylor (HHT) (SCHEMA='HHT' with MODI_EQUI = 'OUI').
It is also possible to use the version without overshooting of the complete HHT scheme (see [R5.05.05](doc:r5.05.05) for further details), via the keyword SCHEMA='NOHHT' (see [R5.05.05](doc:r5.05.05)).
Otherwise, one may choose an explicit method of central-difference type (keyword SCHEMA='DIFF_CENT') or a dissipative scheme of TCHAMWA type (keyword SCHEMA='TCHAMWA')

With an implicit scheme, the solutions in displacement, velocity or acceleration are currently available (keyword FORMULATION = 'DEPLACEMENT', 'VITESSE' or 'ACCELERATION').
It should be noted that the solution in velocity is not available for the HHT schemes (keyword SCHEMA = 'HHT' or 'NOHHT').
Furthermore, with an explicit scheme, one can solve only in acceleration (keyword FORMULATION = 'ACCELERATION').

The explicit schemes being conditionally stable, it may be useful to check whether the time step given as input of the analysis does indeed comply with the stability condition (CFL condition). If STOP_CFL = 'OUI' (default), then if the list of time instants supplied by the user contains one or more time steps greater than the stability condition, the analysis stops in fatal error. If STOP_CFL = 'NON', one emits an alarm and continues the analysis.

In every case, the critical time step is given in the message file for information.

The computation of the CFL is not programmed for all the elements (in particular the discrete elements are ignored); the CFL estimated by *Code_Aster* may therefore be larger (less penalising) than the real CFL, with the risks of sudden divergence which follow from that.

In the explicit case, it is also recommended to use a lumped (diagonalised) mass matrix: which one can obtain with the keyword MASS_DIAG = 'OUI' [§ 7].

**Notes:**

- The choice *MASS_DIAG='NON' is not recommended with the shells* *DKT.*
- *With the elements* *DKT/DKTG it is necessary to specify in* *AFFE_CARA_ELEM, under the factor keyword* *COQUE, the simple keyword* *INER_ROTA = 'OUI'. Otherwise the mass matrix is singular and* *the explicit scheme* *is unusable.*
- *In the explicit case, one does not recommend the use of quadratic finite elements (which can generate spurious oscillations on the solution fields).*

***For the multi-step schemes (Newmark with* MODI_EQUI='OUI'*), it is necessary to recompute the internal forces at the previous time instant. This mode of operation is problematic at the first time instant of a restart of an analysis. Indeed, if one has command variables (which therefore depend on the analysis time instant), it is necessary to recover the value at the previous time instant. This is not always possible, in particular if one is not in* reuse *and if* ETAT_INIT *is made from individual fields (no use of the keyword* ETAT_INIT/EVOL_NOLI *). In that case, one does not compute this contribution at the previous step, which may possibly modify the convergence of the algorithm slightly.***

*It is therefore strongly recommended to specify the initial state via the keyword ETAT_INIT/EVOL_NOLI, in order to allow the computation of the internal forces at the previous time instant.*

#### 3.19.1 Case SCHEMA = 'NEWMARK'

> ◊    BETA         =    /0.25,                            [DEFAUT]

> /beta,                            [R]

> ◊    GAMMA         =    /0.5,                            [DEFAUT]

> /gamm,                            [R]

The time-integration method is that of NEWMARK, with the given values of the parameters beta and gamm.

When one specifies neither beta nor gamm, one has the method known as the “trapezoidal rule” ($beta=0.25$  ; $\mathrm{gamm}=0.5$) which, in the linear case, is unconditionally stable and introduces no spurious dissipation (*i.e.* numerical damping), but which, in the non-linear case, may be unstable [bib1][bib2].

#### 3.19.2 Case SCHEMA = 'HHT'

```text
◊    ALPHA         =    /-0.1,                            [DEFAUT]
/alph,                            [R]

◊    MODI_EQUI    =    /'OUI',                        [DEFAUT]
/'NON',
```

For MODI_EQUI = ’NON’, the time-integration method (implicit integration scheme) is that of the modified average acceleration (of the Newmark family) ([bib1], [bib2]), with the given negative value of alph. The larger |alph| is, the larger the numerical damping introduced by the analysis. But this dissipation is sometimes necessary, in the non-linear case, in order to ensure stability (unless one assigns a damping by material to the structure).

For MODI_EQUI = ’OUI’ (default value), the time-integration method (implicit integration scheme) is that of Hilber-Hughes-Taylor (HHT or $\alpha -\text{méthode}$) [bib2], with the given negative value of alph. The larger |alph| is, the larger the numerical damping introduced by the analysis. Compared with the previous scheme (MODI_EQUI = ’NON’) of modified average acceleration, the numerical damping induced is more “selective”: it is weaker at low and medium frequencies (asymptotically zero at zero frequency) and it increases more quickly when the frequency becomes large.

This second scheme is based on the first one with, in addition, a modification of the equilibrium equation (one shifts the internal and external forces in time) [bib2].

#### 3.19.3 Case SCHEMA = 'DIFF_CENT'

The central-difference scheme is an explicit scheme of order two of the Newmark family, with parameters BETA = 0 and GAMMA = 0.5. It is a one-step scheme which presents no numerical dissipation.

#### 3.19.4 Case SCHEMA = 'TCHAMWA'

```text
◊    PHI            =    /1.05,                            [DEFAUT]
/phi,                            [R]
```

An alternative to the central-difference schemes is the scheme developed by Bertrand Tchamwa and Christian Wielgosz.

This explicit scheme has several interesting particular features. It is not a derivative of Newmark, and the variation of its parameter PHI allows a controllable numerical dissipation of the high frequencies. When it is equal to 1, the dissipation is zero. In order not to degrade the Courant condition too much and to retain stability properties comparable to the central-difference scheme, it is recommended not to choose a PHI greater than 1.10. 1.05 is the value chosen by default.

#### 3.19.5 Operand COEF_MASS_SHIFT

```text
◊     COEF_MASS_SHIFT =    /0.                        [DEFAUT]

                 /coef
```

The datum of the coefficient coef makes it possible to carry out a shift of the mass matrix $M$, which becomes:

$M'=M+\mathit{coef}K$

The value of this coefficient, zero by default, must be non-zero in order to be able to invert, in dynamics with an explicit scheme, the mass matrix when the latter has zero terms for certain specific degrees of freedom, for example the pressure for the elements of HM modelling.

Entering this coefficient also makes it possible to improve greatly the convergence in dynamics with an implicit scheme in this same type of modelling, by imposing a cut-off frequency inversely proportional to the value of coef (at the price of a slight distortion of the whole set of eigenfrequencies of the system)

This keyword makes it possible to trigger the computation, at the end of each time increment, of a search for vibration eigenmodes.

This criterion is useful in order to follow, in the course of the transient analysis, the evolution of the vibratory response of the non-linear structure.

This criterion is computed in the following way: at the end of a time step, one solves $det(K-{\omega}^{2}.M)=0$ . $K$ may be either the elastic stiffness matrix, or the consistent tangent matrix at the current time instant, or the secant matrix. $M$ is the mass matrix. This modal analysis is allowed only for symmetric matrices (mass and stiffness).

The keyword OPTION makes it possible to choose the type of search:

- OPTION='PLUS_PETITE': the NMAX_FREQ eigenvectors and eigenvalues corresponding to the smallest eigenvalues;
- OPTION='BANDE': the eigenvectors and eigenvalues for the frequencies lying in the band FREQ;
- OPTION='CALIBRATION', of which only the number of eigenvalues for the frequencies lying in the band FREQ.

The whole of the results is stored in a data structure of type table_container of name 'ANALYSE_MODALE' attached to the data structure evol_noli. The vibration modes are stored as TYPE_MODE='DEPL_VIBR' in the table (see § 4).

The time instants for which one wants to carry out a computation of a vibration mode are given by a list of time instants LIST_INST or INST (list_r8 or l_r8) or by a frequency PAS_CALC (every $\mathit{npas}$ time steps).

In the absence of these keywords the vibratory modal analysis is carried out at all the time steps.

The keywords PRECISION and CRITERE make it possible to select the time instants, *cf.* [U4.71.00](doc:u4.71.00).

**Note on the list of time instants:**

If LIST_INST or INST of MODE_VIBR contains time instants equal to or earlier than the initial time instant of DYNA_NON_LINE, *Code_Aster* will ignore the computation of the vibration modes for these time instants.

One will then also have to supply the operands of the keyword ETAT_INIT with the corresponding fields of displacement, velocity, acceleration, stress and internal variable of the reduced model. ## 6 Example: motion of a pendulum of large amplitude

```text
#    TITRE Pendule simple en grande oscillation

#

#    PENDULE CONSTITUE D’UN ELEMENT DE CABLE (test SDNL100A).

#

RESU=DYNA_NON_LINE( MODELE=MO, CHAM_MATER=CHMAT, CARA_ELEM=CARA,

EXCIT=( _F( CHARGE = CHA1),

_F( CHARGE = CHA2)),

INCREMENT=_F( INST_INIT = 0., LIST_INST = L_INST1),

ARCHIVAGE=_F( LIST_INST = L_INST2),

SCHEMA_TEMPS=_F( SCHEMA='NEWMARK',

FORMULATION='DEPLACEMENT'),

COMPORTEMENT=_F( RELATION = 'CABLE',

DEFORMATION = 'GREEN'),

CONVERGENCE=_F( RESI_GLOB_RELA = 1.E-6,

ITER_GLOB_MAXI = 100),

NEWTON=_F( REAC_ITER = 1)

)

FIN()
```

- the load cha1 imposes on node 1 to remain fixed and on node 2 to move in the vertical plane XZ,
- the load cha2 is gravity,
- the command DYNA_NON_LINE specifies that:
- the time-integration method will be that of 'NEWMARK', the “trapezoidal rule” (also called average acceleration), because there is no argument under 'NEWMARK',
- the initial state, at time instant 0, is at zero displacement, that is to say that the displacements will be evaluated from the initial position, and at zero velocity,
- the iterative analysis will continue as long as the relative residual is $>{10}^{-2}$ , but the number of iterations will be limited to 100,
- finally the tangent matrix of the linear system to be solved will be re-evaluated at each iteration (by default, since the keyword NEWTON is absent).
