# u4.44.03 Operators AFFE_CHAR_CINE and AFFE_CHAR_CINE_F

## 1 Purpose

Define a loading of type “imposed degrees of freedom”.

This command can be used with a mechanical, thermal or acoustic model. The treatment of these “kinematic” conditions will be carried out without dualisation and therefore without the addition of Lagrange degrees of freedom.

1. For AFFE_CHAR_CINE (except for the case EVOL_IMPO), the assigned values do not depend on any parameter and are defined by real values (mechanical or thermal) or by complex values (acoustic). These values may be zero (restraint).
2. For AFFE_CHAR_CINE_F, the assigned values are functions of one (or several) parameters to be chosen from the set $(\mathrm{INST},X,Y,Z)$.

Produces a data structure of type char_cine_*.

## 3 General remarks

These two commands create concepts of type char_cine_* (_meca/_ther).

The command AFFE_CHAR_CINE can also create concepts of type char_cine_acou.

These types are different from the type charge created by the commands AFFE_CHAR_MECA[U4.44.01], AFFE_CHAR_THER[U4.44.02] or AFFE_CHAR_ACOU[U4.44.04]).

The objects created are therefore not interchangeable.

The advantage of “kinematic” loads is that they do not increase the number of unknowns of the systems to be solved, unlike the method of dualisation by LAGRANGE multipliers, used in the commands producing a concept of type charge.

On the other hand, the use of these loads has the following limitations:

- they can be used only in the case of a relation of type “imposed degree of freedom” (and not for linear relations),
- these loads are not yet accepted in all the global commands. Today the possible commands are:

  - MECA_STATIQUE, STAT_NON_LINE, DYNA_NON_LINE
  - THER_LINEAIRE
- for an analysis that does not use the global commands: assembly of a matrix, then solution, the sequence of commands to be used is more complicated than with “ordinary” loads, as can be seen in example 2 [§ 5.2].

## 4 Operands

### 4.1 General remarks on the operands

The operands under the factor keywords MECA_IMPO, THER_IMPO and ACOU_IMPO are of two forms:

- the operands specifying the geometric entities on which the loadings are assigned (keywords GROUP_MA, GROUP_NO…). The arguments of these operands are identical for the two operators.
- the operands specifying the assigned values (DX, DY, DZ, etc.). The meaning of these operands is the same for the two operators. The arguments of these operands are all of type real for the operator AFFE_CHAR_CINE and of type fonction (or formula) for the operator AFFE_CHAR_CINE_F.

This is true with one exception: the factor keyword ACOU_IMPO (which does not exist in the command AFFE_CHAR_CINE_F) is always of type complex.

We shall therefore not distinguish, in this document, except where expressly stated otherwise, between the two operators AFFE_CHAR_CINE and AFFE_CHAR_CINE_F.

In general, the entities on which values are to be assigned are defined by nodes:

1. either by the operand TOUT = 'OUI', which makes it possible to designate all the nodes of the mesh,
2. or by the operand GROUP_NO, which makes it possible to designate a list of node groups,
3. or by the operand GROUP_MA, which makes it possible to designate all the nodes carried by the mesh cells designated by the lists of GROUP_MA.

### 4.2 Behaviour in the case of overloading:

#### 4.2.1 Overloading within a single command AFFE_CHAR_CINE

When, within one and the same command, one uses several occurrences of MECA_IMPO (or THER_IMPO, ...) and certain nodes are assigned several times, it is the last occurrence which takes precedence. For example:

chcine= AFFE_CHAR_CINE( MECA_IMPO=(

_F( TOUT='OUI', DX= 1., ...)

_F( GROUP_NO='GN3', DX= 3., ...)

In this case, the imposed displacement DX for the node GN3 is: 3.

#### 4.2.2 Overloading between several commands AFFE_CHAR_CINE

If one uses several different commands, the behaviour is different. For example:

chcin1= AFFE_CHAR_CINE( MECA_IMPO= _F( TOUT='OUI', DX= 1., ...)

chcin2= AFFE_CHAR_CINE( MECA_IMPO= _F( GROUP_NO='GN3', DX= 3., ...)

In this case, the imposed displacement DX for the node GN3 is: 4 (because 1+3)

#### 4.2.3 Overloading between AFFE_CHAR_CINE and AFFE_CHAR_MECA

If one “mixes” the commands AFFE_CHAR_MECA and AFFE_CHAR_CINE, the code will stop with a fatal error (FACTOR_41), explaining that there is an over-abundant restraint relation (NOEUDN3 / DX).

### 4.3 Operand MODELE

```text
♦    MODELE = mo
```

Concept produced by the operator AFFE_MODELE[U4.41.01], in which the types of finite elements assigned on the mesh are defined.

### 4.4 Keyword MECA_IMPO

#### 4.4.1 Purpose

Factor keyword usable to impose, at nodes, a displacement value, defined component by component in the global frame.

These boundary conditions will subsequently be treated by the method known as elimination of the imposed degrees of freedom (that is, without dualisation, unlike the treatment of the same type of boundary condition by the use of the operators AFFE_CHAR_MECA or AFFE_CHAR_MECA_F[U4.44.01]).

#### 4.4.2 Syntax

```text
AFFE_CHAR_CINE

    MECA_IMPO =    (_F    (    ♦    /    TOUT =            'OUI'    ,
| GROUP_NO =    lgno    ,            [l_gr_noeud]
| GROUP_MA =    lgma    ,            [l_gr_maille]
♦    |    DX =            ux        ,            [R]
|    DY =            uy        ,            [R]
|    ... (voir la liste complète ci-dessous)
),),

| GROUP_MA =    lgma    ,            [l_gr_maille]
♦    |    DX =            uxf        ,            [fonction(*)]
|    DY =            uyf        ,            [fonction(*)]

),),

fonction(*) : fonction ou formule
```

List of the keywords available under MECA_IMPO in AFFE_CHAR_CINE:

List of the keywords available under MECA_IMPO in AFFE_CHAR_CINE_F:

These are the names of the degrees of freedom carried by the finite elements of the model. The meaning of these names is to be found in the documentation of AFFE_CHAR_MECA [U4.44.01](doc:u4.44.01).

Factor keyword usable to impose, at nodes, a nodal temperature value.

These boundary conditions will subsequently be treated by the method known as elimination of the imposed degrees of freedom (that is: without dualisation, unlike the treatment of the same type of boundary condition by the use of the operators AFFE_CHAR_THER or AFFE_CHAR_THER_F[U4.44.02])

#### 4.5.3 Operands

```text
|    TEMP
```

Temperature imposed on the nodes (or on the middle surface for thermal shells)

```text
|    TEMP_INF
```

Temperature imposed on the lower face for thermal shell elements.

```text
|    TEMP_SUP
```

Temperature imposed on the upper face for thermal shell elements.

For shells, the lower and upper faces are defined, mesh cell by mesh cell, by the direction of the outward normal deduced from the numbering of the nodes: see FACE_IMPO of AFFE_CHAR_MECA[U4.44.01].

### 4.6 Keyword ACOU_IMPO

#### 4.6.1 Purpose

Factor keyword usable to impose, at nodes, an acoustic pressure value.

These boundary conditions will subsequently be treated by the method known as elimination of the imposed degrees of freedom (that is: without dualisation, unlike the treatment of the same type of boundary condition by the use of the operator AFFE_CHAR_ACOU[U4.44.04]).

#### 4.6.2 Syntax

For AFFE_CHAR_CINE

```text
/    ACOU_IMPO = (_F    (    ♦    /    TOUT =                'OUI'    ,
| GROUP_NO =    lgno    ,            [l_gr_noeud]
| GROUP_MA =    lgma    ,            [l_gr_maille]
♦    PRES =                    p        ,        [C]
),    ),
```

For AFFE_CHAR_CINE_F:

No keyword ACOU_IMPO, because there is not yet a complex function.

#### 4.6.3 Operands

```text
PRES
```

Value of the complex acoustic pressure imposed on the specified node(s).

### 4.7 Keyword EVOL_IMPO

```text
/    EVOL_IMPO = evoimp        /    [evol_ther]
/    [evol_elas]
/    [evol_noli]
◊    NOM_CMP = lcmp            [l_TXM]
```

This keyword makes possible the “structural zoom” (see for example the test zzzz230a).

The effect of this keyword is to impose **all** the degrees of freedom of the evolution evoimp as if they were functions of time. This possibility is offered for the data structures evol_elas, evol_noli and evol_ther.

To perform a “structural zoom”, the degrees of freedom must be imposed only on the nodes of the boundary of the “zoom” model. This means that, in general, the “coarse” analysis must be projected onto the mesh cells of the boundary of the “zoom” model.

If, moreover, one does not wish to impose all the components, the keyword NOM_CMP must be used to choose the components to be imposed (by default: all).

*Notes:*

- *Take care not to use several* EVOL_IMPO *on common zones (otherwise there will be accumulation of the imposed values)*
- *Take care with the use of* FONC_MULT *with* EVOL_IMPO *: the result may not be what one expects!*
- *The* EVOL_IMPO *will be used for any value of time lying between* $\mathit{tmin}$ *and* $\mathit{tmax}$ *(extreme values of the time instants of the transient* EVOL_IMPO *). Outside this interval, a fatal error is issued (extrapolation forbidden).*
- *If the* EVOl_IMPO *has only one time instant, “constant” extension is allowed and an alarm is issued.*

## 5 Examples

### 5.1 Degrees of freedom imposed in mechanics

```text
chcine =    AFFE_CHAR_CINE    (MODELE = mo,
MECA_IMPO=(
_F    (TOUT = 'OUI'    , DRZ = 0.),
_F    (GROUP_NO = 'bord1',    DX =    0.,    DY =    0.,    DZ =    0.,
DRX =    0.,    DRY =    0.,)))
```

For this plate problem in the plane $\mathrm{XY}$, all the rotational degrees of freedom about $Z$ are restrained and the plate is clamped on its edge $\mathrm{bord1}$.

### 5.2 Compared use of kinematic loads and “ordinary” loads

#### 5.2.1 Global commands

```text
ch1        =    AFFE_CHAR_THER    ( ... )

ch2        =    AFFE_CHAR_CINE_F    ( TEMP_IMPO =    _F ( ... ))

evoth    =    THER_LINEAIRE        (    ...
EXCIT = (    _F (CHARGE = ch1),
_F (CHARGE = ch2),)
...)
```

There is no difference.

#### 5.2.2 “Step-by-step” analysis

**Ordinary loads**

```text
ch1        =    AFFE_CHAR_MECA ( ... )
mel        =    CALC_MATR_ELEM ( ... OPTION = 'RIGI_MECA'    , CHARGE = ch1)
matas    =    ASSE_MATRICE (    MATR_ELEM = mel ...)
matas    =    FACTORISER (    reuse = matas, MATR_ASSE = matas )
U        =    RESOUDRE (    MATR = matas , CHAM_NO = F )
```

**Kinematic loads**

```text
ch1        =    AFFE_CHAR_CINE ( ... )
mel        =    CALC_MATR_ELEM ( ... OPTION = 'RIGI_MECA' )
matas    =    ASSE_MATRICE (    MATR_ELEM = mel, ..., CHAR_CINE = ch1 )
matas    =    FACTORISER (    reuse = matas, MATR_ASSE = matas, )
vcine    =    CALC_CHAR_CINE ( ..., CHAR_CINE = ch2, )
U        =    RESOUDRE (    MATR = matas , CHAM_NO = F,
CHAM_CINE = vcine)
```

The terms induced by the kinematic loads are transferred to the right-hand side, which requires the computation of an additional nodal field vcine by the command CALC_CHAR_CINE[U4.61.03].
