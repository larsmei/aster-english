# u4.71.00 Selection of one or more fields in a RESULTAT data structure

## 1 Purpose

Description of the keywords for access to the fields of quantities (grandeurs) of a data structure of type resultat.

In order to extract a field of quantities (grandeurs) in a result concept one has two types of indicators: the symbolic names and the access variables.

This document describes all the keywords making it possible to access the fields of quantities (grandeurs) contained in a result data structure and used in the commands CALC_CHAMP [U4.81.04](doc:u4.81.04), CALC_G [U4.82.03](doc:u4.82.03), COMB_SISM_MODAL [U4.84.01](doc:u4.84.01), EXTR_MODE [U4.52.12](doc:u4.52.12), IMPR_GENE [U4.91.02](doc:u4.91.02), IMPR_RESU [U4.91.01](doc:u4.91.01), LIRE_RESU [U7.02.01](doc:u7.02.01), POST_ELEM [U4.81.22](doc:u4.81.22), POST_RCCM [U4.83.11](doc:u4.83.11), POST_RELEVE_T [U4.81.21](doc:u4.81.21), RECU_FONCTION [U4.32.03](doc:u4.32.03), TEST_RESU [U4.92.01](doc:u4.92.01).

## 2 Syntax

```text
# Extraction d’un champ de grandeur de resu

    ◇ / TOUT_CHAM = "OUI" (ou non renseigné),
      / NOM_CHAM = text,

    ◇ / TOUT_ORDRE = "OUI" (ou non renseigné),
      / NUME_ORDRE = int,
      / TOUT_INST = "OUI" (ou non renseigné),
      / INST = float,
      / FREQ = float,
      / TOUT_MODE = "OUI" (ou non renseigné),
      / NUME_MODE = int,
      / NOEUD_CMP = text,
      / LIST_INST = listr8,
      / LIST_FREQ = listr8,
      / LIST_ORDRE = listis,
      / LIST_MODE = listis,
      / NOM_CAS = text,
      / ANGLE = float,

    ◇ CRITERE = / "RELATIF" (par défaut),
                / "ABSOLU",
    # Si: (equal_to("CRITERE", 'RELATIF'))
        ◇ PRECISION = float (défaut: 1e-06),
    # Si: (equal_to("CRITERE", 'ABSOLU'))
        ◆ PRECISION = float,
```
## 3 Extraction of a field of a quantity (grandeur)

### 3.1 Choice of the symbolic names: Operands TOUT_CHAM / NOM_CHAM

```text
/    TOUT_CHAM        =    /'OUI'        [DEFAUT]
```
This keyword indicates that one wants to access the field(s) of quantities (grandeurs) actually computed for the result concept RESU. If one does not use the operand NOM_CHAM, this operand is taken by default as 'OUI'.

The possible fields are described in the specific documentations of the result concepts.

Example: the possible fields are, for a result of type evol_elas [U4.51.01](doc:u4.51.01):

```text
DEPL
SIGM_ELNO
EPSI_ELNO
…    …    …
```
```text
/    NOM_CHAM        =    L_NOMSYMB    [:ref:`l_K16 <l_K16>`]
```
A result concept may be composed of several fields of quantities (grandeurs) of nodal-field type or field-by-element type. This keyword makes it possible to choose a list of symbolic field names from among all the possible ones (cf. TOUT_CHAM).

**Note:**

*The keywords* *TOUT_CHAM and* *NOM_CHAM cannot be used simultaneously.*

### 3.2 Choice of the order numbers: Operands TOUT_ORDRE / NUME_ORDRE / LIST_ORDRE

```text
/    TOUT_ORDRE    =    'OUI'            [DEFAUT]
```
This keyword makes it possible to access the field(s) for all the order numbers already computed.

Example:

- all the time instants for a result of type evol_...
- all the eigenmodes for a result of type mode_meca.

```text
/    NUME_ORDRE    :    LORDRE            [l_I]
```
This keyword makes it possible to access only the field(s) corresponding to a list of order numbers LORDRE (the plural is used here for the case where one has chosen TOUT_CHAM='OUI').

```text
Exemple : RESU =(_F( RESULTAT= RESU, TOUT_CHAM = ‘OUI’, NUME_ORDRE= (3,6))
```
One will access all the fields computed at the third and at the sixth order number.

```text
/    LIST_ORDRE    :    LENTI         [listis]
```
The keyword LIST_ORDRE indicates that one wants to access the field(s) corresponding to a list of order numbers LENTI, defined by the operator DEFI_LIST_ENTI [U4.34.02](doc:u4.34.02) (LENTI is therefore a concept of type listis).

Example:

```text
LISTE     =    DEFI_LIST_ENTI (        VALE = (3,6))
RESU =(_F ( RESULTAT= RESU, TOUT_CHAM = ‘OUI’,    LIST_ORDRE= LISTE )
```
One will access all the fields computed at the third and at the sixth order number.

### 3.3 Other ways of choosing the order numbers: access variables

#### 3.3.1 Operands TOUT_MODE / NUME_MODE / LIST_MODE / NOEUD_CMP

```text
/    TOUT_MODE        =    'OUI'
```
This keyword indicates that one wants to access all the fields for all the mode numbers already computed.

It is licit only for the types of result concept (static or dynamic modes) having NUME_MODE as access variable.

```text
/    NUME_MODE        =    LMODE            [l_I]
```
This keyword indicates that one wants to access the field(s) corresponding to a list of mode numbers LMODE. These numbers are those assigned by the analysis algorithm.

It is licit only for the types of result concept (static or dynamic modes) having NUME_MODE as access variable.

```text
Exemple :    RESU =(_F(RESULTAT= RESU, TOUT_CHAM =‘OUI’, NUME_MODE= (3,6))
```
One will access all the fields corresponding to the third and to the sixth mode.

```text
/    LIST_MODE        =    LENTI            [listis]
```
The keyword LIST_MODE indicates that one wants to access the field(s) corresponding to a list of mode numbers LENTI, defined by the operator DEFI_LIST_ENTI [U4.34.02](doc:u4.34.02) (LENTI is therefore a concept of type listis). It is valid only for the types of result concept having NUME_MODE as access variable.

Example:

```text
LISTE     =    DEFI_LIST_ENTI (        VALE = (3,6))
RESU =(_F( RESULTAT= RESU,    TOUT_CHAM = ‘OUI’,    LIST_MODE= LISTE )
```
One will access all the fields corresponding to the third and to the sixth mode.

```text
/    NOEUD_CMP        =    LNOECMP        [:ref:`l_K16 <l_K16>`]
```
Results of type base_modale or mode_stat have NOEUD_CMP as access variable. The value of these access variables is obtained by concatenating the name of the node and the name of the component. In order to specify a value of the access variable, the user will give two names, the name of the node followed by the name of the component. A list of $n$ access variables will be introduced by the data of n pairs (name of the node, name of the component).

A list of values of this access variable can be supplied by the list $(\mathit{couple1},\mathit{couple2},\dots )$ .

#### 3.3.2 Operand NOM_CAS

```text
/    NOM_CAS        =    NCAS            [:ref:`K16 <K16>`]
```
The keyword NOM_CAS indicates that one wants to access the field corresponding to a loading case. It is licit only for result concepts of type mult_elas which have NOM_CAS as access variable and are produced by MACRO_ELAS_MULT [U4.51.02](doc:u4.51.02).

#### 3.3.3 Operand ANGLE

```text
/    ANGLE            =    LANGL            [l_R]
```
The keyword ANGLE indicates that one wants to access the recombined field(s) for a list of angles. It is licit only for result concepts of type comb_fourier which have ANGLE as access variable and are produced by the operator COMB_FOURIER [U4.83.31](doc:u4.83.31).

#### 3.3.4 Operands FREQ / LIST_FREQ

These operands are licit only for the types of result concept having FREQ as access variable (mode_meca, dyna_harm, …).

```text
/    FREQ            =    LFREQ            [l_R]
```
The keyword FREQ indicates that one wants to access the field(s) corresponding to a list of frequencies LFREQ.

```text
Exemple :    RESU =(_F(RESULTAT= RESU, TOUT_CHAM =‘OUI’, FREQ= (3.52,7.37))
```
One will access all the fields corresponding to the frequencies $3.52$ and $7.37$ .

```text
/    LIST_FREQ        =    LREEL            listr8
```
The keyword LIST_FREQ indicates that one wants to access the field(s) corresponding to a list of frequencies LREEL, defined by the operator DEFI_LIST_REEL (LREEL is therefore a concept of type listr8).

Example:

```text
LISTE     =    DEFI_LIST_REEL (        VALE = (3.52,7.37))
RESU =(_F(RESULTAT= RESU,    TOUT_CHAM = ‘OUI’,    LIST_FREQ = LISTE )
```
One will access all the fields corresponding to the frequencies $3.52$ and $7.37$ .

#### 3.3.5 Operands TOUT_INST / INST / LIST_INST

These operands are licit only for the types of result concept of time evolution having INST as access variables (evol_noli, evol_ther, dyna_trans, …).

```text
/    TOUT_INST        =    'OUI'
```
This keyword indicates that one wants to access all the fields for all the time instants already computed.

```text
/    INST            =    LINST            [l_R]
```
The keyword INST indicates that one wants to access the field(s) corresponding to a list of time instants LINST.

```text
Exemple :    RESU =(_F( RESULTAT= RESU,    TOUT_CHAM = ‘OUI’,    INST= (3. , 7.))
```
One will access all the fields corresponding to the time instants $3.$ and $7.$ .

```text
/    LIST_INST        =    LREEL            listr8
```
The keyword LIST_INST indicates that one wants to access the field(s) corresponding to a list of time instants LREEL, defined by the operator DEFI_LIST_REEL (LREEL is therefore a concept of type listr8).

Example:

```text
LISTE     =    DEFI_LIST_REEL (        VALE = (3. , 7.))
RESU =(_F( RESULTAT= RESU,    TOUT_CHAM = ‘OUI’,    LIST_INST= LISTE )
```
One will access all the fields corresponding to the time instants $3.$ and $7.$ .

#### 3.3.6 Operands PRECISION / CRITERE

These operands make it possible to refine the access by real access variables of time or of frequency.

```text
PRECISION =    / prec                        [R]
/ 1.0D-3 ou 1.0D-6        [DEFAUT]
```
This keyword makes it possible to indicate that one searches for all the fields whose time instant (respectively the frequency) lies in the interval "inst ± prec" (cf. CRITERE).

By default prec = 1.0D-3 or prec = 1.0D-6 (according to the commands).

If CRITERE='ABSOLU', there is no default value.

```text
CRITERE     =    / 'RELATIF'    [DEFAUT]
/ 'ABSOLU'
```
'RELATIF': the search interval is: [inst (1 - prec), inst (1 + prec)]

'ABSOLU': the search interval is: [inst - prec, inst + prec].
