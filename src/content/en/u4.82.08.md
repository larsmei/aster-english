# u4.82.08 Operator DEFI_FISS_XFEM

## 1 Purpose

Define a 2D or 3D crack or interface by means of level-set functions.

For cracks, two level-set functions are defined, making it possible to characterise an arbitrary crack (plane or not). For interfaces, a single level set is necessary. The level sets may be defined in four different ways:

- either from two mesh-cell groups (the mesh-cell group of the crack and the mesh-cell group of the crack front);
- or from two analytical functions.
- or from a catalogue of predefined shapes.
- or by rereading already existing nodal fields.

For the 2D case, the mesh cells of the crack front are POI mesh cells; they must not be given as a node group but as a mesh-cell group.

For the 3D case, the crack front is oriented automatically. The ordered list of the points of the front is displayed automatically in the message file, when the command DEFI_FISS_XFEM is passed through. The orientation method, and the specific case in which it does not work, are described in the documentation [R7.02.12](doc:r7.02.12).

This operator does not make it possible to define a crack coinciding with an edge of the structure.

The characteristics linked to contact on the lips of the crack are not given here but in a specific contact load with the operator DEFI_CONTACT. Cohesive forces between the lips of the crack may also be defined, by this same operator. The crack is then generally declared as being of type COHESIF.

The theoretical aspect of the X-FEM method is dealt with in [R7.02.12](doc:r7.02.12), and the user who is not familiar with the use of level sets is advised to read the few explanatory lines relating to the representation of surfaces by the level-set method.

Furthermore, this operator is also used with meshed cracks, prior to the computation of the stress intensity factors in 3D by the operator CALC_G [U4.82.03](doc:u4.82.03) with the option CALC_K_G.

The operator produces a concept of type fiss_xfem.

## 3 Operands

### 3.1 Operand MAILLAGE

```text
♦    MAILLAGE    =    ma
```

ma: name of the mesh on which the crack is to be defined. This mesh is necessarily a 2D or 3D mesh.

**Caution: the quadratic X-FEM elements lack robustness (especially in 3D); it is advisable to use linear X-FEM elements. It is therefore preferable that** **ma be a linear mesh.**

### 3.2 Definition of a grid to be associated with the crack

An auxiliary grid may be associated with the crack:

- either by giving a grid mesh (see § 3.2.1),
- or by giving a crack already associated with a previous grid (see § 3.2.2),

In the case of use of the upwind method in PROPA_FISS (document U4.82.11), its use is almost mandatory.

This keyword is typically used following a refinement by Homard of the mesh on which the crack was defined.

#### 3.2.1 Operand MAILLAGE_GRILLE

```text
◊    MAILLAGE_GRILLE     = magri                                            [maillage]
```

magri: name of the grid mesh to be associated with the crack

This operand is used to associate the grid mesh magri with the crack. The two level-set functions and their gradients are computed both on the mesh ma given by MAILLAGE (see § 3.1) and on the mesh magri according to the method chosen by DEFI_FISS (see § 3.4), and they are stored with the crack. Several cracks may therefore be defined on the same grid magri.

The mesh magri is created by the operator DEFI_GRILLE [U4.24.02](doc:u4.24.02).

The auxiliary grid used must extend only over the zone planned for propagation of the crack, so as to be able to represent the crack front correctly throughout the propagation simulation. It may lie partly outside the mesh ma (keyword MAILLAGE, see § 3.1) and no relationship exists between this mesh and that of the grid magri. In the presence of several cracks and with a different grid used for each, the grids are independent and may overlap partly or totally. In this case a single grid could also be used for all the cracks.

#### 3.2.2 Operand FISS_GRILLE

In the case where a crack has been defined on a mesh with an associated grid and where one wishes to redefine it on another mesh without changing the grid, computing time can be saved by avoiding recomputing the level-set functions on the grid. Indeed, in this case the level-set functions defined on the grid do not change.

This is always the case when Homard is used on the mesh on which the crack was defined, because the grid is not affected by the modifications of Homard and the level-set functions defined initially do not change. The same crack can therefore be redefined on the refined mesh with the same associated grid, by computing the level-set functions only on the mesh and keeping them identical on the grid.

```text
◊    FISS_GRILLE        = fiss_orig,                                    [fiss_xfem]
```

The crack fiss_orig that was defined previously is specified. The grid already present is associated with the new crack and the computed nodal fields that define the level-set functions and their gradients are copied onto the grid for the new crack. This is equivalent to defining the crack fiss_orig on the new mesh while still using the same grid.

**Note:**

*No check can be made of the consistency between the crack that is going to be defined by* *DEFI_FISS (see §*  3.4 *) and that which was defined on the grid of* *fiss_orig.*

### 3.3 Operand TYPE_DISCONTINUITE

```text
◊    TYPE_DISCONTINUITE        =    /    'FISSURE',                [DEFAUT]
/    'COHESIF'
/    'INTERFACE'
```

By default, a crack is defined. It is however possible to define an interface (in order to treat the case of 2 solids in contact, or of under-thicknesses, …).

In the case where TYPE_DISCONTINUITE = 'FISSURE', the data structure produced is enriched with two tables named 'FOND_FISS' and 'NB_FOND_FISS', which can be recovered using the command RECU_TABLE. The table 'NB_FOND_FISS' contains a single value corresponding to the number of crack fronts. The table therefore contains a single column (named NOMBRE) and a single row. The table 'FOND_FISS' contains the list of the coordinates of the points of all the crack fronts. This table has 6 columns:

- the first column ('NUME_FOND') corresponds to the number of the crack front,
- the next column ('NUM_PT') corresponds to the number of the point of the crack front; this number is local to the current crack front,
- the next column ('ABSC_CURV') corresponds to the value of the curvilinear abscissa along the current crack front,
- the next 3 columns ('COOR_X', 'COOR_Y' and 'COOR_Z') correspond to the coordinates of the point.

The discontinuity type COHESIF makes it possible to have information on the propagation front (because of the data mentioned previously and the second level-set function) in order to transmit it to algorithms for propagation or for tracking of the cracked surface. On the other hand, unlike the type FISSURE, it does not contain information linked to a tip enrichment, since the latter has no reason to exist in the presence of cohesive forces. Indeed, it is important to note that for the discontinuity type COHESIF, the propagation front does not coincide with the end of the Heaviside enrichment, which may cross the whole structure. The initial front must therefore be given independently, by the keyword GROUP_MA_BORD.

### 3.4 Keyword DEFI_FISS

```text
♦    DEFI_FISS    =    _F
```

The factor keyword DEFI_FISS makes it possible to define a crack or an interface in 4 different ways:

- either from two mesh-cell groups (see § 3.4.1);
- or from two analytical functions (see § 3.4.2);
- or from a catalogue of predefined shapes (see § 3.4.3);
- or from existing fields (see § 3.4.4).

#### 3.4.1 Definition of the crack by mesh-cell groups

If one has a crack (or an interface) that is already meshed, then the crack can be defined by giving two mesh-cell groups: GROUP_MA_FISS and GROUP_MA_FOND. This mesh may be independent of the mesh of the structure.

> /    ♦    GROUP_MA_FISS        =    grma

.

with grma a single mesh-cell group.

This mesh-cell group corresponds to only one of the lips of the crack (lower or upper lip). This mesh-cell group must be oriented. In the case of lips that would not be perfectly stuck together, favouring one side will have a slight influence on the local basis of the crack front, an influence that is all the greater as the angle between the two lips is large. For the 2D case, the program sorts the mesh cells of GROUP_MA_FISS so as to have a group of contiguous mesh cells whatever the starting group. It is therefore not necessary to give a mesh-cell group whose members follow one another.

> **◊**     GROUP_MA_FOND        =    grma

with grma a single mesh-cell group.

This operand serves to define the crack front. For interfaces, GROUP_MA_FOND is not to be supplied.

In 2D, GROUP_MA_FOND is a group of point mesh cells.

#### 3.4.2 Definition of the crack by analytical functions

The main interest of this operator is the possibility of defining a crack without the latter necessarily being meshed. In this case, the crack is defined by means of two level-set functions. The first level set (called the “normal” level set) is the one that makes it possible to characterise the surface of the crack. FONC_LN is therefore supplied with a real function of $X$, $Y$ and $Z$ defined beforehand by the operator FORMULE. The surface of the crack will then be the zero iso-value of this function. The second level set (called the “tangent” level set) is the one that makes it possible to characterise the crack front. FONC_LT is therefore supplied with a real function of $X$, $Y$ and $Z$ defined beforehand by the operator FORMULE. The trace of the zero iso-value of FONC_LT in the cracking plane is the crack front. The points of the crack are then characterised by FONC_LN = 0 and FONC_LT < 0, whereas the crack front is characterised by FONC_LN = 0 and FONC_LT = 0.

For interfaces, FONC_LT is not to be supplied.

> /    ♦    FONC_LN            =    fonc,

.

with fonc a function or a formula defined beforehand.

> **◊**     FONC_LT            =    fonc,

.

with fonc a function or a formula defined beforehand.

**Note:**

*For a crack, it is essential that the level sets be the true distance functions; one therefore cannot define an elliptical crack by:*

*LN=FORMULE(NOM_PARA=('X','Y','Z'),VALE=’Z-H’)*

*LT=FORMULE(NOM_PARA=('X','Y','Z'),VALE=’(X/a)²+(Y/b)²-1’)*

*where a and b would be the semi-major axis and the semi-minor axis of the ellipse. Indeed, the function* LT *is not the distance to the ellipse. The distance function to an ellipse cannot be expressed by means of the usual functions. In order to introduce such a crack, the 3rd method must be used: the predefined shapes.*

*For interfaces, any level-set function is possible, and it is not useful to introduce the true distance function.*

**Note:**

*To date nothing would forbid having a level set that defines several closed crack fronts (for example several cracks of “penny-shaped” type). Under these conditions, a call to* DEFI_FISS_XFEM *could then define several cracks. This possibility is forbidden:* *each command* DEFI_FISS_XFEM *defines only a single crack. It is therefore not* *possible to define several closed fronts OR one closed front plus one or several open fronts.*

**Note:**

*Beware of the sign of* *FONC_LT; always remember that the crack is defined on the side* *FONC_LT < 0.*

##### 3.4.3.1 FORM_FISS = 'ELLIPSE'

Case of a plane elliptical crack in 3D or of an inclusion of elliptical shape in 2D. The length of the semi-major axis must be supplied by the keyword DEMI_GRAND_AXE and the length of the semi-minor axis by the keyword DEMI_PETIT_AXE. In order to characterise the plane of the ellipse, the centre of the ellipse must be supplied by the keyword CENTRE and the frame of the plane by the keywords VECT_X and VECT_Y. The vector VECT_X corresponds to the axis of the ellipse along which the length $a$ given under the keyword DEMI_GRAND_AXE is defined, and the vector VECT_Y corresponds to the axis of the ellipse along which the length $b$ given under the keyword DEMI_PETIT_AXE is defined.

Note:

Whether one chooses $0<b⩽a$ or $0<a⩽b$, VECT_X remains always associated with DEMI_GRAND_AXE and VECT_Y remains always associated with DEMI_PETIT_AXE.

In the case of a crack, one may furthermore specify on which side the crack lies (inside or outside the ellipse) by the keyword COTE_FISS. It represents an elliptical crack/inclusion, of semi-major axis $a$, of semi-minor axis $b$ and of centre $C$. The vector $\vec{{e}_{1}}$ corresponds to the keyword VECT_X and the vector $\vec{{e}_{2}}$ corresponds to the keyword VECT_Y.

#### 3.4.4 Definition of the crack by rereading already existing nodal fields

```text
/    ♦    CHAM_NO_LSN        =    ch_lsn,                [cham_no]

    ◊    CHAM_NO_LST        =    ch_lst,                [cham_no]
```

The fields ch_lsn and ch_lst are already existing nodal fields. They must have been created on the same mesh as the mesh ma given as input under the keyword MAILLAGE (cf. § 3.1).

These nodal fields may be obtained successively by reading a table (LIRE_TABLE), then by creating the field by extraction from the table (CREA_CHAMP/OPERATION='EXTR').

They may also have been generated in a mesh-refinement step (MACR_ADAP_MAIL/ MAJ_CHAM).

#### 3.4.5 Definition of the initial propagation front for a cohesive crack

```text
/    ♦    GROUP_MA_BORD        =    group_ma,                [l_gr_maille]
```

For a propagation study in the presence of cohesive forces, it is necessary to give the initial propagation front, that is the line from which cracking starts. It is generally a corner of the structure, or a notch root, or more generally a line located on an edge. It is given either in the form of a group of 1D mesh cells if it is meshed, or in the form of a group of 2D edge mesh cells, whose intersection with the normal level set will supply the initial propagation front.

### 3.5 Operand GROUP_MA_ENRI

```text
◊    GROUP_MA_ENRI        =    grma,                                    [l_gr_maille]
```

This operand makes it possible to know the zone on which the enrichment procedure will be carried out. The enriched nodes must belong to this mesh-cell group.

If GROUP_MA_ENRI is not supplied, then the enrichment procedure will be carried out on the whole mesh ma given as input under the keyword MAILLAGE (cf. § 3.1).

A use of this keyword therefore makes it possible to delimit the enrichment zone, hence that of the crack. The following example presents a crack of elliptical shape in a hollow cylinder. The crack is defined by the datum of mesh-cell groups (keywords GROUP_MA_FISS and GROUP_MA_FOND). Two level sets are deduced from them, considering an extension of the crack front by continuity. If the enrichment zone contains the whole structure, this then leads to a crack in the right-hand part of the cylinder, which is not at all what is wanted. To solve this problem, it is enough to limit the enrichment zone and to supply the keyword GROUP_MA_ENRI with the mesh cells of the left-hand half of the cylinder, for example.

```text
◊    CHAM_DISCONTINUITE    =    'DEPL',                            [DEFAUT]
```

This keyword makes it possible to choose the type of fields to be enriched. For the moment, only the displacement field can be enriched.

### 3.7 Operands TYPE_ENRI_FOND, RAYON_ENRI, NB_COUCHES

```text
◊    TYPE_ENRI_FOND    =    /    'GEOMETRIQUE'                        [DEFAUT]
/    'TOPOLOGIQUE'
```

This keyword makes it possible to choose the type of enrichment at the crack front. Topological enrichment (a single layer) is activated if TYPE_ENRI_FOND= ‘TOPOLOGIQUE’. Geometric enrichment (several layers) is activated if TYPE_ENRI_FOND= ‘GEOMETRIQUE’ (for further information concerning the effects of the enrichment on the quality of the results, see [R7.02.12](doc:r7.02.12) and [U2.05.02](doc:u2.05.02)). The geometric enrichment is driven by the keywords RAYON_ENRI and NB_COUCHES.

```text
◊    RAYON_ENRI        =    Renri,                                [R]
```

This keyword can be supplied only if TYPE_ENRI_FOND = 'GEOMETRIQUE'. If this operand is supplied, it makes it possible to specify a geometric criterion Renri such that all the nodes whose distance to the crack front is smaller than this criterion will be enriched by the singular functions. This enrichment is called “geometric”. Studies have shown that such an enrichment greatly improved the accuracy of the analyses, in particular when the mesh is refined at the crack front. It is advisable to choose Renri approximately equal to 1/10 of the length of the crack. The conditioning is very little affected by the use of the geometric enrichment thanks to the introduction of vector enrichment functions at the crack front [R7.02.12](doc:r7.02.12).

In order to avoid the inconveniences caused by too large an enrichment radius (increase in the computing cost), the zone to be enriched can be defined by stipulating the number of layers of elements to be enriched around the crack front instead of the enrichment radius.

# If RAYON_ENRI    =    None

◊    NB_COUCHES        =    /    2,                                    [DEFAUT]

> /    N,                                    [I]

If RAYON_ENRI is not supplied (and TYPE_ENRI_FOND = ‘GEOMETRIQUE’), then NB_COUCHES is the number of layers of elements to be enriched (2 by default). The use of a large number of layers affects only the computing cost, particularly in 3D.

### 3.8 Operand JONCTION

```text
# Si MAILLAGE_GRILLE = None,

◊    JONCTION    =    _F    (

♦    FISSURE        =    (fiss1, fiss2, …,fissi),        [l_fiss_xfem]

♦     POINT            =    (Px , Py , Pz),                    [l_R]
```

This operand makes it possible to define one or several junctions between a crack and other already existing cracks. These other cracks are then considered as mother cracks: they must already have been defined beforehand by calls to DEFI_FISS_XFEM.

A list of mother cracks is supplied in the keyword FISSURE. All these mother cracks will be taken into account when the current crack is defined. The keyword POINT must be given in the domain in which one wishes the crack to be defined. An example is provided in figure 3.7-a. It is considered in this figure that crack 3 was defined initially so as to cut the domain vertically. The keyword JONCTION is introduced in order to connect it to cracks 1 and 2. The three configurations of the figure can be obtained according to the choice of the position given in the keyword POINT.

![Figure](/figures/u4.82.08/Object_32.png)

Figure 3.8-1: Example of definition of the crack fiss3, for the mother cracks $\mathit{fiss1}$ and $\mathit{fiss2}$, as a function of the point $(\mathit{px},\mathit{py})$ chosen.

Care must be taken when the operand JONCTION is used: the crack will then no longer be represented only by its normal and tangent level sets, but it will also depend on the mother cracks. This may pose a problem if one wishes to use operators such as RAFF_XFEM, which accept only the definition of a crack by level sets. Likewise the graphical representation of the zero iso-value of the level sets is not sufficient; it is preferable to go through the post-processing operations via the operator POST_MAIL_XFEM.

An example of configuration is presented. In this example the cracks onto which another crack connects are identified. Thus for the crack $N=3$, one has $K=2$ where K is the set of the cracks onto which 3 connects. Likewise for the crack $N=5$, one deduces $K=[3,4]$. Crack 5 is therefore defined from the operand jonction and from the two cracks 3 and 4. Crack 3 is itself defined beforehand from the operand jonction acting on crack 2, itself defined from the operand jonction acting on crack 1. The hierarchy tree therefore serves to establish the order of definition of the various cracks (2 from 1, 3 from 2, 4 from 1 and 5 from 3 and 4).

![Figure](/figures/u4.82.08/Object_34.png)

**Figure** 3.8-2 **: Network of cracks on the left, hierarchy tree on the right indicating what connects to what and making it possible to establish the order relations for the crack definitions and the use of the operand** JONCTION **.**

The junction operator makes it possible to establish an order relation for a mesh cell that sees $N$ cracks. The two hierarchy trees on the right will thus be distinguished. In the rightmost tree, cracks 1 and 2 are close enough for a mesh cell seeing crack 3 also to see cracks 1 and 2: it is therefore decided to connect crack 3 to cracks 2 and 1, but also to use the operand junction to indicate that crack 2 is connected to crack 1. For the other tree, a mesh cell sees at most 2 cracks (no mesh cell then sees cracks 1, 2 and 3 at the same time) and in this case crack 3 simply connects to cracks 2 and 1, which are no longer connected to each other.

![Figure](/figures/u4.82.08/Object_29.png)

**Figure** 3.8-3 **: Network of cracks on the left, hierarchy trees on the right.**

The rightmost hierarchy tree indicates that crack 2 cannot be defined independently of crack 1 because it is too close to the latter (a mesh cell seeing crack 3 then also sees cracks 1 and 2).
