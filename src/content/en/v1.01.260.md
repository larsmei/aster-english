# v1.01.260 ERREU07 - Error messages when changing behavior prohibited

**Summary:**

This test validates the issue of an error message when one "shall" a nonlinear calculation by changing constitutive law on some elements.

Note: Some behavior changes are allowed. This is checked in the test zzzz258 (v1.01.258).

## 1 Test principle

This test is a computer test. It is used to validate the programming of the ETAT_INIT keyword processing and more specifically the routine vrcomp.f

To define the initial state of a nonlinear calculation, the user has two options:

- either it indicates an evol_noli data structure and a "minute" in this evol_noli (keywords EVOL_NOLI + INST)
- or it gives 3 "isolated" displacement fields, constraints and internal variables (keywords DEPL, SIGM and VARI)

Programming is different to deal with both cases, which is why we both test them.

The test results in the following two errors:

!---------------------------------------------------------------------------------------!

! <EXCEPTION> <CALCULEL5_42> !

! !

! incompatible behaviors: VMIS_CINE_LINE and VMIS_ISOT_TRAC for the mesh cell M1!

!---------------------------------------------------------------------------------------!

!----------------------------------------------------------------------------------------------------!

! <EXCEPTION> <CALCULEL3_49> !

! !

Misuse : !

You want to "continue" a nonlinear calculation (STAT_NON_LINE or DYNA_NON_LINE). !

! To do this, you specify an initial state (keyword ETAT_INIT / VARI=chvari). !

For the calculation of the 1st time step, the field of internal variables used for the start of the step!

- It's "chvari."

For the element worn by the mesh cell M1, this field of internal variables does not have the same number of!

! internal variables (7) that the number expected by the behavior chosen for the calculation (2). !

! !

So there's a change in behavior for the mesh cell M1!

! The code only accepts changes in behaviour in a few very special cases : !

! - LEMAITRE <-> VMIS_ISOT_XXXX !

! - ELAS <-> XXXX !

It doesn't seem like you're in this case.

! !

Risks & advice: !

Check the affected behavior on this mesh cell!
