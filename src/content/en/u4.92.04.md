# u4.92.04 Procedure TEST_FICHIER

## 1 Purpose

This macro-command makes it possible to test the non-regression of files produced by the Code_Aster commands, principally IMPR_RESU, but one can use it on any text file.

To test a file, one extracts the list of the real and integer numbers present in the file, the cardinality of this list, and the whole of the remaining text (once the numbers have been extracted).

For the numbers, one checks the non-regression of the sum, of the absolute sum or of the min/max of the values to within a given accuracy.

For testing the text of the file, one uses the Python module md5, which provides a "signature" of the text (called md5sum).

Returns OK if the file is identical to the file that served as the reference, NOOK otherwise.

This command is used essentially by the test cases in order to validate the non-regression of the results.

## 3 General points

This procedure makes it possible to test the non-regression of files produced by the Aster commands, principally IMPR_RESU, but one can use it on any text file.

To test a file, one extracts the list of the real numbers and the list of the integers present in the file, the cardinality of these lists, and the whole of the remaining text (once the numbers have been extracted).

For the numbers, one checks the non-regression of the sum, of the absolute sum or of the min/max of the values to within a given accuracy. The real numbers and the integers are processed separately.

One also checks (and this is the only compulsory test) the cardinality of the list of the real numbers identified in the file.

For testing the text of the file, one uses the Python module md5, which provides a "signature" of the text (called md5sum). Thus, any variation of a text (title, name of a component) with respect to a reference file will cause a change in the signature of the file.

**Note 1:**

The file must be closed in order for the value to be reliable (with, for example, DEFI_FICHIER, ACTION = 'LIBERER').

**Note 2:**

The command does not give relevant information on binary files.

The function test_file can be called outside *Code_Aster* in order to obtain the value of the md5sum of a file:

> iret, sum = test_file(    filename='nom_fichier',

> type_test='SOMM',
> verbose=True)

**Note** 3

*For the integer numbers, the value tested on the* integers *is truncated* to the largest integer that can be represented in 32 bits (about 2.e9) *.*

## 4 Operands

### 4.1 Operand FICHIER

```text
♦    FICHIER    =    fich,
```

One supplies here the name of the file to be analysed, with its access path relative to the execution directory or absolute. Examples: 'fort.37' or './REPE_OUT/resultats.pos'.

### 4.2 Operand EXPR_IGNORE

```text
◊    EXPR_IGNORE = regexp
```

The lines of the file satisfying the regular expressions given under this keyword will be ignored in the analysis of the file.

```text
Exemple:*
```

```text
EXPR_IGNORE = (    'DATE=[0-9]{2}/[0-9]{2}/[0-9]{4}',
'^VERSION'    )
```

Here the lines containing DATE=jj/mm/aaaa where $j$ , $m$ , $a$ are digits **or** starting with VERSION are ignored.

### 4.3 Operand TYPE_TEST

Type of the test performed on the real and integer values of the file. The possible values are:

- SOMM: sum of the values
- SOMM_ABS: sum of the absolute values
- MAXI: maximum value
- MINI: minimum value
- MAXI_ABS: maximum of the absolute values
- MINI_ABS: minimum of the absolute values

### 4.4 Operands NB_VALE and NB_VALE_I

NB_VALE is the number of real values expected in the file. It is the only compulsory test.

NB_VALE_I is the number of integer values expected in the file.

### 4.5 Keywords common to the commands TEST_XXX

The definition of the non-regression and reference values, as well as of the allowable tolerances and of the comparison criteria, is detailed in the documentation [u4.92.01](doc:u4.92.01) of the command TEST_RESU.

The specific features of TEST_FICHIER are:

- no complex values,
- no test in absolute value (except with TYPE_TEST),
- VALE_CALC, VALE_CALC_I and VALE_CALC_K may be supplied together,
- no tolerance on the value of the parameter (TOLE_MACHINE and CRITERE take only a single value).
- VALE_CALC supplies the expected reference value for the test on the real values (the sum or the maximum or...).
- VALE_CALC_I supplies the expected reference value for the test on the integer values (the sum or the maximum or...).
- VALE_CALC_K supplies the md5 signature of the text of the file after all the real and integer values have been removed. To obtain the value on the reference file, it is enough to launch the command TEST_FICHIER and to note the displayed value (it is a sequence of 32 hexadecimal characters).
