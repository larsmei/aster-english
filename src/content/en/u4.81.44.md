# u4.81.44 Operator COMBINAISON_FERRAILLAGE

## 1 Purpose

The purpose of this operator is to compute the reinforcement densities in surface (2D) and line (1D) elements as a function of the internal forces for several loading combinations.

As input, this macro-command takes a multiple result of type mult_elas. Each of the results of mult_elas contains the generalised forces, previously obtained by the option EFGE_ELNO.

The command enriches each result of mult_elas with a reinforcement quantity (grandeur) field, by calling the command CALC_FERRAILLAGE several times.

The command also adds results to the mult_elas data structure.

## 3 Operands

### 3.1 Operand RESULTAT and CARA_ELEM

♦ RESULTAT =    resu

> Name of a result concept of type mult_elas. It is necessarily re-entrant.

♦ CARA_ELEM = carac

The elementary characteristics must be supplied by the keyword CARA_ELEM for all static and dynamic results. This change is induced by the integration of POST_COMBINAISON(U4.81.45) which generates an ELAS_MULT result with no associated CARA_ELEM.

### 3.2 Operand CODIFICATION

♦ CODIFICATION = /‘EC2’,                     [DEFAUT]

```text
/'BAEL91',
```

This is the code to be used for the checks: Eurocode 2 (EC2) or BAEL91.

### 3.3 Operand COMBINAISON

> ♦ COMBINAISON = _F(♦ TYPE = / 'ELS_QUASIPERMANENT',

/'ELS_CARACTERISTIQUE',

/'ELU_FONDAMENTAL',

/'ELU_ACCIDENTEL',

♦ /NOM_CAS = l_nomcas

/NUME_ORDRE = l_numeordre,)

With this repeatable operator one supplies to the command the list of cases (results of the mult_elas) on which to carry out the design which correspond to the serviceability limit state checks (the characteristic combination is the only one available for the moment) and ultimate limit state checks (fundamental, accidental).

The choice between ELU_FONDAMENTAL and ELU_ACCIDENTEL makes it possible to choose the value of the safety coefficients GAMMA (see operand AFFE, § 3.4 ).

#### 3.3.1 Keyword TYPE

> ♦ TYPE = / 'ELS_QUASIPERMANENT',

/'ELS_CARACTERISTIQUE',

/'ELU_FONDAMENTAL',

/'ELU_ACCIDENTEL',

With this keyword, one chooses the type of check to be associated with the list of cases. For the moment the options available are the fundamental or accidental ultimate limit states and the characteristic and quasi-permanent serviceability limit states as defined by the Eurocodes.

#### 3.3.2 Keywords NUME_ORDRE and NOM_CAS

Here is supplied the list of cases associated with the check entered in TYPE, either as a list of the order numbers of the cases or as a list of the names of the cases (label associated with each result of the mult_elas).

**Note**

Here the order number does not indicate an analysis time instant or a frequency as for result data structures, but a case number (one of the results contained in the multi_elas).

### 3.4 Operand AFFE

A large part of the keywords entered here are the same as for the command CALC_FERRAILLAGE. One difference with the keywords of CALC_FERRAILLAGE consists in the choice of the safety coefficients:

◊ GAMMA_S_FOND= gs,                [R]

◊ GAMMA_S_ACCI= gs,                [R]

◊ GAMMA_C_FOND= gc,                [R]

◊ GAMMA_C_ACCI = gc,                [R]

The values entered under GAMMA_S_FOND and GAMMA_C_FOND will be chosen to feed CALC_FERRAILLAGE if the user has chosen the option ELU_FONDAMENTAL of the operand COMBINAISON (§ 3.3 ) for a given load case. For ELU_ACCIDENTEL, the values of GAMMA_S_ACCI and GAMMA_C_ACCI will be selected.

### 3.5 Composition of the field produced

The result of each case of name NOM_CAS is enriched by a new field (named 'FERRAILLAGE' in the data structure) whose components are:

If **TYPE_STRUCTURE** **= ‘2D’** :

- a longitudinal reinforcement density in the direction $X$ of the element for the lower face of the element ($\mathrm{DNSXI}$ ) ;
- the equivalent for the upper face ($\mathrm{DNSXS}$ ) ;
- a longitudinal reinforcement density in the direction $Y$ of the element for the lower face of the element ($\mathrm{DNSYI}$ ) ;
- the equivalent for the upper face ($\mathrm{DNSYS}$ ) ;
- the transverse reinforcement density in the direction $X$ of the element ($\mathit{DNSXT}$ ) ;
- the equivalent in the direction $Y$ of the element ($\mathit{DNSYT}$ ) ;
- the total volumetric density of steel ($\mathit{DNSVOL}$ );
- an indicator of the complexity of placing the reinforcement ($\mathit{CONSTRUC}$ ).

If **TYPE_STRUCTURE** **= ‘1D’** :

- a longitudinal reinforcement density along the axis $Y$ of the section, and in the positive direction of the axis (upper face along the height h) ($\mathit{AYS}$ ) ;
- a longitudinal reinforcement density along the axis $Y$ of the section, and in the negative direction of the axis (lower face along the height h) ($\mathit{AYI}$ ) ;
- a longitudinal reinforcement density along the axis of the section, and in the positive direction of the axis (upper face along the width b) ($\mathit{AZS}$ ) ;
- a longitudinal reinforcement density along the axis $Z$ of the section, and in the negative direction of the axis (lower face along the width b)($\mathit{AZI}$ ) ;
- a transverse reinforcement density ($\mathit{AST}$ ) ;
- a total longitudinal reinforcement density ($\mathit{ATOT}$ ) ;
- the total volumetric density of steel ($\mathit{DNSVOL}$ );
- an indicator of the complexity of placing the reinforcement($\mathit{CONSTRUC}$ ).

The reinforcement field is computed for the only existing time instant for each case. One of the main purposes of the command COMBINAISON_FERRAILLAGE is to compute, for each type of reinforcement (longitudinal, transverse…), the governing combination, that is the one which maximises the type of reinforcement considered.

Thus, the algorithm of the command COMBINAISON_FERRAILLAGE calls the command CALC_FERRAILLAGE for each case (order number of mult_elas) by choosing the type of check entered by TYPE_COMB. Then, the reinforcement densities (for each type of reinforcement) are compared with one another; the one which gives rise to the largest reinforcement is the governing combination. This comparison is made at each call of COMBINAISON_FERRAILLAGE, hence on each node of the selected mesh-cell groups.

There will therefore be as many governing combinations as there are types of reinforcement.

Two new cases are created in the given multi_elas structure:

- COMB_DIME_ACIER → Under this case name are entered the maximum reinforcements for each finite element and type of reinforcement
- COMB_DIME_ORDRE → Under this case name are entered the order numbers of the cases which supply the maximum reinforcements (governing cases) for each finite element and type of reinforcement.

### 3.6 Errors and alarms

#### 3.6.1 Errors caused by an inconsistency of the input parameters

A check of the consistency of the input parameters is carried out at the start of the execution of the command COMBINAISON_FERRAILLAGE. The analysis can be stopped by a fatal error in the following cases:

- if no occurrence of the operand COMBINAISON or AFFE is supplied.
- in the case BAEL91 at the ELU FONDAMENTAL: if the keywords GAMMA_S_FOND, GAMMA_C_FOND, FE or FCJ are not supplied;
- in the case BAEL91 at the ELU ACCIDENTEL: if the keywords GAMMA_S_ACCI, GAMMA_C_ACCI, FE or FCJ are not supplied;
- in the case BAEL91 at the ELS: if the keywords N, SIGS_ELS or SIGC_ELS are not supplied;
- in the case BAEL at the ELS_QP: if the keywords ALPHA_E, FYK, FCK, SIGC_ELS_QP, WMAX_INF/SUP(_Y/Z), KT, PHI_X/Y/Z_INF/SUP are not supplied;
- in the case EC2 at the ELU FUNDAMENTAL: if the keywords GAMMA_S_FOND, GAMMA_C_FOND, FYK or FCK are not supplied;
- in the case EC2 at the ELU ACCIDENTEL: if the keywords GAMMA_S_ACCI, GAMMA_C_ACCI, FYK or FCK are not supplied;
- in the case EC2 at the ELS: if the keywords ALPHA_E, SIGS_ELS, SIGC_INF/SUP(_Y/Z)_ELS or FCK are not supplied;
- in the case EC2 at the ELS_QP: if the keywords ALPHA_E, FYK, FCK, SIGC_ELS_QP, WMAX_INF/SUP(_Y/Z), KT, PHI_X/Y/Z_INF/SUP are not supplied;
- for all cases: if the value of the cover is greater than the thickness/height/width of the structural element.

As well as the following particular cases:

- if **FERR_MIN = ‘VALE_MIN’** and the keywords RHO_LONGI_MIN and RHO_TRSNV_MIN are not supplied.
- if **FERR_SYME = ‘OUI’** and the keyword SEUIL_SYME is not supplied.

#### 3.6.2 Alarms issued during the computation of the steels

The computation of the bending steels can issue one or several alarms in the following cases:

- if the ‘1D’ element or at least one facet of the ‘2D’ element is at pivot B and too heavily compressed, with **FERR_COMP = ‘NON’**: in this case the reinforcement density is set to -1 for the element (and the analysis on the other facets of the ‘2D’ element is ignored)
- if the ‘1D’ element or at least one facet of the ‘2D’ element is at pivot C and too heavily compressed with **FERR_COMP = ‘NON’**: in this case the reinforcement density is set to -1 for the element (and the analysis on the other facets of the ‘2D’ element is ignored)
- if **FERR_SYME = ‘OUI’** and the algorithm does not succeed in determining a symmetrical reinforcement for the ‘1D’ element (or for at least one facet of the ‘2D’ element) which respects the tolerance threshold entered at the keyword **SEUIL_SYME**: in this case the reinforcement density is set to -1 for the element
- if the **‘1D’** element is subjected to biaxial bending, and the iterative design algorithm by verification of the Bresler inequality does not manage to converge: in this case the reinforcement density is set to -1 for the element
- if **TYPE_COMB = ‘ELS_QP’** and the iterative design algorithm based on the verification of the crack-opening inequality does not manage to converge: in this case the reinforcement density is set to -1 for the element
