# u4.34.03 Operator DEFI_LIST_INST

To define the list of analysis time instants, as well as its management for the iterative solution algorithms (commands [STAT_NON_LINE](doc:u4.51.03), [DYNA_NON_LINE](doc:u4.53.01), [MECA_NON_LINE](doc:u4.51.04) and [THER_NON_LINE](doc:u4.54.02))

- possibilities of recutting the time step in the event of failure,
- possibilities of adapting the time step.

Produces a data structure list_inst.

## 2 General parameters

### 2.1 Operand METHODE

This keyword makes it possible to choose the mode of management of the list of time instants.

By default, management is manual (METHODE='MANUEL'), which means that one will go through exactly the list of time instants defined by the user. In the event of subdivision, new time instants may be inserted.

In automatic management (METHODE='AUTO'), the code automatically computes the new analysis time instants. The modes of computation of the new time steps are defined under the keyword ADAPTATION. The analysis time instants defined by the user are nevertheless respected.

### 2.2 Operand MODELE

This keyword makes it possible to define the model in the case where one filters the field used by DELTA_GRANDEUR (see below) via a list of mesh-cell groups or of nodes. In this case, the model is mandatory. Otherwise, it is unnecessary.

## 3 Definition of the list of time instants - keyword DEFI_LIST

### 3.1 Operands LIST_INST and VALE

The analysis time instants can be defined in 3 different ways:

- either by supplying the keyword LIST_INST with a concept defined beforehand by the command [DEFI_LIST_REEL](doc:u4.34.01),
- or by supplying the keyword VALE with a list of reals,
- or by supplying the keyword RESULTAT with a concept produced by [STAT_NON_LINE](doc:u4.51.03) or [DYNA_NON_LINE](doc:u4.53.01). This keyword makes it possible to refine an already existing list of time instants. Indeed, one then defines a list of time instants SUBD_PAS **times finer** than the list of the time instants actually computed in [STAT_NON_LINE](doc:u4.51.03) or [DYNA_NON_LINE](doc:u4.53.01). It should be noted that this list of actually computed time instants may differ from the list of time instants given as input to [STAT_NON_LINE](doc:u4.51.03) or [DYNA_NON_LINE](doc:u4.53.01) (for example because of the subdivision) and from the list of archived time instants (if one does not archive every time instant). This functionality is useful for checking the independence of the results with respect to the time discretisation. For example, to obtain a list of time instants 2 times finer, one chooses SUBD_PAS=2.

**Caution**

If the result data structure comes from an analysis with restart, it is not possible to reuse it in the command because one cannot extract a list of unique time instants (some time instants will be duplicated).

### 3.2 Operands PAS_MINI, PAS_MAXI, NB_PAS_MAXI

These operands are to be supplied only in the case of automatic management of the list of time instants (METHODE='AUTO').

![Figure](/figures/u4.34.03/Cadre2.gif)

*Automatic adaptation of the time step*

The operand PAS_MINI makes it possible to specify the minimum time step. If, in the course of adapting the time step, one is led to process a time step smaller than PAS_MINI, then the analysis stops. If this operand is not supplied, in the general case PAS_MINI is then equal to ${10}^{-12}$ (this is moreover the minimum permitted value); if it is not supplied and MODE_CALCUL_TPLUS='IMPLEX', then PAS_MINI is equal to 1/1000th of the first analysis time step (necessarily entered by the user via LIST_INST).

If $\Delta {t}_{i} < \text{PAS\_MINI}$ then STOP.

Caution: the check of PAS_MINI is not carried out during the possible subdivision of the time step in the event of failure (it is SUBD_PAS_MINI which acts during the subdivision). The operand PAS_MINI acts only for the computation of a **new** time step.

The operand PAS_MAXI makes it possible to specify the maximum time step, but its behaviour is different from that of PAS_MINI. Indeed, if, in the course of adapting the time step, one is led to process a time step greater than PAS_MAXI, then the analysis does not stop (unlike the behaviour of PAS_MINI), but the time step is then limited to PAS_MAXI. If this operand is not supplied, this step will not be carried out; if it is not supplied and MODE_CALCUL_TPLUS='IMPLEX', then PAS_MAXI is equal to 10 times the first analysis time step (necessarily entered by the user via LIST_INST).

If $\Delta {t}_{i} > \text{PAS\_MAXI}`$ then $\Delta {t}_{i} = \text{PAS\_MAXI}$

The operand NB_PAS_MAXI makes it possible to specify the number of time steps beyond which the analysis stops. The default value is one million (it is also the maximum permitted value).

### 3.3 Operand PAS_INIT

**Warning**

This keyword is taken into account by MECA_NON_LINE but is not used by STAT_NON_LINE.

This keyword makes it possible to define the initial time step of the analysis.
It has no effect if PAS_INIT is larger than the first time step computed from the list of time instants.

An analysis time instant at PAS_INIT from the initial time instant is inserted. In the event of failure, of cutting and of automatic adaptation, it is possible that this precise time instant is not computed.

## 4 Keyword ECHEC

This repeatable factor keyword makes it possible to manage the list of time instants in the event of failure of convergence. At each occurrence of the keyword ECHEC, one defines a cause of failure (see u4.34.03-echec_events ) and an action to be carried out if this cause is satisfied (see u4.34.03-echec_actions ). The actions may differ between each occurrence of the keyword ECHEC.

If several causes of failure are satisfied simultaneously, the order of triggering of these failures is predetermined; in particular, 'ERREUR' always has priority over 'DELTA_GRANDEUR'.

### 4.1 Definition of the causes of failure

The operand EVENEMENT makes it possible to define the causes of failure.

#### 4.1.1 Event 'ERREUR'

By default, the cause of failure is ERREUR. This cause groups the following reasons:

- Exceeding the maximum permitted number of Newton iterations.
- Failure during the local integration of the constitutive law. The local parameters of the algorithm used for the integration of the constitutive law are found in [COMPORTEMENT](doc:u4.51.11).
- Failure of the Deborst algorithm for plane stresses or 1D models. More details will be found in [COMPORTEMENT](doc:u4.51.11).
- Failure during the solution of the discrete contact problem (see [R5.03.50](doc:r5.03.50)). There is failure when the maximum number of contact iterations is exceeded or when the contact matrix is singular.
- The system matrix is singular. Singularity detection relies on the parameter NPREC of the factor keyword SOLVEUR (see [SOLVEUR](doc:u4.50.01)).
- The iterative linear solver has reached the maximum number of Krylov iterations set by NMAX_ITER in the factor keyword SOLVEUR (see [SOLVEUR](doc:u4.50.01)).
- At convergence, physical criteria are not satisfied during the integration of the constitutive law (notion of “event-driven”).

Even if one finds no occurrence of ECHEC / EVENEMENT = 'ERREUR', the code automatically adds one with the default parameters (that is, the action 'DECOUPE' in mode 'MANUEL' with SUBD_NIVEAU=4).

#### 4.1.2 Event 'DIVE_RESI'

The choice of the event 'DIVE_RESI' makes it possible to specify another possible cause of failure (“event-driven”). There will be failure if the residual does not decrease sufficiently in the course of the Newton iterations. More precisely, there will be failure if: $min[R_{i}, R_{i-1}] > R_{i-2}$ for $i \ge 3$, where $R_{j}$ is the residual (RESI_GLOB_MAXI) at Newton iteration $j$.
If there is failure, then the time step is subdivided (there are no other possibilities). The interest of this functionality is that it is not necessary to wait until one reaches the end of the permitted Newton iterations in order to recut the time step in the event of “notable” non-convergence. Non-convergence is detected sooner, so a saving of time is expected.

**Note**

Activation of this functionality with discrete contact is not advised because, in this type of analysis, the residual does not in general decrease monotonically.

#### 4.1.3 Event 'DELTA_GRANDEUR'

The choice of the event 'DELTA_GRANDEUR' makes it possible to specify another possible cause of failure (“event-driven”). There will be failure if the increment of a component of a field exceeds a fixed threshold, **at convergence**.
One must then define the name of the field by the operand NOM_CHAM (displacement, stress or internal-variable field), the name of the component by the operand NOM_CMP and the value of the reference threshold by the operand VALE_REF.

More precisely, let $v$ be the component NOM_CMP of the field NOM_CHAM and $valref$ the reference value VALE_REF.

If the field NOM_CHAM is a field at the nodes and ${N}_{no}$ is the set of all the nodes of the mesh, then there will be failure if, at convergence:

$$
max(\Delta \vert{v}^{i}\vert, \forall i\in {N}_{no}) > valref
$$

If the field NOM_CHAM is a field at the Gauss points, ${N}_{sp,pg,el}$ is the set of all the sub-points of all the Gauss points of all the elements of the model, then there will be failure if, at convergence:

$$
max(\Delta \vert{v}^{i}\vert, \forall i\in {N}_{sp,pg,el}) > valref
$$

The increment $\Delta$ is to be understood as the increment between two time instants.
By default, the maximum is taken over the whole field. However, one can filter the location by using the keywords GROUP_MA (for the fields SIEF_ELGA and VARI_ELGA) or GROUP_NO (for the field DEPL). In this case, the maximum is taken respectively over the list of mesh-cell groups or the list of node groups.

Example no. 1 with a law VMIS_ISOT_LINE:

```python
ECHEC = (
    _F(
        EVENEMENT="DELTA_GRANDEUR",
        VALE_REF=0.1e-2,
        NOM_CHAM="VARI_ELGA",
        NOM_CMP="V1",
    ),
)
```

There will be failure if the increment of the cumulative plasticity between two time steps exceeds $10^{-3}$.

Example no. 2:

```python
ECHEC = (
    _F(
        EVENEMENT="DELTA_GRANDEUR",
        VALE_REF=5.0e-2,
        NOM_CHAM="DEPL",
        NOM_CMP="DX",
    ),
    _F(EVENEMENT="DELTA_GRANDEUR", VALE_REF=5.0e-2, NOM_CHAM="DEPL", NOM_CMP="DY"),
)
```

There will be failure if the norm (sup norm) of the displacement (in 2D) varies by more than 0.05 between two time steps.

**Note**

In the two preceding examples, although EVENEMENT='ERREUR' is not present, it will still be activated by default.

#### 4.1.4 Event 'INTERPENETRATION'

This event detects the interpenetration of a node into a surface when regularised unilateral contact (penalisation) is activated. The user gives a value of the maximum penetration that he or she wants to obtain (parameter PENE_MAXI) and the code then adapts the penalisation coefficient (ACTION='ADAPT_COEF_PENA') or stops (ACTION='ARRET') in order to satisfy this constraint.
This functionality is available only for contact with FORMULATION='DISCRETE' (see [DEFI_CONTACT](doc:u4.44.11)).

#### 4.1.5 Event 'INSTABILITE'

This event makes it possible to manage the course of a non-linear analysis when an instability is detected during the call to CRIT_STAB (cf. [STAT_NON_LINE](doc:u4.51.03) and [DYNA_NON_LINE](doc:u4.53.01)). If this keyword CRIT_STAB is not used then this event cannot occur.

If an instability is detected, an action will then be triggered, according to two possibilities:

- ACTION='CONTINUE': this is the default value and the analysis will be continued, even in the event of instability,
- ACTION='ARRET': if an instability is captured, then the non-linear solution will be stopped cleanly.

More details on the instability criterion and its use are given in the documents [R7.05.01](doc:r7.05.01) and [U2.08.04](doc:u2.08.04).

#### 4.1.6 Event 'RESI_MAXI'

This event makes it possible to avoid the equilibrium residual “exploding”. Indeed, in certain situations, integration of the constitutive law over time steps that are too large increases the equilibrium residual. It is then in general no longer possible for the residual to decrease afterwards, which leads to failure of the analysis. By activating this event, one sets a maximum value on RESI_GLOB_MAXI during the Newton iterations, which makes it possible to cut the time step or to stop the analysis.

### 4.2 Definition of the actions to be carried out in the event of failure

Depending on the event, only certain actions are possible; see the table below:

| **ACTION****EVENEMENT** | ARRET | DECOUPE | CONTINUE | ARCHIVAGE |
| --- | --- | --- | --- | --- |
| ERREUR | YES | YES |  |  |
| DIVE_RESI |  | YES |  |  |
| DELTA_GRANDEUR | YES | YES |  | YES |
| COLLISION | YES | YES |  |  |
| INTERPENETRATION | YES |  |  |  |
| INSTABILITE | YES |  | YES |  |
| RESI_MAXI | YES | YES |  |  |

For example, in the most general case (EVENEMENT='ERREUR'), there are these possibilities:

- Cut the time step (ACTION='DECOUPE');
- Stop (ACTION='ARRET').

#### 4.2.1 Action 'ARRET'

If one chooses ACTION= 'ARRET', the analysis stops cleanly.

#### 4.2.2 Action 'DECOUPE'

This action consists in redoing the time step by cutting it. There are two methods of cutting the time step: AUTO mode and MANUEL mode.

**Note**

In MECA_NON_LINE, the time instants inserted by the cutting are not compulsory passage points.
Thus if one uses time-step adaptation (acceleration) at the same time, it may be that some of the cutting time instants are ignored.

##### 4.2.2.1 Cutting in mode MANUEL

In MANUEL mode, the time step is cut uniformly. One must therefore specify the number of cuts using the keyword SUBD_PAS.

![Figure](/figures/u4.34.03/Cadre3.gif)

*Cutting in mode MANUEL with SUBD_PAS=2*

The event ERREUR is triggered during time step 1, initially of length $\Delta {t}_{1}^{{N}_{1}}$. This time step is then cut into two time steps (SUBD_PAS = 2) of equal lengths such that $\Delta {t}_{1}^{{N}_{2}} = \Delta {t}_{2}^{{N}_{2}} = \frac{\Delta {t}_{1}^{{N}_{1}}}{2}$. The next time step (number 2 in the initial configuration) then becomes time step 3; its length remains unchanged $\Delta {t}_{3}^{{N}_{2}} = \Delta {t}_{2}^{{N}_{1}}$.

| **Time step** | 1 | 2 | 3 |
| --- | --- | --- | --- |
| **Initial – 1** | $\Delta {t}_{1}^{{N}_{1}}$ | $\Delta {t}_{2}^{{N}_{1}}$ |  |
| **Cutting – 2** | $\Delta {t}_{1}^{{N}_{2}}$ | $\Delta {t}_{2}^{{N}_{2}}$ | $\Delta {t}_{3}^{{N}_{2}}$ |

##### 4.2.2.2 The notion of cutting level

Cutting of the time step is recursive: if the event ERREUR is triggered during an already cut time step, one cuts again. An example is shown in the following figure.

![Figure](/figures/u4.34.03/Cadre1.gif)

*Recursive cutting in mode MANUEL with SUBD_PAS=2*

After the first cutting, the failure occurs in the (new) second time step. One cuts it again with $\Delta {t}_{2}^{{N}_{3}} = \Delta {t}_{3}^{{N}_{3}} = \frac{\Delta {t}_{2}^{{N}_{2}}}{2}$. The following time step remains unchanged $\Delta {t}_{4}^{{N}_{3}} = \Delta {t}_{3}^{{N}_{2}}$, the first time step has converged and therefore also remains unchanged $\Delta {t}_{1}^{{N}_{3}} = \Delta {t}_{1}^{{N}_{2}}$. Which gives:

| **Time step** | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- |
| **Initial – 1** | $\Delta {t}_{1}^{{N}_{1}}$ | $\Delta {t}_{2}^{{N}_{1}}$ |  |  |
| **Cutting – 2** | $\Delta {t}_{1}^{{N}_{2}}$ | $\Delta {t}_{2}^{{N}_{2}}$ | $\Delta {t}_{3}^{{N}_{2}}$ |  |
| **Cutting – 3** | $\Delta {t}_{1}^{{N}_{3}}$ | $\Delta {t}_{2}^{{N}_{3}}$ | $\Delta {t}_{3}^{{N}_{3}}$ | $\Delta {t}_{4}^{{N}_{3}}$ |

There cannot be a difference of more than one level between two time steps.

##### 4.2.2.3 Cutting in mode AUTO

The automatic cutting mode attempts a linear extrapolation of the value of the residuals.

If one denotes by $iter$ the Newton iteration and by ${resi}^{\text{ext}}$ the value of the extrapolated residual (RESI_GLOB_RELA and/or RESI_GLOB_MAXI), then one seeks ${a}_{1}$, ${a}_{2}$ and $b$ such that:

$$
{resi}^{\text{ext}} = \frac{({a}_{1} \cdot iter + {a}_{2})}{b}
$$

Here is the algorithm used:

> For $iter = deb,fin$

> $xx = log({resi}_{iter+1})$
> If $iter > fin -3$

> $poids = 2$

> Otherwise

> $poids = 1$

> One computes

> $xn = xn+poids$
> $sx = sx+poids.xx$
> $sy = sy+poids.iter$
> $sxx = sxx+poids.({xx}^{2})$
> $syx = syx+poids.xx.iter$

> End For
> ${a}_{1} = sxx.sy–sx.syx$
> ${a}_{2} = -(sx.sy)+syx.xn$
> $b = -{sx}^{2}+sxx.xn$

To perform this extrapolation, a minimum of three Newton iterations is required and the last two iterations are considered to have twice the weight of the first ones; if this is not possible (or if the extrapolation fails for another reason), one automatically switches to MANUEL cutting mode (SUBD_PAS=4).

##### 4.2.2.4 Control of the cutting

If convergence is difficult and the event is triggered several times in a row, leading to recursive cutting of the time step, one can stop the process in two ways in MANUEL mode:

- Cutting will stop as soon as cutting has been done more than SUBD_NIVEAU times.
- Cutting will stop as soon as the time step is smaller than SUBD_PAS_MINI.

In AUTO mode, only the keyword SUBD_PAS_MINI is available.

**Note concerning the buckling analysis**

During an elastoplastic buckling analysis, it may happen that the tangent matrix of the system is singular in the course of the Newton iterations. By recutting the time step, one can get past these difficult points.

**Particularities of the operand SUBD_NIVEAU**

The operand SUBD_NIVEAU is a notion which ought to be global to all the occurrences of the keyword ECHEC. Thus, this operand ought to be defined only once. In practice, this is not the case and nothing prevents one from defining a different value of SUBD_NIVEAU at each occurrence of the keyword ECHEC. To guard against that case, the algorithm will ultimately retain as the single global value of SUBD_NIVEAU the **maximum** of the SUBD_NIVEAU values defined by the user.

#### 4.2.3 Action 'CONTINUE'

If the event INSTABILITE is triggered, this action consists in attempting to continue the non-linear analysis. It is the default value for this event, which is the only one that can be combined with this action.

#### 4.2.4 Action 'ARCHIVAGE'

If the event DELTA_GRANDEUR is triggered, this action stops the analysis without error.

In STAT_NON_LINE, the final time instant of the time step which led to the triggering of the event will be archived in the result.
In MECA_NON_LINE, the initial and final time instants of the time step which led to the triggering of the event will be archived in the result.

## 5.1 Keyword ADAPTATION

Time-step adaptation consists in computing a new time step $\Delta {t}_{i+1}$, from the information of the current time step $\Delta {t}_{i}$ (and of the previous time steps $\Delta {t}_{i-1}$, $\Delta {t}_{i-2}$, ...).

The aim is therefore to compute $\Delta {t}_{i+1} = c \cdot \Delta {t}_{i}$, where $c$ is a real coefficient.

The procedure is as follows:

For occurrence $k$ of the keyword ADAPTATION, one defines an event and a mode of computation of $\Delta {t}_{i+1}$. If the event is satisfied, then one computes ${c}^{k}$ with the chosen mode of computation.

One obtains a summary table of this type:

| Occurrence no. 1 | ${c}^{1} = 4.2$ |
| --- | --- |
| Occurrence no. 2 | event not satisfied |
| Occurrence no. 3 | ${c}^{3} = 1.7$ |
| Occurrence no. 4 | ${c}^{4} = 3.9$ |

Then, one chooses $c=min({c}^{k})$ among the occurrences whose event is satisfied. In this example, the new time step will be equal to $\Delta {t}_{i+1} = 1.7 \cdot \Delta {t}_{i}$ .

To use MODE_CALCUL_TPLUS='IMPLEX', this keyword must be used only once.

### 5.1.1 Operand EVENEMENT

This operand makes it possible to specify the triggering criterion for adaptation of the time step.

If EVENEMENT='SEUIL', then the event is satisfied only if the threshold is crossed.

If EVENEMENT='TOUT_INST', then the event is satisfied at every time instant; this case is mandatory with the IMPLEX method.

If EVENEMENT='AUCUN', then the event is never satisfied.

### 5.1.2 Operands NB_INCR_SEUIL, NOM_PARA, CRIT_COMP, VALE_I

These operands are to be supplied only in the case of a threshold-type event (EVENEMENT='SEUIL'). The event is satisfied if one has a “green light” NB_INCR_SEUIL times in a row, a green light being characterised by the condition defined by NOM_PARA, CRIT_COMP and VALE_I.

For example if NB_INCR_SEUIL=2, NOM_PARA='NB_ITER_NEWTON', CRIT_COMP='LE' and VALE_I=5, then the event is satisfied if one has performed fewer than 5 Newton iterations twice in a row.

**Note**

There is no default value for VALE_I in the catalogue of the operator DEFI_LIST_INST. However, if its value is not supplied, VALE_I will be taken as half the maximum number of Newton iterations (declared in the options of the non-linear operator).

### 5.1.3 Operand MODE_CALCUL_TPLUS

This operand is used to specify the mode of computation of the new time step (in fact, of the coefficient $c$).

If MODE_CALCUL_TPLUS='FIXE', then the coefficient $c$ is fixed.
Its value is determined by the keyword PCENT_AUGM. The new time step is then equal to:

$$
\Delta {t}_{i+1} = \left( 1+\frac{\text{PCENT\_AUGM}}{100.} \right) \Delta {t}_{i}
$$

If the following time step $\Delta {t}_{i+2}$ led to exceeding the next time instant of the list of time instants, it would automatically be reduced and the next increase would not be optimal.
In this case, one limits $\Delta {t}_{i+1}$ so that $\Delta {t}_{i+2} = c \Delta {t}_{i+1}$ makes it possible to reach exactly the next time instant. Thus $\Delta {t}_{i+3}$ (after the compulsory time instant) will be optimised, and so on.

If MODE_CALCUL_TPLUS='DELTA_GRANDEUR', then the coefficient $c$ is linked to the variation, over the time step, of a chosen quantity. The following formula is used:

$$
c = \underset{i \in N}{min}\left( \frac{{V}_{ref}}{\vert \Delta {V}_{i} \vert} \right)
$$

with $N$ the set of nodes or of Gauss points for which $\Delta {V}_{i}$ is not zero. The reference value ${V}_{ref}$ is chosen by the user.

If the field $\Delta V$ is identically zero, then one considers that the criterion (the event) is not satisfied. By default, all the values of the component are examined. However, one can filter the location by using the keywords GROUP_MA (for the fields SIEF_ELGA and VARI_ELGA) or GROUP_NO (for the field DEPL). In this case, the evaluation concerns only the list of mesh-cell groups or the list of node groups.

If MODE_CALCUL_TPLUS='ITER_NEWTON', then the coefficient $c$ is linked to the variation, over the time step, of the number of Newton iterations. The following formula is used:

$$
c = \sqrt{\frac{{N}_{ref}}{{N}_{it}+1}}
$$

where ${N}_{it}$ is the number of Newton iterations performed and ${N}_{ref}$ a reference value chosen by the user. Recall that the prediction is considered to be Newton iteration no. 0, which means that if one converges as early as the prediction then $c=\sqrt{{N}_{ref}}$.

If MODE_CALCUL_TPLUS='IMPLEX', then the coefficient $c$ is linked to the increments of internal variables (cumulative plastic strain or damage) of the previous time step (see [R5.03.81](doc:r5.03.81)). In this case, the keyword ADAPTATION must be used only once. The coefficient $c$ will necessarily lie between 0.5 and 1.2. Moreover, by definition of the IMPLEX method there will be no cause of failure.

### 5.1.4 Operand PCENT_AUGM

This operand is used to specify the percentage increase of the time step if MODE_CALCUL_TPLUS = 'FIXE'. By default, one increases by 100%, that is, one doubles the value of the time step. The value may be negative and must be strictly greater than -100.

### 5.1.5 Operands VALE_REF, NOM_CHAM, NOM_CMP

These operands are used to specify the computation of the increase coefficient $c$ of the time step if MODE_CALCUL_TPLUS='DELTA_GRANDEUR' (cf. u4.34.03-delta_grandeur) with VALE_REF the reference value ${V}_{ref}$ and NOM_CHAM the name of the quantity field considered.

### 5.1.6 Operand NB_ITER_NEWTON_REF

This operand is used to supply the reference number of Newton iterations, denoted ${N}_{ref}$ (cf. u4.34.03-mode_calc_tplus) in the case where MODE_CALCUL_TPLUS = 'ITER_NEWTON'.

## 5.2 Operand INFO

For the moment, this operand is not used.
