# v1.01.368 PLEXU08 - Validation of new CALC_EUROPLEXUS features

**Summary:**

During the CALC_EUROPLEXUS redesign project new features were added to the macro-command. The list of these additions is as follows:

- new constitutive law: VMIS_ISOT_TRAC(modelization A),
- new load: required displacements (DDL_IMPO) other than blockages (modelling B),
- new Modelling: 3D on mesh cells HEXA8 and TETRA4 support. (modellings C and D)

Other features have also been added since:

- pressure loading on the faces of elements 3D (PRES_REP/PRES) (modelling E)
- FORCE_NODALE loading (modelling F)
- new Modelling: 3D_SI on mesh cell support HEXA8 (modelling G)
- load LIAISON_MAIL(modelling H)

The purpose of this test is to validate the proper functioning of these additional features.

## 1 Modelling A

### 1.1 Purpose

The purpose of this test is to validate the use of VMIS_ISOT_TRAC behavior in CALC_EUROPLEXUS.

### 1.2 Description

The mesh, model, elemental characteristics and loads of the plexu03a test are taken over. Only the material assigned to elements BARRE is modified to activate the VMIS_ISOT_TRAC law. We keep an elastic behavior for the hulls.

The elastic properties of materials are recalled:

| Density | ${m}_{b}=2500\mathit{Kg}/{m}^{3}$ | ${m}_{a}=7500\mathit{Kg}/{m}^{3}$ |

and the right section of the cable: ${S}_{a}=1,5{.10}^{-4}{m}^{2}$ .

## 3 Modelling C

### 3.1 Purpose

The purpose of this test is to validate the use of 3D Modelling on mesh cell HEXA8 support in CALC_EUROPLEXUS. It is already possible in EPX to read an initial stress state on the corresponding elements. So we will also use and validate this feature that was immediately activated in CALC_EUROPLEXUS.

### 3.2 Description

This test is the equivalent of test case EPX bm_cub8_ini_med_cont.

This is a single element cube. The lower side is clamped and a load (taxed displacement) is applied to the upper side. This calculation is done with the STAT_NON_LINE operator to produce an initial state for the EPX calculation.

CALC_EUROPLEXUS is then launched with this initial state (movements + stresses) and without additional loading than those that were used to obtain the initial state. EPX is expected to obtain a balanced initial state. One performs about 100 time step. The result is recovered and it is verified that nothing has moved from the initial state.

### 3.3 Validation principle

Comparison with the initial state.

## 7 Modelling G

### 7.1 Purpose

The purpose of this test is to validate the use of elements 3D_SI on mesh cell HEXA8 support with an initial state of displacement and stress and with applied pressure loading (PRES_REP/PRES).

### 7.2 Description

This Modelling is a copy of the E Modelling in which 3D modelling was replaced by 3D_SI.

However, for 3D_SI modelling, there are differences between Code_Aster and EPX. This effect is that the static initial state sending to EPX (with only the one already applied) does not give a balanced state in EPX. The validation is therefore a little different.

A first calculation is started by activating the balancing (EQUI='OUI'). If at the exit of this calculation the displacement and input stress values are found, the correct account of the initial state will be demonstrated for the 3D_SI.

A second calculation is then started without the balancing (EQUI='NON') being activated. The node GRN1 displacement curves are viewed to see that the imbalance is quite limited. This calculation allows the correct consideration of the pressure load to be validated qualitatively and to see that the Code_Aster and EPX models are not too far apart from each other and that it is therefore consistent to use a Code_Aster-EPX chaining with these elements models if the balancing is activated.

## 8 Modelling H

### 8.1 Purpose

The purpose of this test is to validate the use of LIAISON_MAIL loading.

### 8.2 Description

![Figure](/figures/v1.01.368/100000000000032B000001C459D50FBBDE99FF09.png)

On the mesh shown in the above figure, the 3D part (modified by elements 3D) is connected to the overfacial part (modified by elements Q4GG) with kinematic restraints using LIAISON_MAIL/COQUE_MASSIF from the AFFE_CHAR_MECA operator. The faces of the elements 3D in $x=0$ are blocked and a force is imposed on an node at the opposite end.

The calculation is done with STAT_NON_LINE. This provides an initial state to CALC_EUROPLEXUS. CALC_EUROPLEXUS is not required to load other than those that created the initial state.

### 8.3 Validation principle

Comparison with the initial state: LIAISON_MAIL is considered to be well translated to EPX if the system remains at equilibrium, i.e. in the initial state provided.

## 9 Conclusion

Tests show that the different features are well taken into account by CALC_EUROPLEXUS.

However, be careful to use 3D_SI Modelling with an initial state, as EPX Modelling is not completely equivalent to Code_Aster Modelling. It is necessary to put the keyword EQUI to OUI in this case.
