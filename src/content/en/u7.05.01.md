# u7.05.01 Procedure IMPR_RESU in ‘IDEAS’ format

## 1 Purpose

Write a mesh and/or the results of an analysis to a file in the 'IDEAS' format. The use of this format is not recommended because it only handles simple cases.

At present this procedure makes it possible to write, as one chooses:

- a mesh,
- fields at the nodes (of displacements, of temperatures, of eigenmodes, of static modes, …),
- fields by element at the nodes or at the Gauss points (of stresses, of generalised forces, of internal variables…), if these fields by element do not have sub-points.

For concepts of type resultat, one can print only part of the information, by selecting the fields and the order numbers that one wishes to exploit.

It is possible to select the topological entities (nodes, mesh cells, node groups and mesh-cell groups) on which one wants to print the results. The selection is not possible for the printing of the mesh.

## 3 Write formats

The procedure IMPR_RESU makes it possible to write values to a file in the I-DEAS™ format, software marketed by the company EDS / UGS, with a view to graphical visualisation.

### 3.1 Operands FORMAT / VERSION

The operand FORMAT makes it possible to specify the print format and is mandatory in the case of a printout in the I-DEAS™ format.

The operand FORMAT makes it possible to request the creation of an ASCII file, called a "universal file" (of type .unv or .msup), which can be re-read by I‑DEAS™.

The universal file used by the I-DEAS™ software has a different computer structure depending on the version of the I-DEAS™ software. The operand VERSION makes it possible to specify the version of I-DEAS™ that one wishes to use. This operand is therefore licit only when the operand FORMAT is equal to 'IDEAS'. The authorised versions are version 4 and version 5 of I-DEAS™.

By default, the printout is done in version 5.

Example: IMPR_RESU ( RESU= (_F (    FORMAT= 'IDEAS',

> VERSION= 4, .........) ))

Upward compatibility of the versions of I-DEAS™ is ensured from version 5 onwards. One can therefore use versions later than version 5 of I-DEAS™ with files written in version 5 (because any version N of I-DEAS™ can re-read the files created by version N–1).

### 3.2 Operand UNITE

Logical unit of the written file (30 by default, which corresponds to the default number of the mesh files of type .unv in ASTK).

## 4 Keyword RESU

This factor keyword makes it possible to specify the results to be printed and the format according to which one wants to print them.

## 5 Printing the mesh: operands MAILLAGE / MODELE

The operand ‘MAILLAGE’ makes it possible to print the mesh in the I-DEAS™ format. Printing the mesh can be requested only once and before any other result. By default one prints the whole mesh.

One can nevertheless reduce the printing of the mesh to only those mesh cells of the mesh that support a finite element, by defining the operand MODELE. As a result, the concept of type modele is optional in the majority of the printouts. However, it can be used to print only the part of the mesh whose mesh cells are assigned in the model.

Furthermore, in the 'IDEAS' format, when the keyword MODELE is supplied one looks for the I‑DEAS™ finite-element type closest to that of *Code_Aster* , otherwise a default finite-element type is assigned in the I-DEAS™ universal file.

In the 'IDEAS' format, the numbering of the nodes is that of *Code_Aster*  except when the mesh comes from the I-DEAS™ software (one checks for the presence of the character string AUTEUR=INTERFACE_IDEAS in the first line of the mesh title and from the tenth position); in this case one restores the I-DEAS™ numbering.

**Notes:**

1. *The 3D mesh cells of type PYRAM5 and PYRAM13 are not available in I-DEAS. These mesh cells are therefore not written in the universal file created by the command* *IMPR_RESU in the format* *IDEAS.*
2. *The 3D mesh cell of type HEXA27 is not available in I-DEAS. Aster mesh cells of this type are converted into mesh cells of type HEXA20 in the universal file created by the command* *IMPR_RESU in the format* *IDEAS.*

## 6 Operands CHAM_GD and RESULTAT

The values of the computed fields are stored in data structures called fields of quantities (grandeurs). These fields of quantities (grandeurs) may be directly accessible (concept CHAM_GD) or be found in a data structure grouping several fields of quantities (grandeurs) (concept resultat).

- A field of a quantity (grandeur) is a data structure which makes it possible to store fields defined at the nodes (cham_no_* ) or fields defined by element (cham_elem_* ). For the fields by element, one distinguishes the fields defined at the nodes of the elements and the fields defined at the Gauss points of the elements.
- A result concept is composed of one or more fields of quantities (grandeurs). For example, at each analysis step one stores in the resultat data structure the field of the quantity (grandeur) displacement. This structure is therefore a matrix structure of order 2, one index of which is, for example, the list of the analysis time instants and the other the set of the computed fields (displacements, stresses, strains, ...).

One accesses in this case a field of a quantity (grandeur) by specifying a value of an access variable (order number, time instant, frequency, mode number, ...) and a field name ('DEPL', 'SIGM_ELNO',...). There exist several types of result concept: evol_elas, evol_noli, mode_meca,.... To each one corresponds a list of fields and a list of licit access variables.

Given the resultat data structure, one easily understands that the printout possibilities available are those of the fields of quantities (grandeurs), supplemented by specific possibilities.

**Notes:**

1. *The 3D mesh cells of type PYRAM5 and PYRAM13 are not available in I-DEAS. The values of the Aster fields associated with these mesh cells are therefore not written in the universal file created by the command* *IMPR_RESU in the format* *IDEAS.*
2. *The 3D mesh cell of type HEXA27 is not available in I-DEAS. The values of the Aster fields computed on this type of mesh cell are written on mesh cells of type HEXA20; that is, one transfers only the values of the Aster fields on the first 20 nodes.*

### 6.1 Operand CHAM_GD

The values of the fields of quantities (grandeurs) are written in one or more datasets of the universal file:

| dataset 55 | for the fields at the nodes, |
| --- | --- |
| dataset 57 | for the fields by element at the nodes, |
| dataset 56 | for the fields by element at the Gauss points (in fact, one writes constant fields per element by averaging over the Gauss points). |

In I-DEAS™, certain datasets are typed: displacements, stresses, strains, temperature, pressure. One therefore groups the components so as to write the typed datasets, then one writes the other components in datasets of type “UNKNOWN”.

Datasets of type “UNKNOWN” contain at most six components; for a field of a quantity (grandeur) of n components one therefore writes n/6 datasets.

### 6.2 Operand RESULTAT

The operand RESULTAT makes it possible to print the fields contained in a result concept. One can for example choose to print only certain fields (Cf. the keyword: NOM_CHAM).

The result concept is written field of a quantity (grandeur) by field of a quantity (grandeur) in datasets 55, 56 or 57.

## 8 Selection on the components

In order to reduce the volume of the printouts and the size of the «universal» I-DEAS™ file, the user can print only the values of certain components (for example only the displacement along the axis X: component DX or only the stress XX: component SIXX).

### 8.1 Operand TOUT_CMP

This keyword makes it possible to indicate that one wishes to print all the components of the field. This is the default value.

### 8.2 Operand NOM_CMP

This keyword makes it possible to choose the list of the components of the CHAM_GD or of all the fields of the result concept that one wishes to print.

The keywords TOUT_CMP and NOM_CMP cannot be used simultaneously.

When the user specifies the keyword NOM_CMP, the datasets created in the universal file are typed UNKNOWN, which will prevent the user from plotting deformed shapes (even if the dataset contains the components DX, DY, DZ, DRX, DRY, DRZ) and from computing the Von Mises and/or Tresca criteria (even if the dataset contains the components SIXX, SIYY, … SIXZ).

This functionality makes it possible to choose the components, both for cham_no and for cham_elem with real values.

The operand NOM_CMP is not programmed for the cham_no and cham_elem with complex values.

## 9 Selection of the topological entities

In order to reduce the volume of the printouts and the size of the «universal» I-DEAS™ file, it is sometimes necessary to print only part of the result. To do this one may wish to print a field at the nodes only at certain nodes, or a field by element only on certain elements.

This selection, which will be denoted "selection on topological entities", is possible in the 'IDEAS' format.

### 9.1 Operand TOUT

This keyword indicates that one wishes to print the field over the whole structure (all the nodes for a field at the nodes, all the elements for a field by element).

### 9.2 Operand NOEUD

This keyword makes it possible to indicate the list of the nodes on which one wishes to print a cham_no. If this keyword is used in the case of the printout of a cham_elem, it is ignored, and the cham_elem is printed on all the mesh cells specified elsewhere.

### 9.3 Operand GROUP_NO

This keyword makes it possible to indicate the list of the node groups on which one wishes to print a cham_no. If this keyword is used in the case of the printout of a cham_elem, it is ignored, and the cham_elem is printed on all the mesh cells, specified elsewhere.

### 9.4 Operand MAILLE

This keyword makes it possible to indicate the list of the mesh cells on which one wishes to print a cham_elem. For a cham_no, it makes it possible to indicate the list of the nodes, vertices of the mesh cells, at which one wishes to print the cham_no.

### 9.5 Operand GROUP_MA

This keyword makes it possible to indicate the list of the mesh-cell groups on which one wishes to print a cham_elem. For a cham_no, it makes it possible to indicate the list of the nodes, vertices of the mesh cells, at which one wishes to print the cham_no.

## 10 Operand SOUS_TITRE

This argument makes it possible to print a comment subtitle; for more details consult the document [U4.03.01](doc:u4.03.01).

The default SOUS_TITRE is:

- for a cham_gd
- for a cham_no

```text
SOUS_TITRE =    ('CHAMP AUX NOEUDS'    )
```

- for a cham_elem

```text
SOUS_TITRE =    ('CHAMP PAR ELEMENT &LOC(cham_elem)')
```

Example:

```text
CHAMP PAR ELEMENT AUX POINTS DE GAUSS
```

- for a resultat
- for a cham_no

```text
SOUS_TITRE = (    'CHAMP AUX NOEUDS',

'NUMERO D''ORDRE &NUM_ORDRE(Resultat cham_no)',
```

```text

```

- for a cham_elem

```text
SOUS_TITRE = (    'CHAMP PAR ELEMENT &LOC(Resultat cham_elem)',
```

## 11 Note

In Aster, there exist fields by element with sub-points (both for fields by element at the nodes and for fields by element at the Gauss points).

In the 'IDEAS' format, IMPR_RESU does not allow the printout of these fields by element with sub-points.
