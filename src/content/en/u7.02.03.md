# u7.02.03 Operator LIRE_TABLE

## 1 Purpose

Read a file containing a table.

This command makes it possible to read a table written in a file in TABLEAU format, ASTER format, or a format known as LIBRE.

In the TABLEAU and ASTER formats, the file may come directly from an IMPR_TABLE in the same format.

The LIBRE format, as its name indicates, is more flexible. Certain conditions must nevertheless be respected so that the columns are correctly identified and the expected result is obtained.

Produces a concept of type table.

## 2 Syntax

```text
table = LIRE_TABLE(
    ◆ UNITE = unit,
    ◇ FORMAT = / "ASTER",
               / "LIBRE",
               / "TABLEAU" (par défaut),
    ◇ NUME_TABLE = int (défaut: 1),
    ◇ SEPARATEUR = text (défaut: " "),
    ◇ RENOMME_PARA = "UNIQUE" (ou non renseigné),
    ◇ TITRE = text,
    ◇ INFO = / 1,
             / 2,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Operand UNITE

Logical-unit number of the file containing the table or tables to be read.

### 3.2 Operand FORMAT

Name of the format in which the table of the file was written.

#### 3.2.1 Notes

When reading the values, an attempt is made to interpret the value as an integer, a real, a real with the comma instead of the point as the decimal separator, and failing that as a character string.

The empty-cell value is not the same in the TABLEAU, ASTER and LIBRE formats.

#### 3.2.2 Format TABLEAU

This is the default format.

In TABLEAU format, the command estimates the number of columns present in the file. To do this, the lines are split using SEPARATEUR. The number of columns of the table is then taken to be the maximum found over all the lines.

Lines beginning with the character # are treated as comments and added to the title of the table.

Among the values one may find (-), which means that there is no value for this parameter.

There are no delimiters to separate several tables in a file. The end of a table is considered to have been reached when the number of columns decreases.

The TABLEAU format must make it possible to reread the tables printed with IMPR_TABLE in the same format. However, unlike the ASTER format, the type is determined automatically according to the values read. The type of character strings may thus be different.

#### 3.2.3 Format ASTER

The ASTER format requires certain characteristics illustrated in the following table:

| **#DEBUT_TABLE** |  |  |  |  |  |  |  |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **#TITRE** line 1 of the title text |  |  |  |  |  |  |  |
| **#TITRE** line 2 and following |  |  |  |  |  |  |  |
| INTITULE | CHEMIN | SEGMENT | RESU | NOM_CHAM | INST | SIXX |  |
| K8 | K16 | I | K8 | K16 | R | R |  |
| GLOBAL | CHEM1 | 1 | SIG | SIGM_ELNO | 0.00000E+00 | –1.48981E+07 |  |
| GLOBAL | CHEM1 |  | SIG |  | 1.00000E+00 | –2.48981E+07 |  |
| GLOBAL | CHEM1 | 2 | SIG | SIGM_ELNO | 1.00000E+00 | –3.48981E+07 |  |
| … |  |  |  |  |  |  |  |
| **#FIN_TABLE** |  |  |  |  |  |  |  |

Every table in ASTER format begins with the keyword **#DEBUT_TABLE** and ends with **#FIN_TABLE**. These are the delimiters that make it possible to know where the reading begins and where it stops.

**#DEBUT_TABLE** is then followed by title lines, which must be preceded by the keyword **#TITRE**.

There then follows a line containing all the names of the parameters, then a line containing all the types of these parameters. These types must belong to the following list: K8, K16, K24, K32, K80, I, R.

The following lines give the value of all the parameters.

Among the values one may find (-), which means that there is no value for this parameter.

The ASTER format must make it possible to reread the tables printed with IMPR_TABLE in the same format.

#### 3.2.4 Format LIBRE

The LIBRE format is very close to the TABLEAU format except that the character # has no particular meaning and that the absence of a value for a parameter corresponds to an empty string.

### 3.3 Operand NUME_TABLE

It is possible to read one table among several in a file. One indicates the number of the i-th table to be read. By default, the first table is read.

### 3.4 Operand SEPARATEUR

Several consecutive separators count as only one. The default separator is a space.

To indicate that the fields are separated by a tabulation, one will indicate: SEPARATEUR='t'.

### 3.5 Operand RENOMME_PARA

In a table, all the parameters must be distinct. If this is not the case in the file to be read, the reading fails because the table cannot be produced.

By specifying RENOMME_PARA = 'UNIQUE' (the only possible choice if the keyword is filled in), if a parameter that has been read has already been encountered, a numbered suffix of the form «_i» is added to it.

Example: two columns are named INST in the file. The table will be produced with a parameter named INST and the second named INST_1.

### 3.6 Operand TITRE

Title attached to the concept produced by this operand [U4.03.01](doc:u4.03.01).

This title replaces that of the table that was read.

### 3.7 Operand INFO

With INFO = 2, details of the data read are displayed. They are very numerous and are of interest only in order to understand why a file is not read as one expected.

## 4 Examples

### 4.1 Creation of a table in 'ASTER' format with IMPR_TABLE

In this example (extract from zzz128b), several tables are written in 'ASTER' format in a file.

TT=POST_RELEVE_T( ACTION=_F( INTITULE = 'RESU_U2',

NOEUD = ( 'B', 'C', 'D', 'E', 'F', ),

RESULTAT = U2,

NOM_CHAM = 'DEPL',

TOUT_ORDRE = 'OUI',

TOUT_CMP = 'OUI',

OPERATION = 'EXTRACTION'))

IMPR_TABLE( UNITE=37,

TABLE=TT,

FORMAT='ASTER')

IMPR_TABLE( UNITE=37,

TABLE=TT,

FORMAT='ASTER',

NOM_PARA=( 'NOEUD', 'INST', 'ABSC_CURV',

'DX', 'DY', 'DZ', 'DRX', )

)

### 4.2 Reading of tables in 'ASTER' format with LIRE_TABLE

TT2=LIRE_TABLE( UNITE=37,

FORMAT='ASTER',

NUME_TABLE=1,

TITRE='VALIDATION DE LIRE_TABLE',)

TT_RED=LIRE_TABLE( UNITE=37,

FORMAT='ASTER',

NUME_TABLE=2,

TITRE='VALIDATION DE LIRE_TABLE',

)

### 4.3 Reading of a table in LIBRE format

Take for example a table such as this one in OpenOffice Calc:

| Tableau produit dans OpenOffice |  |  |
| --- | --- | --- |
| enregistré au format csv avec le point-virgule comme séparateur |  |  |
| et sans séparateur de texte |  |  |
|  |  |  |
| Colonne A | Colonne B | Colonne C |
| label1 | 111 | 0,09 |
| nom 2 | 222 | 10,09 |
| valeur3 | 444 | 2240,18 |
| exemple4 | 888 | 994640,73 |
| ligne5 | 1776 | 883240965,82 |

It is saved in text format (CSV format) with the semicolon as the column separator and without enclosing the character strings (without a text separator).

The following text file is obtained:

Tableau produit dans OpenOffice;;

enregistre au format csv avec le point-virgule comme separateur;;

et sans separateur de texte;;

;;

Colonne A;Colonne B;Colonne C

label1;111;0,09

nom 2;222;10,09

valeur3;444;2240,18

exemple4;888;994640,73

ligne5;1776;883240965,82

To read it in Code_Aster, one may do:

tab = LIRE_TABLE( UNITE=55,

FORMAT='LIBRE',

SEPARATEUR=';', )
