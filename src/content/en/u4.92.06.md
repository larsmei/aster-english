# u4.92.06 Procedure TEST_COMPOR

## 1 Purpose

This macro-command makes it possible to test the mechanical constitutive laws from the point of view of robustness and reliability:

- in the mechanical case, the test implements a simulation of a multi-axial loading path on a material point, with the aim of checking the robustness of the numerical integration of the constitutive behaviours tested, their insensitivity to a change of units, the invariance of the result with respect to a global rotation applied to the problem, and the correctness of the tangent matrix;
- in the case of the command variables (temperature, …) this test checks that the command variables on which the coefficients of the model depend are correctly taken into account, as well as the strain terms that result from them.

## 3 Operands

### 3.1 Keywords COMPORTEMENT/NEWTON

The syntax of these keywords is described in the document [U4.51.03](doc:u4.51.03) and [U4.51.11](doc:u4.51.11).

### 3.2 Keyword CONVERGENCE

```text
◊    CONVERGENCE=_F()
```

If neither of the two following operands is present, then everything proceeds as if: RESI_GLOB_RELA = 1.E-6.

#### 3.2.1 Operand RESI_GLOB_RELA/RESI_GLOB_MAXI

```text
◊    |RESI_GLOB_RELA =    resrel,                    [R]
```

The algorithm continues the global iterations as long as:

$\underset{i=1,\dots ,\mathrm{nbddl}}{\max}\mid {F}_{i}^{n}\mid >\text{resrel}.\max\mid L\mid$

where ${F}^{n}$ is the residual of iteration $n$ and $L$ the vector of the imposed loading and of the support reactions (cf. [R5.03.01](doc:r5.03.01) for more details).

When the loading and the support reactions become zero, that is when $L$ is zero (for example in the case of a total unloading), one tries to switch from the relative convergence criterion RESI_GLOB_RELA to the absolute convergence criterion RESI_GLOB_MAXI. This operation is transparent for the user (alarm message issued in the .mess file). When the vector $L$ becomes non-zero again, one automatically switches back to the relative convergence criterion RESI_GLOB_RELA.

However, this switching mechanism cannot work at the first time step. Indeed, in order to find a reasonable value of RESI_GLOB_MAXI automatically (since the user has not supplied it), one needs to have had at least one time step that has converged in RESI_GLOB_RELA mode. Consequently, if the loading is zero from the first time instant, the analysis stops. The user must then first check that the zero loading is normal from the point of view of the modelling being carried out, and if that is the case, find another convergence criterion (RESI_GLOB_MAXI for example).

If this operand is absent, the test is performed with the default value, unless RESI_GLOB_MAXI is present.

```text
◊    |RESI_GLOB_MAXI =    resmax,                    [R]
```

The algorithm continues the global iterations as long as:

$\underset{i=1,\dots ,\mathrm{nbddl}}{\max}\mid {F}_{i}^{n}\mid >\text{resmax}$

where ${F}^{n}$ is the residual of iteration $n$ (cf. [R5.03.01](doc:r5.03.01) for more details). If this operand is absent, the test is not performed.

If RESI_GLOB_RELA and RESI_GLOB_MAXI are both present, both tests are performed.

#### 3.2.2 Operand ITER_GLOB_MAXI

```text
◊    ITER_GLOB_MAXI =    /10                        [DEFAUT]
/maglob
```

Maximum number of iterations performed in order to solve the global problem at each time instant (10 by default).

### 3.3 OPTION='THER'

Thermo-mechanical test making it possible to validate the taking into account of the temperature variation in the constitutive laws (cf. V6.07.108). These tests make it possible to check the following two points:

- The thermal expansion is correctly computed (taking into account the variation of the thermal expansion with the temperature)
- The variation of the material coefficients with the temperature is correct, in particular in the incremental solution of the constitutive behaviour.

It is a double simulation, the first in thermomechanics, the second in pure mechanics. The first will be validated by comparison with the second, assuming of course that the constitutive behaviour tested provides a correct solution in pure mechanics.

The first simulation (the solution that one seeks to validate) consists in applying a temperature variation on a material point, by blocking for example the strains along $x$: ${\varepsilon}_{xx}=0$. The imposed temperature increases linearly as a function of time.

The second simulation (which must be equivalent to the first) consists in applying to the same material point an imposed strain along $x$: ${\varepsilon}_{xx}=-{\varepsilon}^{\mathrm{th}}=-\alpha (T)(T-{T}_{\mathrm{ref}})$, in pure mechanics. Indeed, for any constitutive behaviour (assuming the additive decomposition of the strains):

${\sigma}_{xx}=E(T)({\varepsilon}_{xx}-{\varepsilon}^{\mathrm{th}}-{\varepsilon}_{xx}^{p})$

in the first case, ${\sigma}_{xx}=E(T)(0-{\varepsilon}^{\mathrm{th}}-{\varepsilon}_{xx}^{p})$, and in the second: ${\sigma}_{xx}=E(T)(\varepsilon -{\varepsilon}_{xx}^{p})$.

It is therefore enough, at each time instant, to apply, for the mechanical analysis, ${\varepsilon}_{xx}=-{\varepsilon}^{\mathrm{th}}=-\alpha (T)(T-{T}_{\mathrm{ref}})$.

Moreover, in order to obtain the same results in both cases, it is necessary, at each time step of the second simulation, to perform the purely mechanical analysis with coefficients whose values are interpolated as a function of the temperature at the current time instant (operand list_mater).

#### 3.3.1 Operand MATER

```text
♦    MATER=    mater,
```

This keyword makes it possible to supply the name of the material (mater) defined by DEFI_MATERIAU[U4.43.01], in which the parameters required for the chosen constitutive behaviour are provided, as functions of the temperature.

#### 3.3.2 Operand LIST_MATER

```text
♦     LIST_MATER=    list_mater,
```

This keyword makes it possible to supply a list of materials (list_mater), defined by DEFI_MATERIAU[U4.43.01], whose constant parameters correspond to those of mater, interpolated as a function of the temperature.

#### 3.3.3 Operands ALPHA / YOUNG

```text

    YOUNG            =    young,                                    [fonction]
```

These keywords make it possible to supply Young's modulus and the thermal expansion coefficient as functions of the temperature, in order to compute the thermal strains and the corresponding stresses.

#### 3.3.4 Operands TEMP_INIT     / TEMP_FIN/ INST_FIN

### 3.4 OPTION= 'MECA'

Purely mechanical test, which implements a simulation of a strain loading path at a material point, that is to say on a model such that the stress and strain states are homogeneous at every time instant. It thus makes it possible to test a certain number of constitutive models, with the aim of checking the robustness of their numerical integration, their insensitivity to a change of units, the invariance with respect to a global rotation applied to the problem, and the correctness of the tangent matrix. This test carries out, for each modelling, an inter-comparison between the reference solution (obtained with a very fine time step), the solution with a moderately coarse discretisation, the solution with the effect of the temperature (or of another command variable), the solution on changing the system of units ($\mathrm{Pa}$ to $\mathrm{MPa}$), and that obtained after rotation or symmetry (see the document [v6.07.101](doc:v6.07.101)).

#### 3.4.1 Operand LIST_MATER

```text
♦    LIST_MATER=    list_mater,
```

This keyword makes it possible to supply a list of 2 materials (list_mater), defined by DEFI_MATERIAU[U4.43.01], whose constant parameters are evaluated either in $\mathit{Pa}$, or in $\mathit{Mpa}$.

#### 3.4.2 Operands POISSON / YOUNG

```text
    POISSON        =    poisson,                                [R]

    YOUNG            =    young,                                    [R]
```

These keywords make it possible to supply Young's modulus and Poisson's ratio.

#### 3.4.3 Operands LIST_NPAS / LIST_TOLE

```text
◊    LIST_NPAS        =    list_npas,                                [l_I]

◊    LIST_TOLE        =    list_tole,                                [l_R]
```

These keywords make it possible to supply the time discretisation and the corresponding tolerances.

By default, $\text{list\_npas}=[1,1,1,1,1,5,25]$ (4 "equivalent" problems with the coarsest discretisation, that is 1 increment per loading segment, then a variation of the discretisation: 1 then 5 then 25 increments per segment).

By default, $\text{list\_tole}=4\times [1.E-10]+[1.E-1]+2\mathrm{\ast }[1.E-2]+[1.E-8]$. The accuracy required for the equivalent problems is deliberately very small (otherwise there is a risk of a bug). The following accuracies are looser, since the constitutive behaviours are in general sensitive to the time discretisation. The last value is the tolerance on the tangent matrix.

#### 3.4.4 Operand PREC_ZERO

```text
◊    PREC_ZERO        =    prec_zero,                                [l_R]
```

This keyword makes it possible to supply a "numerical" zero for each tested variable, in order to compute a significant relative error. prec_zero therefore has the same length as vari_test. By default this list is equal to: $3\times 1.E-10$.

#### 3.4.5 Operand VARI_TEST

```text
◊    VARI_TEST        =    vari_test,                                [Kn]
```

List of the tested components, assumed invariant in the equivalent problems (rotation, change of units). By default vari_test = ('V1',VMIS','TRACE').

#### 3.4.6 Operand SUPPORT

```text
◊     SUPPORT        =    /‘POINT’                                [DEFAUT]
/'ELEMENT'
```

See [U4.51.12](doc:u4.51.12)

#### 3.4.7 Keyword MODELISATION

The keyword MODELISATION makes it possible, in the case SUPPORT='ELEMENT', to carry out the analysis on a 3D element or on a 2D element, in plane stresses. It is not available in the case SUPPORT='POINT', because it is enough to impose a zero value on the components corresponding to the plane stresses or to the plane strains in order to obtain the same result.

#### 3.4.8 Keyword ANGLE

This keyword makes it possible to specify an angle (in degrees) in order to perform an overall rotation about $Z$ applied both to the loading, to the mesh, and to the post-processing. This makes it possible above all to check the reliability of the integration of the constitutive behaviour, as in the tests COMP001, COMP002.

By default, the rotation is identically zero.

In the case of materials possessing an intrinsic orientation (orthotropy, crystalline constitutive behaviours), one should also use the keyword MASSIF, with a first angle value identical to that supplied under ANGLE.

#### 3.4.9 Keywords MASSIF/ANGL_EULER / ANGL_REP

These keywords make it possible to define an orientation intrinsic to the material (orthotropy, crystalline constitutive behaviours), and make it possible to call, within the macro-command, the keyword MASSIF of AFFE_CARA_ELEM[U4.42.01].

By default, the orientation is zero, and one does not call AFFE_CARA_ELEM.

#### 3.4.10 Keywords VERI_MATR_OPTION

This keyword is used to group the operands that manage the behaviour of TEST_COMPOR during the checking of the analytical tangent matrix against that obtained by numerical perturbation.

#### 3.4.11 Operand VALE_PERT_RELA

```text
◊    VALE_PERT_RELA    =                                        [R]
```

Makes it possible to define the value of the numerical relative perturbation that enters into the computation of the perturbed matrix. For more detail refer to [U4.51.11](doc:u4.51.11).

#### 3.4.12 Operand PRECISION

```text
◊    PRECISION            =                                        [R]
```

The operand PRECISION makes it possible to define the value above which one considers that the analytical matrix and the perturbed matrix are different.

#### 3.4.13 Operand PREC_ZERO

```text
◊    PREC_ZERO            =                                        [R]
```

Below PREC_ZERO, one does not compare the values of the terms of the tangent matrix. This makes it possible to handle the situations in which the terms of the perturbed tangent matrix are very close to zero.

### 3.5 Operand INFO

Specifies the detail of the information printed in the message file.

In INFO=2 mode, one prints all the tables produced by SIMU_POINT_MAT.
