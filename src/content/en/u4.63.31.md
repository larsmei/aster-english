# u4.63.31 Operator REST_GENE_PHYS

## 1 Purpose

Recover in the physical basis results in generalised coordinates.

This operator makes it possible to recover in the physical space results obtained on a system in generalised coordinates by modal recombination methods.

The concept produced is a concept of type:

- dyna_trans if the generalised results come from an analysis by modal recombination or following the extrapolation of experimental measurement results onto a numerical model (the input concept is of type tran_gene),
- mode_meca for the recovery following a modal analysis with projection onto a modal basis (the input concept is of type mode_gene),
- dyna_harmo for the recovery following a harmonic analysis with projection onto a modal basis, without substructuring (the input concept is of type harm_gene).

## 2 Syntax

```text
/ dyna_harmo
/ dyna_trans
/ mode_meca = REST_GENE_PHYS(
    ◆ RESU_GENE = harm_gene / mode_gene / mode_meca / tran_gene,
    ◇ MODE_MECA = mode_meca,
    ◇ NUME_DDL = nume_ddl,
    ◇ / TOUT_INST = "OUI" (ou non renseigné),
      / INST = list[float],
      / LIST_INST = listr8,
      / TOUT_ORDRE = "OUI" (ou non renseigné),
      / NUME_ORDRE = list[int],
      / NUME_MODE = list[int],
    ◇ / FREQ = list[float],
      / LIST_FREQ = listr8,
    ◇ CRITERE = / "ABSOLU",
                / "RELATIF" (par défaut),
    # Si: (equal_to("CRITERE", 'RELATIF'))
        ◇ PRECISION = float (défaut: 1e-06),
    # Si: (equal_to("CRITERE", 'ABSOLU'))
        ◆ PRECISION = float,
    # Si: exists("RESU_GENE")
        ◇ ENVELOPPE = / "NORME_MOMENT",
                      / "VALE_ABS",
    ◇ INTERPOL = / "LIN",
                 / "NON" (par défaut),
    ◇ / MULT_APPUI = "OUI" (ou non renseigné),
      / CORR_STAT = "OUI" (ou non renseigné),
    ◇ / ACCE_MONO_APPUI = list[fonction / formule / nappe],
    ◇ / GROUP_NO = list[grno],
    ◇ / GROUP_MA = list[grma],
    ◇ TOUT_CHAM = "OUI" (ou non renseigné),
    # Si: not exists("TOUT_CHAM")
        ◇ NOM_CHAM = / "ACCE" (par défaut),
                     / "ACCE_ABSOLU",
                     / "DEPL",
                     / "EFGE_ELNO",
                     / "FORC_NODA",
                     / "SIGM_ELNO",
                     / "SIPO_ELNO",
                     / "VITE",
    ◇ & DIRECTION = list[float],
    ◇ TITRE = text,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

### 3.2 Operand MODE_MECA

```text
◊    MODE_MECA = mode
```

Concept of type mode_meca containing a basis of eigenmodes obtained by dynamic substructuring.

This operand is used in the case of a recovery in the physical system of a transient-analysis result carried out on a modal basis computed by dynamic substructuring. The modal basis contained in the concept mode_meca was obtained by the command REST_SOUS_STRUC [U4.63.32](doc:u4.63.32). It is therefore a double recovery, after having carried out a double projection (cf. example in [§4]).

### 3.3 Operand NUME_DDL

```text
◊    NUME_DDL = numeddl
```

Concept of type nume_ddl containing a numbering corresponding to a reduced model in the case of an analysis with dynamic condensation when the user wishes a recovery on the degrees of freedom belonging to this reduced model.

This operand thus makes it possible to obtain, following the recovery, a concept mode_meca which could be used subsequently for an analysis on the reduced model (see the test case SDNV107A for an example).

### 3.4 Operands TOUT_ORDRE / NUME_ORDRE / NUME_MODE / TOUT_INST / LIST_INST / INST

```text
◊    /    TOUT_ORDRE = 'OUI'
```

In order to recover on all the modes of the concept mode_gene.

```text
/    NUME_ORDRE = num
```

List of integers containing the order numbers of the modes on which the recovery is carried out.

```text
/ NUME_MODE = num
```

List of integers containing the numbers of the modes in the global spectrum on which the recovery is carried out.

```text
/ TOUT_INST = 'OUI'
```

If one wishes to recover on all the time instants contained in the generalised result (tran_gene).

/ LIST_INST = list

List of increasing reals of type listr8 containing the time instants for which one wishes to carry out the recovery.

/ INST = inst

List of reals containing the time instants on which the recovery is carried out.

For a transient analysis, one checks that the time instants requested by the option LIST_INST do indeed lie in the domain of definition of the tran_gene.

The results at an arbitrary time instant may be obtained by linear interpolation between the results at two analysis time instants actually contained in the tran_gene.

### 3.5 Operands FREQ / LIST_FREQ

These operands are used in the case of a recovery on the physical basis of generalised harmonic analyses (harm_gene).

```text
/    FREQ = freq
```

Frequency at which one wishes to recover the harmonic analysis

```text
/    LIST_FREQ = list
```

List of reals containing the frequencies for which one wishes to carry out the recovery.

For each frequency indicated, one recovers the fields obtained at the nearest analysis frequency. There is no interpolation.

### 3.6 Operands TOUT_CHAM / NOM_CHAM

```text
◊    /    TOUT_CHAM = 'OUI'
```

Makes it possible to recover the fields of symbolic name DEPL, VITE and ACCE contained in the generalised result (tran_gene, harm_gene).

```text
/    NOM_CHAM = nomcha
```

List of the symbolic names of the fields that one wishes to recover: 'DEPL', 'VITE', 'ACCE' and, if they have been computed, 'ACCE_ABSOLU', 'EFGE_ELNO', 'SIPO_ELNO', 'SIGM_ELNO' or 'FORC_NODA'.

The recovery of the fields 'EFGE_ELNO', 'SIPO_ELNO', 'SIGM_ELNO' and 'FORC_NODA' is possible in the multi-support case.

### 3.9 Operand MULT_APPUI

After the transient analysis of the generalised seismic response of a structure, the user must indicate 'OUI' under the keyword MULT_APPUI in order to recover the absolute displacements (and/or velocities and/or accelerations). If nothing is specified, the operator recovers the relative quantities.

**Note:**

If the transient analysis of the generalised seismic response of a structure is carried out in the TRAN_GENE option of CALC_MISS, the result is directly absolute without specifying MULT_APPUI='OUI', because the loading comes directly from the seismic soil forces computed by MISS.

### 3.10 Operands ACCE_MONO_APPUI and DIRECTION

```text
◊    | ACCE_MONO_APPUI = (gamma1, gamma2, gamma3),              [fonction]
     | DIRECTION        = (dx1, dy1, dz1, dx2, dy2, dz2, dx3, dy3, dz3),  [l_R]
```

After the analysis of the generalised seismic response of a singly excited structure, the user indicates the name of the imposed accelerograms (keyword ACCE_MONO_APPUI) and the directions of the earthquake (keyword DIRECTION) in order to recover the absolute accelerations (accelerations only, which will be stored in the field ACCE_ABSOLU). If nothing is specified, the operator recovers the relative quantities. The field ACCE_ABSOLU will then be absent.

**Note:**

It is possible to impose up to 3 accelerograms under the keyword ACCE_MONO_APPUI. They must be the same as those imposed under the keyword FONC_MULT of the factor keyword EXCIT of the command DYNA_VIBRA.

If the transient analysis of the generalised seismic response of a structure is carried out in the TRAN_GENE option of CALC_MISS, the result is directly absolute without specifying ACCE_MONO_APPUI and DIRECTION, because the loading comes directly from the seismic soil forces computed by MISS.

### 3.11 Operand CORR_STAT

After the transient analysis of the generalised seismic response of a structure, provided that the user has requested 'CORR_STAT' = 'OUI' in DYNA_VIBRA, the displacements (and/or velocities and/or accelerations) can then be recovered with correction, by the static modes, of the truncation of the modal basis. The user must indicate 'OUI' under the keyword CORR_STAT. If nothing is specified, the operator recovers the quantities without static correction.

### 3.12 Operand GROUP_NO

```text
◊    /    GROUP_NO = lgrno
    /    GROUP_MA = lgrma
```

After a transient dynamic analysis on a modal basis, the user may recover kinematic fields on only part of the nodes or mesh cells of the mesh.

List of the node/mesh-cell groups corresponding to the locations where the user wants to recover kinematic fields.

### 3.13 Operand ENVELOPPE

```text
◊    ENVELOPPE = "VALE_ABS" / "MOMENT_NORM"
```

This operand makes it possible to compute the envelopes of the various fields over time:
`ACCE`, `VITE`, `DEPL`, `EFGE_ELNO` and `REAC_NODA`, using one of the following options:

| Option | Description |
| --- | --- |
| VALE_ABS | Computes the maximum of the components from their absolute values: for each scalar component $x_i(t)$, one retains $\max_t \|x_i(t)\|$. |
|  |  |
| NORME_MOMENT | Similar to **VALE_ABS**, except for the computation of the envelope of the moment components. In this case, the envelope is determined from the resultant norm of the moment. Formally, if $\mathbf{M}(t) = (M_x(t), M_y(t), M_z(t))$, one defines the norm of the moment as $\\|\mathbf{M}(t)\\| = \sqrt{M_x(t)^2 + M_y(t)^2 + M_z(t)^2}$. The time instant corresponding to the maximum norm is $t^* = \arg\max_t \\|\mathbf{M}(t)\\|$. The envelope values are then given by $\mathbf{M}^* = \mathbf{M}(t^*)$. In other words, the envelope corresponds to the components of the moment at the time instant at which the resultant moment is the most intense. |

## 4 Example: Recovery of a transient-analysis result carried out on a modal basis computed by dynamic substructuring: double recovery

Modal analysis on a generalised model: $(\stackrel{ˉ}{\text{K}}-\stackrel{ˉ}{\text{M}}{\omega}^{2})\eta =0$

with $\stackrel{ˉ}{\text{K}}=(\begin{array}{ccc}{\stackrel{ˉ}{\text{K}}}_{1}& & \\ & {\stackrel{ˉ}{\text{K}}}_{2}& \\ & & \ddots \end{array})$ and $\stackrel{ˉ}{\text{M}}=(\begin{array}{ccc}{\stackrel{ˉ}{\text{M}}}_{1}& & \\ & {\stackrel{ˉ}{\text{M}}}_{2}& \\ & & \ddots \end{array})$ and linking equations $\text{L}\eta =0$

```text
modgene = CALC_MODES ( MATR_RIGI = :math:`\stackrel{ˉ}{\text{K}}`,
MATR_MASS = :math:`\stackrel{ˉ}{\text{M}}`
)
```

One obtains a generalised modal basis: the eigenmodes of the global structure are linear combinations of the eigenmodes of the substructures: it is onto this generalised modal basis $\Phi$ that one projects the assembled generalised matrices (double projection).

$\begin{array}{cccc}\overline{\overline{\text{K}}}& =& {\Phi}^{T}\overline{\text{K}}\Phi & \text{opérateur}\text{PROJ\_MATR\_BASE}\\ \overline{\overline{\text{M}}}& =& {\Phi}^{T}\overline{\text{M}}\Phi & \\ \overline{\overline{\text{C}}}& =& {\Phi}^{T}\overline{\text{C}}\Phi & \\ {\overline{\overline{\text{F}}}}_{\mathrm{ext}}& =& {\Phi}^{T}{\overline{\text{F}}}_{\mathrm{ext}}& \text{opérateur}\text{PROJ\_VECT\_BASE}\end{array}$

Transient analysis on the modal basis $\Phi$ obtained by dynamic substructuring.

```text
trangen = DYNA_VIBRA (BASE_CALCUL="GENE",
                      MATR_MASS = :math:`\overline{\overline{\text{M}}}`,
                      MATR_RIGI = :math:`\overline{\overline{\text{K}}}`,
                      MATR_AMOR_GENE = :math:`\overline{\overline{\text{C}}}`,
                      EXCIT = _F(VECT_ASSE_GENE = :math:`{\overline{\overline{\text{F}}}}_{\mathrm{ext}}`)    )
```

Recovery of the modal basis $\Phi$ in the initial physical system:

```text
modmeca = REST_SOUS_STRUC    (    RESU_GENE = modgene,
SQUELETTE = squel    )
```

Recovery of the transient analysis in the initial physical system:

```text
tran = REST_GENE_PHYS( RESU_GENE = trangen,
                       MODE_MECA = modmeca    )
```
