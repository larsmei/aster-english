# u4.15.12 Operator DEBUG

## 1 Purpose

Makes it possible to activate or deactivate the debugging functionalities between the various commands.

Some keywords are accessible in the commands DEBUT and POURSUITE.

This is a functionality intended for developers.

## 2 Syntax

```text
DEBUG(
    ◇ SDVERI = / "OUI",
               / "NON",
    ◇ JXVERI = / "OUI",
               / "NON",
    ◇ JEVEUX = / "OUI",
               / "NON",
    ◇ IMPR_MACRO = / "OUI",
                   / "NON",
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Operand SDVERI

Warning: this functionality can cause a non-negligible extra cost during the execution.

This keyword triggers the checking of the data structures produced by the operators. It is used within the code development procedures in the non-regression tests.

### 3.2 Operand JXVERI

Makes it possible to check the integrity of the memory segments between two consecutive command executions. This functionality concerns only the so-called static memory-management mode, when a memory area allocated at the start of the execution is managed by JEVEUX by chaining the various objects allocated during the execution. In the so-called dynamic memory-management mode the various objects are allocated directly by the system and no chaining exists.

### 3.3 Operand JEVEUX

Makes it possible to activate the debug operating mode of the JEVEUX memory manager: non-deferred unloading to disk and assignment of the value segments to an undefined value [D6.02.01](doc:d6.02.01).

### 3.4 Keyword IMPR_MACRO

Allows or disallows the displays produced by the macros in the message file. Reading the message files can be tedious when they contain all of the echoes of the sub-commands generated by the macro itself. By default, only the echo of the commands explicitly called by the user in the command set will appear.
