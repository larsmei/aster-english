# u4.51.04 Operator MECA_NON_LINE

**Summary:**

Compute the mechanical or coupled thermo-hydro-mechanical evolution, in quasi-statics or in
dynamics, of a structure in the non-linear regime.

The non-linearity is linked either to the constitutive behaviour of the material (for example plastic), or to the
geometry (for example in large displacements), or to frictional contact.

To have details on the solution method employed, one will refer to the reference documents
[R5.03.01] and
[R5.05.05].

The evolution may be studied in several successive jobs (re-entrant concept), either in
continuation (the last computed time instant is the initial time instant of the following analysis), or in restart
starting from an earlier time instant.

Produces a data structure of type evol_noli.

This documentation is provisional; the operator cannot be used in
AIP studies and it lies outside the scope of qualification.

## 2 Contents of the data structure EVOL_NOLI

The data structure EVOL_NOLI contains the list of the fields archived during the analysis (according to
the various options of the keyword ARCHIVAGE). By default, it contains, for each time instant,
the list of the following fields:

- DEPL: field (at the nodes) of the displacements;
- SIEF_ELGA: field (at the Gauss points) of the stresses;
- VARI_ELGA: field (at the Gauss points) of the internal variables;
- COMPORTEMENT: map of the constitutive behaviour. This map contains information on the non-linear

constitutive behaviour used; it is not readable when one prints it in MED format.

In addition to these fields, the data structure also contains parameters. At each
time instant, one stores at least:

| **Name** | **Origin keyword** | **Description** | **Type** |
| --- | --- | --- | --- |
| INST |  | Value of the analysis time instant | R |
| EXCIT | EXCIT | Information on the loadings | K24 |
| MODELE | MODELE | Model | K8 |
| CARAELEM | CARA_ELEM | Elementary characteristics | K8 |
| CHAMPMAT | CHAM_MATER | Material field | K8 |

## 3 General parameters

The general parameters describe the model, the material field and the elementary
characteristics (in particular for the structural elements).

MODELE is the name of the model whose elements are the subject of the mechanical analysis. The data
structure comes from the command [U4.41.01](doc:u4.41.01). It is always mandatory.

CHAM_MATER is the name of the material field assigned on the model. The data
structure comes from the command [U4.43.01](doc:u4.43.01). All the main mesh cells of the
model must be associated with a material.

CARA_ELEM is the name of the characteristics of the shell, beam, pipe, bar, cable and
discrete elements assigned on the model. The data structure comes from the command
[U4.42.01](doc:u4.42.01). Obviously, this keyword is optional: if the model does not
contain such elements, it is not useful; on the other hand, if the model contains such
elements, it is mandatory.

## 4 Parameterisation of the analysis

The non-linear analysis is solved by an incremental method, so it is necessary to
**parameterise** the analysis. One uses for this the time variable (denoted INST), even if it has no
physical meaning in statics.
The (pseudo)-temporal discretisation is managed by the factor keyword INCREMENT, which will define
the time intervals taken in the incremental method.

**Note**

The time instants thus defined have a physical meaning only for constitutive relations in which
time appears explicitly (viscoelastic or viscoplastic, for example).
In the other cases, they only make it possible to index the load increments and to
parameterise the evolution of a possible temperature field.

### 4.1 General definition of the list of time instants

To supply the list of time instants, there are two ways of proceeding.

1/ One gives the list of time instants by the keyword LIST_INST. This list is given by the operator DEFI_LIST_REEL [U4.34.01](doc:u4.34.01).
By default the operator will impose an automatic cutting of the time step.

2/ One may define the analysis time instants by the operator DEFI_LIST_INST [U4.34.03](doc:u4.34.03) and manage
simultaneously the automatic cutting of the time step and other advanced functionalities.

To deactivate the automatic cutting, it is enough to impose the action ARRET in ECHEC:

```python
inst = DEFI_LIST_INST(DEFI_LIST=_F(LIST_INST=listr8),
                      ECHEC=_F(EVENEMENT="ERREUR", ACTION="ARRET"))
```

One must also recall that, by convention, the initial time instant of the analysis
of a virgin analysis (without restart) is designated by the order number 0. Furthermore,
the order numbers are necessarily increasing and without "gaps".

### 4.2 Management of restarts

If one specifies nothing, the analysis will be carried out over all the time instants defined by LIST_INST. It is
possible to manage this list more finely.
The initial time instant of the analysis (which therefore is not (re)computed) is designated either by its value
(INST_INIT), or by its order number in the list of time instants (NUME_INST_INIT).

In the absence of the keywords INST_INIT or NUME_INST_INIT, the default is NUME_INST_INIT=0.

The final time instant (last computed step) is designated in the same manner as the initial time instant
(either NUME_INST_FIN, or INST_FIN), except that it is not possible to refer to the time instant
of the initial state.

- If the automatic recutting of the time step is activated, NUME_INST_FIN does not take it

into account and always works on the initial list of time instants. NUME_INST_INIT and NUME_INST_FIN
are active only at initialisation.

- The list of time instants being strictly increasing, it may happen that certain time steps

are not archived although they were requested. For example, in the case of a restart of an analysis.
If the analysis in restart of a previous analysis has no time instant greater than the first
phase of the analysis, no time step will be archived.

**Notes**

**A - Simple example (default behaviour)**

```python
listInst = DEFI_LIST_REEL(DEBUT=0.,
                          INTERVALLE=_F(JUSQU_A= 10.,NOMBRE=10)),
evolNoli = MECA_NON_LINE(INCREMENT=_F(LIST_INST=listInst,
                         INST_FIN=4.)),
evolNoli = MECA_NON_LINE(reuse=evolNoli,
                         INCREMENT=_F(LIST_INST=listInst),
                         ETAT_INIT=_F(EVOL_NOLI=evolNoli))
```

The first MECA_NON_LINE carries out the analysis for the time instants 1, 2, 3 and 4.

### 4.3 Selection of the time instants

The time instants in MECA_NON_LINE are located by an order number (an integer). If the user
wants to use a time instant (a real) and not an order number for the selection, the keywords
PRECISION and CRITERE make it possible to identify this order number (see [U4.71.00](doc:u4.71.00)
for the detailed syntax).

These parameters serve to locate the right order number (NUME_INST_FIN/NUME_INST_INIT) when
the user supplies the time instant (INST_FIN/INST_INIT).

Let the following list of time instants be:

| NUME | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| INST | 0.0010 | 0.0020 | 0.0030 | 0.0040 | 0.0050 | 0.0060 | 0.0070 |

If the user wants to select the time instant corresponding to NUME=4, it is enough to say
INST=0.0040.

Let us take another example

| NUME | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| INST | 0.10000001 | 0.10000002 | 0.10000003 | 0.10000004 | 0.10000005 | 0.10000006 | 0.10000007 |

If the user wants to select the time instant corresponding to NUME=4, it is not enough to say
INST=0.10000004, because the relative gap between the time instants is
$\frac{0,10000005-0,10000004}{0,10000004}=1,0\times 10^{-7}$ which is smaller than the
default precision value ($1,0\times 10^{-6}$ ).
One will therefore not be able to distinguish NUME=3, 4 and 5 (the code then stops in fatal error).
It is then enough to change the parameter PRECISION in order to be able to select the time instant
(in our example, PRECISION=1E-8 will be suitable).

## 5 Settings of the non-linear solvers

### 5.1 Choice of the method

There exist three broad categories of accessible non-linear solvers:

- the Newton method (and its variants);
- the non-linear solvers called [SNES](https://petsc.org/release/manual/snes/) (Scalable Nonlinear Equations Solvers) of the [PETSC](http://petsc.org) library;
- the solver `RASPEN` (Restricted Additive Schwarz Preconditioned Exact Newton), which is based on a non-linear domain-decomposition approach.

The solver is selected by the keyword METHODE.

### 5.2 Newton method and its variants

When METHODE="NEWTON", one uses the Newton-Raphson algorithm to solve the problem
(see [R5.03.01](doc:r5.03.01)).

It is the factor keyword NEWTON (a single occurrence) which makes it possible to set the various
parameters.

The prediction phase (Cf. [R5.03.01](doc:r5.03.01)) aims to compute an estimate
of the displacement field in order to allow Newton's method to converge more rapidly.
When the keyword is absent, it is the rate tangent matrix (option RIGI_MECA_TANG) which
is used if one has chosen for Newton's method a PREDICTION='TANGENTE', and it is the
elastic matrix (option RIGI_MECA) which is used if one has chosen PREDICTION='ELASTIQUE'.

The keyword REAC_INCR=mf makes it possible to control the frequency of updating of the matrix
with respect to the time steps.

- If the matrix used in prediction corresponds to the elastic computation, it is evaluated only once

at the initial time instant, at the start of the algorithm, unless the elastic characteristics depend on
time or on a command variable such as the temperature, which depends on time

- This "elastic" matrix is computed using the Young's modulus given under the keyword ELAS

of the operator [U4.43.01](doc:u4.43.01), and not the slope at the origin
of the tensile curve given under the keyword TRACTION (and which, for its part, serves in the expression
of the constitutive relations VMIS_ISOT_TRAC, VMIS_ECMI_TRAC and VISC_ISOT_TRAC)

**Notes**

The matrix used for the global iterations of the method is the (consistent) tangent matrix
[R5.03.01](doc:r5.03.01) if MATRICE='TANGENTE' or the elastic matrix if MATRICE='ELASTIQUE'.

The keyword REAC_ITER=it makes it possible to control the frequency of updating of the matrix
with respect to the Newton iterations.
Thus at the first Newton iteration, one reassembles the tangent matrix only if it equals 1:
otherwise one keeps the matrix used in the prediction phase. By convention, if it equals 0
the matrix is not re-evaluated during the whole time step.

### 5.3 Method `SNES`

When METHODE="SNES", one calls the non-linear solver [SNES](https://petsc.org/release/manual/snes/) of the [PETSC](http://petsc.org) library. It is a very generic implementation of numerous different solvers, ranging from the classical Newton method to the BFGS method or the Picard method, as well as all the possible combinations of the latter (see [bib1]_). The parameterisation is done by a list of options transmitted in the form of character strings by the keyword OPTION_PETSC of the factor keyword SOLVEUR (see [U4.50.01](doc:u4.50.01)). Its use is reserved for advanced users.

### 5.4 Method `RASPEN`

The method `RASPEN` is based on a non-linear domain-decomposition method. It is usable only in the HPC context. It relies on 2 levels of non-linear solvers:

- a local level, where a non-linear problem is solved on each subdomain, without communication with its neighbours and therefore in a parallel and asynchronous manner;
- a global level, which exploits the previous local solutions in order to facilitate the solution of the problem considered.

As for the method `SNES`, the parameterisation is done by a list of options transmitted in the form of character strings by the keyword OPTION_PETSC of the factor keyword SOLVEUR. The options which concern the local solver are prefixed by `lsnes_` whereas the options which concern the global solver are prefixed by `gsnes_`.
One may conveniently define these options as follows:

```python
myOptions = (
    # local snes
    "-prefix_push lsnes_ "
    + "-snes_monitor -snes_linesearch_type basic -snes_rtol 1.e-8 -snes_atol 1.e-50 -snes_max_it 5  "
    + "-ksp_type preonly  -pc_type lu -pc_factor_mat_solver_type mumps "
    + "-prefix_pop "
    # global snes
    + "-prefix_push gsnes_  "
    + "-snes_linesearch_type basic -ksp_monitor -ksp_rtol 1.e-7 -ksp_atol 1.e-50  -snes_max_it 20  "
    + "-prefix_pop "
)
```

The first line expresses the fact that one is going to parameterise the non-linear solver local to each subdomain, called "lsnes" ("l" for local, "snes" for Scalable Nonlinear Equations Solvers).
Next, one expresses that one wants to monitor the local non-linear solver, which by default is Newton's method; one specifies that the line search is not used (basic means that one uses a step of 1.) and one gives the relative and absolute convergence criteria as well as the maximum number of iterations.
Next one expresses that one wishes to use the MUMPS solver to solve the linearised problems.
One then does the same for the global non-linear solver called "gsnes".

For any further detail, the reader is referred to [bib2]_.
Its use is reserved for advanced users.

### 5.5 Line search

The line search may make it possible to improve the convergence of Newton's method
(Cf. [R5.03.01] for more details).

**Note:**

It is inadvisable to use the line search with the GROT_GDEP strains, for
the modellings COQUE_3D and in the presence of contact.

This keyword makes it possible to choose the line-search method, that is to say the algorithm for
searching for the zero of the functional (see [R5.03.01](doc:r5.03.01)).
The method is a one-dimensional secant method.

The parameters ITER_LINE_MAXI=itelin and RESI_LINE_RELA=reslin are the
parameters of the line search.
One gives the maximum number of iterations itelin to be carried out and the precision reslin to
be reached in order to achieve convergence of the line search.

The keywords RHO_MIN, RHO_MAX and RHO_EXCL set the interval $I$ in which one computes the
coefficient $\rho$ of the line search, in the form

$$
I=[\rho_{min},\rho_{max}]-[-\rho_{exc},\rho_{exc}]
$$

## 6.1 Settings of the convergence

The factor keyword CONVERGENCE makes it possible to control the convergence parameters of the analysis.

The keyword ITER_GLOB_MAXI gives the maximum number of iterations carried out to solve the
global problem at each time instant. An excessive increase of this parameter
is generally the sign of a problem in the modelling or of an inadequate temporal
discretisation.

There exist two convergence criteria: RESI_GLOB_RELA in relative form and RESI_GLOB_MAXI in absolute form.
If one supplies nothing, then everything proceeds as if RESI_GLOB_RELA = 1.E-6.

For RESI_GLOB_MAXI=resmax, the algorithm continues the global iterations as long as

where ${F}^{n}$ is the residual of iteration n (Cf. [R5.03.01](doc:r5.03.01) for more
details). If this operand is absent, the test is not carried out.

For RESI_GLOB_RELA=resrel, the algorithm continues the global iterations as long as:

$$
\underset{i=1, \dots , \mathrm{nbddl}}{\max} {F}^{n}
>
\text{resrel} . {\max} L
$$

where $L$ is the vector of the imposed loading and of the support reactions
(Cf. [R5.03.01](doc:r5.03.01) for more details).

When the loading and the support reactions become zero, that is to say when $L$ is
zero (for example in the case of a total unloading), RESI_GLOB_RELA is displayed as -1, and one tries
to switch from the relative convergence criterion RESI_GLOB_RELA to the absolute convergence
criterion RESI_GLOB_MAXI. This operation is transparent for the user
(alarm message issued in the .mess file). When the vector $L$
becomes non-zero again, one automatically switches back to the relative convergence criterion
RESI_GLOB_RELA.

However, this switching mechanism cannot work at the first time step.
Indeed, in order to find a reasonable value of RESI_GLOB_MAXI automatically
(since the user has not supplied it), one needs to have had at least one converged step
on a RESI_GLOB_RELA mode. Consequently, if the loading is zero from the first time instant,
the analysis stops. The user must then already check that the zero loading is normal
from the point of view of the modelling being carried out, and if such is the case, find another
convergence criterion (RESI_GLOB_MAXI for example).

If RESI_GLOB_RELA and RESI_GLOB_MAXI are both present, both tests are carried out.

## 6.2 Advanced convergence criteria

The criterion RESI_REFE_RELA $\varepsilon_{refe}$ leads one to estimate the convergence of
Newton's algorithm in the following manner. Starting from a reference, which may be:

- A stress SIGM_REFE
- A strain EPSI_REFE for incompressible elements, grid elements and membrane elements;
- An internal variable VARI_REFE if one uses non-local laws with strain gradient;
- A thermal flux FLUX_THER_REFE in a THM case;
- Two hydraulic fluxes FLUX_HYD1_REFE and FLUX_HYD2_REFE in an HHM case;
- A displacement DEPL_REFE if one uses joint elements with a constitutive behaviour of type CZM;
- A force EFFORT_REFE and a moment MOMENT_REFE if one uses structural elements (discrete elements, bars, beams or cables);
- A line force EFFORT_REFE and a line moment MOMENT_REFE if one uses 2D structural elements (plates and shells);

One computes a residual reference ${F}^{\mathit{ref}}$ (a vector of the same length as
the residual vector). Convergence will be achieved if and only if:

$$
\forall i \in [1, \dots, \mathit{nbddl} ] \mid {F}_{i}^{n}\mid
<
\varepsilon_{refe} \, {F}_{i}^{\mathit{ref}}
$$

EFFORT_REFE and MOMENT_REFE not expecting values of the same dimension for the 1D and 2D structural
elements, it is strongly inadvisable to use this convergence criterion on
a model comprising these two types of element.

## 9 Restarts, archiving and management of the initial state

In the case where one wishes to continue an analysis already carried out, the keyword RESULTAT indicates which
object is enriched.

### 9.1 Definition of an initial state

The keyword ETAT_INIT makes it possible to define a reference initial state. In the case where the user
has specified that the result concept is re-entrant (by the keyword RESULTAT), the keyword ETAT_INIT is
mandatory. By convention, the initial state of a virgin analysis (without restart) is stored at the order
number 0.

By default (if one specifies nothing) all the fields are identically zero. The initial state may
be defined either by specifying each field of the initial state, or by
extraction from a pre-existing concept of type evol_noli.

If one gives a data structure of type EVOL_NOLI=evol coming from another analysis by the keyword
EVOL_NOLI, one automatically extracts the fields of this data structure for the initial state.

The extraction of the initial mechanical state in the data structure evol_noli is done from the
archiving number NUME_ORDRE or from the archiving time instant INST.

If NUME_ORDRE or INST are not filled in, one takes the last existing archived number.
These extracted fields will be archived at the first time instant of the list of time instants defined
under the keyword INCREMENT.
In the case where one supplies INST, the keywords PRECISION and CRITERE (see
[U4.71.00](doc:u4.71.00) for the detailed syntax) serve to locate the right order number.
Indeed, the time instants are located by an order number (an integer). If the user wants
to use a time instant (a real) and not an order number for INST, the operand PRECISION
makes it possible to select this order number.

**A - Simple example (default behaviour)**

```python
listInst = DEFI_LIST_REEL(DEBUT=0.,
                          INTERVALLE=_F(JUSQU_A= 10.,NOMBRE=10)),
evolNoli = MECA_NON_LINE(INCREMENT=_F(LIST_INST=listInst,
                         INST_FIN=4.)),
evolNoli = MECA_NON_LINE(reuse=evolNoli,
                         INCREMENT=_F(LIST_INST=listInst),
                         ETAT_INIT=_F(EVOL_NOLI=evolNoli))
```

The first MECA_NON_LINE carries out the analysis for the time instants 1, 2, 3 and 4.

The second MECA_NON_LINE: carries out the analysis for the time instants from 5 to 10, the initial state
corresponding to time 4.

**B - Example to show the interest of two different lists of time instants**

```python
listInst1 = DEFI_LIST_REEL(DEBUT=0.,
                           INTERVALLE=_F(JUSQU_A= 10., NOMBRE=10)),

evolNoli = MECA_NON_LINE (INCREMENT=_F(LIST_INST=listInst1))

listInst2 = DEFI_LIST_REEL(DEBUT=20.,
                           INTERVALLE=_F(JUSQU_A= 30., NOMBRE=10))

evolNoli = MECA_NON_LINE(reuse=evolNoli,
                         RESULTAT=evolNoli,
                         INCREMENT=_F(LIST_INST=listInst2, INST_INIT=20.),
                         ETAT_INIT=_F(EVOL_NOLI=evolNoli,))
```

The first MECA_NON_LINE carries out the analysis for the time instants from 1 to 10. The initial
state, of order number 0, is virgin (all the fields are zero).

The second MECA_NON_LINE carries out the analysis of the time instants 21 to 30. The initial state
corresponds to time instant 10 of the first MECA_NON_LINE (last time instant computed in the
first MECA_NON_LINE). This initial state corresponds, for this second MECA_NON_LINE, to
time instant 20 (INST_INIT=20.).

The use of a non-zero initial state will change the computation of the thermal strain.
If there is a non-zero initial state, then the computation of the thermal strain is purely incremental.

If one uses an initial state whose model is different from the analysis model supplied in
the operator, one automatically proceeds to the passage between the two models:

- If the analysis model is included in the model given in the initial state, the data

of the initial state are simply copied mesh cell by mesh cell for all the fields

- If the model given in the initial state is included in the analysis model, one begins

by copying the values of the initial state for the common mesh cells, then one completes with the
zero value. One must be careful about the meaning that a zero initial internal variable
may have in the analysis

The keywords DEPL, SIGM and VARI make it possible (respectively) to give an initial field of displacement, of
stresses and of internal variables.
If one of these fields is not specified, it is taken as zero by default. They may for example
come from the command CREA_CHAMP [U4.72.04](doc:u4.72.04), or else have been read in a
file by the command LIRE_RESU [U7.02.01](doc:u7.02.01).

The stress field and the field of internal variables are fields at the Gauss points, and the displacement field
is a field at the nodes. If the fields are not defined on the right
supports, the conversions may be done automatically.
There is no condition imposed on the fields given by the user. They may very well
represent a non-equilibrated mechanical state and/or one not complying with the constitutive law.
If the analysis has difficulty converging in this case, the simplest thing is to create artificially
a zero initial stress state in order to force the selection of the incremental mode,
or to use a purely elastic matrix, which allows certain convergence at the price
of a large number of iterations.

In large strains, the user wishing to use the GDEF_LOG formalism with an
initial stress field (ETAT_INIT) will refer to the test case SSNP159b. Indeed, in order to
impose an initial stress field, the user must give as input the stress tensor
defined in the logarithmic space $T$ (and not the Cauchy one
$\sigma$ ). The components of the latter being stored as internal
variables, one must use the keyword VARI.

If the material characteristics depend strongly on the command variables, one should
be careful about the selection of the initial state, at the risk of not converging. Indeed,
the elastic constitutive behaviours exist in two versions (see
[U4.51.11](doc:u4.51.11)). The "pure" elastic version is chosen automatically
by the code when there is no initial state; otherwise, one selects the incremental version.
Now, only the latter is effective if one has strong variations of the material characteristics
(elastic in this case) with respect to the command variables.

If one uses simultaneously a state coming from a complete result (keyword EVOL_NOLI) and the
*individual* definition of a field (for example the stresses), the overloading rule applies
and the fields given individually replace those present in the data structure
given as the initial state.

### 9.2 Archiving of the results

The factor keyword ARCHIVAGE (a single occurrence) makes it possible to archive some or certain results
at all or certain time instants of the analysis.

In the absence of this keyword, all the time steps are archived, including the analysis
time instants newly created by automatic recutting of the time step. Archiving makes it possible to
reduce substantially the size of the databases by selecting the saved time instants.

The designation of the time instants to be stored is carried out either by a list of time instants
(keywords LIST_INST or INST) or else by an archiving frequency PAS_ARCH=npas (every npas
time steps).

- the last analysis step is always stored in order to be able to carry out a restart
- if one uses an access by list of time instants, then the analysis time instants newly

created by automatic recutting of the time step will not be archived

- the initial state is systematically archived under the order number 0 as soon as one is

not in restart of an analysis

**Notes**

The keyword CHAM_EXCLU makes it possible to specify the fields which will not be archived, except at
the last time step.

### 9.3 Customised archiving

The factor keyword OBSERVATION makes it possible to post-process certain fields at the nodes or at the elements
on parts of the model at time instants of a list (called an observation list) generally more
refined than the list of archived time instants defined in the keyword ARCHIVAGE
(where one stores all the fields over the whole model). It serves essentially for savings in
storage, but also to evaluate fields on reduced parts of the mesh, without needing
to post-process after the analysis. It is possible, for example, to compute the norm of the
stresses, in the von Mises sense, and to store it in the observation table.

This keyword is repeatable and allows the creation of an observation table of the same name as the
result concept of MECA_NON_LINE, which one will be able to extract using the command
[RECU_TABLE](doc:u4.71.02).

One may use only 99 occurrences of the keyword OBSERVATION at most.

It is possible to name an occurrence of the observation (column NOM_OBSERVATION) by
using the keyword TITRE. If it is not used, the column NOM_OBSERVATION contains
OBSERVATION_xx with xx varying from 1 to 99.

#### 9.3.1 Selection in the transient

To create the list of the observations to be made on the transient, LIST_INST, INST and PAS_OBSE have
the same meaning as the operands of the same name serving to
define an archiving list. PAS_OBSE playing the same role as PAS_ARCH in ARCHIVAGE.

The operand OBSE_ETAT_INIT specifies whether one must observe the fields at the initial time instant, because
the initial time instant is not manageable by the list of time instants.

The parameters PRECISION and CRITERE make it possible to manage the precision of the selection of the time instants
for the observation.

#### 9.3.2 Selection of the values

NOM_CHAM makes it possible to define the field to be post-processed as well as its components given by their name
(NOM_CMP) or, for the internal variables, the name of the latter (instead of V1, V2, …).
One may define only 20 components at most per occurrence of the factor keyword OBSERVATION.
One may post-process the fields output by default by the operator, or request the output of other
fields (for the moment, only EPSI_ELGA).

For other fields, one must make a request for an evolution.

The selection for NOM_VARI works only for fields of type VARI_ELGA.

#### 9.3.3 Selection in space

The keywords TOUT, GROUP_NO and GROUP_MA make it possible to define the geometric support of the
post-processing:

- for fields at the nodes ('DEPL', 'VITE', 'ACCE', 'DEPL_ABSOLU', 'VITE_ABSOLU', 'ACCE_ABSOLU',

'CONT_NOEU', 'FORC_NODA'), one extracts the list of the nodes.

- for fields at the Gauss points ('SIEF_ELGA', 'VARI_ELGA'), one extracts the list of the mesh cells.

Caution: do not use TOUT='OUI' on large meshes!

#### 9.3.4 Observation of an ELGA field

For an ELGA field, one begins by choosing the components, or the formula between the components, with
the keyword EVAL_CMP:

- If EVAL_CMP='VALE', one simply extracts the list of the components given by NOM_CMP or NOM_VARI.
- If EVAL_CMP='FORMULE', one evaluates the formula given by the simple keyword FORMULE.

If one applies a formula on the components, one will therefore have one value and therefore one observation;
otherwise, one will have as many observations as there are components in the list NOM_CMP or NOM_VARI.

Once the components or the formula on the components have been evaluated, by the keyword EVAL_ELGA, one
may:

- Extract these values on the integration points and sub-points with EVAL_ELGA='VALE'.

In this case, one must explicitly specify the integration point and sub-point by POINT
and SOUS_POINT. The integration sub-points appear for the structural elements
(beams, plates, shells, pipes, etc.).

- Request extraction of the maximum EVAL_ELGA='MAX' or the minimum EVAL_ELGA='MIN' over all the

points and sub-points of a mesh cell.

If one explicitly requests a point and a sub-point, one will have as many realisations as there are
points requested, multiplied by the number of components requested. On the other hand, if one requests
the maximum or the minimum, there will be a single observation per component requested.

Once the components (or the formula on the components) have been evaluated, as well as the extraction
point/sub-point, one may, by the keyword EVAL_CHAM:

- Extract these values on all the mesh cells with EVAL_CHAM='VALE'.
- Request extraction of the maximum EVAL_CHAM='MAX', the minimum EVAL_CHAM='MIN' or the mean

EVAL_CHAM='MOY'.

- Request extraction of the minimum value in absolute value EVAL_CHAM='MINI_ABS' such that

MINI_ABS(-1, 3, 4, -12, -0.1) = 0.1.

- Request extraction of the maximum value in absolute value EVAL_CHAM='MAXI_ABS' such that

MAXI_ABS(-1, 3, 4, -12, -0.1) = 12.

Here is an example to extract the maximum of the trace of the stress tensor on
GROUP_MA='TOTO':

```python
trace  = FORMULE(VALE='0.333*(SIXX+SIYY+SIZZ)', NOM_PARA=('SIXX','SIYY','SIZZ',));

OBSERVATION =_F( NOM_CHAM = 'SIEF_ELGA',
                 GROUP_MA = 'TOTO',
                 EVAL_CHAM = 'MAX',
                 NOM_CMP = ('SIXX','SIYY','SIZZ',),
                 EVAL_CMP = 'FORMULE',
                 FORMULE = trace,
                 EVAL_ELGA = 'MAX')
```

### 10.1 General principles

The factor keyword EXCIT makes it possible to describe at each occurrence a load (applied loads and
boundary conditions), and possibly a multiplying coefficient and/or a type of load.

The non-linear analysis is solved by an incremental method, so it is necessary to
**parameterise** the analysis.
One therefore also applies the loadings in an incremental manner, for example by applying
the force progressively (a ramp).
The basic principle is to separate the *spatial* part of the loading and the
*(pseudo)-temporal* part.

$$
\underline{L}_{ext} \left ( {\underline{u}, t} \right )
=
g \left ( t \right )
\underline{L}_{ext} \left ( \underline{u} \right )
$$

The spatial part of the loading
$\underline{L}_{ext} \left ( \underline{u} \right )$ is given by the keyword
CHARGE (possibly comprising the evolution of a temperature field).

- In a thermo-mechanical analysis, if the initial temperature is different from the reference

temperature (given in [U4.43.01](doc:u4.43.01)), the associated strain field at
the initial time instant may be incompatible and therefore lead to an associated non-zero state of stresses and of
internal variables. If one uses an incremental constitutive relation
and if one does not explicitly define an initial state of stresses and of internal variables
(associated with an initial temperature field different from the reference temperature),
the stress field and the field of internal variables computed at the first increment will take into account
only the variation of temperature between the initial time instant and the first time instant, and not
the possible compatibility stresses associated with the initial temperature. In order to take
this initial state into account, one must give it explicitly, for example thanks
to the keywords in ETAT_INIT. In order to avoid such situations, which may lead to
analysis errors, it is better to start an analysis by considering that one must start from a
virgin state.

- If one carries out an analysis in axisymmetry and one imposes nodal forces, these forces

must be divided by $2\pi$ (one works on a sector of one radian) with respect
to the real loadings. Likewise, if one wishes to compute the resultant of the forces, the
result is to be multiplied by $2\pi$ in order to have the total resultant on the complete
structure. Likewise in plane stresses or in plane strain, one works on a
unit thickness: the forces (over the thickness) applied must be divided by the thickness;
the real forces are obtained by multiplying by the thickness the forces of the analysis.

**Notes**

The temporal part of the loading $g \left ( t \right )$
is given by the keyword FONC_MULT.
If one does not specify the multiplying function, one applies a step function.

It is possible to define directly
$\underline{L}_{ext} \left ( {\underline{u}, t} \right )$ in the keyword CHARGE
if one uses the command AFFE_CHAR_MECA_F (function of time). In this case, one must be careful:
indeed, if one uses FONC_MULT at the same time, one multiplies the loading again by
a function of time.

By default, TYPE_CHARGE equals 'FIXE_CSTE': this corresponds to a loading applied on the
initial geometry and not piloted. It may however be a function, and, in particular,
depend on time.
A fixed loading is re-evaluated only at each new time instant, and only if it depends on
time (defined in [AFFE_CHAR_MECA_F](doc:u4.44.01) and parameterised by the time instant, or else assigned
by FONC_MULT).

### 10.2 Incremental loadings

If TYPE_CHARGE='DIDI' then the Dirichlet conditions (imposed displacements,
linear conditions) will apply to the displacement increment from the time instant given
under ETAT_INIT/NUME_DIDI (by default the time instant of restart of the analysis) and not to the total
displacement.

For example, for an imposed displacement (keyword DDL_IMPO of [AFFE_CHAR_MECA](doc:u4.44.01)) the
condition will be of the form $u-{u}_{0}=d$ where ${u}_{0}$ is the displacement defined
by NUME_DIDI and not $u=d$ .

The differential Dirichlet option is available both for mechanical loadings (CHAR_MECA)
and for kinematic loadings (CHAR_CINE).

## 11 Contact

The factor keyword CONTACT makes it possible to introduce the contact/friction conditions.

### 11.1 Passing of the parameters linked to the definition of the contact

The user defines the contact (surfaces in contact, formulation used, etc.) by means of the operator DEFI_CONT. Then, this concept is supplied to the command MECA_NON_LINE by means of the keyword DEFINITION.

### 11.2 Choice and control of the global solution algorithm

Within the framework of the simulation of frictional contact, it is necessary to treat the geometric non-linearity.
The choice of the algorithm used is made using the keyword ALGO_RESO_GEOM. Two choices are possible:

- a solution by a global Newton algorithm (ALGO_RESO_GEOM='NEWTON'): in this case, at each Newton iteration, one carries out the pairing on the current configuration,
- a solution by a so-called fixed-point algorithm (ALGO_RESO_GEOM='POINT_FIXE'): in this case, one carries out a certain number of solutions for a given pairing, before pairing again. The management of the criterion used to manage the pairing is done in this case using REAC_GEOM.

Indeed, the fixed-point algorithm requires one to specify the condition which will trigger a new pairing. This condition is managed by the keyword REAC_GEOM.
Various options exist for the user:

- REAC_GEOM=’AUTOMATIQUE’: the updating of the geometry (pairing) is controlled by a geometric convergence criterion (RESI_GEOM). This criterion controls the variation of the geometry between two iterates. When the criterion is reached, one updates the geometry. This is the recommended option. In this case, the user has a convergence criterion on this parameter, using a tolerance to be supplied (RESI_GEOM) and a maximum number of iterations (ITER_GEOM_MAXI).
- REAC_GEOM='CONTROLE': the updating of the geometry is done after a certain fixed number of iterations. This number is supplied by the user using the parameter NB_ITER_GEOM. For example, if NB_ITER_GEOM=2, then one updates the geometry every two Newton iterations.
- REAC_GEOM='SANS': in this case, one never updates the geometry, and one always works on the initial configuration. This option is valid only under the assumption of small perturbations or when the normal to the contact surfaces does not change during the analysis.

## 12 Management of the verbosity

The keyword INFO makes it possible to produce various intermediate printouts in the message file.

Other printouts are made systematically during the non-linear analysis, independently
of the value assigned to the keyword INFO: they are the printouts of the residuals and of the relative
displacement increments during the Newton iterations.

Caution: the output files may become very large with INFO greater than 2.
