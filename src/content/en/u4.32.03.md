# u4.32.03 Operator RECU_FONCTION

## 1 Purpose

Extract, in the form of a function, the evolution of one quantity as a function of another.

If the extraction is carried out from a data structure resultat, or from a field of a quantity (grandeur) cham_gd, or from a resu_gene, the function produced corresponds to the time evolution of a component at a node or at a Gauss point of the mesh.

From a data structure tran_gene, one can also extract the evolution of two parameters at a shock node.

From a table, one can extract the evolution of 2 parameters in the columns of the table, or a function contained in a cell of the table.

From a nappe, one can extract the function corresponding to a given value of the parameter.

From a data structure melasflu one can extract the evolution of modal parameters as a function of the flow velocity of the fluid, or the evolution of the critical velocity as a function of the Connors number.

From a data structure interspectre one can extract the frequency evolution of the interspectrum associated with the $i$-th row and the $j$-th column of the interspectral matrix, or the time evolution of the interspectrum at the $n$-th component of the diagonal.

Produces a data structure of type fonction or fonction_c.

On exit from the command, the function is reordered by increasing abscissae. On the other hand, it is forbidden to have several identical abscissae (it would no longer be a function).

#### 3.3.1 Time evolution of a physical or generalised component, type tran_gene


- in terms of the physical variables: one has specified GROUP_NO = grno.
- in terms of the generalised variables: one has specified NUME_CMP_GENE = n_val .

NOM_CHAM gives the name of the field which one wants to recover ('DEPL', 'VITE', 'ACCE', or 'PTEM'). The option 'PTEM' makes it possible to extract, for each time instant (or order number) of recovery, the values of the analysis time step.

**Note:**

*Carrying out this recovery on the physical basis is the role of the command* *REST_GENE_PHYS. In later versions, this functionality will be removed from* *RECU_FONCTION; one will have to carry out the recovery and then extract the function.*

##### 3.3.1.1 Operands MULT_APPUI and ACCE_MONO_APPUI

```text
◊    MULT_APPUI
```

If this keyword is 'OUI', one recovers the evolution of the variables in the physical space by treating the problem in absolute motion in the case of a multi-support excitation. Otherwise, the recovery in the physical space is carried out by assuming that the problem is treated in relative motion. This keyword cannot be used if the keyword CORR_STAT is used.

```text
◊    ACCE_MONO_APPUI
```

In the case of a single-support acceleration, one must indicate here the acceleration imposed on all the supports in the direction considered, in order to calculate the absolute acceleration of the point.

If the keyword is not filled in, one obtains the relative acceleration as the result of the command.

**Note:**

*The name of the concept must be the same as that entered under* *FONC_MULT of* *DYNA_VIBRA.*

##### 3.3.1.2 Operands CORR_STAT

```text
◊    CORR_STAT
```

If this keyword is 'OUI', the evolution of the variables in the physical space is obtained by taking into account the correction due to the consideration of static modes (cf. [R4.05.03]). This keyword cannot be used if the keyword MULT_APPUI is used.

##### 3.3.1.3 Information concerning the shock nodes

```text
◊    NOM_PARA = para
```

It designates the name of the parameter (variable or abscissa) of the function. The values currently allowed for lpara are:

```text
/    'TEMP'            /    'INST'            /    'EPSI'
/    'X'                /    'Y'                /    'Z'
/    'FREQ'            /    'PULS'            /    'AMOR'
/    'DX'            /    'DY'            /    'DZ'
/    'DRX'            /    'DRY'            /    'DRZ'
```

plus those specific to the shock nodes (cf. [§3.3.2.2]).

##### 3.10.2.2 Operand NOM_RESU

```text
◊    NOM_RESU = resu
```

It designates the name of the result; the function thus created is a function whose value has the name lresu (8 characters).

##### 3.10.2.3 Operand INTERPOL

```text
◊    INTERPOL
```

Type of interpolation of the function between the values of the parameter of the domain of definition. After this keyword one expects a list of parameters (two at most) among 'LIN', 'LOG'. If a single value is given, the interpolation will be the same for the abscissae and the ordinates. If two values are given, the first corresponds to the interpolation of the abscissae and the second to the interpolation of the ordinates.

##### 3.10.2.4 Operands PROL_DROITE /PROL_GAUCHE

```text
◊    PROL_DROITE et PROL_GAUCHE
```

They define the type of prolongation to the right (to the left) of the domain of definition of the variable:

- 'CONSTANT' for a prolongation with the last (or first) value of the function,
- 'LINEAIRE' for a prolongation along the first defined segment (PROL_GAUCHE) or the last defined segment (PROL_DROITE),
- 'EXCLU' if the extrapolation of the values outside the domain of definition of the parameter is forbidden.

### 3.11 Operand TITRE

```text
◊    TITRE
```

Title attached to the concept produced by this operator [U4.03.01](doc:u4.03.01).

### 3.12 Operand INFO

```text
◊    INFO
```

Specifies the printout options in the MESSAGE file.

| 1 | no printout (by default) |
| --- | --- |
| 2 | printout of the descriptor of the function and of the list of the first 10 values of the function in increasing order of the first 10 parameters |
