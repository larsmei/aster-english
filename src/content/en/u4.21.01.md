# u4.21.01 Operator LIRE_MAILLAGE

## 1 Purpose

Create a mesh by reading from a file.

The supported file formats are: ASTER, MED, GIBI, GMSH and IDEAS.

Produces a data structure of type maillage.

**Important note:**

*One can check the quality of the mesh read by using (following* *LIRE_MAILLAGE, the command* *MACR_INFO_MAIL* [U7.03.02](doc:u7.03.02).

## 2 Syntax

```text
maillage = LIRE_MAILLAGE(
    ◇ FORMAT = / "ASTER",
               / "GIBI",
               / "GMSH",
               / "IDEAS",
               / "MED" (par défaut),
    ⟐ VERI_MAIL = _F(
         ◇ VERIF = / "OUI" (par défaut),
                   / "NON",
         ◇ APLAT = float (défaut: 0.001),
      ),
    # Si: ( not equal_to("FORMAT", 'MED') )
        ◇ UNITE = unit (défaut: 20),
    # Si: ( equal_to("FORMAT", 'MED') )
        ◇ UNITE = unit (défaut: 20),
        ◇ NOM_MED = text,
        ◇ INFO_MED = / 0 (par défaut),
                     / 1,
        ◇ PARTITIONNEUR = / "SANS" (par défaut),
                          / "PTSCOTCH",
    # Si: ( equal_to("FORMAT", 'IDEAS') )
        ◇ CREA_GROUP_COUL = / "OUI",
                            / "NON" (par défaut),
    ◇ INFO = / 0,
             / 1 (par défaut),
             / 2,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Operand UNITE

```text
◊    UNITE =    i
```

Logical-unit number of the mesh file. Unit 20 by default.

### 3.2 Operand FORMAT

```text
◊    FORMAT        =    /    'MED'        [DEFAUT]
                        /     'ASTER'
                        /     'GMSH'
```

This keyword is used to specify the format of the file to be read. Today three formats are supported: 'MED', 'ASTER' and 'GMSH'.

The format 'ASTER' is described in [U3.01.00](doc:u3.01.00).

The format 'MED', which means "Modelling and Exchange of Data", is a neutral data format developed by EDF R&D and the CEA for the exchange of data between analysis codes. The data that one can exchange according to this format are the meshes and the result fields: fields at the nodes, fields by element. MED files are binary and portable files (relying on the HDF library, Hierarchical Data Format). Reading a MED file with LIRE_MAILLAGE makes it possible to recover a mesh produced by any other code capable of creating a MED file. It is the format recommended in **code_aster** and the default one.

Whatever the format, the data read are:

| the list of nodes | number, name, coordinates, |
| --- | --- |
| the list of mesh cells | number, name, type, name of the nodes, |
| the list of node groups | number, name, number of nodes, names of the nodes, |
| the list of mesh-cell groups | number, name, number of mesh cells, names of the mesh cells. |

**Note:**

*In a MED file, there is a partition of the nodes and of the mesh cells according to the groups. A partition corresponds to a MED family. In a MED file, the groups are distributed within the families: one therefore finds families of nodes and families of mesh cells. When a MED file is read, the lists of the node groups and of the mesh-cell groups are built on the fly by decomposition of the families.*

Concerning GMSH, files in ASCII formats 1.0 and 2.0 are read.

In GMSH, the groups are always numbered. They are also sometimes named in version 2.0.

For GMSH format version 1, the node and mesh-cell groups are read in the following way:

- all the element groups numbered 1, 2, ... of GMSH are transformed into mesh-cell groups (GROUP_MA) bearing the name GM1, GM2,
- the groups are mutually exclusive: a mesh cell cannot belong to several groups.

For GMSH format version 2, the node and mesh-cell groups are read in the following way:

- only the groups named in *GMSH* (section *PhysicalNames* of the *msh* format) are imported;
- the groups may overlap: a mesh cell may belong to several groups;
- the GMSH type of the mesh cell must be consistent with the GMSH dimension of the group in order to be able to belong to this group (for example a 2-node segment for a 1D group)

### 3.3 Operand VERI_MAIL

The keyword VERI_MAIL triggers 4 checks on the mesh:

- absence of orphan nodes,
- absence of "duplicate" mesh cells,
- absence of quadratic mesh cells having the same vertex nodes but not the same mid-side nodes,
- absence of mesh cells that are too flat.

If these checks are not satisfied, the code issues an alarm.

By default (that is to say in the absence of the keyword VERI_MAIL), the checks are carried out. If the user wishes to avoid these checks, the following will be written:

```text
VERI_MAIL = _F (VERIF = 'NON',)
```

A node is declared orphan if it does not form part of the connectivity of any mesh cell.

A mesh cell is declared "duplicate" if 2 mesh cells (or more) have connectivities formed by the same list of nodes.

The keyword APLAT= ap makes it possible to issue alarms when the mesh contains mesh cells that are too flat.

The flatness of a mesh cell is defined as the ratio Amin/Amax where Amin and Amax are the lengths of the shortest and the longest edges of the mesh cell. The name of the mesh cells whose flatness is lower than ap will be printed on the 'MESSAGE' file.

Other quality criteria for the mesh are available via the command MACR_INFO_MAIL [U7.03.02](doc:u7.03.02).

In the case of the issue of an error or alarm message, it is possible to try to create a repaired mesh with the following function

```python
fix_mesh = mesh.fix()
```

### 3.4 Operands for the format 'MED'

```text
◊    NOM_MED = mamed
```

A MED file may contain several meshes. Each mesh is identified by its name. To read one mesh in particular, its name must be supplied as the argument of this keyword NOM_MED. In the absence of the keyword, the first mesh found in the file will be read. When the file contains only one mesh, there is therefore nothing to specify.

**Notes:**

      - *In a mesh, a mesh-cell group may be composed of elements of different dimensions (edges, faces or volumes).*
      - *This kind of group is displayed in Salome (Mesh module) as several groups* *bearing the same name under different categories, but in fact it is a single group* *in code_aster.*

```text
◊    INFO_MED=         /    1,            [DEFAUT]
                       /    2,
                       /    3
```

Prints information specific to the progress of the re-reading of the MED mesh file (number of nodes and of mesh cells re-read, information on the MED families, …):

- INFO_MED    =    1 : no printout,
- INFO_MED    =    2 : only printouts relating to the family / group correspondence,
- INFO_MED    =    3: all the information is printed.

```text
◊    PARTITIONNEUR=    / ‘SANS’,    :             [DEFAUT]
                       / ‘PTSCOTCH’
```

By default (SANS), the mesh is not partitioned (sequential and former parallelism).

With PTSCOTCH, this makes it possible to partition a mesh contained in a file in order to distribute it among the various sub-domains during a parallel analysis. The mesh is cut into as many sub-domains as there are MPI processes. In sequential mode, the keyword is ignored. Warning: for the moment, certain POI1 mesh cells are not copied.

### 3.5 Operands for the format 'IDEAS'

```text
◊    CREA_GROUP_COUL
```

The user may request the creation of mesh-cell groups and of node groups gathering all the mesh cells and nodes of the same colour by indicating CREA_GROUP_COUL = 'OUI'. These groups are named COUL_n where n is the colour number in IDEAS.

By default this is not done, so as not to increase unnecessarily the number of mesh-cell groups and of node groups.

**Notes:**

- *Only Cartesian coordinate systems are treated.*
- *Only a single Cartesian coordinate system is handled.*
- *During the conversion of the IDEAS universal file, a check is made as to whether the user has defined several coordinate systems. If this is the case, an alarm message warns the user, asking that it be checked that all the coordinate systems are identical.*

### 3.6 Operand INFO

```text
◊    INFO =    /    1    ,                [DEFAUT]
               /    2
```

Print level.

If: INFO= 1

- title of the mesh,
- number of nodes,
- number of mesh cells of each type,
- number of node groups and, for each of them, its name and the number of nodes of the group
- number of mesh-cell groups and, for each of them, its name and the number of mesh cells of the group.

If: INFO= 2 one prints, in addition to the information of INFO= 1:

| list of the nodes | number, name, coordinates, |
| --- | --- |
| list of the mesh cells | number, name, type, name of the nodes, |
| list of the node groups | number, name, number of nodes, names of the nodes, |
| list of the mesh-cell groups | number, name, number of mesh cells, names of the mesh cells. |
