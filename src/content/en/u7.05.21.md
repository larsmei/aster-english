# u7.05.21 Procedure IMPR_RESU in 'MED' format

## 1 Purpose

Write the result of an analysis to a file in MED format. One describes all the keywords of the command IMPR_RESU [U4.91.01](doc:u4.91.01) as regards this output format only.

One can write, as one chooses, to a file in MED format:

- a mesh,
- fields at the nodes,
- fields at the elements.

When writing the fields by element at the Gauss points, one also writes the localisation of the reference elements (coordinates and weights of the Gauss points).

MED (Modelling and Exchange of Data) is a neutral data format developed by EDF R&D and the CEA for the exchange of data between analysis codes. The data that one can exchange according to this format are the meshes and the result fields at the nodes and by element. The MED files are binary and portable files (relying on the HDF5 library, Hierarchical Data Format). Writing results to a MED file allows any other analysis code interfaced with MED to read the results produced by *Code_Aster*  via the command IMPR_RESU.

## 3 Operands FORMAT, UNITE, PROC0, VERSION_MED and INFO

### 3.1 Operand FORMAT

The operand FORMAT makes it possible to specify the format of the file in which to write the result.

The format ’MED’ indicates to the procedure IMPR_RESU that the result must be written to a file in MED format. It is the default write format.

When a new file is created in MED format, the printout is made in MED format 3.3.1. If the file already exists, the MED format level is retained.

### 3.2 Operand UNITE

Defines the unit in which one writes the med file. By default, UNITE = 80 and corresponds to the default unit of type rmed in astk.

### 3.3 Operand PROC0

The operand PROC0, whose default value is 'OUI', makes it possible to restrict the printout to the processor of rank 0. If one assigns it the value 'NON', the printouts will be carried out on all the processors.

### 3.4 Operand INFO

The keyword INFO, when it is equal to 2, makes it possible to obtain information on the printouts carried out by the command.

### 3.5 Operand VERSION_MED

```text
◊    VERSION_MED    =    /’3.3.1’,                                [DEFAUT]
/’4.0.0’,
/’4.1.0’,
```

When a new file is created in med format, the printout is made in med format 3.3.1. If the file already exists, the med format level is retained.

One can change the MED file version with the keyword VERSION_MED.

## 4 Factor keyword RESU

This factor keyword makes it possible to specify the results and the fields to be printed.

### 4.1 Operand MAILLAGE

If the result is a mesh (operand maillage [U4.91.01](doc:u4.91.01)), the data reported in the result file in MED format are:

| the list of nodes | number, name, coordinates, |
| --- | --- |
| the list of mesh cells | number, name, type, name of the nodes, |
| the list of node groups | number, name, number of nodes, names of the nodes, |
| the list of mesh-cell groups | number, name, number of mesh cells, names of the mesh cells. |

**Note:**

*In a MED file, there is a partition of the nodes and of the mesh cells according to the groups. A partition corresponds to a MED family. In a MED file, the groups are distributed within the families: one therefore finds families of nodes and families of elements.*

### 4.2 Operand RESULTAT

The operand RESULTAT makes it possible to print, in a MED file, fields contained in a resultat concept.

One writes the following information to the ’MESSAGE’ file:

- operand ’RESULTAT’,
- operand ’NOM_CHAM’,
- operand ’NUME_ORDRE’,
- name of the field stored in the MED file: concatenation of the three preceding operands.

If INFO_MAILLAGE = = ‘OUI’, more detailed information is printed in the ‘MESSAGE’ file when the MED mesh is written. One may for example obtain the types of mesh cells printed, the names of the MED families that are created, etc.

### 4.3 Operand CARA_ELEM

The operand CARA_ELEM is used for the printout of the fields with sub-points. When CARA_ELEM is supplied, the fields with sub-points are printed by adding information to the MED file that makes it possible to position the sub-points, taking into account the information contained in the sd_cara_elem (thickness of a shell, twist angle of a multi-fibre beam, …).

### 4.4 Operand CHAM_GD

The operand CHAM_GD makes it possible to print in the file a data structure of type cham_gd. Concretely, one can therefore print with this keyword a carte, a field by element or a field at the nodes.

### 4.5 Operand NOM_CHAM_MED

The operand NOM_CHAM_MED makes it possible to define the name of the MED field. It is a string of 64 characters. This can be used in particular when one wishes to print certain components of the field as several fields in the same MED file (for example for the visualisation of SIRO_ELEM).

### 4.6 Operand NOM_RESU_MED

The operand NOM_RESU_MED is an alternative to NOM_CHAM_MED concerning the terminology of the MED fields. Its use will make it possible to no longer name the MED fields explicitly, which means that all the fields contained in the result will be printed. Each MED field name will be constructed from:

- the character string supplied to NOM_RESU_MED (a string of at most 8 characters) ,
- the symbolic name of the Aster field.

For example:

```text
IMPR_RESU = (
FORMAT    = ’MED’,
RESU    = _F(    RESULTAT        = U,
NOM_RESU_MED    = ’U_HAUT’,

GROUP_MA = ’HAUT’,
NUME_ORDRE    = 1, )
)
```

If the result U contains the fields DEPL and SIEF_ELGA, then the command above will produce the MED fields:

- ’U_HAUT__DEPL’ ,
- ’U_HAUT__SIEF_ELGA’ ,

This can be used in particular when one wishes to print, in the same MED file, the same field on different mesh-cell groups.

### 4.7 Operand IMPR_NOM_VARI

This keyword is useful in the case of the internal variables. When it is used and the printout of a field VARI_*  has been requested, it is in fact a field VARI_*_NOMME that will be printed. This field will have components whose name will be based on the catalogue of the constitutive laws used in the analysis. If two constitutive laws have common internal variables, these will be merged into a single component.

### 4.8 Operand PARTIE

It is not possible to write complex fields. That is why one must choose between the real part (PARTIE=’REEL’) , the complex part (PARTIE=’IMAG’), the modulus (PARTIE='MODULE') or the phase (PARTIE='PHASE').

### 4.9 Operand TYPE_NOM

In the case where the type of result is a MULT_ELAS (result of [MACRO_ELAS_MULT](doc:u4.51.02)).
One must specify how the results will be written to the MED file.
The default value taken by TYPE_NOM is "NUME_ORDRE". Thus, each load case is saved on a time instant of the result.
The other value that TYPE_NOM can take is "NOM_CAS"; in this case, each case will be stored in a different result whose result name in the MED file will be:

```text
"NOM_CAS_NOM_CHAM"
```

For example, if the result contains two load cases `FX` and `FY`, each containing the fields DEPL and SIEF_ELGA,
the following MED fields will be produced:

- 'FX______DEPL'
- 'FX______SIEF_ELGA'
- 'FY______DEPL'
- 'FY______SIEF_ELGA'

### 4.10 Operands TOUT_ORDRE / NUME_ORDRE / LIST_ORDRE / NUME_MODE / INST / LIST_INST / FREQ / LIST_FREQ / NOEUD_CMP / NOM_CAS / ANGLE / PRECISION / CRITERE

Cf. document [U4.91.01](doc:u4.91.01).

## 5 Selection on the components

Another way of reducing the volume of the printouts is to print only the values of certain components (for example only the displacement along the axis X: component DX).

Note: the selection of the components does not work for the fields with sub-points.

### 5.1 Operand TOUT_CMP

This keyword makes it possible to indicate that one wishes to print all the components of the field.

### 5.2 Operand NOM_CMP

This keyword makes it possible to choose the list of the components of the cham_gd or of all the fields of the result concept that one wishes to print.

The keywords TOUT_CMP and NOM_CMP cannot be used simultaneously.

These components are described in the specific documentation of the elements.

## 6 Selection of the topological entities

In order to reduce the volume of the printouts, it is sometimes necessary to print only part of the result. To do this one can print a field at the nodes only at certain nodes, or a field by element only on certain elements.

Note: the selection of the topological entities does not work for the fields with sub-points.

### 6.1 Operand TOUT

This keyword indicates that one wishes to print the field over the whole structure (all the nodes for a field at the nodes, all the elements for a field by element).

### 6.2 Operand GROUP_NO

This keyword makes it possible to indicate the list of the node groups on which one wishes to print a cham_no. If this keyword is used in the case of the printout of a cham_elem, it is ignored, and the cham_elem is printed on all the mesh cells, specified elsewhere.

### 6.3 Operand GROUP_MA

This keyword makes it possible to indicate the list of the mesh-cell groups on which one wishes to print a cham_elem. For a cham_no, it makes it possible to indicate the list of the nodes, vertices of the mesh cells, at which one wishes to print the cham_no.

IMPR_RESU = (
