# u4.43.03 Operator AFFE_MATERIAU

## 1 Purpose

Assign materials to geometric zones of a mesh or of a model. There may be up to 26 materials on one and the same mesh cell (which is necessary for the multifibre beams or the polycrystalline materials), but one will be able to use only a single field of type cham_mater in the operators.

Define the command variables (temperature, space, hydration, drying, corrosion, …) for the numerical analyses.

Produces a data structure of type cham_mater.

## 2 Syntax

```text
cham_mater = AFFE_MATERIAU(
    ◆ | MAILLAGE = maillage,
      | MODELE = modele,
    ◆ / AFFE = _F(
           ◆ / TOUT = "OUI" (ou non renseigné),
             / GROUP_MA = list[grma],
           ◆ MATER = list[mater],

      / CHAM_MATER = cham_mater,
    ◇ AFFE_COMPOR = _F(
         ◆ / TOUT = "OUI" (ou non renseigné),
           / GROUP_MA = list[grma],
         ◆ COMPOR = compor,
      ),
    ◇ AFFE_VARC = _F(
         ◇ / TOUT = "OUI" (ou non renseigné),
           / GROUP_MA = list[grma],
         ◆ NOM_VARC = / "CORR",
                      / "EPSA",
                      / "GEOM",
                      / "HYDR",
                      / "IRRA",
                      / "M_ACIER",
                      / "M_ZIRC",
                      / "NEUT1",
                      / "NEUT2",
                      / "NEUT3",
                      / "PTOT",
                      / "SECH",

                          / "EPSA_NOEU",
                          / "GEOM",
                          / "HHO_TEMP",
                          / "HYDR_ELNO",
                          / "HYDR_NOEU",
```

## 3 General points

This command serves to assign the material characteristics on the finite elements of the model (even though it is the mesh cells of the mesh which are actually assigned). These material characteristics are defined in the materials which one assigns to the mesh cells (keyword MATER). Each material contains a certain number of parameters (Young's modulus, density, ...). These parameters may be functions of certain variables. We shall call these variables "command variables".

Currently, the command variables used are:

- the temperature,
- space,
- hydration,
- drying,
- the metallurgical phases,
- irradiation,
- corrosion,
- …

All these command variables must be assigned with the command AFFE_MATERIAU (keyword AFFE_VARC).

In the case of models with multifibre beams, one must also assign in this command the "constitutive behaviours" defined with the command DEFI_COMPOR/MULTI_FIBRE [U4.43.06](doc:u4.43.06).

## 4 Operands

### 4.1 MAILLAGE

```text
♦    MAILLAGE= ma,
```

Name of the mesh (or of the skeleton) which one wants to assign with material characteristics.

**Notes:**

- *The assignment operation is the same for the mesh cells of a skeleton as for the mesh cells of a mesh. In the remainder of the document, one will always say mesh for simplicity.*
- *When one assigns materials to the mesh cells of a skeleton, it is because one wants to compute stresses (for example) on the post-processing mesh cells (coarser).*

### 4.2 MODELE

```text
♦    MODELE= mo,
```

Name of the model.

If this argument is used, one checks that the mesh cells assigned in the command do indeed belong to the model.

### 4.3 Factor keyword AFFE

The factor keyword AFFE makes it possible to assign different materials to "pieces" of the mesh.

#### 4.3.1 Note concerning fracture-mechanics analyses

In general, the material characteristics must be known on the finite elements modelling the "matter": the "volume" elements (or structural elements). The "skin" finite elements are there in order to apply boundary conditions and do not have to know the material properties of the underlying matter. An exception exists for the computation of the option CALC_K_G of the operators CALC_G_XXXX. For these analyses, the finite elements modelling the lips of the crack must be assigned the same material as the underlying "volume" elements.

#### 4.3.2 Operands TOUT='OUI', GROUP_MA

The keywords TOUT and GROUP_MA make it possible to designate the set of mesh cells which will be assigned.

If a mesh cell appears in several occurrences of the factor keyword AFFE, the overloading rule is applied: it is the last assignment which takes precedence [U2.01.08](doc:u2.01.08).

#### 4.3.3 Operand MATER

```text
♦    MATER= mat,
```

Name of the material which one wants to assign.

In the general case, each mesh cell is assigned only one material. Sometimes, one must indicate a list of materials when the non-linear mechanical constitutive behaviour is obtained by the command DEFI_COMPOR [U4.43.06](doc:u4.43.06). In this latter case, the number of materials in the list is limited to 26.

**Caution:** if one can have several materials per mesh cell, one will be able to use only a single field of type cham_mater in the operators.

### 4.4 Factor keyword CHAM_MATER

The keyword CHAM_MATER is an alternative to AFFE and makes it possible to use the material characteristics defined in a previous AFFE_MATERIAU concept. Thus, it is possible to distinguish, in the command file, the assignment of the materials (AFFE) and the assignment of the command variables (AFFE_VARC). Here is an example:

> cm1 = AFFE_MATERIAU(MODELE=mo, AFFE = _F(GROUP_MA='gma', MATER=materiau))
> cm2 = AFFE_MATERIAU(MODELE=mo, CHAM_MATER=cm1, AFFE_VARC=...)

The keywords AFFE and CHAM_MATER are mutually exclusive, and each of them allows the definition of the assignments of the material.

### 4.5 Keyword AFFE_VARC

This factor keyword makes it possible to assign fields of **command variables**  to the mesh cells of the mesh.

This keyword may be repeated. One must use several occurrences of AFFE_VARC in order to be able to assign several different command variables. But one can also use several occurrences for a single variable. For example, on a mixed model (3D + beams), one can assign as temperature:

1 evol_ther computed on the 3D elements

1 temperature field (constant in time) on the beam elements.

A command variable is a scalar (real) which can influence the material constitutive behaviour via the parameters which are functions (for example a parameter of DEFI_MATERIAU / ELAS_FO). A command variable is a field known **before**  the analysis. This field may vary in time. In rare cases, the command variables may be used as variables of a function defining a loading (e.g. AFFE_CHAR_THER_F/SOURCE).

The command variables were introduced first and foremost for the mechanical analyses. The most usual command variable for the mechanical analyses is the temperature.

For the drying analyses (operator SECH_NON_LINE), the temperature command variable must obligatorily be present.

For the thermal analyses, it is possible to use one (or several) command variable(s), but this concerns only a few very rare parameters:

> SECH_NAPPE / FONCTION
> THER_FO / LAMBDA
> THER_FO / RHO_CP
> THER_COQUE_FO / COND_LMM, COND_TMM, ...

Still for the thermal analyses, command variables may be used among the variables of the functions given to the following command:

> AFFE_CHAR_THER_F/SOURCE

#### 4.5.1 Operand NOM_VARC

```text
♦    NOM_VARC= nomvarc,
```

Name of the command variable which one wants to assign (TEMP, GEOM, IRRA, CORR, HYDR, SECH, ...).

Meaning and role of the various variables:

| TEMP | temperature |
| --- | --- |
| GEOM | directions of space |
| CORR | corrosion of steels |
| EPSA | anelastic strain |
| HYDR | hydration of concrete |
| IRRA | Irradiation |
| M_ACIER | metallurgical phases of the steel |
| M_ZIRC | metallurgical phases of the zircaloy |
| NEUT1 | "neutral" variable 1: makes it possible to vary the material coefficients of the materials as a function of a 'user' parameter (see example 3 below) |
| NEUT2 | "neutral" variable 2 (like NEUT1) |
| NEUT3 | "neutral" variable 3 (like NEUT1) |
| SECH | drying of concrete |
| PTOT | Total fluid pressure |

Certain command variables are scalars. Others are "vectors" comprising several scalar components.

The names of the components of the command variables are given in the table below

| TEMP | TEMP, TEMP_MIL, TEMP_SUP, TEMP_INF |
| --- | --- |
| GEOM | X, Y, Z |
| CORR | CORR |
| EPSA | EPSAXX, EPSAYY,EPSAZZ, EPSAXY,EPSAXZ, EPSAYZ |
| HYDR | HYDR |
| IRRA | IRRA |
| M_ACIER | FERRITE, PPERLITE, PBAINITE, PMARTENS, PAUSTENI, PCOLDSUM, TAUSTE, TRANSF, TACIER |
| M_ZIRC | ALPHPUR, ALPHBETA, BETA, TZIRC, TEMPS |
| NEUT1 | NEUT1 |
| NEUT2 | NEUT2 |
| NEUT3 | NEUT3 |
| SECH | SECH |
| PTOT | PTOT |

The command variable IRRA corresponds to a fluence, that is to say to the integral over time of a neutron flux. It is used by several constitutive laws, in specific units:

- it must be expressed in DPA (displacements per atom) for the law IRRAD3M (cf. [R5.03.23](doc:r5.03.23));
- it must be expressed in ${10}^{20}n/{\mathrm{cm}}^{2}$ for the laws VISC_IRRA_LOG, GRAN_IRRA_LOG, LEMAITRE_IRRA (cf. [R5.03.09](doc:r5.03.09)).

In the case of the use of an Mfront law, one will refer to the documentation [U2.10.02](doc:u2.10.02) for the correspondence between the names of the Aster and Mfront external variables.

#### 4.5.2 Operands TOUT='OUI', GROUP_MA

These keywords make it possible to designate the mesh cells of the zone to be assigned.

#### 4.5.3 Operand CHAM_GD

This keyword makes it possible to associate with the command variable nomvarc the field chvarc. This field is a field of reals (not of functions). It is therefore independent of time and will be used throughout the transient analyses.

If the values of the command variable depend on time, one must use the keyword EVOL (see below). The cham_elem ELGA are authorised only if they come from the operator PROJ_CHAMP/METHODE = 'SOUS_POINT', in order to assign the values to the Gauss sub-points of the elements with sub-points.

For the command variable SECH, the field supplied must contain only the component SECH.

#### 4.5.4 Operands EVOL, NOM_CHAM, FONC_INST, PROL_DROITE, PROL_GAUCHE

These keywords make it possible to associate with the command variable nomvarc the transient evovarc. The keyword NOM_CHAM makes it possible to indicate the symbolic name of the fields of the result data structure to be used. By default, the code chooses:

| **NOM_VARC** | **NOM_CHAM** |
| --- | --- |
| TEMP | 'TEMP' |
| GEOM | 'GEOM' |
| CORR | 'CORR' |
| EPSA | 'EPSA_ELNO' |
| HYDR | 'HYDR_ELNO' |
| IRRA | 'IRRA' |
| M_ACIER | 'META_ELNO' |
| M_ZIRC | 'META_ELNO' |
| NEUT1 | 'NEUT' |
| NEUT2 | 'NEUT' |
| NEUT3 | 'NEUT' |
| SECH | 'SECH' |
| PTOT | 'DEPL' |

The fields are real fields (neither complex nor functions).

The cham_elem ELGA are authorised only if they come from the operator PROJ_CHAMP/METHODE = 'SOUS_POINT', in order to assign the values to the Gauss sub-points of the elements with sub-points.

The keyword FONC_INST = finst makes it possible to define a function (of time) which serves as a correspondence between the "time" of the evolution evovarc (t_evo) and the "time" of the subsequent analysis (t_calc). The function may be a simple "translation" (in order to take into account the fact that the beginning of the time instants of the mechanical analysis is different from the time instant of the beginning of the thermal analysis), but one can do something more complicated, for example in order to impose a "cyclic" mechanical loading (thermal expansion) while computing only a single temperature cycle. One may consult the test case zzzz223a in order to illustrate the use of this keyword.

Caution: the function finst is the one which transforms t_calc into t_evo: t_evo = finst(t_calc)

The keywords PROL_GAUCHE and PROL_DROITE make it possible to specify whether one can use the transient evovarc before the "min" time instant of the transient (PROL_GAUCHE) and/or after the "max" time instant of the transient (PROL_DROITE).

The value 'EXCLU' will cause an error if one seeks to use the transient outside its domain.

The value 'CONSTANT' prolongs the transient by the values at the "min" time instant (or "max").

The value 'LINEAIRE' prolongs the transient linearly from the first 2 points (or the last points) of the transient.

#### 4.5.5 Operand VALE_REF

This keyword makes it possible to define a "reference" value for the command variable nomvarc when the latter needs a reference value.

Currently, only two command variables require a reference value: 'TEMP' and 'SECH'. For these two variables, the keyword VALE_REF is mandatory. For the other variables, this keyword is forbidden.

For the command variable 'TEMP' in the case of shells, the reference temperature is assumed to be the same for the 3 components. That is why one enters it only once.

```text
♦    VALE_REF= Tref    (ouc0)        [R]
```

##### 4.5.5.1 Reference temperature (${T}_{\mathrm{ref}}$) :

The reference temperature ${T}_{\mathit{ref}}$ introduced after the keyword VALE_REF is the temperature for which there is no thermal strain (cf. [R4.08.01](doc:r4.08.01)).

If the coefficient of thermal expansion $\alpha$ (whose value is introduced in the command DEFI_MATERIAU [U4.43.01](doc:u4.43.01)) does not depend on the temperature: ${\varepsilon}^{\mathrm{th}}(T)=\alpha (T-{T}_{\mathrm{ref}})$ .

If the coefficient of thermal expansion depends on the temperature, the mathematical expression making it possible to compute the thermal strain differs according to the specification of the coefficient of thermal expansion in the command DEFI_MATERIAU:

- the values of the coefficient of thermal expansion (introduced in DEFI_MATERIAU) have been determined by dilatometry tests carried out at the temperature ${T}_{\mathrm{ref}}$ .

In this case, the keyword TEMP_DEF_ALPHA must not be specified in the command DEFI_MATERIAU and the thermal strain is computed by the expression:

${\varepsilon}^{\mathrm{th}}(T)=\alpha (T)(T-{T}_{\mathrm{ref}})$ and ${\varepsilon}^{\mathrm{th}}({T}_{\mathrm{ref}})=0$

where $\alpha (T)$ is given under the keyword ALPHA (or ALPHA_* ) in DEFI_MATERIAU.

- the values of the coefficient of thermal expansion are determined by dilatometry tests which took place at a temperature ${T}_{\text{def}}$ different from the reference temperature ${T}_{\mathrm{ref}}$ .

One must then carry out a change of frame in the computation of the thermal strain [R4.08.01](doc:r4.08.01).

${\epsilon}^{\mathit{th}}(T)={\epsilon}_{m}^{\mathit{th}}(T)-{\epsilon}_{m}^{\mathit{th}}({T}_{\mathit{ref}})$

| where | ${\varepsilon}_{m}^{\mathrm{th}}$ is the measured thermal strain (defined with respect to the temperature ${T}_{\text{def}}$ ), |
| --- | --- |
|  | ${\varepsilon}^{\mathrm{th}}$ is the computed thermal strain (defined with respect to the temperature ${T}_{\mathrm{ref}}$ ). |

The temperature ${T}_{\text{def}}$ is given under the keyword TEMP_DEF_ALPHA in DEFI_MATERIAU, and the values of the expansion coefficient (defined with respect to the temperature ${T}_{\text{def}}$ ) are given under the keyword ALPHA or (ALPHA_* ) in DEFI_MATERIAU.

**Note:**

- *In a THM modelling, the temperature is not a command variable* and *the coefficient of thermal expansion* cannot *be a function of the temperature.* One must therefore not use the command variable TEMP in THM. An error message will stop you
- *It is not possible to use a formula* nor a nappe *for* ALPHA *, because of the modifications to be taken into account described above.* The parameter ALPHA can depend ONLY on the temperature, and provided that it is a function. *The user, if he* *wishes to use a formula, must first tabulate it by means of the command* CALC_FONC_INTERP *.*

##### 4.5.5.2 Reference drying (${c}_{0}$) :

${c}_{0}$ represents the initial water content of the concrete. The user must supply this number when he carries out a mechanical analysis (MECA_STATIQUE or STAT_NON_LINE) with a loading of drying type.

c0 must be given in the same units as the "drying" (AFFE_MATERIAU/AFFE_VARC= _F(NOM_VARC='SECH' ...) for example in $L/{m}^{3}$ ). This unit must be consistent with the parameter DEFI_MATERIAU/ELAS_FO/K_DESSIC.

At this initial water content, the desiccation shrinkage is zero, since:

EPS_rd = K_DESSIC (c0 - c).

#### 4.5.6 Initial state in STAT_NON_LINE

In the command STAT_NON_LINE, the initial state is not computed. It is supplied by the user. By default, the initial state of an analysis is "virgin": displacements, stresses and internal variables are zero.

The possible inconsistency of an initial state may disappear as early as the first computed time step, but it may persist. This depends on the way in which the constitutive law is integrated (choice of the programmer of the law).

If the constitutive behaviour is integrated in an incremental way (old vocabulary: COMP_INCR), the inconsistency of the initial state will persist for all the time instants of the analysis. Otherwise, the inconsistency will disappear at the first time step.

It is therefore very important that the initial state of the analysis be "correct".

If the command variables, at the initial time instant, are such that they cause non-zero anelastic strains, this strain leads to an incorrect initial state.

Indeed, one must have:

$\sigma =A(ϵ-{ϵ}_{\mathit{anel}})$

Since the displacement is zero, the strain $ϵ$ is zero. The stress $\sigma$ cannot be zero.

In practice, therefore, at the initial time instant one must have:

- the temperature equal to the reference temperature
- the hydration equal to zero
- …

### 4.6 Factor keyword AFFE_COMPOR

This factor keyword makes it possible to assign the "multifibre constitutive behaviour" of the multifibre beam elements.

The keywords TOUT and GROUP_MA make it possible to designate the set of mesh cells which will be assigned.

After the keyword COMPOR, the user will indicate the name of a concept of type compor coming from the command DEFI_COMPOR/MULTIFIBRE.

#### 4.6.1 Operand MATER

```text
♦    MATER= mat,
```

Name of the material which one wants to assign.

In the general case, each mesh cell is assigned only one material. Sometimes, one must indicate a list of materials when the non-linear mechanical constitutive behaviour is obtained by the command DEFI_COMPOR [U4.43.06](doc:u4.43.06).

## 5 Examples

**Example 1: Mechanics without thermal expansion**

```text
chmat = AFFE_MATERIAU    (    MAILLAGE= ma,

AFFE= (
_F(TOUT= 'OUI'    ,            MATER= acier),
_F(GROUP_MA=('gma1','gma2','gma3'),    MATER = alu,),),
)
```

On the whole of the mesh (except the mesh cells contained in the groups: gma1, gma2, gma3) the material named acier is assigned.

On the mesh cells contained in the groups gma1, gma2, gma3 the material alu is assigned.

**Example 2: Mechanics with thermal expansion**

Assignment over the whole mesh of the material MAT, some of whose parameters are functions of the temperature. Moreover the coefficient of thermal expansion is defined for this material. The time evolution of the temperature is given via the result data structure EVOTH (of type evol_ther). The reference temperature (that for which the expansion is zero) is equal to 20 degrees.

CHMAT = AFFE_MATERIAU (MAILLAGE = MA,

AFFE =_F(TOUT='OUI', MATER = MAT, ),

AFFE_VARC=_F(NOM_VARC='TEMP', EVOL =EVOTH, VALE_REF=20. ),

)

**Example 3: Mechanics with thermal expansion + complex modelling**

In the previous example, the thermal evolution (EVOTH) applies to all the elements of the model. But it may happen that this situation is unrealistic for certain complex modellings. One must then repeat several times the keyword AFFE_VARC/NOM_VARC='TEMP' in order to assign different thermal evolutions to different parts of the model.

In the following example, the model is a 3D model in which steel reinforcements are embedded. A thermal analysis was carried out beforehand without taking the reinforcements into account. One obtained a result which one called EVOTH3D. The temperature of the nodes of the reinforcement elements is then unknown. If, moreover, one is able to evaluate the temperature of the reinforcements (measurements, ...) and if this temperature is stored in the field (TEMP_ARM), one can then carry out the mechanical analysis of thermal expansion with the following material field:

CHMAT = AFFE_MATERIAU (MAILLAGE = MA,

AFFE =_F(... ),

AFFE_VARC=(

_F(NOM_VARC='TEMP', GROUP_MA='VOLUM', EVOL =EVOTH3D, VALE_REF=20. ),

_F(NOM_VARC='TEMP', GROUP_MA='ARMA', CHAM_GD =TEMP_ARM, VALE_REF=20. ),

))

**Example 4: Mechanics with the influence of irradiation**

Assignment over the whole mesh of the material MAT, some of whose parameters are functions of the irradiation. The time evolution of the irradiation is given via the result data structure EVOL = FLUENC.

CHMAT = AFFE_MATERIAU (MAILLAGE = MA,

AFFE =_F(TOUT='OUI', MATER = MAT, ),

AFFE_VARC=_F(NOM_VARC='IRRA', EVOL =FLUENC, ),

)

**Example 5: Mechanical analysis with an imposed Young's modulus field**

In this example (taken from the test case ssnv130c), one wants to illustrate the possibility of using a Young's modulus field which one assumes to be known (CHYOUNG). For example, this field is read in a file (LIRE_CHAMP) or else it is the result of an analysis.

The "trick" consists in defining a material for which the Young's modulus (keyword ELAS/E) is the "identity" function of the variable 'NEUT1', and one assigns the field CHYOUNG as the command variable 'NEUT1'.

CHYOUNG= ...

NU_F=DEFI_CONSTANTE( VALE=0.3 )

E_F = DEFI_FONCTION(NOM_PARA='NEUT1',VALE=(-1.E-9,-1.E-9, 1.E+9,1.E+9))

MA=DEFI_MATERIAU(ELAS_FO=_F(E=E_F, NU=NU_F,),);

CM=AFFE_MATERIAU( MAILLAGE=M,

AFFE=_F(TOUT= 'OUI', MATER= MA),

AFFE_VARC=_F(NOM_VARC='NEUT1', CHAM_GD=CHYOUNG),

)
