# Python methods for accessing Aster objects

> **Summary.**

This document presents the Python methods for accessing the information contained in Aster data structures. This information can be processed by Python programming, or used for the conditional chaining of the subsequent commands.

## 1 Introduction and precautions for use

In *Code_Aster*, most commands are programmed in Fortran. The data structures produced are accessible only through the JEVEUX memory manager, itself written in Fortran. In a standard run of the code, only the names of the concepts (and not the objects that themselves carry the computed information) are passed up to the supervisor, from command to command, by means of the keywords.

In a use of Python more advanced than the simple declaration of *Code_Aster* commands, the command file written in Python can use the content of the data structures specific to *Code_Aster*. Indeed, Python can be used in command files to create macro-commands and operations such as loops (for, while,…), tests (if,…), executions of external commands (via the os module), etc. The page "Use / Examples / Examples of the use of Python in Aster" of the website www.code‑aster.org brings together a certain number of application cases. It is then of interest to the user to recover the product of the Fortran computations in the Python space, that is, in the command file. Several Python methods have been developed in order to access the content of other data structures.

To recover computed data (in the JEVEUX memory), it is absolutely necessary that the instructions leading to their production have indeed been executed beforehand. In other words, the code must be run in PAR_LOT='NON' mode (keyword of the command DEBUT or POURSUITE). In this case, indeed, there is no global analysis of the command file; each instruction is executed sequentially. When an instruction is reached, all the concepts preceding it have therefore already been computed.

```
DEBUT ( PAR_LOT = ‘NON’)
```

It must then be noted that the command file thus produced is not readable by EFICAS, which tolerates only files composed exclusively of commands specific to Code_Aster. Only the simple variables (reals, integers, strings) defined in declarative mode $a=’\mathit{toto}’$ or in algebraic mode $n=3+4$ are readable by EFICAS.

The information read back from the JEVEUX memory, the product of a prior analysis, can be exploited for example in order to (non-exhaustive list):

- Chain other commands conditionally (execution of a while loop until a computed value of a limit stress is obtained)

- Handle in Python the content of a table or of a fonction, for the purposes of computation

- Recover the attributes of a mesh: list of the node groups and of the mesh-cell groups, coordinates.

## 2 Tables

Data structures of type table are produced in Aster by creation (CREA_TABLE), by reading from a file (LIRE_TABLE), or by recovery from another concept (RECU_TABLE). Functionally they are tables of heterogeneous data (integers, reals, character strings) whose columns are identified by label names.

They are convenient structures whose use is widespread in the code. For example, most post-processing commands produce tables: in order to extract stresses at given geometric locations, in order to produce computed macroscopic quantities (grandeurs) (post-processing in fracture mechanics).

Take for example the following table tab1, coming from an Aster analysis:

| NOEUD | NUME_ORDRE | DX |
| --- | --- | --- |
| $\mathit{N2}$ | 14 | 0.93 |
| $\mathit{N2}$ | 15 | 1.16 |
| $\mathit{N1}$ | 3 | 0.70 |
| $\mathit{N1}$ | 2 | 0.46 |
| $\mathit{N1}$ | 1 | 0.23 |

**Table** 2-1

It could also have been created directly as an Aster concept of type table by:

```
tab1=CREA_TABLE(LISTE = (
_F(        PARA=’NOEUD’,            LISTE_K=(‘N2’,’N2’,’N1’,’N1’,’N1’),),
_F(        PARA=’NUME_ORDRE’,    LISTE_I=(14,15,3,2,1),),
_F(        PARA=’DX’,            LISTE_R=(0.93,1.16,0.70,0.46,0.23),),)
```

Any value in the table can be recovered directly when its access key (column label name) and the row number are known:

>>> print tab1[’DX’,3]

0.70

It is also possible to recover the whole of the table in the Python environment through a dedicated class, produced by the EXTR_TABLE method, attached to the class of the ASTER concept:

tab2 = tab1.EXTR_TABLE()

tab2 is a Python object, an instance of the class Table of the module Utilitai.Table. It can be handled with the methods associated with this class; one can call help(Table) to find out the methods of this class.

The table tab2 could also have been defined directly by a dictionary:

```
From Utilitai.Table import Table

listdic = [    {'NOEUD': 'N2' ,'NUME_ORDRE': 14,'DX': 0.93, },
{'NOEUD': 'N2' ,'NUME_ORDRE': 15,'DX': 1. 16,},
{'NOEUD': 'N1' ,'NUME_ORDRE': 3 ,'DX': 0.70, },
{'NOEUD': 'N1' ,'NUME_ORDRE': 2 ,'DX': 0.46, },
{'NOEUD': 'N1' ,'NUME_ORDRE': 1 ,'DX': 0.23, }, ]

listpara=['NOEUD','NUME_ORDRE','DX']

listtype=['K8','I','R']

tab2=Table(listdic,listpara,listtype)
```

The operations possible on tab2 are described below.

### 2.1 Printout

```
>>> tab2

----------------------------------------------

NOEUD        NUME_ORDRE    DX

N2            14                9.30000E-01

N2            15                1.16000E+00

N1            3                7.00000E-01

N1            2                4.60000E-01

N1            1                2.30000E-01
```

Also possible:

```
>>> print tab2
```

Display of a single parameter:

```
>>> t.DX

----------------------------------------------

DX

9.30000E-01

1.16000E+00

7.00000E-01

4.60000E-01

2.30000E-01
```

The IMPR_TABLE command uses the printout capabilities offered by this class. The interested reader may read the Python programming of this macro-command. In particular, the possibility of printing cross tables.

### 2.2 Creation or printout of a sub-table extracted by a filter

Extraction according to a single criterion:

```
>>> print tab2.NUME_ORDRE <=5

----------------------------------------------

NOEUD        NUME_ORDRE    DX

N1            3                7.00000E-01

N1            2                4.60000E-01

N1            1                2.30000E-01
```

Extraction according to two criteria with the logical combination «&» / AND:

```
>>> print (t.NUME_ORDRE < 10) & (t.DX>=0.3)

----------------------------------------------

NOEUD        NUME_ORDRE    DX

N1            3                7.00000E-01

N1            2                4.60000E-01
```

Extraction according to two criteria with the logical combination «|» / OR:

```
>>> print (t.NUME_ORDRE < 2) | (t.DX<0.5)

----------------------------------------------

NOEUD        NUME_ORDRE    DX

N1            1                2.30000E-01

N1            2                4.60000E-01
```

Extraction of a restricted number of labels:

```
>>> t['DX','NUME_ORDRE']

----------------------------------------------

DX                NUME_ORDRE

9.30000E-01    14

1.16000E+00    15

7.00000E-01    3

4.60000E-01    2

2.30000E-01    1
```

Extraction according to an equality criterion (here with the value of the criterion itself deduced from the table)

```
>>> t.DX == max(t.DX)

----------------------------------------------

NOEUD        NUME_ORDRE    DX

N2            15                1.16000E+00
```

### 2.3 Sorting

Sorting of the whole table according to a label:

```
>>> t.sort('NUME_ORDRE')

>>> t

----------------------------------------------

NOEUD        NUME_ORDRE    DX

N1            1                2.30000E-01

N1            2                4.60000E-01

N1            3                7.00000E-01

N2            14                9.30000E-01

N2            15                1.16000E+00
```

To sort according to several labels, the order of precedence being the order in which the labels are declared, the labels must be supplied in the form of a list or of a tuple:

```
>>> t.sort(['NUME_ORDRE',’DX’])
```

A second argument, ordre, equal to 'CROISSANT' or 'DECROISSANT', makes it possible to specify the sort order:

```
>>> t.sort(['NUME_ORDRE',’DX’],'DECROISSANT')
```

### 2.4 Access to the values

The content of the table is accessible through the values() method, which produces a dictionary whose keys are the access parameters of the table and whose values are the columns:

```
>>> tab2.values()

{'NOEUD': [:ref:`'N1', 'N1', 'N1', 'N2', 'N2' <'N1', 'N1', 'N1', 'N2', 'N2'>`], 'NUME_ORDRE': [:ref:`1, 2, 3, 14, 15 <1, 2, 3, 14, 15>`], 'DX': [:ref:`0.23, 0.46, 0.70, 0.93, 1.156 <0.23, 0.46, 0.70, 0.93, 1.156>`]}
```

The parameters are given by the attribute para (same as tab2.values().keys())

```
>>> tab2.para

['NOEUD', 'NUME_ORDRE', 'DX']
```

## 3 Access methods on concepts

### 3.1 Access to the content of a list SD

lst = listr8 .Valeurs()

lst is a Python list that contains the values of the Aster list: lst = 0., 1.1, 2.3, ...

### 3.2 Access to the content of a fonction SD or of a nappe SD

lst1, lst2 , (lst3) = [fonction / nappe] .Valeurs()

lst1 and lst2 are two Python lists that contain the abscissae and the ordinates. If the function is complex, a third list is obtained, and lst2 and lst3 will contain the lists of the real and imaginary parts.

lst1 = [fonction] .Absc()

lst1 is the list of the abscissae, that is, also the first list returned by Valeurs().

lst2 = [fonction] .Ordo()

lst2 is the list of the ordinates, that is, also the second list returned by Valeurs().

dico1 = [fonction] .Parametres()

returns a dictionary containing the parameters of the function; the JEVEUX type (FONCTION, FONC_C, NAPPE) is not returned, so the dictionary can be supplied to CALC_FONC_INTERP as it stands (see efica02a).

### 3.3 Evaluation of a fonction SD or of a formule

Functions and formulae can be evaluated simply in the Python namespace, that is, in the command file, as follows:

```
FONC1=FORMULE(    VALE='(Y**2)+ X’,
NOM_PARA=('X','Y',)),
);

>>> print FONC1(1.,2.)

5.
```

or with a function:

```
FONC2=DEFI_FONCTION( NOM_PARA='X', VALE=(0., 0., 1., 4.,) )

>>> print FONC2(0.5)

2.
```

In the case of functions, it should be noted that a relative tolerance of 1.e-6 is applied when the value of the parameter lies very close to the bounds, so as to avoid an error due to a forbidden extension, to within rounding.

### 3.4 Access to the content of a maillage SD

Two methods make it possible to recover the list of the mesh-cell groups and of the node groups of a data structure of type maillage:

```
[ (tuple), …]        = [maillage] .LIST_GROUP_MA()
```

returns a list of tuples, each containing the name of each mesh-cell group, the number of mesh cells it contains, and the highest dimension (0, 1, 2 or 3) of its mesh cells:

tuple = (‘GMA’, number of mesh cells, mesh-cell dim.)

```
[ (tuple), ...]        =[maillage] .LIST_GROUP_NO()
```

returns the list of the node groups in the form:

tuple = (name of the group_no, number of nodes of the group_no)

### 3.5 Access to the content of an SD matr_asse_*

Let matr be a data structure matr_asse_depl_r.

A numpy array of the full matrix is recovered by:

array = matr.EXTR_MATR()

To recover the matrix with sparse storage, one does:

data, lines, cols, dim = matr.EXTR_MATR(sparse=True)

One has:

array has dimension (dim, dim)

number of non-zero terms: len(data) = len(lines) = len(cols)

data[k] = array[ lines[k], cols[k] ]

Likewise, for matrgene, a data structure matr_asse_gene_r, for example, produced by the operator PROJ_MATR_BASE.

A numpy array of the full matrix is recovered by:

array = matrgene.EXTR_MATR_GENE()

### 3.9 Retrieval in Python of fields by element and fields at the nodes (EXTR_COMP)

The EXTR_COMP method, applied to a field, makes it possible to retrieve the content of the field in Python.

#### 3.9.1 Arguments of the EXTR_COMP command

The command has 3 arguments:

ch1 = CHAMP.EXTR_COMP(comp=' ',lgma=[],topo=0), for fields at the nodes,

ch1 = CHAMP.EXTR_COMP(comp,lgma,topo=0), for fields by element,

| comp | component of the field on the list lgma. For fields at the nodes, if comp is left at its default, all the components are returned. The result of the command is modified (see below). |
| --- | --- |
| lgma | list of mesh-cell groups; if empty, all the group_ma are taken (equivalent to TOUT='OUI' in the Aster commands. |
| topo | topology information is returned if >0 (optional, default = 0). |

Table 3.9.1-1

Note: for fields at the nodes, the command can be launched as follows: ch1=CHAMP.EXTR_COMP(topo=1). In this case, all the components are returned for all the topological entities of the field CHAMP.

#### 3.9.2 Example of use

Starting from the result U:

1. A field (node or elXX) corresponding to a time instant is created with CREA_CHAMP.

1. The component is extracted by the EXTR_COMP method (declared for the cham_elem and the cham_no), which creates a new type of Python object: post_comp_cham_el and post_comp_cham_no, whose attributes are described below. All the components can be extracted at once by not specifying the component (for fields at the nodes only).

U = STAT_NON_LINE( ... )

U104 = CREA_CHAMP(

TYPE_CHAM = 'NOEU_DEPL_R',

OPERATION = 'EXTR',

RESULTAT = U,

NOM_CHAM = 'DEPL',

NUME_ORDRE = 104,

)

U104NP = U104.EXTR_COMP('DX',['S_SUP',])

print U104NP.valeurs

V104 = CREA_CHAMP(

TYPE_CHAM = 'ELGA_VARI_R',

OPERATION = 'EXTR',

RESULTAT = U,

NOM_CHAM = 'VARI_ELGA',

NUME_ORDRE = 104,

)

V104NP = V104.EXTR_COMP('V22',[],1)

print V104NP.valeurs

print V104NP.maille

print V104NP.point

print V104NP.sous_point

#### 3.9.3 Results of the EXTR_COMP command

ch1.valeurs: Numeric.array containing the values

- For fields by element, if the topology has been requested (topo>0):

- ch1.maille: mesh-cell numbers

- ch1.point: number of the point in the mesh cell

- ch1.sous_point: number of the sub-point in the mesh cell

- For fields at the nodes, if the topology has been requested (topo>0):

- ch1.noeud: node numbers

- ch1.comp: if all the components of the field have been requested (comp = ' ', the default value), the component associated with the value.

## 4 Method for accessing an arbitrary data structure

Any vector or any collection present in memory can be recovered, provided that the data structure is known.

Two methods are possible (and equivalent): by using the catalogue of the data structure, or directly the JEVEUX name of the object.

In the first case, one uses the "property" sdj of the concept, which makes it possible to navigate in the data structure (see the example below).

### 4.1 Access to a data structure of vector type

The getvectjev method gives access to a data structure of vector type. It is always applied to the "aster" object, and takes as argument the complete character string (including spaces) that defines the name of the object, contained in the data structure, that one wants to access. This name can be determined by means of the Aster command IMPR_CO(CONCEPT=_F(NOM=nom)).

Example: recover the coordinates of the nodes of a mesh named MA:

res = aster.getvectjev("MA .COORDO .VALE ")

The equivalent syntax, using the data-structure catalogue, is:

res = MA.sdj.COORDO.VALE.get()

A Python list containing the values of the vector is obtained.

### 4.2 Access to a data structure of collection type

In a similar way, the getcolljev method allows collections to be consulted from Python. It returns a dictionary whose keys are the names of the objects in the case of a named collection, and the index numbers otherwise.

Example: recover the information concerning the connectivity of the elements of the mesh MA:

res = aster.getcolljev("MA .CONNEX ")

The equivalent syntax, using the data-structure catalogue, is:

res = MA.sdj.CONNEX.get()

A dictionary resembling the following is obtained:

{3: (2, 1, 5), 2: (6, 9, 10, 7, 11, 12, 13, 8), 1: (1, 6, 7, 2, 3, 8, 5)}
