# u4.53.51 Operator CALC_TRANSFERT

## 1 Purpose

This operator makes it possible to compute the matrix of dynamic transfer functions of a linear mechanical system between two points of the numerical model. The transfer functions may be in acceleration, velocity or displacement. One can treat the case of absolute or relative motions, under the action of an entrainment excitation.

It is also possible to obtain the response at any point of the numerical model as a function of an output signal supplied by the user.

This operator uses as input data the responses of the mechanical system to unidirectional excitations, preferably of white-noise type.

It produces one or two data structures of type table, one for the matrix of transfer functions, the other for the possible computed signal.

## 2 Syntax

```text
table = CALC_TRANSFERT(
    ◆ NOM_CHAM = / "DEPL",
                 / "VITE",
                 / "ACCE",
    ◆ ENTREE = _F(
         ◆ GROUP_NO = grno,
      ),
    ◆ SORTIE = _F(
         ◆ GROUP_NO = grno,
      ),
    ◇ REPERE = / "RELATIF" (par défaut),
               / "ABSOLU",
    # Si: equal_to("REPERE", 'RELATIF')
        ◆ ENTRAINEMENT = _F(
             ◆ DX = fonction_c / fonction,
             ◆ DY = fonction_c / fonction,
             ◇ DZ = fonction_c / fonction,
          ),
    ◆ RESULTAT_X = dyna_trans / tran_gene / harm_gene / dyna_harmo,
    ◆ RESULTAT_Y = dyna_trans / tran_gene / harm_gene / dyna_harmo,
    ◇ RESULTAT_Z = dyna_trans / tran_gene / harm_gene / dyna_harmo,
    ◇ SIGNAL = _F(
         ◆ MESURE_X = fonction_c / fonction,
         ◆ MESURE_Y = fonction_c / fonction,
         ◇ MESURE_Z = fonction_c / fonction,
         ◆ TABLE_RESU = co,
         ◇ TYPE_RESU = / "HARMONIQUE" (par défaut),
                       / "TEMPOREL",
      ),
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Description of the macro-command and preliminary steps

The operator CALC_TRANSFERT makes it possible to compute the dynamic transfer-function matrix between two points of the structure (input => output). It also allows the user to determine the signal at one point of the structure (at the input) knowing the signal at another point of the structure (at the output).

![Figure](/figures/u4.53.51/100002010000039C000001A5BE1AB41D936D5F4A.png)

Figure 1 – Schematic representation of the use of the macro-command

Before using the command, the user must carry out several linear dynamic analyses under unidirectional excitation. For example, if the study is in 3D (respectively 2D), the user must carry out 3 analyses (respectively 2 analyses) exciting one of the three (respectively 2) directions. It is preferable to carry out these dynamic analyses by means of a unidirectional white noise.

The dynamic analyses must be carried out with the same list of frequencies if the analysis is harmonic and with the same list of time instants if the analysis is transient. For a transient analysis, the user must take care to have a list of time instants with a constant step. Otherwise an error message will be issued, because the Fourier transform required by the various analyses requires a constant step.

The dynamic analyses must be of the same type, either tran_gene, or harm_gene, or dyna_trans, or else dyna_harmo.

When the user must supply the entrainment functions and/or the measured signals, it is preferable that the latter be discretised on the same list of frequencies (case of a harmonic analysis) or on the same list of times (case of a transient analysis).

## 4 Operands

### 4.1 Concepts created by the command

This command creates as output a concept of type table. It is also possible to output a second table containing the signals corresponding to the dynamic excitation (at the input) computed from the measured signals (at the output).

The first concept produced, whatever use the user makes of the macro-command, is a table which contains the data of the transfer-function matrix arranged as follows:

- The first column corresponds to the frequencies (FREQ);
- The following ones correspond to the components of the matrix arranged in order by rows ${H}_{xx}$ , ${H}_{xy}$ , ${H}_{xz}$ , ${H}_{yx}$ , ${H}_{yy}$ , ${H}_{yz}$ , ${H}_{\mathrm{zx}}$ , ${H}_{\mathrm{zy}}$ and ${H}_{zz}$ . In the 2D case, one will have ${H}_{xx}$ , ${H}_{xy}$ , ${H}_{yx}$ and ${H}_{yy}$ .

$H(\omega )=(\begin{array}{ccc}{H}_{xx}& {H}_{xy}& {H}_{xz}\\ {H}_{yx}& {H}_{yy}& {H}_{yz}\\ {H}_{\mathrm{zx}}& {H}_{\mathrm{zy}}& {H}_{zz}\end{array})$

### 4.2 Operands RESULTAT_X, RESULTAT_Y and RESULTAT_Z

```text
♦    RESULTAT_X    =    resu_x
```

Name of the concept of type resultat for which the linear dynamic analysis was carried out with a unidirectional excitation along $x$ .

```text
♦    RESULTAT_Y    =    resu_y
```

Name of the concept of type resultat for which the linear dynamic analysis was carried out with a unidirectional excitation along $y$ .

```text
◊    RESULTAT_Z    =    resu_z
```

Name of the concept of type resultat for which the linear dynamic analysis was carried out with a unidirectional excitation along $z$ .

**Notes:**

*Only result data structures of type* *dyna_trans,* *dyna_harmo,* *tran_gene and* *harm_gene can be supplied in these operands.*

*The analyses produced by the dynamic operators and which are to be supplied in the operands* *RESULTAT_X,* *RESULTAT_Y and* *RESULTAT_Z must be of the same type:* *dyna_trans, or* *dyna_harmo or* *tran_gene or* *harm_gene.*

### 4.3 Operand NOM_CHAM

```text
♦    NOM_CHAM = nomcha
```

```text
Nom symbolique du champ que l'on souhaite extraire des calculs dynamiques linéaires réalisés au préalable par l'utilisateur et renseignés dans les opérandesRESULTAT_X, RESULTAT_Y et RESULTAT_Z.
```

The possible names of the field are: 'DEPL', 'VITE' and 'ACCE'.

**Note:**

The various functions supplied by the user, such as the entrainment functions supplied under the keyword *ENTRAINEMENT* or the measured functions supplied under the keyword *SIGNAL*, must be of the same type as **nomcha.**

### 4.4 Operand REPERE

```text
♦    REPERE =     /'ABSOLU'
/'RELATIF'
```

This mandatory operand makes it possible to supply the type of response computed by the dynamic operators. If the reference frame is RELATIF (for a linear dynamic analysis in relative motion), then the user must supply the entrainment signal under the keyword ENTRAINEMENT (see paragraph 4.5).

### 4.5 Factor keyword ENTRAINEMENT

The factor keyword ENTRAINEMENT makes it possible to supply the entrainment excitations which were used to carry out the various linear dynamic analyses in relative motion.

**Note:**

*The various entrainment functions supplied under the keyword* *ENTRAINEMENT must be of the same type as* **nomcha**  ('DEPL', 'VITE' or 'ACCE') *.*

#### 4.5.1 Operands DX, DY and DZ

```text
♦    DX = entr_x
```

This operand makes it possible to supply the unidirectional excitation (along the direction $x$) used for the first dynamic analysis.

```text
♦    DY = entr_y
```

This operand makes it possible to supply the unidirectional excitation (along the direction $y$) used for the second dynamic analysis.

```text
◊    DZ = entr_z
```

This operand makes it possible to supply the unidirectional excitation (along the direction $z$) used for the third dynamic analysis.

### 4.6 Factor keywords ENTREE and SORTIE

#### 4.6.1 Operand GROUP_NO

```text
♦    GROUP_NO    =    grno
```

The mandatory factor keywords ENTREE and SORTIE make it possible to supply the name of a node group (grno, containing a single node) on which the extraction of the field 'DEPL' or 'VITE' or 'ACCE' is carried out.

### 4.7 Factor keyword SIGNAL

This factor keyword (optional) makes it possible to determine the dynamic excitation (at the input) which led to the measured signals (at the output) supplied by the user under the factor keyword SIGNAL.

#### 4.7.1 Operands MESURE_X, MESURE_Y and MESURE_Z

```text
♦    MESURE_X = f_x
```

This operand makes it possible to supply the signal measured along the direction $x$ .

```text
♦    MESURE_Y = f_y
```

This operand makes it possible to supply the signal measured along the direction $y$ .

```text
◊    MESURE_Z = f_z
```

This operand makes it possible to supply the signal measured along the direction $z$.

**Note:**

*The signals must be of the same type as* **nomcha** *and must be discretised on one and the same list of frequencies or of times.*

#### 4.7.2 Operand TYPE_RESU

```text
♦    TYPE_RESU =    /'TEMPOREL',
/'HARMONIQUE'
```

This operand makes it possible to supply the type of results required as output of the table.

#### 4.7.3 Operand TABLE_RESU

```text
♦    TABLE_RESU = nom_table
```

This operand makes it possible to supply the name of the table in which the signals computed from the measured signals will appear.

The table will be composed of several columns arranged as follows:

If TYPE_RESU = 'TEMPOREL':

INST, FX, FY, FZ

If TYPE_RESU = 'HARMONIQUE':

FREQ, Re_FX, Im_FX, Re_FY,Im_FY, Re_FZ, Im_FZ
