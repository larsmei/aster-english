# u3.02.01 Interface of the GMSH mesh file with Aster

**Summary:**

GMSH is a tool for modelling, meshing and post-processing, distributed under the GNU-GPL licence ([https://gmsh.info](https://gmsh.info), executables, sources and documentation available on this site).

The principle of the interface which makes it possible to use in *Aster* a file coming from GMSH is described here.

This interface is implemented in *Aster* by the command PRE_GMSH [U7.01.31](doc:u7.01.31).

## 1 Use of GMSH

GMSH is a free or mapped meshing tool which incorporates a modeller and post-processing functionalities. The modeller, simple to use, makes it possible to prepare the meshing of structures by geometric constructions (creation of lines, surfaces, translations/rotations, extrusions…).

The model of the structure can be built interactively (with the mouse) or else by a command file.

The documentation of GMSH is available at this address:
[https://gmsh.info](https://gmsh.info).

The description of the geometry of the structure is contained in a .geo file; the mesh produced is saved with the extension .msh; this file will be converted by the command PRE_GMSH to the *Aster* format.

## 2 GMSH entities and Aster groups

The GMSH modeller handles points, lines, surfaces or volumes as geometric entities (not meshed). The GMSH mesh is built by meshing, in this order, the lines, the surfaces and then the volumes supported on them.

In general, one handles parts of the mesh in order to apply the material properties, the boundary conditions or the loadings. In order to access these sub-parts of the mesh, it is necessary to define “physicals” in GMSH. A “physical” is composed of one or more geometric entities. The GMSH–Aster interface produces a mesh-cell group for each “physical”: if “physical 21” is made up of two volumes, the mesh-cell group $\mathit{GM21}$ contains the mesh cells of these two volumes.

**Note:**

*In GMSH, one visualises the entities constituting a “physical” by the menu Tools/Visibility and by selecting the number. One can then use the command* *DEFI_GROUP in* Aster *in order to handle a more explicit mesh-cell group name.*

**Warning:**

One must not create “physicals” grouping other “physicals”, because that would lead to the production of duplicate mesh cells.

The number of the “physicals” must be less than 1000000.

## 3 Examples

### 3.1 GMSH geometry and mesh

One creates a very simple geometry: a square of side $1$ . Here, one creates the points, the lines and the surface; one could also have made it by translation/extrusion…

**NB:**

*One creates a “physical” which contains the square surface of number 107.*

```text
L=1;

d=0.45;

Point(1) = {0, 0, 0, d};

Point(2) = {L, 0, 0, d};

Point(3) = {L, L, 0, d};

Point(4) = {0, L, 0, d};

Line (1) = {1, 2};

Line (2) = {2, 3};

Line (3) = {3, 4};

Line (4) = {4, 1};

Line Loop (106) = {2, 3, 4, 1};

Plane Surface (6) = {106};

Physical Surface(107) = {6};
```

### 3.2 Aster mesh file produced by the operator PRE_GMSH

```text
TITRE

AUTEUR=INTERFACE_GMSH DATE=17/07/2003

FINSF

%

COOR_3D NBOBJ=9

%FORMAT=(1*NOM_DE_NOEUD,3*COORD)

N1 0.00000000000000E+00 0.00000000000000E+00 0.00000000000000E+00

N2 1.00000000000000E+00 0.00000000000000E+00 0.00000000000000E+00

N3 1.00000000000000E+00 1.00000000000000E+00 0.00000000000000E+00

N4 0.00000000000000E+00 1.00000000000000E+00 0.00000000000000E+00

N5 4.99999999999993E-01 0.00000000000000E+00 0.00000000000000E+00

N6 1.00000000000000E+00 4.99999999999993E-01 0.00000000000000E+00

N7 5.00000000000007E-01 1.00000000000000E+00 0.00000000000000E+00

N8 0.00000000000000E+00 5.00000000000007E-01 0.00000000000000E+00

N13 5.00000000000000E-01 5.00000000000000E-01 0.00000000000000E+00

FINSF

%

TRIA3 NOM=INDEFINI NBOBJ=8

M1 N13 N1 N5

M2 N8 N1 N13

M3 N5 N2 N13

M4 N13 N2 N6

M5 N6 N3 N13

M6 N13 N3 N7

M7 N7 N4 N13

M8 N13 N4 N8

FINSF

%

GROUP_MA NOM=GM107

M1 M2 M3 M4 M5 M6 M7 M8

FINSF

%

FIN
```

The eight triangles making up the meshed square are then accessible in *Aster* in the mesh-cell group GM107.
