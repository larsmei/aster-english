# u4.84.32 Command DEFI_CHAR_SOL

## 1 Purpose

Produce a load usable in the dynamic solution operators DYNA_VIBRA and DYNA_NON_LINE in order to be able to take into account seismic loads on the boundaries of 2D or 3D soil domains. The loads created potentially come from two sources: either loads of “plane wave” type deduced from motions imposed on the lateral boundaries in the direction of propagation, or right-hand-side complements of “nodal force” type imposed on the lateral boundaries in the directions transverse to the propagation.

The imposed-motion data or the force fields may likewise come from two sources: either a result file of transient evolutions coming from an auxiliary analysis of a 2D soil column by DEFI_SOL_EQUI, or an evolution of result type computed on an auxiliary model and projected onto the boundaries of the domain.

It takes into account the concomitance of these alternative choices:

- source of the transient data of motions or forces on the boundaries: either a unit of transient results obtained by DEFI_SOL_EQUI for the auxiliary analysis of a 2D soil column, behind the keyword UNITE_TRAN_UNIT, and in this case one supplies data consistent with DEFI_SOL_EQUI; or a result of transient evolutions on the boundaries of the basin computed on an auxiliary 2D or 3D model, entered behind the keyword RESU_INIT and consistent with the new syntax of CREA_RESU. In both cases, one must specify the type of load, plane wave or imposed force, by the keyword CHARGEMENT.

## 2 Syntax

```text
char_meca = DEFI_CHAR_SOL(
    ◇ CHARGEMENT = / "FORCE" (par défaut),
                   / "ONDE_PLANE",
    ◆ MODELE = modele,
    ◆ / UNITE_TRAN_INIT = unit,
      / RESU_INIT = evol_noli / dyna_trans / evol_char,
    # Si: exists("UNITE_TRAN_INIT")
        ◇ LONG_CARA = float,
        ◇ AXE = / "X",
                / "Y",
                / "Z",
        ◇ NOM_PARA = / "Y",
                     / "Z" (par défaut),
        ◇ Z0 = float,
        ◇ NOM_CMP = / "DX" (par défaut),
                    / "DY",
        ◆ | GROUP_MA_DROITE = grma,
          | GROUP_MA_GAUCHE = grma,
        ◆ TABLE_MATER_ELAS = table,
    # Si: exists("RESU_INIT")
        ◇ MATR_RIGI = matr_asse_depl_r,
        ◇ COEF = float (défaut: 1.0),
        ◇ NOM_CHAM_INIT = / "ACCE",
                          / "FORC_NODA" (par défaut),
                          / "REAC_NODA",
        ◇ DDL_EXCLUS = / "DX",
                       / "DY",
                       / "DZ",
                       / "DRX",
                       / "DRY",
                       / "DRZ",
        ◇ MATR_AMOR = matr_asse_depl_r,
        ◇ NUME_DDL = nume_ddl,
        ◆ LIST_INST = listr8,
        ◇ PRECISION = float (défaut: 1e-06),
        ◇ CRITERE = / "RELATIF" (par défaut),
                    / "ABSOLU",
    ◇ TITRE = text,
    ◇ INFO = / 1 (par défaut),
             / 2,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Operand MODELE

```text
♦    MODELE = mo
```

Makes it possible to define the name of the model to which the load will be assigned. Depending on the dimension of the problem, it must be, in 2D, a plane-strain model ('D_PLAN'), or, in 3D, a volume model with a modelling '3D'.

### 3.2 Operand CHARGEMENT

◊    CHARGEMENT =        /    'ONDE_PLANE',

```text
/    'FORCE',
```

Indicates the nature of the imposed loading:

- CHARGEMENT = 'ONDE_PLANE': loading in the form of a vertically propagating plane wave imposed on the model and deduced from the plane-wave motion imposed on a 2D soil column or on another auxiliary model. The wave is a shear wave if one has a horizontal excitation motion, and a pressure wave if one has a vertical excitation motion.
- CHARGEMENT = 'FORCE': loading in the form of opposing forces imposed on the lateral edges of the model.

### 3.3 Operand UNITE_TRAN_INIT

Supplies the logical unit for writing, in 'TABLEAU' format, the transient evolutions at each of the levels of a 2D column of stratified soil obtained during a previous call to DEFI_SOL_EQUI. During this previous call, the evolutions are created by means of the keyword UNITE_RESU_TRAN. The loads imposed on the model are extracted in the form of force distributions depending on time and on the elevation of the stratification, from the file corresponding to this unit.

#### 3.3.1 Operand NOM_CMP

◊    NOM_CMP =            /    'DX',        [DEFAUT]

```text
/    'DY',
```

Indicates the direction of the signal imposed on the 2D soil column that was used to supply the results of the transient evolutions to be imposed as boundary conditions:

- NOM_CMP = 'DX': the imposed signal is horizontal (corresponds to a vertically propagating shear wave);
- NOM_CMP = 'DY': the imposed signal is vertical (corresponds to a vertical pressure wave).

#### 3.3.2 Operand AXE

◊    AXE =                /    'X',

```text
/    'Y',
/    'Z',
```

Indicates the direction of the load imposed on the model. This parameter is necessary in 3D and, by its presence, makes it possible to activate this loading case.

**Note:**  this keyword is not necessary in 2D because the direction of the load depends on the type of loading and on the direction of the signal: for NOM_CMP = 'DX', one has 'X' for CHARGEMENT = 'ONDE_PLANE' and 'Y' for CHARGEMENT = 'FORCE'. The converse holds for NOM_CMP = 'DY'.

#### 3.3.3 Operand NOM_PARA

◊    NOM_PARA=                /    'Y',

```text
/    'Z',        [DEFAUT]
```

Makes it possible to specify, in 3D only, the direction of propagation of the plane-wave signal generating the force to be applied and corresponding to the vertical direction of the model. This operand is not necessary in most cases because it is generally deduced from the direction of the signal imposed on the soil column by NOM_CMP and from the direction of the load imposed on the model by AXE. But for NOM_CMP = 'DY', and AXE = 'X', for example, one may have a propagation parameter for a loading of type 'FORCE' equally well in the direction 'Y' as in the direction 'Z'. And for NOM_CMP = 'DX', and AXE = 'X', for a loading of type 'ONDE_PLANE', one may equally well have an SH wave in the direction 'Y' as an SV wave in the direction 'Z'.

One nevertheless considers a default value ' Z' as the vertical direction for a 3D problem.

#### 3.3.4 Operands GROUP_MA_DROITE/GROUP_MA_GAUCHE

♦     |  ◊ GROUP_MA_DROITE = gmda

```text
| ◊ GROUP_MA_GAUCHE = gmga
```

Make it possible to define respectively the names of the mesh-cell groups representative of the right-hand edge and of the left-hand edge of the model to which the load will be assigned. One must supply at least one of these operands. These mesh-cell groups are line groups in 2D and surface groups in 3D, except in the case of a loading of type 'FORCE' in 3D, where one must define line mesh-cell groups encircling the edges of the model.

#### 3.3.5 Operand TABLE_MATER_ELAS

Indicates the table which contains the information on the geometrical description of the layers of stratified soil and that of the initial characteristics of the materials constituting these layers, layer by layer. It corresponds to the table produced by the call to DEFI_SOL_EQUI which also produced the file entered by UNITE_TRAN_INIT.

#### 3.3.6 Operand Z0

Indicates the elevation of the free surface, zero by default, of the model with which to make the zero elevation of the 2D soil-column model correspond geometrically.

#### 3.3.7 Operand LONG_CARA

Indicates, in the case of a plane-wave loading, the value of the characteristic length defined in DEFI_MATERIAU, keyword ELAS, making it possible to compute the added stiffness on the absorbing boundary constituted by the right-hand and left-hand edges of the soil column.

### 3.4 Operand RESU_INIT

Supplies the name of the result of the transient evolution computed on an auxiliary model, from which one must extract the velocity, displacement or nodal-force fields necessary for the generation of the right-hand-side evolutions to be applied as boundary conditions on the edges of the model.

#### 3.4.1 Operand COEF

◊    COEF    =    /    1,0,    [DEFAUT]

> /    coef

Gives the combination factor to be applied in the case of a loading of type 'FORCE'. It may be necessary to apply factors -1 in the case of a pressure wave P or in the case of a shear wave S on the nodal-force fields computed on the auxiliary model of the original result entered behind the keyword RESU_INIT.

#### 3.4.2 Operands MATR_AMOR / MATR_RIGI

```text
♦    MATR_AMOR= matr_a

◊    MATR_RIGI= matr_k,
```

In the case of a loading of type 'ONDE_PLANE', names of the assembled damping and stiffness matrices (the latter optional) that one uses in the products $KU+CV$ constituting the right-hand-side evolution produced, from which one can create the load to be applied on the model.

#### 3.4.3 Operands NUME_DDL / MATR_RIGI

```text
◊    / MATR_RIGI= matr_k
/ NUME_DDL = nume,
```

In the case of a loading of type 'FORCE', entries from which one can obtain the reference numbering, or conversion, of the right-hand-side evolution produced, from which one can create the load to be applied on the model.

#### 3.4.4 Operands INST / LIST_INST / PRECISION / CRITERE

```text
◊    INST= litps
```

List of real values of the analysis time instants of the original result.

```text
◊    LIST_INST= litps
```

List of reals produced by DEFI_LIST_REEL [U4.34.01](doc:u4.34.01) of the analysis time instants of the evolutions produced.

```text
◊    PRECISION =    / prec         [R]
/1.0D-6        [DEFAUT]
```

Precision used to search for the time instant specified in the original result.

```text
◊    CRITERE =    / 'RELATIF',
/ 'ABSOLU,'
```

Criterion used to search for the time instant specified in the original result.

#### 3.4.5 Operand NOM_CHAM_INIT

```text
♦    NOM_CHAM_INIT=     / 'ACCE',
/ 'FORC_NODA',
/ 'REAC_NODA',
```

Name of the field of the result of the starting evolution, computed of type evol_char or dyna_trans, which one then converts into the field of the result of the right-hand-side evolution of type evol_char transformed into a load.

#### 3.4.6 Operand DDL_EXCLUS

```text
◊    DDL_EXCLUS =    nom_cmp        [TXM]
```

Name of the component to be excluded on the field of the result of the starting evolution computed of type evol_char or dyna_trans, which one then converts into the field of the result of the right-hand-side evolution of type evol_char transformed into a load. It applies in general to a field 'FORC_NODA'. One takes the whole field if the keyword is not supplied.

### 3.5 Operand TITRE

```text
◊    TITRE = titre
```

Allows the user to define a title for the loading.

### 3.6 Operand INFO

```text
◊    INFO =
```

Indicates a printout level for information in the file "MESSAGE":

INFO = 1: no printout

INFO = 2: printout of information on the loading.
