# u4.54.03 Operator THER_NON_LINE_MO

## 1 Purpose

Compute the non-linear steady thermal response with a moving loading.

This operator makes it possible to solve the steady heat equation in a moving reference frame attached to a loading and travelling in a given direction and at a given velocity [R5.02.04](doc:r5.02.04).

The non-linearities of the problem come both from the material characteristics, which depend on the temperature, and from boundary conditions of radiation type.

Problems of this type can be treated with models using plane, axisymmetric and three-dimensional structural finite elements.

The concept produced by this operator is of type evol_ther, as for an analysis by THER_LINEAIRE [U4.54.01](doc:u4.54.01) or THER_NON_LINE [U4.54.02](doc:u4.54.02), but it contains only a single order number, since one performs a steady analysis.

## 3 Operands

### 3.1 Operand MODELE

```text
♦    MODELE= mo
```

Name of the model whose elements are the subject of the thermal analysis.

### 3.2 Operand CHAM_MATER

```text
♦    CHAM_MATER= chmat
```

Name of the material field assigned to the model.

### 3.3 Keyword EXCIT

```text
♦    EXCIT=
```

Factor keyword which makes it possible to define several loadings. For each occurrence of the factor keyword, one defines a load which is constant in time.

#### 3.3.1 Operand CHARGE

```text
♦    CHARGE = char
```

Concept of type charge produced by AFFE_CHAR_THER or by AFFE_CHAR_THER_F [U4.44.02](doc:u4.44.02).

**Important notes:**

*For each occurrence of the factor keyword* *EXCIT the various concepts* *char used must be built on the same model* *mo.*

*Furthermore, the operator* *AFFE_CHAR_THER or* *AFFE_CHAR_THER_F must necessarily fill in, under the factor keyword* *CONVECTION, a concept of type* *cham_no_DEPL_R defining the displacement velocity of the domain and produced by* *CREA_CHAMP.*

*Care must be taken to define boundary conditions consistent with the travel of the part (or of the loading, depending on the chosen reference frame) and the stationarity assumption:*

*If the solid is animated by a uniform translational motion at constant velocity, it is equivalent to consider the computed temperature field:*

- *as a snapshot at a given time instant,*
- *or as a time sequence of the temperature map in a section of fixed abscissa, orthogonal to the direction of travel.*

![Figure](/figures/u4.54.03/10000D16000069BB0000356F2B433754D92B2E05.svg)

*Thus, downstream in space (early in time), the boundary condition on the edge of the part must impose the temperature of the part before the moving loading arrives. Upstream in space (or late in time), a zero heat flux (adiabaticity) guarantees the stationarity assumption.*

### 3.4 Keyword ETAT_INIT

```text
◊    ETAT_INIT
```

Makes it possible to define the initial field from which the analysis in the moving reference frame under the stationarity condition is performed.

#### 3.4.1 Operand EVOL_THER

```text
♦     EVOL_THER = temp
```

Name of the data structure of type evol_ther from which is extracted the temperature field from which the solution of the problem is computed.

#### 3.4.2 Operand NUME_ORDRE

```text
◊    NUME_ORDRE =    /    nuini_evol
/    0                        [DEFAUT]
```

Order number of the field to be extracted from this data structure.

**Note:**

*For this type of analysis, there is no initial condition to define (it is defined by a boundary condition on an edge of the domain defined by the model). Nevertheless, one can still perform the steady analysis starting from a temperature field already computed as the solution of the problem for only part of the load. This can be useful in the case where the application of the whole loading makes convergence difficult. One can then chain several solutions with a loading which evolves progressively and take as the first iterate of a current analysis the solution of the previous analysis. Concretely, one then uses the keyword* *ETAT_INIT to define the temperature field with which one wants to initialise the current analysis.*

### 3.5 Keyword CONVERGENCE

```text
◊    CONVERGENCE=
```

Makes it possible to define the values associated with the convergence criteria:

#### 3.5.1 Operand CRIT_TEMP_RELA

```text
◊    CRIT_TEMP_RELA =    / 1.e-3
/ testr
```

The algorithm continues the iterations as long as the relative variation of the iterate is greater than testr.

${(\underset{i=1,\mathrm{...},\mathrm{nb}\mathrm{ddl}}{\Sigma}{({T}_{i}^{n}-{T}_{i}^{n-1})}^{2})}^{1/2}/{(\underset{i=1,\mathrm{...},\mathrm{nb}\mathrm{ddl}}{\Sigma}{({T}_{i}^{n})}^{2})}^{1/2}>\mathrm{testr}$

where ${T}_{i}^{n}$ denotes the value of the temperature at node i for the n-th iteration.

#### 3.5.2 Operand CRIT_ENTH_RELA

```text
◊    CRIT_ENTH_RELA =    / 1.e-2
/ testl
```

The algorithm continues the iterations as long as the relative variation of the iterate is greater than testl.

${(\underset{i=1,\mathrm{...},N}{\Sigma}{({\beta}_{i}^{n}-{\beta}_{i}^{n-1})}^{2})}^{1/2}/{(\underset{i=1,\mathrm{...},N}{\Sigma}{({\beta}_{i}^{n})}^{2})}^{1/2}>\mathrm{test1}$

where ${\beta}_{i}^{n}$ denotes the value of the enthalpy at the n-th iteration at the i-th Gauss point.

#### 3.5.3 Operand ITER_GLOB_MAXI

```text
◊    ITER_GLOB_MAXI =    / 10
/ iterl
```

The algorithm continues the external iterations as long as the number of external iterations is less than iterl.

### 3.6 Keyword SOLVEUR

```text
◊    SOLVEUR =
```

This factor keyword is optional: it makes it possible to choose another solver for the solution of the system.

This operand is common to the whole set of global commands [U4.50.01](doc:u4.50.01).

### 3.7 Operand TITRE

```text
◊    TITRE = titre
```

Title which one wants to give to the result stored in temp, a data structure of type evol_ther [U4.03.01](doc:u4.03.01).

## 4 Modelling

Non-linear thermal problems in a moving reference frame and under the stationarity condition can be treated with models using the 3D or 2D plane finite elements described in the documents [U3.23.01](doc:u3.23.01) and [U3.24.01](doc:u3.24.01).

## 5 Examples

The main commands used to perform a non-linear thermal analysis in a moving reference frame and under the stationarity condition are presented below.

```text
conduc    =    DEFI_FONCTION    (    NOM_PARA    =    'TEMP',
VALE        =    ... )

enthal    =    DEFI_FONCTION    (    NOM_PARA    =    'TEMP',
VALE        =    ... )

mat        =    DEFI_MATERIAU (    THER_NL=    _F(    LAMBDA    =    conduc,
BETA    =    enthal ),)

...

chavi    =    CREA_CHAMP (    MAILLAGE    =    mail, TYPE_CHAM='NOEU_DEPL_R',
AFFE        = _F(    TOUT    =    'OUI',
NOM_CMP    =    ('DX','DY'),
VALE_R        =    (1.0 , 0.0) )

char    =    AFFE_CHAR_THER (    MODELE        =    model,
FLUX_REP    =_F(    GROUP_MA    =    sou,
FLUN        =    5.E6 ),
CONVECTION=_F(    VITESSE    =    chavi ) )

tempe    =    THER_NON_LINE_MO (    MODELE            =    model,
CHAM_MATER    =    chmat,
EXCIT            =_F(CHARGE    =    char ),
)

...
```
