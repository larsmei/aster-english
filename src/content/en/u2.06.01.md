# u2.06.01 Carrying out an eigenmode analysis of a structure

**Summary**

This document presents an overall view of the various approaches available in *Code_Aster* for computing the vibration eigenmodes of a mechanical structure. These approaches are described starting from the simplest to implement, for standard studies, and going progressively towards more elaborate implementations for advanced studies.

The necessary sequences of the *Code_Aster* operators are presented, without going into the detail of each operator.

## 1 Reminders: formulation of the problem

One considers a mechanical structure represented, within the framework of a finite-element modelling, by its stiffness matrix $K$, mass matrix $M$ and possibly damping matrix $C$. The equation governing the evolution of the structure is written $M\ddot{x}+C\dot{x}+Kx=0$.

One wants to characterise the free vibrations of the mechanical structure, defined by eigenfrequencies ${f}_{i}=\frac{{\omega}_{i}}{2\pi }$ (${\omega}_{i}$: natural angular frequency of mode no. $i$) and the associated mode shapes ${x}_{i}$ (and the modal dampings ${\zeta}_{i}$ if the model contains damping).

In the absence of damping (the simplest and most frequent case), the modal analysis consists in finding the pairs $\left\lbrace {\omega}_{i},{x}_{i}\right\rbrace$ such that $(K-{\omega}_{i}^{2}M){x}_{i}=0$.

## 2 Data setup of the problem

The data setup for an analysis of vibration eigenmodes is classical and common to most mechanical analyses in *Code_Aster*:

- reading of the mesh (operator LIRE_MAILLAGE),
- assignment of the model characteristics: a beam-type or 3D or …? model (AFFE_MODELE),
- definition and assignment of the materials (DEFI_MATERIAU and AFFE_MATERIAU) and/or assignment of the characteristics of the structural elements (AFFE_CARA_ELEM),
- possible imposition of boundary conditions (stage absent if the structure is completely free). The particularity of the modal analysis in *Code_Aster* at present is that, in general, the displacement boundary conditions, if there are any, must be imposed by dualisation (AFFE_CHAR_MECA, factor keyword DDL_IMPO – the most common – or FACE_IMPO or ARETE_IMPO) rather than by kinematic loads (AFFE_CHAR_CINE).

## 3 Analysis of the vibration eigenmodes of a structure

From the input data seen in the previous paragraph, the various possibilities offered by *Code_Aster* for computing the eigenmodes of a structure are presented here, going from the simplest to implement to more complicated sequences.

### 3.1 The simplest studies

For simple studies (one considers here a structure modelled without damping, without prestress, without fluid–structure interaction, without gyroscopy, without mixed modelling (i.e. all the finite elements are of the same dimension: volume, or else surface, or else line)), the most ergonomic solution is to use the modal analysis wizard available in the Aster module of the Salomé-Méca software.

![Figure](/figures/u2.06.01/10000000000006900000041A548F590FDE677EFE.png)

Figure 3.1-a: Location of the modal analysis wizard in Salomé-Méca.

The wizard simply asks the user to supply the mesh, to enter the data on the materials and any boundary conditions. And finally the eigenmode search criterion (for example: the first N modes? or the modes over a given frequency band? or the modes around a target frequency?).

The wizard then automatically generates the *Code_Aster* command file, visible in the tree of the study, which the user can open and edit (with the Eficas graphical interface or a text editor) if, for example, the user wishes to modify certain parameters or options.

Finally, execution of the analysis automatically generates a message file (extension .mess) containing the detail of all the analyses, as well as a result file (in MED format) containing the eigenmodes. One can open this file in the ParaViS module in order to visualise the deformed shapes (paragraph 5.1).

### 3.2 More advanced features

#### 3.2.1 Sequence of the Code_Aster commands

From the input data, one proceeds as follows:

- computation of the assembled matrices (operator ASSEMBLAGE with the options 'RIGI_MECA' and 'MASS_MECA'; other options exist for computing more specific matrices, for example the geometric stiffness, the damping, the gyroscopy, etc.);
- computation of the eigenmodes: operator CALC_MODES, with the keyword OPTION and the factor keyword CALC_FREQ used to specify the search criterion.

OPTION='BANDE' or 'PLUS_PETITE' or 'CENTRE' or 'TOUT' is to be preferred for its CPU performance if one is seeking a relatively large number of modes (up to 50 to 80; beyond that, it is recommended to split the search into several sub-bands, cf. paragraph 3.2.4.1), in particular with the search option on a given band (OPTION='BANDE') for better robustness.

On the contrary, OPTION='PROCHE' or 'SEPARE' or 'AJUSTE', which is more costly, is rather to be used to compute a few modes with a very good quality, for example if one wants to refine first estimates of eigenmodes (cf. paragraph 3.2.3).

As a first step, it is advisable to leave the default parameters of these operators, and to specify only the search criterion for the eigenfrequencies (by default, the first 10 modes).

![Figure](/figures/u2.06.01/Object_2.png)

**Figure** 3.2-a **: Computation of the modes by way of the assembled matrices.**

**Example:**

computation of the eigenmodes over the band $[\mathrm{20 };300]\mathit{Hz}$:

ASSEMBLAGE( MODELE = modele,

CHAM_MATER = ch_mat,

CARA_ELEM = cara_el,

CHARGE = c_limite,

NUME_DDL = CO("numerota"), # creation of a numbering of the

# degrees of freedom

MATR_MASS = matr_m,

OPTION = 'BANDE',

CALC_FREQ =_F( FREQ = (20., 300.) )

)

#### 3.2.2 Usefulness of an intermediate computation of the assembled matrices: a few examples

##### 3.2.2.1 Prior counting of the eigenfrequencies

Before the analysis proper of the eigenmodes, it is strongly recommended to carry out a count of the eigenmodes contained in one or more given frequency bands (in the standard case of real modes; if the modes to be computed are complex, it will be a count around a point of the complex plane). This count is much faster than the analysis proper of the eigenmodes.

A priori knowledge of the number of eigenfrequencies contained in the search band has a twofold usefulness, of verification and of optimisation of the CPU performance of the modal analysis:

- verification: one can check that the number of eigenmodes computed by the modal solver is indeed equal to the number of eigenmodes counted *a priori*;
- CPU optimisation: if the number of eigenfrequencies counted over the search frequency band is too high (a threshold lying between 50 and 80 is commonly observed), the user will be able to split the search band into several sub-bands, by means of the operator CALC_MODES with the option 'BANDE' split into sub-bands (cf. paragraph 3.2.4.1).

The counting of the eigenmodes is carried out by the operator INFO_MODE. As a first approach, the user can simply supply:

- in the standard case of real modes: the matrices of the structure with the keywords MATR_* as well as its search band(s) with the keyword FREQ;
- in the case of complex modes (structures with damping, for example): one must specify TYPE_MODE='COMPLEXE' and supply the search disc in the complex plane by RAYON_CONTOUR (and possibly CENTRE_CONTOUR) in place of FREQ.

##### 3.2.2.2 Structures with hysteretic damping

One must explicitly compute the assembled total stiffness matrix including the hysteretic contribution (complex matrix).

The sequence of the operators is as follows:

- computation of the assembled hysteretic stiffness matrix (computed from the elastic stiffness matrix) and of the mass matrix (ASSEMBLAGE with the options 'RIGI_MECA_HYST' and 'MASS_MECA' respectively);
- modal analysis with, as input, the hysteretic stiffness matrix (complex) and the mass matrix (CALC_MODES).

One will refer to the documentation [U2.06.03](doc:u2.06.03) for more information on taking hysteretic damping into account in *Code_Aster*.

##### 3.2.2.3 Taking prestresses into account

Taking prestresses into account (non-zero boundary conditions, static external loadings, ...) requires the assembled mechanical and geometric stiffness matrices to be computed. One can then combine them to form the assembled total stiffness matrix, which is the one used for the modal analysis.

The sequence of the operators is as follows, in a relatively simple case of static external loading:

- definition of the external loading (operator AFFE_CHAR_MECA, with for example the keyword FORCE_NODALE),
- computation of the stress field associated with this loading (operator MECA_STATIQUE or STAT_NON_LINE or MACRO_ELAS_MULT to compute the static response, then CREA_CHAMP with the keyword OPERATION='EXTR' to recover the stress field),
- computation of the assembled matrices of mechanical stiffness, geometric stiffness associated with the stress field, and mass (ASSEMBLAGE),
- combination of the mechanical stiffness and geometric stiffness matrices to form the total stiffness matrix (COMB_MATR_ASSE),
- modal analysis with, as input, the total stiffness matrix and the mass matrix (CALC_MODES).

**Example:**

The test case SDLL101 presents an example of an analysis of the modes of a beam subjected to static forces.

##### 3.2.2.4 Taking gyroscopy into account (rotating machines)

In addition to the other assembled matrices (stiffness, mass and possibly damping other than gyroscopic), one must compute the gyroscopic damping matrix with the option 'MECA_GYRO'. The operator CALC_MODE_ROTATION then makes it possible to compute the eigenmodes of the structure for various rotational speeds defined by the user under the keyword VITE_ROTA.

One can then plot the Campbell diagram (evolution of the eigenfrequencies as a function of the rotational speed) of the rotating structure by means of the operator IMPR_DIAG_CAMPBELL.

**Note:**

*The operator* CALC_MODE_ROTATION is in reality a macro-command calling CALC_MODES: if need be, the user can therefore carry out the various elementary stages of CALC_MODE_ROTATION “by hand”, but in a much less ergonomic manner*. The test case SDLL129 illustrates the procedure in the case of a rotor with bearings whose characteristics depend on the rotational speed.*

##### 3.2.2.5 Use of the modes for a dynamic analysis on a modal basis

Here too one must have access to the assembled matrices: their projection onto a modal basis supplies the generalised matrices usable for a dynamic analysis, with CPU performance much better than the direct use of the assembled matrices. This model-reduction method is described in the reference documentation [R5.06.01](doc:r5.06.01) and the user's documentation [U2.06.04](doc:u2.06.04).

#### 3.2.3 Improving the quality of the eigenmodes

Attention is drawn to the fact that **the quality of a modal analysis depends above all on the quality of the input data and of the physical modelling**. One may in particular mention:

- the choice of the boundary conditions: are they representative of reality? Their influence on the result of the analysis is strong;
- the fineness of the mesh: a mesh-convergence study is necessary, as for any numerical study;
- the choice of the modelling: by structural elements (beam, shell, …) or in 3D? For example, for a slender structure, a beam modelling will generally be better than a 3D modelling even with a good mesh fineness.

If the input data and the modelling are fixed, it is possible to improve the “computational” quality of the result by means of the keyword AMELIORATION='OUI', which automatically carries out a chaining of two modal analyses: the first, which gives a first estimate of the eigenmodes (eigenfrequencies, mode shapes, …) with the search criterion requested by the user (for example with CALC_FREQ / OPTION='BANDE' or 'PLUS_PETITE', which use the subspace method), the second by the inverse iteration method (CALC_FREQ / OPTION='PROCHE'), which refines the estimate of the previous analysis.

Note 1: The first estimate is generally already good and satisfactory. For more complicated models, it is nevertheless advisable to carry out this improvement.

Note 2: this automatic feature is limited to the cases where the structure is represented by real symmetric matrices, and does not comprise multiple modes or several rigid-body modes. For the other cases, or if for example one wants to improve only certain modes among all those computed, one can of course carry out the sequence of the analyses manually.

The sequence of the commands is then as follows:

#### 3.2.4 Optimisation of the CPU performance

##### 3.2.4.1 Splitting of the search frequency band

If one is seeking many eigenmodes (either because the search band is very wide, or because the modal density is high), the performance of the modal analysis will be better by splitting the global search band $\left[{f}_{min};{f}_{max}\right]$ into several ($n$) sub-bands: $\left[{f}_{min};{f}_{2}\right]$, $\left[{f}_{2};{f}_{3}\right]$, …, $\left[{f}_{n};{f}_{max}\right]$. This is done by means of the operator CALC_MODES with the option 'BANDE' and by specifying the frequency splitting with the keyword FREQ=(fmin,f2,...,fn,fmax). In order to define the sub-bands, the user can rely on the *a priori* count of the eigenfrequencies supplied by the operator INFO_MODE, which can itself also operate by sub-bands.

![Figure](/figures/u2.06.01/Object_22.png)

**Figure** 3.2-c **: Computation of the eigenmodes by splitting into sub-bands.**

**Example:**

identical to paragraph 3.2.1, splitting the band $[\mathrm{20 };300]\mathit{Hz}$ into three sub-bands:

ASSEMBLAGE( MODELE = modele,

CHAM_MATER = ch_mat,

CARA_ELEM = cara_el,

CHARGE = c_limite,

NUME_DDL = CO("numerota"), # creation of a numbering of the

# degrees of freedom

MATR_ASSE =(

_F( MATRICE= CO("matr_k"), OPTION= 'RIGI_MECA'),

_F( MATRICE= CO("matr_m"), OPTION= 'MASS_MECA'),

)

);

nb_modes = INFO_MODE( MATR_RIGI = matr_k,

MATR_MASS = matr_m,

FREQ = (20.,300.),

);

modes = CALC_MODES( MATR_RIGI = matr_k,

MATR_MASS = matr_m,

CALC_FREQ =_F( FREQ = (20., 100., 200., 300.) )

);

**Notes:**

- *There is a gain in CPU performance even when the sub-bands are treated sequentially (which is the case by default). The implementation of parallelism (cf. the following paragraph) makes it possible to improve the performance still further.*
- *For optimum performance, it is advisable to have sub-bands that are as balanced as possible (that is, with a number of modes sought per sub-band that is relatively uniform).*

##### 3.2.4.2 Parallelism

For the modal analysis, parallelism can be implemented at two levels:

- parallelisation of the modal analyses carried out on each sub-band, in the operators INFO_MODE and CALC_MODES with the option 'BANDE' split into several sub-bands;
- parallelism at the level of the linear solver MUMPS, in the operator CALC_MODES when it is used with OPTION='BANDE' or 'PLUS_PETITE' or 'CENTRE' or 'TOUT'.

In order to implement parallelism, one must:

- have a version of *Code_Aster* built with a parallel compiler (for example: OpenMPI, …). On the centralised Aster4 server, parallel versions already exist: STAxx_impi;
- select in ASTK a parallel version of *Code_Aster*;

![Figure](/figures/u2.06.01/10000000000003B300000227E0B3B9A25E75524C.png)

**Figure** 3.2-d **: Selection in ASTK of a parallel version of** *Code_Aster* **(example on the centralised Aster4 server).**

- specify in ASTK the number of processors and of compute nodes to be used; one must use at least as many processors as there are non-empty frequency sub-bands, and it is advisable to use a number of processors that is a multiple of the number of non-empty sub-bands (for example: if there are 5 non-empty sub-bands, use 10 or 15 or … processors);

![Figure](/figures/u2.06.01/10000201000003B2000002265BA099DF6866EF29.png)

**Figure** 3.2-e **: Declaration in ASTK of the number of processors and compute nodes to be used.**

- In the *Code_Aster* command file:
- in order to use the basic mode (parallelisation of the sub-bands only) with INFO_MODE or CALC_MODES with the option 'BANDE' split into several sub-bands, there is nothing to do: the default keywords activate the parallelisation of the sub-bands;
- in order to use the advanced mode (parallelisation of the sub-bands for INFO_MODE and CALC_MODES with the option 'BANDE' split into several sub-bands, and of the linear solver for all the modal operators): use the linear solver MUMPS (factor keyword SOLVEUR, operand METHODE='MUMPS'; it is also recommended to set the operands RENUM='QAMD' and GESTION_MEMOIRE='IN_CORE').

**Example:**

identical to paragraph 3.2.4.1, parallelising both the analyses on the sub-bands and the linear solver:

modes = CALC_MODES( MATR_RIGI = matr_k,

MATR_MASS = matr_m,

![Figure](/figures/u2.06.01/Shape6.gif)

CALC_FREQ =_F( FREQ = (20., 100., 200., 300.) ),

NIVEAU_PARALLELISME = 'COMPLET',

SOLVEUR =_F( METHODE = 'MUMPS',

RENUM = 'QAMD',

GESTION_MEMOIRE = 'IN_CORE' ),

);

**Note:**

*For optimum performance, it is advisable to have sub-bands that are as balanced as possible (i.e.: with a number of modes sought per sub-band that is relatively uniform).*

The implementation of parallelism is presented in more detail in the generic documentation [U2.08.06](doc:u2.08.06) and the user's guides of INFO_MODE [U4.52.01](doc:u4.52.01) and of CALC_MODES with the option 'BANDE' split into several sub-bands [U4.52.02](doc:u4.52.02).

##### 3.2.4.3 Model reduction: analysis by substructuring

When the numerical model comprises a high number of degrees of freedom or when the structure studied is an assembly of components meshed separately, one can use model-reduction methods by substructuring, which rely on a geometric partitioning of the global structure. On large models, these methods present better CPU performance than a direct analysis.

- Dynamic substructuring

This method has a very general field of application. The documentation [U2.07.05](doc:u2.07.05) details its implementation.

- Cyclic substructuring

This method has a much more restrictive field of application than the previous one: it makes it possible to treat only structures with cyclic repetitivity (for example: a bladed wheel, …). The test case SDLV301 gives an example of implementation.

## 5 Post-processing of the eigenmodes

### 5.1 Visualisation

The mode shapes computed by one of the methods described previously can be exported in various formats in order to be visualised in mechanical-analysis platforms: MED format for the Salomé platform, UNV format, …

The user can thus characterise graphically the modes computed: bending mode? mode in a given plane? local mode? etc.

**Example:**

printout in MED format.

```text
modes = CALC_MODES (...) # calcul modal
```

```text

           RESU=_F( RESULTAT = modes ) )
```

One can then open the file created in the Salomé platform in order to visualise the mode shape, animate it, …

### 5.2 Normalisation of the modes

The mode shapes are defined up to a multiplicative factor (cf. formulation of the modal problem in paragraph 1).

By default, the modes computed by the operator CALC_MODES are normalised so that the largest physical component is equal to 1. The user can modify this normalisation, either directly in the operator CALC_MODES by means of the factor keyword NORM_MODE, or later by means of the operator NORM_MODE [U4.52.11](doc:u4.52.11). In both cases, the code also computes or updates the following modal parameters, which depend on the normalisation chosen: FACT_PARTICI_D*, MASS_GENE and RIGI_GENE. It also enriches the data structure with the parameters MASS_EFFE_UN_D* and INER_EFFE_UN_D* (which are themselves independent of the normalisation). These parameters (defined in paragraph 4) can be useful in particular for eliminating from a modal basis certain unwanted modes (cf. paragraph 5.3).

**Example:**

normalisation with respect to the mass.

First possibility:

```text
modes = CALC_MODES( MATR_RIGI = matr_k,
                    MATR_MASS = matr_m,
                    OPTION = 'BANDE',
                    CALC_FREQ =_F( FREQ = (20., 300.) ),
                                   NORM_MODE =_F( NORME = 'MASS_GENE' )
)
```

Second possibility:

```text
modes = CALC_MODES( MATR_RIGI = matr_k,
                    MATR_MASS = matr_m,
                    OPTION = 'BANDE',
                    CALC_FREQ =_F( FREQ = (20., 300.) ),
)
```

```text
modes = NORM_MODE( reuse = modes,
                   MODE = modes,
                   NORME = 'MASS_GENE' )
```

### 5.3 Filtering of the modes according to a criterion

With a view to a transient-response analysis, for example, the user can choose to keep in the projection modal basis only certain modes judged important in the dynamic response or fulfilling a given criterion. This can be done either directly in CALC_MODES with the factor keywords FILTRE_MODE and IMPRESSION, or by means of the operator EXTR_MODE [U4.52.12](doc:u4.52.12). One can thus filter the modes according to various options: from their number in the global spectrum, from their generalised mass, etc.

**Example 1:** elimination of the modes whose unit effective mass is lower than 5%, and display in the RESULTAT file of the cumulation of the unit effective masses of the modes retained.

First possibility:

```text
modes = CALC_MODES( MATR_RIGI = matr_k,
                    MATR_MASS = matr_m,
                    OPTION = 'BANDE',
                    CALC_FREQ =_F( FREQ = (20., 300.) ),
                    NORM_MODE =_F( NORME = 'MASS_GENE' ),
                    FILTRE_MODE =_F( CRIT_EXTR = 'MASS_EFFE_UN',
                                     SEUIL = 0.05 ),
                    IMPRESSION =_F( CRIT_EXTR = 'MASS_EFFE_UN',
                                    CUMUL = 'OUI'),
)
```

Second possibility:

```text
modes = CALC_MODES( MATR_RIGI = matr_k,
                    MATR_MASS = matr_m,
                    OPTION = 'BANDE',
                    CALC_FREQ =_F( FREQ = (20., 300.) ),
                    NORM_MODE =_F( NORME = 'MASS_GENE' ),
)
```

```text
modes_f = EXTR_MODE( FILTRE_MODE =_F( MODE = modes,
                                      CRIT_EXTR = 'MASS_EFFE_UN',
                                      SEUIL = 0.05 ),
                     IMPRESSION =_F( CRIT_EXTR = 'MASS_EFFE_UN',
                                     CUMUL = 'OUI'),
);
```

**Example 2:** elimination of the modes whose unit effective rotational inertia is lower than 5%, and display in the RESULTAT file of the cumulation of the unit effective masses of the modes retained.

First possibility:

```text
modes = CALC_MODES( MATR_RIGI = matr_k,
                    MATR_MASS = matr_m,
                    OPTION = 'BANDE',

                    NORM_MODE =_F( NORME = 'MASS_GENE' ),
                    FILTRE_MODE =_F( CRIT_EXTR = 'INER_EFFE_UN',
                                     SEUIL = 0.05 ),
                    IMPRESSION =_F( CRIT_EXTR = 'INER_EFFE_UN',
                                    CUMUL = 'OUI'),
)
```

Second possibility:

```text
modes = CALC_MODES( MATR_RIGI = matr_k,
                    MATR_MASS = matr_m,
                    OPTION = 'BANDE',
                    CALC_FREQ =_F( FREQ = (20., 300.) ),
                    NORM_MODE =_F( NORME = 'MASS_GENE' ),
)
```

```text
modes_f = EXTR_MODE( FILTRE_MODE =_F( MODE = modes,
                                      CRIT_EXTR = 'INER_EFFE_UN',

                     IMPRESSION =_F( CRIT_EXTR = 'INER_EFFE_UN',

```

**Note:**

- *The operator* *EXTR_MODE makes it possible to filter with a threshold applied to one or more given directions (keyword* *SEUIL_X for example for the direction DX), which is not possible directly in* *CALC_MODES at present.*

### 5.4 Filtering of the modes according to a "local" criterion

It is sometimes necessary to be able to filter the modes with respect to a criterion computed on the basis of only part of the model.
For this one has the operator POST_MODE.

**Example:** selection of modes on the basis of a local unit effective-mass criterion

One computes (in an approximate manner) the effective mass and inertia criteria, unit and non-unit, on the desired part of the model:

```text
table_crit = POST_MODE( MODE=modes,
                        GROUP_MA=("BATIMENT2",),
                        CARA_ELEM=caraelem,
                        MATR_MASS=masse,
)
```

One modifies the table created by filtering on the chosen criterion, here local unit effective masses along X greater than 5%:

```text
table_crit = CALC_TABLE(reuse=table_crit,
                        TABLE=table_crit,
                        ACTION=_F(OPERATION="FILTRE",
                                  NOM_PARA="MASS_EFFE_UN_DX", CRIT_COMP="GT", VALE=0.05),
)
```

One can then recover the list of the selected modes and build a **mode_meca** object containing only these modes.

Retrieval of the list of the numbers of the selected modes:

```text
liste_modes = table_crit.EXTR_TABLE().values()["NUME_MODE"]
```

Extraction of the selected modes:

```text
EXTR = EXTR_MODE(FILTRE_MODE=_F(MODE=modes, NUME_MODE=liste_modes))
```
