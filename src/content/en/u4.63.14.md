# u4.63.14 Operator PROJ_SPEC_BASE

## 1 Purpose

Project one or more turbulence spectra onto one (or more) modal basis (bases). The spectra are defined by the operator DEFI_SPEC_TURB [U4.44.31](doc:u4.44.31). The modal basis (or bases) may be defined by:

- a concept of type melasflu produced by the operator CALC_FLUI_STRU [U4.66.02](doc:u4.66.02),
- a concept of type mode_meca produced by the operator CALC_MODES [U4.52.02](doc:u4.52.02),
- a list of concepts of type cham_no_depl_r corresponding to the mode shapes.

Makes it possible to compute, for each modal basis defined, an interspectral matrix of generalised excitations. An option makes it possible, where applicable, to compute only the auto-spectra.

The concept produced is of type interspectre.

## 2 Syntax

```text
interspectre = PROJ_SPEC_BASE(
    ◆ SPEC_TURB = spectre,
    ◇ TOUT_CMP = / "OUI" (par défaut),
                 / "NON",
    ◆ / BASE_ELAS_FLUI = melasflu,
      / MODE_MECA = mode_meca,
      / CHAM_NO = cham_no,
    # Si: exists("BASE_ELAS_FLUI")
        ◆ VITE_FLUI = float,
        ◇ PRECISION = float (défaut: 0.001),
    ◆ FREQ_INIT = float,
    ◆ FREQ_FIN = float,
    ◆ NB_POIN = int,
    ◇ OPTION = / "TOUT" (par défaut),
               / "DIAG",
    ◆ / TOUT = "OUI" (ou non renseigné),
      / GROUP_MA = grma,
    ◇ & MODELE_INTERFACE = modele,
    ◇ VECT_X = float,
    ◇ VECT_Y = float,
    ◇ ORIG_AXE = float,
    ◇ TITRE = text,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Operand SPEC_TURB

```text
♦    SPEC_TURB= l_spec
```

List of concepts of type spectre produced by the operator DEFI_SPEC_TURB [U4.44.31](doc:u4.44.31) defining several turbulent excitation spectra.

**Notes:**

1. *The operand* *SPEC_TURB makes it possible to take into account several turbulent excitation spectra. The interspectra of generalised excitations are computed for each of the physical spectra supplied and are then added.*
2. *Turbulence spectra of "correlation length" type apply only to the tubes of steam generators. It is possible to project several turbulence spectra of "correlation length" type simultaneously, but the excitation zones of each spectrum must be strictly disjoint from one another. The zones over which these excitations apply are defined for each spectrum, with the command* *DEFI_SPEC_TURB* [U4.44.31](doc:u4.44.31).
3. *Turbulence spectra of "correlation length" type cannot be combined with spectra of another type.*
4. *In the case of a spectrum of type* SPEC_CORR_CONV_3 *, the double projection is very resource-intensive, because one must loop over the directions, the mesh cells, their Gauss points and the modes (double loop), and each time evaluate the analytical function which defined the spectrum. It is advisable to use this type of spectrum on reduced meshes (fewer than 1000 degrees of freedom), starting with a small number of frequency-discretisation points in order to assess the analysis time.*

### 3.2 Operand BASE_ELAS_FLUI

The operand BASE_ELAS_FLUI is used when one wishes to carry out the projection of a spectrum defined by one of the factor keywords SPEC_LONG_COR_n, SPEC_FONC_FORME or SPEC_EXCI_POINT of the operator DEFI_SPEC_TURB [U4.44.31](doc:u4.44.31). In this case, one must supply the fluid velocity vitefl.

```text
♦    /    BASE_ELAS_FLUI= baseflui
```

Concept of type melasflu produced by the operator CALC_FLUI_STRU [U4.66.02](doc:u4.66.02), which defines one modal basis or a set of modal bases onto which the spectra are projected, as well as the discretisation in velocity.

The operator computes an interspectral matrix of generalised excitations ${S}_{\mathrm{fifj}}^{k}(\omega )$ corresponding to the fluid velocity vitefl which one must supply.

The concept melasflu also supplies the name of the concept type_flui_stru produced at the beginning of the study by the command DEFI_FLUI_STRU [U4.25.01](doc:u4.25.01). The concept type_flui_stru contains all the information characteristic of the configuration studied: one finds there, among other things, the data necessary for the dimensionalisation of the projected excitation.

### 3.3 Keyword VITE_FLUI

The operand VITE_FLUI must be supplied if one uses a basis of type melasflu.

♦    VITE_FLUI = vitefl

Fluid flow velocity for the response analysis.

### 3.4 Keyword PRECISION

◊    PRECISION = prec

Precision on the fluid flow velocity (by default 1.E-3).

### 3.5 Operands MODE_MECA or CHAM_NO

The operands MODE_MECA or CHAM_NO are used when one wishes to carry out the projection of a pressure spectrum defined by one of the factor keywords SPEC_CORR_CONV_n of the operator DEFI_SPEC_TURB [U4.44.31](doc:u4.44.31).

```text
/    MODE_MECA= basemeca
```

Concept of type mode_meca produced by the operator CALC_MODES [U4.52.02](doc:u4.52.02), which defines the modal basis onto which the spectra are projected. This modal basis may have been computed taking into account an added fluid-mass effect, by recourse to the operator CALC_MATR_AJOU [U4.66.01](doc:u4.66.01) or MACRO_MATR_AJOU [U4.66.11](doc:u4.66.11).

```text
/    CHAM_NO= l_cham
```

List of concepts of type cham_no_depl_r, which define the mode shapes of the modal basis onto which the spectra are projected.

This way of defining the modal basis makes it possible to impose on the structure a particular type of motion; a similar approach is adopted in the operator CALC_MATR_AJOU [U4.66.01](doc:u4.66.01), where the operand CHAM_NO also appears.

**Note:**

| *The operator determines the mutual-acceptance matrix relating the pressure spectrum to the interspectral matrix of generalised excitations acting on the structure:* ${S}_{\mathit{fifj}}(\omega )={S}_{p}(\omega )\times {J}_{\mathit{Aij}}(\omega )$ *where* * ${S}_{p}(\omega )$ *is the pressure power spectral density,* * ${J}_{\mathit{Aij}}(\omega )$ *is the mutual-acceptance matrix,* * ${S}_{\mathit{fifj}}(\omega )$ *is the matrix of interspectra of generalised excitations.* |
| --- |

**Note:**

| *In the case where the modal basis is defined by a list of fields at the nodes (keyword* *CHAM_NO* *), it is imperative to supply the mechanical model associated with the elements on which the projection of the spectrum must be applied (by the keyword* *MODELE_INTERFACE* *).**If a modal basis of type* *mode_meca* *is given and if* *the structure is modelled with thin shells of type* *DKT* *,* *it is not mandatory to supply the keyword* *MODELE_INTERFACE* *.* |
| --- |

The theoretical details are given in the internal report HP-51/97/027/B.

### 3.6 Operand MODELE_INTERFACE

The operand MODELE_INTERFACE is used when one wishes to carry out the projection of a pressure spectrum defined by one of the factor keywords SPEC_CORR_CONV_n of the operator DEFI_SPEC_TURB [U4.44.31](doc:u4.44.31).

```text
◊    MODELE_INTERFACE= modele
```

Concept of type modele produced by the operator AFFE_MODELE [U4.41.01](doc:u4.41.01), defining:

1. Either the (thermal) interface model between the structure and the fluid used beforehand for the computation of the added matrices by CALC_MATR_AJOU [U4.66.01](doc:u4.66.01) or MACRO_MATR_AJOU [U4.66.11](doc:u4.66.11).
2. Or the mechanical model of the structure if the latter is modelled by thin shell elements (DKT).

**Note:**

*In the case where a thermal interface model is defined, the computation of the acceptance coefficients is carried out with the aid of this model, which characterises the wetted surface of the structure, under the assumption of a homogeneous turbulence over the whole fluid-structure interface.*

*In the case where the model given is mechanical, the acceptance coefficients may be computed on the structure, provided that the latter is modelled with thin shells of type* *DKT.*

*If the keyword* *MODELE_INTERFACE* *is not supplied, the mechanical model used is the one which is associated with the stiffness matrix, referenced in the modal projection basis.*

**Note:**

*In the case where the spectrum has been defined analytically with the option* *SPEC_CORR_CONV_3, the interface model must mandatorily be supplied, because the projection is carried out using the shape functions carried by the elements of the model.*

### 3.7 Operand GROUP_MA / TOUT

The operand GROUP_MA is used when one wishes to carry out the projection of a pressure spectrum defined by one of the factor keywords SPEC_CORR_CONV_n of the operator DEFI_SPEC_TURB [U4.44.31](doc:u4.44.31).

```text
♦    GROUP_MA/TOUT
```

List of mesh-cell groups or the whole of the mesh, on which the projection will be carried out. The mesh-cell groups must belong to the mesh associated with the model (thermal or mechanical) used for the computation of the acceptance coefficients.

```text
◊    VECT_X= l_cmpx
```

List of three components of a unit vector $x$ defining:

- the direction of the flow on the surface of the plane structure, in the case of a CORCOS correlation,

### 3.11 Operands FREQ_INIT, FREQ_FIN and NB_POIN

```text
♦    FREQ_INIT= fi
♦    FREQ_FIN= ff
♦    NB_POIN= np
```

These operands define the frequency band and the number of frequency-discretisation points of the interspectra to be computed. The number of discretisation points must be equal to a power of 2, in order to allow post-processings of FFT type (Fast Fourier Transform). It is recommended to compute these three quantities according to the following method.

If $({f}_{1}^{k},\mathrm{...},{f}_{N}^{k})$ denote the frequencies of the modes of the $k$-th basis of the structure then:

$\text{FREQ\_INIT}=\underset{k}{\min}(\frac{{f}_{1}^{k}}{2})$ $\text{FREQ\_FIN}=\underset{k}{max}({f}_{N}^{k}+\frac{{f}_{1}^{k}}{2})$

The number of discretisation points can then be deduced from the minimum frequency step defined by:

$\mathit{df}=\underset{i,k}{min}(2\times \pi \times {\mu}_{i}^{k}\times {f}_{i}^{k})$

where ${\mu}_{i}^{k}$ denotes the reduced damping of the $i$-th mode of the $k$-th modal basis.

### 3.12 Operand TOUT_CMP

```text
◊    TOUT_CMP= ’OUI’ ou ’NON’
```

Indicator of the components of the modal mode shapes that one adopts in order to compute the excitation interspectra on a modal basis:

| ’OUI’ | one uses the three translational components, |
| --- | --- |
| ’NON’ | one uses only the translational component which was defined beforehand by means of the operator DEFI_FLUI_STRU. |

### 3.13 Operand OPTION

```text
◊    OPTION= ’TOUT’ ou ’DIAG’
```

Indicator of the choice of the computation to be carried out:

| ’TOUT’ | if one wishes to compute all the interspectra of generalised excitations (default option), |
| --- | --- |
| ’DIAG’ | if one wishes to compute only the auto-spectra of generalised excitations. |

### 3.14 Operand TITRE

```text
◊    TITRE= titre
```

Argument of text type defining the title attached to the output concept interspectre.
