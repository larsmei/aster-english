# v1.01.285 ZZZZ285 - PROJ_CHAMP Validation / Collocation

**Summary:**

This test is a computer test. It validates the PROJ_CHAMP METHODE='COLLOCATION' command for all types of mesh cells $\mathrm{2D}$ and $\mathrm{3D}$ , with straight or curved edges.

The implementation of a field projection to nodes by the 'COLLOCATION' method is also illustrated in the context of distributed parallelism.

There are 7 modellings ($A$ , $B$ , $C$ , $D$ , $E$ , $F$ , $G$ , $H$ ).

## 1 Purpose of the test

We want to validate the implementation of 'COLLOCATION' field projection method to nodes for all mesh cells $\mathrm{2D}$ and $\mathrm{3D}$ types with straight or curved edges.

The implementation of a field projection to nodes by the 'COLLOCATION' method is also illustrated in the context of distributed parallelism.

## 2 Test principle

### 2.1 modellings ($A$ , $B$ , $C$ , $D$ , $E$ , $F$ )

On mesh cell a square (in $\mathrm{2D}$) or a cube (in $\mathrm{3D}$) using straight-edge linear elements (TRIA3, QUAD4, HEXA8, PENTA6, TETRA4, PYRAM5). The square (or cube) is meshed twice with different discretizations. Let's call these 2 meshes MA1 and MA2.

The CREA_MAILLAGE command is used to transform these linear meshes into quadratic meshes ('LINE_QUAD').

The CREA_MAILLAGE command is also used to create mesh cells "QUAD+": QUAD9, HEXA27 and PENTA18.

For all types of mesh cells: TRIA, QUAD, ..., PYRAM linear meshes("LIN"), quadratic ("QUAD") or "QUAD+"

With the MODI_MAILLAGE / DEFORME command, MA1 and MA2 meshes can be deformed to make the elements edges curved.

A field is then created at nodes (CH1) which is "analytic" in form (application of a formula to the nodes coordinates of mesh MA1). Three different formulae can be used:

- a function refines the coordinates (noted ‘degree 1')
- a quadratic coordinate function (noted ‘degree 2')
- any function of the coordinates (noted "degree 2+" although fractional powers are actually used).

CH1 is then projected from MA1 to MA2. CH2 is obtained. This field is again projected from MA2 to MA1. CH1B is obtained.

CH1 and CH1B with the same support mesh, then the relative error caused by double projection can be calculated.

The "maximum" of the relative error on the mesh is then calculated (and tested).

Note: As the PROJ_CHAMP command is sometimes used between 2 meshes with the nodes geometrically confused (e.g. THM studies), this configuration (MA2 = MA1) is also tested to verify that the projection error is zero in this case.

### 2.2 Modelling ($G$ )

The test illustrates a first, sub-optimal way of performing a parallel projection but which is very simple to implement.
The test is run in parallel with 4 MPI processes. A field is built on a classic Mesh object and is therefore fully available on each MPI process (in other words, it is duplicated on each process and you can access all its nodes, mesh cells and groups). We want to project this field on another mesh, which is a ParallelMesh which is therefore distributed between processes (each knows only part of the ParallelMesh). By using the PROJ_CHAMP command conventionally, the projection is performed in parallel for each subdomain and a new distributed field is created.
For verification, the target field is built directly on the ParalleMesh and is checked for its similarity to the field from the projection.

### 2.3 Modelling ($H$ )

The test illustrates a second, also sub-optimal, way of performing a parallel and very simple projection of implementation.
The test is run in parallel on 4 MPI processes. A field is built on a ParallelMesh object. This field is projected on another mesh, which is also a ParallelMesh. Using keyword DISTRIBUTION from PROJ_CHAMP, an auxiliary mesh, called ConnectionMesh, is built which is duplicated on all processes. The projection is performed by each process on this ConnectionMesh and a new distributed field is created, consistent with the distribution of the mesh target.
For verification, the target field is built directly on the ParalleMesh and is checked for its similarity to the field from the projection.

## 3 reference solution

The reference solution is 0. Ideally, the projection error must be zero.

## 5 Summary of the results

When you project a mesh on itself, there is no projection error.

When the edges are straight and the fields are of the same degree as the elements, there is no projection error.

In the general case (different meshing and any field), the error may vary from 1.e-6 to 5.e-2 ($\text{5\%}$ ) if the edges are straight. When the edges are curved the error varies between 2.e-3 and 5.e-2. Thus, it is found that for the curved edges, even if they disturb the matching algorithm (in two steps, the first linearizing the mesh cells), the maximum error is no greater than for the straight edges (here $\text{5\%}$ ).

Finally, the verification of the parallel projection of projecting a field of an mesh on a distributed version of itself, there is no projection error.
