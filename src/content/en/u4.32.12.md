# u4.32.12 Macro-command CALC_SPECTRE_IPM

## 1 Purpose

This macro-command makes it possible to carry out a fast and efficient post-processing analysis in order to determine the floor spectra of any building after a seismic dynamic analysis, taking into account the interaction of the floor with the masses of the equipment (*cf.* document [R4.05.08](doc:r4.05.08)).

It may for example be used after a transient dynamic analysis of a building under earthquake loading, a transient dynamic analysis on a reduced modal basis, calculated in the relative reference frame, or else following a non-linear transient dynamic solution.

This macro-command executes successively:

1. the extraction of the relative acceleration at one or more nodes of the mesh in the result concept (RECU_FONCTION [U4.32.03](doc:u4.32.03));
2. the combination with the ground acceleration in order to obtain the absolute acceleration (CALC_FONCTION [U4.32.04](doc:u4.32.04));
3. calculation of the transfer function which takes into account the interaction of the floor and of the masses
4. the calculation of the acceleration response spectrum with several damping coefficients (CALC_FONCTION [U4.32.04](doc:u4.32.04));
5. the printout of the floor spectra.

For practical examples of implementation, the reader may refer to the test case sdld109 [V2.01.109](doc:v2.01.109).

The macro-command produces a concept of type table_sdaster.

## 2 Syntax

```text
table = CALC_SPECTRE_IPM(
    ◇ MAILLAGE = maillage,
    # Si: exists("MAILLAGE")
        ◆ EQUIPEMENT = _F(
             ◆ NOM = text,
             ◆ GROUP_NO = grno,
             ◆ RAPPORT_MASSE_TOTALE = float,
             ◆ COEF_MASS_EQUIP = float,
             ◆ FREQ_SUPPORT = float,
             ◆ AMOR_SUPPORT = float,
             ◆ AMOR_EQUIP = float,
             ◆ FREQ_EQUIP = float,
          ),
    # Si: not exists("MAILLAGE")
        ◆ EQUIPEMENT = _F(
             ◆ NOM = text,
             ◆ NOEUD = no,
             ◆ RAPPORT_MASSE_TOTALE = float,
             ◆ COEF_MASS_EQUIP = float,
             ◆ FREQ_SUPPORT = float,
             ◆ AMOR_SUPPORT = float,
             ◆ AMOR_EQUIP = float,
             ◆ FREQ_EQUIP = float,
          ),
    ◆ CALCUL = / "ABSOLU",
               / "RELATIF",
    ◆ AMOR_SPEC = float,
    ◇ LIST_INST = listr8,
    ◇ LIST_FREQ = listr8,
    ◇ FREQ = float,
    ◆ NORME = float,
    # Si: equal_to("CALCUL", 'RELATIF')
        ◆ RESU = _F(
             ◆ / TABLE = table,
               / FONCTION = fonction,
             ◆ ACCE_Z = fonction,
          ),
    # Si: equal_to("CALCUL", 'ABSOLU')
        ◆ RESU = _F(
             ◆ / TABLE = table,
               / FONCTION = fonction,
          ),
    ◇ TOLE_INIT = float (défaut: 0.001),
    ◇ CORR_INIT = / "OUI",
                  / "NON" (par défaut),
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

The classical post-processing of a seismic analysis in transient dynamics consists in carrying out the following calculations:

- The floor spectrum obtained from the absolute accelerations, for the direction $Z$ , calculated at a specified node of the mesh (for example in the case of a «stick» model);
- Three operators of *Code_Aster* can produce result concepts corresponding to transient dynamic analyses:
- DYNA_VIBRA [U4.53.03](doc:u4.53.03) produces a resu_gene concept, including the relative acceleration and displacement fields. In this case, the ground accelerations must be added in order to obtain the absolute accelerations, which are necessary for the calculation of the floor spectrum.
- CALC_MISS [U7.03.12](doc:u7.03.12) produces a dyna_trans concept, including the absolute acceleration and displacement fields. In this case, the accelerations are used directly for the calculation of the floor spectrum; conversely, subtraction of the ground displacements is mandatory (to be read with the command LIRE_FONCTION [U4.32.02](doc:u4.32.02) from a specific file given by its logical unit) in order to obtain the relative displacements.
- DYNA_NON_LINE [U4.53.01](doc:u4.53.01). The treatment is then the same as for the previous point.

Here is a schematic of the calculation algorithm of this macro-command:

*Loop #1 on the floors*

- *Recovery of the properties of the support and of the equipment*

*Loop #2 over the floor nodes*

> *•* *Recovery of the relative acceleration functions at the nodes:* RECU_FONCTION
> *•* *If relative calculation*

*Combination or not with the ground acceleration function:* *CALC_FONCTION/COMB*

> *•*     Calculation of the transfer function
> *•* *Calculation of the response spectrum, with specified values of frequencies and* *of damping with* *CALC_FONCTION/SPEC_OSCI*
> *•* *Printout of the acceleration spectrum for each node* *:* IMPR_FONCTION

*End of loop #2*

*End of loop #1*

Floor–mass interaction is taken into account by transforming the acceleration measured at node N by means of a transfer function. This transfer function converts the response of a model A into a model B, as illustrated in the figure below. Document R4.07.05 gives more complete explanations of the method and of the assumptions.

### 3.1 Keyword MAILLAGE

This keyword corresponds to the mesh read by the operator LIRE_MAILLAGE [U4.21.01](doc:u4.21.01).

This keyword is optional. Knowledge of the mesh is necessary only in the case where the user uses the simple keyword GROUP_NO of the factor keyword PLANCHER. Indeed, as described in the previous algorithm, the treatment is carried out on the nodes and, if the user gives directly the name of the nodes present in the table, the mesh is not necessary.

### 3.2 Keyword PLANCHER

This keyword is mandatory in order to define the names of the floors, where the spectra will be calculated. These names will be used to select or filter the display parameters in the table structure produced by the macro-command table_sdaster.

#### 3.2.1 Operand NOM

This mandatory operand makes it possible to name the floor considered.

#### 3.2.2 Operands NOEUD / GROUP_NO

These operands make it possible to define the nodes (individually or by groups) making up the floor where the spectra will be calculated. It is possible to supply GROUP_NO if the mesh has been supplied.

#### 3.2.3 Keyword RAP_MASS

This is the ratio of the masses of the equipment to the mass of the floor $\lambda =\frac{{m}_{2}}{{m}_{1}}$ . It lies between 0 and 1.

#### 3.2.4 Keyword RAP_MASS_COEFF

This is the list of the ratios of the individual masses ${\alpha}_{i}$ of each piece of equipment to the total mass of the equipment ${m}_{i}={\alpha}_{i}{m}_{2}$ . The sum of the coefficients must be equal to 1.

#### 3.2.5 Keyword FREQ_SUPP

This keyword defines the frequency of the support ${f}_{1}$ of model A.

#### 3.2.6 Keyword FREQ_EQUI

This keyword defines the list of the frequencies of the equipment. ${f}_{i}$ .

#### 3.2.7 Keyword AMOR_SUPP

This keyword defines the damping of the support ${\xi}_{1}$ .

#### 3.2.8 Keyword AMOR_EQUI

This keyword defines the list of the dampings of the equipment ${\xi}_{i}$ .

### 3.3 Keyword CALCUL

This mandatory keyword makes it possible to define the nature of the transient dynamic analysis used for the post-processing: in the absolute reference frame ('ABSOLU') or the relative reference frame ('RELATIF').

### 3.4 Operand AMOR_SPEC

This mandatory operand makes it possible to define the values of the reduced damping coefficient used in the calculation of the spectral response. See also CALC_FONCTION [U4.32.04](doc:u4.32.04), keyword SPEC_OSCI.

### 3.5 Operand LIST_INST

This optional operand makes it possible to specify the list, produced by DEFI_LIST_REEL [U4.34.01](doc:u4.34.01), defining all the time steps for the transient dynamic analysis.

### 3.6 Operand FREQ / LIST_FREQ

/ ◊      FREQ = L_FR

/ ◊      LIST_FREQ = LFREQ

List of frequencies previously defined by a listr8 concept.

This optional operand makes it possible to define the frequency values; see also CALC_FONCTION [U4.32.04](doc:u4.32.04), keyword SPEC_OSCI.

### 3.7 Operand NORME

♦    NORME = r

The response spectrum will be normalised by the value $r$ (pseudo-acceleration value). The analyses are carried out in most cases in units of the International System (USI) and the acceleration histories are often given in the unit $m/{s}^{2}$ . The response spectra are generally given with $g=\mathrm{9.81m}/{s}^{2}$ .

Thus, this mandatory operand NORME may be used as a unit-conversion factor between the calculated accelerations and the response spectrum; see also CALC_FONCTION [U4.32.04](doc:u4.32.04), keyword SPEC_OSCI.

### 3.8 Keyword RESU

This mandatory keyword makes it possible to specify the input data from which the nodal accelerations are extracted.

♦     / 'TABLE'        = TAB                [TABLE_SDASTER]

> / 'FONCTION'    = FCT                [FONCTION_SDASTER]

The post-processing is carried out from a table or from a function containing the results to be read. Typically, an observation table or function derived from a transient dynamic analysis.

The table supplied has two possible formats:

- Either it has (at least) the columns INST, NOEUD, NOM_CHAM, NOM_CMP and VALE. In this case, only the lines which have both the value ACCE in the column NOM_CHAM and the value DZ in the column NOM_CMP are taken into account. The analysis stops if the table does not contain such lines.
- Or it has (at least) the columns INST, NOEUD, NOM_CHAM and DZ. In this case, only the lines which have the value ACCE in the column NOM_CHAM are taken into account. The analysis stops if the table does not contain such lines.

#### 3.8.1 Keyword ACCE_Z

♦     ACCE_Z =     /AC_Z                [FONCTION]

In this case CALCUL ='RELATIF', the user must supply the ground-acceleration function, defined on the same list of time instants, in each spatial direction, in order to combine it with the relative accelerations so as to calculate the absolute accelerations.

### 3.9 Operand TOLE_INIT

◊     TOLE_INIT = 1e-3

This optional operand makes it possible to specify a limit criterion for the initial value of the initial accelerations of the signals. One checks that the ratio between the initial value of the signal and the maximum of the signal is less than the tolerance defined.

### 3.10 Operand CORR_INIT

◊     CORR_INIT =         /    'NON'        [DEFAUT]

> /    'OUI'

This optional operand makes it possible to correct the initial value of the signal if it is greater than the tolerance given.

## 4 Examples

The following example is taken from the test case sdld109 [V2.01.109](doc:v2.01.109):

tabl_spe = CALC_SPECTRE_IPM(MAILLAGE = MAILLAGE,

AMOR_SPEC = 0.05,

EQUIPEMENT =(_F(NOM='NOEUD2',

GROUP_NO='N02',

RAPPORT_MASSE_TOTALE = lbd,

COEF_MASS_EQUIP = (m2_1/m2,m2_2/m2,m2_3/m2),

FREQ_EQUIP = (f2_1,f2_2,f2_3),

FREQ_SUPPORT = f1,

AMOR_SUPPORT = amor_supp,

AMOR_EQUIP = (amor_equi,amor_equi,amor_equi)

),),

LIST_INST = L_INST,

CALCUL ='RELATIF',

LIST_FREQ = L_FREQ,

NORME = 1.,

RESU = (_F(TABLE = TAB,

ACCE_Z = ACCE,),),

)

In this test case, an input result obtained in the relative reference frame (single-support) is used; the entrainment signal, named here ACCE, must therefore be given.
