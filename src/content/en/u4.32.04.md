# u4.32.04 Operator CALC_FONCTION

## 1 Purpose

Carry out mathematical operations on data structures of type fonction.

The operator makes it possible to carry out general operations on functions (integration, derivative, absolute value, combination, polynomial regression…) and operations dedicated to signal processing and to the earthquake (calculation of the FFT, envelope smoothing, correction of accelerograms...).

Produces a data structure fonction, fonction_c or nappe, according to the factor keyword used.

On exit from the command, the function is reordered by increasing abscissae.

## 3 Operands

### 3.1 Factor keyword DERIVE

This keyword makes it possible to differentiate the function (with respect to its parameter) given by FONCTION.

It does not apply to concepts of type nappe.
The only method (given by METHODE) currently available is DIFF_CENTREE (by default).

**Note**

See keyword INTEGRE

### 3.2 Factor keyword INTEGRE

This keyword makes it possible to integrate the function (with respect to its parameter) given by FONCTION.

The constant of integration is given by COEF; by default it is 0.

It does not apply to concepts of type nappe.

Two methods (entered via METHODE) are available: the method of the 'TRAPEZE' (by default) and the 'SIMPSON' method.

The integral is exact for the piecewise-linear functions such as those supplied on input. The error committed with respect to the integral of the function which one has discretised is in $o(\frac{1}{{n}^{2}})$ for functions of class $\mathcal{C}^{2}$ .

Simpson's method is exact for polynomials of degree less than or equal to 3. The error is in $o(\frac{1}{{n}^{4}})$ for functions of class $\mathcal{C}^{4}$ .

For arbitrary functions, very irregular, such as accelerograms, it is recommended to use the trapezoidal method.

On the other hand, when the function (before discretisation) is sufficiently regular, Simpson's method is much more precise.

- For INTEGRE as for DERIVE, the NOM_PARA of the function produced is unchanged. On the other hand, the NOM_RESU may be modified in the following cases: for differentiation, DEPL becomes VITE, VITE becomes ACCE; for integration, ACCE becomes VITE, VITE becomes DEPL. The user always has the possibility of modifying it by the keyword of the same name NOM_RESU in the command.
- Concerning the prolongations, the function produced has, by default, EXCLU prolongations to the left and to the right, whatever those of the starting function may be. One should not therefore expect a linear prolongation to become constant in the differentiated function. Here again, the user is in control of the prolongations for the function produced, through the keywords PROL_DROITE and PROL_GAUCHE.

**Notes**

### 3.3 Factor keyword INVERSE

This keyword makes it possible to invert the function given by FONCTION.
It is necessary that the latter be bijective (strictly increasing or strictly decreasing).

It does not apply to concepts of type nappe.

- The labels of the parameters are not inverted! It is left to the user to assign the correct values through the keywords NOM_PARA and NOM_RESU. By default, the NOM_PARA is unchanged and NOM_RESU is assigned to TOUTRESU.
- The interpolation modes are swapped: for example (LIN, LOG) becomes (LOG,LIN).
- The prolongations EXCLU and LINEAIRE are unchanged. On the other hand, a CONSTANT prolongation is changed to EXCLU.

**Note**

### 3.4 Factor keyword ABS

This keyword makes it possible to create a function or a nappe containing the absolute value of a function or of a nappe given by FONCTION.

- The parameters (prolongations, interpolations, NOM_PARA and NOM_RESU) of the function produced are the same as those of the starting function.
- Except for the LINEAIRE prolongation, it is systematically changed to EXCLU as a precaution. Indeed, the linear prolongation to the right of a decreasing function leads, for sufficiently large abscissae, to negative values: the responsibility is therefore left to the user to assign PROL_DROITE=’LINEAIRE’ himself (and respectively for PROL_GAUCHE).

**Note**

### 3.5 Factor keyword ENVELOPPE

This keyword makes it possible to calculate the envelope of several functions.

This operation is available on operands of nature fonction or nappe.

The list of functions or nappes whose envelope one seeks is given by the keyword FONCTION.

The keyword CRITERE='SUP' seeks the **upper** envelope and the keyword CRITERE='INF' seeks the **lower** envelope.

- The functions must all be of the same nature (fonction or nappe)
- Case of simple functions: for the prolongations, interpolations, NOM_PARA and NOM_RESU, it is the parameters of the first of the functions in the list which are retained. The abscissa support of the envelope function will be the union of the lists of abscissae of all the functions.
- Case of nappes: the parameters (prolongations, interpolations, NOM_PARA, NOM_RESU and NOM_PARA_FONC) must necessarily be identical between the nappes supplied. The abscissa supports (values of the parameters and abscissae of the functions of the nappes) are homogenised so that the envelope can be calculated. The nappe produced will have this discretisation as abscissae.

**Notes**

### 3.6 Factor keyword FRACTILE

This keyword makes it possible to calculate the fractile of several functions.

This operation is available on operands of nature fonction or nappe.

The list of functions or nappes for which one seeks to calculate the fractile is given by FONCTION.

FRACT is the value of the quantile to be calculated. By default FRACT = 1; the fractile is then the upper envelope.

### 3.7 Factor keyword MOYENNE

This keyword makes it possible to calculate the mean of several functions given by FONCTION.

This operation is available on operands of nature fonction or nappe.

### 3.8 Factor keyword COHERENCE

This keyword makes it possible to calculate the coherence function of time signals.

The coherence function depends on the distance between two measurement points and on the frequency. It expresses the correlation between the two signals, measured at a distance $d$, as a function of the frequency. The complex coherence function is evaluated in the frequency domain, by way of the spectral densities (DSP). The operator returns the real part of the complex coherence, which corresponds to the **unlagged coherency** or to the **plane wave coherency** in the case of a plane wave.

The time signals must have the same discretisation (same time step ${dt}$ and same duration $T$ ). The user must supply two nappes which contain respectively the signals at stations 1 and 2, a distance $d$ apart. The signals in each nappe are parameterised by NUME_ORDRE (1,2,3,..) and then paired in order to calculate the coherences and to take their mean.

#### 3.8.1 Keywords NAPPE_1 and NAPPE_2

NAPPE_1 contains $N$ functions measured at station 1. The functions of the nappe must be numbered from 1 to $N$ by NOM_PARA = 'NUME_ORDRE'.

NAPPE_2 contains $N$ functions measured at station 2. The functions of the nappe must be numbered from 1 to $N$ by NOM_PARA = 'NUME_ORDRE'.

#### 3.8.2 Keyword FREQ_COUP

FREQ_COUP is the cut-off frequency for the plotting of the coherence functions. The cut-off frequency must be less than $\frac{1}{2 \, dt}$ , where $dt$ is the time step of the time signals. For the evaluation of the coherence functions, the cut-off frequency is always determined by the time step of the time signals. If FREQ_COUP is filled in, then the coherence function is cut off at this frequency before recovery.

#### 3.8.3 Keyword NB_FREQ_LISS

NB_FREQ_LISS is the number of frequency steps used for the smoothing of the DSPs by a Hamming window. The Hamming window obtained with NB_FREQ_LISS = 12 is shown in the figure below.

![Figure](/figures/u4.32.04/100002010000032C00000264D1C6B9423CE554DD.png)

*Hamming window for the calculation of the coherence of two functions*

NOM_PARA is not a keyword of the factor keyword COHERENCE.

#### 3.8.4 Keyword OPTION

The keyword OPTION makes it possible to define whether the entire signal or only the strong phase is used for the calculation of the coherence function:

- If OPTION='TOUT', one uses the time signals as they are.
- If OPTION='DUREE_PHASE_FORTE', one evaluates the coherence function for the duration of the strong phase only. The start and end time instants of the strong phase are calculated for the first signal only. One then uses the same time interval for the other signals. In the case of an earthquake, this assumes that all the records come from the same event. To evaluate the duration of the strong phase, one uses the notion of Arias intensity. One must then fill in the lower and upper bounds (see [INFO_FONCTION](doc:u4.32.05)).

#### 3.8.5 Keywords BORNE_INF and BORNE_SUP

The keywords BORNE_INF and BORNE_SUP give the bounds limiting the share of Arias intensity defining the initial and final time instants of the strong phase (they are given as a percentage of the Arias intensity) of the earthquake — the same meaning as for [INFO_FONCTION](doc:u4.32.05). By default, one takes 5% and 95%.

### 3.9 Factor keyword COMB

This keyword makes it possible to calculate the function giving the **real** linear combination of several concepts of nature fonction or nappe.

The name of the function to be combined is given by FONCTION and the value of the coefficient is given by COEF.

One may use the keyword LIST_PARA to give the list of the values of the parameters for which the combination of functions will be discretised. If this keyword is not filled in, a default list is built by taking the union of the lists of the values of the parameters of each function.

LIST_PARA is not a keyword of the factor keyword COMB.

**Note**

See the notes for the keyword ENVELOPPE

### 3.10 Factor keyword COMB_C

This keyword makes it possible to calculate the function giving the **complex** linear combination of several concepts of nature fonction_c.

The name of the function to be combined is given by FONCTION.
The value of the coefficient is given by COEF_C (complex) or COEF_R (real).

One may use the keyword LIST_PARA to give the list of the values of the parameters for which the combination of functions will be discretised. If this keyword is not filled in, a default list is built by taking the union of the lists of the values of the parameters of each function.

LIST_PARA is not a keyword of the factor keyword COMB_C.

**Note**

See the notes for the keyword ENVELOPPE

### 3.11 Factor keyword MULT

This factor keyword makes it possible to multiply several fonction, fonction_c or nappe.
It produces a concept of the same nature, fonction, fonction_c or nappe.

FONCTION gives the name of the function to be multiplied with the others.

LIST_PARA makes it possible to discretise the result function as for COMB.

LIST_PARA is not a keyword of the factor keyword MULT.

### 3.12 Factor keyword COMPOSE

This factor keyword makes it possible to calculate the composed function of two functions $F(G( \cdot ))$ .

The function $F(\cdot)$ is given by FONC_RESU and $G( \cdot )$ is given by FONC_PARA.

It does not apply to concepts of type nappe.

One checks that the NOM_PARA of $F(\cdot)$ does indeed correspond to the NOM_RESU of $G( \cdot )$.

### 3.13 Factor keyword ASSE

This factor keyword makes it possible to create a real function by concatenating two tabulated real functions.

It does not apply to concepts of type nappe.

The functions to be concatenated are given by FONCTION. One expects exactly two functions.

The discretisation points of the function created are those of the set of the two functions, modulo the effects of overloading.

If the domains of definition of the functions overlap, one of the functions imposes its points on the overlap zone and, for the prolongations, one uses the keyword SURCHARGE:

- SURCHARGE= 'DROITE': it is the function which has the largest abscissa which is chosen,
- SURCHARGE= 'GAUCHE': it is the function which has the smallest abscissa which is chosen.

One checks that all the functions have the same NOM_PARA, as well as the same interpolations.

### 3.14 Factor keyword EXTRACTION

This factor keyword makes it possible to build, from a complex function (type fonct_c), a real function representing either the real part, or the imaginary part, or the modulus, or the phase of the complex function.

The (complex) function to be treated is given by the keyword FONCTION.

The keyword PARTIE makes it possible to choose which extraction operation to carry out

| Value of PARTIE | Operation |
| --- | --- |
| REEL | extraction of the real part of the function |
| IMAG | extraction of the imaginary part of the function |
| MODULE | calculation of the modulus of the function |
| PHASE | calculation of the phase (in degrees) of the function |

### 3.15 Factor keyword PUISSANCE

The factor keyword PUISSANCE makes it possible to build the n-th power of a function or of a set of functions supplied in the form of a nappe.

The result function calculated will be $f{(\cdot)}^{n}$ .

The function to be treated $f{(\cdot)}$ is given by the keyword FONCTION and the exponent $n$ will be given by EXPOSANT.

By default, $n=1$ .

### 3.16 Factor keyword REGR_POLYNOMIALE

The factor keyword REGR_POLYNOMIALE calculates the polynomial regression of a function by the least-squares method (using the function `polyfit` of `numpy`).

The function to be treated $f{(\cdot)}$ is given by the keyword FONCTION and the degree of the polynomial sought is given by DEGRE.

One may use the keyword LIST_PARA to tabulate the polynomial calculated. Otherwise, it is tabulated on the list of the abscissae of the function $f{(\cdot)}$.

LIST_PARA is not a keyword of the factor keyword REGR_POLYNOMIALE.

### 3.17 Factor keyword FFT

The factor keyword FFT calculates the direct or inverse Fourier transform of a function (hence by the FFT algorithm).

The name of the function on which the operation is carried out is given by FONCTION.

If the NOM_PARA of the function is INST, then the direct FFT is calculated.

If the NOM_PARA of the function is FREQ, then the inverse FFT is calculated.

It does not apply to concepts of type nappe.

The FFT algorithm is faster for samples whose length is a power of 2.

#### 3.17.1 Keyword METHODE

The keyword METHODE makes it possible to choose the way of treating the cases where the sample is not a power of two:

- The method 'PROL_ZERO' (by default) proposes to extend the input signal with zeros until one has a total number of samples which is the first power of 2 whose value is greater than the initial number of samples.
- The method 'TRONCATURE' will consider only the first samples whose total number is the greatest power of two whose value is less than the initial number of samples.
- The method 'COMPLET' makes it possible to take into account the whole of the input signal, whatever the number of samples.

For example, on a signal of 601 values, the method 'PROL_ZERO' will complete the signal so as to have 1024 samples, whereas the method 'TRONCATURE' will consider only the first 512 time instants.

If the input signal has a number of samples which is a power of two, the two methods are of course equivalent: one takes the signal into account without modifying it.

**Note**

In the case of a sample of length $N$ , whose time step would be $dt$ , the sampling frequency of the FFT is $\frac{1}{N \, dt}$ . On the other hand, the last frequency for which the discrete transform is calculated is not $\frac{1}{dt}$ , but $\frac{N-1}{N \, dt}$ .

#### 3.17.2 Keyword SYME

The keyword SYME applies only to the inverse Fourier transform.

In the case where one were to supply the complete spectrum, the inverse transform is calculated directly by using SYME = 'OUI'. The methods 'TRONCATURE' and 'PROL_ZERO' are then not active.

If the (complex) spectrum supplied on input to the inverse FFT does not contain the folded part (associated with the negative frequencies of the spectrum), one can nevertheless estimate a time signal having the same spectral content on the part associated with the positive frequencies. If one denotes by ${X}_{k}$ the $k$-th sample of the Fourier transform of a sample of length $N$ , then one has ${X}_{k}={X}_{(N-k)}^{\text{*}}$ , where ${(\cdot)}^{\text{*}}$ corresponds to the complex conjugate. This information can be exploited to reconstruct a time signal while knowing only half of the spectrum. This operation is carried out when one chooses SYME = 'NON'. The time signal is then reconstructed so as to obtain a time sample of even length. In theory, in order to reconstruct a time signal of length $2 \times M$ , the spectrum must satisfy certain conditions:

- The spectrum must be of length $M+1$ ,
- The first point of the spectrum must be real,
- The last point of the spectrum must be real.

If these conditions are not satisfied, then one builds an approximate spectrum of odd length satisfying these conditions. If the initial spectrum is of even length, the last point is then reconstructed by carrying out a prolongation by interpolation of the initial spectrum. This reconstruction may introduce a slight bias when the spectral content of the sample is very significant on the last points of the spectrum.

The methods 'TRONCATURE' and 'PROL_ZERO' are still available for the inverse FFT. Take care, however, with the use of the method 'TRONCATURE'. If the number of truncated points is significant, then the results may be very appreciably different.

### 3.18 Factor keyword INTERPOL_FFT

The factor keyword INTERPOL_FFT carries out the interpolation of an accelerogram by the "zero padding" method. This method consists in calculating the Fourier transform of the initial signal, in completing the frequency signal obtained with new frequencies of zero value, then in calculating the inverse Fourier transform of this modified frequency signal. This functionality uses the same algorithms as the keyword FFT. The method is necessarily 'COMPLET' and SYME = 'NON'.

It makes it possible not to add frequency content to the interpolated function.

The name of the function on which the operation is carried out is given by FONCTION. The NOM_PARA of the function is necessarily the time INST.

The keyword PAS_INST makes it possible to give the time increment desired for the interpolated signal. It must be smaller than the time increment of the function supplied.

The time step actually obtained is often slightly different from that indicated via PAS_INST. The keyword PRECISION defines the maximum difference desired between these two values; if it is exceeded, an alarm message is issued in order to warn the user.

### 3.19 Factor keyword CORR_ACCE

The factor keyword CORR_ACCE makes it possible to correct an accelerogram (seismic signal in acceleration) so that the displacement signal does not possess a drift. One returns on output the corrected accelerogram. The signal may then be integrated by the standard methods (keyword INTEGRE of CALC_FONCTION). It is advisable to check the quality of the result by checking the absence of drift of the displacement signal and by comparing the response spectra before and after modification.

The name of the function on which the operation is carried out is given by FONCTION. This is the real accelerogram measured. It does not apply to concepts of type nappe.

#### 3.19.1 Keyword METHODE

The keyword METHODE makes it possible to designate the method which one wishes to use in order to correct the signals: correction by polynomials or by filtering in the frequency domain.

For the correction by polynomials (METHODE='POLYNOME'), one removes the drift of the signal, calculated by linear smoothing in the least-squares sense over the whole of the signal. The drift of the corresponding relative velocity is also removed, unless CORR_DEPL='NON'. In this latter case, one does not correct the drift of the relative displacement; this is the default value.
If CORR_DEPL='OUI', one also removes the drift of the relative displacement. This option is to be used with caution, because one does not know a priori the value of the final displacement after the earthquake.

For the correction by filtering (METHODE='FILTRAGE'), one removes the drift by filtering ("passe_haut") of the signal in the frequency domain. This filter is described in the documentation [R4.05.05](doc:r4.05.05).
The frequency of the filter is given by the keyword FREQ_FILTRE.

One must choose the smallest frequency which makes it possible to obtain the desired effect, namely to remove the drift, without (too greatly) altering the other properties of the signal. By default, the frequency of the filter is 0.05Hz. This value is generally well suited to seismic signals. This value may be decreased if the signal allows it, or increased if a drift persists.

#### 3.21.1 Choice of the discretisations

By default, for the calculation of the oscillator spectrum, one considers for the reduced dampings the values 0.02, 0.05 and 0.10.
For the frequencies of the SROs, one considers 150 frequency values in Hz with a discretisation which depends on the frequency interval.

The first value is at $0.2Hz$, then one deduces the following 150 by the rule described by the table below ( $n_1$, $n_2$ designate the order number of the start and of the end of the interval):

| $n_1$ | $n_2$ | Frequency step |
| --- | --- | --- |
| 1 | 57 | 0.05 Hz |
| 58 | 65 | 0.075 Hz |
| 66 | 79 | 0.10 Hz |
| 80 | 103 | 0.125 Hz |
| 104 | 131 | 0.25 Hz |
| 132 | 137 | 0.5 Hz |
| 138 | 141 | 1.0 Hz |
| 142 | 150 | 1.5 Hz |

A list of reduced dampings $\left({\xi}_{1},\cdots,{\xi}_{i},\cdots\right)$ different from that used by default may be given by the keyword AMOR_REDUIT.

A list of frequencies different from that used by default may be given by FREQ or LIST_FREQ. In this latter case, the frequencies are supplied under a concept listr8. The frequencies must be strictly positive.

#### 3.21.2 Normalisation

The oscillator spectrum will be normalised to the value given by the keyword NORME (value of the pseudo-acceleration); this value is recalled in the message file.

#### 3.21.3 Choice of the type of SRO

The keyword NATURE makes it possible to choose the nature of the SROs. It defines the nature of the function or of the functions of the nappe created by the command CALC_FONCTION.
The keyword PSEUDO (OUI or NON) makes it possible to choose the way in which these values are calculated. All the options are recalled in the table below.

| Keyword | PSEUDO='OUI' (default) | PSEUDO = 'NON' |
| --- | --- | --- |
| ACCE | Pseudo-acceleration spectrum | Spectrum in absolute acceleration |
| VITE | Pseudo-velocity spectrum | Spectrum in relative velocity |
| DEPL | Relative displacement spectrum | Relative displacement spectrum |

The nature of the function which serves to build the spectrum is given by NATURE_FONC. The choice is imposed according to the method selected: 'ACCE' (time signal) or 'DSP' (power spectral density in acceleration). This keyword makes it possible to overload the NOM_RESU of the function specified under the keyword FONCTION when the latter is created by [RECU_FONCTION](doc:u4.32.03).

The keyword METHODE gives the method which one wishes to use: the default method is the method 'NIGAM'. If one chooses the method 'HARMO', then the response spectrum is obtained by successive harmonic calculations (for various natural frequencies of the oscillator) by way of an FFT/IFFT of the input signal. The two methods, 'NIGAM' and 'HARMO', are detailed in the document [R5.05.01](doc:r5.05.01). If one chooses 'RICE' then one determines the equivalent SRO for the data of a DSP.

By default, the use of SPEC_OSCI produces a nappe. If AMOR_REDUIT contains only one damping, one creates a nappe containing only one function. In this case, one may choose TYPE_RESU='FONCTION' in order to return this function directly.

The keyword DUREE is to be filled in only if METHODE='RICE' and therefore NATURE_FONC='DSP'. This is the duration of the strong phase of the earthquake. The seismic signal is considered as stationary over this duration. This value is necessary in order to evaluate the peak factor which appears in the Vanmarcke formula in order to find the SRO equivalent to the data of the DSP.

### 3.22 Factor keyword PROL_SPEC_OSCI

This factor keyword PROL_SPEC_OSCI makes it possible to extend a spectrum below the frequency of definition (for example fmin = 0.25Hz) by giving as a criterion a value of maximum displacement dmax.

One calculates the slope from the first two values of the spectrum (the smallest frequency fmin is greater than zero) and one extends the spectrum in displacement by retaining this slope up to the value dmax.

The keyword FONCTION gives the function on which the operation is carried out. It does not apply to concepts of type nappe.

The oscillator spectrum will be normalised to the value given by the keyword NORME (value of the pseudo-acceleration); this value is recalled in the message file.

The displacement value used to extend the spectrum is given by the keyword DEPL_MAX. If the slope of the spectrum is less than zero, dmax must be greater than the first displacement value of the spectrum given.

### 3.23 Factor keyword DSP

The factor keyword DSP calculates the power spectral density (DSP) equivalent to the data of an oscillator response spectrum (SRO) with the Vanmarcke formula, a function of nature fonction [R4.05.03](doc:r4.05.03).

The oscillator spectrum can be calculated only on the functions of NOM_PARA = 'FREQ'. The function defining the SRO is given by the keyword FONCTION.

For the calculation of the DSP from an oscillator spectrum, one considers that

- the SRO expresses the median maximum (fractile 0.5); otherwise one must fill in another value via the keyword FRACT.
- the DSP is equal to zero for frequencies less than or equal to $1/2\pi Hz$ .
- the spectrum is normalised according to the value of NORME.

The user must check that the frequency discretisation (list of the frequencies) is sufficient with respect to the frequency content of the signals to be modelled. It is also advisable to check the equivalence between the DSP and the SRO given, by carrying out draws or by determining values of the maximum response of an oscillator with [POST_DYNA_ALEA](doc:u4.84.04). The operator calculates the power spectral density (DSP) equivalent to the data of an oscillator response spectrum (SRO) with the Vanmarcke formula. One does not carry out any iteration in order to optimise the fit.

An example of application is proposed in the test case ZZZZ100D.

The keywords AMOR_REDUIT and LIST_FREQ are identical to those described for SPEC_OSCI .

The keyword FREQ_PAS designates the frequency step if LIST_FREQ is not filled in.

The cut-off frequency is given by the keyword FREQ_COUP. One determines the DSP up to this frequency. The SRO is extended (constant value corresponding to the ZPA) up to this value if necessary.

#### 3.23.1 Keyword DUREE

The duration of the strong phase of the earthquake is given by the keyword DUREE. The seismic signal is considered as stationary over this duration. This value is necessary in order to evaluate the peak factor which appears in the Vanmarcke formula.

One considers oscillator spectra normalised to the value given by the keyword NORME (value of the pseudo-acceleration). In general, the SROs are given in $g$, so one must fill in NORME = 9.81.

#### 3.23.2 Keyword FRACT

The DSP is adjusted on a fractile of the response spectrum given by the keyword FRACT. The value of the fractile has an impact on the determination of the peak factor, used in the Vanmarcke formula. In general one considers that the target spectrum corresponds to the median and therefore fract = 0.5.

#### 3.23.3 Keyword NB_ITER

The number of iterations for improving the adjustment of the DSP is given by the keyword NB_ITER. It may be necessary to carry out fewer iterations in order to avoid the *overfitting* of the DSP (two iterations, for example).

#### 3.23.4 Keyword NB_FREQ_LISS

The number of frequency steps used for the smoothing of the DSPs by a Hamming window is given by NB_FREQ_LISS. The Hamming window obtained with NB_FREQ_LISS = 12 is shown in the figure u4.32.04-coherence.

#### 3.23.5 Keyword FREQ_FILTRE_ZPA

The optional keyword FREQ_FILTRE_ZPA gives a frequency (in $Hz$ ) for filtering the high frequencies beyond the ZPA frequency. It is therefore a low-pass filter. This filter applies to the DSP in the frequency domain. This filter makes it possible to remove residual frequency content beyond the value of the ZPA. The meaning is the same as for the operator GENE_ACCE_SEISME.

### 3.24 Factor keyword INTEGRE_FREQ

This keyword allows the simple or double frequency integration of a function of time by using a high frequency filter given by a cut-off frequency, or a low one given by a filtering frequency.

The function on which the operation is carried out is given by the keyword FONCTION. It does not apply to concepts of type nappe.

The keyword NIVEAU gives the level of simple (=1) or double (=2) integration.

The cut-off frequency gives the level of high filtering of the signal. It is given by FREQ_COUP.

The low filtering frequency of the signal is given by the keyword FREQ_FILTRE. The default value is 0.

### 3.25 Factor keyword DERIVE_FREQ

The factor keyword DERIVE_FREQ allows the simple or double frequency differentiation of a function of time by using a high frequency filter given by a cut-off frequency.

The name of the function on which the operation is carried out is given by the keyword FONCTION. It does not apply to concepts of type nappe.

The keyword NIVEAU gives the level of simple (=1) or double (=2) differentiation.

The cut-off frequency FREQ_COUP gives the level of high filtering of the signal.

  - Interpolation: linear
  - Prolongation: 'EXCLU'

  - NOM_RESU: that of the functions

#### 3.26.2 Overloading of the attributes

The user may overload the attributes given by default by using the following keywords.

##### 3.26.2.1 Keyword NOM_PARA

The keyword NOM_PARA designates the name of the parameter (variable or abscissa) of the function or of the nappe. The values currently allowed for para are: 'TEMP', 'INST', 'EPSI', 'X', 'Y' , 'Z', 'FREQ', 'PULS', 'AMOR', 'DX', 'DY', 'DZ', 'DRX', 'DRY', 'DRZ' and 'ABSC'.

##### 3.26.2.2 Keyword NOM_RESU

The keyword NOM_RESU makes it possible to document the function created by giving a name (8 characters) to the function. Barring exceptions, this name is not tested.

##### 3.26.2.3 Keyword INTERPOL

When the concept produced is a nappe, the keyword INTERPOL defines the type of interpolation between two consecutive values of the parameter of the nappe and between two functions (once these have been evaluated). Same meaning as in D[DEFI_NAPPE](doc:u4.31.03).

When the concept produced is a function (real or complex), the keyword INTERPOL defines the type of interpolation for the abscissae and the ordinates of the function. One expects up to two values. If a single value is supplied, it is used for the abscissae and the ordinates. Same meaning as in [DEFI_FONCTION](doc:u4.31.02).

##### 3.26.2.4 Keywords PROL_DROITE and PROL_GAUCHE

They define the type of prolongation to the right (respectively to the left) of the domain of definition of the variable:

- 'CONSTANT' for a prolongation with the last (or the first) value of the function,
- 'LINEAIRE' for a prolongation along the first defined segment (PROL_GAUCHE) or the last defined segment (PROL_DROITE),
- 'EXCLU' if the extrapolation of the values outside the domain of definition of the parameter is forbidden.

##### 3.26.2.5 Keywords NOM_PARA_FONC/INTERPOL_FONC/PROL_DROITE_FONC/PROL_GAUCHE_FONC

These keywords make it possible to modify the attributes of the nappe and apply to the parameters of the functions of the latter. They have the same meaning as the keywords without the suffix FONC.

- NOM_PARA_FONC is the name of the parameter of the functions (as in [DEFI_NAPPE](doc:u4.31.03)).
- INTERPOL_FONC is the type of interpolation for the abscissae and the ordinates of the functions of the nappe (identical to the keyword INTERPOL of the factor keyword DEFI_FONCTION of [DEFI_NAPPE](doc:u4.31.03)).
- PROL_GAUCHE_FONC/PROL_DROITE_FONC define the prolongations of the functions (identical to the keywords PROL_GAUCHE/PROL_DROITE of the factor keyword DEFI_FONCTION of [DEFI_NAPPE](doc:u4.31.03)).
