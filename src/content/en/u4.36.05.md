# u4.36.05 Operator GENE_FONC_ALEA

## 1 Purpose

To generate a trajectory of a multivariate one-dimensional stochastic process (i.e. with several components and indexed on a single variable), stationary, with zero mean, from its spectral density matrix (interspectral matrix). The trajectories of the stochastic process are time functions which then make it possible to carry out a transient dynamic analysis.

The trajectories obtained have an interspectral matrix which converges on average towards the target interspectral matrix and are the realisations of an asymptotically Gaussian process (i.e. when the number of draws tends to infinity). The algorithm used is a simulation algorithm by trigonometric series with random phase and an inverse fast Fourier transform.

The time functions produced are stored in an interspectre data structure. Each function is identified by its order number. It can be extracted by using the operator RECU_FONCTION [U4.32.03].

## 2 Syntax

```text
interspectre = GENE_FONC_ALEA(
    ◆ INTE_SPEC = interspectre,
    ◇ NUME_VITE_FLUI = int,
    ◇ INTERPOL = / "NON",
                 / "OUI" (par défaut),
    # Si: equal_to("INTERPOL", 'OUI')
        ◇ DUREE_TIRAGE = float,
        ◇ FREQ_INIT = float,
        ◇ FREQ_FIN = float,
    ◇ NB_POIN = int,
    ◇ NB_TIRAGE = int (défaut: 1),
    ◇ INIT_ALEA = int,
    ◇ INFO = / 1 (par défaut),
             / 2,
    ◇ TITRE = text,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Operand INTE_SPEC

```text
♦    INTE_SPEC = intf                                                [interspectre]
```

Name of the interspectral matrix towards which the interspectral matrix of the generated signals must tend.

The interspectral matrix is a complex matrix, each term of which is written ${S}_{\mathit{XY}}(f)={\int}_{-\infty }^{+\infty }E[X(t)Y(t-\tau )]{e}^{-\mathrm{2i}\pi f\tau }d\tau$ where $E[\text{}\cdot \text{}]$ is the mathematical expectation, and where $X$ and $Y$ are two stationary random processes (for example two components of a loading at two distinct points of a mesh).

**Note:**

*To be physical, the interspectral matrix must be a positive-definite Hermitian matrix.*

This interspectral matrix is generated mainly by the operators:

> DEFI_INTE_SPEC, LIRE_INTE_SPEC and CALC_INTE_SPEC.

For further information on the meaning of the parameters, the reader is invited to consult the documentation of the command DEFI_INTE_SPEC [U4.36.02](doc:u4.36.02).

### 3.2 Operand NUME_VITE_FLUI

```text
◊    NUME_VITE_FLUI= nk                                                    [I]
```

This order number corresponds to a flow velocity if the interspectra model, via the operators CALC_FLUI_STRU and DEFI_SPEC_TURB, a turbulent excitation induced by a fluid flow.

### 3.3 Operand INTERPOL

```text
◊    INTERPOL    =
```

```text
/    'OUI'                                            [DEFAUT]
```

One allows interpolation of the frequency functions constituting the terms of the interspectral matrix. In particular, the new discretisation will depend on the duration of the signal to be generated (keyword DUREE_TIRAGE) and on the number of points of the FFT (keyword NB_POIN).

```text
/    'NON'
```

The values of the interspectrum used are only the existing values (no interpolation used).

**Caution:**

*If INTERPOL='NON', it is necessary that:*

- *the different terms of the interspectral matrix have exactly the same discretisation and a constant frequency step. If the number of discretisation points of the interspectrum is not a power of 2, and/or is not compatible with the interspectrum, one or more alarms are emitted and an ad hoc power of 2 is chosen,*
- *the interspectra are discretised finely enough to allow generation of time histories with enough time instants.*

### 3.4 Operand DUREE_TIRAGE

```text
◊    DUREE_TIRAGE    =    durée                                                [R]
```

Duration of the signal to be generated, for each draw (the total duration will therefore be nt $\text{}\times \text{}$ durée).

If the keyword DUREE_TIRAGE is not present, the duration of the signal to be generated is computed by $\text{durée}=\frac{1}{\Delta f}$ where $\Delta f$ is the frequency step of the interspectrum (original minimum step of the interspectrum, or step computed from the keywords FREQ_INIT, FREQ_FIN and NB_POIN).

**Note:**

*The generated signals start at time instant 0. with a zero value.*

**Note:**

To obtain the desired duration, the generation algorithm adjusts the number of points used in the FFT (cf. [§3.6] Operand NB_POIN) and, if needed, extends the interspectrum beyond the min and max frequencies with null values.

### 3.5 Operands FREQ_INIT / FREQ_FIN

```text
◊    FREQ_INIT = fi                                                        [R]

◊    FREQ_FIN = ff                                                        [R]
```

First and last frequency values for which the interspectrum will be taken into account.

The presence of these keywords has the effect of truncating the interspectrum. If the keywords are not present, it is the minimum and maximum frequency values of the interspectrum which are used.

### 3.6 Operand NB_POIN

```text
◊    NB_POIN = nb_poin                                                    [I]
```

Number of discretisation points of the interspectrum to be used in the generation algorithm.

This number must be a power of 2 because it corresponds to the number of points of the inverse fast Fourier transform used by the generation algorithm. If this is not the case, it is the power of 2 immediately greater than nb_poin which is retained.

If the keyword NB_POIN is not present, the number of points is computed so that Shannon's theorem is satisfied, that is $\frac{1}{\Delta t}>2\cdot {f}_{\max}$ , where $\Delta t$ is the time step of the signal to be generated (which depends on NB_POIN and on DUREE_TIRAGE) and where ${f}_{\max}$ is the maximum frequency retained from the interspectrum.

**Suggestion:**

*It is advised not to specify the number of points; the coded algorithm in that case automatically chooses the optimal value. In particular, if the keywords DUREE_TIRAGE and NB_POIN are not present, then one is assured that the generated signal is consistent both with the discretisation step of the interspectrum and with the maximum frequency. However, if the user wants to specify NB_POIN, the two notes which follow should help.*

**Note:**

*If the keywords DUREE_TIRAGE and NB_POIN are present then one has:* $\Delta t=\frac{1}{2}\times \frac{\text{durée}}{\text{nb\_poin}}$ *In this case, if nb_poin is too small with respect to durée for Shannon's theorem to be satisfied, then an alarm is emitted and it is the minimum number of points allowing Shannon's theorem to be satisfied which is retained. The value specified by NB_POIN is therefore taken into account only when it is greater than the minimum value. By imposing a high number of points, one can force the signal to have a time-discretisation step smaller than the default one. One must then be aware that the discretisation of the time history is finer than is theoretically allowed by the maximum frequency of the interspectrum.*

**Note:**

*If INTERPOL='NON' and if nb_poin is not compatible with the interspectrum, an alarm is emitted and an ad hoc power of 2 is chosen.*

**Note:**

*The number of points making up the generated signals is equal to twice the number of discretisation points of the interspectrum, and therefore to twice nb_poin when the keyword is supplied. This number of points is useful to know for later use in CALC_INTE_SPEC [U4.36.03](doc:u4.36.03) (cf. [§ 3.9] "Operand INFO" and [§ 6] "Examples").*

### 3.7 Operand NB_TIRAGE

```text
◊    NB_TIRAGE = nt                                                        [I]
```

Number of draws which the generated time signals must contain. The resulting signals will contain nt statistically independent draws placed end to end.

One can then post-process the results obtained from these generated signals with the operator CALC_INTE_SPEC [U4.36.03](doc:u4.36.03), cf. [§ 6] "Examples".

**Caution:**

*If the keyword DUREE_TIRAGE is present, the total duration of the signal will be nt $\text{}\times \text{}$ durée. However, it is of course not equivalent to generate 1 draw of duration nt $\text{}\times \text{}$ durée_tirage and nt draws of duration durée_tirage placed end to end. There is statistical independence between the different segments of duration d in the second case and not in the first.*

### 3.8 Operand INIT_ALEA

```text
◊    INIT_ALEA    =    ni                                                        [I]
```

Causes initialisation at its ni-th term of the sequence of pseudo-random numbers used for the generation of the signals.

If the keyword INIT_ALEA is absent, the terms of the sequence used are those immediately following those already used. If no term has yet been used, the sequence is initialised at its first term.

**Suggestion:**

*Unless there is a particular use, it is advised not to supply the keyword INIT_ALEA in the following operators: GENE_FONC_ALEA, GENE_VARI_ALEA and GENE_MATR_ALEA. In this case, at the first call to one of these operators, the sequence of pseudo-random numbers is initialised at its first term. Omitting the keyword INIT_ALEA at each call of these operators in the command file guarantees the statistical independence of the pseudo-random numbers used.*

**Note:**

*The seed of the sequence remains identical from one execution of Code_Aster to another; the results therefore remain strictly identical (one can thus test the non-regression of statistical results which have not converged). If one wishes to generate results which are statistically independent from one execution to another, then one must use the keyword INIT_ALEA with values greater than the number of terms used in the previous executions.*

**Caution:**

*The random-variable generator used is that of the Python module "random". It depends on the version of Python used by Code_Aster. Results which have not converged statistically may therefore vary from one version of Code_Aster to another or from one platform to another, if the version of Python is not the same and if between the two versions the module random has changed (the case between Python 2.1 and 2.3).*

**Note:**

*In Python version 2.3, the period of the generator is 2**19937-1.*

```text

```

titre is the title of the analysis to be printed at the head of the results [U4.03.01](doc:u4.03.01).

## 4 Verification stage

Various checks are carried out to ensure that the data are consistent (nb_poin large enough with respect to the maximum frequency and the duration to be generated, duration large enough with respect to the discretisation of the interspectrum, and so on). Alarms are emitted where applicable.

If the keyword NB_POIN is present, then one checks that the value given is a power of 2. Otherwise, an alarm is emitted and the value is modified.

If INTERPOL='NON', one checks that the different terms of the interspectral matrix have the same discretisation with a constant frequency step.

## 5 Concept produced

The time functions produced are stored in an interspectre data structure. Each function is identified by its order number. It can be extracted by using the operator RECU_FONCTION [U4.32.03](doc:u4.32.03).

```text

# des opérateurs associés utiles (pour la récupération des fonctions

# générées et leur éventuelle vérification).

# L'interspectre utilisée n'a pas de signification. Il n'y a pas

# d'utilisation des fonctions générées (avec un dyna_tran_modal par

# exemple).

# Les cas test zzzz180a et sdll107a fournissent des exemples plus complets

# Définition de l'interspectre

spect11 = DEFI_FONCTION(
NOM_PARA = 'FREQ',
VALE_C =    (
0.        ,    10.    ,    0.,
50.0    ,    10.    ,    0.,
150.    ,    0.1    ,    0.,
)
)

spect12 = DEFI_FONCTION(
NOM_PARA = 'FREQ',
VALE_C =    (
0.        ,    0.5    ,    0.8,
150.    ,    0.5    ,    0.8,
)
)

spect22 = DEFI_FONCTION(
NOM_PARA = 'FREQ'
VALE_C =    (

150.    ,    1..    ,    0.,
)
)

mat_int = DEFI_INTE_SPEC(
DIMENSION = 2,
PAR_FONCTION =    (    _F(    NUME_ORDRE_I = 1,
NUME_ORDRE_J = 1,
FONCTION = sp11),
_F(    NUME_ORDRE_I = 1,
NUME_ORDRE_J = 2,
FONCTION = sp12),
_F(    NUME_ORDRE_I = 2,
NUME_ORDRE_J = 2,
FONCTION = sp22)
)
)

# Génération des deux fonctions temporelles via la structure de données

# interspectre

DUREE_TIRAGE    =    5.,

)

# Récupération des deux fonctions par exemple pour un IMPR_FONCTION

FONC1 = RECU_FONCTION(    INTE_SPEC = vect,
NUME_ORDRE = 1)

FONC2 = RECU_FONCTION(    INTE_SPEC = VECT1,

# Vérification : Calcul de l'interspectre des fonctions générées

# Attention : la valeur donnée à NB_POIN est importante. Il est

# souhaitable de la prendre égale au nombre de points constituant

# les fonctions (2*nb_fft si provenant de GENE_FONC_ALEA).

INST_FIN=50.,
DUREE_ANALYSE=5.,
DUREE_DECALAGE=5.,
NB_POIN=2048,
FONCTION=( FONC1, FONC2, ))

# Récupération de l'auto-spectre de FONC1 pour comparaison à spetc11

F11 =RECU_FONCTION(INTE_SPEC=INTERS,
NUME_ORDRE_I=1,
)
```
