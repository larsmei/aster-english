# u4.01.13 New features and modifications of version 17

**Summary:**

The purpose of this document is to provide an overall view of the syntax modifications and of the new possibilities of the code_aster commands introduced during the development of version 17, that is, since version 16.5.

For further details, one should consult the documentation of the commands and the histor files of the sub-versions.

## 1 Mechanics

- Output of the fields **RESI_GLOB_RELA** via **MECA_NON_LINE** (#26870 - 17.1)
  For the command MECA_NON_LINE, the residual fields at the nodes are stored during the analysis and can be printed at the end.
- Follower loading **FORCE_FACE** . (#34164 - 17.3)
  The possibility is added of making `FORCE_FACE` a follower load via `TYPE_CHARGE='SUIV'`. The tangent matrix is modified accordingly.
- Addition of the option **SIMY_ELGA** for the elements **GRAD_INCO / GRAD_VARI** (#34478 - 17.3)
  The option SIMY_ELGA, which makes it possible to compute a mean stress per finite element, is added for the elements GRAD_INCO or GRAD_VARI.
- Non-symmetric tangent matrix for the interface elements (#34573 - 17.3)
  This development includes several improvements: introduction of a distinction between the constitutive laws of JOINT and the laws of INTERFACE, change over to generalised strains and stresses for the INTERFACE elements in order to systematise the programming, and treatment of symmetric or non-symmetric matrices with the use of the generic routines.
- New **shell/3D connection** based on a variational formulation (#29018 - 17.3)
  A first version (intended to be improved later) of a new COQUE/3D link is introduced, based on a variational formulation.
- New command **REST_HOMO_LOCAL** for the reconstruction of the local fields (#34321 #34671 #34682 - 17.3)
  This command takes as input the thermal and/or mechanical correctors and a thermoelastic (or elastic or thermal) result on a homogeneous global mesh. It returns a result concept of the same type as the global input result, which contains the reconstructed local solution on the mesh of the VER (Representative Elementary Volume). Optionally, the local solution can be reconstructed on the complete mesh (CALC_MATE_HOMO works on 1/8 of the geometry).
The command `REST_HOMO_LOCAL` can be used with parallel meshes.
- Operator **CALC_MATE_HOMO** — addition of a new **TYPE_HOMO = 'PLAQUE_CT_MINDLIN'** (#34899-35094 - 17.4)
  The purpose of this development is the addition of a new option to `CALC_MATE_HOMO : TYPE_HOMO = 'PLAQUE_CT_MINDLIN'` in order to define the homogenisation of plates with transverse shear. This will produce a table of orthotropic characteristics (but with isotropic expansion) for ELAS_COQUE and finite-element modelling DST.
- Operator **CALC_MATE_HOMO** — new formulation for transverse shear **TYPE_HOMO="PLAQUE_CT_TOURATIER"** (#35094 - 17.4)
  The purpose of this development is the addition of a new `TYPE_HOMO="PLAQUE_CT_TOURATIER"` to the command `CALC_MATE_HOMO`. It is a new kinematic formulation for plates, for taking transverse shear into account without the introduction of correction coefficients.
- Introduction of a new macro-command **THERMECA_MULT** (#33809 - 17.4)
  A new macro-command THERMECA_MULT is introduced, making it possible to obtain the mechanical responses corresponding to thermal fields applied to one and the same mechanical model.
This command THERMECA_MULT is distinguished from MACR_ELAS_MULT by the fact that it is possible to supply a temperature field as a loading.
- Simultaneous **HHO** and **FE** analysis (#35004 - 17.4)
  This development makes possible the simultaneous analysis of HHO elements and finite elements.
- **HHO elements: order higher than 2** (#34395 -17.4)
  The purpose of this development is the addition of HHO elements for the following orders: k=0: CONSTANTE, k=1: LINEAIRE, k=2: QUADRATIQUE, k=3: CUBIQUE, k=4: QUARTIQUE.
- Detection of the plane of the discrete element when **DIS_CONTACT / DIS_CHOC** and **COIN_2D** (#34860 - 17.4)
  This development concerns a change to the constitutive law COIN_2D, so as to supply compulsorily 3 values under the keyword `PRECISION`. These values govern the flatness tests in the planes YZ, XZ and XY respectively.
- Addition of the option **EVOL_IMPO** to **CHAR_MECA** or of **DIDI** to **CHAR_CINE** (#28597 -17.4)
  This development makes it possible to make the loading type `DIDI` compatible with `CHAR_CINE` loadings.

## 2 Thermal

- Operator **THER_NON_LINE - TRANSITOIRE** (#33079 - 17.1)
  The command THER_NON_LINE is now implemented on the Python side. Some keywords are not yet supported (drying, model reduction); in that case the Fortran operator is called.
- Computation of the **temperature gradient GRAT** (#33934 - 17.2)
  One wishes to have the temperature gradient in the form of a field at the nodes. This field is necessary in order to compute the “relocalised” stresses at the end of a homogenised analysis. The temperature-gradient field is called GRAT.
- Extension of the analyses available for **HHO** (#33950/#33946/#33966/#34394 - 17.2 to 17.3)
  The HHO elements are made compatible with orthotropic thermal analyses and with a transient THER_NON_LINE analysis.
The possibility is added of supplying command variables VARC for HHO in thermal analysis.
The HHO elements in thermal analysis are available at order 0 in thermal analysis.
- Introduction of a new macro-command **CALC_THER_MULT** (#33806 - 17.4)
  This new macro-command `CALC_THER_MULT` makes it possible to carry out thermal analyses with linearisation of the mesh and an automated time step.
This command computes the evolution of the temperature in the structure under multiple transient thermal loadings. Two thermal responses can be taken into account: thermal response to a unit shock, or thermal response to an arbitrary loading coming from an AFFE_CHAR_THER.
- Correction of the **tangent matrices** in non-linear thermal analysis: **thermal conduction** (#34600 - 17.4)
  The tangent matrices of non-linear thermal analysis do not lead to quadratic convergence, even on very simple cases. In this development, account is taken of the dependence of thermal conduction on temperature.
- New operator **SECH_NON_LINE** (#33112 -17.4)
  Until now, drying analyses were carried out with the command `THER_NON_LINE`. This development creates a new command specific to drying analyses, `SECH_NON_LINE`, associated with the drying laws, and produces a new result `EVOL_SECH` possessing a field SECH with a component "SECH".

## 3 Fluid–structure interaction

- Change to **DEFI_SPEC_TURB (SPEC_CORR_CONV_1-2)/PROJ_SPEC_BASE** (#32094 - 17.1)
  The operators DEFI_SPEC_TURB/ PROJ_SPEC_BASE did not make it possible to carry out, in a suitable way, an analysis of the response of a structure to turbulence. The options available were too restrictive concerning the spectra and the correlation lengths. The changes concern:

  - the possibility of defining correlation lengths and convective velocities.
  - the possibility of integrating a transverse correlation length for Au-Yang and Corcos.
  - the possibility of defining correlation lengths depending on the angular frequency.
  - the removal of the Au-Yang correlation, because it is wrong.
- Relax the check of consistency of the **IFS** formulations (#35153 - 17.4)
  In order to lift in part the restriction on the possibility of mixing several FORMULATION values in IFS in the same mesh, the keyword `VERI_FORMULATION_IFS` is added in `AFFE_MODELE`.

## 4 Constitutive laws

### 4.1 New laws or improvements:

- Introduction of a quasi-brittle constitutive law with a cap in compression: **ENDO_LOCA_TC** (#32232 -17.1)
  Introduction of a new constitutive law for concrete which covers the following phenomenology:

  - Damage in tension / shear and a dedicated threshold
  - Hardening in tension identical to ENDO_LOCA_EXP
  - Damage in compression and a dedicated threshold
  - Hardening in compression of perfect-plasticity type, asymptotic after a first linear phase
  - The thresholds have an analytical expression (robustness, efficiency)
  - The stress is bounded whatever the loading direction
  - Regularisation of the angular points for the tangent matrix (as for ENDO_LOCA_EXP)
  - Viscous regularisation of the damage
  The vocabulary in DEFI_MATER_GC and DEFI_MATERIAU has been revised. (#34613 -17.3)
- Constitutive law **ENDO_LOCA_TC**: modification of the numerical regularisations (#34393 - 17.3)
  The two regularisation parameters are evaluated (one in order to “round off” the shape of the damage threshold, the other in order to round off the tension–compression transition) so that the impact on the stresses is of the same order of magnitude as the precision requested for the integration of the constitutive behaviour (via RESI_INTE_RELA).
- Constitutive law **ENDO_LOCA_TC** — Estimation of the influence of viscosity (#34611 - 17.3)
  The internal variable SIGMVISC is introduced, which evaluates the difference from the stress which one would have for the same strain in the absence of viscosity. Another internal variable, ENDOTOT, is also introduced, which measures the maximum damage which can be observed in the current state by scanning all the possible loading directions.
- Integration of the modified **Cam-Clay** constitutive model via Mfront (#33516 - 17.1)
  Integration of the modified Cam-Clay constitutive model (named MCC) via MFront. It will eventually replace the constitutive law CAM_CLAY in order to gain in robustness and in performance for carrying out non-linear analyses. This update will make it possible to produce, progressively, variations of MCC, thus allowing increasingly realistic predictions with respect to experimental tests on soils.
- Integration of the **Barcelona** constitutive model via MFront (#33678 - 17.2)
  The purpose of this issue is the integration of the Barcelona constitutive model with MFront, while at the same time deactivating the existing Fortran version. In time, this new integration will make it possible to develop more sophisticated variations of the Barcelona model suited to materials of bentonite type.
- Integration of the **CSSM** constitutive model via MFront (#33712 - 17.2)
  The purpose of this issue is the integration of the CSSM constitutive model (Critical State Soil Model) via MFront in Code_Aster. CSSM relies on the combination of two models, close to modified Cam-Clay and to Iwan, in order to represent the phenomenology of soils, both under monotonic and under cyclic loadings (which neither modified Cam-Clay nor Iwan manages to do on its own).
- Change to the constitutive law **DIS_GRICRA** (#33519 - 17.2)
  In the material DIS_GRICRA, KP is added, which is the elastic stiffness in parallel (identical for the 3 directions). This discrete element is placed in parallel in order to avoid null pivots, because DIS_GRICRA can return a null tangent matrix.
- For the discrete constitutive law **DIS_CHOC**, account taken of an **elastic spring in parallel** (#34730 - 17.3)
  The use of a shock discrete element can lead to singular-matrix configurations. In order to work around this case, the practice is to duplicate the support element in order to add an elastic spring with a low stiffness. This spring in parallel can now be taken into account directly in the constitutive behaviour DIS_CHOC.
- For the discrete constitutive law **DIS_CHOC** with friction and a non-symmetric tangent matrix (#35026 - 17.4)
  The objective of this development is to move to a formulation involving a true non-symmetric tangent matrix for the constitutive law DIS_CHOC in the presence of Coulomb friction, in statics and in dynamics. This issue gave rise to an update of the affected test cases, and to the addition of new tests.
- For the discrete constitutive laws, addition of an **elastic spring in parallel** (#35027 -17.4)
  This development consists in adding an elastic spring in parallel for all the constitutive laws of discrete elements (when this is possible).
- Enrichment of the constitutive law **DIS_ECRO_TRAC** (#32285 -17.4)
  One wishes to model a non-linear spring in the axial direction and in the tangential direction. The constitutive law 'DIS_ECRO_TRAC' makes it possible to model an elastoplastic spring with a tension curve. The objective of this development is to enrich this constitutive law in order to extend it to both directions at the same time: axial or tangential.
- Replacement of **FONC_DESORP** for the definition of the desorption isotherms in BETON_DESORP HR = f(C,T) (#33617 - 17.2)
  The keyword `ELAS_FO/FONC_DESORP` becomes BETON_DESORP/FONC_DESORP, with BETON_DESORP a new keyword of DEFI_MATERIAU. Other parameters are introduced under BETON_DESORP, making it possible to evaluate the hygrometry from the Leverett isotherm.
- Development of a new constitutive law for drying **SECH_RFT** (#33618 -17.2)
  A new constitutive law relating to drying has been developed and validated on the experimental data of the VeRCoRs concrete. The model is RICHARD_FICK_TEMPERATURE (Adia et al., 2020). This model is to be introduced in the form of a new option known as ’SECH_RFT’ of the keyword RELATION in the operator `THER_NON_LINE`, and in the form of a new keyword of the operator DEFI_MATERIAU.
- Supplements to the developments of **SECH_RFT** and **BETON_DESORP** (#34147- 33620 - 17.4)
  The keyword `UNITE_PRESSION` is added to DEFI_MATERIAU/BETON_DESORP: it makes it possible to choose the desired unit for the capillary pressure PCAP. The keywords `UNITE_TEMPS` and `UNITE_LONGUEUR` are added to SECH_RFT. For the 4 drying modellings (3D_SECH, 3D_SECH_DIAG, AXIS_SECH and AXIS_SECH_DIAG), two options are created for the computation of fields at the Gauss points: `DIFF_ELGA` for the diffusion coefficient and `HYGR_ELGA` for the hygrometry.
- Visco-hyperelastic constitutive law **ELAS_HYPER_VISC** (#34083 - 17.2)
  Introduction of a visco-hyperelastic MFront constitutive law ELAS_HYPER_VISC. This model is adopted for elastomers. It is compared and validated with Abaqus simulations.
- Modification of the formulation of desiccation creep in the constitutive law **BETON_BURGER_FP** (#25328 - 17.3)
  In the constitutive law BETON_BURGER, the computation of desiccation creep was overestimated (Bazant model) when there are cycles of large humidity variations. The Mfront file of this constitutive law has been modified in order to correct this point and, at the same time, an implicit solution scheme has been adopted in this new formulation.
- Integration of the **BURGER_AGEING** constitutive model in a THM framework (#33999 - 17.3)
  The constitutive model BURGER_AGEING is available in an MFront version. The BURGER_AGEING model is designed to predict a basic creep which is linear in stress and includes an ageing effect, unlike the BETON_BURGER model. The BURGER_AGEING model is furthermore developed within the framework of a THHM modelling, because of the influence of the capillary pressure and of the temperature on the creep behaviour which it predicts.
- **Hill** constitutive law in Mfront (#34665 - 17.3)
  Introduction of a hyperelastic MFront constitutive law adopted for compressible foams. This is the Hill law, whose potential is expressed as a function of the principal stretches and of the variation of the volume.
- MFront constitutive law for vessel steel **VISC_ISOT_PLAS** (#31499 - 17.4)
  One wishes to capitalise an isotropic elastoviscoplastic MFront constitutive law named VISC_ISOT_PLAS. This model is adopted for irradiated vessel steel (bainitic). It is multi-scale, takes into account the properties of the microstructure, static and dynamic ageing, and large strains.

### 4.2 Improvements of the Mfront/code_aster interface:

- Account taken of the keywords and of the **command variables** by Mfront (#24065/23957 -17.1)
  The keywords `RESI_INTE_MAXI` and `ITER_INTE_MAXI` of COMPORTEMENT had default values which are now removed. Thus, the parameters Epsilon and IterMax of the Mfront file are no longer systematically overwritten. The values of the MFront file are overloaded only if the keyword is present.
RESI_INTE_MAXI and RESI_INTE_RELA are renamed RESI_INTE.
For the management of the command variables, a correspondence is created in Behaviour_module between the established MFront name for each component of a command variable and the aster component name in the external-variable field generated by code_aster. This facilitates the ergonomics of the use of the command variables transmitted to Mfront via the MGIS interface.
- Large strains **GREEN_LAGRANGE** with MGIS (#33782 - 17.2)
  This development consists in connecting large strains GREEN_LAGRANGE with MGIS. In aster, one uses DEFORMATION="GREEN_LAGRANGE" and in MFront, one uses: @DSL DefaultFiniteStrain.
The Cauchy stress sig is returned.
- Use of Mfront possible for the interface constitutive laws **CZM** (#34369 -17.3)
- Improvement of the MFront/MGIS interface: **error codes** (#34642 17.3)
  The management of the error codes of MGIS/MFront was incorrect and may wrongly suggest that a constitutive law has not converged. The three possible return codes of Mfront are taken into account in order to convert them in code_aster.
- Use of the **GRAD_VARI** modellings with MFront constitutive laws (#34627 - 17.3)
  This use is now possible and tested on a von Mises constitutive law with linear isotropic hardening with an AXIS_GRAD_VARI modelling

### 4.3 General points:

- Definition of **AFFE_MATERIAU** in several pieces (#33342 - 17.1)
  One can split into two distinct calls the assignment of AFFE_MATERIAU: on the one hand, the assignment of the materials (AFFE), and on the other hand, the assignment of the command variables (AFFE_VARC), by calling the material field already defined.
- Check of consistency of the elastic parameters for geomechanics (#33602 - 17.1)
  In DEFI_MATERIAU, with the keywords ELAS and ELAS_FO, one could enter only E and nu. For many materials (soils, rocks, etc.), one “knows” K and G better (bulk and shear moduli), or the two wave speeds of the P and S waves: Vp and Vs.
Under ELAS (this is not done for the functions for the moment), one can now supply either (E, NU), or (K, MU), or (CELE_P, CELE_S, RHO).
- Introduction of a vapour-density exchange term **ECHANGE_THM_HR** in THM (#33856 - 17.2)
  One wishes to introduce a mass-exchange condition (water and vapour) at the interface in order to model ventilated media in a more realistic way.
The vapour density being directly related to the relative humidity, this amounts to writing a condition in relative humidity (which is generally the information available to the user).
In the end, it is a non-linear mixed condition on the wall.
A new keyword `ECHANGE_THM_HR` is therefore introduced here in `AFFE_CHAR_MECA`, with GROUP_MA and 3 keywords in order to define coefficients: `HR_EXT` (for the external relative humidity), `ALPHA` (for the value of the exchange coefficient) and `PVAP_SAT` for the value of the saturating vapour pressure.
A version in AFFE_CHAR_MECA_F exists in order to be able to vary PVAP_SAT with the temperature and the other coefficients with time.
- Introduce piloting **PRED_ELAS** for the interface constitutive law **CZM_LAB_MIX** (#34485 - 17.3)
  The piloting in question is introduced, on the basis of a control of the increment of the maximum sliding variable.
The piloting increment is normalised by the critical sliding delta_c, which is a material parameter (a piloting increment of 1 corresponds to a sliding increment of delta_c).
- Introduction of piloting **PRED_ELAS** for the constitutive law **VMIS_ISOT_NL** (#34190 - 17.3), with the aim of facilitating limit-analysis computations and of ensuring more robust analyses when this piloting is already used elsewhere in the structure (reinforced concrete)

## 5 Linear and non-linear dynamics

- Reduction of the memory consumption of **DYNA_VIBRA** (#31151 - 17.1)
  In DYNA_VIBRA, a large block of memory was allocated at the start of the analysis.
Memory consumption has been improved by cutting the jeveux objects into several blocks, so as to be able to allocate / unload them as the analysis proceeds.
- Modification of the computation of the **irreversible displacements** of the command **POST_NEWMARK** (#33544 - 17.1)
  Update of the way in which the command POST_NEWMARK computes the irreversible displacements from the mean acceleration.
The method implemented (construction of a fictitious acceleration signal, clipped at the critical-acceleration value before double integration) gave less satisfaction and seemed less robust than obtaining the velocity signal from the integration of the mean acceleration and clipping for the velocities lower than zero before integration in order to obtain the displacements.
The algorithm is replaced by a simple time integration of the mean acceleration, with clipping at zero if the values are lower than 0 before time integration in order to obtain the displacements.
- Improvement of the performance of the **projection stage** for the computation of the factor of safety with **POST_NEWMARK** (#33542 - 17.1)
  The mesh used for the projection of the stresses is restricted to the 2D finite elements adjacent to the slip line (a stage necessary for the computation of skin stresses **SIRO_ELEM** on the slip line).
The user is allowed to carry out a projection by COLLOCATION of the operator PROJ_CHAMP (in that case, SIEF_NOEU must be precomputed by the user).
The projection is carried out for the NOEU field, then the ELGA stress field is computed time instant by time instant.
- Procedure for **automatic cutting of frequency bands** upstream of a CALC_MODES (#33821 - 17.2)
  A new command is introduced allowing an automatic cutting into balanced frequency bands (i.e., each having a comparable number of eigenfrequencies), upstream of a multi-band modal analysis via CALC_MODES.
This is an iterative method based on an eigenvalue-counting procedure (Sturm test available in INFO_MODE), which it is proposed to implement.
Because of its non-intrusive character, this method simply takes the form of a Python function which will return to the user the “optimal” frequency bands, which can then be entered in a CALC_MODES.
- Implementation of the **HHT scheme without overshooting** in DYNA_NON_LINE (#33909 - 17.2)
  The “No Overshooting” version of the HHT scheme is implemented in DYNA_NON_LINE.
This consists in adapting the formulation proposed by Kaiping (2008) to the non-linear case in order to implement it in DYNA_NON_LINE, then in studying the presence of overshooting via several elementary test cases (by comparing the results obtained with those coming from the HHT scheme currently present in DYNA_NON_LINE).
The NOHHT scheme is thus available in DYNA_NON_LINE, for the formulations in displacement and in acceleration.
- Seismic analysis of tanks: **equivalent pressure EC8/DERESMA** (#31186 - 17.2)
  The usual approach for the analysis of the seismic resistance of tanks is based on Eurocode 8 part 4 (EC8, standard NF EN 1998-4).
The effects of the fluid under earthquake on the wall of the tank are represented by an equivalent pressure field defined by the superposition of several functions in cylindrical coordinates (for vertical cylindrical tanks).
These fields are then imposed on the wall in order to allow an equivalent static seismic analysis of push-over type.
A macro-command carrying out this analysis is developed.
The macro-command DEFI_PRES_EC8 produces a formula usable in AFFE_CHAR_MECA/FORCE_COQUE_FO (#33522).
- Output of the macro-command **MACR_SPECTRE** (#33961 - 17.2)
  The default behaviour of MACR_SPECTRE is changed so as not to print by default the envelope of the horizontal directions of the spectra (denoted H).
- Addition of a **refined mesh output** for the option VERI_MASSE of **POST_NEWMARK** (#33996 - 17.2)
  The mesh used for the computation of the sliding mass in the command POST_NEWMARK is made available to the user, in the case of use of the option `VERI_MASSE`.
- Addition of the possibility of taking into account the **regression scatter for the estimation of ky in POST_NEWMARK** (#33997 - 17.2)
  The computation option for **ky** developed in issue32770 considers a linear regression between the factor of safety and the mean acceleration for a range lying between **0.8 and 1.2** of the factor of safety. The critical-acceleration value retained is that at 3σ of the regression.
The user is given the possibility of choosing another multiplicative factor between **0 and 6** (0 = not taken into account, 6 = conservative estimate at −6σ).
- Addition of the name for **GROUP_MA** during the computation of the **mean acceleration in POST_NEWMARK** (#34011 - 17.2)
  At the output of the macro-command **POST_NEWMARK**, a new mesh is supplied — identical to the mesh used for the dynamic analysis — containing the mesh-cell group used for the computation of the resultant and of the sliding mass (if **VERI_MASSE** is activated).
- Optimisation of the macro-command **DYNA_ISS_VARI** (#34287 -17.3)
  The optimisation of the command was carried out along 2 lines of improvement: optimisation of the computation of the coherence matrix and optimisation of the computation of the eigenvalues and of the energy. A gain by a factor of 10 is noted on a test case.
- Operator **GENE_ACCE_SEISME**: ZPA correction (#30484 - 17.3)
  In the simulation of accelerograms with gene_acce_seisme, one wishes to generate signals which possess exactly the right PGA (the ZPA on the spectrum). The keyword is added: `CORR_ZPA = 'OUI' or 'NON'` (default)
- Shock law with **buckling DYNA_VIBRA** (#34294 17.3)
  The operator DYNA_VIBRA is modified so as to make the relation FLAMBAGE usable with a generic buckling law, given in the form of three functions, namely the buckling threshold, the stiffness and the damping as a function of the total indentation. Thus, the input data of `DYNA_VIBRA/FLAMBAGE` are now identical to those of the constitutive law CHOC_ENDO_PENA usable in DYNA_NON_LINE.
- Operator **COMB_SISM_MODAL**: Addition of the method ENVELOPPE (#34351 - 17.3)
  Addition of the option `ENVELOPPE` to the keyword `ANALYSE`. This “Envelope” analysis option makes it possible to compute the spectral response of a system in the multi-support case with an envelope spectrum of all the input spectra, for each direction. The multi-support system is considered as a MONO_APPUI system.
- Operator **COMB_SISM_MODAL**: New combination methods (#33545 #34054 - 17.3)
  The following combination methods are added in `COMB_SISM_MODAL` under the keyword `COMB_MODE/TYPE "NRC_GROUPING", "NRC_DSA" and "NRC_TEN_PERCENT"`.
- Operator **COMB_SISM_MODAL**: Programming optimisation, memory consumption and performance (#34465-34698-34677 -17.3 - 17.4)
  Improvement of the operator in order to reduce the run time
The programming of the macro COMB_SISM_MODAL is revised in order to remove duplicates, improve the readability of the blocks, improve the use of the variables and the pythonisation of the scripting.
The excess memory consumption appears in the case of the treatment of the option ELNO in COMB_SISM_MODAL: the script is optimised in order to improve the consumption.
- Operator **CALC_FONCTION / SPEC_OSCI HARMO**: addition of a direct-computation option (#34798 -17.4)
  The operator CALC_FONCTION makes it possible to compute response spectra in pseudo-acceleration by the NIGAM method (time solution) or HARMO (filtering in the frequency domain). For the keyword `SPEC_OSCI`, a new keyword `PSEUDO = 'OUI' or 'NON'` is added (default = 'OUI'), so as to be able to compute the absolute acceleration. The computation of the absolute acceleration and of the relative velocity will be possible only with the method `HARMO`.
- Change to the operator **MODE_STATIQUE by grouping the supports** (#34760 - 17.4)
  At present the operator `MODE_STATIQUE` makes it possible to compute, in MULTI_APPUI, the pseudo-modes by blocked degree of freedom, that is: support by support, direction by direction. In certain industrial cases with a very large number of supports, one wishes to group the supports.
The objective of this development is to compute the static modes by support group in MODE_STATIQUE. In MODE_STATIQUE, a keyword `CORRELE="OUI"/"NON"` is added under the factor keyword PSEUDO_MODE. If CORRELE="OUI", then a single mode is created per active direction. The user must specify NOM_APPUI (of length <=8), which will be used to name the mode.
- Improvement of the performance of the transient dynamic analysis in **REST_GENE_PHYS** (#34914 -17.4)
  The objective of this issue is to improve the performance of the transient dynamic analysis while reducing the use of memory as far as possible.
In the operator `REST_GENE_PHYS`, an optional keyword `ENVELOPPE="NORME_MOMENT"` or `ENVELOPPE="VALE_ABS"` is added. Activation of this keyword makes it possible to compute the maximum envelopes at each time instant t, as the computation of the solution advances.
- Changes to **CALC_MISS** with introduction of the single-support loading (#34597 - 17.4)
  The development allows the introduction of the option `EXCIT_MONO`. This new option makes it possible to take into account a mono_appui loading in CALC_MISS.
Two other options are also introduced: `EXCIT_FORC`, which takes the place of ACCE_X, ACCE_Y and ACCE_Z, and `EXCIT_GENE`, which takes the place of EXCIT_HARMO.
The options supplied with `PARAMETRE` have been made compulsory only in the cases where they really have to be used (that is, when MISS3D is called). The same applies to `VERSION` and `TABLE_SOL`, which are used only for Miss3D.
The option `TYPE_EXCIT` is introduced, which obliges the user to enter the type of excitation (in time or in frequency).
The option `LIST_FREQ_CALC` is introduced in order to manage better the definition of the list of computation frequencies (not available for the option TRAN_GENE).
The option `INTERPOL` is introduced, which makes more explicit for the user the possibility of re-interpolating a time function supplied as input.

## 6 Structural elements

### 6.1 General points

- Computation of a field **EGRU of generalised forces in the global frame** (#33252/33584 - 17.1)
  In the command MODI_REPERE, a new keyword NOM_CHAM_RESU has been added and concerns only the field EFGE_ELNO. If `NOM_CHAM_RESU=EGRU_ELNO` is indicated, then a new field named "EGRU_ELNO" is created and contains the field EFGE_ELNO computed in the new frame. The resultat data structure of MODI_REPERE will also contain EFGE_ELNO, which remains unchanged (THE INITIAL FIELD). ### 6.4 Discrete elements

- Update and **improvement of the pairing** of the Python methods for contact (#33736,34349 - 17.3)
  In the operator DEFI_CONT, a new architecture/development of the contact-pairing part is carried out:

  This development makes it possible to carry out additional post-processings on the pairing for the debugging of studies.
- Introduction of **contact/friction in augmented Lagrangian** (#34372 - 17.3) .
  The possibility is introduced of carrying out frictional-contact analyses in large sliding, relying on:

  - a mortar approach with use of a sub-mesh for the numerical integration, representing the intersection of the master and slave mesh cells
  - a formulation of augmented-Lagrangian type
  - a solution by a generalised Newton method
  It is a mixed formulation in which the multipliers are carried by the nodes of the slave elements, in P2P1 in 3D and P2P2 in 2D. Two formulations are introduced: a so-called classical formulation, of Alart & Curnier type, activated by `ALGO_CONT='LAGRANGIEN'` and `VARIANTE='CLASSIQUE'` (the multipliers there are expressed in the local basis of the element), and a so-called robust formulation (the default), proposed by Poulios & Renard, activated by `ALGO_CONT='LAGRANGIEN'` and `VARIANTE='ROBUSTE'`. The multipliers there are expressed in the global frame.
- Addition of a **penalisation method** (#34603 - 17.3)
  The formulation is degraded by removing the multipliers, which leads naturally to a penalised approach. It therefore inherits the characteristics of the original formulation, namely that a single penalisation coefficient is used for the contact *and* for the friction. The quadratic convergence observed on the augmented-Lagrangian formulation is observed. The formulation is activated by ALGO_CONT="PENALISATION".

## 13 Performance

- Performance of **GDEF_LOG** (#33694 - 17.1)
  A great deal of time was spent in “integration of the constitutive law” in the GDEF_LOG case, even with a linear constitutive behaviour, in particular in the computation of the logarithmic strains. The factorisation of the code allows a gain of:

  - ~20% in “integration of the constitutive law” (ex perf02a)
  - 7% on average over all the GDEF_LOG tests
- Reduce the disk footprint of the outputs of **DEFI_SOL_EQUI** (#33639 - 17.1)
  Reduction of the disk footprint of the output files of the macro-command `DEFI_SOL_EQUI` by offering the user the possibility of recording, in the table recorded in the logical unit UNITE_RESU_TRAN, only:

  - acceleration at the free field
  - acceleration at the outcropping bedrock
  - acceleration at the borehole
  - acceleration on the lower nodes of the layers of the soil column (defined either via column 'M' of the soil table, or via the keyword COUCHE)
  For this last point, the user will be able to supply a list with the names of the layers where the accelerations are desired (this can be useful for comparisons with the seismic motion "within"). The keywords `TOUT_ACCE` and `LIST_COUCHE_ACCE` are added.
- Optimisation of the performance of **REST_GENE_PHYS** (#33336 - 17.1)
  In the studies, the time costs of this operator REST_GENE_PHYS (and of DEFI_BASE_MODALE) were disproportionate with respect to those of CALC_MODES (which itself benefits from 3 levels of parallelism and from long-standing optimisations in the modal analysis and in MUMPS).
Now that the latter are optimised. Accelerations of up to a factor of 30 are observed.
- Simplification of the nodal pairing for **LIAISON_GROUP** (#33763 - 17.1)
  The nodal pairing carried out in LIAISON_GROUP was not optimal. There are far too many checks of no usefulness, and the order of the loops has been reversed in order to gain in efficiency.
- **Mesh reading** time (#34447 - 17.3)
  The naming of the nodes and of the mesh cells in aster is removed. The reading of the mesh `LIRE_MAILLAGE` in MED format is rewritten in C++ with the med interface which is already available. One can therefore make the best use of the improvements of the collections in C++ with direct accesses in memory. In the example treated, one goes from 5 h to 7 min.

- Use of **“simple Lagrange multipliers”** (#33452/33510 - 17.1)
  In order to limit the number of degrees of freedom, one would like to be able to make do with simple Lagrange multipliers. This is done for the commands STAT_NON_LINE and CALC_PRECONT. For the cases of the macro-command CALC_PRECONT, the keyword DOUBLE_LAGRANGE='OUI' or 'NON' is introduced in order to ensure the homogeneity of the choices with the loadings.
- Export the local portion of a matrix or of a vector to **petsc4py** (#33690 - 17.1)
  Within the framework of the thesis work on non-linear preconditioning, one wishes to be able to solve a non-linear problem on each sub-domain. To this end, one wishes to export the local portion of a matrix or of a vector to petsc4py. On this basis, one will be able to build a non-linear solver on each sub-domain.
- Stop the STAT_NON_LINE analysis by **a number of time steps** (#34051 - 17.2)
  The idea is to be able to control more finely the list of time instants of a static analysis in order to limit the memory footprint. The user is left the possibility of controlling the number of time steps in STAT_NON_LINE, whatever the initial length of the list of time instants.
The keyword `NB_PAS_MAXI` is used in DEFI_LIST_INST.
If NB_PAS_MAXI is reached, even if one is not at the end of the list of time steps given by the user, the analysis stops cleanly and archives the data.
- Develop the non-linear solver **RASPEN** (#33849 - 17.2)
  Within the framework of the thesis of Mehdi ETTAOUCHI, work is carried out on non-linear solvers based on domain decomposition. One is interested specifically in the Restrictive Additive Schwarz Preconditioned Exact Newton (RASPEN) approach, which has good robustness properties. It is implemented in MECA_NON_LINE.
- Introduction of a second-level preconditioner in **RASPEN** (#34401 - 17.4)
  Within the framework of a thesis, work is carried out on non-linear solvers based on domain decomposition. One is interested specifically in the Restrictive Additive Schwarz Preconditioned Exact Newton (RASPEN) approach, which has good robustness properties; introduced in 17.2, it is now proposed to add the possibility of using a 2nd-level preconditioner. Its objective is to improve the scalability of the method in the presence of numerous sub-domains.
- Allow time-step cutting with **RASPEN** (#35109 - 17.4)
  In order to make RASPEN usable in studies, the possibility of time-step cutting is added.
- Add options in **PETSC/HPDDM** (#34931 - 17.4)
  The aim of this development is to add keywords under the option SOLVEUR for HPDDM.
Another construction of the coarse problem is added, with harmonic_overlap `HARMO` in addition to geneo `GENEO`.
It is suited to the non-symmetric problem. By default, the solver operates with mode AUTO (default): GENEO if the matrix is SYME, otherwise HARMO.
One is also allowed to give the number of modes which one wants to compute for the coarse problem (`NB_MODE`, default=30), and a threshold in order to eliminate the useless MODES in relative terms with respect to the most important one (SEUIL, default=0.0, all the modes are kept).

  There is now only the command `DEBUT` which, in automatic mode (MODE="AUTO", which is the default), initialises the analysis if there is no database and re-reads a database if it exists.
