# u4.63.33 Operator REST_COND_TRAN

## 1 Purpose

Recover in the physical basis of complete models the results of transient evolutions on condensed models.

This operator makes it possible, from results of non-linear transient evolutions on condensed models, to obtain another transient-evolution result on a more complete model.

The concept produced is a concept of type dyna_trans in every possible case:

- following a non-linear transient analysis evol_noli with solution on a modal projection basis. One then recovers on the complete physical model from this modal basis entered by the keyword BASE_MODALE.
- following a linear transient analysis dyna_trans or a non-linear one evol_noli on a mixed model composed of finite elements assigned a possibly non-linear constitutive behaviour and of macro-elements condensing models assigned a linear constitutive behaviour. One then recovers on one of the linear physical models entered by the keyword MACR_ELEM_DYNA.

## 2 Syntax

```text
/ dyna_trans
/ evol_noli = REST_COND_TRAN(
    ◇ reuse = <objet de RESU_FINAL ou RESULTAT>,
    ◇ RESULTAT = dyna_trans / evol_noli,
    ◇ TYPE_RESU = / "DYNA_TRANS" (par défaut),
                  / "EVOL_NOLI",
    ◇ / BASE_MODALE = mode_meca,
      / MACR_ELEM_DYNA = macr_elem_dyna,
    ◇ / TOUT_INST = "OUI" (ou non renseigné),
      / TOUT_ORDRE = "OUI" (ou non renseigné),
      / NUME_ORDRE = int,
      / INST = float,
      / LIST_INST = listr8,
    ◇ CRITERE = / "ABSOLU",
                / "RELATIF" (par défaut),
    # Si: (equal_to("CRITERE", 'RELATIF'))
        ◇ PRECISION = float (défaut: 1e-06),
    # Si: (equal_to("CRITERE", 'ABSOLU'))
        ◆ PRECISION = float,
    ◇ INTERPOL = / "LIN",
                 / "NON" (par défaut),
    ◇ TOUT_CHAM = "OUI" (ou non renseigné),
    # Si: not exists("TOUT_CHAM")
        ◇ NOM_CHAM = / "ACCE" (par défaut),
                     / "DEPL",
                     / "VITE",
    # Si: exists("BASE_MODALE")
        ◇ CHAM_MATER = cham_mater,
        ◇ CARA_ELEM = cara_elem,
    ◇ RESU_FINAL = dyna_trans / evol_noli,
    ◇ TITRE = text,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Operand RESULTAT

♦    RESULTAT = evol

Result of a non-linear transient evolution on models with modal condensation making it possible to obtain another transient-evolution result on a more complete model. Product of an analysis carried out by DYNA_VIBRA or DYNA_NON_LINE.

### 3.2 Operand RESU_FINAL

◊    RESU_FINAL = resphy

If this operand is supplied, the evolution of the transient-evolution result on the complete model may be completed by the time instants of the concept entered by the operand RESULTAT and the result concept is then re-entrant.

### 3.3 Operands BASE_MODALE / MACR_ELEM_DYNA

♦     / BASE_MODALE

Concept of type mode_meca containing a basis of projection modes for the solution of a non-linear transient analysis evol_noli with the keyword PROJ_MODAL in DYNA_NON_LINE. One then recovers on the complete physical model from this modal basis entered here by this keyword. An example of recovery of a result dyna_trans is given in the test SDNV107A. One may also complete the result recovered on the complete model in order to obtain a result of type evol_noli: an example is given in the test SDNV107C.

/ MACR_ELEM_DYNA

This keyword makes it possible to introduce the name of a dynamic macro-element computed on a part of the model on which one will proceed to the recovery on the physical basis. Its supply is necessary when this macro-element is used as a super-mesh cell of substructures defined by the keyword AFFE_SOUS_STRUC in the mixed model, which also comprises classical finite elements, on which one has computed the linear or non-linear evolution entered under the keyword RESULTAT. An example is given in the tests MISS06B (non-linear) and MISS06C (iterative linear).

### 3.4 Operands TYPE_RESU / CHAM_MATER / CARA_ELEM

```text
Dans le cas où l'opérande BASE_MODALE est renseigné, il est possible de compléter le résultat restitué sur le modèle complet afin d'obtenir un résultat de type evol_noli. Il faut alors préciser TYPE_RESU='EVOL_NOLI'. Pour calculer les champs 'SIEF_ELGA' et 'VARI_ELGA' sur la partie de modèle linéaire condensé, il est alors nécessaire de préciser les concepts renseignés par les opérandes CHAM_MATER et CARA_ELEM s'ils existent pour le modèle complet.
```

### 3.5 Operands TOUT_ORDRE / NUME_ORDRE / TOUT_INST / LIST_INST / INST

```text
◊    /    TOUT_ORDRE = 'OUI'
```

In order to recover on all the orders of the concept evol.

```text
/    NUME_ORDRE = num
```

List of integers containing the numbers of the orders on which the recovery is carried out.

```text
/    TOUT_INST = 'OUI'
```

If one wishes to recover on all the time instants contained in the result evol.

> /    LIST_INST = list

List of increasing reals of type listr8 containing the time instants for which one wishes to carry out the recovery.

> /     INST = inst

List of reals containing the time instants on which the recovery is carried out.

For a transient analysis, one checks that the time instants requested by the option LIST_INST do indeed lie in the domain of definition of the result evol.

The results at an arbitrary time instant may be obtained by linear interpolation between the results at two analysis time instants actually contained in the result evol.

### 3.6 Operands TOUT_CHAM / NOM_CHAM

```text
◊    /    TOUT_CHAM = 'OUI'
```

Makes it possible to recover the fields of symbolic name DEPL, VITE and ACCE contained in the result evol.

```text
/    NOM_CHAM = nomcha
```

List of the symbolic names of the fields that one wishes to recover: 'DEPL', 'VITE', 'ACCE'.

### 3.7 Operand INTERPOL

```text
◊    INTERPOL =
```

| 'LIN' : | an interpolation is allowed between two time instants; this interpolation can be used only between two analysis time instants, but may lead to errors if the two archiving time instants [U4.53.03](doc:u4.53.03) are separated by a time which is very long with respect to the periods of the phenomena studied. |
| --- | --- |
| 'NON' : | the recovery must be carried out *stricto sensu*. |

### 3.8 Operands PRECISION / CRITERE

```text
◊    PRECISION = prec
```

```text
◊    CRITERE =
```

When INTERPOL is 'NON', indicates with what precision the search for the time instant to be recovered must be carried out

| 'ABSOLU': 'RELATIF': | search interval [Inst - prec, Inst +prec], search interval [(1 - prec).Inst, (1 + prec) .Inst] Inst being the recovery time instant. |
