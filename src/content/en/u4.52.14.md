# u4.52.14 Operator MODE_STATIQUE

## 1 Purpose

Compute static modes for a unit imposed displacement, force or acceleration. One can also compute coupling modes (interface modes) in order to define a smaller generalised model.

A static mode is the static deformed shape of an isostatic or hyperstatic structure on which one imposes:

- at a **blocked degree of freedom** (node – component) a unit imposed displacement,
- at a **free degree of freedom** (node – component) a unit nodal force,
- in a **direction**, a unit imposed acceleration,
- at a **degree of freedom** (node – component) a unit imposed acceleration.

The coupling modes correspond to the modes of the substructure statically condensed onto the interface. These modes, defined only on the interface, are then statically expanded onto the whole of the substructure.

The operator makes it possible to compute the set of static modes corresponding to several node–component pairs. The stiffness matrix must be assembled using a set of kinematic boundary conditions sufficient for all the rigid-body modes to be removed (operators AFFE_CHAR_MECA [U4.44.01](doc:u4.44.01) or AFFE_CHAR_CINE [U4.44.03](doc:u4.44.03)). It is possible to request only part of the static modes corresponding to these kinematic conditions.

The concept produced can be used to complete a modal base of vibration eigenmodes (operator DEFI_BASE_MODALE [U4.64.02](doc:u4.64.02) or DYNA_ALEA_MODAL [U4.53.22](doc:u4.53.22)), to determine the loadings required for the computation of the entrainment motion under a seismic excitation (operator CALC_CHAR_SEISME [U4.63.01](doc:u4.63.01)) and to introduce the displacements at multi-support anchorages or the correction modes in a spectral analysis (operator COMB_SISM_MODAL [U4.84.01](doc:u4.84.01)).

Produces a concept of type mode_meca.

### 3.5 Nature of the applied loads

#### 3.5.1 keyword MODE_STAT

```text
♦ / MODE_STAT
```

factor keyword for the definition of the static modes with unit imposed displacement. These modes are used to determine the loading due to the multi-support entrainment motion under a seismic excitation (operator CALC_CHAR_SEISME [U4.63.01](doc:u4.63.01)) (cf. reference [R4.05.01](doc:r4.05.01)) or to introduce the displacements at multi-support anchorages in a spectral analysis (operator COMB_SISM_MODAL [U4.84.01](doc:u4.84.01)) (cf. reference [R4.05.03](doc:r4.05.03)). See example §4.1.

##### 3.5.1.1 Operands TOUT / GROUP_NO

```text
♦ /    TOUT = 'OUI'
```

Computation of the modes on all the nodes of the system that have blocked degrees of freedom.

```text
/    GROUP_NO = g_noeu
```

Computation of the modes on the node groups g_noeu (subset of the blocked nodes).

##### 3.5.1.2 Operands TOUT_CMP / AVEC_CMP / SANS_CMP

```text
♦ /    TOUT_CMP = 'OUI'
```

Computation of the modes on all the components blocked at the nodes defined previously.

```text
/    AVEC_CMP = l_cmp
```

Computation of the modes on the components cited only.

```text
/    SANS_CMP = l_cmp
```

Computation of the modes excluding the components cited.

#### 3.5.2 keyword FORCE_NODALE

```text
/ FORCE_NODALE
```

factor keyword for the definition of the static modes with unit imposed force. These modes are used to complete a modal base of vibration eigenmodes (operator DEFI_BASE_MODALE [U4.64.02](doc:u4.64.02) or DYNA_ALEA_MODAL [U4.53.22](doc:u4.53.22)). Cf. reference [R5.06.01](doc:r5.06.01) and see example §4.2.

##### 3.5.2.1 Operand TOUT / GROUP_NO

```text
♦ /    TOUT = 'OUI'
```

Computation of the modes on all the nodes of the system that have **free** degrees of freedom.

```text
/    GROUP_NO = g_noeu
```

Computation of the modes on the node groups g_noeu.

##### 3.5.2.2 Operands TOUT_CMP / AVEC_CMP / SANS_CMP

```text
♦ /    TOUT_CMP = 'OUI'
```

Computation of the modes on all the components **free** at the nodes defined previously.

```text
/    AVEC_CMP = l_cmp
```

Computation of the modes on the components cited only.

```text
/    SANS_CMP = l_cmp
```

Computation of the modes excluding the components cited.

#### 3.5.3 keyword PSEUDO_MODE

```text
/ PSEUDO_MODE
```

factor keyword for the definition of the static modes (or pseudo-modes) with unit imposed acceleration. These modes are used to complete a modal base of vibration eigenmodes (operator DEFI_BASE_MODALE [U4.64.02](doc:u4.64.02) or DYNA_ALEA_MODAL [U4.53.22](doc:u4.53.22)) (cf. reference [R5.06.01](doc:r5.06.01), to determine the correction modes in a spectral analysis (operator COMB_SISM_MODAL [U4.84.01](doc:u4.84.01), keyword MODE_CORR) (cf. reference [R4.05.03](doc:r4.05.03)). One treats the single-support case (operands AXE / DIRECTION, see example §4.3) or the multi-support case (operand GROUP_NO and * CMP, see example §4.4).

##### 3.5.3.1 Operands AXE / DIRECTION / NOM_DIR

```text
♦ /    AXE = l_axe
```

Computes the modes along the axes of the global frame given (l_axe), these axes being $'X'$ , $'Y'$ and $'Z'$ .

```text
♦ /    DIRECTION = l_dir
```

Computes the mode along the given direction (l_dir)

(l_dir): direction vector with 3 components.

```text
♦    NOM_DIR = n_dir
```

User name that one wishes to give to the mode computed in the direction (${n}_{\mathrm{dir}}$ ). By default the name is DIR_N, $N$ being the number of the static mode. This name is mandatory.

##### 3.5.3.2 Operands TOUT / GROUP_NO

```text
♦ /    TOUT = 'OUI'
```

Computation of the modes on all the nodes of the system.

```text
/    GROUP_NO = g_noeu
```

Computation of the modes on the node groups g_noeud.

**Note on use for the seismic analysis:**

In the framework of a static correction in spectral analysis (`COMB_SISM_MODAL`), the taking into account of the pseudo-mode
depends on the type of analysis:

- In single support (`TYPE_ANALYSE='MONO_APPUI'`), only the pseudo-modes defined by `AXE` or `DIRECTION` are used;
- In multi-support (`TYPE_ANALYSE='MULT_APPUI'`), only the pseudo-modes defined by `NOEUD` or `GROUP_NO` are taken into account.

It is strongly recommended to define distinct `MODE_STATIQUE` objects for each case of use in order to avoid
ambiguities when calling `COMB_SISM_MODAL`.

##### 3.5.3.3 Operands TOUT_CMP / AVEC_CMP / SANS_CMP

```text
♦ /    TOUT_CMP = 'OUI'
```

Computation of the modes on all the components at the nodes defined previously.

```text
/    AVEC_CMP = l_cmp
```

Computation of the modes on the components cited only.

```text
/    SANS_CMP = l_cmp
```

Computation of the modes excluding the components cited.

##### 3.5.3.4 Operands CORRELE / NOM_APPUI

```text
◊    CORRELE = / 'OUI'
               / 'NON' [DEFAUT],
```

The modes are correlated; one computes only a single mode per direction.
This mode corresponds to the sum of the modes obtained by applying the acceleration at each node in this direction.

```text
# Si CORRELE = 'OUI'
     ◆ NOM_APPUI = text,
```

One must give a support name that makes it possible to retrieve the mode corresponding to the support.

#### 3.5.4 keyword MODE_INTERF

```text
/ MODE_INTERF
```

factor keyword for the definition of the coupling modes. These modes are used to complete a modal base of vibration eigenmodes (operator DEFI_BASE_MODALE [U4.64.02](doc:u4.64.02) or DYNA_ALEA_MODAL [U4.53.22](doc:u4.53.22)). Cf. reference [R5.06.01](doc:r5.06.01) and see example §4.2.

##### 3.5.4.1 Operand TOUT / GROUP_NO

```text
♦ /    TOUT = 'OUI'
```

Computation of the modes on all the nodes of the system that have **blocked** degrees of freedom.

```text
/    GROUP_NO = g_noeu
```

Computation of the modes on the node groups g_noeu.

##### 3.5.4.2 Operands TOUT_CMP / AVEC_CMP / SANS_CMP

```text
♦ /    TOUT_CMP = 'OUI'
```

Computation of the modes on all the components blocked at the nodes defined previously.

```text
/    AVEC_CMP = l_cmp
```

Computation of the modes on the components cited only.

```text
/    SANS_CMP = l_cmp
```

Computation of the modes excluding the components cited.

##### 3.5.4.3 Operand NB_MODE

```text
♦    NB_MODE= nbmod
```

Number of modes to be computed. It is, for the moment, not possible to specify a frequency band of interest, or the maximum frequency of the modes to be computed. The user must therefore estimate for himself the number of modes to be taken into account. The list of the frequencies associated with the interface modes makes it possible to determine the number of modes to be taken into account in the analysis for the reduced model.

##### 3.5.4.4 Operand SHIFT

```text
♦    SHIFT = shift
```

Shift frequency (shift) used for the computation of the interface modes. The choice of this value makes it possible to improve the accuracy of the computation of the modes. One may choose a shift value corresponding to 10% of the first eigenfrequency expected for the coupling modes. The arbitrary default value is set to $1\mathit{Hz}$ .

### 3.6 keyword SOLVEUR

```text
◊ SOLVEUR = ...
```

This factor keyword is optional: it makes it possible to choose the linear solver used in certain parts of the algorithm. The syntax being common to several commands, please consult the manual [U4.50.01](doc:u4.50.01).

Note: for the keyword MODE_INTERF, one must solve linear systems but for these, the solver is chosen “hard-coded” in the programming (LDLT if there are very few degrees of freedom and MUMPS if there are more).

### 3.7 Operand TITRE

```text
◊ TITRE = titre
```

Attached to the concept produced by this operator [U4.03.01](doc:u4.03.01).

### 3.8 Operand INFO

```text
◊ INFO
```

Indicates the level of printout of information in the “MESSAGE” file:

1: no printout

2: printout of the static modes computed.

### 4.5 Computation of the coupling modes

The coupling modes $\Psi =T\Phi$ are the static expansion of the modes $\Phi$ of the reduced problem.

$$
[{T}^{T}(K-{\omega}^{2}M)T]\Phi =0
\textrm{,}
$$

where $T$ are the static modes with imposed displacement. One obviously does not compute $T$ explicitly in this case. The modes are computed by an approximate method detailed in the reference [R4.06.02](doc:r4.06.02).

```text
minter = MODE_STATIQUE     (    MATR_RIGI = rigidite,
MATR_MASS = masse,
MODE_INTERF=_F    ( GROUP_NO = 'base',
AVEC_CMP =( 'DX','DY'),
NB_MODE=10,
SHIFT=1.,
),
) ;
```
