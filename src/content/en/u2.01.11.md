# u2.01.11 User's guide for the handling of fields and tables

**Summary:**

The aim of this document is to provide the user with a few recipes related to the handling of fields or tables.

This document describes the following cases of field handling:

- Continuing a STAT_NON_LINE analysis after having removed or added elements in the model (e.g.: excavation of a tunnel, placing of the layers of a dam);
- Defining an initial stress state (or of internal variables) from "analytical formulae";
- Applying a pressure on a part (not provided for in the mesh) of the boundary of a 3D structure;
- Computing the integral of the stresses or of a derived quantity on the boundary of a 3D structure;
- Reading back a field that is constant per element and projecting it onto the nodes of the mesh.

And for the tables:

- Evaluating a damping on the computed eigenfrequencies.

## 1 How to continue a STAT_NON_LINE analysis after having removed or added elements in the model

### 1.1 Problem statement

The restart of an analysis with a model made up of additional elements, or conversely of a model restricted to certain elements, requires certain precautions. Indeed, the analysis is no longer carried out on the same number of elements, which means that the fields defining the initial state for the restart of the analysis (displacement, stress and internal-variable fields) must undergo a few adjustments in order to be taken into account in the solution operator.

When one removes finite elements from the model, the problem is a priori fairly simple: it is enough to "forget" information. On the other hand, when one wants to add elements, one must "invent" some.

That is why, in the remainder of this document, we shall treat the case of the addition of elements.

### 1.2 Addition of elements in the model

#### 1.2.1 Objective

We shall present a methodology which makes it possible to carry out this kind of analysis, starting from an example.

![Figure](/figures/u2.01.11/Shape1.gif)

Step 0 Step 1 Step 2 Step 3

In this example one wishes to simulate the progressive addition of elements in the study, for example to simulate the construction of a dam by successively adding layers of elements.

Four steps will be necessary to carry out these analyses: at the first step, the analysis will be carried out on a model made up of the mesh-cell group $\mathrm{E1}$ , at the second on a model made up of the mesh-cell groups $\mathrm{E1}+\mathrm{E2}$ , and so on up to step 4. The user will have taken care, when building the mesh, to define explicitly the mesh-cell groups $\mathrm{E1}$ , $\mathrm{E2}$ , $\mathrm{E3}$ and $\mathrm{E4}$ .

The user will begin by carrying out step 0, which consists in performing the analysis on the mesh restricted to the group $\mathrm{E1}$ . For the following steps, which consist in continuing the analysis carried out previously, several "forms" of implementation can be envisaged:

- either one carries out a restart (new command file): this choice is not relevant if the number of layers of elements is large,
- or one enriches the command file: the size of the command file is a function of the number of restarts, and therefore of the number of layers; this choice is not necessarily judicious.
- or one uses a Python loop: we favour this choice because it has the advantage of being easily extensible in order to take into account the addition of further layers.

In substance, the procedure is the same: with the aim of supplying an initial state to the analysis, it calls the operator CREA_CHAMP:

- to extract the displacement, stress and internal-variable fields,
- to extend these fields to the new model.

##### 1.2.2.1 Initialisation

Each concept produced by these operators will be stored in a Python list. These lists must therefore be allocated. Let $n$ be the number of layers of elements: in this example, $n=4$ .

One will write in the command file:

- MOD=[None]*n,
- MAT=[None]*n,
- CHA=[None]*n,
- U=[None]*n,
- DEP=[None]*n,
- SIG=[None]*n,
- VARI=[None]*n.

## 2 How to define an initial stress state (or of internal variables) with analytical formulae

### 2.1 Objective

The objective is to be able to build two of the fields making up the initial state of a non-linear analysis: the stress field and the field of internal variables.

In both cases, the solution consists in chaining a certain number of CREA_CHAMP commands.

The reader is invited to consult the documentation [U2.01.09](doc:u2.01.09) ("Analytical definition of an initial stress field and of an initial field of internal variables") which answers this problem explicitly. The reader may also look at the command file of the test case zzzz130a which illustrates this implementation.

We present below a "concise" recipe for each of the cases.

### 2.2 Building an analytical stress field

#### 2.2.1 Recipe

- Defining the formulae: from the analytical expression of each stress, one builds the corresponding Aster concept by means of the operator FORMULE.

Example:

```text
SIZZ = FORMULE (REEL='''(REEL:Z) = RHO*G*Z''').
```

(the formula thus defined depends on the variable Z (geometric coordinate)).

- Creation of the field of formulae: one builds a neutral field (without a particular quantity) in order to associate, with each previously defined formula, a component of this field.

```text
Exemple :

SIZF=CREA_CHAMP(OPERATION='AFFE',TYPE_CHAM='ELGA_NEUT_F', AFFE=_F(TOUT=(OUI','NOM_CMP'='X1',VALE_F=SIZZ),...);
```

- Creation of the parameter field:

We must have available a field whose components are among the variables of the formulae of the evaluation field. In this example, we must have available the geometry field (component Z) at the Gauss points. One proceeds in two steps:

- extraction of the geometry field at the nodes:

```text
CHXN = CREA_CHAMP(OPERATION='EXTR',

TYPE_CHAM='NOEU_GEOM_R',NOM_CHAM='GEOMETRIE',...)
```

  - transformation of the field at the nodes into a geometry field at the Gauss points:

```text
CHXG = CREA_CHAMP(OPERATION='DISC',

TYPE_CHAM='ELGA_GEOM_R',...)
```

- Creation of the field by evaluation of the functions:

One can now evaluate the field: one uses the operation EVAL:

```text
SIGZ2=CREA_CHAMP(OPERATION='EVAL', TYPE_CHAM='ELGA_NEUT_R',

CHAM_F=SIZF, CHAM_PARA=CHXG, …)
```

- Creation of the stress field: in order to obtain our analytical stress field, the quantity SIEF_R must be assigned to the evaluation field.

```text
SIGZ=CREA_CHAM(OPERATION='ASSE', TYPE_CHAM='ELGA_SIEF_R',

ASSE=_F(CHAM_GD=SIGZ2,

NOM_CMP='X1',NOM_CMP_RESU='SIZZ'),...).
```

#### 2.2.2 Commands used

| Commands | Functionality |
| --- | --- |
| FORMULE | Creation of the formulae |
| CREA_CHAMP/OPERATION='AFFE' | Creation of the field of formulae |
| CREA_CHAMP/OPERATION='EXTR' | Creation of the parameter field |
| CREA_CHAMP/OPERATION='EVAL' | Creation of the evaluation field |
| CREA_CHAMP/OPERATION='DISC' | Creation of the desired stress field after change of quantity |

### 2.3 Building a non-zero field of internal variables

Two methods can be envisaged for creating a non-zero field of internal variables.

#### 2.3.1 First method

##### 2.3.1.1 Recipe

This method requires knowledge of the number of internal variables of each constitutive law of your STAT_NON_LINE. Document U4.51.11 makes it possible to obtain this information. This method relies on the assignment of all the internal variables of the laws supplied to your STAT_NON_LINE. One uses the assignment operator AFFE of CREA_CHAMP for this purpose.

This operation is carried out in two steps:

- one first creates a NEUT_R map

Example:

```text
VAIN = CREA_CHAMP(OPERATION='AFFE',,TYPE_CHAM='CART_NEUT_R',

AFFE=(_F(GROUP_MA ='GM1',

NOM_CMP=('X1','X2'),VALE=(0,,2,)),

_F(GROUP_MA ='GM2',

NOM_CMP=('X1','X2','X3',X4','X5'),

VALE=(0,0,0,9,2,1)),...)
```

  - one transforms the NEUT_R map into a field at the Gauss points of VARI_R via the operation 'ASSE':

```
VARI=CREA_CHAMP(OPERATION='ASSE', TYPE_CHAM='ELGA_VARI_R',

ASSE=(_F(CHAM_GD=VAIN,

GROUP_MA='GM1',NOM_CMP=('X1','X2'),

NOM_CMP_RESU=('V1','V2'))

_F(CHAM_GD=VAIN,

GROUP_MA='GM2',

NOM_CMP=('X1','X2','X3','X4','X5'),

NOM_CMP_RESU=('V1','V2','V3','V4','V5'),),),

...)
```

The field of internal variables VARI contains 2 internal variables for the elements of the group $\mathrm{GM1}$ and 5 for $\mathrm{GM2}$ . Thus the constitutive law to be applied on the group $\mathrm{GM1}$ of the model in the solution operator will have to comprise exactly 2 internal variables.

##### 2.3.1.2 Commands used

| Commands | Functionality |
| --- | --- |
| CREA_CHAMP/AFFE | Creation of a map in which all the components are assigned. |
| CREA_CHAMP/OPERATION='ASSE' | Transformation of the map into a field of internal variables. |

#### 2.3.2 Second method

##### 2.3.2.1 Recipe

This method makes it possible to assign explicitly only the mesh cells which possess non-zero components. One proceeds as follows:

- One carries out a first dummy analysis (in order to have available *a posteriori* a "model" field of internal variables):

```text
UBID=STAT_NON_LINE(COMPORTEMENT=(_F(GROUP_MA='GM1',RELATION=...),

_F(GROUP_MA='GM2',RELATION=...),), …)
```

- One extracts the field of internal variables VBID from the result UBID:

```text
VBID=CREA_CHAMP(OPERATION='EXTR',RESULTAT=UBID,

TYPE_CHAM='ELGA_VARI_R',NOM_CHAM='VARI_ELGA',...)
```

- This time one assigns the non-zero values:

```text
VAIN1 = CREA_CHAMP(OPERATION='AFFE',,TYPE_CHAM='CART_NEUT_R',

AFFE=(_F(GROUP_MA='GM1',

NOM_CMP=('X2'),VALE=(2,)),

_F(GROUP_MA ='GM2',

NOM_CMP=('X3',X4','X5'),VALE=(9,2,1)),),

...)
```

- One sets to zero the "model" field of internal variables and one overloads it with the non-zero values:

```text
VAIN2 = CREA_CHAMP(OPERATION='ASSE',TYPE_CHAM='ELGA_VARI_R'

ASSE=(_F(TOUT='OUI',CHAM_GD=VBID,

CUMUL='OUI',COEF_R=0.),

_F(GROUP_MA='GM1',CHAM_GD=VAIN1,

CUMUL='OUI',COEF_R=1.,

NOM_CMP=('X2'),NOM_CMP_RESU=('V2'),),

_F(GROUP_MA='GM2',CHAM_GD=VAIN1,

CUMUL='OUI',COEF_R=1.,

NOM_CMP=('X3','X4','X5'),

NOM_CMP_RESU=('V3','V4','V5'),),),...)
```

##### 2.3.2.2 Commands used

| Commands | Functionality |
| --- | --- |
| STAT_NON_LINE | Creation of a dummy result |
| CREA_CHAMP/EXTR | Extraction of the field of internal variables. |
| CREA_CHAMP/AFFE | Creation of a map in which only the non-zero components are assigned. |
| CREA_CHAMP/ASSE | Transformation of the map into a field of internal variables in order to assemble it with the field extracted from the result (previously reset to zero). |

## 3 How to apply a pressure on a restricted part (not meshed exactly) of the boundary of a 3D structure

It is possible with *Code_Aster* to assign a pressure field on a geometric zone of the part to be analysed which is not necessarily meshed. Indeed, it is enough to create the skin mesh supporting the pressure zone, to create on it a pressure field which one projects onto the mesh of the part. The data setup is then similar to the recovery / projection of a pressure field computed by a CFD code.

In the example below, one wants to assign a pressure on a circular zone centred on a face of a cube, uniformly meshed with HEXA8. The mesh of the disc is produced separately.

![Figure](/figures/u2.01.11/1000020000000252000000D4C6794B7ED83EBA4E.png)

*Note:*

*One checks the value of the total force resultant by a computation of the integral of the pressure over the assigned zones. Indeed, the projection operation induces a loss (proportional to the coarseness of the mesh) which it is advisable to measure.*

We shall concern ourselves with the creation of the load CHA_PROJ. The various steps are the following:

- reading of the mesh (disc) carrying the pressure force;
- creation of the pressure field on the disc;
- projection of the pressure field from the disc onto the structure being analysed;
- creation of the load.

We shall detail each of these steps.

### 3.1 Step 1: creation of the pressure field on the disc

- **Creation of a pressure field constant per element**

```text
VAL =CREA_CHAMP(    TYPE_CHAM    =    'ELEM_PRES_R',
OPERATION    =    'AFFE',
MODELE        =    modele2,
PROL_ZERO    =    'OUI',
AFFE    =_F(    GROUP_MA = 'disque',
NOM_CMP = 'PRES',
VALE = 100000000. ),
...)
```

- **Creation of a result of type** EVOL_CHAR **from this field**

```text
RES_PRES=CREA_RESU(OPERATION = 'AFFE',

TYPE_RESU = 'EVOL_CHAR',

NOM_CHAM = 'PRES',

AFFE = _F(CHAM_GD = VAL ,

MODELE = modele2,

INST = 0. ), )
```

### 3.2 Step 2: projection of the pressure field from the disc onto the structure being analysed

```text
RES_PROJ=PROJ_CHAMP(METHODE='COLLOCATION',

RESULTAT=RES_PRES,

MODELE_1=modele2,

MODELE_2=MODE,

DISTANCE_MAX=1.,

CAS_FIGURE='2.5D',

PROL_ZERO='OUI',

VIS_A_VIS=_F(GROUP_MA_1='disque',

GROUP_MA_2='Group_1',),

TOUT_ORDRE='OUI',);
```

### 3.3 Step 3: creation of the load

For the creation of the loading, one uses the loadings that evolve in time, of type evol_char, produced by LIRE_RESU [U7.02.01](doc:u7.02.01) (or CREA_RESU), and containing pressure fields, volume force densities in 2D or 3D and surface force densities in 2D or 3D.

```text
CHA_PROJ=AFFE_CHAR_MECA(MODELE=MODE,

EVOL_CHAR=RES_PROJ,)
```


## 4 How to compute the integral of the stresses or of a derived quantity on the boundary of a 3D structure

### 4.1 Objective

The user has a stress field (at the Gauss points). He wishes to integrate each component on the boundary of his model or to compute a derived quantity such as an axial moment.

| ${\int}_{S}{\sigma}_{xx}\mathit{ds}$ ${\int}_{S}{\sigma}_{xx}.y\mathit{ds}$ |
| --- |

The computation of the integral is done by the command POST_ELEM. When one wishes to integrate a quantity derived from a field, it must be defined (FORMULE) and evaluated (CREA_CHAMP) beforehand.

The stresses at the Gauss points are not computed directly on the faces, so the user is faced with a few difficulties. A recipe has been established in order to be able to carry out this computation. It is presented below.

For more details, one will consult the test case tplv07a which implements this recipe in a thermal setting in order to compute the outgoing flux on a boundary.

### 4.2 Recipe

#### 4.2.1 Step 1: computation of the 3D stress field at the nodes

First of all, the stress fields at the nodes must be computed.

```text
CALC_CHAMP(CONTRAINTE='SIGM_NOEU',RESULTAT=...,)
```

The following step consists in building a neutral field whose values:

- are located at the Gauss points of the mesh cells (2D and 3D), and
- correspond to the values of the stresses.

#### 4.2.2 Step 2: computation of a neutral field corresponding to the stresses

It is assumed that the 3D model (MO3D) which was used to carry out the analysis contains, in addition to the "3D" elements, boundary elements (facets) on all its boundaries.

##### 4.2.2.1 Case of the integration of an existing field

1. Extraction of the stress field at the nodes:

```text
SIGNO=CREA_CHAMP(OPERATION='EXTR', TYPE_CHAM='NOEU_SIEF_R',

NOM_CHAM='SIEF_NOEU',RESULTAT=...,INST=...)
```

1. Transformation of the field SIGNO into a neutral field:

```text
NEUTNO=CREA_CHAMP(OPERATION='ASSE', TYPE_CHAM='NOEU_NEUT_R',MODELE=MO3D,

PROL_ZERO='OUI',ASSE=_F(TOUT='OUI',CHAM_GD=SIGNO,

NOM_CMP=('SIXX','SIYY','SIZZ'),

NOM_CMP_RESU=('X1','X2','X3'),)
```

##### 4.2.2.2 Case of the integration of a derived field (for example for the computation of an axial moment or of a thermal flux)

When the quantity to be integrated does not exist directly, it must be built. The approach is then exactly the same as that described in § 2.2.1. One will begin by defining the integrand with the operator FORMULE, then a field of functions of type NEUT (CREA_CHAMP/OPERATION='ASSE') and finally one will evaluate it (CREA_CHAMP/OPERATION='EVAL').

One will also refer to the test case tplv07a for an example in thermal analysis.

#### 4.2.3 Step 3: computation of the integral on the boundary

It is enough to integrate the field NEUTNO on the boundary mesh cells. For example, for the face 'HAUT', the command is the following:

```text
INT=POST_ELEM(CHAM_GD=NEUTNO, MODELE=MOD3D,

INTEGRALE=_F(GROUP_MA='HAUT',

NOM_CMP=('X1','X2','X3'),),)
```

### 4.3 Commands used

| Commands | Functionality |
| --- | --- |
| CALC_CHAMP | Creation of the stress fields at the nodes by element at the various time instants. |
| CALC_CHAMP | Creation of the stress fields at the nodes at the various time instants. |
| AFFE_MODELE | Creation of a 3D model. |
| CREA_CHAMP/EXTR | Extraction of the stress field at the nodes at the time instant INST. |
| (FORMULE) | Definition of the integrand where applicable. |
| CREA_CHAMP/ASSE (CREA_CHAMP/AFFE) | Transformation of the stress field into a neutral field. Creation of a neutral field of functions. |
| (CREA_CHAMP/EVAL) | Evaluation of the field of functions where applicable. |
| POST_ELEM | Computation of the integral by specifying the mesh-cell groups of the face. |

## 5 How to read back a field constant per element and project it onto the nodes of the mesh

### 5.1 Objective

The user has a field with 3 components, constant per element, in MED format. He wishes to be able to project it onto the nodes of another mesh.

More precisely, one considers 2 meshes. The first is a mesh made up of surface mesh cells on which a field constant per mesh cell has been computed (coming, for example, from a fluid analysis). The second is a line mesh (representing, for example, a piping line onto which one wishes to project the field computed on the first mesh). The aim is therefore to read the field back on mesh 1 and to transfer it to the nodes of mesh 2.

![Figure](/figures/u2.01.11/1000020100000322000002F231F285324883E7C9.png)

For the technique presented here to work, it is enough simply that the meshes be parallel to one another (for example, they must both lie along the z axis) and that they have a range of coordinates in common along the axis along which they are parallel.

### 5.2 Method

#### 5.2.1 Reading back the MED file

The reading back is done in two steps:

1. Reading back of mesh 1:

  - MAIL1 = LIRE_MAILLAGE(FORMAT = 'MED',);

- Reading back of the field with LIRE_CHAMP. Indeed, it is LIRE_CHAMP which most simply makes it possible to read back fields that are constant per element, via the production of the map (in the sense of *Code_Aster*). The field to be read back is called here 'ForceLineique'; one stores it in a map with 3 components of error-indicator type (this last point is incidental, because one uses it only as a container):

CH1=LIRE_CHAMP(FORMAT = 'MED',

MAILLAGE = MAIL1,

UNITE = 20,

NOM_MED = 'ForceLineique',

INST = 0.0001,

TYPE_CHAM = 'CART_ERRE_R',

NOM_CMP = ('ERREST','NUEST','SIGCAL',),

NOM_CMP_MED = ('FX','FY','FZ',),);

#### 5.2.2 Creation of the result and projection of the field

In order to be able to project the field by means of PROJ_CHAMP, it must first be stored in a result data structure by using the command CREA_RESU:

1. Creation of the result:

EVOL1=CREA_RESU(OPERATION = 'AFFE',

TYPE_RESU = 'EVOL_NOLI',

NOM_CHAM = 'ERME_ELEM',

AFFE = (_F(CHAM_GD = CH1,

INST = 0.0001,),),);

1. Projection:

EVOL2=PROJ_CHAMP(RESULTAT = EVOL1,

NOM_CHAM = 'ERME_ELEM',

MODELE_1 = MO1,

MODELE_2 = MO2,

TYPE_CHAM = 'NOEU',);

where MO1 and MO2 are models resting respectively on mesh 1 and on mesh 2 (the reading back of which is not set out here). These models must be consistent with one another and, of course, with the subsequent use that one wishes to make of the field. Consequently, their creation is not part of this explanation, because it depends on the application sought.

In the end, one now obtains a new result data structure containing a nodal field defined on mesh 2. A last (optional) step consists in modifying the name and the type of the field in order to obtain a true nodal field. In what follows, this is what one will seek to obtain by converting the error field obtained into a displacement field (nodal field with 3 components).

#### 5.2.3 Modification of the type of the field

The last step breaks down into two sub-steps:

1. Extraction of the field:

CHTMP1 = CREA_CHAMP(OPERATION = 'EXTR',

NOM_CHAM = 'ERME_ELEM',

TYPE_CHAM = 'NOEU_ERRE_R',

RESULTAT = EVOL2,

INST = 0.0001,);

1. Conversion of the field:

CHNOFIN = CREA_CHAMP(OPERATION = 'ASSE',

TYPE_CHAM = 'NOEU_DEPL_R',

MODELE = MO2,

ASSE = (_F(CHAM_GD = CHTMP1,

COEF_R = 1.0,

TOUT = 'OUI',

NOM_CMP = ('ERREST',

'NUEST',

'SIGCAL'),

NOM_CMP_RESU = ('DX',

'DY',

'DZ'),),),);

## 6 How to use the value of the computed eigenfrequencies to evaluate the damping

One wishes to interpolate a damping function $F(\mathit{FREQ})=\text{f\_amor}$ on the eigenfrequencies of a model.

The eigenfrequencies and eigenmodes are obtained by CALC_MODES.

modes = CALC_MODES(…)

One extracts only the list of the computed frequencies by doing the following (one obtains a table made up of a column with the order numbers and a column with the frequencies):

tab = RECU_TABLE(RESU=modes,

NOM_PARA='FREQ')

The trick consists in creating an identity function on the list of frequencies $G(\mathit{FREQ})=\mathit{FREQ}$ by recovering the values from the table:

g_freq = RECU_FONCTION(TABLE=tab,

PARA_X='FREQ',

PARA_Y='FREQ')

The damping evaluated on the eigenfrequencies is therefore f_amor = F(G(FREQ)), that is:

amor = CALC_FONCTION(COMPOSE=_F(FONC_PARA=g_freq,

FONC_RESU=f_amor))

This example is available in sdld22a.com1.
