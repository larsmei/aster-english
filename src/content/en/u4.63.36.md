# u4.63.36 Operator POST_GENE_PHYS

## 1 Purpose

Recover in the physical basis part of the results in generalised coordinates.

This operator makes it possible to recover in the physical space results obtained on a system in generalised coordinates by modal recombination methods. Unlike the operator REST_GENE_PHYS, this operator makes it possible to limit the recovery by filtering on:

- One or more groups/lists of nodes or of mesh cells
- One or more fields at the nodes or at the elements, for all the components or only those of interest
- A list of order numbers, frequencies, or time instants according to the type of generalised result

In addition, the operator automatically takes the static correction into account during the recovery. It also makes it possible to extract absolute displacements and velocities for multi-support systems and to compute the absolute acceleration in the single-support case as well as in the multi-support case.

The concept produced is of type table. It may be handled by the classical post-processing operators in *Code_Aster* (RECU_TABLE, RECU_FONCTION, IMPR_TABLE).

## 2 Syntax

```text
table = POST_GENE_PHYS(
    ◆ RESU_GENE = tran_gene / harm_gene,
    ◇ MODE_MECA = mode_meca,
    ◆ OBSERVATION = _F(
         ◇ NOM_CHAM = / "DEPL" (par défaut),
                      / "VITE",
                      / "ACCE",
                      / "DEPL_ABSOLU",
                      / "VITE_ABSOLU",
                      / "ACCE_ABSOLU",
                      / "FORC_NODA",
                      / "EFGE_ELNO",
                      / "EGRU_ELNO",
                      / "SIPO_ELNO",
                      / "SIGM_ELNO",
                      / "EFGE_ELGA",
                      / "SIGM_ELGA",
         ◇ NOM_CMP = text,
         ◇ / INST = float,
           / LIST_INST = listr8,
           / TOUT_INST = "OUI" (ou non renseigné),
           / NUME_ORDRE = int,
           / TOUT_ORDRE = "OUI" (ou non renseigné),
           / FREQ = float,
           / LIST_FREQ = listr8,
         # Si: (exists("INST")) or (exists("LIST_INST")) or (exists("FREQ")) or (exists("LIST_FREQ"))
             ◇ CRITERE = / "ABSOLU",
                         / "RELATIF" (par défaut),
             # Si: (equal_to("CRITERE", 'RELATIF'))
                 ◇ PRECISION = float (défaut: 1e-06),
             # Si: (equal_to("CRITERE", 'ABSOLU'))
                 ◆ PRECISION = float,
         ◆ | GROUP_NO = grno,
           | GROUP_MA = grma,
         # Si: (equal_to("NOM_CHAM", 'ACCE_ABSOLU'))
             ◇ & ACCE_MONO_APPUI = formule / nappe / fonction,
               & DIRECTION = float,
      ),
    ◇ TITRE = text,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

**Note**: Recovery of the results by the operator POST_GENE_PHYS is not available for analyses in dynamic substructuring.

### 3.2 Operand MODE_MECA

```text
◊    MODE_MECA = mode
```

Concept of type mode_meca containing a basis of eigenmodes of the structure.

In the absence of this operand, the recovery basis for the modal recombination is retrieved automatically from the generalised result res_gen at the input of the operator.

### 3.3 Keyword OBSERVATION

This factor keyword may be repeated as many times as there are recoveries. For each of the observations, the user is free to choose the name of the field and its components, the order numbers, and the geometric support of the recovery.

In the table produced, each occurrence of the keyword OBSERVATION is indexed by the parameter NUME_OBS of the table.

#### 3.3.1 Filtering by the name of the field and its components

```text
♦ NOM_CHAM = / 'DEPL',          [DEFAUT]
              / 'VITE',
              / 'ACCE',
              / 'DEPL_ABSOLU',
              / 'VITE_ABSOLU',
              / 'ACCE_ABSOLU',
              / 'FORC_NODA',
              / 'EFGE_ELNO',
              / 'EGRU_ELNO',
              / 'SIPO_ELNO',
              / 'SIGM_ELNO',
              / 'EFGE_ELGA',
              / 'SIGM_ELGA',
```

This keyword defines, for the observation in progress, the name of the field to be recovered. Note that for the force and stress fields, it is up to the user to make sure that these have indeed been computed on the modal projection basis with the operator CALC_CHAMP. Before the analysis, the operator POST_GENE_PHYS checks the existence of these fields in the projection basis.

```text
◊    NOM_CMP = lcomp,                [l_K]
```

List of the names of the components of the field to be recovered.

This keyword is optional. If it is absent, all the components of the field are retrieved and taken into account.
If the user specifies a list of components, the operator POST_GENE_PHYS first checks the existence of
these components in the requested field before carrying out the analysis.

#### 3.3.2 Filtering by selection of the geometric support of the recovery

```text
♦    /    GROUP_NO    = lgrno,        [l_noeud]
     /    GROUP_MA    = lgrma,        [l_gr_ma]
```

It is mandatory to specify one of these 2 keywords. This makes it possible to define the geometric support for the recovery of the requested field (list of the node/mesh-cell groups).

**Note:**

For the recovery of an elementary field (**_EL*), it is indispensable to specify
the keyword `GROUP_MA` in order to identify the groups of elements concerned.

For a nodal field, the user may define the nodes directly via the keyword
`GROUP_NO`, or specify the mesh cells carrying the nodes of interest for the recovery
by means of the keyword `GROUP_MA`.

#### 3.3.3 Filtering by the order numbers, time instants, or analysis frequencies

```text
◊    /    TOUT_ORDRE    = 'OUI',      [DEFAUT]
     /    NUME_ORDRE    = num,        [l_I]
     /    TOUT_INST     = 'OUI',
     /    INST          = inst,       [l_R]
     /    LIST_INST     = list,       listr8
     /    FREQ          = freq,       [l_R]
     /    LIST_FREQ     = list,       listr8
```

By default, the recovery is carried out on all of the order numbers stored in the result:
that is, on all the time instants for a transient analysis, and on all the frequencies
for a harmonic analysis.

It is possible for the user to limit the recovery to part of the analysis: a list of
order numbers (NUME_ORDRE), of time instants (INST, LIST_INST), or of frequencies (FREQ, LIST_FREQ).
It is important to note that no interpolation of the results is carried out. The time instants or
frequencies requested must necessarily correspond to the time instants or frequencies present in
the concept *tran_gene* or *harm_gene* supplied as input.

The following operands make it possible to adjust the criteria for selecting the time instants or frequencies:

```text
◊    CRITERE     = / 'ABSOLU',
                    / 'RELATIF',      [DEFAUT]

◊    PRECISION   = / prec,            [R]
                    / 1.E-06,         [DEFAUT]
```

#### 3.3.4 Taking into account an entrainment acceleration in the single-support case

```text
◊    | ACCE_MONO_APPUI = (gamma1, gamma2, gamma3),          [fonction]
     | DIRECTION        = (dx1, dy1, dz1,
                           dx2, dy2, dz2,
                           dx3, dy3, dz3),                  [l_R]
```

In the single-support case, in order to recover an acceleration in the absolute frame (ACCE_ABSOLU), it is necessary
to specify the functions giving the magnitude of the acceleration of the supports as well as the directions
of their motion. It is possible to supply up to three directions.

**Note 1:**

In the multi-support case, the computation of the absolute displacements, velocities and accelerations requires no
additional information. It is enough to specify a NOM_CHAM among DEPL_ABSOLU, VITE_ABSOLU
and ACCE_ABSOLU. The information relating to the absolute motions of the supports is already stored
in the generalised concept.

**Note 2:**

If a static correction of the loadings has previously been taken into account during the analysis on the
generalised basis (CORR_STAT = 'OUI' in DYNA_VIBRA), this correction is automatically included in
the recoveries of POST_GENE_PHYS.
