# u7.03.12 Operator CALC_MISS

## 1 Purpose

The purpose of this command is to prepare the data, to run the Miss3D software, then to post-process its results in order to produce concepts that can be used in code_aster. Depending on the input arguments of the command, one obtains the harmonic or transient response of the structure, or evolutions of the displacements, velocities and accelerations at certain locations, or else concepts of transient nodal seismic-force load.

This operator can also be used together with DYNA_NON_LINE for non-linear transient analyses, by the Laplace-time method (test case *miss03* and its associated documentation [v1.10.122](doc:v1.10.122)).

Advice on the implementation of soil-structure interaction analyses is given in [u2.06.07](doc:u2.06.07) and [u2.06.05](doc:u2.06.05).

## 3 Operating principle

Depending on its input arguments, CALC_MISS produces a concept whose type varies, or else does not produce a concept:

- If TYPE_RESU is equal to 'FICHIER' or 'FICHIER_TEMPS', no concept is produced. Only the execution of Miss3D is launched. The results (dynamic soil stiffness and seismic forces) are then written in the files identified by the logical units such as UNITE_RESU_IMPE, UNITE_RESU_FORC, UNITE_RESU_MASS, UNITE_RESU_RIGI or UNITE_RESU_AMOR. There is no post-processing of the results coming from Miss3D
- If TYPE_RESU is equal to 'CHARGE', a mechanical load is produced in the form of a nodal force
- If TYPE_RESU is equal to 'TABLE_CONTROL', the Miss3D analysis is the same as for FICHIER. A table is produced containing a point-wise post-processing of the Miss3D results
- Otherwise (TYPE_RESU is equal to 'HARM_GENE', 'TRAN_GENE' or 'TABLE'), one runs Miss3D only if the logical units UNITE_RESU_IMPE and UNITE_RESU_FORC are not supplied. Otherwise, one uses the files supplied as input. Post-processing is then carried out and the requested concept is returned to the user.

```
* Les calculs MISS3D sur de gros modèles (ou avec beaucoup de fréquences) peuvent être longs et coûteux en mémoire. Heureusement ceux-ci peuvent être accélérés en activant un ou deux niveaux de parallélisme. La valeur TYPE_RESU = ’FICHIER_TEMPS’ permet d’en activer deux, les autres valeurs, un seul. Pour plus d’informations on pourra consulter les documentations :ref:`u2.06.07 <u2.06.07>` et :ref:`u2.08.06 <u2.08.06>`
* CALC_MISS produit un concept tran_gene ou harm_gene, incluant les champs d'accélération et de déplacements absolus (exception faite pour le cas de chargement EXCIT_MONO). Dans ce cas, les accélérations sont directement employées pour le calcul du spectre de plancher ; inversement, la déduction des déplacements de sol est obligatoire (à lire avec la commande LIRE_FONCTION (:ref:`u4.32.02 <u4.32.02>`) depuis un fichier spécifique donné par son unité logique) pour obtenir les déplacements relatifs
* Dans le cadre d'un calcul avec l'option EXCIT_MONO, un chargement mono-appui est appliqué au calcul harmonique. Les résultats sont donc fournis en **repère relatif**
* Lors de l'exécution de Miss3D, si le mot-clé MACR_ELEM_DYNA est renseigné, on l'utilise. Sinon, il est créé par CALC_MISS à partir des opérandes BASE_MODALE, MATR_RIGI et MATR_MASS
* Dans le cas où TYPE_RESU vaut FICHIER_TEMPS, on fait un appel à Miss3D pour chaque fréquence de calcul. Ces appels peuvent être faits en parallèle. Pour cela, il suffit d'exécuter la version parallèle MPI de Code_Aster et demander plusieurs processeurs (pas de mot-clé supplémentaire nécessaire)
```

## 4 Definition of the model

### 4.1 Keyword TYPE_RESU

Defines the type of analysis to be performed. Five values are allowed:

- FICHIER: only the execution of Miss3D is carried out. One recovers directly the files produced by Miss3D in the files identified by the logical units UNITE_RESU_IMPE and UNITE_RESU_FORC. CALC_MISS does not return a concept (nothing to the left of the «=» sign)
- FICHIER_TEMPS: only the execution of Miss3D is carried out. One recovers directly the files produced by Miss3D in the files identified by the logical units UNITE_RESU_RIGI, UNITE_RESU_MASS, UNITE_RESU_AMOR and UNITE_RESU_FORC. CALC_MISS does not return a concept (nothing to the left of the «=» sign). This option is specific to the Laplace-time method ([r4.05.07](doc:r4.05.07))
- CHARGE: one computes a mechanical load from the seismic-force file
- HARM_GENE: one computes the harmonic response of the structure (of type harm_gene) after having run Miss3D or from the files coming from a previous solution (TYPE_RESU='FICHIER')
- TRAN_GENE: one computes the harmonic response of the structure and then one returns to the time domain via the inverse Fourier transform (one obtains a concept of type tran_gene) after having run Miss3D or from the files coming from a previous solution (TYPE_RESU='FICHIER')
- TABLE: one computes the harmonic response of the structure to a unit excitation at certain points, and one returns a concept of type table which contains the response functions in displacement, velocity, acceleration and oscillator spectrum recombined over the loading cases
- TABLE_CONTROL: one recovers from the Miss3D analysis the transfer functions at certain control points and the harmonic and transient responses to a supplied acceleration. One produces a concept of type table

### 4.2 Operands PROJET/REPERTOIRE

The keyword REPERTOIRE makes it possible to define a directory (entered by its full path on the execution machine) in which the Miss3D analysis will be run. One will be able to find there all the Miss3D data and result files (for debugging, for example). These files will begin with a root name given by the operand PROJET (which is equal to MODELE by default).

```
Si REPERTOIRE n'est pas défini, l'exécution aura lieu dans un répertoire temporaire qui sera détruit en fin de calcul.
```

### 4.3 Operand MACR_ELEM_DYNA

This is the dynamic macro-element of the structure (type macr_elem_dyna) produced by the command of the same name ([u4.65.01](doc:u4.65.01)).

### 4.4 Operand BASE_MODALE

Basis of the modes of the structure. If MACR_ELEM_DYNA is not supplied, this modal basis is used to determine it.

```
* Quand on n'effectue que le calcul Miss3D (TYPE_RESU='FICHIER'), on fournit soit MACR_ELEM_DYNA, soit BASE_MODALE
* Quand on demande le post-traitement, il est nécessaire de renseigner le mot-clé BASE_MODALE (utilisé pour le calcul harmonique). On peut malgré tout fournir un macro-élément spécifique en cas de besoin
```

### 4.5 Operands MATR_RIGI and MATR_MASS

These keywords make it possible to supply the stiffness and mass matrices of the structure. They will be used during the harmonic analysis and, where applicable, to create the dynamic macro-element.

### 4.6 Operand MATR_AMOR

This keyword makes it possible to supply a damping matrix of the structure used during the harmonic analysis, alternating with the use of modal damping with the keyword AMOR_REDUIT.

### 4.7 Operand UNITE_IMPR_ASTER

Logical unit number on which one can recover the file produced by the operator IMPR_MACR_ELEM, format 'MISS_3D', called internally by CALC_MISS. The default value is 25.

### 4.8 Operands UNITE_RESU_IMPE, UNITE_RESU_RIGI, UNITE_RESU_MASS, UNITE_RESU_AMOR, UNITE_RESU_FORC

Logical unit numbers of the files containing the dynamic soil stiffness (or its decomposition into stiffness, mass and damping) and the seismic forces by frequency.

```
* Si on ne demande que le calcul Miss3D, UNITE_RESU_IMPE, UNITE_RESU_RIGI, UNITE_RESU_MASS, UNITE_RESU_AMOR et UNITE_RESU_FORC sont utilisés suivant les cas pour stocker les fichiers résultats
* Si on demande un post-traitement, il ne faut utiliser ces arguments que si le calcul Miss3D a été exécuté auparavant (les fichiers sont alors des données pour CALC_MISS)
* Les opérandes UNITE_RESU_RIGI, UNITE_RESU_MASS, UNITE_RESU_AMOR sont d'un usage spécifique à la méthode Laplace-temps (cas TYPE_RESU='FICHIER_TEMPS') et la présence de UNITE_RESU_AMOR ou de UNITE_RESU_MASS rend obligatoire le mot-clé facteur MATR_GENE
* Dans l'exécution de Miss3D, le post-traitement de la rigidité dynamique (respectivement des forces sismiques) n'est effectué que si le mot-clé UNITE_RESU_IMPE (respectivement UNITE_RESU_FORC) est renseigné. Ceci permet de réduire un petit peu le temps de calcul
```

### 4.9 Operand GROUP_MA_INTERF

This keyword makes it possible to define the list of surface mesh-cell groups constituting the soil-structure interface, passed internally to the operator IMPR_MACR_ELEM ([u7.04.33](doc:u7.04.33)).

### 4.10 Operands GROUP_MA_FLU_STR/GROUP_MA_FLU_SOL/GROUP_MA_SOL_SOL

In the case of a soil-fluid-structure interaction, these keywords make it possible to complete the list of surface mesh-cell groups made up respectively of the fluid-structure, fluid-soil and free-soil interfaces (passed internally to the operator IMPR_MACR_ELEM ([u7.04.33](doc:u7.04.33)).

```
Le mot-clé GROUP_MA_SOL_SOL pour l'interface sol libre peut être aussi présent optionnellement en interaction sol-structure, afin de modéliser les liaisons imparfaites entre le sol et la structure le long de l'enfoncement de la fondation.
```

### 4.11 Operand TABLE_SOL

The data describing the soil stratifications are supplied in the form of a table produced by the command DEFI_SOL_MISS ([u7.02.34](doc:u7.02.34)).

```
Cette donnée est à fournir exclusivement dans le cas ou la macro-commande CALC_MISS fait appel à Miss3D.
```

### 4.12 Operand MATER_SOL

For a homogeneous soil, one supplies the soil properties:

- E is Young's modulus
- NU Poisson's ratio
- RHO the density

```
Cette donnée est à fournir exclusivement dans le cas ou la macro-commande CALC_MISS fait appel à Miss3D.
```

### 4.13 Operand MATER_FLUIDE

In the case of a soil-fluid-structure interaction analysis (ISSF='OUI'), one supplies the fluid properties:

- RHO is the density
- CELE the wave celerity
- AMOR_BETA the damping.

One also indicates whether or not the domain represents a fluid half-space, according to the definition of Miss3D.

```
Cette donnée est à fournir exclusivement dans le cas ou la macro-commande CALC_MISS fait appel à Miss3D.
```

### 4.14 Operand SOURCE_SOL

Factor keyword defining the loads arising from point sources in the soil domain, given by their direction and the coordinates of the source.

```
* Cette donnée est à fournir exclusivement dans le cas TYPE_RESU='FICHIER'
* Le vecteur DIRECTION est automatiquement normé à 1 par Miss3D
```

### 4.15 Operand SOURCE_FLUIDE

Factor keyword defining the loads arising from point pressure sources in the fluid domain, given by the coordinates of the source.

```
Cette donnée est à fournir exclusivement dans le cas TYPE_RESU='FICHIER'
```

### 4.16 Operand AMOR_REDUIT

List of the reduced dampings passed internally to DYNA_VIBRA ([u4.53.03](doc:u4.53.03)). Let $nb_{mode}$ be the number of dynamic modes defined in the modal basis and $nb_{amor}$ the number of reduced dampings supplied:

- If $nb_{amor}<nb_{mode}$, then one completes the list of dampings up to $nb_{mode}$ with the last damping in the list
- One then adds a zero damping, which will be applied to the static modes present

### 4.17 Operand SURF

This operand indicates whether or not one has a shallow foundation.

#### 4.17.1 Operand ISSF

This operand indicates whether or not one has a fluid domain and therefore also fluid-structure, soil-fluid and free-soil interfaces supplied by the operands GROUP_MA_FLU_STR, GROUP_MA_FLU_SOL and GROUP_MA_SOL_SOL in the operand PARAMETRE.

## 5 Miss3D analysis – factor keyword PARAMETRE

This factor keyword makes it possible to enter the parameters of the Miss3D analysis: interface type, foundation type, analysis frequencies, spectral and spatial discretisation, which complete the soil description data. **These data are necessary as soon as Miss3D must be run**.

The mode AUTO='OUI' makes it possible to define automatically the value of certain parameters, in accordance with the advice in the documents [u2.06.07](doc:u2.06.07) and [u2.06.05](doc:u2.06.05). This concerns the parameters OFFSET_MAX, OFFSET_NB, DREF, RFIC and SPEC_MAX.

### 5.1 Operands FREQ_MIN, FREQ_MAX, FREQ_PAS

These operands supply the bounds and the frequency step of the Miss3D analysis in the frequency-domain solution (thus one excludes TYPE_RESU='FICHIER_TEMPS').

### 5.2 Operand LIST_FREQ, FREQ

These operands supply the list of real frequencies of the Miss3D analysis. This datum is mutually exclusive with the keywords FREQ_xxx.

```
* On utilise FREQ dans le cas où on crée la liste de fréquences *à la main* et LIST_FREQ dans le cas où on utilise une liste de réels produite par code_aster via DEFI_LIST_REEL.
* L'utilisation de LIST_FREQ (ou FREQ) n'est possible que si on fait le calcul Miss3D seul ou bien si on cherche la réponse à une excitation harmonique (Présence d'EXCIT_GENE).
* Dans les autres cas, il est nécessaire de fournir une liste de fréquences à pas constant en utilisant les mots-clés FREQ_MIN, FREQ_MAX, FREQ_PAS.
```

### 5.3 Operand FREQ_IMAG

This operand is to be used only in the mode TYPE_RESU='FICHIER_TEMPS' (which corresponds to the Laplace-time method). Indeed, this keyword serves to define the imaginary part of the complex frequency when one places oneself in the Laplace domain. In all the other types of analysis, one is in the frequency domain and the frequency is then always purely real.

```
On ne peut utiliser qu'un seul mot-clé à la fois parmi FREQ_IMAG, FREQ_MIN, LIST_FREQ et FREQ.
```

### 5.4 Operand Z0

This operand gives the elevation of the free surface of the soil.

### 5.5 Operand RFIC

This operand indicates the value of the parameter, homogeneous to a characteristic distance, necessary in order to eliminate the fictitious resonances.

```
Il s'agit d'une option disponible exclusivement dans le cadre d'une fondation enfoncée.
```

### 5.6 Operand DREF

This operand indicates the value of the parameter, homogeneous to a characteristic distance, which makes it possible to eliminate the vertical slope of the impedance for a zero frequency.

### 5.7 Operand ALLU

This operand indicates the value of the absorption coefficient, between 0 and 1, at the soil-fluid interface. Valid if ISSF='OUI'.

### 5.8 Operands OFFSET_MAX, OFFSET_NB

These operands supply the maximum bound and the subdivision of the spatial discretisation for the computation of the dynamic stiffness by Miss3D from the soil data.

### 5.9 Operands SPEC_MAX, SPEC_NB

These operands supply the maximum bound and the subdivision of the spectral discretisation for the computation of the dynamic stiffness by Miss3D from the soil data.

### 5.10 Operand TYPE

This operand makes it possible to store the frequency-dependent dynamic stiffness matrix in a file of binary or ascii format. If one wants to exploit them with the command LIRE_IMPE_MISS ([U7.02.32](doc:u7.02.32)), one must then take care to use the same type of file.

### 5.11 Operand AUTO

This operand makes it possible to trigger the automatic mode for defining the value of certain Miss3D parameters, in accordance with the advice in the documents [u2.06.07](doc:u2.06.07) and [u2.06.05](doc:u2.06.05). This concerns the parameters OFFSET_MAX, OFFSET_NB, DREF, RFIC and SPEC_MAX. These automatic values are displayed in the message file.

```
A noter que si avec ce mode automatique, l'utilisateur donne quand même la valeur de tout ou partie de ces paramètres, ces valeurs viennent surcharger les valeurs calculées automatiquement.
```

### 5.12 Operand OPTION_DREF

This operand makes it possible to specify, with the mode AUTO='OUI', whether one must use the DREF option. If so, then the code automatically computes the value to give it.

### 5.13 Operand OPTION_RFIC

This operand makes it possible to specify, with the mode AUTO='OUI', whether one must use the RFIC option. If so, then the code automatically computes the value to give it.

### 5.14 Operand COEF_OFFSET

This operand makes it possible to define the oversampling coefficient for the automatic computation of the parameter OFFSET_NB (documents [u2.06.05](doc:u2.06.05) and [u2.06.07](doc:u2.06.07)). By default it is equal to the recommended value of 12 (12 points per element).

## 6 Post-processing

In the case where TYPE_RESU is different from 'FICHIER', 'FICHIER_TEMPS' and 'TABLE_CONTROL', the Miss3D result files are post-processed by CALC_MISS in order to supply the harmonic or transient response of the structure, or evolutions of the characteristic quantities (displacement, velocity, acceleration, oscillator spectrum) at certain post-processing points.

### 6.1 Definition of the loading

There are three different ways of imposing the loading by means of CALC_MISS:

- One can apply the equivalent seismic force evaluated beforehand with Miss3D by multiplying this force by a multiplier function. This is the option EXCIT_FORC
- One can apply a generic loading on the model which was produced beforehand with AFFE_CHAR_MECA by means of the option EXCIT_GENE
- Finally, one can impose a single-support loading at the base of the model via the option EXCIT_MONO

```
Compte-tenu de la différente nature des chargements, on ne peut imposer qu'un seul type pour calcul:

* En effet, l'option EXCIT_FORC produit un résultat en repère absolu, tandis que EXCIT_MONO produit un résultat en repère relatif. Le mélange de chargement n'est donc pas raisonnable
* De l'autre coté, l'option EXCIT_GENE permet de produit un chargement générique (que ça soit un déplacement imposé dans le repère absolu ou un chargement type mono-appui)
```

#### 6.1.1 Operand TYPE_EXCIT

If a loading EXCIT_MONO or EXCIT_FORC is present, one must declare the nature of the loading supplied by the user. Two choices are possible:

- 'INST' for a time-domain loading
- 'FREQ' for a frequency-domain loading

#### 6.1.2 Operands INTERPOL, PAS_INST, INST_FIN

In the case where the user supplies a time-domain loading (TYPE_EXCIT='INST'), one has the possibility of re-interpolating this loading (INTERPOL = 'OUI', by default 'NON'). One must then supply two additional parameters:

- PAS_INST, that is the interpolation time step
- INST_FIN, that is the final time instant of the loading

```
Dans tous les cas, INST_FIN ne peut pas être plus grand que l'instant final de la fonction initiale. En ne connaissant pas la nature du chargement, on ne choisit pas la nature d'un éventuel prolongement. INST_FIN a donc plutôt un fonction de coupure du signal d'entrée .
```

Operand MODELEe

This is the model of the structure (passed to DYNA_VIBRA).

### 6.2 Analysis of the harmonic or transient response of the structure

One is in the case TYPE_RESU='HARM_GENE' (harmonic response) or 'TRAN_GENE' (transient response). One then computes the harmonic response of the structure to the loading supplied (EXCIT_GENE, EXCIT_MONO or EXCIT_FORC).

```
Dans le cas 'TRAN_GENE', on effectue la restitution temporelle en utilisant l'opérateur REST_SPEC_TEMP (option PROL_ZERO).
```

#### 6.2.1 Operands EXCIT_FORC, ACCE_X, ACCE_Y, ACCE_Z, DEPL_X, DEPL_Y, DEPL_Z

The option EXCIT_FORC is used to impose the loading via the equivalent seismic forces computed beforehand with Miss3D. In this case one will supply:

- Either an accelerogram in one or more directions (ACCE_X, ACCE_Y, ACCE_Z)
- Or imposed displacements in one or more directions (DEPL_X, DEPL_Y, DEPL_Z)

```
En fonction de la nature du chargement il faut fournir soit des fonctions réelles (TYPE_EXCIT='INST') soit des fonctions complexes (TYPE_EXCIT='FREQ').
```

#### 6.2.2 Operands EXCIT_HARMO, VECT_ASSE, FONC_MULT, COEF_MULT, FONC_MULT_C, COEF_MULT_C, PHAS_DEG=SIMP, PUIS_PULS

EXCIT_HARMO makes it possible to define a generic load in CALC_MISS, a load which will be supplied as input to DYNA_VIBRA. For more details on the definition of a generic load in DYNA_VIBRA one may refer to the option EXCIT in the documentation [u4.53.03](doc:u4.53.03).

#### 6.2.3 Operands EXCIT_MONO, DIRECTION, ACCE

EXCIT_MONO makes it possible to define a single-support loading at the base of the model. For this, one must specify:

- The direction (keyword DIRECTION) of the entrainment motion ('X', 'Y' or 'Z')
- The multiplier function (keyword ACCE). This multiplier function may be real (TYPE_EXCIT='INST') or complex (TYPE_EXCIT='FREQ')

### 6.3 Analysis of the evolutions at certain points

One is thus in the case TYPE_RESU='TABLE'. In this case, one computes the harmonic response of the structure to a unit acceleration (in the direction or directions requested). Then, for each loading, one recombines at each post-processing location $M$ the unit frequency contributions (equation :eq:`eq-recombinaison`):

$$
{u}_{M}(f)={u}_{x}\times FFT(a_x)+{u}_{y}\times FFT(a_y)+{u}_{z}\times FFT(a_z)
$$

One also computes the $FFT$ of this response and the oscillator spectrum supplied by CALC_FONCTION/SPEC_OSCI. One does the same for ${\dot{u}}_{M}$ and ${\ddot{u}}_{M}$. All these functions are stored in a table. One thus finds, for each loading case (for the first NUME_CAS = 0):

- On the first line, the «loading functions», that is the accelerograms of the excitation (time-domain, NOM_PARA='INST') in the 3 directions: FONC_X, FONC_Y, FONC_Z
- On the second line, the $FFT$ of these signals (NOM_PARA='FREQ')
- Then for each point, the evolution of the displacement, velocity and acceleration. With, for each, the signal, its $FFT$ and the oscillator spectrum

#### 6.3.1 Operands EXCIT_FORC, ACCE_X, ACCE_Y, ACCE_Z

The option EXCIT_FORC is used to impose the loading via the equivalent seismic forces computed beforehand with Miss3D. In this case one will supply an accelerogram in one or more directions (ACCE_X, ACCE_Y, ACCE_Z).

#### 6.3.2 Operand NORME, AMOR_SPEC_OSCI, LIST_FREQ_SPEC_OSCI

These parameters are passed to CALC_FONCTION for the option SPEC_OSCI ([u4.32.04](doc:u4.32.04)), where AMOR_REDUIT has been renamed AMOR_SPEC_OSCI so as not to confuse it with the list of dampings used for the harmonic analysis. Likewise, LIST_FREQ has also been renamed here LIST_FREQ_SPEC_OSCI in order to avoid confusion with the keyword LIST_FREQ.

### 6.4 Post-processing of the results at the control points

One is thus in the case TYPE_RESU='TABLE_CONTROL'.

#### 6.4.1 Operand GROUP_MA_CONTROL

This is the group of point mesh cells locating the control points (passed to IMPR_MACR_ELEM). During post-processing, response functions are created for each of the points, which are taken in the order of definition of this mesh-cell group. Thus, in the table, the point designated PC1 does not in general correspond to a node or node group named PC1. It is the first point mesh cell of GROUP_MA_CONTROL.

#### 6.4.2 Operand TOUT_CHAM

If this operand is absent, one post-processes in time only the accelerations at the control points. If it is present with the value TOUT_CHAM='OUI', one will also post-process in time the velocity and displacement fields.

#### 6.4.3 Operands ACCE_X, ACCE_Y, ACCE_Z, NORME, AMOR_SPEC_OSCI, LIST_FREQ_SPEC_OSCI

Identical to the paragraphs of the option TYPE_RESU='TABLE'.

#### 6.4.4 Table produced

The loading applied in the Miss3D analysis is a unit harmonic acceleration. The first two lines correspond to the accelerations ACCE_X/Y/Z supplied by the user, interpolated with the time step supplied, and its $FFT$:

- At each control point, one recovers the transfer function in the three directions for this excitation. These are the lines with TRANSFERT/FREQ
- Then, one has the combination ${a}_{Mx}(f)={ft}_{x}(f)\times FFT({a}_{x})$ and the same thing in y and z depending on the loading applied
- One also computes the $FFT$ of this response and the oscillator spectrum supplied by CALC_FONCTION/SPEC_OSCI
- All these functions are stored in the table produced

```
Le paramètre de la table désignant le point de contrôle est nommé GROUP_NO pour être homogène au cas TABLE. Comme on l'a vu plus haut, il s'agit simplement d'un numéro de point dans le groupe de mailles des points de contrôle.
```

### 6.5 Definition of the list of analysis frequencies - the operand LIST_FREQ_CALC

The definition of the list of frequencies for the frequency-domain analysis is handled automatically in the case where TYPE_RESU is equal to 'TRAN_GENE'. In the case where the load is supplied in the time domain (TYPE_EXCIT='INST') one would have:

- A frequency step $\Delta f=\frac{1}{n_{pas}\cdot\Delta t}$
- A maximum analysis frequency $f_{max}=\frac{1}{2\Delta t}$

where:

- $n_{pas}$ is the number of time steps of the list of time instants
- $\Delta t$ is the time step

In the case where the load is supplied in the frequency domain (TYPE_EXCIT='FREQ'), the frequency range used is that of the harmonic signal. In the case where TYPE_RESU is equal to 'HARM_GENE','TABLE' or 'TABLE_CONTROL' one can define the list of frequencies via the keyword LIST_FREQ_CALC.

```
Le mot-clé LIST_FREQ_CALC n'est pas à renseigner si TYPE_RESU vaut 'TRAN_GENE'.
```

#### 6.5.1 The parameters AUTO, FREQ_MIN, FREQ_MAX, FREQ_PAS, FREQ and LIST_FREQ

If AUTO is equal to 'OUI', the frequency list is handled automatically as in the case where TYPE_RESU is equal to 'TRAAN_GENE'. If AUTO is equal to 'NON', the user can define the frequency list:

- Either one uses FREQ_MIN, FREQ_MAX and FREQ_PAS to supply respectively the minimum frequency, the maximum frequency and the frequency step
- Or one uses FREQ to supply a list of frequencies by hand
- Or one uses LIST_FREQ to supply a frequency list built with DEFI_LIST_REEL

## 7 Analysis of a seismic-force load

In the case where TYPE_RESU is equal to 'CHARGE', the result file of the frequency-domain seismic forces of MISS3D is post-processed by CALC_MISS in order to supply the transient excitation of seismic forces in one direction of space applied on the soil-(fluid-)structure interface.

### 7.1 Operand MODELE

This is the model of the structure to which one adds a super-element comprising a macro-element obtained from the transient or frequency-domain evolution of the impedance of the soil domain (and possibly of the fluid domain) obtained by means of the code_aster-MISS3D chain through the option TYPE_RESU='FICHIER_TEMPS' or TYPE_RESU='FICHIER' of CALC_MISS.

### 7.2 Operand FONC_SIGNAL

Time-domain imposed-displacement signal, generally obtained by double time integration of an accelerogram. The latter generally corresponds, in the data of the code_aster-MISS3D chain, to an acceleration imposed at the surface of the soil in the far field. The integrations can be obtained directly in the transient domain or in the frequency domain by means of the operator CALC_FONCTION ([u4.32.04](doc:u4.32.04)).

### 7.3 Operand UNITE_RESU_FORC

Makes it possible to define the logical unit of the generated file which will contain the frequency-domain seismic forces computed with the option TYPE_RESU='FICHIER' of CALC_MISS.

### 7.4 Operand FREQ_MAX

This operand supplies the value of the cut-off frequency for the computation of the transient seismic force obtained by the combination of the frequency-domain seismic forces (supplied by UNITE_RESU_FORC) and of the imposed-displacement signal supplied by FONC_SIGNAL.

### 7.5 Operand NOM_CMP

This operand supplies the component (to be chosen among 'DX', 'DY' and 'DZ') giving the direction of the seismic excitation.

```
* On calcule une charge pour une seule direction à la fois
* Dans le cas de sollicitations simultanées dans plusieurs directions, il faut alors créer autant de charges différentes avec l'option TYPE_RESU='CHARGE' de CALC_MISS
```

### 7.6 Operand GROUP_NO_AFFE

This operand supplies the list of node groups on which the seismic load is imposed. These nodes may be real, for example the central node of a foundation made rigid by a LIAISON_SOLIDE relation, or else fictitious, corresponding to modal coordinates linked to the physical coordinates of the dynamic interface of the soil macro-element by a LIAISON_INTERF relation.

### 7.7 Operand ISSF

This operand indicates whether or not one has a fluid domain.

### 7.8 Operand VARI

This operand makes it possible to activate or not the spatial-variability functionalities, as in the operator DYNA_ISS_VARI ([u4.53.31](doc:u4.53.31)).

### 7.9 Operand UNITE_RESU_IMPE

Makes it possible to define the logical unit of the generated file which will contain the frequency-domain impedances computed with the option TYPE_RESU='FICHIER' of CALC_MISS.

### 7.10 Keyword INTERF

#### 7.10.1 Operand MODE_INTERF

```text
♦    MODE_INTERF    =    /    'TOUT',
                         /    'CORP_RIGI'
                         /    'QUELCONQUE'
```

This operand makes it possible to characterise the type of interface modes of the model. Three types of interface modes are possible: if one chooses a modelling based on the six rigid-body modes, one must supply 'CORP_RIGI'; if one works with all the interface modes (finite-element unit modes), one supplies 'TOUT'. For all the other foundation cases (embedded geometry, arbitrary representation modes for a flexible foundation, case ISSF='OUI'), one supplies 'QUELCONQUE'.

#### 7.10.2 Operand GROUP_NO_INTERF

With this keyword, one defines the node group based on the surface mesh cells constituting the soil-structure interface.

### 7.11 Keyword MATR_COHE

#### 7.11.1 Operands TYPE, VITE_ONDE and PARA_ALPHA

These are the same parameters used in the operator DYNA_ISS_VARI ([u4.53.31](doc:u4.53.31)).

### 7.12 Keyword MATR_GENE

#### 7.12.1 Operand BASE

Name of the concept of the basis of the interface modes.

#### 7.12.2 Operand NUME_DDL_GENE

Name of the generalised numbering concept based on the previous modal basis. In general with full storage

### 7.13 Operand PRECISION

This is the same parameter used in the operator DYNA_ISS_VARI ([u4.53.31](doc:u4.53.31)).

## 8 Analysis of the dynamic stiffness in the time domain

In this paragraph one will detail the options specific to the Laplace-Time method ([r4.05.07](doc:r4.05.07)), that is in the case TYPE_RESU='FICHIER_TEMPS'

### 8.1 Operand PRECISION

Precision parameter of the Laplace-time computation method (TYPE_RESU='FICHIER_TEMPS').

```
On conseille fortement de laisser la valeur par défaut.
```

### 8.2 Operand COEF_SURECH

Parameter for imposing the oversampling coefficient for the Laplace-time method.

```
On recommande de garder la valeur par défaut afin de garantir un bon résultat sur toute la fenêtre de calcul:
  * En effet, lorsque cet opérande vaut 1.0 (pas de suréchantillonnage), l'impédance transitoire est valide uniquement sur 70% environ de la fenêtre de calcul.
  * Ainsi, si l'utilisateur augmente ce coefficient, la précision de calcul sera améliorée, mais avec un surcoût de calcul proportionnel à cette valeur
```

### 8.3 Operand FACTEUR_INTERPOL

It gives the value of the interpolation step and therefore of the factor of reduction of the run time.

### 8.4 Operand PCENT_FREQ_CALCUL

It gives, as a percentage, the ratio between the number of samples without interpolating and the total number of samples.

### 8.5 Operand COEF_MULT

It makes it possible to assign a multiplicative factor to the transient impedances. Useful, for example, for conversions to 2D models by dividing the 3D impedance results by a domain thickness.

### 8.6 Operand TYPE_FICHIER_TEMPS

Parameter which makes it possible to specify the format of the output time-domain file, between 'ASCII' (default) and 'BINAIRE'. The binary format makes it possible to save space and a little time but is not readable by the user. The format thus defined must be consistent with the format specified with the keyword TYPE under the option FORCE_SOL of AFFE_CHAR_MECA.

### 8.7 Operands INST_FIN, PAS_INST and INST_ECRI_FIN

- The keywords PAS_INST and INST_FIN are mandatory with the Laplace-time analysis method in order to give the time step and the final time instant of the integration analysis of the method.
- The keyword INST_ECRI_FIN (optional) makes it possible to limit the storage size of the transient impedances sufficient for the analysis of the seismic forces. Otherwise, this size is determined from INST_FIN.

### 8.8 Operand MATR_GENE

This parameter makes it possible to specify all the options relating to the dynamic-stiffness analyses (test case *miss03* and its associated documentation [v1.10.122](doc:v1.10.122)). If this optional factor keyword is used, then one must also define the values of the operands UNITE_RESU_AMOR and UNITE_RESU_MASS.

#### 8.8.1 Operand DECOMP_IMPE

This keyword makes it possible to specify the method of decomposition of the impedance.

```
On recommande de laisser la valeur par défaut ('PRODUIT').
```

#### 8.8.2 Operand AMOR_HYST

This keyword makes it possible to specify the way in which the hysteretic damping in the soil will be taken into account. There are two possible choices:

- 'DANS_MATR_AMOR': The damping matrix given by the user (via MATR_AMOR under MATR_GENE) takes the hysteretic damping of the soil into account
- 'DANS_IMPEDANCE': This is the opposite case of the previous one

#### 8.8.3 Operands MATR_MASS, MATR_RIGI and MATR_AMOR

These arguments serve to define the mass, stiffness and damping matrices which can be used by the decomposition of the impedance:

- If one has AMOR_HYST='DANS_MATR_AMOR', then one must mandatorily supply, at least, MATR_AMOR
- Conversely, AMOR_HYST='DANS_IMPEDANCE', then it is enough, as a minimum, to give one of the three matrices for the decomposition.

### 8.9 Operand EXCIT_SOL

This optional factor keyword serves to characterise the excitation transmitted by the soil: definition of the seismic forces. If one wishes to compute only the dynamic stiffness, this keyword is unnecessary.

#### 8.9.1 Operands NOM_CHAM, CHAM_X, CHAM_Y and CHAM_Z

These arguments serve to specify the input signal. Its nature (displacement, velocity or acceleration signal) is indicated by the value of NOM_CHAM (by default one expects an imposed displacement). This signal may have from one to three components, along $X$ , $Y$ and $Z$ and, for each direction, one can give the corresponding function: CHAM_X, CHAM_Y and CHAM_Z.

#### 8.9.2 Operand UNITE_RESU_FORC

Makes it possible to define the logical unit of the generated file which will contain the seismic forces, which will be reusable in DYNA_NON_LINE via a loading of type FORCE_SOL in AFFE_CHAR_MECA (test case *miss03c* and its associated documentation [v1.10.122](doc:v1.10.122)).
