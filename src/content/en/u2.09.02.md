# u2.09.02 Carrying out the analysis of a stud–flange assembly

## 1 Purpose

This note concerns the production of the mesh and the global analysis of a stud–flange assembly with *Code_Aster*.

The analyses proper, as well as the macro-commands mentioned in this document, are available in the command files of the test cases ZZZZ120A and ZZZZ120B.

The production of the mesh requires the use of the function MACR_GOUJ2E_MAIL, which must be defined at the beginning of the command file. The analysis, on the other hand, is carried out solely with the commands of *Code_Aster*. The macro-command POST_GOUJ allows the results to be presented in a format which facilitates their reading. Like the function MACR_GOUJ2E_MAIL, this macro-command must be defined at the beginning of the command file. The analysis also requires the use of the database containing the geometric and mechanical characteristics of the assemblies.

We give the content of the database in its version 1.00 of 16/09/1999, which was produced by the MMN Department from the old database («gouj2ech.base_v1_11» version 1.09 of 9/6/1997) qualified by the UTO, and we briefly recall the way of feeding this new database.

This database is designed so that the addition of new data, characterising new local situations, can be carried out easily.

## 2 Introduction

This note concerns the use of the function macr_gouj2e_mail and of the macro-command POST_GOUJ, which make it possible, respectively, to produce the mesh of a stud–flange assembly and to post-process the results of a mechanical analysis carried out with the classical commands of *Code_Aster*. The analysis also requires the use of the database containing the geometric and mechanical characteristics of the assemblies.

First we describe the function macr_gouj2e_mail and the macro-command POST_GOUJ. The text of these macro-commands as well as their catalogues are available in the command files of the test cases ZZZZ120A and ZZZZ120B.

In the second part we detail the content of the study profile and of the command file. We continue by specifying the way of using the function macr_gouj2e_mail, the macro-command POST_GOUJ and the classical commands in order to produce the mesh and the global analysis of a stud–flange assembly. To finish, we describe the content of the result file (.resu) before briefly addressing the content of the message file (.mess).

The last part is devoted to the database of the geometric and mechanical characteristics of the studs. We describe the constitutive-behaviour curves of the threads as well as the organisation of the various data. We give the content of the database in its version 1.00 of 16/09/1999, which was produced by the MMN Department. Finally, we briefly recall the way of feeding this database.

### 3.3 Geometric definition of the stud–flange assembly

The stud–flange assemblies concerned here are those which keep the vessel head or the manhole cover plate closed.

![Figure](/figures/u2.09.02/10001BFC000069D5000045F8CF1EC4D4748C13CB.svg)

**Figure 3.3-a: description of the various geometric parameters** **of the stud–flange assembly**

The internal radius of the flange, the external radius of the stud as well as the pitch or the height of a thread are characteristic quantities of a given assembly. These last three quantities are therefore not accessible to the user.

All the dimensions (lengths) must be given in **millimetres**. If the user gives values for the heights of the top of the flange and of the bottom of the flange, these cannot be less than one millimetre.

## 4 Description of the macro-command POST_GOUJ

### 4.1 Purpose of POST_GOUJ

Carry out the post-processing in a specific format.

Transform a table created by POST_RELEVE_T into a table of a specific format of type table_sdaster. The table of type table_sdaster contains the parameters 'NUME_FILET', 'NOEUDS' (node number corresponding to the thread number), 'NUME_ORDRE' (corresponding to the load increment), 'REACTION' (reaction of the threads) and 'REACTION_CUM' (cumulative reaction of the threads in %).

Produces a data structure of type table_sdaster.

### 4.2 Syntax

```text
ntab    [table_sdaster]    = POST_GOUJ

(

♦    TABLE    = tabl_post_rele    ,                                                [TXM]

)
```

### 4.3 Operand

#### 4.3.1 Operand TABLE

```text
♦    TABLE=                                                                    [TXM]
```

This operand makes it possible to indicate the name of the table of type tabl_post_rele that one wishes to modify.

## 5 Carrying out the analysis of a stud–flange assembly

In this part one indicates the way of using the function macr_gouj2e_mail, the macro-command POST_GOUJ and the commands of *Code_Aster* in order to carry out a global analysis of a stud–flange assembly. One will begin by describing the study profile (file .astk), one will continue by explaining the content of the command files (file .comm), of results (file .resu) and of messages (file .mess). The content of the database (logical unit 38 free format) is described in [§6].

### 5.1 The study profile

In the study profile, only two files are mandatory as data: the command file (file .comm) and the file containing the database (logical unit 38 free format). The file containing the mesh (file .mail) is produced automatically and is not visible to the user. Nevertheless, the latter can visualise the mesh produced by putting as a result the file «Gibi mesh, (mgib)» corresponding to logical unit 53, and by using in the command file the command IMPR_RESU as indicated in paragraph [§ 5.2.2].

The result file (file .resu) makes it possible to exploit the results.

#### 5.2.2 Production of the mesh

The function macr_gouj2e_mail, cf. [§3], and the set of commands described below ensure the production of the mesh of a stud–flange assembly such as the one presented in [Figure 3.3-a]. **Apart from the command** **IMPR_RESU, they are all necessary.**

- the function macr_gouj2e_mail;
- The line loc_outils=aster.repout();
- the command EXEC_LOGICIEL;
- the command PRE_GIBI;
- the command MAIL=LIRE_MAILLAGE;
- the command MAIL=DEFI_GROUP;
- the optional command IMPR_RESU.

The command EXEC_LOGICIEL launches the Gibi software, which generates the mesh file in Gibi format (file .mgib) from the Gibi data files (file .datg) to which the user does not have access.

The function macr_gouj2e_mail serves to recover from the database the internal radius of the flange, the external radius of the stud and the pitch of the threads of the stud characterised by its type and its variant, cf. [§3]. Moreover this function prepares the Gibi data files (.datg). The geometric characteristics of the flange and of the threads are specified by means of the operands H_CORP_BRID (Height of the Flange Body, the part of the flange engaged with the threads) and R_EXT_BRID (External Radius of the Flange), which are mandatory. The operands H_HAUT_BRID (Height of the Top of the Flange) and H_BAS_BRID (Height of the Bottom of the Flange) are optional; they are equal to zero by default. All the dimensions must be given in **millimetres**. If the user gives values for the heights of the top of the flange and of the bottom of the flange, these cannot be less than 1 millimetre. The internal radius of the flange, the external radius of the stud as well as the pitch or the height of a thread are characteristic quantities of a given assembly which are stored in the database; they are therefore not to be entered by the user.

One indicates the total and theoretical number of threads with the mandatory simple keyword NB_FILET. If some of the threads are absent or missing, the simple keyword FILET_ABST makes it possible to indicate the list of them. The absent threads are not meshed.

#### 5.2.3 Carrying out the analysis

Before writing the «analysis» part of the command file, it is advisable to consult the database in order to know the types of threads, the materials and the tension curves which are associated with a given type of stud–flange assembly.

Carrying out the analysis requires the chaining of the following *Code_Aster* commands:

- the command DEFI_GROUP, which enriches the mesh by creating node groups;
- the command AFFE_MODELE, which assigns the mechanical phenomena to the various mesh-cell groups;
- the command AFFE_CARA_ELEM, which makes it possible to define the cross-section of the beam which models the stud and the characteristics of the discrete elements which model the threads;
- the command DEFI_MATERIAU, which makes it possible to define the materials of the threads of the stud;
- the command AFFE_MATERIAU, which assigns the materials defined to the appropriate mesh-cell groups;
- the command AFFE_CHAR_MECA, which assigns the boundary conditions and the loading;
- the command DEFI_FONCTION, which defines the multiplier function to be applied to the loading;
- the command DEFI_LIST_REEL, which defines the list of time instants;
- the command STAT_NON_LINE, which carries out the analysis;
- the command CALC_CHAMP, which computes the nodal forces;
- the command POST_RELEVE_T, which recovers the relevant results;
- the macro-command POST_GOUJ, which reorganises the results in the appropriate format;
- the command IMPR_TABLE, which makes it possible to print the results.

Concretely this is expressed by the following commands:


MAIL=DEFI_GROUP(reuse =MAIL,

MAILLAGE=MAIL,

## 6 Presentation and use of the database

### 6.1 General points

A threaded assembly leads to a beam modelling for the stud (beam element) and a 2D modelling for the threads (two-node discrete elements) and the flange (2D axisymmetric elements). The three elements of an assembly are shown schematically in [Figure 6.1-a].

![Figure](/figures/u2.09.02/1000E2C60000213600002BE14DAB6ECF2A6787A9.svg)

**Figure 6.1-a: Schematic representation of an assembly**

The stud and the flange have a linear elastic constitutive behaviour. The non-linear constitutive behaviour is localised in the threads. It applies to the discrete elements and is determined independently by a local 2D axisymmetric analysis whose results have been exploited. This constitutive behaviour appears in the form of a relation, indexed by the position of the thread in the structure, between a displacement difference $(u-v)$ and the shear force $\tau =q=f(u-v)$ which is associated with it. Knowing the constitutive behaviour of the elements constituting an assembly, one solves the global problem of which the displacements of the stud $u(y)$ and of the flange $v(y)$ are the solutions.

It is these various relations which are described, in the form of functions given point by point, in the database presented in this note. These curves were obtained for **tensions exerted at the head of the stud and not compressions**.

Within the framework of the summary above, certain parameters characteristic of a given assembly intervene only at the time of the integration of the global problem.

This is the case, for example, of the number of threads, of the global force exerted at the head of the stud, of the blocking conditions of the flange (lateral surface and/or base blocked). These parameters therefore do not appear in the specifications of a curve characteristic of a thread.

The parameters which, on the other hand, determine the constitutive behaviour of the threads are listed below:

- Designation of the standardised form of the geometry of the stud, example: M33, M155;
- Type of the stud–flange assembly, example: NOMINAL or HELICOIL;
- Stiffener of the top of the flange, example: AVEC or SANS;
- Geometric characteristics of the clearance, example: MINI or MAXI;
- Constitutive behaviour of the threads and stud/tapping contact condition, example: ELASTIQUE (linear elastic) or ELASTOPLASTIQUE (non-linear tension curve).

Each combination of these various parameters therefore leads a priori to a specific shear–displacement-jump relation. Each of these combinations is identified by a letter; for example: for the standardised form of the geometry of the stud M33, if the stud–flange assembly is NOMINAL, the stiffener of the top of the flange is present (AVEC), the clearance is MAXI and the constitutive behaviour of the threads is ELASTOPLASTIQUE, one will speak of the stud M33 of variant A, denoted: M33_A, cf. [Table 6.2-3]. The association of the standardised form of the geometry of the stud (M33) and of the variant (A) uniquely identifies the data sheet of an assembly grouping all the data concerning it (geometry of the assembly, characteristics of the assembly, constitutive-behaviour curve of the threads $\tau =q=f(u-v)$, definition of the materials of the flange and of the stud) in the database, cf. [Table 6.3-1] and [Table 6.3-2].

**Notes 6.1-1:**

- *All the configurations other than those with inserted threads (HELICOIL* ), cf. [bib3], [bib4], were computed in plasticity. If one nevertheless wishes the threads to have a linear elastic constitutive behaviour, one will have to use RELATION='DIS_GOUJ2E_ELAS' *of the keyword* COMPORTEMENT *of the command* STAT_NON_LINE, cf. [§ 5.2.3].
- *The curves representative of anomalies are themselves also specific to the place of the load-bearing threads of these anomalies;* *A and* *B identifying respectively, in the data sheet of an assembly, that of the first and of the second thread.*
- **The user will have to make sure** *that the types of constitutive behaviour of the threads that he or she has chosen do or do not correspond to a configuration computed in the database.*

### 6.3 Presentation of the database

The database is the subject of a specific computer processing; certain rules are indispensable to observe in order to complete it in a rigorous way.

The database file is divided into three parts: the date and version references, the header frame, the assembly data sheets. These three parts are taken up and detailed below:

- The first line contains the date and the version number of the database. This line is considered as being a comment.
- The frame of the header makes it possible to note the successive evolutions of the database: author(s), version date and subject.
- The third part contains the data sheets of the assemblies. These are constituted in the following way:

| a/ | **The type of the stud as well as the variant**. |
| --- | --- |
| b/ | **The geometry of the assembly**, the part in which one finds: the cross-section of the stud, the external radius of the stud, the height or the pitch of the thread and the internal radius of the flange. |
| c/ | **The characteristics of the assembly**; one finds there: the thread configuration, the characteristic top of the flange, the type of clearance, the mechanical constitutive behaviour, the flange material and the stud material. |
| d/ | **The curves describing the constitutive behaviour of the threads** (FIRST THREAD, SECOND THREAD, ORDINARY THREAD, ...). |
| e/ | **The materials of the flange and of the stud**: Young's modulus and Poisson's ratio. |
