# u2.03.06 Carrying out a civil-engineering study with prestressing cables

> **Summary.**

The aim of this document is to give advice for carrying out studies of reinforced concrete with prestressing cables, using the dedicated features (DEFI_CABLE_BP/CALC_PRECONT). It gives information on the precautions for meshing, on the ways of applying the prestress, and on the possibilities of phasing.

## 1 Introduction

Civil-engineering studies are often fairly complex to carry out, in so far as they involve $mathrm{3D}$ modellings, shells, bars and several materials. This document tries to pool the experience acquired on the subject by giving methodological advice for the mesh and for the modelling stage, as regards prestressed structures.

The numerical implementation of the tension requires a few usual precautions, in particular in the case of non-linear analyses, since the chronology of the loadings can affect the results. In this document, we see how to set up the commands in order to reproduce a few examples of situations that can be envisaged in reality.

For a more visual presentation, the materials of the training course "Code_Aster/salome_meca Module 4: Civil engineering" can also be consulted (
[02-Modeling of the prestressed reinforced structures](https://www.code-aster.org/V2/spip.php?action=dw2_out&id=2030)
`  <[https://www.code-aster.org/V2/spip.php?action=dw2_out&id=2030](https://www.code-aster.org/V2/spip.php?action=dw2_out&id=2030)>`_) and an application in the form of practical work, accessible via the test FORMA42.

## 2 Preliminary note

In *Code_Aster*, two types of modelling exist for describing prestress.

- The first method is suited to describing **bonded prestress**. In this case, the prestressing cables are represented by $1D$ elements with the modelling BARRE. The prestress can be applied easily via the operators DEFI_CABLE_BP and AFFE_CHAR_MECA, which make it possible to estimate the initial tension profile (N), variable along the cable, according to the regulatory formulae (BPEL or ETCC), and to transform it into a loading.
- The second method (less proven) is suited to describing **unbonded prestress** (typically the TGG). In this case, the prestressing cables are represented by $mathrm{1D}$ elements with the modelling CABLE_GAINE. Tensioning of the cable is obtained by simulating the process of tensioning the cable via the operator CALC_PRECONT, assuming that the cables slide with a friction of Coulomb-law type.

## 3 First stage: the mesh

To carry out an analysis on a prestressed reinforced-concrete structure, it is necessary to mesh the concrete, the reinforcements and the prestressing cables.

- The mesh of the concrete can be produced with any volume element in $mathrm{3D}$ or in $mathrm{2D}$. In $3D$, the elements can be linear or quadratic. If a shell-type modelling is chosen, the elements will be linear.
- The reinforcements can be represented:

  - either individually; in this case, they will necessarily be meshed with $mathit{SEG2}$ (linear elements) whose nodes are common with those of the concrete. One must therefore think of this when meshing the concrete. Moreover, one must be careful if the concrete is meshed with quadratic elements, so as to match properly all the concrete nodes located along the reinforcement with a steel node: in other words, if the concrete is meshed with quadratic elements, at the place where a reinforcement must pass, one must define 2 steel $mathit{SEG2}$ for one concrete mesh cell;
  - or in a distributed manner, in the form of a surface whose nodes are the same as the nodes of the concrete. The mesh cells may equally well be triangles or quadrangles, linear or quadratic. One must therefore take care to identify this surface at the time of meshing the concrete, and to duplicate the mesh cells in order to define the steel layer (via *Transformation → Duplication Nodes/Elements* in *salome_meca*). If there are several layers of reinforcement, these elements will have to be duplicated as many times as necessary.
- The prestressing cables must be meshed with one-dimensional elements. If the modelling BARRE is used, these elements will be $mathit{SEG}2$; if the modelling CABLE_GAINE is used, these elements will be $mathit{SEG}3$. Whatever the modelling, it is not necessary to make the nodes of the cable coincide with the concrete nodes: the command DEFI_CABLE_BP indeed makes it possible to create the kinematic relations which will link the nodes of the cable with the nodes of the concrete of the surrounding mesh cell. One must, on the other hand, take care to have a similar level of discretisation for the concrete and the steel, so as to have, as far as possible, one steel node in each concrete mesh cell (so that all the elements see the cable) and to avoid having several steel nodes in one concrete mesh cell (in order to avoid weighing the problem down with unnecessary Lagrange multipliers).

The anchorage nodes having to be defined for each cable, it is necessary to have created node groups for each end of the cables.

## 4 Second stage: data setup of the problem

The various stages of the data setup of a typical prestressed-concrete problem in *Code_Aster* are detailed here, for the two types of modelling. For each stage, the possible questions to be asked and the information which must be supplied are specified. In the case of the modelling BARRE, an example of application is proposed in the appendix, where the various variants for the solution stage are given.

### 4.1 Reading and possible enrichments of the mesh

- Check that the anchorage nodes are indeed accessible (individually) through a GROUP_NO.
- Create any node groups or mesh-cell groups for post-processing. If one wishes to post-process the tensions in prestressing cables, one must remember to order the nodes of the corresponding node group (option 'SEGM_DROI_ORDO' or 'NOEUD_ORDO' in DEFI_GROUP/CREA_GROUP_NO).
- Orient correctly the mesh-cell groups on which loadings of pressure or flux type are imposed (command ORIE_PEAU_3D (2D)).

### 4.2 Assignment of a model

- **For the reinforcements**

In the case of a 3D modelling, the reinforcements will be modelled by BARRE elements if they have been represented by line elements, or by GRILLE_MEMBRANE or MEMBRANE elements if they have been represented by surface elements.

In the case of a plate-type modelling (DKT, Q4GG), one must use the modelling GRILLE_EXCENTREE.

- **For the prestressing cables**

For bonded cables, the model BARRE (based on $mathit{SEG}2$) will be used.

For unbonded cables, the model CABLE_GAINE (based on $mathit{SEG}3$) will be used.

### 4.3 Characteristics of the structural elements

In AFFE_CARA_ELEM, define:

- for the passive reinforcements, either their cross-section (BARRE), or the cross-section and the orientation of the layer (GRILLE)
- for the prestressing cables, define the cross-section (BARRE).

### 4.4 Definition of the materials

Various types of law are available, according to the phenomena which one wishes to take into account (elasticity, damage, creep, …). Summary tables giving the main characteristics of each of them are available in [u2.03.07](doc:u2.03.07).

The choice of the law determines the keywords to be entered under DEFI_MATERIAU [U4.43.01](doc:u4.43.01).

In the presence of cables, and in order to be able to use DEFI_CABLE_BP, one must also have entered, in addition to the parameters linked to the constitutive law used, and according to the regulation used (BPEL or ETCC):

- for the concrete, **either** the keyword BPEL_BETON, entering if necessary the losses by creep PERT_FLUA and the losses due to shrinkage PERT_RETR, **or** the keyword ETCC_BETON();
- for the steel of the prestressing cables, **either** the keyword BPEL_ACIER, entering the rupture stress F_PRG, the friction coefficient on the straight part FROT_LINE and on the curved part FROT_COURB, the relaxation coefficient MU0_RELAX, and the relaxation of the steel at 1000 hours RELAX_1000, **or** the keyword ETCC_ACIER. In this case, the data to be supplied are the rupture stress F_PRG, the friction coefficient COEF_FROT, the in-line loss coefficient PERT_LIGNE, and the relaxation of the steel at 1000 hours RELAX_1000.

All these parameters are optional.

**Notes:**

1. *The parameter* *F_PRG* *does not come into play in a possible non-linear analysis with plasticity of the cables;* *it serves only* *to compute the loss by relaxation. In order to allow an analysis with yielding, the yield stress must be declared with the constitutive law chosen.*
2. *The command* *DEFI_CABLE_BP cannot consider the case in which the elastic characteristics of the concrete crossed by the cable may vary with temperature.*
3. *The command* *DEFI_CABLE_BP can support the case in which a cable crosses several concrete materials. All the concretes must however have the same properties with respect to the BPEL* *or ETCC, that is to say the same properties under the keyword* *BPEL_BETON* *or ETCC_BETON.*

**Case of unbonded cables:**

When the modelling CABLE_GAINE is used, the user must also enter the friction law which is to be used, via the keyword CABLE_GAINE_FROT. The choice is logically of type 'FROTTANT', which implies entering the friction coefficients on the straight line and on the curve. The user also has, however, the possibility of choosing the option 'ADHERENT', in order to make comparisons easily between the two behaviours (results equivalent to the modelling BARRE), or the option 'GLISSANT', which makes it possible to avoid the possible convergence difficulties linked to friction.

### 4.5 Definition of the cables

The stage of definition of the cables goes through the command DEFI_CABLE_BP. This makes it possible to define what the tension in the cables must be according to the rules of the BPEL/ETCC, as a function of the initial tension, of the anchorage draw-in (which applies only for the active anchorages), of the relaxation of the steel and of the delayed strains of the concrete (creep and shrinkage).

Let us note that a single DEFI_CABLE_BP can group several cables, provided that they have the same input parameters for the computation of the tension, and that one wishes to tension all these cables simultaneously. This is in general preferable from the point of view of performance. In order to facilitate the data setup and to avoid resorting to Python macros, it is possible to define the cables via a table defined in an external file (cf. SSNV229A).

If the user has chosen to model unbonded cables (FROTTANT or GLISSANT), one should specify in DEFI_CABLE_BP, ADHERENT='NON'.

The punching created by the anchorages can sometimes give rise to numerical modelling difficulties. The origin of this problem is linked to the incompatibility of the loading mode (a point force created by the anchorage) with respect to the mesh of the concrete ($mathrm{2D}$ or $mathrm{3D}$). To avoid this problem, the keyword CONE under DEFI_CABLE_BP makes it possible to define a volume representing the dispersion cone placed at the end of the cables, and thus to distribute the punching force over a volume of the concrete, and no longer over one or a few nodes. The geometry of this volume corresponds to a cylinder whose dimensions (length and radius) should ideally correspond to the dispersion cone actually employed. It must be noted, however, that if the mesh of the concrete in this region is not sufficiently fine, the volume of the cone will not include any additional nodes and the problem will not be modified. Overlap of the cones is also not possible. The option CONE cannot be activated in the case of unbonded cables.

**Notes:**

1. *Each cable end can be declared as being "active" or "passive". If a cable has no active end, no tension is then applied.*
2. *Use of the option* *CONE requires particular attention as to the way of imposing the boundary conditions, on pain of seeing redundant kinematic conditions appear which prevent solution of the problem.*

### 4.6 Definition of the loadings

#### 4.6.1 Case of bonded cables

Two variants exist for carrying out the tensioning. The first method consists in applying the prestress directly, in the form of an initial tension in the cables, as a loading with STAT_NON_LINE. The loading is instantaneous. Its drawback is that the tension which results from equilibrium is generally lower than that requested by the user, because of the elastic strain of the concrete under the effect of the prestress.

The second method is an improvement on the first and is based on the macro-command CALC_PRECONT, which encompasses a certain number of manipulations of the model in order to ensure the tensioning (cf. [R7.01.02](doc:r7.01.02)). By using this operator, the tension at equilibrium is exactly that requested (that is to say, that computed by the regulatory formulae); it also allows the successive tensioning of the cables, in order to recreate the phasing of the prestressing of the structure. Finally, the last advantage of this method is the possibility of applying the cable tension gradually, which may be necessary for behaviours of non-linear type, in particular in the event of cracking of the concrete during the prestressing stage.

Basic method: STAT_NON_LINE

In addition to the boundary conditions and the various loadings, it is sufficient to create a loading linked to the cables via the operator AFFE_CHAR_MECA, including the loadings linked to the tension and those linked to the kinematic relations between the steel and the concrete, that is:

CHCAB=AFFE_CHAR_MECA(MODELE=MO,RELA_CINE_BP=_F(CABLE_BP=CAB_BP3,                             SIGM_BPEL='OUI',RELA_CINE='OUI',),).

However, if the user envisages chaining several STAT_NON_LINE, this loading will have to be duplicated, including only the kinematic relations (SIGM_BPEL='NON', RELA_CINE='OUI'). This loading will be used from the second call to STAT_NON_LINE onwards.

Recommended method: CALC_PRECONT

In addition to the boundary conditions and the various loadings, one must define the loadings linked to the cables, which must include only the kinematic relations, that is:

CHCAB=AFFE_CHAR_MECA(MODELE=MO,RELA_CINE_BP=_F(CABLE_BP=CAB_BP3,                         SIGM_BPEL='NON',RELA_CINE='OUI',),).

These loadings will be used:

- for any analysis with STAT_NON_LINE during the stages prior to tensioning (for example, if one simulates a creep stage)
- for the stages subsequent to tensioning (otherwise the analysis stops in fatal error because of a matrix which cannot be factorised), whether the analysis is done with STAT_NON_LINE or with CALC_PRECONT.

One must therefore remember to define as many loadings as there are different tensioning stages.

#### 4.6.2 Case of unbonded cables

The instructions are the same as for the bonded case with CALC_PRECONT. On the other hand, one must also plan to create additional loadings making it possible to block the sliding at the anchorage nodes of the cables once they have been tensioned. That is:

CGLIS =AFFE_CHAR_MECA(    MODELE=MO,

> DDL_IMPO=(    _F(GROUP_NO=('PC1D','PC1F'),

> GLIS=0.0,),)

## 5 Solution of the mechanical problem

The last stage consists in solving the mechanical problem. It proceeds differently according to the method employed and to whether phasing is taken into account. This chapter details how to proceed for each of the choices, specifying the loadings to be included (keyword EXCIT) when calling CALC_PRECONT or STAT_NON_LINE.

### 5.1 Bonded cables tensioned with CALC_PRECONT

Three cases are possible:

| 1 | The user wishes to tension simultaneously all the prestressing cables, as well as an instantaneous loading, without any other loadings beforehand. In this case, it is sufficient to call the macro-command CALC_PRECONT only once. The loading is composed of the boundary conditions and of any instantaneous loadings (no loading concerning the cables). Under the keyword CABLE_BP, one will include all the DEFI_CABLE_BP concepts (see scenario 3 in the appendix). |
| --- | --- |
| 2 | The user wishes to carry out analyses before the tensioning of the cables. In this case, one should: * either deactivate the cables in the model by assigning them the constitutive law RELATION='SANS' under the keyword COMPORTEMENT of STAT_NON_LINE. In this case, the stiffness of the cables is zero. It is also indispensable to add to the loadings the kinematic relations linking cable and concrete (loading obtained by writing AFFE_CHAR_MECA(RELA_CINE_BP=_F(RELA_CINE='OUI'))) (see scenarios 1 and 3 in the appendix). * or not include the cables in the model used to carry out the analyses before the tensioning of the cables (which is more tedious, since one must work with 2 models). |
| 3 | The user wishes to tension the cables successively. In this case, CALC_PRECONT must be called as many times as necessary. CABLE_BP will contain the DEFI_CABLE_BP concepts associated with the cables which one is in the process of tensioning during this call to CALC_PRECONT. CABLE_BP_INACTIF will contain those which one wishes to tension later. In this way, it is the macro-command which takes care of assigning a constitutive law SANS to these cables and of including the kinematic relations associated with these same cables. For the loading, the boundary conditions must be included systematically, as well as any instantaneous loadings. From the second call to CALC_PRECONT onwards, one should in addition include the kinematic relations linked to the cables already tensioned at the previous stages (see scenario 1 in the Appendix). |

In every case, for the STAT_NON_LINE which follow the tensioning of the cables, it is important not to forget the whole set of kinematic relations linked to the cables.

### 5.2 Bonded cables tensioned with STAT_NON_LINE

If the user does not wish to use CALC_PRECONT in order to tension the prestressing cables, it is possible to resort to the former method of tensioning the cables, despite its drawbacks [R7.01.02](doc:r7.01.02).

Tensioning is carried out simply by including in the loads the concept AFFE_CHAR_MECA defined by RELA_CINE_BP = F(RELA_CINE = 'OUI', SIGM_BPEL='OUI'). At the end of this analysis, the tension in the cables is no longer equal to that prescribed by the BPEL. Nevertheless, it is possible to determine a multiplicative coefficient (of the order of ten percent) to be applied to the initial tensions applied to the cables (at the level of the declaration of the operator DEFI_CABLE_BP), making it possible to compensate globally for the losses by instantaneous strain of the structure. Once the command file has been modified by these correction coefficients, the modelling of the prestressing cables is complete.

Warning: in the case of a chaining of STAT_NON_LINE, one should, from the second call onwards, include in the loading only the kinematic relations and not the tension in the cables, on pain of adding this tension at each analysis (see scenario 2 in the appendix). This therefore requires creating a second AFFE_CHAR_MECA with the operand RELA_CINE_BP = F(RELA_CINE = 'OUI', SIGM_BPEL='NON') (cf. scenario 2 in the Appendix).

### 5.3 Unbonded cables tensioned with CALC_PRECONT

The instructions are identical to the case of bonded cables. Two specific points should nevertheless be noted.

1. The constitutive law for the cable is no longer simply elastic, but:

  - RELATION = 'KIT_CG', RELATION_KIT =('ELAS','CABLE_GAINE_FROT'),

'ELAS' may be replaced by 'SANS' when the cable must not take part in the analysis.

- Once the cables have been tensioned, the loading which blocks the sliding of the anchorage nodes must be added (cf. § 4.6.2). It is recommended to rely on the test case SSNV164D.

## 6 Particular cases: relaxation of the cables and rupture of the cables

### 6.1 Relaxation of the cables

To model the relaxation of the cables, two options are possible, but only in the case of bonded cables (modelling BARRE and not CABLE_GAINE): use the regulatory formulae, or use a viscoelastic law for the cables.

- When the regulatory formulae (BPEL or ETCC) are used, the losses by relaxation are computed at a given date. This is therefore to be used with caution when a non-linear analysis is carried out.
- For relaxation, the ETCC formula requires knowledge of the state of tension in the cable after the instantaneous losses have been taken into account: the analysis must therefore be done in 2 stages. Refer to the test case SSNV229B for an example. The user also has the possibility of using a simplified version: this is the option TYPE_RELAXATION='ETCC_DIRECT' (as opposed to TYPE_RELAXATION='ETCC_REPRISE'). The test SSNV229A implements this option.
- For a fully non-linear analysis, it is sufficient to assign to the prestressing cable (modelling BARRE) the constitutive law RELAX_ACIER (cf. [R5.03.09](doc:r5.03.09) and test SSNL143 for further details).

### 6.2 Rupture of the cables

To simulate the rupture of a **bonded** cable, one must take care that the mesh is sufficiently refined for there indeed to be only one cable per concrete mesh cell.

If one assumes that the tension is zero throughout the cable, it is sufficient to call CALC_PRECONT again, having defined a new DEFI_CABLE_BP with the cable or cables concerned and having defined a zero tension.

If one assumes that the cable is re-anchored, then it is possible to enter the profile of one's choice. The proposed sequence is as follows:

- carrying out the initial tensioning analysis
- recovery of the tension in the cable(s) concerned: CALC_CHAMP/POST_RELEVE_T
- modification of the tensions in the table by means of a formula defined by the user
- creation of the concept DEFI_CABLE_BP by defining the cable by means of the factor keyword MODI_CABLE_RUPT
- new application of the prestress by means of CALC_PRECONT.

The test SSNV229C provides an example.

Warning: given the modelling assumptions, the responses obtained are rather qualitative and must not be examined in a very local manner.

## 7 Post-processing

For the bonded cases, it is possible to recover the tension profile in the cable computed according to the regulatory formulae, via the command:

TAB_1_I=RECU_TABLE(CO=CAB_BP, NOM_TABLE='CABLE_BP',)

After tensioning of the cables, it is of course possible to plot the tension profile at several time instants, by means of the commands POST_RELEVE_T/RECU_FONCTION/IMPR_FONCTION. An example is present in the test FORMA42.
