# v4.02.001 TPLL01 - Infinite linear thermal wall

**Summary:**

This test case is for a linear steady-state thermal analysis calculation. It includes 10 modellings that test the elements 2D and 3D.

This test case has several interests:

- **For modellings from A to I** , it tests on almost all elements 3D and 2D (except 2D_AXIS, PYRAM and Dumping), the calculation of linear thermal base options: "rigidity", "mass", exchange, imposed flux, imposed temperature,
- **In the J** Modelling, a spatial error mapping is calculated using ERTH_ELEM CALC_ERREUR option, which will be supported in a Python loop by the HOMARD refinement/derefining tool encapsulated in MACR_ADAP_MAIL.
- The orientation of the wall is any in relation to the coordinates,
- This is one of the few test cases to test elements TETRA10 and QUAD9 linear thermal and to combine AFFE_CHAR_THER / LIAISON_DDL commands.

## 12 Modelling J

### 12.1 Modelling characteristics

It is a functional test case and computer non-regression of the thermal-imposed ex post error indicator calculation (see [R4.10.03](doc:r4.10.03)). It exhumes a spatial error mapping on which will be supported, in a Python loop, the HOMARD refinement/derefining tool encapsulated in MACR_ADAP_MAIL (see [U7.03.01](doc:u7.03.01)).

The calculation of this error indicator card is performed, via the ERTH_ELEM option of the post-processing CALC_ERREUR operator, on an EVOL_THER (provided to keyword RESULTAT) from an earlier thermal calculation (linear or non-linear, transient or stationary, isotropic or orthotropic, via THER_LINEAIRE or THER_NON_LINE, cf. necessary environment, parameterization and usage area [R4.10.03](doc:r4.10.03) §6.2/4).

This calculation requires the prior use of the CALC_CHAMP ‘FLUX_ELNO' option which determines the values of the heat flow vector at nodes (see example of [R4.10.03](doc:r4.10.03) §6.5).

The indicator is made up of fifteen components by element and for a given moment. In this test case the fifteen components are calculated but the refinement/derefining procedure is based only on the ERTABS component which represents absolute total spatial error (see [R4.10.03](doc:r4.10.03) §6.3).

In order to be able to post-process via POST_RELEVE or GIBI, we need to extrapolate fields by element to nodes fields by element. The addition of the option ‘ERTH_ELNO_ELEM' (after the call to ‘ERTH_ELEM_TEMP') allows this purely computer-based transformation to be performed. For a moment and a given finite element, it only duplicates the fifteen components of the indicator on each node of the element.

This Modelling is therefore an example of the use in a PYTHON loop of possible "indicator calculation"/"mesh refining/derefining" couplings, as well as of test case non-regression options ‘ERTH_ELEM_TEMP' and ‘ERTH_ELNO_ELEM' and their adhesion to the re-mailing process.

This test case takes over the Modelling characteristics I and its associated mesh (TETRA10 + TRIA6).

### 12.2 Test values

The non-regression computer component of the ERTREL (total relative spatial error) of the error indicator is tested against V6.2.1 versions of the SGI and SUN platforms of *Code_Aster* and the V4.3 version of the HOMARD software. The relative tolerance is therefore severe: 5.10–6%.

| **Identification** | **Aster** | **Tolerance** |
| --- | --- | --- |
| ERTREL on mesh cell MA1 before re-mailing | 4.15918735 10–5 | 5.10–8 |
| ERTREL on node NO4 before re-mailing | 4.15918735 10–5 | 5.10–8 |
| ERTREL value on mesh cell M1 after re-mailing | 5.48408914 10–6 | 5.10–7 |
