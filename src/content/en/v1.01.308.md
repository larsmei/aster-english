# v1.01.308 ERREU10 - Stop validation for instability in STAT_NON_LINE

**Summary:**

This test validates the management of the shutdown on the detection of instability in STAT_NON_LINE. This is based on the test case SSLL105 where a flashing instability is observed.

## 1 Test principle

This test has only one model where one of the nonlinear resolutions of the test case SSLL105D is taken.

When calling STAT_NON_LINE, a flashing instability occurs and we will check here that the associated exception is intercepted and the test is properly completed: the base is properly closed and would therefore be usable in pursuit.

This mode of stopping on instability, whether in STAT_NON_LINE or DYNA_NON_LINE, is triggered by declaring in DEFI_LIST_INST an event of the type 'INSTABILITE' associated with the 'ARRET' action. Without this specific argument, the code, in its default mode, will attempt to continue the calculation even in the presence of instability: the nonlinear algorithm follows a branch of solution.

In practice, we will test the three instability criteria options, which are defined *via* the value associated with keyword SIGNE on CRIT_STAB in STAT_NON_LINE [U4.51.03](doc:u4.51.03).

The critical load, during the nonlinear calculation, initially exceeds 2 and decreases to below 1: so we have a instability by positive values.

So if the shutdown criterion considers any calculated value between -1 and 1 (SIGNE = 'POSITIF_NEGATIF') to be unstable then the calculation must stop well because of the 'INSTABILITE' event of DEFI_LIST_INST.

If this criterion considers unstable the critical loads between 0 and 1 (SIGNE = 'POSITIF'), the same type of shutdown will also be used.

On the other hand, if the shutdown criterion is based on the -1 to 0 (SIGNE = 'NEGATIF') instability interval, then the nonlinear calculation must continue until the end of its moment list.
