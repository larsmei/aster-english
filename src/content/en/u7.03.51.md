# u7.03.51 Macro-command RAFF_XFEM

## 1 Purpose

Perform the computation of the error criterion prior to a mesh refinement for cracks and interfaces modelled by the X-FEM method.

The command produces a data structure cham_no.

## 2 Syntax

```text
/ carte
/ cham_no = RAFF_XFEM(
    ◇ TYPE = / "DISTANCE" (par défaut),
             / "ZONE",
    ◆ FISSURE = fiss_xfem,
    # Si: equal_to("TYPE", 'ZONE')
        ◆ RAYON = float,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 General operation

The operator RAFF_XFEM makes it possible to create a field in anticipation of a mesh refinement in the framework of cracks represented by the X-FEM method. The idea is to characterise the nodes or the mesh cells located in a zone around the crack front (zone of interest). This will make it possible to refine subsequently the mesh cells close to the crack front, for example in order to improve the computation of the energy release rate.

The field created by RAFF_XFEM may be qualified as an *a priori* “error” field (or indicator).

The indicator created may be of 2 types (TYPE = 'DISTANCE' or 'ZONE').

### 3.1 Distance indicator

By choosing this type of indicator, the operator RAFF_XFEM creates an a priori “error” field at the nodes. This error at each node reflects the minimum of the distances to the crack fronts (or to the surface for the interfaces).

Thus, the nodes close to the X-FEM crack fronts (or to the X-FEM surfaces for the interfaces) will have a high “error”. Conversely, the further away the node is, the smaller the “error” will be. This criterion is used for the mesh-refinement software used subsequently (see for example sslp317a,b). The nodes closest to the crack fronts will be refined as a priority.

More precisely, if one denotes by $\mathrm{lsn}$ the normal level set and by $\mathrm{lst}$ the tangential level set, the nodal field created has the formula:

$\mathrm{erreur}=-r$ where $r$ is the distance:

- to the crack front for the cracks: $r=\sqrt{({\mathrm{lsn}}^{2}+{\mathrm{lst}}^{2})}$
- to the interface for the interfaces: $r=\sqrt{({\mathrm{lsn}}^{2})}$

The values of the field are therefore all negative. Very distant nodes ($r$ large) will have negative error values very far from 0 and close nodes ($r$ small) will have negative error values close to 0. It will suffice to tell Homard (MACR_ADAP_MAIL) to refine the mesh cells where the value is the largest (mathematically speaking). To do this, it will be necessary to specify in MACR_ADAP_MAIL:

USAGE_CMP = 'RELATIF'

One may either refine a given percentage of the mesh cells closest to the front (CRIT_RAFF_PE), or give a value of the distance (more precisely the opposite of the distance) below which the mesh cells will be refined (CRIT_RAFF_ABS). For further advice, consult the documentation [U2.05.02](doc:u2.05.02).

This distance indicator may pose problems which will not be discussed here. That is why a second, more robust, indicator has been developed.

### 3.2 Zone indicator (binary indicator)

This is the **recommended** indicator.

By choosing this indicator, the operator RAFF_XFEM creates a field by mesh cell (field of type carte) of binary nature. The principle of this indicator is to be equal to 1 in the zone to be refined (zone of interest) and 0 everywhere else. The zone of interest is in 2D a disc around the crack front and in 3D a torus around the crack front, characterised by the datum of a radius ${R}_{\mathit{raff}}$ .

For the interfaces, the zone of interest is a band around the interface.

More precisely:

The field is initialised to 0.

The field is set to 1 if the mesh cell contains:

- the crack front (for the cracks),
- the interface (for the interfaces).

In addition, the field is set to 1 if the mesh cell has at least one node located at a distance from the front (or from the interface) less than ${R}_{\mathit{raff}}$ . This distance is determined in the same way as that appearing in the distance indicator (see § 3.1 ).

This indicator is easier to handle than the distance indicator. It is used with the default keywords of MACR_ADAP_MAIL, but exclusively with a criterion in absolute value (CRIT_RAFF_ABS). The value of the criterion does not matter (between 0 and 1), but for reasons of readability it is recommended to choose CRIT_RAFF_ABS= 0,5. Examples of use will be found in the tests sslv155[b,c] , sslv110f , sslp317c . For further advice, consult the documentation [U2.05.02](doc:u2.05.02).

### 3.3 Note common to the 2 types of indicator

It must be noted that the 2 indicators are based on the level sets. At the present time, the level sets are computed over the whole mesh, but one may limit the potential enrichment zone to only part of the mesh (keyword GROUP_MA_ENRI of the command DEFI_FISS_XFEM). In the case where the level sets are liable to define a crack outside the zone delimited by GROUP_MA_ENRI 1
, the indicator computed by RAFF_XFEM, being based on the level sets, does not take the restriction of the crack into account. This means that certain nodes or certain mesh cells (outside GROUP_MA_ENRI) may have high error values without however being close to the crack front. In order to prevent these nodes from causing an unnecessary refinement in this zone, it is also recommended to limit the refinement zone in MACR_ADAP_MAIL, by means of the keyword GROUP_MA (supply the same mesh-cell group as the one given under GROUP_MA_ENRI).

See the documentation of DEFI_FISS_XFEM [U4.82.08] for an illustrated example of such a case.

## 4 Operands

### 4.1 Operand TYPE

```text
◊    TYPE    =    /    'DISTANCE',                    [DEFAUT]
/    'ZONE'

Permet de choisir le type d'indicateur. Par défaut, c'est indicateur en distance qui est choisi.
:ref:`3 <RefNumPara__21660_123247218>`
Voir la description du fonctionnement des 2 types d'indicateur au §.
```

### 4.2 Operand FISSURE

```text
    FISSURE        =    (fiss1, fiss2)
```

(fiss1, fiss2): list of the names of the cracks (or interfaces) defined beforehand by the operator DEFI_FISS_XFEM [U4.82.08](doc:u4.82.08). The number of cracks (or interfaces) is not limited.

### 4.3 Operand RAYON

Makes it possible to supply the value of the radius of the zone of interest (see § 3.2 ). This operand is possible only for the zone indicator.
