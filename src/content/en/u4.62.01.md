# u4.62.01 Operator MACR_ELEM_STAT

## 1 Purpose

Create macro-elements for analyses of "static substructuring" or for analyses of "structural modification".

In the case of analyses of "static substructuring", the macro-element is computed by assembly of ordinary finite elements and condensation of the matrices onto the "external" degrees of freedom.

In the case of "structural modification", the macro-element is computed by expansion and condensation of the identified (measured) modal model onto the "external" degrees of freedom.

Produces a data structure of type macr_elem_stat.

## 2 Syntax

```text
macr_elem_stat = MACR_ELEM_STAT(
    ◇ reuse = <objet de MACR_ELEM>,
    ◇ MACR_ELEM = macr_elem_stat,
    ◆ | DEFINITION = _F(
           ◆ MODELE = modele,
           ◇ CHAM_MATER = cham_mater,
           ◇ CARA_ELEM = cara_elem,
           ◇ CHAR_MACR_ELEM = char_meca,
           ◇ INST = float (défaut: 0.0),
           ◇ NMAX_CAS = int (défaut: 10),
           ◇ NMAX_CHAR = int (défaut: 10),
           ◇ & PROJ_MESU = harm_gene / mode_gene / tran_gene,
             & MODE_MESURE = mode_meca,
        ),
      | RIGI_MECA = _F(
        ),
      | MASS_MECA = _F(
        ),
      | CAS_CHARGE = _F(
           ◆ NOM_CAS = text,
           ◇ SUIV = / "NON",
                    / "OUI" (par défaut),
           ◇ CHARGE = char_meca,
           ◇ INST = float (défaut: 0.0),
        ),
    ◇ & EXTERIEUR = _F(
           ◆ | GROUP_NO = grno,
        ),
    ◇ AMOR_MECA = _F(
      ),
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 General points

This operator is a **mandatory** step for static substructuring or for a structural-modification analysis by condensation of the measurement.

For static substructuring, it is used:

- to define a macro-element (keywords: DEFINITION and EXTERIEUR),
- to request the condensation of the stiffness (or mass) matrix,
- to define (and condense) the associated loadings; the user may on this occasion name one or more load cases.

These 3 steps can be carried out in a single call to MACR_ELEM_STAT. But they can be carried out in several stages thanks to the use of the keyword "reuse" (enrichment of the macr_elem_stat). The definition step must be carried out first. The condensation of the mass must be done after the condensation of the stiffness.

For structural modification, it is used:

- to define a macro-element (keywords: DEFINITION and EXTERIEUR),
- to request the expansion and the condensation of the measurement in order to arrive at condensed stiffness and mass matrices.

The macr_elem_stat is a data structure which contains:

- its references: modele, cara_elem, cham_mater, load,
- its topological description: the external nodes,
- its condensed matrices (stiffness, mass, ...),
- a list of named condensed loadings (for static substructuring).

The use of the full set of static-substructuring operators is described in the user's guide U2.07.02, and the structural-modification procedure is described in the user's guide U2.07.03.

## 4 Operands

### 4.1 Keyword DEFINITION

```text
◊    DEFINITION
```

This factor keyword (not repeatable) is used to define the macro-element.

#### 4.1.1 Operand MODELE

```text
♦    MODELE= mo
```

"Static substructuring" case:

Name of the model that one wishes to condense. The matrices (and loadings) that one condenses are always computed on the model **as a whole**. When one wishes to condense several subsets of one and the same mesh, one must therefore create several models on different mesh-cell groups.

"Structural modification" case:

Name of the model given under the keyword MODELE_CALCUL of the command PROJ_MESU_MODAL associated with repgene of the keyword PROJ_MESU. This model serves as a support for the expansion of the measurement onto the "external" nodes.

#### 4.1.2 Operand CHAM_MATER

```text
◊    CHAM_MATER= chmat
```

Name of the material field associated with the model. This argument is unnecessary if the model contains only discrete elements and static substructures. It is mandatory otherwise.

#### 4.1.3 Operand CARA_ELEM

```text
◊    CARA_ELEM= carac
```

Name of the elementary characteristics if the model includes beam, plate or shell elements.

#### 4.1.4 Operands CHAR_MACR_ELEM / INST

```text
◊    CHAR_MACR_ELEM= lchar
```

This argument is used to define:

- the thermal loading which may modify the material characteristics, when these depend on the temperature; one will if necessary specify the time instant of the thermal evolution (keyword INST),
- the kinematic conditions applied to the **internal nodes** (cf. keyword EXTERIEUR) of the macro-element.

```text
◊    INST= inst
```

During an analysis for which the material characteristics depend on the temperature, one specifies here the temperature field to be used. The field used is the one corresponding to the time instant inst of the thermal evolution referenced in the list of loads lchar (refer to the command CALC_MATR_ELEM('RIGI_MECA')) [U4.61.01](doc:u4.61.01).

**Notes on the kinematic conditions:**

*In the static-substructuring operators, kinematic conditions of "Dirichlet" type are always dualised, never eliminated.*

*In general one will apply the kinematic conditions on the* **external nodes** *at the higher level of substructuring. They will therefore not appear in the loads of* *lchar.*

*On the other hand, the kinematic conditions that must be given before condensation (lchar) are those that one will no longer be able to give afterwards:*

- *the conditions involving internal nodes (imposed degrees of freedom or linear relations) because these nodes will be eliminated,*
- *the conditions defined from the* **edges** *of the finite elements* (FACE_IMPO) *because these finite elements will no longer exist after condensation.*

**Note on the argument** **lchar:**

*The loads which appear in the list* *lchar are those which make it possible to compute the stiffness and mass matrices:*

- *possible temperature load modifying the material characteristics,*
- *kinematic conditions (dualisation).*

*on the other hand, these loads play no part in the definition of the loadings (right-hand sides).*

*For example, the expansions due to the temperature field will be taken into account in a load case only if the load containing this temperature field is explicitly given in the definition of this load case (keywords* CAS_CHARGE *and* CHARGE). *In the same way the* **non-zero kinematic conditions** *must be given again in the definition of the load cases.*

#### 4.1.5 Operands NMAX_CAS / NMAX_CHAR

```text
◊    NMAX_CAS= nbcamx
```

One gives here an **upper bound** on the number of load cases that the user will define on the macro-element (see argument CAS_CHARGE). This number is taken by default as 10.

```text
◊    NMAX_CHAR= nbchmx
```

One gives here an **upper bound** on the number of concepts of type load that one will assign to **each** load case (see argument CAS_CHARGE). This number is taken by default as 10.

#### 4.1.6 Operand PROJ_MESU

```text
♦    PROJ_MESU= repgene
```

repgene denotes the name of the concept produced by the command PROJ_MESU_MODAL [U4.73.01](doc:u4.73.01) which made it possible to define the measurement and the projection basis.

#### 4.1.7 Operand MODE_MESURE

```text
♦    MODE_MESURE= modemes
```

One gives here the name of the concept containing the eigenmodes identified experimentally. These eigenmodes make it possible to build the modal model of the initial structure which will then be condensed onto the "external" nodes.

### 4.2 Keyword EXTERIEUR

```text
♦    EXTERIEUR=
```

This factor keyword (not repeatable) is used to define the set of "external" nodes onto which the matrices and the loadings will be condensed (the other nodes will be called "internal"). This keyword must appear in the first call to the command MACR_ELEM_STAT (one defines the exterior of a macro-element in a single step).

Each external node carries the same degrees of freedom as the corresponding node of the model mo. A macro-element is topologically (and geometrically) entirely defined by the set of its external nodes.

#### 4.2.1 Notes on the definition of the "exterior" of a macro-element

- The exterior of a macro-element is the set of "external" nodes which define the topology and the geometry of the macro-element,
- each "external" node carries **all** the degrees of freedom which exist on this node in the underlying model. The macro-elements produced by *Aster* can be used only by joining their external nodes and consequently all the degrees of freedom that they carry. Other analysis codes operate differently. For certain modellings (sliding, hinge, …), one will be led not to join certain nodes and to use, at the higher substructuring level, linear relations between the degrees of freedom of the external nodes of several macro-elements,
- when defining the external nodes of a macro-element, if a node appears several times, it is counted only once,
- for programming reasons, both external nodes and internal nodes must exist: neither family may be empty.

#### 4.2.2 Operand GROUP_NO

```text
GROUP_NO= l_grno
```

List of the names of the node groups that one wishes to be "external".

### 4.3 Keywords RIGI_MECA / MASS_MECA

```text
♦    RIGI_MECA
```

This keyword is used to specify that one wishes to condense the stiffness matrix.

"Static substructuring" case:

This matrix is computed on **all** the elements of the model as well as on the LAGRANGE elements of the kinematic conditions contained in the argument of CHAR_MACR_ELEM.

"Structural modification" case:

The condensed stiffness matrix is computed by expansion of the measured spectral matrix onto the "external" nodes.

```text
◊    MASS_MECA
```

This keyword is used to specify that one wishes to condense the mass matrix.

"Static substructuring" case:

This matrix is computed on **all** the elements of the model (GUYAN condensation).

"Structural modification" case:

The condensed mass matrix is obtained by expansion of the matrix of measured generalised masses onto the "external" nodes.

```text
◊    AMOR_MECA
```

This keyword is used to specify that one wishes to condense the damping matrix.

This feature is not available in "static substructuring":

"Structural modification" case:

The condensed damping matrix is obtained by expansion of the matrix of measured generalised dampings onto the "external" nodes.

### 4.4 Keyword CAS_CHARGE.

```text
◊    CAS_CHARGE
```

This factor keyword makes it possible to define a set of **named** load cases (keyword NOM_CAS). These load cases may be applied to the higher-level model (CALC_VECT_ELEM [U4.61.02](doc:u4.61.02)).

In general, one will seek to apply the nodal loadings (FORCE_NODALE) at the higher level of substructuring.

On the other hand all the loadings defined on the finite elements must be applied before any condensation: (PESANTEUR, ROTATION, FORCE_FACE, FORCE_CONTOUR, FORCE_INTERNE, FORCE_COQUE, FORCE_POUTRE, PRES_REP, …) since these finite elements will have "disappeared" after condensation.

Note that for a macro-element, there is no notion of contour, of orientation, of face, ...

#### 4.4.1 Operand NOM_CAS

```text
♦    NOM_CAS= nocas
```

The loading condensed under the name nocas (between "quotes") corresponds to the loading defined by the arguments of CHARGE and INST to which one **systematically** adds the loadings of name nocas possibly present on the lower-level substructures contained in the model mo.

#### 4.4.2 Operand SUIV

```text
◊    SUIV= 'OUI'/'NON'
```

This keyword states whether the load case "follows" the macro-element in its geometric transformations: translation, rotation, (cf. operator DEFI_MAILLAGE [U4.23.01](doc:u4.23.01)). For example, the loading due to a rotation (centrifugal force), a pressure (or a restrained expansion) is "follower" because its direction is linked to the position of the substructure. On the other hand, gravity is a "non-follower" loading (its direction is absolute).

**Warning:**

*Kinematic loadings are always "follower" because their taking into account is done in the stiffness matrix (dualisation) and this matrix is "follower" by nature.*

#### 4.4.3 Operands CHARGE / INST

```text
◊    CHARGE= lchar,
◊    INST= tps,
```

The keywords CHARGE and INST have the same meaning as in the operator CALC_VECT_ELEM [U4.61.02](doc:u4.61.02).

## 5 Examples of definition of a macro-element

### 5.1 Defining the exterior of a macro-element

```text
sup1 =        MACR_ELEM_STAT    (
```

DEFINITION=    _F    (    MODELE= mo,            CHAM_MATER= chmat),
EXTERIEUR=    _F    (    GROUP_NO= EXT ),
)

> sup3 =        MACR_ELEM_STAT    (

DEFINITION=    _F    (    MODELE= mo ,            CHAM_MATER= chmat,),
EXTERIEUR=    _F    (    GROUP_NO= ('L1','L3'),)

### 5.2 Condensing stiffness and mass matrices

```text
sup1 =        MACR_ELEM_STAT    (reuse = sup1,
```

RIGI_MECA= _F (),    MASSE_MECA= _F (),
)

### 5.3 Defining a loading on the macro-element

```text
sup1 =        MACR_ELEM_STAT    (reuse = sup1,
```

CAS_CHARGE=    (    NOM_CAS= 'ch1'    ,    CHARGE= ch1,),
)

### 5.4 Defining the macro-element, its loadings, and requesting the condensation of the matrices

```text
sup2 =        MACR_ELEM_STAT    (
```

DEFINITION    = _F    (    MODELE= mo    ,    CHAM_MATER= chmat),
EXTERIEUR        = _F    (    GROUP_NO= EXT ),
RIGI_MECA        = _F    (),
MASSE_MECA    = _F     (),
CAS_CHARGE    = _F    (    NOM_CAS= 'ch1'    ,    CHARGE= ch1 ),
)

### 5.5 Defining a macro-element for a structural-modification analysis and requesting the condensation of the matrices

```text
Sup4 =        MACR_ELEM_STAT    (
```

DEFINITION    = _F    (    MODELE= mo    ,    CHAM_MATER= chmat

> PROJ_MESU=repgene, MODE_MESURE=modemes),

EXTERIEUR        = _F    (    GROUP_NO= EXT ),
RIGI_MECA    = _F    (),    MASSE_MECA= _F (),
)
