# v2.08.011 FORMA11 - Practical work of the "dynamic analysis" training: modal analysis

**Summary:**

These tests correspond to the practical work of dynamic formation of *Code_Aster*. These are four geometries, consisting of all of a linear elastic material for which modal analysis is performed: search for eigenfrequencies and associated modes.

The modellings used are:

- Modelling A: Multiple mode searches of a beam (POU_D_E)
- Modelling B: Searching for rigid body modes of a sphere (3D)
- Modelling C: Use of the CALC_MODES operator for the analysis of a cooling tower (DKT),

The practical work of dynamic training is presented in this document:

- TP1: Searches for multiple modes of a beam,
- TP2: Search for rigid body modes,
- TP3: Using CALC_MODES macro-command.

### 1.4 Remarks

The good practice is to use the option ‘BANDE' rather than ‘PLUS_PETITE' or ‘CENTRE'.

The number of frequencies is automatically determined by the Sturm test and thus all multiplicities are taken into account.

The ‘SORENSEN' method is the fastest (despite its iterative character which allows for better accuracy)

The project is to a smaller space (compared to ‘TRI_DIAG' and ‘JACOBI') and only factorization (compared to the reverse power algorithms used when using OPTION='AJUSTE'/'SEPARE'/'PROCHE').

In the presence of multiple modes, the slightest modification of the parameterization of the modal method (or the associated tripaille NUME_DDL...) produces different own vectors.

But they always create the same clean space,

### 2.4 Remarks

Factorization of ${(K-\sigma \text{})}^{-1}={\mathrm{LDL}}^{T}$ shifted matrices controlled by the parameterization: NMAX_ITER_SHIFT, SOLVEUR/NPREC[U4.50.01] and PREC_SHIFT can only be performed if these are regular.

This often poses a problem when the magnitude of the terms of $K$ is large in front of the terms of $M$ and $\sigma$ is a good value of its own. Operator policy is to emit an ALARME when it comes to a Sturm test and an ERREUR_FATALE when it comes to the operator's work matrix. In case of a problem, one can always change the option or shift.

The detection of rigid body modes is often problematic for conventional modal solvers! The good practice is to use the SORENSEN method using a frequency band with a low bound of zero, if not slightly negative. Normally the solver captures them without any problem (it is just a few specific multiple modes). If not, with TRI_DIAG, the MODE_RIGIDE option is recommended.

## 3 Modelling C

### 3.1 Description of the problem

The objective of this Modelling is to use CALC_MODES [U4.52.02](doc:u4.52.02) macro-command with the 'BANDE' option cut into several sub-bands. This command allows to launch a sequence of real eigenmode calculations.

The following actions are carried out:

- Obtaining modes by simultaneous iterations in specified frequency bands,
- Application of a standard, filtering according to a modal parameter criterion above a certain threshold and finally concatenation of data structures calculated in one.

The modes are calculated by the CALC_MODES [U4.52.02](doc:u4.52.02) command with the 'BANDE' option and standardized by the NORM_MODE [U4.52.11](doc:u4.52.11) command. The calculated modes are filtered and concatenated using the EXTR_MODE [U4.52.12](doc:u4.52.12) command.

#### 3.1.1 Purpose

The objective of this modelling is:

- To "weigh" the finished elements model and evaluate the number of modes,
- D-use CALC_MODES macro-command with 'BANDE' option cut into multiple sub-bands to calculate eigenfrequencies.

#### 3.1.2 Geometry

We can get the mesh back from the test case directory.
