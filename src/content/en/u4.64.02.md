# u4.64.02 Operator DEFI_BASE_MODALE

## 1 Purpose

The purpose of the operator is to define:

- the basis of a dynamic substructure, when one has split the complete structure into substructures;
- or the basis of a modal recombination, when one treats the complete structure directly.

The modal basis obtained by this operator is of type: 'CLASSIQUE' if the modal basis is composed of dynamic eigenmodes and of the static deflected shapes computed by the operator from a concept of type interf_dyna_clas produced by DEFI_INTERF_DYNA [U4.64.01](doc:u4.64.01). The option DIAG_MASS makes it possible to recompute a numbering for the static modes such that the mass matrix is diagonal.

The basis is of RITZ type in the other cases.

The operator produces a concept of type mode_meca.

## 3 Operands

### 3.1 Factor keyword CLASSIQUE

```text
♦    /    CLASSIQUE = _F(
```

Factor keyword for the definition of a modal basis of type 'CLASSIQUE', when one carries out an analysis by dynamic substructuring.

#### 3.1.1 Operand INTERF_DYNA

```text
♦    INTERF_DYNA = intdyn
```

Name of the concept of type interf_dyna_clas produced by DEFI_INTERF_DYNA [U4.64.01](doc:u4.64.01).

The operator computes the static deflected shapes corresponding to the various defined interfaces, relying on the numbering used for the computation of the eigenmodes.

#### 3.1.2 Operands MODE_MECA / NMAX_MODE

```text
◊    MODE_MECA = modes
```

List of the concepts of type mode_meca containing the eigenmodes of the structure.

```text
◊    NMAX_MODE = nbmodes
```

List of integers giving, for each mode_meca concept, the maximum number of eigenmodes to retain. Starting from the i-th modal basis of the list modes, one then retains the modes corresponding to the nbmodes[i] lowest frequencies.

In general, the length of the list of integers supplied under the keyword NMAX_MODE must correspond to that of the list of modal bases (keyword MODE_MECA). The only exception to this rule is when a single value is given in NMAX_MODE. In that case, the value of NMAX_MODE is used for each of the modal bases.

If NMAX_MODE is not supplied, one takes by default all the modes of each of the modal bases given under the keyword MODE_MECA.

### 3.2 Factor keyword RITZ

```text
♦    /    RITZ = _F(
```

Factor keyword making it possible:

- in the case of an analysis by substructuring, to build a substructure modal basis of type 'RITZ';
- in the case of an analysis carried out directly on the complete structure, to build an enriched modal basis (for example: vibration eigenmodes, which one enriches with static modes associated with external forces).

The basis is constituted in two different ways: either from two occurrences of the keyword RITZ (one with the keyword MODE_MECA or BASE_MODALE, and another necessarily with the keyword MODE_INTF; the other possibilities are not allowed); or from a single occurrence of the keyword RITZ, in which case only the keyword MODE_MECA is accepted (little used, except possibly to reduce the number of modes or to change the reference numbering).

#### 3.2.1 Keyword MODE_MECA

Name of the concept of type mode_meca containing the vibration eigenmodes of the structure, or of the substructure in the case of an analysis by substructuring.

It may be used alone, or in the presence of a second occurrence of RITZ with the keyword MODE_INTF (if one wishes to add interface modes, for example).

One may give a list of mode_meca obtained for the same structure (with different boundary conditions, for example).

#### 3.2.2 Keyword MODE_INTF

Name of the concept of type mode_meca (produced by CALC_MODES [U4.52.02](doc:u4.52.02) or by MODE_STATIQUE [U4.52.14](doc:u4.52.14)) or mult_elas (produced by MACRO_ELAS_MULT [U4.51.02](doc:u4.51.02)) containing:

- in the case of an analysis by substructuring: the modes that one wants to use as interface modes of the substructure;
- in the case of an analysis carried out directly on the complete structure: modes which enrich the basis of vibration eigenmodes given under the preceding keyword MODE_MECA. These may, for example, be static deflected shapes associated with external forces (a known imposed force; an impact force associated with an obstacle; etc.).

It can be used only in the presence of a second occurrence of the keyword RITZ which will contain the keyword MODE_MECA or BASE_MODALE (even if one has to set NMAX_MODE to zero if, for example, one does not wish to take this keyword into account).

#### 3.2.3 Keyword BASE_MODALE

Name of the concept of type mode_meca produced by a previous call of the operator DEFI_BASE_MODALE [U4.64.02](doc:u4.64.02). It can be entered only when the number of occurrences of the keyword RITZ is equal to two. The other occurrence of the keyword RITZ will then necessarily contain the keyword MODE_INTF (in order to enrich an existing basis). The name of the resulting mode_meca concept of the operator may be different from this one, or identical (it is then re-entrant).

#### 3.2.4 Operand NMAX_MODE

Number of modes to retain among the dynamic (or static) modes given by one of the preceding keywords under the occurrence of the keyword RITZ. If one supplies a list of mode_meca, one must give either a list of the same length for the numbers of modes to retain, or a single value (in that case, this value is applied to all the mode_meca concepts).

If NMAX_MODE is not supplied, one takes by default all the modes.

#### 3.2.5 Operand INTERF_DYNA

Dynamic interface of the substructure (to be supplied if necessary, and only if one uses the factor keyword 'RITZ').

#### 3.2.6 Operand NUME_REF

Reference numbering onto which all the displacement fields (dynamic and static modes) constituting the 'RITZ' basis will be reordered.

#### 3.2.7 Operand LIST_AMOR

List of the modal dampings that the user may supply in order to enrich the modes declared under the keyword MODE_MECA. This amounts to adding reduced dampings for these same modes even if, originally, they are real modes. This option is useful for simulating experimental results.

#### 3.2.8 Operand ORTHO

Operand making it possible to carry out an orthonormalisation of the Ritz basis (to be supplied if one wishes this re-orthonormalisation, and only if one uses the factor keyword 'RITZ'). This orthonormalisation is performed with an iterative Gram-Schmidt algorithm (IGS) following the Kahan-Parlett version.

#### 3.2.9 Keyword MATRICE

Name of the concept of type matr_asse_* which will be taken into account for the scalar products during the re-orthonormalisation of the RITZ basis. This keyword is mandatory if ORTHO='OUI'.

### 3.3 Factor keyword DIAG_MASS

```text
♦    /    DIAG_MASS = _F(
```

Keyword making it possible to recompute the static modes by eliminating the dynamic contribution and by carrying out a Gram-Schmidt orthogonalisation.

#### 3.3.1 Keyword MODE_MECA

Name of the concept of type mode_meca containing the dynamic eigenmodes of the substructure being treated.

#### 3.3.2 Keyword MODE_STAT

Name of the concept of type mode_meca produced by the operator MODE_STATIQUE [U4.52.14](doc:u4.52.14) which contains the static modes.

### 3.4 Factor keyword ORTHO_BASE

```text
♦    /    ORTHO_BASE = _F(
```

Keyword making it possible to orthonormalise the modes of a basis. This orthonormalisation is performed with an iterative Gram-Schmidt algorithm (IGS) following the Kahan-Parlett version.

#### 3.4.1 Keyword BASE

Name of the concept of type mode_meca or mult_elas containing dynamic eigenmodes.

#### 3.4.2 Keyword MATRICE

Name of the concept of type matr_asse_* which will be taken into account for the scalar products during the re-orthogonalisation.

### 3.5 Factor keyword SOLVEUR

```text
◊ SOLVEUR = _F(...)
```

This factor keyword is optional: it makes it possible to choose another solver for the solution of the system. In the case of this command, the syntax of the keyword is restricted to two methods: one may choose between the default method, MULT_FRONT, and the methods LDLT or MUMPS. The syntax being common to several commands, please consult the manual [U4.50.01](doc:u4.50.01).

### 3.6 Operand TITRE

```text
◊    TITRE = titre
```

Title of the concept created.

### 3.7 Operand INFO

```text
◊    INFO =
```

Level of the information supplied in the file MESSAGE:

| 1 | no printout; |
| --- | --- |
| 2 | writing of the general information (upstream concepts, type of basis). |

## 4 Examples

### 4.1 Dynamic substructuring

The various modellings of the test case SDLS106 present the complete implementation of an analysis by substructuring, with various methods (Craig-Bampton, Mc Neal, compatible meshes or not, etc.).

### 4.2 Enrichment of a basis of eigenmodes with static modes

```text
# calcul des matrices assemblées et de la numérotation des DDL

...

# calcul des modes propres de vibration

modesvib = CALC_MODES( MATR_RIGI=K_ASSE,

MATR_MASS=M_ASSE,

CALC_FREQ=_F( NMAX_FREQ = nb_freq) ,

);

# application d'une force extérieure

force = AFFE_CHAR_MECA( MODELE=modele,

FORCE_NODALE=_F( NOEUD = 'N11',

FX=800., FY = -1000.));

# calcul de la déformée statique associée à cette force extérieure

modestat = MODE_STATIQUE( MATR_RIGI=K_ASSE,

MATR_MASS=M_ASSE,

FORCE_NODALE=_F( NOEUD='N11',

AVEC_CMP=('DX','DY') ),

);

# construction de la base modale enrichie

basemode = DEFI_BASE_MODALE( RITZ =(_F( MODE_MECA=modesvib ),

_F( MODE_INTF=modestat ),

),

NUME_REF=NUMDDL,

);
```

The test case SDNL104c presents the complete implementation of this technique.

Another example is given by the test case SDNL301a, in which the static deflected shapes that enrich the basis of eigenmodes are those linked to external forces generated by shocks.
