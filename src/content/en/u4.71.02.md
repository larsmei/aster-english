# u4.71.02 Operator RECU_TABLE

## 1 Purpose

```text
Permet de récupérer dans une table les valeurs d’un paramètre d’une structure de données résultat, ou bien, d’extraire une table contenue dans une autre structure de données pour celles qui le permettent.
```
```text
La table créée peut alors être utilisée dans d’autres commandes (IMPR_TABLE par exemple).
```
```text
Produit une structure de données de type table.
```
## 2 Syntax

```text
table = RECU_TABLE(
    ◆ CO = datastructure,
    ◆ / NOM_TABLE = text,
      / NOM_PARA = text,
      / TOUT_PARA = "OUI" (ou non renseigné),
    ◇ TITRE = text,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```
## 3 Operands

```text
♦    CO    =    nomsd ,
```
Name of the data structure from which one wants to extract a table.

```text
♦    /    NOM_TABLE    =    nomtab ,
```
Name of the table stored in the data structure.

Today, the data structures containing a table which one can extract by RECU_TABLE / NOM_TABLE are the following:

- a data structure of type evol_noli obtained by STAT_NON_LINE or DYNA_NON_LINE; the name of the table is then 'OBSERVATION',
- a data structure of type maillage. The name of the table is then 'CARA_GEOM',
- a data structure of type cabl_precont obtained by the command DEFI_CABLE_BP. The name of the table is then 'CABLE_BP',
- a data structure of type melasflu obtained by the command CALC_FLUI_STRU; the name of the table is then 'MATR_GENE'.
- the data structures of type evol_elas and evol_noli containing the global error estimators computed by CALC_ERREUR. The name of the table is then 'ESTI_GLOB'.
- a data structure of type evol_noli obtained by STAT_NON_LINE or DYNA_NON_LINE, or of type evol_elas obtained by DYNA_VIBRA on a physical basis, contains a table named 'PARA_CALC' comprising the list of the time instants actually computed and, if the user activates the analysis, the energy balance. The table contains 7 columns:

  - INST: analysis time instant,
  - TRAV_EXT: work of the external forces,
  - ENER_CIN: kinetic energy,
  - ENER_TOT: total strain energy,
  - TRAV_AMOR: energy dissipated by damping,
  - TRAV_LIAI: energy dissipated and/or stored by the connections,
  - DISS_SCH: energy dissipated by the numerical scheme.

```text
♦    /    NOM_PARA    =    lpara ,
```
List of the names of the parameters to be extracted from the SD RESULTAT nomsd.

This functionality makes it possible to extract, in the form of a table, the evolution of certain parameters of an SD RESULTAT, for example the piloting parameter ETA_PILOTAGE in the case of an SD of type evol_noli. The extracted parameters must be of integer, real or complex type, thereby excluding character strings. The first column of the table produced contains the order numbers (NUME_ORDRE) and the following ones contain the evolution of the parameters lpara.

```text
♦    /    TOUT_PARA    =    ‘OUI’ ,
```
This keyword makes it possible to extract all the parameters of the SD RESULTAT nomsd of integer, real or complex type.

This produces the same table as if one gives all these parameters to NOM_PARA.

```text
◊    TITRE    =    titr ,
```
Title which one wants to give to the result table.

## 4 Examples

- recovery of a few geometric characteristics of a mesh:

```text
cargeo = RECU_TABLE ( CO= maillage    ,        NOM_TABLE= 'CARA_GEOM' ,)
```
- recovery of the values "observed" in the command DYNA_NON_LINE

The command DYNA_NON_LINE [U4.53.01](doc:u4.53.01) makes it possible to choose a set of mesh cells or of nodes for which one wishes to observe one or more components of certain fields (keyword OBSERVATION).

```text
dynl = DYNA_NON_LINE ( ...    OBSERVATION= _F    ( ... ) ... )

tabobs = RECU_TABLE ( CO= dynl , NOM_TABLE= 'OBSERVATION' , )
```
- recovery of the piloting parameter of an SD of type evol_noli

```text
stnl = STAT_NON_LINE ( ...    PILOTAGE= _F    ( ... ) ... )

etapilo = RECU_TABLE ( CO= stnl    , NOM_PARA= 'ETA_PILOTAGE' ,)
```
