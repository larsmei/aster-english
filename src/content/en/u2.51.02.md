# u2.51.02 Plotting curves with Code_Aster

**Summary:**

This document explains how, starting from an analysis result, one can produce tables or functions, extract the values of these tables or functions, manipulate them, and finally, as a last step, use the print commands in order to plot curves.

If you have a function or a table and you simply wish to represent it in the form of a curve, go directly to paragraph [§ 4 ], and consult the documentations of the commands IMPR_FONCTION [U4.33.01](doc:u4.33.01) and IMPR_TABLE [U4.91.03](doc:u4.91.03).

**Preliminary note**

*The post-processing must be carried out in* *POURSUITE and not in continuation of the analysis. There are several reasons for this:*

1. *in the event* of an error *, one does not lose the hours of the run which made it possible to reach the* result *,*
2. one can carry out numerous post-processings directly by launching Stanley on the result database of the analysis (see astk [U1.04.00](doc:u1.04.00) or *STANLEY* [U4.81.31](doc:u4.81.31)),
3. *in order to simplify the post-processing, one can use the possibilities offered by Python, which require being in* *PAR_LOT='NON' in* *POURSUITE, which prevents the use of eficas for this type of post-processing, whereas it is simpler to use eficas to build the main data set.*

## 1 Extracting the data with the help of the Aster commands

One assumes that the user has an analysis result obtained from, for example, the command CALC_MODES for an eigenmode analysis, STAT_NON_LINE for a non-linear static analysis, or DYNA_NON_LINE for a non-linear dynamic analysis…

One has in every case a result concept which will be, for example, of type mode_meca, mode_flamb, dyna_trans, tran_gene, evol_elas, evol_noli, evol_ther, etc. depending on the command used and which contains fields of values that one wishes to represent in the form of curves.

### 1.1 Producing a function or a table

**Reminder**

*A function is composed of two lists of values, abscissae and ordinates; the abscissae are necessarily monotonic.*

*A table is an agglomeration of values not necessarily of the same type, which one accesses via a parameter, “column name”. In the use of tables which interests us here, one will generally produce columns of real numbers; their variation is arbitrary.*

*For further details on what a table is, one may consult the documentation of* *IMPR_TABLE* [U4.91.03](doc:u4.91.03).

The values can be extracted by using the following commands:

- RECU_FONCTION [U4.32.03](doc:u4.32.03): produces a function from a result, from a field, from a table… Example: time evolution of a component of a field at a particular point.
- POST_RELEVE_T [U4.81.21](doc:u4.81.21): produces a table from a result or from a field. One can extract a quantity associated with the components of a field (a component, an invariant…) at certain particular points or along a path which is not necessarily straight.
- MACR_LIGN_COUPE [U4.81.13](doc:u4.81.13): produces a table from a result or from a field along a cutting line (straight line composed of regular segments).
- RECU_TABLE [U4.71.02](doc:u4.71.02): produces a table from the values of one or more parameters of a result. For example: the evolution of the piloting parameter in the course of an analysis. One can also extract a table from a few particular data structures.
- CREA_CHAMP [U4.72.04](doc:u4.72.04): makes it possible to extract a field from a result data structure. This can be useful when a command does not know how to treat certain results. One can for example then recover a function via RECU_FONCTION/CHAM_GD.

### 1.2 Treating data blocks

A data block is simply an array of values with N rows and P columns.

In certain cases, one has one or more files each composed of one or more data blocks, separated by lines of text. In order to build functions from such files, one can use LIRE_FONCTION [U4.32.02](doc:u4.32.02).

For example, one carries out a parametric study; each analysis produces an array which comes to enrich a result file; the file may also have been built by a single analysis or else manually, it hardly matters. Such a file could look like this:

One has several blocks which do not necessarily have the same number of columns.

Suppose that one wishes to compare the displacement DY obtained with the two values of PARA; one will use for example:


fDY1=LIRE_FONCTION(

INDIC_PARA=(1,1,), # the abscissae are taken in block 1, column 1


INDIC_RESU=(1,3,), # the ordinates are taken in block 1, column 3


UNITE=38,

NOM_RESU='DY',)

TYPE='FONCTION',

INDIC_PARA=(2,1,), # the abscissae are taken in block 2, column 1


INDIC_RESU=(2,5,), # the abscissae are taken in block 2, column 5


UNITE=38,

NOM_PARA='INST',

NOM_RESU='DY',)

# classical plotting of two functions with IMPR_FONCTION:


IMPR_FONCTION(FORMAT='XMGRACE',

UNITE=29,

COURBE=(_F(FONCTION=fDY1,

LEGENDE='PARA=1.23',),

_F(FONCTION=fDY2,

LEGENDE='PARA=1.98',),),

TITRE='DY=f(t)',)

## 2 Transforming the values of a table or of a function into Python objects

**Note**

*The processings in Python which are used from now on require being in* *PAR_LOT='NON' in* *POURSUITE (or* *DEBUT).*

The object here is to recover the values of a table or of a function in a Python object in order to manipulate them afterwards. Note that it is sometimes practical to produce a function from the data of a table, possibly filtering certain rows of the table; this is a use of RECU_FONCTION [U4.32.03](doc:u4.32.03), which we shall not address here.

On objects of type function, one has the methods:

1. Valeurs, in order to recover the abscissae and the ordinates in 2 Python lists of reals.

With the data of the previous paragraph:

One obtains:

[1.0, 1.1, 1.2, 1.8, 2.45]

[0.207127, 0.414928, 0.792728, 0.688227, 0.343029]

1. Absc and Ordo make it possible to recover the abscissae and the ordinates separately.

One can access the content of a cell of a table with [ *parameter_name* , *row_number* ]:

-8.14498E-2

One can also transform the (JEVEUX) table object into an instance of the Python class Table.

The document [U1.03.02](doc:u1.03.02) details the Python methods available on objects of type Table. For the extraction of the values, one has in particular a method values() which returns a dictionary whose keys are the parameter names (e.g. ‘DY’) and the values the lists of the values of the table.

**Warning**

The Python lists are indexed from $0$ to $n-1$ (for $n$ elements); the equivalent of tab[‘DY’, 2] is therefore tabpy[‘DY’][1]!

For the plotting of curves from lists of Python reals, see [§ 4 ].

## 3 Manipulating the values in Python

A few examples are given here of the manipulation of the values obtained previously in the form of lists or of Numeric arrays.

Numeric is an optional Python module (that is to say not included in the Python distribution supplied on www.python.org) but indispensable in order to use *Code_Aster*; one can therefore do import Numeric on all *Code_Aster* installations.

### 3.1 With Python lists

Python lists are easily manipulated by using loops. Let us take the example of the guide [U2.51.01](doc:u2.51.01) for $–10.<x<10.$ in $100$ steps:

| $y=-1.5$ | if $\sin(x)<0$ |
| --- | --- |
| $y=-5.$ | otherwise |

One therefore seeks to build two lists of reals, $\mathrm{lx}$ and $\mathrm{ly}$.

As always in Python, there are several ways of doing it, more or less simply, more or less elegantly!

x0=-10.

pas=20./100

| lx=[] | or else | lx=[x0+i*pas for i in range(101)] |
| --- | --- | --- |

for i in range(101):

lx.append(x0+i*pas)

def f(x):

if sin(x)<0.:

return -1.5

else:

return -5.

| ly=map(f, lx) | which applies the function $f$ to all the elements of $\mathrm{lx}$ |
| --- | --- |

One can plot this curve by using the keywords ABSCISSE and ORDONNEE of IMPR_FONCTION (cf. [§ 4 ]).

### 3.2 With Numeric arrays

The manipulation of the data in the form of Numeric arrays is simplified by the use of very efficient operations (called *ufunc*) on the whole array (in the following example one uses sin()). Numeric also handles arrays with several dimensions.

Taking up the previous example again:


from Numeric import *

lx = arrayrange(-10., 10.+0.2, 0.2, Float)

ly = array(map(f, lx))

or else without using f:


ly = -1.5*less(sin(lx), 0.) + (-5.)*(1.-less(sin(lx), 0.))

Note that map() returns a list and not a Numeric array. The second expression is between 10 and 20 times faster on *very* large arrays (${10}^{5}$ – ${10}^{6}$ terms), which is however fairly rarely the case of the functions or tables coming from *Aster*.

One can plot this curve by using the keywords ABSCISSE and ORDONNEE of IMPR_FONCTION, taking care to convert the Numeric arrays into a list, for example (cf. [§ 4 ]):


ABSCISSE = lx.tolist()

### 4.3 Plot of a large number of curves

In certain applications, one is led to plot numerous curves. Suppose that one wishes to compare our results with 50 measurement points obtained elsewhere. It would then be tedious to define 50 files in astk and to use 50 different logical units in the command file!

It is then sufficient to use the type «repe» as a result in astk (cf. [U1.04.00](doc:u1.04.00)):


![Figure](/figures/u2.51.02/10000000000002820000001A609F5D738459A97E.png)

One then proceeds as follows in the command file with PAR_LOT='NON' in POURSUITE:

# definition of the 50 post-processing node groups


lgrno = [:ref:` 'point01', 'point02', ..., 'point50'  < 'point01', 'point02', ..., 'point50' >`]

# for each post-processing node...


for point in lgrno:

unit = 29

# the files DEPL_point0i.dat will be copied into Resultats/courbes/


DEFI_FICHIER(UNITE=unit, FICHIER=‘./REPE_OUT/DEPL_’+point+’.dat’)

tab=POST_RELEVE_T(

ACTION=_F(INTITULE = 'VonMises',

RESULTAT = resM,

NOM_CHAM = 'SIEQ_ELNO',

NOM_CMP = 'VMIS',

TOUT_ORDRE = 'OUI',

GROUP_NO = point,

OPERATION = 'EXTRACTION',),)

IMPR_TABLE(

UNITE = unit,

TABLE = tab,

FORMAT = 'XMGRACE',

NOM_PARA = ('INST', 'VMIS'),)

# one “releases” the unit in order to reuse it for the following curve


DEFI_FICHIER(UNITE=unit, ACTION=‘LIBERER’)

## 5 A few useful tips

A few manipulations of the data of the tables in Python are proposed here, which recur when one wishes to go further in the generation of curves from *Code_Aster*.

**Extract from the table coming from** **POST_RELEVE_T the list of the post-processing nodes:**

When one post-processes a quantity on a node group (with more than one node) for several time instants, the nodes appear for each time instant; it is therefore necessary to extract the list of these nodes without repetition.

| tabpy = tab.EXTR_TABLE() | Creation of the Python Table object |
| --- | --- |
| tno = tabpy.NOEUD.values() | One extracts the values of the column NOEUD |
| lno = list(set([i.strip() for i in tno])) |  |
|  | Efficient method for eliminating the |
|  | duplicates, using set |
| lno.sort() | Sort in increasing order |

**Build one or more keywords dynamically:**

This can in particular be useful for filling in the factor keyword FILTRE of IMPR_TABLE according to the context; one builds in this case a dictionary which is then supplied as an argument of the command.

This:


IMPR_TABLE(

UNITE = unit,

TABLE = tab,

FORMAT = 'XMGRACE',

FILTRE = (_F(NOM_PARA='NOEUD',

VALE_K = 'N4',),

_F(NOM_PARA='NOEUD',

VALE_K = 'N4',),),

NOM_PARA = ('INST', 'VMIS'),

)

is equivalent to this:


mfac = {‘FILTRE’ : [{‘NOM_PARA’:‘NOEUD’, ‘VALE_K’: ‘N4’},

{‘NOM_PARA’:‘INTITULE’, ‘VALE_K’: ‘exemple’},],

‘NOM_PARA’ : [‘INST’, ‘VMIS’],

‘UNITE’ : unit,

‘FORMAT’ : 'XMGRACE',}

IMPR_TABLE(

TABLE = tab,

**mfac

)

The advantage being of course to be able to build the dictionary as one wishes.

**Note**

*The factor keywords (here* *FILTRE) can be built by using* *_F(keyword = value), but it is more flexible to see them as a list of dictionaries.*
