# v1.01.370 PLEXU10 - Validation of slippery and rubbing cables in CALC_EUROPLEXUS

**Summary:**

Mechanisms to model slippery and rubbing cables have been added to EUROPLEXUS.

This series of tests validates the call of CALC_EUROPLEXUS to these prestressed features calculated in Code_Aster or not, but also directly participates in their validations in EUROPLEXUS.

**Slippering cables:**

The Modelling of slippery cables is done only by a restraint ( *LCAB GLIS* ). This restraint, inspired by RELA_CINE_BP loading, calculates the kinematic relationships between concrete and cable by leaving the movement of each node cable in the tangent direction to the trajectory of the cable. To take into account the large deformations and slippages, this restraint is updated to each time step.

**Rubbing cables:**

The Modelling of the rubbing cables is done using the same restraint as for slippery cables. Specific discrete elements are used to model friction. restraints should also be made on the nodes of the non-common discrete elements with elements cables. This restraint is enabled by the *LCAB FROT syntax*.

**Model A:** Validation of the call to restraint EPX *LCAB GLIS* (reproduction of the test bm_str_lcab_glis).

**Model B:** Validation of the correct consideration of an initial prestress status with the restraint *LCAB GLIS* .

**Model C:** Tensioning of a slippery cable in EPX (reference Code_Aster).

**Modelling D:** Validation of the call to restraint EPX *LCAB FROT* , (reproduction of the test bm_str_lcab_frot_amor). This test is part of the validation of LCAB FROT in EPX, it provides a reference value for a tensioning of a rubbing cable with an anchoring rearward.

**Modelling E:** Reproduction of the test bm_str_lcab_frot

**Model F:** Validation of Code_Aster/EPX chaining with rubbing cables.

### 2.2 Details

Without the restraints between the cable and the concrete, the loading would only have an effect on the 5 mesh cells at the end where the traction is applied. The restraint *LCAB GLIS* imposes a total kinematic relationship to the two nodes at the ends of the cable (or nodes anchor) and a partial kinematic relationship to the other nodes (not restraint in the direction of the cable).

The imposed load will therefore drive the node anchor with the concrete nodes, which will pull all the cable.

The nodes cable then moves along the path. For this test and its equivalent in EPX the validation is visual. The ParaVIS module of SalomeMeca was used to visualize the movements of nodes cables over time.

Once this visualization has been done, non-regression tests have been added to the EPX test. To validate the call of CALC_EUROPLEXUS to the restraint EPX *LCAB GLIS,* the same values as EPX are tested.

## 3 Modelling B

This Modelling validates the use of an initial prestress state with the restraint EPX *LCAB GLIS* .

### 3.1 Boundary conditions and loads

The 6 nodes at each end of the concrete are clamped.

In addition, the model is assigned a prestressed load calculated from DEFI_CABLE_BP and CALC_PRECONT. The voltage imposed on the cable is defined by keyword TENSION_INIT of DEFI_CABLE_BP, its value is set to $2.E5N$. This load is sent to EPX as an initial state.

### 3.2 Details

In EPX, prestress without additional loading is applied. When calculating this prestressed state by CALC_PRECONT, the kinematic relationships between the cable and the concrete were total (i.e. in the three directions of space). For this test, arriving in EPX, we will have slippery restraints.

Despite this, the system is tested even though it is at equilibrium when it arrives from EPX. Indeed, the stress profile calculated in DEFI_CABLE_BP is made with zero friction coefficients. Therefore, the stress is equal on all mesh cells. Once in EPX, although the restraints are released in each node in the tangent cable direction, the nodes do not move because of this uniform stress profile.

To test this balance, we perform many time step and check on a few values that nothing has changed.

Rq: It was verified that by calculating a voltage profile with friction the cable was moving along its path in EPX.

## 4 Modelling C

It uses both LIRE_EUROPLEXUS without going through CALC_EUROPLEXUS to recover the result of the EPX test contained in an MED file (given in unit 19) and reproduces the calculation with CALC_EUROPLEXUS.

Same as Modelling B. Prestress loading differs only in the value of the initial voltage given by TENSION_INIT. It is here equal to $2.37182E+08$.

As already said, in the EPX calculation, damping features are used to simulate a quasi-static calculation and thus obtain a stabilized solution in a reasonable time.

## 5 Modelling D

This Modelling provides a reference for the EPX test bm_str_lcab_frot_amor which reproduces the setting of a rubbing cable. Reference values are voltage profiles calculated with DEFI_CABLE_BP.

The EPX bm_str_lcab_frot_amor test uses EPX damping.

It uses both LIRE_EUROPLEXUS without going through CALC_EUROPLEXUS to recover the result of the EPX test contained in an MED file (given in unit 19) and reproduces the calculation with CALC_EUROPLEXUS.

### 5.1 Friction material

The BPEL_ACIER material is assigned to the Code_Aster cable and the EPX friction discretes with the following parameters:

| FROT_LINE | 0,003 |
| --- | --- |
| FROT_COURB | 0,2 |

### 5.2 Boundary conditions and loads

**EPX:**

Same boundary conditions and loading as Modelling A. Only the multiplier function changes to simulate the anchoring retreat.

| **Time** | **Coefficient** |
| --- | --- |
|  | 0.0 |
| 0.002 | 1.0 |
| 0.06 | 1.0 |
| 0.1 | 0.933333 |
| 1.0 | 1.0 |

The change from multiplicative to 0.93333 represents a 0.2 m decrease of ANCR2.

**Code_Aster:**

Same boundary conditions as model B. Prestress loading differs only on the initial voltage value given by TENSION_INIT. It is here equal to $315367000$. The call to DEFI_CABLE_BP is made twice, first without an anchoring step and second time with an anchoring step of 0.116.

The value of the voltage to be applied in Code_Aster was determined as follows. The results of the EPX calculation were recovered. The EPX field of cable stress was converted into stress fields. From this field at Gauss points (SIEF_ELGA) the field was calculated at the corresponding nodes (SIEF_NOEU). The first node cable from the node ANCR2 with the updated Y coordinate was then detected in the 0.06s time field of movement, and the first node cable from the node ANCR2 was physically not removed from the concrete during this voltage phase. The value of the voltage to be applied in Code_Aster is the nodes field of stress at this node.

Contrary to what one might think, the anchoring step to apply in Code_Aster is not 0.2m but 0.116m. Indeed, the anchoring step should not be calculated from the node ANCR2 but from the last node still included in the concrete following the initial phase. The value of 0.116m is then obtained.

### 5.3 Comparison of voltage profiles

![Figure](/figures/v1.01.370/10000200000004AE000002118FD747A5179FC31E.png)

The analysis in EPX is given here:

*In the initial phase of tensioning, we see that the curves are almost perfectly superimposed for curvilinear abscisses greater than about 20.0 m. By printing the value of curvatures in each node calculated in EPX, we found that some values in the middle of the cable were quite different from the others, whereas in the circular part the curvature must be the same in each point. This is probably the result of very slight impreciseness in the mesh at this level. Code_Aster does not see it because it uses a spline method that interpolates the trajectory of the cable globally while in EPX one simply interpolates the trajectory locally.*

*Concerning the anchoring step, there are slightly larger differences but the curves are parallel on this part. The differences can arise from a consideration of friction on nodes normally removed from concrete or from the interpretation of the node reference for determining the anchoring step to be applied in Code_Aster.*

The voltage imposed on the cable is defined in DEFI_CABLE_BP by the TENSION_INIT and RECUL_ANCRAGE keywords, which are respectively $2.E7N$ and $0.01m$. This load is sent to EPX as an initial state.

Two calculations are performed. In both cases, o n applies the prestress without additional loading in EPX. In the first, the keyword EQUI is set to 'OUI' so that EPX balances the given initial state Code_Aster. We check that the system does not evolve. In the second, EQUI is set to 'NON'. A light damping is added to allow the system to balance itself.
