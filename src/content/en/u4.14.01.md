# u4.14.01 Operator DETRUIRE

## 1 Purpose

Destroy user concepts.

After destruction, the concept can therefore naturally no longer be used in the following commands. The destruction of an object is not as natural as it may appear. It is important to understand fully its behaviour, described in this documentation.

The destruction of unused objects makes it possible to reduce the size of the files associated with the 'GLOBALE' database. The repacking mechanism is handled by the memory manager during the work. However, another repacking mechanism can be triggered by the user by means of the keyword RETASSAGE= 'OUI' within the procedure FIN [U4.11.02](doc:u4.11.02).

## 2 Syntax

```text
DETRUIRE(
    ◆ NOM = datastructure,
    ◇ INFO = / 1 (par défaut),
             / 2,
)

◆ : obligatoire
◇ : optionnel
⟐ : présent par défaut
& : ensemble
/ : un seul parmi
| : plusieurs choix possibles
```

## 3 Operands

### 3.1 Keyword NOM

```text
♦    NOM = lco
```

List of the objects to destroy. All the direct references to the objects supplied are removed in the context where DETRUIRE is invoked. See below for the detailed behaviour.

### 3.2 Operand INFO

```text
◊    INFO = info
```

In the case where INFO=2, the list of the objects destroyed is printed in the MESSAGE file.

## 4 How does destruction work?

### 4.1 Example

One creates a list of reals named listr

```text
listr = DEFI_LIST_REEL( … )
```

One destroys the concept named listr

```text
DETRUIRE(NOM=listr)
```

Note that reusing the same Python variable listr has the same effect as DETRUIRE.

### 4.2 In detail

The objects created by code_aster (a mesh, a result) are Python objects.

DETRUIRE removes the references to the object in the command set. Python actually deletes this object when there is no longer any reference to this object.

Take the example:

> mesh = LIRE_MAILLAGE()
> alias = mesh
> lst = [mesh]

One has created a *mesh* object; mesh is a variable that references (or "that gives access to", or again "that points to") this object. alias is a variable that references the same object. lst is a list, created with the operator [ ], which contains a single entry, and this entry also references the same mesh object.

If one does:

> DETRUIRE(NOM=mesh)

All the direct references to the mesh object are removed from the command set.

Thus, the variables mesh and alias are removed.

Indeed, during the execution, one sees:

> Deletion of the reference: ‘mesh’
> Deletion of the reference: ‘alias’

On the other hand, the reference via the list is not seen (one would have to walk through all types of object!) and therefore, in accordance with the way Python works, the mesh object is not actually destroyed, since there is still a reference to this object.

If one deletes the list:

> del lst

or the entry of the list:

> del lst[0]

Then there is no longer any reference to the object, which is then actually destroyed. One can see:

> Deleting 00000004 <MAILLAGE_SDASTER> mesh

Note that:

> DETRUIRE(NOM=lst[0])

would have had exactly the same behaviour (deletion of mesh and alias but not of lst[0]), because one passes the object to DETRUIRE and not the list lst or the index 0.

One would also have the same behaviour with a dictionary containing a mesh object or any object referencing the mesh.

Indeed, only the container (the list object, dictionary or other) knows how to delete one of its entries.

### 4.3 Dependency between objects

The data structures (field at the nodes–numbering, field by element–model, and so on) rely on one another. Destroying a data structure that is used by another therefore has no immediate effect. On the other hand, when all the references to a data structure are removed, it is then actually removed.
